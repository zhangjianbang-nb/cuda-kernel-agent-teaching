一 · 微基准加速比与端到端收益之间的结构性鸿沟

KernelBench 系基准给出的数字是单 kernel 在隔离环境下的加速比，其测量条件通常包含：固定 shape、预热后的稳态、无并发干扰、无框架调度介入、输入张量已就位。生产负载打破其中每一个条件。一个在微基准上达到高加速比的 kernel，进入真实模型后要经过算子分发、流同步、内存池分配、layout 转换、autograd 图拼接等多层路径，每一层都可能吞掉收益。这里的鸿沟不是测量误差，而是结构性的：微基准测的是 kernel 本体时间，端到端测的是 kernel 在调用图中的边际贡献。

把这件事形式化。设模型一次前向的总时延为 $$T_{\text{e2e}} = \sum_i \left( t_i^{\text{kernel}} + t_i^{\text{dispatch}} + t_i^{\text{sync}} + t_i^{\text{layout}} \right) + T_{\text{framework}}$$，其中 $$t_i^{\text{kernel}}$$ 是第 i 个算子的设备执行时间，后三项分别是分发开销、同步开销与布局转换开销，$$T_{\text{framework}}$$ 是图级调度与内存管理开销。微基准只优化第一项。若某算子被替换后 $$t_i^{\text{kernel}}$$ 下降 $$\Delta$$，但新 kernel 引入了额外的 layout 转换 $$t_i^{\text{layout}} = \delta$$，则端到端收益为 $$\Delta - \delta$$；当 $$\delta \geq \Delta$$ 时，部署该 kernel 的净收益为零甚至为负。这就是为什么“微基准加速比”不能直接作为部署决策依据——它缺少 $$\delta$$ 这一项。

具体例子：一个融合 attention 的 kernel 在隔离测试中对单次 attention 调用取得可观加速，但真实模型中该 attention 的上游输出是非连续 stride 布局，新 kernel 要求连续布局，于是框架插入一次 transpose+contiguous 拷贝。这次拷贝的带宽代价按数据量除以有效带宽估算，在长序列下与 kernel 节省的计算时间同量级，端到端收益被抵消。工程判断因此不是“这个 kernel 快不快”，而是“这个 kernel 在调用图中引入的额外数据移动是否小于它节省的执行时间”。

代价维度在这里发生转换：微基准阶段关注的时延，在端到端阶段要让位于“时延+带宽+显存峰值”的联合账本。一个 kernel 可能降低时延却抬高显存峰值，导致 batch size 被迫下调，反而恶化吞吐。这类 trade-off 只有 trace 驱动的端到端闭环才能暴露，单 kernel 基准在定义上无法回答。

二 · 这个方向的边界：它不做什么

生产端到端部署方向的边界必须划清，否则会与相邻方向重复劳动。它不负责生成 kernel 的搜索策略——那是 agent 脚手架与多轮 RL 的领域；它不负责判定单个 kernel 的数值正确性——那是正确性 oracle 与形式验证的领域；它不负责构造可信的微基准分数——那是基准与可信评测的领域。它负责的是：给定一个已经通过正确性检验、在微基准上表现出潜力的 kernel，判断它在真实模型、真实负载、真实框架栈中是否值得部署，以及部署后如何度量其真实边际收益。

边界的第一层是“真实负载”的定义。trace 驱动的真实负载回放要求输入的不是合成 shape，而是从生产流量中采集的算子序列、shape 分布、并发模式与内存压力剖面。这里立刻遇到数据获取的隐私与可复现性冲突：生产 trace 含用户数据特征，脱敏后可能改变 shape 分布，导致回放失真；而完全合成的 trace 又退回微基准的老路。工程上的折中是分层回放——保留 shape 与调用序列的统计特征，剥离内容语义，用固定种子保证可复现。代价是回放保真度与隐私合规之间的持续张力，任何声称“完全真实”的回放都要追问其脱敏路径。

边界的第二层是“集成”的粒度。端到端闭环优化不是把 kernel 塞进框架就结束，而是要处理分发感知的调度：同一个算子在不同 shape、不同 dtype、不同并发下应选择不同 kernel 实现，调度决策本身有开销。设调度查询耗时为 $$t^{\text{dispatch}}$$，若它为每个算子引入固定开销，则在算子粒度细、调用频次高的模型中，调度开销会随算子数线性累积。分发感知的 kernel 调度因此要把“选择哪个 kernel”的决策成本计入端到端账本，而不是假设调度免费。

具体例子：一个模型含大量小算子，逐个替换为定制 kernel 后单算子时延下降，但每个定制 kernel 需要一次独立的 dispatch 分支判断与参数打包，累积的 dispatch 开销在小算子上占比显著，端到端反而变慢。这说明端到端方向的边界包含“何时不该替换”——保留框架原生算子可能是更优的工程判断，而这个判断只能由端到端闭环给出。

三 · 为什么其他方向替代不了它

基准与可信评测能给出可比较的分数，但分数的坐标系是隔离环境，无法回答“在这个模型的这条调用路径上是否值得”。Agent 脚手架与执行反馈能迭代出更快的 kernel，但反馈信号若来自微基准，优化目标就与部署目标错位——agent 会朝着微基准加速比爬坡，而非朝着端到端边际收益爬坡。多轮 RL 与可验证奖励同理：奖励函数若定义为单 kernel 加速比，策略学到的就是隔离环境下的最优，而非调用图约束下的最优。正确性 oracle 与形式验证保证数值无误，但不保证性能收益为正。硬件感知 DSL 与 profile 提供 roofline/SOL 分析，能指出 kernel 离硬件上限多远，但 SOL 高不代表端到端收益高——一个接近 SOL 的 kernel 若引入布局转换，仍可能净亏。

替代不了的根源在于目标函数不同。微基准的目标是 $$\min t_i^{\text{kernel}}$$，端到端的目标是 $$\min T_{\text{e2e}}$$，后者是前者的带约束聚合，且约束来自框架栈与调用图。任何只在单算子层面优化的方向，都无法在原理上保证聚合目标下降。这不是工程实现问题，而是优化目标的定义域问题：单算子最优解集合与端到端最优解集合的交集可能很小。

具体例子：两个候选 kernel，A 在微基准上更快但需要额外的一次全局同步，B 稍慢但可异步融入现有流。在隔离环境下 A 胜出，在端到端闭环中 B 因省去同步而胜出。只有端到端评测能区分这两者，其他方向各自在自己的坐标系里都是“正确”的，但坐标系本身不覆盖部署决策。

代价维度：端到端闭环的评测成本显著高于微基准——trace 回放需要真实模型加载、框架栈就位、多次重复以压制噪声，单次评测的时延与显存占用都更高，且 trace 采集本身有工程成本。这是这个方向必须承受的代价，也是它不可被廉价替代的原因：它买的是决策相关性，不是测量吞吐。

四 · 生产就绪度分级：把“是否值得部署”变成可操作判据

端到端方向的核心产出不是单个布尔判断，而是生产就绪度分级。分级的意义在于把“值得部署”拆成可验证的阶梯，每一级有明确的准入条件与失败代价。一个可操作的分级至少包含：隔离正确性通过、微基准潜力确认、trace 回放下端到端收益为正、框架集成后无回归、分发调度开销可接受、显存峰值不越界。每一级都是一个 gate，未通过则不得进入下一级。

伪代码思路：对候选 kernel k，依次执行 gate 序列，任一 gate 失败即返回该级失败原因与代价估计。

  • gate 1：正确性 oracle 通过（引用正确性方向，不展开）。
  • gate 2：微基准加速比超过阈值，且 SOL 分析显示有剩余空间（引用 profile 方向）。
  • gate 3：trace 回放下 $$T_{\text{e2e}}(k) < T_{\text{e2e}}(\text{baseline})$$，且差值超过回放噪声带。
  • gate 4：集成后无 layout 转换净增，$$\delta \leq \Delta$$。
  • gate 5：dispatch 开销累积后仍为正收益。
  • gate 6：显存峰值不超过部署预算。

分级的代价在于评测时间与工程复杂度：每一级都需要独立的 harness，gate 3 与 gate 4 需要真实模型与 trace，单次完整分级可能耗费数倍于微基准的机时。但分级的收益是把“部署后才发现回归”的风险前移，避免在生产环境中回滚。具体例子：某 kernel 通过 gate 1–3，但在 gate 4 发现布局转换净增，分级机制在集成前就拦截，省去一次生产回滚；若没有分级，这个 kernel 会带着微基准光环进入部署，然后在真实流量下暴露负收益。

分级的另一个工程判断是阈值设定：gate 3 的收益阈值不能设为“大于零”，因为回放噪声与测量抖动会制造假阳性。阈值应基于回放重复测量的方差确定，且随模型规模与算子占比调整——小算子在大模型中的端到端占比低，其收益阈值应更高，否则会把噪声当信号。

五 · 分发感知调度：端到端账本里最容易被忽略的一项

分发感知的 kernel 调度是端到端方向独有的机制，其他方向不处理它。其核心是：kernel 选择不是静态绑定，而是运行时按 shape、dtype、并发度查表或计算。调度器本身有成本，且这个成本随调用频次放大。设模型有 N 个算子调用点，每个调用点的调度决策耗时为 $$t^{\text{dispatch}}$$，则调度总开销为 $$N \cdot t^{\text{dispatch}}$$；若定制 kernel 使 N 增大（例如把一个融合算子拆成多个定制算子），调度开销随之上升。

机制上，分发感知调度需要一张按负载特征索引的 kernel 选择表，表项由 trace 回放阶段的端到端测量填充，而非由微基准填充。这意味着调度表的构建本身依赖端到端闭环——两个机制互为前提，构成这个方向的闭环结构。代价是调度表的维护成本：负载分布漂移时表项失效，需要重新回放填充；表查询的缓存友好性也影响 $$t^{\text{dispatch}}$$ 的实际值。

具体例子：一个 GEMM 类算子在短序列与长序列下最优 kernel 不同，静态绑定只能选一个，分发感知调度按序列长度分支。分支判断的耗时若未计入账本，短序列场景下分支开销可能超过 kernel 本身节省的时间；把分支判断做成查表并缓存，可将 $$t^{\text{dispatch}}$$ 压到可忽略，但缓存未命中时仍有一次性成本。工程判断是：调度粒度应与算子粒度匹配，过细的分支在细粒度算子上不划算。

这一项的不可替代性在于：它同时依赖真实负载分布（来自 trace）与端到端收益测量（来自闭环），任何单算子方向都无法独立构建。它也是“微基准收益被吞掉”的主要通道之一——调度开销不在 kernel 时间里，却在端到端时间里。

六 · 闭环的工程形态与判断落点

端到端闭环的工程形态是：trace 采集 → 回放 harness → 候选 kernel 注入 → 端到端测量 → 分级 gate → 调度表更新 → 再回放。闭环的关键是注入点与测量点的对齐：注入必须发生在框架真实调用路径上，测量必须覆盖完整前向（或训练步），否则测到的仍是隔离环境。对齐失败的典型症状是“闭环测出的收益与微基准几乎相同”，这说明注入点绕过了框架栈，闭环退化为微基准。

闭环的代价是评测基础设施的固定投入：trace 存储、回放环境、注入钩子、噪声压制。这些投入不产生单 kernel 加速比，但产生部署决策。工程判断因此是：当候选 kernel 数量大、部署风险高时，闭环基础设施的摊销成本可接受；当只有零星候选时，闭环可能比候选本身更贵，此时分级 gate 可裁剪为最小集（gate 1、3、4），跳过完整调度表构建。

最后落在具体机制上：端到端方向的判断不是“这个 kernel 快”，而是“这个 kernel 在 trace 回放的调用图中，扣除 dispatch、sync、layout 与显存代价后，边际收益为正且超过噪声带”。这个判断的输入只能来自闭环，输出是分级结果与调度表项。任何绕过闭环的部署决策，本质上是在用微基准坐标系回答端到端问题——坐标系错位，答案再精确也不相关。

端到端收益的归因边界：微基准加速比在什么条件下必然失效

把微基准加速比折算成端到端收益，本质是一次归因分解，而不是一次缩放。设某 kernel 在隔离环境下的耗时为 t_micro，其在真实负载中占父算子链的比例为 f，则理想上限由 Amdahl 给出：

$$S_{e2e} \le \frac{1}{(1-f) + f/S_{micro}}$$

该式暴露了本方案的第一个硬边界：当 f 低于某个阈值时，无论 S_micro 多大，端到端收益都被 1/(1-f) 封顶。一个在 KernelBench 上取得高加速比的 elementwise 融合 kernel，若在真实模型中只占单层时延的极小份额，其端到端贡献在测量噪声之下，此时任何“部署收益”的断言都不成立。更关键的是，f 本身随 batch size、序列长度与并发度漂移——同一 kernel 在离线大 batch 下占比可观，在在线小 batch 下被 launch 与调度开销稀释，因此单一 f 下的归因结论不可外推。

第二类失效条件来自框架集成层。trace 驱动的真实负载回放能捕获算子序列与张量形状，但捕获不到框架侧的隐式代价：算子分发（dispatch）路径、layout 转换、显存池碎片、流同步点。一个微基准中被反复调用的 kernel，在真实图中可能因前后算子要求不同 memory format 而被迫插入 transpose，把收益反向吞掉。工程上必须把“kernel 时间”与“图重写后的净时间”分开记账，否则会把框架开销误记为 kernel 收益。分发感知的调度正是为此存在：它要求 kernel 的注册与选择逻辑在图层面可见，而非在算子内部黑盒决定。

第三类代价是评测本身的系统开销，它决定了这套方案不能无限细化。trace 回放需要保存真实负载的输入张量与调用序列，存储与重放时延随 trace 长度线性增长；隐私约束又迫使负载脱敏或合成，而合成负载的形状分布一旦偏离真实分布，f 的估计即失真。可复现性与真实性在此直接冲突，工程判断是：以形状分布与调用频次的统计量替代原始数据，把回放精度控制在能稳定区分“收益显著”与“收益不可测”的粒度，而不是追求逐 bit 复现。
