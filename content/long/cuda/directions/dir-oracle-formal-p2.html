一 · 三条路线的机制解剖：从采样到证明

为 LLM 生成的 kernel 建立正确性保证，工程上可落地的路线只有三条，它们的机制差异不在“测得多不多”，而在“断言从哪里来”。第一条是契约感知的差分测试：把 kernel 的输入域按语义切成等价类（形状、步长、对齐、dtype、归约轴长度、batch 组合），每一类上同时跑参考实现与候选 kernel，逐元素比对。第二条是批不变性与确定性检查：不比对绝对数值，而是构造同一逻辑输入的不同物理排布（不同 batch 切分、不同 tile 顺序、不同 stream 交错），要求输出在给定容差内一致，从而把“并行归约顺序”这一自由度的错误暴露出来。第三条是形式化/符号执行验证：把 kernel 的语义翻译成逻辑公式或符号表达式，对输入域做全称量化，交给 SMT 求解器或交互式定理证明器判定等价性。

三者的机制分水岭是“断言的来源”。差分测试的断言来自参考实现，本质是存在性抽样——它证明的是“这些点上没错”，错误覆盖率由等价类划分的质量决定。批不变性检查的断言来自 kernel 自身的不变量，本质是元性质检验——它不关心单个输出对不对，只关心输出对物理排布是否敏感，因此能抓到参考实现同样会犯的错（比如参考实现和候选实现共享同一个错误的归约顺序假设）。形式验证的断言来自规格（spec），本质是全称证明——它要么给出“对所有合法输入成立”的证明，要么给出反例。三条路线不是替代关系，而是断言强度递增、代价递增的阶梯。

$$\text{Coverage}_{\text{diff}} = \frac{|\{x \in \mathcal{E} : \text{tested}(x)\}|}{|\mathcal{E}|},\quad \text{Guarantee}_{\text{formal}} = \forall x \in \mathcal{D}.\ \text{sem}(K_c, x) \equiv_{\epsilon} \text{sem}(K_r, x)$$

代价差异立刻显现。差分测试的代价是执行时延与显存：每个等价类要跑两次 kernel 加一次比对，等价类数量随形状维度组合爆炸，一个覆盖 4 个 dtype × 6 种对齐 × 5 种归约长度的矩阵就是 120 次启动，每次启动的固定开销（kernel launch、同步、host-device 拷贝）在小 shape 上远大于计算本身。批不变性检查的代价是重复执行：同一输入要跑 N 种排布，N 通常取 3–5，直接乘以时延。形式验证的代价是编译/求解时间：符号执行要把循环展开成路径约束，归约长度 1024 的 kernel 展开后约束规模可达数万条，SMT 求解在浮点理论上的复杂度使单次验证可能耗时数十分钟到数小时，且对 Triton 的动态 shape 语义覆盖不足。

具体例子：一个 softmax kernel 的候选实现把行内归约写成两段式（先求 max 再求 sum），参考实现写成单趟 Welford。差分测试在 batch=1、长度 128 时通过；批不变性检查构造 batch=7、长度 1000（非 2 的幂、尾部不满 warp）时发现候选实现漏掉了尾部掩码，输出在最后 24 个元素上偏大。形式验证若要对这个 kernel 给出全称保证，需要先把“浮点 max 与 sum 的结合顺序无关性”编码成公理，而这本身就是一个未决的语义建模问题——这正是第三条路线的根本代价所在。

二 · 等价类划分：差分测试的真实成本在构造而非执行

差分测试的工程瓶颈不是跑比对，而是等价类怎么切。切粗了漏边界，切细了组合爆炸。可操作的机制是沿 kernel 的“语义敏感维度”做正交分解：形状维度（是否整除 tile、是否触发尾块）、内存维度（对齐到 128B/32B/4B、是否跨页、是否别名）、数值维度（dtype、是否含 inf/nan/denormal、动态范围）、并行维度（grid/block 配置、归约轴长度是否为 2 的幂）。每个维度取“边界值 + 典型值”，用正交表而非全组合生成测试点，把 O(∏n_i) 压到 O(max n_i) 量级。

这里有一个容易被忽略的代价：参考实现本身的可信度。差分测试的断言完全依赖参考实现，若参考实现是 PyTorch 的 eager 版本，它在非连续 stride、非对齐指针上的行为与 CUDA kernel 的语义假设并不总是一致（例如 PyTorch 对空 tensor 的归约返回 0 还是 nan）。因此契约感知的验证器必须显式声明“参考语义”，把 PyTorch 行为当作 spec 的一部分固定下来，否则测试通过只是两个实现碰巧同错。

$$\text{Cost}_{\text{diff}} \approx |\mathcal{E}| \cdot \big(t_{\text{launch}} + t_{\text{ref}} + t_{\text{cand}} + t_{\text{cmp}}\big),\quad |\mathcal{E}| = \prod_{d \in D} |V_d|\ \text{（全组合）或}\ \max_{d} |V_d|\ \text{（正交）}$$

性能代价的具体形态：小 shape 上 t_launch 主导，一个 64×64 的 kernel 计算只要几微秒，但一次 launch + 同步 + D2H 拷贝要几十微秒，120 个等价类就是毫秒级开销，相对于 kernel 本身是数量级的放大。这直接影响 agent 的多轮迭代节奏——如果每轮反馈都要跑完整差分套件，单轮 wall-clock 从秒级涨到分钟级，RL 采样的吞吐被验证成本吃掉。工程折中是分层：快速轮只跑“边界等价类”（非整除、非对齐、含特殊值），慢速轮才跑全组合。

具体例子：一个 layernorm kernel 在 hidden=768（对齐）上全部通过，正交表加入 hidden=769（非对齐、尾块 1 个元素）后暴露越界读——候选实现按 32 元素向量化加载，未处理尾部，读到了下一行的数据。这个错误在随机测试里出现的概率约等于随机抽到非对齐长度的概率，而正交表把它变成必测项。

三 · 批不变性与确定性：不依赖参考实现的不变量

批不变性检查的机制是构造同一逻辑输入的不同物理表示，然后要求输出一致。对归约类 kernel，逻辑输入是“一个 batch 的 N 个向量”，物理表示可以是 batch=8 一次跑完，也可以是 batch=1 跑 8 次、或 batch=3+5 分两次跑、或改变 grid 的切分方式让每个 block 处理不同的行子集。若 kernel 的语义正确，这些表示应给出逐元素相同（或在浮点容差内相同）的结果。这条路线的高明之处在于它不需要参考实现：不变量来自“批处理不应改变单样本结果”这一语义公理，因此它能独立于 PyTorch 行为发现错误。

确定性检查是它的姊妹：同一输入、同一配置跑两次，要求 bitwise 相同。这抓的是原子操作的非确定性累加（atomicAdd 的浮点顺序随调度变化）、未初始化共享内存、竞态条件。代价是必须禁用或固定会影响调度的一切因素（固定 grid、禁用动态并行、固定 stream），这在生产配置下未必可行，因此确定性检查通常只在受控测试环境下跑。

$$\text{Inv}(K) : \forall x,\ \forall \pi \in \Pi_{\text{phys}}.\ \|K(x; \pi) - K(x; \pi_0)\|_\infty \le \epsilon_{\text{batch}},\quad \epsilon_{\text{batch}} = \kappa \cdot \text{ulp} \cdot \log_2 N$$

容差设计是这条路线的核心难点。批不变性不是 bitwise 相等：改变 batch 切分就改变了归约树形状，浮点非结合性导致结果在 ulp 级别漂移。容差必须与归约长度挂钩——长度 N 的树形归约，最坏误差随 log N 增长，因此 ε 应设为 κ·ulp·log₂N 量级，κ 取小常数。容差设太紧会把正确实现判错（假阳性），设太松会漏掉真实错误（假阴性）。这个 trade-off 没有通用解，只能按 dtype 和归约结构标定。

性能代价：每个测试点要跑 N_phys 次（通常 3–5），时延直接乘以这个系数；更麻烦的是构造不同物理表示需要 host 端重排数据或改变 launch 配置，带来额外的拷贝与同步。具体例子：一个 batched GEMM 的候选实现在 batch=1 时正确，batch=4 时因共享内存 tile 复用逻辑错误导致第 2、3 个 batch 的结果被覆盖；批不变性检查用 batch=1 跑 4 次与 batch=4 跑 1 次对比，逐元素差异远超 ε_batch，定位到 tile 复用。这个错误差分测试也能抓，但需要参考实现恰好在该 shape 上正确；批不变性检查不依赖这一点。

四 · 形式验证：规格建模的代价高于求解本身

形式验证的机制是把 kernel 语义编码为逻辑公式，对输入域全称量化，用 SMT 求解器判定“存在反例”或“不可满足”。对 CUDA 而言，可行路径是先把 kernel 翻译成中间表示（如将线程/block 索引符号化、把共享内存建模为数组、把同步建模为 happens-before 约束），再对循环做有界展开或归纳不变式。对 Triton 而言，语义更接近张量操作，可翻译成带形状约束的表达式，但动态 shape 与 masked load 的语义使翻译器必须显式建模“越界访问返回何值”。

真正的代价不在求解，而在规格建模。浮点等价性本身没有公认定义：IEEE-754 允许实现选择舍入模式、FMA 融合、denormal 处理，而并行归约的结合顺序是实现自由。要证明“候选 kernel 与参考在容差内等价”，必须先形式化容差语义——这要求把 ulp 误差传播写成可判定的约束，而误差传播在长归约链上是非线性的，SMT 的浮点理论（FPA）对这种约束的求解能力有限。工程上常见的退让是：只对无归约或短归约的 kernel 做形式验证，对长归约只验证“无越界、无竞态、无未定义行为”这类安全性性质，把数值等价留给前两条路线。

$$\text{VC}(K_c, K_r) = \big(\text{idx} < N \Rightarrow \text{addr}(\text{idx}) \in [\text{base}, \text{base}+\text{len})\big) \wedge \big(\text{sync}(t_1,t_2) \Rightarrow \text{hb}(t_1,t_2)\big) \wedge \big(|K_c(x)-K_r(x)| \le \epsilon(x)\big)$$

代价的量级：符号执行展开归约长度 1024 的 kernel，路径约束随展开深度线性增长，每条约束含浮点运算，SMT 求解在 FPA 理论上的最坏复杂度是指数级；实际工程中单 kernel 验证从数分钟到数小时不等，且失败时给出的反例往往是求解器内部路径，映射回源码需要额外工作。对 Triton 的覆盖不足体现在 masked load/store 的语义、`tl.dot` 的精度契约、动态 grid 的符号化——这些在翻译层就要人工补公理，补错公理会让证明失去意义。

具体例子：一个向量加法 kernel 的形式验证可以在分钟级完成（无归约、逐元素、地址约束简单），证明“对所有合法 idx，输出等于 a[idx]+b[idx] 且无越界”。而一个 1024 长度的 softmax，若坚持数值等价证明，求解器会在浮点 exp 与归约的结合顺序上打转；工程判断是把它拆成“安全性证明（无越界/无竞态）+ 差分测试（数值）+ 批不变性（归约顺序）”，形式验证只承担它能承担的那部分。

五 · 三条路线的代价对照与组合判据

把三条路线的代价放在同一张表上，工程决策就变成“给定预算选断言强度”。关键判据是 kernel 的语义结构：逐元素 kernel（无归约、无跨线程通信）的形式验证代价最低、收益最高，因为地址约束与数值约束都局部化；归约 kernel 的形式验证代价陡增，应退到批不变性 + 差分；含原子操作或动态并行的 kernel，确定性检查是唯一能抓竞态的手段，形式验证对调度非确定性几乎无能为力。

路线断言来源主代价覆盖盲区适用 kernel 形态
契约感知差分参考实现等价类数 × launch 时延 + 显存参考实现同错、未枚举的边界全部，尤其逐元素与短归约
批不变性/确定性kernel 自身不变量N_phys 倍重复执行 + 容差标定单样本内部错误、容差掩盖的错误归约、batched、含并行累加
形式验证规格（spec）翻译 + 求解时间，规格建模人力浮点等价定义、Triton 语义覆盖逐元素、短归约、安全性性质

组合判据可以写成一条决策链：先做安全性形式验证（越界、竞态、未定义行为），因为它的规格最成熟、代价最可控，且能拦住最危险的一类错误；再做批不变性检查，用不变量覆盖归约顺序与 batch 组合；最后用契约感知差分做数值等价，等价类按正交表分层，快轮只跑边界、慢轮跑全组合。这条链的代价是叠加的，但每一层的边际收益递减点不同——安全性验证的边际收益在第一个反例后就饱和，差分测试的边际收益随等价类数量对数增长。

具体例子：一个融合的 attention kernel，形式验证证明“所有 load/store 地址在界内、同步满足 happens-before”（分钟级，拦住越界与竞态）；批不变性检查用 batch=1/2/4/8 与不同 sequence 切分对比，发现 causal mask 在非 2 的幂长度下的尾部处理错误（ε_batch 超限）；差分测试在正交表上补测 dtype=fp16 与 denormal 输入，发现 exp 溢出处理与参考不一致。三层各自抓到不同类别的错误，没有一层能独立覆盖。

代价的工程量化：形式验证的翻译器开发是一次性成本，但每个新 kernel 形态都要补公理，边际成本不低；差分测试的等价类表可以跨 kernel 复用，边际成本随 kernel 数量摊薄；批不变性检查的容差标定需要按 dtype 与归约长度做一次，之后复用。因此对 agent 大规模生成 kernel 的场景，差分与批不变性是吞吐友好的主力，形式验证是抽样审计——对高风险 kernel（生产关键路径、含复杂同步）才上全称证明。

三条路线各自的失效面：契约审计、差分不变性与符号执行

三条路线并非同一保证的不同强度，而是三种不同性质的证据。契约感知审计把“正确”拆成可判定的谓词集合（形状整除、掩码覆盖、越界不写、dtype 提升规则），用生成器在边界格点上枚举输入，其失效条件是契约本身不完备——审计通过只说明声明的性质成立，未声明的批组合仍可出错，代价是组合爆炸带来的验证时延与 token 消耗（每个反例都要回灌给 agent 作为修复信号）。批不变性与确定性检查走差分路线：固定同一逻辑输入，改变 batch 切分与线程块划分，比较两次输出的逐位或容差一致性，机制上是把“并行归约顺序”当作被测量的变量；它抓得住归约树重排引起的漂移，却抓不住所有切分下都同错的系统性偏差，且逐位比较对合法浮点重排过于苛刻，需引入误差界。

$$ \big|\,\hat{y}_{b=1} - \hat{y}_{b=B}\,\big| \le \gamma_{n}\,|y|,\quad \gamma_{n}=\frac{n\,u}{1-n\,u} $$

其中 $u$ 为机器精度、$n$ 为归约链长度，$\gamma_n$ 给出前向误差的经典上界；实践中它常被放宽为经验容差，于是“通过”退化为统计性断言。第三条路线用符号执行或 SMT 对 kernel 的索引与算术建模，能给出全输入空间的证明，但失效条件最硬：浮点非结合性使等价性本身难以定义，工具对 CUDA/Triton 的同步、warp 语义与内建函数覆盖不足，建模开销随线程数增长，单次证明的编译与求解时间远超前两条路线，且模型与真实硬件语义的缝隙本身就是不可审计的风险。

路线证据类型主要失效条件系统代价
契约审计声明性质的枚举反例契约不完备格点组合爆炸、时延与 token
差分不变性切分间一致性系统性同错、容差掩盖多配置重跑、显存翻倍
符号执行全空间证明浮点语义与工具覆盖求解时间、建模人力

工程判断落在证据的叠加方式上：用契约审计覆盖边界与掩码类错误，用差分检查覆盖归约与切分敏感路径，仅在数值契约必须可审计时才把符号执行用于小规模核心片段，而不是对整 kernel 求解——把最贵的路线限制在误差界定义最清晰的那一层，才是三条路线共存的现实边界。
