一 · 三条路线在“同一问题”上的机制分叉

评测一个 kernel 是否“真快、真对、真可迁移”，同一道题至少有三条机制不同的技术路线：端到端黑盒测速（把 kernel 塞进完整模型或完整算子链，只量墙钟时间与输出一致性）、微基准白盒测速（固定输入形状、固定 launch 配置，单独量 kernel 本体，并用 SOL/roofline 归一化）、语义等价性验证路线（不追求速度数字，而是用多级 oracle 与变异测试判定实现是否在语义上等价于参考）。三条路线不是精度递进关系，而是观测对象不同：黑盒观测的是“系统在真实负载下的表现”，白盒观测的是“kernel 自身在理想口径下的上限”，验证路线观测的是“实现与规格之间的等价关系”。

机制差异首先体现在被测量的量上。黑盒路线的被测量是 T_e2e = T_launch + T_kernel + T_sync + T_framework，其中框架开销与同步开销往往与 kernel 无关，却随 batch、dtype、内存布局漂移；白盒路线的被测量被压缩为 T_kernel 本身，代价是必须人为固定 launch 配置与输入分布，从而引入“配置选择偏差”——同一 kernel 在不同 block size 下的最优值可能相差一个量级，而基准只记录其中一个点。验证路线的被测量根本不是时间，而是“在输入集合 X 上，f_impl(x) 与 f_ref(x) 的差异是否落在容差内”，其代价是输入集合的构造成本与 oracle 的误判率。

一个具体例子：同一个 reduction kernel，黑盒路线把它放进 LayerNorm 的完整前向里测，得到的数字被框架调度稀释；白盒路线单独 launch 并扫 block size，得到的是该 kernel 的 SOL 占比；验证路线则构造含 NaN、含极大值、含非连续 stride 的输入，判定实现是否在边界上仍等价。三条路线对“这个 kernel 好不好”给出的判断可以互相矛盾，而基准的可信度恰恰取决于能否说清这种矛盾来自机制而非实现。

二 · 测速口径的归一化：SOL 与 roofline 如何把三条路线拉到同一坐标系

跨路线比较的前提是把时间换算成无量纲的效率指标。roofline 模型给出上界：对给定计算量 F（FLOP）与访存量 B（Byte），在峰值算力 P 与峰值带宽 W 下，可达时间下界为

$$T_{\min} = \max\left(\frac{F}{P},\ \frac{B}{W}\right),\qquad \text{SOL} = \frac{T_{\min}}{T_{\text{measured}}}$$

SOL 的价值在于它把“快”从绝对时间变成了相对物理上限的比例，从而让不同 GPU、不同论文、不同路线之间的数字具备可比性——这正是跨架构数字不可比的直接解法。但 SOL 归一化本身有代价：它要求基准作者正确估计 F 与 B，而 B 的估计依赖于对 cache 行为的假设。若一个 kernel 的实际访存被 L2 大量吸收，用 HBM 带宽算出的 T_min 会偏大，SOL 被系统性高估。这是白盒路线特有的口径风险，黑盒路线因为不归一化反而“诚实但不可比”，验证路线则完全绕开该问题。

机制上，三条路线对 SOL 的依赖程度不同：白盒路线必须报告 SOL，否则单点时间无意义；黑盒路线通常报告相对基线的加速比 T_base / T_impl，其可信度取决于基线选择是否随意——这正是 KernelBench 系基准被诟病的核心之一；验证路线不报告 SOL，但它的结论会被白盒路线引用为“这个 SOL 是在语义等价前提下取得的”。三者构成一条证据链：验证路线保证“对”，白盒路线保证“快得有上限解释”，黑盒路线保证“快得能落地”。任何一环缺失，评测器都会把“能跑”误判为“真快”。

代价的具体形态：SOL 归一化需要额外一次 profile 采集（NCU 计数器读取），这引入测量时延与计数器复用开销；对短 kernel，NCU 的采样开销可能超过 kernel 本体时间，导致 SOL 失真。工程判断是：对 T_kernel 低于采样粒度的 kernel，改用批量重复 launch 摊薄开销，并在报告中标注摊薄倍数，否则 SOL 数字不可复现。

三 · 正确性 oracle 的分级机制与假阴/假阳的此消彼长

多级 oracle 的机制是按输入分布分层：随机输入层覆盖典型数值范围，边界输入层覆盖 dtype 极值与零附近，极端输入层覆盖 NaN/Inf、非连续 stride、空 tensor、超大 shape。每一层的判定逻辑不同：随机层用相对误差容差，边界层用绝对误差加 ULP 距离，极端层用“是否产生非法值”的布尔判定。分级的目的是让假阳（把错判成对）与假阴（把对判成错）在不同层上被分别压低，而不是靠单一容差硬扛。

假阴与假阳的此消彼长有明确的机制根源：容差 ε 放宽会降低假阴但抬高假阳，收紧则相反。设 oracle 判定为 |f_impl - f_ref| ≤ ε·|f_ref| + δ，则存在一个临界区间，实现恰好落在容差边缘——此时任何浮点重排（例如 reduction 的结合顺序改变）都会让判定翻转。这就是为什么“能跑”的 kernel 在换一个 block size 后可能被判错：不是实现变了，是误差累积路径变了。变异测试校准 checker 正是针对这一点：向参考实现注入已知语义变异（如漏掉一个边界分支、把 max 写成 min），检验 oracle 是否能捕获；捕获率低说明假阳高，误杀率高说明假阴高。

代价是双向的：变异测试需要为每个变异体跑完整输入集，成本随变异体数量线性增长，且变异体的构造本身需要领域知识，无法自动化到“随便改一行”。一个具体例子：对 softmax kernel 注入“未减去最大值”的变异，随机输入层可能因数值范围小而检测不到，只有极端输入层（含大值）才能触发溢出并暴露错误——这说明单层 oracle 的假阳率被输入分布掩盖，分级是必要的而非可选的。

三条路线在此处的分野：黑盒路线通常只做随机层比对（因为端到端跑不动极端输入），假阳率最高；白盒路线可以做边界层但受限于固定 shape；验证路线承担全部三层，代价是评测时间与变异测试成本。评测器的误判率量化，本质上就是在这三层上分别报告假阴/假阳，而不是给一个笼统的“通过率”。

四 · 泛化与知识迁移评测：三条路线在“可迁移”上的机制缺口

“真可迁移”要求 kernel 在未见过的 shape、dtype、架构上仍保持正确与效率。三条路线对此的机制缺口各不相同。黑盒路线天然覆盖真实负载，但它的输入分布由模型固定，无法主动探测迁移边界；白盒路线可以扫 shape，但扫的是离散网格，网格外的行为未知；验证路线可以构造任意输入，却不测量效率，因此无法回答“迁移后是否还快”。

机制上，泛化评测需要一个分布偏移协议：训练/生成阶段见过的 shape 集合 S_train 与评测集合 S_test 必须有可控的重叠度，且 S_test 需包含 S_train 中不存在的极值点。若 S_test 只是 S_train 的随机采样，测得的“泛化”只是插值能力；只有外推点才能暴露硬编码的 tile size、写死的 shared memory 容量、假设的对齐条件。代价是外推点上的失败率天然偏高，基准必须区分“因未优化而慢”与“因不正确而失败”，否则会把泛化失败误记为性能退化。

一个具体例子：某 kernel 在 S_train 内所有 shape 都达到高 SOL，但在一个非 2 的幂的 shape 上因 tile 边界处理缺失而输出错误。黑盒路线若测试集不含该 shape，会给出“通过且快”的结论；白盒路线若只扫 2 的幂网格，同样漏检；只有验证路线在极端输入层构造该 shape 才能捕获。这说明三条路线的组合不是冗余，而是互补的观测面：缺任何一面，评测器都会在某一类误判上失守。

知识迁移的机制更微妙：它要求 kernel 在架构间迁移时，其优化决策（如 warp 数、向量化宽度）仍成立。白盒路线通过 SOL 归一化可以跨架构比较，但 SOL 的分母 P、W 随架构变化，归一化后的数字掩盖了“该决策在新架构上是否仍最优”。代价是跨架构评测必须重跑 profile，无法复用旧数字；这也是跨论文数字不可比的根源之一。

五 · 三条路线的代价对照与工程取舍

把代价摊开对照，三条路线的取舍才清晰。下表只列机制性代价，不列具体数值：

路线被测量主要代价典型误判形态
黑盒端到端墙钟时间 + 输出一致性框架/同步开销污染、基线选择随意把框架优化误记为 kernel 优化
白盒微基准kernel 本体时间、SOL配置选择偏差、NCU 采样开销、SOL 分母估计误差单点最优被当作普遍最优
语义验证输入集上的等价性变异测试成本、容差临界区翻转容差边缘的假阳/假阴

工程取舍的核心问题是：评测预算花在哪条路线上。若目标是给 RL 提供可验证奖励，验证路线必须承担主力，因为奖励信号对假阳极度敏感——一个假阳会把错误实现推上高奖励，污染后续多轮迭代；代价是变异测试与多层输入集的评测时延，这直接压缩了单位时间内可评估的候选数。若目标是生产端到端收益判断，黑盒路线不可替代，但必须固定基线选择规则并报告框架开销占比，否则加速比不可解释。白盒路线适合做诊断与回归，不适合单独作为通过/失败判据。

一个具体取舍例子：对同一批候选 kernel，先用验证路线筛掉语义不等价的实现（成本高但假阳低），再对通过者跑白盒 SOL 排序（成本中），最后对头部候选跑黑盒端到端确认落地收益（成本高但样本少）。这个漏斗的机制是把最贵的观测留给最少的样本，同时保证每一级的误判不会级联放大。代价是漏斗前级的假阴会误杀好实现，因此前级容差需偏松、后级才收紧——这与“先严后松”的直觉相反，原因是假阴的代价（丢掉一个好 kernel）在漏斗中可被后级补救，而假阳的代价（让坏 kernel 通过）会污染整条链。

六 · 评测器误判率的量化：三条路线各自的校准点

量化评测器自身的误判率，需要在三条路线上分别定义校准点。黑盒路线的校准点是基线复现误差：同一基线在多次运行间的方差若与待测加速比同量级，则加速比不可信；机制上通过重复运行与固定环境（锁频、清 cache、固定 driver）压低方差，代价是评测吞吐下降。白盒路线的校准点是SOL 分母的可信区间：P、W 的估计误差直接传播到 SOL，需报告误差带而非单点；代价是每次评测多一次硬件标定。验证路线的校准点是变异测试的捕获率与误杀率：捕获率低意味着假阳高，误杀率高意味着假阴高，两者需同时报告，因为单一指标可被容差调节操纵。

机制上，三条路线的校准可以统一为一个误判率向量 (FP_black, FP_white, FP_verify) 与 (FN_black, FN_white, FN_verify)，基准报告应给出该向量而非“总体通过率”。这样做的代价是报告复杂度上升，但收益是可复现：读者能判断一个“通过”是在哪条路线上通过的，从而知道它排除了哪类误判、残留了哪类误判。工程判断落在具体机制上——若某基准只报告黑盒通过率，它的假阳主要来自框架开销与基线随意，读者应将其结论降级为“能跑”而非“真快”；只有当三条路线的校准点都被报告，评测器才具备区分“能跑”与“真快、真对、真可迁移”的资格。

三条路线的失效边界：oracle 越严，误判代价越高

多级 oracle、变异测试校准、SOL 归一化三条路线并非可叠加的免费午餐，各自的失效条件恰好互补。多级 oracle 的边界在输入分布：随机输入能捕获数值漂移，边界输入能捕获索引越界与掩码错误，极端输入（极大/极小 shape、非对齐 stride、空张量）能捕获分支与尾块处理缺陷；但三者都建立在“参考实现本身正确”这一前提上，一旦参考实现与目标 kernel 共享同一个数学近似（例如都用同一套低精度累加顺序），oracle 就退化为自证。变异测试校准的失效条件是变异算子与真实缺陷分布不匹配：注入的变异若集中在算术替换，checker 的检出率会被高估，而真实 agent 提交的错误更多来自同步缺失与共享内存竞争，这类变异需要构造并发时序才能触发，成本远高于算术变异。SOL 归一化的边界在 roofline 模型本身：当 kernel 的实际瓶颈是访存模式而非峰值带宽时，SOL 利用率会把“结构上不可能更快”的 kernel 判为低效，从而误伤正确实现。

$$\text{误判代价} = P(\text{假阳})\cdot C_{\text{污染}} + P(\text{假阴})\cdot C_{\text{漏检}},\quad C_{\text{污染}} \gg C_{\text{漏检}}$$

上式的工程含义是：在 RL 奖励链路里，假阳（错误 kernel 被判正确）会直接把污染写进奖励信号，其代价是整批训练样本的信用分配失效；假阴只是浪费一次候选，代价可控。因此三条路线的校准目标不对称——oracle 应偏向“宁可错杀”，变异测试应优先覆盖并发类缺陷，SOL 归一化则应把“结构上限”显式建模进分母，而不是用峰值带宽一刀切。具体例子：一个做 reduction 的 Triton kernel 在随机输入下与参考实现逐元素吻合，但极端输入下 block 数不足导致尾块未覆盖，多级 oracle 的极端输入层能拦住它；而同一 kernel 若被变异测试只注入算术变异，checker 会放行。系统代价方面，多级 oracle 的极端输入构造会增加单次评测的显存峰值与启动开销，变异测试的并发变异需要重复执行 kernel 多次，编译时间与测速时延同步上升；SOL 归一化本身几乎零成本，但它依赖的 profile 采集（NCU 计数器）会引入额外一轮执行，使端到端评测时延增加一个 profile pass。

路线失效条件主要代价
多级 oracle参考实现与目标共享近似极端输入显存峰值、启动开销
变异测试校准变异算子偏离真实缺陷分布并发变异重复执行、编译时间
SOL 归一化瓶颈非峰值带宽额外 profile pass 时延

三者的组合顺序也有工程判断：先用变异测试把 checker 的假阳率压到可接受区间，再用多级 oracle 做输入维度的兜底，最后用 SOL 归一化把“快”从绝对时延转成结构利用率——顺序颠倒会让 SOL 的低效判定先污染候选池，使真正正确的慢 kernel 在进入 oracle 之前就被筛掉。跨架构不可比的问题在这一层体现得最直接：同一 SOL 利用率在不同 GPU 上对应不同的绝对时延，若基准不锁定测速口径与 profile 工具版本，三条路线的校准结果无法跨论文复用，评测器自身的误判率也就无法被独立复现。
