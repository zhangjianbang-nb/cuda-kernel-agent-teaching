一 · 一句话直觉与它到底约束了什么

把“浮点误差累积界”压缩成一句可操作的话：对 n 项求和，最坏情况下结果的绝对误差不会超过一个只与 n、单位舍入 u 和输入绝对值之和有关的量。朴素顺序求和的放大因子随 n 线性增长，树形/成对求和的放大因子随 log n 增长。这句话的价值不在于给出一个精确的误差值，而在于它把“kernel 重排归约之后还能不能过容差 oracle”从经验判断变成了可计算的判据：给定输入分布、给定归约拓扑、给定 dtype，你能在跑 kernel 之前就算出误差上界，再和 oracle 的容差比较。

严格定义如下。设真实和为 $s=\sum_{i=1}^{n}x_i$，浮点计算结果为 $\hat{s}$，单位舍入 $u=\epsilon_{\text{mach}}/2$（FP32 下 $u=2^{-24}$），则朴素求和的误差满足

$$\left|\hat{s}-s\right|\le \gamma_{n}\sum_{i=1}^{n}|x_i|,\qquad \gamma_n=\frac{nu}{1-nu},\qquad u=\frac{\epsilon_{\text{mach}}}{2}$$

这个界有三个结构性特征，读的时候必须抓住。第一，它是绝对误差界，右端乘的是 $\sum|x_i|$ 而不是 $|s|$——这意味着正负相消的输入会让相对误差爆炸，界本身却依然成立（它只是变得很松）。第二，$\gamma_n$ 里的 $n$ 是参与舍入的运算次数，不是元素个数；树形归约的深度是 $\lceil\log_2 n\rceil$，所以放大因子从 $nu$ 降到 $\log_2 n\cdot u$ 量级。第三，$1-nu$ 的分母是一个警戒线：当 $nu$ 逼近 1 时界发散，这对应“累加器精度已经不足以表达部分和”的情形，此时界不再有信息量。

把它落到 kernel 语境：一个 reduction kernel 把 4096 个 FP32 元素从“每线程串行累加 32 个再跨线程树形合并”改成“每线程串行累加 128 个再合并”，串行段长度从 32 涨到 128，串行部分的放大因子线性涨 4 倍，而跨线程树形部分的 log 因子基本不变。误差界的总预算是两段之和，改动归约拓扑等于在两项之间重新分配预算。这就是为什么 kernel 优化（改变 block 大小、改变每线程元素数、改变是否用 warp shuffle）会直接移动误差界，而不是“实现细节不影响数值”。

二 · 为什么 kernel agent 必须显式持有这个界

在 LLM 生成 kernel 的流水线里，正确性判定通常落在一个容差 oracle 上：把 agent 产出的 kernel 输出与参考实现（PyTorch eager 或手写 baseline）逐元素比较，允许 $|a-b|\le \text{atol}+\text{rtol}\cdot|b|$。这个 oracle 的通过/失败是 RL 的可验证奖励信号，也是部署前的准入门槛。问题在于：参考实现本身也有误差，agent 的重排归约又引入新的误差，两者叠加后的偏差是否落在容差内，是一个必须先算清楚的问题。如果不算，会出现两类系统性错误。

第一类是假阴性：agent 写出了一个数值上完全合法、甚至更稳定的树形归约，但因为参考实现是朴素顺序求和、两者在正负相消输入上偏差超过了人为设定的紧容差，被判为错误。奖励信号因此惩罚了正确的优化，这是典型的激励不相容——agent 学到的是“不要改归约顺序”，而不是“写出更快的归约”。第二类是假阳性：容差被放得很松（比如 rtol=1e-2），一个把 FP32 累加器偷偷换成 FP16 的 kernel 也能通过，部署到长序列 attention 或大 batch layernorm 上才暴露精度崩塌。误差界的作用是把容差从“拍脑袋常数”变成“由 dtype、n、归约拓扑推导出的区间”。

代价体现在三个地方。其一是token 与编译时间：agent 每轮生成后都要跑 oracle，如果容差判据不稳定，同一份 kernel 在不同随机种子下反复被判通过/失败，多轮 RL 的信用分配会被噪声淹没；显式算界可以把判据固定下来，减少无效重采样。其二是时延：为了压误差界而强制使用 Kahan 补偿求和或 float64 累加器，会让 reduction 的算术强度翻倍甚至数倍，在带宽受限的 kernel 上直接把时延拉高——界告诉你“是否值得付这个代价”。其三是显存：混合精度累加（FP16 输入、FP32 累加器）需要额外的寄存器或 shared memory 暂存，占用率下降会反过来影响延迟隐藏，这是误差预算与性能预算的联合权衡。

具体例子：对一个长度 8192 的 FP32 softmax 分母求和，朴素顺序求和的 $\gamma_n\approx 8192\times 2^{-24}\approx 4.9\times10^{-4}$，乘以 $\sum|x_i|$（全为正，等于真实和）后相对误差界约 $5\times10^{-4}$；改成两路树形归约后放大因子降到约 $13\times2^{-24}\approx7.7\times10^{-7}$。如果 oracle 设 rtol=1e-5，朴素实现必然在边界附近抖动，树形实现稳定通过。这个计算在写 kernel 之前就能完成，不需要跑任何 GPU。

三 · 界的失效条件：三条必须写进判据的前置假设

这个界不是无条件成立的，把它当万能判据是工程上最常见的翻车点。三条前置假设必须在 oracle 里显式检查，否则界算得再准也是错的。

  • 无溢出、无次正规数：推导依赖每一步舍入的相对误差不超过 u，这要求中间部分和始终在正规数范围内。如果输入量级跨度大（比如 $10^{30}$ 与 $10^{-30}$ 混在一起），部分和会溢出为 inf 或落入次正规区，相对误差模型失效，界不再适用。kernel 侧的对应动作是检查输入的动态范围，或在归约前做 scaling。
  • FP16/BF16 累加需换模型：上面的 $\gamma_n$ 是按单一 dtype 的 u 推导的。混合精度（FP16 输入、FP32 累加）的误差来自输入转换误差与累加误差两部分，前者是 $O(u_{\text{FP16}}\sum|x_i|)$ 且与 n 无关，后者才是 $\gamma_n$ 项。直接用 FP32 的 u 去套 FP16 输入会低估误差几个数量级；反过来用 FP16 的 u 去估整个链路会高估。必须分段建模。
  • 条件数大的输入使相对误差远超界：界是绝对的，当 $\sum|x_i|\gg|s|$（正负相消）时，绝对界除以 $|s|$ 得到的相对误差可以任意大。此时单一相对容差 rtol 无法同时容纳“大和”与“小差”，必须改用相对-绝对混合容差 $\text{atol}+\text{rtol}\cdot|s|$，并让 atol 由 $\gamma_n\sum|x_i|$ 推出而不是拍一个常数。

代价在这里表现为判据复杂度：一个只做逐元素比较的 oracle 是 O(n) 时间、零额外显存；一个带前置假设检查的 oracle 需要额外一趟求 $\sum|x_i|$、检查 inf/nan/次正规、判断 dtype 组合，时间翻倍、需要额外的归约缓冲区。在 KernelBench 这类基准上，这意味着每个候选 kernel 的验证时延上升，进而压缩多轮 RL 中每单位时间能评估的候选数。工程判断是：把 $\sum|x_i|$ 与条件数估计做成一次预计算（对固定输入只算一次），而不是每个候选 kernel 重算。

四 · 常见误解：界是上界，不是预测值

第一个误解是把界当成“实际误差会接近这个值”。$\gamma_n\sum|x_i|$ 是最坏情况的上界，实际误差通常小一到两个数量级，因为舍入误差有正有负、部分相互抵消。用界去反推“实测误差应该是多少”会得出错误结论；界的正确用法是做可行性判定——如果连上界都超过容差，这个 kernel 一定过不了；如果上界远小于容差，可以放心通过；只有上界跨在容差两侧时，才需要实测。

第二个误解是认为“树形归约一定比朴素求和准”。在无相消、量级均匀的输入上这个结论成立；但在极端动态范围下，树形归约的中间节点可能先溢出，而朴素求和的累加顺序反而让大数先合并、小数被吞掉但不溢出。界只描述舍入放大，不描述溢出，所以“更小的 $\gamma_n$”不等于“更鲁棒的 kernel”。这也是为什么前置假设检查必须独立于界存在。

第三个误解是把 n 当成元素个数。对一个二维 reduction，如果 kernel 先沿行归约再沿列归约，参与舍入的运算次数是两段之和而非乘积；如果用了 split-K 再合并，合并阶段的 n 是 split 数而不是总元素数。误用 n 会让界高估或低估一个数量级。具体到伪代码层面，正确的做法是沿归约树逐层累加放大因子：

$$\gamma_{\text{total}}\approx\sum_{\text{level}}\gamma_{n_{\text{level}}}$$

其中每一层的 $n_{\text{level}}$ 是该层实际发生的串行加法次数（树形层为 1，串行段为段长）。这个逐层求和的思路比套一个全局 n 更贴近 kernel 的真实执行结构，代价是需要 agent 或编译器把归约拓扑显式暴露出来——这也是为什么 Triton/CuTe 的归约实现比手写 CUDA 更容易做误差预算：拓扑在 IR 层面可见。

第四个误解是把界当成 dtype 的属性而不是“dtype + 拓扑 + 输入分布”的联合属性。同一个 FP32 kernel，输入全正时相对误差界约 $nu$，输入正负各半时相对误差界可以放大到 $\sum|x_i|/|s|$ 倍。把界写死成“FP32 就是 1e-6”会在真实负载上系统性失效。工程上正确的做法是把界做成 oracle 的一个函数：输入 dtype、归约拓扑、$\sum|x_i|$、$|s|$ 四个参数进去，容差出来。

线性界为什么在 kernel 归约里先崩：边界、失效条件与系统代价

这个界最容易被误读成“误差随 n 线性增长，所以 n 越大越危险”。真正决定它能否作为 oracle 判据的，不是 n 本身，而是界右侧的 Σ|x_i| 与左侧 |ŝ−s| 是否在同一量纲上可比。朴素串行求和的误差上界写成 γ_n·Σ|x_i|，其中 γ_n=nu/(1−nu)、u=ε_mach/2，FP32 下 u 约为 2^-24。注意 γ_n 的分母：当 nu 逼近 1 时界发散，这并非数值爆炸，而是模型本身失效——它假设每一步舍入都被 |x_i| 加权放大，一旦 n 大到 nu 不再是小量，这个一阶模型就不再是“上界”而只是形式上的符号游戏。在 kernel 里 n 是 block 内元素数乘以归约层数，一个 1024 线程的 block 做树形归约，n 的有效量级是 log2(1024)=10 层而非 1024 次串行加，这正是成对求和能把线性换成对数的机制来源；但若代码写成每个线程串行累加 32 个元素再跨线程归约，n 就同时包含 32 的串行段与 10 的树形段，界的形状是分段的，不能用一个 γ_n 一概而论。

失效条件必须写进 oracle 的实现里，而不是留在文档里。该界只对无溢出、无次正规数的情形成立：一旦中间累加出现 inf 或 denormal，舍入不再是相对误差意义上的 u 量级，界的推导前提（每次运算的相对误差不超过 u）直接崩塌，此时 |ŝ−s| 可能远大于 γ_nΣ|x_i| 而 oracle 仍判“通过”，这是最危险的假阴性。FP16/BF16 累加需要换混合精度误差模型：BF16 只有 8 位尾数，u 比 FP32 大约三个数量级，且累加器若仍是 BF16，γ_n 会迅速吃掉全部有效位；工程上的做法是累加用 FP32、输入用低精度，此时界要按“输入量化误差 + FP32 累加误差”两项叠加，而不是套用单精度 γ_n。更隐蔽的是条件数大的输入：正负相消使 Σ|x_i| 远大于 |s|，界本身仍然成立，但相对误差 |ŝ−s|/|s| 会被 Σ|x_i|/|s| 放大，绝对界看着宽松、相对判据却早已失守，因此容差必须是相对-绝对混合形式，例如 tol = atol + rtol·Σ|x_i|，把界的右侧直接搬进判据，而不是拍一个固定 1e-5。

系统代价体现在三处，且都与“界是否可信”直接挂钩。其一是判据的 token 与编译开销：把 γ_nΣ|x_i| 作为 oracle 的一部分，需要在 host 侧或 kernel 内额外计算 Σ|x_i|，这是一次与归约同规模的遍历，等于把主 kernel 的带宽代价翻倍；若在 kernel 内用原子加维护该和，还会引入串行化点，在小 block 上直接吃掉归约本身的吞吐。其二是重排带来的正确性代价：树形归约把界从线性压到对数，但要求所有部分和按固定配对顺序合并，任何为了 occupancy 而做的动态调度、warp 内 shuffle 顺序变化，都会让实际误差落在不同常数上，界仍成立但 oracle 的容差余量被压缩，重排越激进、余量越薄。其三是低精度路径的显存与精度权衡：用 FP32 累加器意味着寄存器压力上升，block 内归约的寄存器占用翻倍会压低 occupancy，反过来又迫使更小的 tile，n 变小、界变紧，看似有利，实则把并行度换成了串行段，界的形状又回到分段混合。一个具体例子：对长度 4096 的向量做 FP16 输入、FP32 累加的 block 归约，若 Σ|x_i| 因正负相消达到 |s| 的 10^3 倍，即便 γ_n 在树形下只有几十个 u，混合容差的绝对项也必须按 10^3·u·Σ 的量级给足，否则正确 kernel 会被误判为错——这正是把界当判据时最常见的工程翻车点。

$$\mathrm{tol}=\mathrm{atol}+\mathrm{rtol}\cdot\sum_{i=1}^{n}|x_i|,\qquad \mathrm{rtol}\gtrsim\gamma_{n}$$

把这张表读成一句话：界的可信区间由“有限性 + 精度模式 + 条件数”三者共同圈定，任何一项越界，γ_nΣ|x_i| 就从判据退化为装饰。工程判断上，oracle 应当先做有限性与精度模式分派，再按输入条件数动态选择 rtol 的量级，而不是对所有 kernel 套同一个容差；代价是每次评测多一次 Σ|x_i| 归约和一次条件数估计，换来的是把假阴性与假阳性都压到可解释的范围内——这比事后调容差便宜得多。
