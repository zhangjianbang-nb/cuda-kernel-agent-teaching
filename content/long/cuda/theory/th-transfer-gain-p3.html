一 · 增益公式的隐含前提：可加性与同口径

公式 $G_{\text{transfer}}=(s_{\text{target}}^{\text{after}}-s_{\text{target}}^{\text{before}})/s_{\text{target}}^{\text{before}}$ 在代数上只是一次比值，但它在工程上成立需要三个隐含前提，缺一即失效。第一是同口径：$s_{\text{after}}$ 与 $s_{\text{before}}$ 必须由同一个评分函数、同一套正确性 oracle、同一计时协议给出。若 before 用的是宽松的数值容差而 after 换成了严格容差，分子里就混进了评分口径变化，而非迁移增益。第二是可加性：公式默认目标任务得分的变化可以被归因为“源任务知识”这一项，但真实 pipeline 里同时发生了 prompt 变化、检索上下文变化、采样温度变化、编译选项变化。第三是分母非零且稳定：$s_{\text{before}}$ 若本身处于噪声区间（见计时噪声与置信区间条目的口径），比值会把噪声放大成虚假增益。

机制上，工程上可操作的做法是把 $G$ 拆成可归因的分量：固定评分与 oracle、固定采样预算与编译 flag，只让“是否注入源任务经验”这一个变量变化，做配对实验。伪代码思路是：对每个目标题 $i$，跑 $k$ 次采样得到 $s_i^{\text{before}}$ 与 $s_i^{\text{after}}$ 的分布，先算配对差 $\Delta_i$，再聚合。若只报均值 $G$，等于把配对结构丢掉，方差被低估。代价是 token 与编译时间翻倍：每道题要跑两组、每组 $k$ 次，且每次都要真实编译与计时，单题成本约为单组实验的两倍以上；对 KernelBench 规模的题集，这是可观的时间预算。

具体例子：某目标题 before 得分 0.62、after 得分 0.58，$G=-6.5\%$；若 after 那次恰好换了更严格的浮点容差，正确性判定收紧导致得分下滑，这 −6.5% 就被误读为“负迁移”，而实际是口径漂移。判断依据不是符号，而是配对差是否落在该题计时与判定噪声的置信区间之外。

二 · 分布差异：负迁移的第一类失效条件

给定事实明确指出：源/目标任务分布差异大时增益为负。这里的“分布”不是抽象的数据分布，而是 kernel 生成任务的结构分布——算子族（elementwise、reduction、matmul、attention）、shape regime（小 batch 延迟受限 vs 大 batch 带宽受限）、dtype、内存层级访问模式。MetaKernelBench 实测双向迁移为 −19%~+29%，说明同一对源/目标在方向反转时符号可以翻转，增益不是对称量。

机制上，负迁移来自“错误先验的强注入”：源任务上学到的优化模式（例如对 reduction 用大量 shared memory 分块）被当作默认策略迁移到目标任务的 elementwise 题上，反而引入了不必要的同步与占用率损失。公式层面可以把 $G$ 写成源任务策略在目标任务上的期望收益减去其引入的失配代价：

$$G_{\text{transfer}} \approx \underbrace{\mathbb{E}_{t\sim T}\left[\Delta s_{\text{match}}(t)\right]}_{\text{可迁移部分}} - \underbrace{\mathbb{E}_{t\sim T}\left[\Delta s_{\text{mismatch}}(t)\right]}_{\text{失配代价}}$$

当失配代价的期望超过可迁移部分，$G<0$。这个分解的工程价值在于：它提示我们不该问“迁移好不好”，而该问“目标任务中有多大比例落在源任务策略的适用域内”。代价是显存与带宽层面的：错误的分块策略会推高 shared memory 占用、压低 occupancy，进而拉长时延；这类代价在 profile 上表现为 stall 归因从 memory throttle 转向 barrier，可与 Warp Stall 归因分解条目的口径对接。

具体例子：源任务是批量较大的 matmul（计算受限），目标任务是 batch=1 的 decode 阶段小算子（延迟受限）。把 matmul 的大 tile 策略迁过去，单题时延反而上升，$G$ 为负；而反向迁移（把延迟优化的小 kernel 经验带到 matmul）同样可能因占用率不足而退化。这正是 −19%~+29% 双向区间存在的结构性原因，也是每模型/每方向仍有 16%–45% 题目退化的来源。

三 · 硬件与 dtype 漂移：迁移的物理边界

给定事实：硬件或 dtype 变化会破坏迁移，需要重新验证。这不是保守条款，而是硬约束。kernel 的性能结论高度依赖具体的 SM 数量、寄存器文件大小、shared memory 容量、L2 容量、HBM 带宽与指令吞吐比例。一个在 A 卡上达到高 SOL 的分块参数，换到 SM 数更少或带宽/算力比不同的卡上，roofline 拐点位置移动，最优 tile 直接失效。

机制上，tile 尺寸的选择本质是在占用率与数据复用之间求平衡，其可行域由硬件资源约束界定：

$$\text{occupancy} = f\left(\frac{\text{regs per thread}\times\text{threads per block}}{\text{regs per SM}},\ \frac{\text{smem per block}}{\text{smem per SM}}\right)$$

硬件变化改变分母，可行域随之收缩或扩张；dtype 变化则改变每次访存的字节数与向量化宽度，进而改变带宽利用率的实际上界。FP32 迁到 BF16 时，同样的向量化宽度下每条指令搬运的元素数翻倍，若代码仍按 FP32 的 unroll 因子组织，就会出现指令发射不足或寄存器压力反转。代价体现在编译时间与验证成本上：每次硬件或 dtype 变更都必须重跑正确性 oracle 与计时，不能复用旧结论；对多卡、多 dtype 的评测矩阵，验证成本随维度乘积增长。

具体例子：某 kernel 在 FP32 下用 128 线程块、每线程 8 元素向量化达到带宽上限附近；迁到 BF16 后同样配置下每线程实际搬运字节减半，带宽利用率下降，$s_{\text{after}}$ 低于 $s_{\text{before}}$，$G$ 为负——但这是 dtype 漂移导致的配置失配，不是知识本身无效。正确做法是把 dtype 作为迁移适用域的一个显式维度，跨 dtype 迁移必须重新调 tile 与 unroll，再谈增益。

四 · 样本量与置信区间：均值增益的统计上限

给定事实：样本量小时置信区间很宽，不能只看均值。这条直接限定了 $G$ 的可报告边界。MetaKernelBench 的 −19%~+29% 是聚合量，但每个模型/方向仍有 16%–45% 的题退化，说明题目层面的方差极大，聚合均值对单题预测力很弱。

机制上，若把每题配对差 $\Delta_i$ 视为独立样本，均值增益的标准误为 $\mathrm{SE}=\sigma_\Delta/\sqrt{n}$，置信区间半宽随 $1/\sqrt{n}$ 收缩。当 $n$ 很小（例如只跑十几道题），半宽可能与被测增益同量级，此时“$G=+8\%$”与“$G=0$”在统计上不可区分。工程判断应是：报告 $G$ 时必须同时报告 $n$、$\sigma_\Delta$ 与区间；若区间跨零，不得宣称正迁移。

$$\hat{G}\pm z_{1-\alpha/2}\cdot\frac{\sigma_\Delta}{s_{\text{before}}\sqrt{n}}$$

代价是 token 与算力：把 $n$ 提高四倍才能把区间半宽减半，而每题都要真实编译、计时、跑 oracle，成本线性上升。另一个隐性代价是选择偏差——在小样本上挑出“最好的一次”报告，等价于对噪声做最大化，$G$ 被系统性高估。这与奖励黑客的激励不相容条目同源：只要评价口径允许挑样本，优化压力就会流向挑样本而非真提升。

具体例子：某方向 20 道题，均值 $G=+6\%$，但配对差标准差较大，区间为 $[-4\%,+16\%]$；同时该方向有约三分之一的题退化。此时正确结论是“该方向迁移增益不显著，且存在稳定的退化子集”，而不是“迁移有效”。退化子集本身才是下一步优化的信号：定位这些题的结构特征（shape regime、dtype、算子族），据此收窄适用域。

五 · 适用域的工程刻画：从“是否迁移”到“迁移到哪里”

把上述失效条件合并，可以得到一个可操作的适用域判据：迁移增益为正，当且仅当目标任务中落在源任务策略适用域内的题目比例足够高，且硬件与 dtype 未漂移，且样本量足以把区间压到零的一侧。这三条对应三个可测量的量：适用域覆盖率、硬件/dtype 一致性标记、配对差的置信区间。

机制上，工程上应把 $G$ 从标量升级为带条件的函数 $G(\text{算子族},\text{shape regime},\text{dtype},\text{硬件})$，并在每次迁移前先做一次“适用域探测”：用少量目标题跑 before/after 配对，估计覆盖率与退化子集的位置，再决定是否全量迁移。伪代码思路是分层采样——按算子族与 shape regime 分层，每层至少若干题，先算层内 $G$ 与区间，只有区间整体为正的层才纳入迁移范围。代价是探测阶段本身的编译与计时开销，以及分层带来的样本量需求上升；但相比全量迁移后才发现负增益，这个前置成本更低。

具体例子：把源任务的 reduction 经验迁向目标任务时，先按“是否计算受限”分层。计算受限层内 $G$ 为正且区间不跨零，延迟受限层内 $G$ 为负且退化题集中在小 shape。于是适用域被刻画为“计算受限的 reduction 子集”，迁移只在该子集启用，其余题目走默认策略。这样既保留了 +29% 一侧的收益，也避开了 −19% 一侧的损失。

规模上限也由此显现：适用域覆盖率随目标任务与源任务的分布距离单调下降，当覆盖率低于某一阈值时，聚合 $G$ 必然转负，此时继续扩大迁移规模只会放大失配代价。工程判断应落在“先测覆盖率、再定迁移范围”，而不是把迁移当作默认开启的全局开关。

增益公式在哪些条件下会从“正”翻成“负”

跨域迁移增益界的形式本身很朴素：$$G_{\text{transfer}}=\frac{s_{\text{target}}^{\text{after}}-s_{\text{target}}^{\text{before}}}{s_{\text{target}}^{\text{before}}},\qquad G\in[-1,+\infty)$$ 它的下界被 −1 钉死（目标任务得分不可能跌成负数），上界却敞开，这已经暗示了一件事：增益的分布是右偏的、非对称的。工程上真正要防的不是“增益不够大”，而是“增益为负且幅度可观”。MetaKernelBench 实测的双向迁移区间 −19%~+29% 说明，同一套源任务知识，在方向 A→B 上可能是正收益，在 B→A 上却可能是净损失；更关键的是，即便在整体均值为正的方向上，每个模型仍有 16%–45% 的题出现退化。也就是说，均值掩盖了一个长尾：一部分题被迁移“带坏”了，而均值被另一部分题的强正增益拉回。用均值做部署决策，等于用右偏分布的中位数去赌尾部风险。

第一个失效条件是分布差异。迁移的隐含假设是源任务与目标任务共享某种可复用的结构——相同的访存模式、相同的并行分解、相同的数值稳定性约束。一旦这个假设破裂，源任务上学到的“最优 tile 尺寸”“最优 unroll 因子”“最优 shared memory 布局”就会变成目标任务的负迁移先验：agent 带着一个在源域被验证过的模板去写目标 kernel，模板里的常量（比如按源域 dtype 位宽算出的向量化宽度、按源域 SM 数算出的 grid 规模）在目标域直接失配，编译器不会报错，但生成的 SASS 会多出冗余的 predicate 与寄存器溢出。代价是可测量的：寄存器压力上升导致 occupancy 下降，occupancy 下降又反过来压低带宽利用率，最终在 roofline 上从带宽受限区滑向延迟受限区。这类退化不会体现在“能否编译通过”上，只会体现在 NCU 的 achieved occupancy 与 DRAM throughput 两个计数器上，因此正确性 oracle 全绿并不等于迁移成功。

第二个失效条件是硬件或 dtype 变化。这是最容易被低估的一条，因为它不改变算法、只改变执行环境。同一个 Triton kernel 在 dtype 从 fp16 切到 bf16 时，尾数位宽变化会改变归约的数值误差累积路径，原本“误差可忽略”的假设需要重新验证；同一个 CuTe 布局在 SM 架构换代后，warp 调度粒度与 shared memory bank 结构变化会让原本无冲突的 swizzle 变成有冲突。迁移增益界在这里的失效方式是静默的：$s_{\text{after}}$ 与 $s_{\text{before}}$ 都还在合法区间内，但两者的差已经不再反映“知识迁移”的效果，而反映“环境漂移”的效果。工程判断是：任何硬件或 dtype 变更都必须把迁移增益重新测量，而不是把旧增益当作常量沿用。重新验证的代价是编译时间与 profile 采集时间——每个候选 kernel 都要重跑一轮 NCU，这在多轮 RL 的 rollout 预算里是实打实的 token 与时延开销。

第三个失效条件是样本量。$G$ 是一个比值型统计量，分母 $s_{\text{before}}$ 本身带噪声，比值会把噪声放大。样本量小时，置信区间极宽，均值几乎不携带信息。举一个具体场景：在 KernelBench 系基准上，某方向只跑了少量题目，均值显示 +8%，但逐题看有相当比例的题落在负区间——此时“均值 +8%”与“多数题退化”可以同时成立，因为少数题的强正增益撑起了均值。表格里可以直观看到这种撕裂：

因此适用边界的工程表述应当是条件化的：增益界只在“源目标分布足够接近、执行环境未漂移、样本量足以压窄置信区间”三者同时成立时才可作为决策依据；任一条件破裂，公式就从“预测工具”退化为“事后描述工具”。规模上限也由此而来——当目标任务集合扩大到覆盖多种 dtype 与多种 SM 架构时，单一 $G$ 值不再有意义，必须按 dtype×架构分桶分别测量，桶内样本量不足时只能给出区间而非点估计。这也解释了为什么迁移增益不能作为跨域 agent 的唯一奖励信号：它奖励的是“均值好看”，而不是“尾部可控”，而生产端到端收益恰恰由尾部决定。
