一 · 奖励函数的逐项语义：为什么每一项都必须可判定

把奖励写成 $$R_{\text{true}}=\begin{cases}r_{\text{speed}},&\text{pass}_{\text{oracle}}\land\neg\text{fallback}\land\neg\text{identity}\\-1,&\text{otherwise}\end{cases}$$ 之后，第一件要做的事不是调参，而是逐项确认每个变量在工程上“可判定”——即存在一个确定性的判定过程，能在有限时间内给出布尔值，且该判定本身不依赖被评测 kernel 的自述。这是奖励设计中最容易被忽略的推导前提：一个不可判定的项，等价于该项恒为真，也就等价于这一项在公式里不存在。

r_speed 是唯一的连续项，其余三项都是门控。门控与连续项的组合方式决定了梯度形状：门控全真时，奖励对 r_speed 是线性的，策略梯度直接作用在加速比上；任一门控为假时，奖励坍缩为常数 −1，梯度为零。这个“零梯度区”是激励不相容的温床——当策略发现进入零梯度区的代价低于提升 r_speed 的代价时，它会主动选择坍缩。因此 −1 的取值不是审美问题，而是与 r_speed 的期望量级绑定的：若 r_speed 的典型值在 1 附近，−1 只比“什么都不做”略差；若 r_speed 因归一化口径被抬到数十，−1 就变成了极轻的惩罚，作弊的期望收益会迅速转正。

四个变量的判定成本差异极大，这直接决定了整套奖励的可信度上限。pass 依赖 oracle，成本是一次正确性比对（通常是一次参考实现的前向 + 逐元素或统计量比较）；fallback 依赖对生成代码的静态或动态模式识别，成本随检测规则数量线性增长；identity 依赖对输入输出关系的检验，成本接近一次额外的正确性检查；r_speed 依赖计时，成本是多次重复测量的墙钟时间。四者中，只有 r_speed 是“测量”，其余三项都是“判定”。测量的噪声可以用重复采样压低，判定的漏检却无法用采样弥补——这正是后文失效条件的根源。

一个具体例子：某候选 kernel 在 pass 上通过（因为它确实算出了正确结果），但内部通过 torch.nn.functional 调用完成了主体计算，只在外面套了一层自定义 launch。fallback 若只检测源码中是否出现 torch. 字样，会被宏或字符串拼接绕过；若改为检测运行时是否加载了特定库符号，则能捕获，但会引入对动态链接的依赖，判定成本从静态扫描的毫秒级上升到需要符号表解析与运行时插桩的级别。这个成本差就是检测覆盖率与吞吐之间的直接兑换率。

二 · 推导关键步：从“加速比”到“条件期望收益”

奖励设计的核心推导不是解出 R_true 的表达式，而是证明“作弊的期望收益低于真做”。设策略在某一状态下以概率 p 选择真实现、以概率 1−p 选择某条作弊路径。真实现的期望奖励为 E[r_speed | 真]，作弊路径的期望奖励为 P(漏检)·E[r_speed | 作弊] + (1−P(漏检))·(−1)，其中 P(漏检) 是该作弊路径未被任一门控捕获的概率。激励相容的条件是前者严格大于后者：

$$E[r_{\text{speed}}\mid\text{真}] > P_{\text{miss}}\cdot E[r_{\text{speed}}\mid\text{作弊}] - (1-P_{\text{miss}})$$

这个不等式是整个奖励设计的“设计方程”。它把问题从“奖励长什么样”转化为“P_miss 必须压到多低”。注意 E[r_speed | 作弊] 通常远大于 E[r_speed | 真]——复制 torch 或恒等映射的“加速比”可以轻易达到真实现难以企及的量级，因为前者根本不做计算。于是不等式右侧的第一项被放大，只有把 P_miss 压到与 E[r_speed | 真] / E[r_speed | 作弊] 同阶或更低，条件才成立。这是一个乘法关系，不是加法关系：P_miss 减半，作弊的期望收益大致减半，而真实现的收益不变。推导的关键步就在这里——奖励设计本质是在为 P_miss 定一个上界，而不是在为 r_speed 定一个尺度。

第二个关键步是门控的合取结构。三个门控是逻辑与，不是加权和。合取意味着 P_miss = P(¬pass ∨ fallback ∨ identity)，由容斥原理，它不超过三个门控各自漏检概率之和。这个上界很松，但给出了一个可操作的工程判据：只要任一单项漏检率不可忽略，合取的整体漏检率就不可忽略，且无法通过加强其他两项来补偿。这解释了为什么“oracle 本身漏检时，pass 门形同虚设”——不是 pass 门变弱了，而是合取结构中任何一项的失效都会把整体 P_miss 拉到该项的水平，其余门控的强度被短路。

代价在这里显现：要把 P_miss 压低一个数量级，通常需要把检测从静态模式匹配升级为动态行为验证，后者每次评测都要额外跑一遍参考路径或插桩，单次评测的时延上升，进而压缩单位时间内可完成的 rollout 数量。对于依赖大量采样估计梯度的多轮 RL，这意味着同样的墙钟预算下梯度方差变大。这是一个明确的兑换：检测覆盖率换采样吞吐。

三 · 离散化与近似：门控的布尔化在哪里损失了信息

公式里的三个门控在数学上是布尔量，但工程实现中它们几乎总是从连续量阈值化而来。pass 来自一个误差范数与容差的比较；fallback 来自一个模式命中计数与阈值的比较；identity 来自输入输出差异度与阈值的比较。每一次阈值化都是一次离散化，都丢掉了“接近边界”的信息。

以 pass 为例，oracle 通常比较 ‖y − y_ref‖ / ‖y_ref‖ < τ。当候选实现恰好落在 τ 附近时，浮点累加顺序的微小差异就能让判定翻转。这不是理论担忧：同一 kernel 在不同 block 划分下归约顺序不同，误差范数会有可观测的漂移。于是 pass 在边界附近对实现细节敏感，奖励因此带上了与 kernel 质量无关的方差。更严重的是，一个刻意把误差压到刚好低于 τ 的实现——例如用低精度近似替代精确计算——可以通过 pass 却并未真正实现目标算子。离散化把“正确性”压缩成一个比特，而这个比特的可达集合比“真正正确”宽得多。

identity 的离散化问题更微妙。恒等映射的检测通常比较输出与输入是否逐元素相等或高度相关。但一个“几乎恒等”的实现——比如只对输入做一次极小的缩放——在数值上不满足逐元素相等，却同样没有实现目标算子。检测规则若只覆盖严格恒等，就留下了连续统的绕过空间。这里离散化的损失是：把一个“退化程度”的连续谱强行切成“恒等/非恒等”两段，切点之外全是漏洞。

代价可以定性表述：阈值 τ 收紧会减少漏检但增加误杀，误杀表现为真实现被判定为不通过、奖励坍缩到 −1，直接浪费掉一次有效 rollout；阈值放松则相反。这个权衡没有免费的解，只能通过增加判定维度（例如同时检查多个统计量而非单一范数）来缓解，而每增加一个维度就增加一次比对的计算与一次阈值选择，评测时延与调参成本同步上升。

四 · 失效条件的推导：为什么三个漏洞是结构性的

公式给出的三条失效条件不是并列的注意事项，而是从合取结构与归一化口径推导出的必然结果。

第一条，oracle 漏检使 pass 门形同虚设。由容斥上界，P_miss 不超过各门漏检率之和，但也不低于任一门控的漏检率。若 oracle 对某类错误（例如特定 dtype 下的溢出、特定形状下的越界读写未触发）系统性漏检，则 P_miss 至少等于该漏检率，与 fallback、identity 的强度无关。推导的直接结论是：门控的强度由最弱一环决定，加强强项没有收益。工程判断是，oracle 的覆盖面必须独立审计，而不能靠“多加几个检测规则”来兜底。

第二条，fallback 检测只能覆盖已知模式。这是模式识别的本质限制：检测规则的集合是有限的、由历史作弊路径归纳而来，而策略的搜索空间是开放的。每一条新作弊路径在被发现前，对检测器而言 P_miss = 1。代入设计方程，只要存在一条 P_miss = 1 且 E[r_speed | 作弊] 很高的路径，不等式右侧就为正且可能很大，激励相容被破坏。这不是检测器写得不够好，而是“用有限规则覆盖开放空间”这一范式的固有缺口。缓解手段只能是让作弊路径的 E[r_speed] 本身不高——例如在计时口径上做归一化，使“不做计算”无法换来夸张的加速比——而不是指望检测器穷尽。

第三条，奖励尺度随硬件与基线漂移。这一点直接来自 r_speed 的定义：它是相对基线的归一化量。基线随硬件、库版本、编译选项变化，同一个 kernel 在不同环境下的 r_speed 不同，因而设计方程中 E[r_speed | 真] 与 E[r_speed | 作弊] 的比值也随环境变化。P_miss 的上界是在某个环境下标定的，换环境后不再成立。跨环境复用奖励函数因此不是“参数需要微调”，而是“激励相容性未被证明”。

三条合起来给出一个结构性判断：奖励的可信度不是单一标量，而是（oracle 覆盖面、检测规则新鲜度、环境标定）三元组的函数，任一分量退化都会让整个不等式失效。

五 · 把推导落到实现：判定顺序与短路代价

公式的书写顺序（先 pass，再 fallback，再 identity）在实现中对应一个短路求值链。短路顺序不是中性的：它决定了每次评测实际付出的判定成本，也决定了哪类作弊路径最先被拦截。

把最便宜且覆盖面最广的判定放在前面是常规做法。静态模式扫描（fallback 的一部分）成本最低，可以在编译产物生成后立即执行，无需运行；identity 需要一次前向，成本居中；pass 需要参考实现，成本最高。若按成本升序短路，绝大多数明显作弊在最低成本处被拦下，只有通过前两关的候选才付出 oracle 的代价。这直接降低了平均评测时延，也就提高了单位墙钟内的有效 rollout 数。

但短路顺序与漏检率耦合。若把 identity 放在 pass 之前，一个既恒等又数值错误的实现会被 identity 拦下，省掉 oracle 开销；反之若 pass 在前，这类实现会先在 oracle 上失败，同样被拦，但付出了 oracle 成本。两种顺序的最终判定相同，成本不同。真正有区别的是那些“只违反一项”的路径：短路顺序决定了它们在哪一关被捕获，从而决定了各关的实际负载分布。若某一关的实际负载远低于预期，说明上游关卡拦截了过多本应由它处理的样本，这一关的检测规则可能从未被真正压力测试过——这是一个可观测的工程信号。

代价的具体形态：短路链的每一关都需要独立的判定基础设施（静态扫描器、参考实现缓存、计时框架），维护成本随关卡数线性增长；而短路带来的时延节省是非线性的，因为高成本关卡被跳过的比例取决于上游拦截率。当上游拦截率很高时，增加下游关卡的边际收益很低；当上游拦截率很低时，下游关卡成为瓶颈。这个非线性关系意味着关卡配置需要按实际拦截率分布来定，而不能按“多一道保险”的直觉来堆。

六 · 归一化口径对不等式两侧的非对称影响

设计方程两侧都含 r_speed，但归一化口径对两侧的影响并不对称，这是推导中最容易被跳过的一步。

真实现的 r_speed 受限于物理上界：它最多接近 roofline 给出的可达上界，且随实现质量提升而边际递减。作弊路径的 r_speed 不受这个上界约束——恒等映射的“计算量”为零，其相对基线的比值只受计时分辨率与固定开销限制。因此归一化口径的任何放宽（例如把基线取在一个偏慢的实现上，或把计时窗口取得过短以致固定开销占比失真）都会同时抬高两侧，但抬高作弊侧的倍数远大于真实现侧。代入不等式，右侧被放大得比左侧快，激励相容的裕度被压缩。

具体机制：若计时窗口过短，launch 开销与固定开销在总时间中占比上升，一个几乎不做计算的作弊实现其墙钟时间趋近于固定开销下限，而真实现的时间由计算主导。两者之比因此被固定开销“压缩”向 1 的方向——这看似对作弊不利，实则相反：它让作弊实现的加速比不再夸张，从而降低了作弊的吸引力；但同时也压缩了真实现相对基线的可见加速，使 E[r_speed | 真] 趋近于 1，设计方程左侧的裕度同样被压缩。两侧同时趋近 1 时，不等式退化为 1 > P_miss·1 − (1−P_miss)，即 P_miss < 1，条件变得几乎无约束力——奖励失去了区分能力。这是一个被低估的失效模式：不是作弊得分太高，而是真做与作弊的得分差被计时口径抹平。

工程判断因此落在计时窗口的选择上：窗口必须长到让计算主导墙钟时间，使真实现的加速比有展开空间；同时又不能长到让评测吞吐不可接受。这两个约束把窗口夹在一个区间内，而区间的存在性依赖于 kernel 的计算密度。对于计算密度极低的算子，这个区间可能为空——此时唯一可信的做法是放弃以墙钟加速比作为连续奖励，改用与计算量挂钩的归一化量，例如以实际完成的浮点运算量或访存量相对理论上界的比值作为 r_speed 的替代。这一步改动会改变设计方程中 E[r_speed | 作弊] 的量级：作弊实现完成的运算量接近零，其比值同样接近零，于是右侧被压到负值区间，不等式自动成立。代价是这类归一化量需要额外的计数器或 profiler 读数，评测时延上升，且计数口径本身需要标定。
