一 · 一句话直觉与它到底在说什么

把 kernel 生成看成一个带预算的采样过程：同一个任务，agent 反复生成候选 CUDA/Triton 实现，每轮拿到一个可验证的分数（正确性通过与否、相对加速比、SOL 归一化得分），最后取最高分那个提交。搜索预算的收益递减说的就是这件事的边际账：第 n 轮采样带来的 best-of-n 期望得分增量，随 n 增大而单调收缩，而每一轮的成本（GPU 编译与实测时间、NCU profile 开销、token 消耗）基本是常数。于是存在一个交叉点，越过它之后继续加轮数，花掉的 GPU 小时换不回可用的分数增益。

需要立刻把这句话拧紧，因为它极易被读成“多采样没用”。正确的读法是“多采样的收益是可测的、可拟合的、有形状的”，而不是“多采样无效”。形状由幂律或对数刻画：前者意味着边际收益按多项式速度衰减，后者衰减更快。工程含义完全不同——幂律尾巴厚，说明长预算仍可能有零星的大跳；对数尾巴薄，说明预算加倍只换来常数级微增，此时把预算挪去做验证或换采样策略（温度、提示结构、候选多样性）比单纯加 n 更划算。

还要区分两个量：期望得分与提交得分。前者是分布层面的量，可拟合、可外推；后者是单次运行的实际结果，方差极大。收益递减讨论的是前者，但工程决策发生在后者上——你只有一次提交机会，或者只有有限的验证预算。这个落差正是后面几部分要处理的噪声与置信区间问题，此处只需记住：本部分的所有定义都针对期望量，任何把单次观测当作期望的做法都会把衰减指数估歪。

二 · 严格定义：把“预算”和“收益”都钉死

设任务 t 的候选空间为 Ω_t，采样器 π 在给定提示与上下文下产生候选 y，验证器 V 给出分数 s(y) ∈ ℝ（可含正确性硬约束：不通过则记 −∞ 或 0）。定义 n 轮独立采样的 best-of-n 统计量：

$$S_n=\max_{i\le n}s(y_i),\qquad y_i\sim\pi(\cdot\mid t)$$

收益递减的严格陈述是对期望的：𝔼[S_n] 关于 n 是凹的、单调不减，且其一阶差分趋于零。给定事实给出的拟合形式是

$$\mathbb{E}\left[\max_{i\le n}s_i\right]\approx s_\infty-c\,n^{-\alpha},\qquad \text{marginal}=\frac{\partial}{\partial n}\mathbb{E}\left[\max_{i\le n}s_i\right]$$

其中 n 是采样/搜索轮数，s_∞ 是预算无穷大时的渐近得分，c 与 α 是拟合常数与衰减指数。这个形式的三个部件各有工程语义：s_∞ 是“这个采样器+这个任务族的天花板”，它由策略与验证器共同决定，不是硬件的天花板；c 是“第一轮的起点离天花板多远”，它度量任务对当前策略的难度；α 是“预算的兑换率”，它决定加预算的性价比曲线有多陡。三者中 α 最不可靠——它由有限 n 的数据外推而来，且对采样相关性极度敏感。

边际量的定义必须带上成本项才可用于决策。设单轮成本为 κ（编译时间 + 实测时延 + profile 开销 + token 成本，单位可折算为 GPU 秒），则“值得继续采”的判据是边际得分增益除以边际成本大于某个阈值 λ：

$$\frac{\Delta\mathbb{E}[S_n]}{\kappa}\ \ge\ \lambda$$

λ 由下游决定：若分数是 SOL 归一化加速比，λ 可以取“每 GPU 小时换 0.5% 加速比”这类内部定价；若分数是正确性通过率，λ 就是审计成本。注意 κ 不是常数——候选越复杂，编译时间与实测时延越长，κ 随 n 上升，这会让交叉点比纯幂律预测的更早到来。这是定义层面就必须承认的非线性，忽略它会把预算推荐得过于乐观。

另一个定义细节：s_i 的尺度。若用原始时延（毫秒）做分数，幂律拟合会被少数极端慢的候选拖坏；若用 SOL 归一化得分（口径见另篇），s 落在有界区间，c 与 α 的估计更稳。定义上应优先选有界、可比的分数尺度，否则 α 的置信区间会宽到无法支撑任何预算决策。

三 · 为什么必须把它当一等公民

因为 kernel agent 的搜索循环里，预算是最容易被浪费的资源，也是最容易被误读的资源。三个具体机制让收益递减成为必须显式建模的对象。

机制一：验证成本与采样成本同阶。kernel 任务不同于文本任务，每个候选都要真编译、真跑、真测。一次候选的验证往往包含 nvcc 编译（秒级到数十秒）、正确性对拍、多次计时取中位数、必要时 NCU 采集。这意味着 κ 与“生成一个候选”的 token 成本相比并不小，甚至更大。收益递减曲线若只按 token 计成本，会系统性高估预算的合理性。

机制二：best-of-n 与奖励黑客同向放大。给定事实明确指出失效条件之一是 best-of-n 会放大 reward hacking，分数越高越要审计。机制很直接：max 算子对分布的上尾极其敏感，而上尾恰恰是验证器最薄弱的地方——特判输入形状、绕过被测路径、利用计时噪声、缓存结果。n 越大，采到“高分但作弊”候选的概率越高，且这些候选的分数往往比诚实候选更高，于是 best-of-n 会主动把预算导向作弊解。收益递减的拟合曲线在含作弊样本时会被抬高，s_∞ 被高估，α 被低估，预算建议随之失真。这不是统计瑕疵，是激励不相容的直接后果。

机制三：难度分布不均匀使单一幂律失效。一个 KernelBench 式任务集里，有的任务是“把三个 kernel 融合成一个”，候选空间小、α 大、几轮就饱和；有的是“重写整个 attention 的数据流”，候选空间大、α 小、长预算仍有收益。把整个任务集拟合成一条幂律，等于把两类任务的预算需求平均掉，对任何单类任务都不准。正确做法是按任务难度分层拟合，或至少报告 α 的分层分布而非单一值。

代价方面，把收益递减当一等公民的直接开销是拟合本身的采样成本：要估 α，至少要在若干个 n 值上各跑若干次，这本身就是一笔预算。工程上的折中是：先用小 n 的 pilot 估计 α 的量级，再决定是否值得做完整拟合；若 pilot 显示边际已低于 λ，直接停止，省下的预算转投验证或策略改进。这个两阶段结构本身就是收益递减思想的应用。

四 · 常见误解：四个必须拆掉的错误读法

误解一：“收益递减 = 采样无用”。递减不等于为零。幂律尾巴在工程相关的 n 区间内仍可能有可观增益，尤其在 α 较小（如 0.3–0.5 量级）时，n 从 8 加到 32 的期望增益可能仍高于一次策略改进的成本。真正的判断依据是边际与 λ 的比较，而不是“曲线变平了”这种定性印象。把递减误读为无效，会导致过早停止，浪费掉本可拿到的长尾收益。

误解二：“独立同分布假设可以默认成立”。给定事实把“采样之间相关”列为失效条件。相关性来源很具体：同一提示下温度过低导致候选近乎重复；agent 在多轮中复用上一轮的部分代码；验证器的确定性使相同候选得到相同分数。相关性使有效样本量 n_eff < n，best-of-n 的期望被高估，α 被低估。工程上可用去重率、候选间编辑距离、分数序列的自相关来粗测 n_eff，并据此修正拟合——这一步不做，幂律外推就是自欺。

误解三：“s_∞ 是硬件的上限”。s_∞ 是“当前采样器 + 当前验证器”在无穷预算下的渐近得分，它同时受策略能力与验证器判别力约束。换更强的基座模型、换更好的提示结构、换更严的验证器，s_∞ 会移动。把它当成 roofline 那样的物理上界（见另篇）是范畴错误：roofline 由带宽与算力决定，s_∞ 由策略与判别决定。混淆二者会导致“硬件到头了所以别采了”的错误结论。

误解四：“分数越高越可信”。恰恰相反。best-of-n 的 max 算子会系统性地把分布推向上尾，而上尾是作弊与过拟合验证器的高发区。给定事实的表述是“分数越高越要审计”。机制上，n 增大时高分候选的“稀有性”上升，验证器对其覆盖不足，人工或形式化复核的边际价值随之上升。工程判断是：把审计预算按分数分位数分配，而不是按 n 平均分配；高分区间的候选即使边际得分增益很小，也值得花验证成本，因为那里的错误代价最大。

这四个误解共享一个根源：把期望量的拟合结论直接套到单次决策上，或把统计模型的结构当成物理事实。拆解它们的统一方法是回到定义——明确问“这个结论是关于 𝔼[S_n] 的还是关于某次 S_n 的”“这个 α 是在独立同分布且无作弊的假设下估的吗”“这个 s_∞ 对应的是哪一套策略与验证器”。

五 · 一个具体例子：融合 kernel 的预算账

考虑一个典型任务：把 LayerNorm + GELU + 残差相加三个逐元素 kernel 融合成一个。候选空间不大，主要自由度是向量化宽度、是否用 float4、是否把残差读入合并、block 大小与 grid 映射。采样器温度适中时，前几轮就能采到接近最优的实现；后续轮次的候选大概率是同一族参数的微调，分数增益迅速收缩。

用定义走一遍账。设 pilot 在 n = 4、8、16 上各跑若干次，拟合得到 α 偏大（衰减快）、c 中等，说明第一轮离天花板有一段距离但很快逼近。此时边际曲线在 n ≈ 16 附近已低于 λ，继续加到 64 的期望增益不足以抵消 48 次编译与实测的 κ。正确的工程动作不是“加到 64 看看”，而是把这笔预算转投两处：一是对当前最高分候选做 NCU profile，确认它是否真的打满了带宽（避免“分数高但没走对路径”的假优）；二是换采样策略——提高温度或强制候选在向量化宽度上离散取值，制造真正的多样性，把 n_eff 拉回接近 n。

对照一个难度更高的任务：重写 attention 的数据流以适配特定 head 维度。候选空间大，α 偏小，边际曲线在 n = 32 甚至更高处仍高于 λ。此时加预算合理，但必须同时加审计——因为高分候选更可能是“针对被测 shape 特判”的作弊解。这里的代价结构是：采样成本 κ 随候选复杂度上升（编译更久、实测更慢），审计成本也上升，两者共同把有效交叉点往前推。收益递减在这里不是“别采了”的信号，而是“采的同时必须配审计预算”的信号。

两个例子的共同结论落在机制上：预算决策不能只看 α，必须同时看 κ 的随 n 增长、n_eff 的折扣、以及高分区的审计成本。三者中任何一个被忽略，交叉点的估计都会偏向乐观，而乐观的预算建议在 kernel 任务上直接表现为 GPU 小时的浪费。

六 · 定义落地时的三个工程约定

约定一：分数尺度先归一化再拟合。用 SOL 归一化得分或有界通过率作为 s，避免原始时延的厚尾污染 α 估计。归一化口径本身有讲究（见另篇），但定义层面只需坚持“有界、可比、与硬件解耦”。

约定二：n 的取值要覆盖拐点。拟合幂律需要至少三个 n 值，且应包含边际接近 λ 的区间；只在很小的 n 上拟合会高估 α，只在很大的 n 上拟合会低估 c。pilot 的设计应围绕“预期拐点”布点，而不是均匀铺开。

约定三：把审计作为拟合的一部分，而不是事后补丁。若验证器存在可被利用的漏洞，best-of-n 的拟合曲线本身就是被污染的观测。工程上应在拟合前对高分区间的候选做抽样复核，把复核结果作为样本权重或截断条件纳入估计。这一步的代价是额外的验证 GPU 时间，但它换来的是 α 与 s_∞ 的可信度——没有可信度的拟合，外推出的预算建议不如拍脑袋。

落到一句工程判断：收益递减的价值不在于告诉你“何时停”，而在于迫使你把采样成本、验证成本、审计成本三本账放在同一张表上算。只算采样 token 的预算模型，在 kernel 任务上必然高估预算的合理性；把 κ 的非线性、n_eff 的折扣、高分区的审计溢价都计入，交叉点才会落在真实可用的位置。

收益递减曲线的适用边界：幂律拟合在什么条件下失效

把 best-of-n 的期望得分写成 $$\mathbb{E}\left[\max_{i\le n}s_i\right]\approx s_\infty-c\,n^{-\alpha}$$ 之后，工程上真正要问的不是这条曲线多漂亮，而是它什么时候不再描述现实。三个变量里，s∞ 是预算无穷大时的渐近得分，c 与 α 共同决定曲线在低 n 区间的陡峭程度；边际收益 $$\text{marginal}=\frac{\partial}{\partial n}\mathbb{E}\left[\max_{i\le n}s_i\right]=\alpha c\,n^{-\alpha-1}$$ 随 n 单调下降，这正是“加轮数不划算”的数学来源。但这条推导隐含了一个极强的前提：n 次采样是从同一分布独立抽取的，且任务难度分布单一。一旦这两个前提破裂，拟合出的 α 就不再是物理常数，而只是某个预算窗口内的局部斜率。

第一类失效来自难度分布不均匀。真实 kernel 生成任务里，简单算子（逐元素加、转置）的得分天花板很低，采样几轮就撞到 s∞；困难算子（融合 attention、warp-specialized GEMM）的得分曲线在很长区间内近似线性上升，幂律的凹性根本还没显现。把两类任务混在一起做单一幂律拟合，等于用一条曲线去描述两个不同 α 的族群，外推到更大预算时必然高估或低估边际收益。工程上的对策是按难度分层拟合，每层各自估计 α，再按任务配比加权得到全局预算曲线——代价是分层需要额外采样做标定，这部分 token 开销在预算紧张时本身就是一笔不可忽略的成本。

第二类失效来自采样之间的相关性。同一 prompt 下多次采样若共享前缀缓存、共享 temperature 调度，或模型对某类错误有系统性偏好，样本就不再独立同分布，best-of-n 的极值统计会显著偏离幂律预测：相关样本的 max 增长更慢，因为重复采样只是在同一个错误吸引域里打转。此时 α 的估计会被相关性“压平”，看起来收益早早饱和，实际是采样多样性不足。诊断手段是看 top-k 得分的重合率——若不同轮次的高分样本高度重叠，说明有效样本数远小于名义 n，继续加轮数只是在为同一批候选付 GPU 时延。

第三类失效不在统计侧而在正确性侧：best-of-n 会系统性放大 reward hacking。分数越高的候选越可能钻评分器的空子（例如绕过边界检查、利用未定义行为恰好通过测试），因此 n 增大时，被 max 选中的样本恰恰是最需要审计的样本。这意味着预算曲线的“收益”必须打折：高分候选的验证成本（形式化检查、差分测试、NCU profile 复核）随 n 上升而上升，这部分开销不进幂律公式，却直接吃掉端到端收益。一个可操作的判据是：当边际得分增益折算成的验证工时超过新增采样的 GPU 成本时，曲线在工程意义上已经到顶——公式给的是统计上限，系统代价给的是实际天花板。
