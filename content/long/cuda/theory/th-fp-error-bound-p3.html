一 · 界成立的三条前提：无溢出、无次正规、逐次舍入

γ_n 这个因子不是凭空出现的，它来自一个非常具体的推导链条：每一次浮点加法都被建模为 fl(x+y) = (x+y)(1+δ)，其中 |δ| ≤ u，然后把 n 次这样的扰动做乘积展开并丢弃二阶以上项，得到 (1+u)^n − 1 的上界，再除以 1−nu 得到 γ_n。这条链条要成立，必须同时满足三个前提，缺一个，界就不再是界，而只是一段“看起来像界”的算术。

第一个前提是无溢出。推导中默认每一步中间结果的指数都在可表示范围内，因此舍入只损失尾数位、不改变数量级。一旦某一步中间和溢出到 inf，后续所有加法都变成 inf 传播，误差不再是“有限倍数”，而是彻底失去意义。工程上的直接后果是：对 FP32 输入做归约时，若数据分布未知（例如未归一化的 logits、未裁剪的梯度），必须在 kernel 里先做一次缩放或分段，否则 γ_n·Σ|x_i| 这个量本身就已经是 inf，容差比较退化成 inf ≤ tol 的恒假命题。

第二个前提是无次正规数介入。次正规数的有效位数少于规格化数，其相对误差不再是统一的 u，而是随指数下降而恶化；此时“每次加法相对误差 ≤ u”的假设被打破，γ_n 的线性放大不再刻画真实行为。第三个前提是逐次舍入模型：它假设每一步只引入一次相对扰动，而 FMA 指令把乘加融合成一次舍入，实际扰动次数少于模型假设，因此界仍然保守成立；但反过来，若编译器把归约重排成树形又插入额外的类型转换（例如 FP32 累加器中间被降到 TF32），扰动结构就偏离模型，界需要重新推导。

代价体现在验证环节：为了让 oracle 的容差判定有意义，kernel 侧往往要加一段前置检查——扫描输入的最大绝对值与是否存在 inf/nan，这一步是 O(n) 的额外带宽读取。对一个大归约而言，这意味着多读一遍全局内存，在带宽受限的 kernel 上直接把有效吞吐砍掉一截；如果把它做成单独的 pass，还要多一次 launch 与一次中间缓冲写回。例子：对一个长度 2^20 的 FP32 向量求和，前置扫描读 4 MB、归约本身再读 4 MB，带宽开销翻倍，而收益只是让 γ_n 的界在数值上可计算。

二 · 规模上限：当 nu 逼近 1，界自己先崩掉

γ_n = nu/(1−nu) 的分母是这套界最脆弱的部位。当 n 增大到 nu 接近 1 时，γ_n 发散，界失去任何约束力；对 FP32，u ≈ 2^-24，理论上 n 要到 2^24 量级分母才显著偏离 1，看似遥远，但真正的约束不在分母，而在界的松紧度。

$$\gamma_n\sum_i|x_i| \;\approx\; n u \sum_i|x_i|$$

这个量随 n 线性增长，而真实误差在随机舍入下通常按 √n 增长（误差项近似独立同分布时方差相加）。于是界与真实误差之间出现一个 √n 量级的鸿沟：n = 2^20 时，界比典型误差松大约一千倍。这不是数学缺陷，而是最坏情况界的本质——它必须覆盖所有输入排列，包括刻意构造的“每一步舍入都朝同一方向”的对抗性序列。

工程判断由此而来：容差 oracle 若直接采用 γ_n·Σ|x_i| 作为阈值，在 n 较大时会把大量实际正确的重排归约判为失败，因为重排改变了求和顺序，误差确实变了，但远没有到界的量级。反过来，若把阈值收紧到 √n·u·Σ|x_i|，则对抗性输入会漏判。规模上限的真正含义是：γ_n 界适合做上界证明（保证不会错得离谱），不适合做等价性判据（判断两次求和是否在容差内一致）。

具体机制上，一个可操作的折中是分层判定：先用 γ_n 界做快速拒绝（超出即判失败，无需进一步分析），再对落在界内但在 √n 尺度外的样本做逐元素残差检查。代价是残差检查需要保留原始输入或做一次重算，显存与算力开销上升；对 KernelBench 式的端到端评测，这意味着 oracle 不再是纯后验比较，而要引入输入侧的前置统计量，评测流水线的状态变多、可复现性变差。例子：成对求和与朴素求和在 n = 2^16 上的差异通常落在 u·Σ|x_i| 的几倍之内，远低于 γ_n 界给出的 nu·Σ|x_i|，若 oracle 用后者，两者都会被判“通过”，判据实际上没有区分力。

三 · 混合精度累加：γ_n 模型整体失效

FP16/BF16 累加是这套界最典型的失效场景，且失效方式不是“界变松”，而是“界的结构不对”。γ_n 假设所有加法在同一精度下进行、单位舍入为常数 u；而混合精度累加（FP16 输入、FP32 累加器）的扰动结构是分层的：输入转换有一次舍入，累加在更高精度下进行、单位舍入更小，最后输出转换再舍入一次。三层扰动不能合并成一个 γ_n。

正确的做法是把误差拆成三段：输入量化误差（每项 ≤ u_in·|x_i|，与 n 无关但逐项累加）、累加器舍入误差（≤ γ_n·u_acc 形式，u_acc 远小于 u_in）、输出舍入（单次）。总界的主导项通常是输入量化，它随 Σ|x_i| 线性增长而不随 n 放大——这与朴素求和的 nu·Σ|x_i| 在 n 大时行为完全不同。若沿用 γ_n 公式，会同时高估累加段、低估量化段，两个错误方向叠加，界的可信度归零。

代价是评测口径的分裂：同一个 kernel 在 FP32 与混合精度两种模式下，oracle 需要两套容差公式，且混合精度那套依赖输入分布（量化误差与 |x_i| 的相对大小有关）。对 agent 生成的 kernel 做自动验证时，这意味着容差不能是全局常数，必须由 kernel 声明的累加精度与输入 dtype 共同决定，验证器要读取 kernel 的元信息而非仅比较输出。例子：BF16 只有 8 位尾数，u_in 比 FP32 大约 2^8 倍，即便用 FP32 累加，最终误差也由输入量化主导；此时把 γ_n 界套上去，得到的阈值比真实误差小两个数量级，正确 kernel 会被系统性误判。

四 · 条件数：正负相消让相对误差脱离界的管辖

γ_n·Σ|x_i| 是绝对误差界，它管的是“误差绝对值不超过多少”。但 oracle 通常关心相对误差 |ŝ−s|/|s|，而 |s| 可以远小于 Σ|x_i|。定义条件数 κ = Σ|x_i| / |Σx_i|，则相对误差界为 γ_n·κ。当输入存在大规模正负相消时，κ 可以任意大，γ_n 界在相对意义下彻底失效——不是界错了，而是界约束的量与判据需要的量不是同一个。

这是失效条件里最容易被 agent 忽略的一条：生成的 kernel 在随机正输入上通过容差，换到零均值、高方差的输入上就失败，而失败原因不是 kernel 写错了，是判据选错了。工程上的修法是相对-绝对混合容差：|ŝ−s| ≤ atol + rtol·|s|，其中 atol 取 γ_n·Σ|x_i| 的一个小倍数（覆盖绝对误差），rtol 覆盖条件数放大后的相对部分。混合容差的关键是 atol 必须由输入统计量算出而非拍脑袋，否则在 κ 大的样本上 atol 主导、判据退化成绝对比较，失去对重排误差的敏感度。

代价在评测吞吐上：计算 Σ|x_i| 与 |s| 需要额外一遍归约（或复用前置扫描的结果），并且混合容差使“通过/失败”不再是单一阈值比较，而是两次比较加一次条件判断，单样本判定成本上升。对大规模 KernelBench 扫描，这意味着 oracle 从纯 GPU 后验比较变成需要 CPU 侧统计量参与的混合流水线，吞吐受 PCIe 回传限制。例子：一个均值接近零、方差为 1 的 2^18 长向量，Σ|x_i| 约为 |s| 的数百倍，κ 达到数百，γ_n·κ 给出的相对界比实际相对误差松两个数量级以上，此时只有混合容差能把“重排导致的真实差异”与“界过松导致的假阳性”区分开。

五 · 界的适用域与验证器的责任边界

把上面几条合起来，可以得到一个明确的适用域判据：γ_n 界在（无溢出 ∧ 无次正规 ∧ 单一精度逐次舍入 ∧ κ 有界 ∧ n·u 远离 1）时是可信的上界；任一条件不满足，界要么失效、要么松到没有判据价值。验证器的责任不是无条件套公式，而是在 kernel 元信息与输入统计量上先做一次适用性检查，不满足就走替代模型（混合精度三段界、混合容差、或直接放弃界改用采样比对）。

这个检查本身有成本：它要求验证器在跑 kernel 之前就读输入（或读 kernel 声明的 dtype 与累加策略），把“先验比较”变成“先检查再比较”。对 agent 的迭代循环，这意味着每一轮验证都多一次输入扫描与元信息解析，单轮时延上升；但换来的是判据的可信度——没有适用性检查的 oracle，其通过率数字在不同输入分布之间不可比，跨轮次的奖励信号因此失真。例子：同一个重排归约 kernel，在随机正输入上通过率接近全通过，在零均值输入上通过率骤降，若验证器不记录输入统计量，这个差异会被误读成 kernel 不稳定，进而污染多轮信用分配。

最终落在一条工程判断上：γ_n 界是证明工具而非判据工具，它的价值在于给出“误差不会超过这个量级”的保证，从而让 oracle 的阈值有一个可辩护的上限；但把它直接当作等价性阈值，会在规模、精度、条件数三个维度上同时失真。可信的评测应当把界用作拒绝下界（超出即失败），把 √n 尺度的经验模型用作接受判据（界内且残差小即通过），并在 kernel 元信息层面强制声明适用域，让“这个界对这段代码成不成立”成为可检查的命题而不是默认假设。

适用边界：假设、失效条件与规模上限

γ_n 界成立的第一组前提是算术模型本身：每一次加法的相对误差不超过 u，且不出现溢出、不出现次正规数、不出现 FTZ 刷新。一旦 kernel 在 FP16/BF16 上做累加，这条前提直接断裂——半精度加法的单位舍入远大于 FP32，且累加器本身位宽不足，误差不再由 γ_n 刻画，而必须换成混合精度误差模型：输入量化误差、累加器舍入、以及最终上转 FP32 时的二次舍入三项分别计入。工程上判断是否越界的方法很直接：若累加器精度低于输入精度，γ_n 界即失效；若累加器精度不低于输入精度，γ_n 仍可作为上界使用，只是 u 取累加器精度对应的值。代价体现在寄存器与带宽：FP32 累加器使每线程占用翻倍，在 reduction 树较深时压低 occupancy，这是精度换来的显存与调度代价。

第二组前提是输入分布。γ_n·Σ|x_i| 是绝对误差界，它按各项绝对值之和放大；当输入存在正负相消时，真实和 s 远小于 Σ|x_i|，相对误差 |ŝ−s|/|s| 会被 Σ|x_i|/|s| 这个条件数放大，远超 γ_n 所暗示的量级。此时容差 oracle 若只设相对容差，会把正确重排判为失败，或把错误结果判为通过。正确做法是相对-绝对混合容差：|ŝ−s| ≤ atol + rtol·|s|，其中 atol 取 γ_n·Σ|x_i| 的量级，rtol 取条件数的倒数估计。代价是 oracle 需要额外一趟归约求 Σ|x_i|，在 n 很大时这趟归约的带宽开销与主归约同阶，等于把验证成本翻倍。

规模上限来自 γ_n = nu/(1−nu) 的分母：当 n 接近 1/u 时界发散，公式失去意义。FP32 下 u≈2^-24，n 的理论天花板在千万量级，但真正先触发的往往是树形求和的深度约束与寄存器压力，而非 γ_n 本身。下表给出不同求和结构下界随 n 的增长形态与主要系统代价：

求和结构误差增长主要代价
朴素串行γ_n，线性于 n延迟随 n 线性增长，无法并行
成对/树形γ_{log n}，对数于 n共享内存与同步开销，深度受限
Kahan 补偿与 n 弱相关每步额外 4 次浮点运算，寄存器翻倍

具体例子：一个 4096 项归约，朴素串行在 FP32 下 γ_n≈4096·2^-24≈2.4e-4，乘以 Σ|x_i| 后若输入量级为 1e3，绝对误差界约 0.24；改用树形归约后深度为 12，γ_{12}≈7e-7，界缩小三个数量级。但树形归约引入 log n 层同步，每层一次 shared memory round-trip，在小 block 上同步延迟可能超过串行求和的收益。因此适用边界的工程判断不是“树形一定更好”，而是：当 n·u 已接近容差阈值、且 block 内并行度足以摊薄同步开销时，重排才值得；否则 γ_n 界虽紧，换来的时延代价反而吃掉收益。

公式成立的三道门槛：溢出、次正规与条件数

γ_n 界的推导只用到一条性质：每次舍入的相对扰动不超过 u，且扰动不改变指数范围。因此它的适用边界首先由浮点数的动态范围决定，而非由 n 决定。当部分和 |ŝ| 越过 FP32 的最大正规数（约 3.4×10^38，由 8 位阶码决定），舍入模式从「就近取整到正规数」切换为「饱和到 ±Inf」，此后 γ_n 的归纳假设彻底断裂——误差不再是 u 的倍数，而是无穷大。次正规区间（指数域全零、有效位前导零）同样破坏模型：此时相邻可表示数的间距固定为 2^-149，相对误差界不再随 |x_i| 缩放，γ_n·Σ|x_i| 会给出一个偏小的、虚假的保证。工程上的判据是：在 kernel 内对部分和做一次指数范围检查（或利用 `__finite`/`isfinite` 谓词），把「界是否可信」作为一个布尔量随结果一起返回，而不是让容差 oracle 事后猜测。

第二道门槛是条件数。γ_n 界是前向绝对误差界，其右端以 Σ|x_i| 为尺度；当输入存在严重正负相消时，真值 |s| 远小于 Σ|x_i|，于是相对误差 |ŝ−s|/|s| 可以被放大到任意倍数，而绝对界依然「成立」。这正是混合容差必须写成 |ŝ−s| ≤ atol + rtol·|s| 而非单一 rtol 的原因：前者在相消场景下退化为 atol 主导，后者则会对一个绝对误差很小、相对误差巨大的结果误判为失败。对 kernel 重排归约而言，这意味着树形求和把 γ_n 从 O(n) 压到 O(log n) 只降低了绝对界，并不能挽救病态输入下的相对精度——重排改变的是求和顺序，不是问题的条件数。

第三道门槛是精度模式本身。γ_n 的 u = ε_mach/2 是 FP32 的 2^-24；一旦 kernel 用 FP16/BF16 累加（或 tensor core 的 FP32 累加器实际以截断方式工作），单次运算的误差不再是「相对 u 的扰动」，而可能是一次数量级更大的截断，此时必须换成混合精度误差模型：把高精度累加器视为精确、把低精度输入量化视为一次前置扰动，误差界写成 γ_n·Σ|x_i| + Σ|δ_i| 的形式，其中 δ_i 是输入量化误差。这条修正直接改变编译期决策——用 BF16 输入换吞吐，代价是 Σ|δ_i| 项进入容差预算，可能吃掉树形归约省下的那部分裕度。规模上限也由此显形：当 n·u 逼近 1 时 γ_n 发散，界失去意义，实际含义是「朴素求和的误差已与结果同量级」，此时唯一出路是分段补偿（Kahan/Neumaier）或提升累加精度，而非继续加大 n。
