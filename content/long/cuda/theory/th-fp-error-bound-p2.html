一 · 逐项拆解：这个界到底约束了谁

公式 $\left|\hat{s}-s\right|\le \gamma_{n}\sum_{i=1}^{n}|x_i|$ 的左侧是绝对误差，右侧是两个因子的乘积。第一个因子 $\gamma_n$ 只与运算次数和单位舍入有关，与数据无关；第二个因子 $\sum|x_i|$ 只与数据有关，与算法无关。这种“算法因子 × 数据因子”的乘积结构是整条推导的骨架，也是工程上最容易被误读的地方：很多人把 $\gamma_n$ 当成误差本身，实际上它只是一个放大系数，真正的误差量级由 $\sum|x_i|$ 决定。

$\gamma_n=\frac{nu}{1-nu}$ 的分子 $nu$ 是“最坏情况下 n 次舍入各自贡献一个 u”的线性叠加，分母 $1-nu$ 则来自误差自身的反馈：每一次舍入后的部分和本身已经带有误差，下一次运算又在这个带误差的值上继续舍入，于是误差按几何级数累积。把分母展开成 $1+nu+(nu)^2+\cdots$ 就能看出，当 $nu\ll 1$ 时 $\gamma_n\approx nu$，分母是可以忽略的修正项；但当 $n$ 大到 $nu$ 接近 1 时，这个界本身发散，说明该模型已经失效——这不是界的保守性，而是模型假设（误差不改变数量级）被破坏。工程含义是：对 FP32，$u=2^{-24}$，$n$ 要到 $10^{7}$ 量级分母才开始显著，普通 kernel 的归约长度远达不到，所以实际计算中几乎总是用 $\gamma_n\approx nu$ 这个简化形式；但对 FP16 累加，$u=2^{-11}$，$n$ 只需几千分母就不可忽略，这正是混合精度误差模型必须另起一套的原因。

$u=\epsilon_{\text{mach}}/2$ 的定义里那个 1/2 来自舍入到最近偶数（round-to-nearest-even）的对称性：一次舍入的相对误差不超过半个 ulp，即 $\epsilon_{\text{mach}}/2$。若硬件采用截断舍入（round-toward-zero），误差上界要翻倍，此时 $u=\epsilon_{\text{mach}}$，整个 $\gamma_n$ 随之翻倍。这是一个具体的机制性代价：同一个 kernel 在不同舍入模式下，oracle 容差需要按 2 倍余量设计，否则在截断模式下会误判为失败。

具体例子：一个长度 $n=4096$ 的 FP32 归约，输入全为同号且量级相近的 1.0，则 $\sum|x_i|=4096$，$\gamma_n\approx 4096\times 2^{-24}\approx 2.4\times10^{-4}$，绝对误差界约 $1.0$。若输入正负交替、$\sum|x_i|$ 仍是 4096 但真实和 $s$ 接近 0，则相对误差界被放大到无法使用——这就是条件数问题的入口，下一节展开。

二 · 推导关键步：归纳法里藏着的假设

推导的标准路径是对 n 做归纳。设 $\hat{s}_k$ 是前 k 项的部分和，$s_k$ 是精确部分和，归纳假设为 $|\hat{s}_k-s_k|\le \gamma_k\sum_{i\le k}|x_i|$。第 k+1 步计算 $\hat{s}_{k+1}=\mathrm{fl}(\hat{s}_k+x_{k+1})$，把这一步的舍入误差记为 $\delta_{k+1}$，满足 $|\delta_{k+1}|\le u\cdot|\hat{s}_k+x_{k+1}|$。关键的一步在这里：把 $|\hat{s}_k+x_{k+1}|$ 放大为 $|\hat{s}_k|+|x_{k+1}|$，再进一步放大为 $(1+\gamma_k)\sum_{i\le k}|x_i|+|x_{k+1}|$。这一步用了三角不等式，是整条推导中第一个“离散化/近似”发生的地方——它把带符号的部分和替换成了绝对值之和，代价是界对正负相消的输入完全失去区分能力。

第二个近似发生在合并 $\gamma$ 因子时：$(1+\gamma_k)(1+u)\le 1+\gamma_{k+1}$ 这一步依赖 $\gamma_{k+1}=\frac{(k+1)u}{1-(k+1)u}$ 的单调性，等价于把两个独立的相对误差因子乘起来后仍用一个统一的 $\gamma$ 覆盖。严格来说这一步要求 $ku<1$，否则分母为负、不等式方向翻转。这就是失效条件“仅对无溢出、无次正规数成立”的代数来源：一旦部分和溢出到 inf，$\delta$ 不再是相对量而是绝对量，$|\delta|\le u|\hat{s}+x|$ 这个前提直接崩溃；次正规数则让有效位数随数值减小而减少，$u$ 不再是常数，$\gamma_n$ 的常数系数假设失效。

第三个近似是“每一项的舍入误差独立且都取最坏值”的叠加。实际硬件中相邻项的舍入误差方向相关（尤其在同号输入下系统性偏向一侧），所以 $\gamma_n\sum|x_i|$ 是一个上界而非典型值。工程上这意味着：用这个界做 oracle 容差会偏保守，通过率被低估；反过来若用典型误差（约 $\sqrt{n}u\sum|x_i|$，随机游走模型）做容差，则会漏掉系统性偏置的失败案例。两种容差口径对应两种不同的验证策略，这是 kernel 评测中必须显式选择的口径，不能混用。

伪代码层面的推导骨架可以写成：对每个累加步，维护一个“误差预算”变量 $E$，初始为 0，每步更新 $E\leftarrow E(1+u)+u\cdot|x_{k+1}|$，最后 $E$ 就是界。这个递推的闭式解正是 $\gamma_n\sum|x_i|$。它的代价是每步一次乘加，若在 kernel 里真的实现这个预算追踪（用于运行时自检），开销约为归约本身的两倍，属于不可接受的时延代价；因此实践中只在离线分析或编译期静态推导时使用，运行时靠固定容差。

三 · 离散化与近似发生在哪：三个可指认的位置

第一个位置是把连续实数运算离散化为浮点运算时，用“一次舍入的相对误差不超过 u”替换了真实的舍入行为。真实硬件的舍入是确定性的、与尾数低位模式相关，而模型把它当成有界扰动。这个替换丢失的信息是误差的符号与相关性，代价是界无法预测系统性偏置。具体例子：对全 1 输入做朴素求和，实际误差往往单调累积而非随机抵消，模型给出的界仍然成立但远大于实测值，导致基于该界的容差 oracle 对这类 kernel 过于宽松。

第二个位置是树形/成对求和的推导中，把递归深度 $\lceil\log_2 n\rceil$ 当作误差累积层数。成对求和的界形如 $\gamma_{\lceil\log_2 n\rceil}\sum|x_i|$，这里的近似在于：每一层的加法次数不同（底层 $n/2$ 次、顶层 1 次），但推导把它们统一按最深路径的层数计。严格推导需要对每层分别计 $\gamma$，再用 $\sum$ 合并，结果仍是 $\log$ 量级但常数更紧。工程含义是：树形归约的误差界对 n 是对数增长，这就是 kernel 重排归约（把串行累加改成 warp shuffle 树形）后能通过更紧容差 oracle 的根本原因；代价是树形归约需要额外的共享内存或 shuffle 指令，时延上多出 $\log n$ 步的同步开销，但误差界从 $nu$ 降到 $\log n\cdot u$，对 $n=4096$ 是约 12 倍到 4096 倍的界收紧。

第三个位置是混合精度模型中对 FP16 累加的近似。FP16 的 $u=2^{-11}$，若直接套用 $\gamma_n$，$n$ 超过约 2048 时分母 $1-nu$ 显著小于 1，界迅速膨胀到无意义。实际做法是把累加拆成“FP16 乘 + FP32 累加”，此时误差来源有两部分：输入量化为 FP16 的误差（每项一次，与 $|x_i|$ 成正比）和 FP32 累加的 $\gamma_n$。合并后的界是 $\gamma_n\sum|x_i|+\sum|\Delta x_i|$，其中 $\Delta x_i$ 是量化误差。这个模型的近似在于假设量化误差与累加误差独立可加，忽略了量化后数值分布改变对累加误差的影响。代价是显存带宽减半（FP16 存储）换来的精度损失需要额外的容差余量，具体余量取决于输入动态范围。

用表格对比三种求和结构的界与代价：

结构误差界量级额外时延额外显存

四 · 条件数：界失效时相对误差的真实来源

公式给出的是绝对误差界，但 oracle 通常按相对误差判定。把绝对界除以 $|s|$ 得到相对界 $\gamma_n\sum|x_i|/|s|$，其中 $\sum|x_i|/|s|$ 就是求和问题的条件数。当输入正负相消、$|s|\ll\sum|x_i|$ 时，条件数可以任意大，相对误差界随之失控——这不是界的缺陷，而是问题本身病态。具体例子：交替符号的级数求和，$\sum|x_i|=n$ 而 $|s|$ 可能只有 $O(1)$，条件数为 $n$，相对误差界变成 $n^2u$，对 $n=10^5$ 的 FP32 已经超过 1，界完全失去意义。

工程应对是改用相对-绝对混合容差：判定条件写成 $|\hat{s}-s|\le \max(\tau_{\text{rel}}|s|,\tau_{\text{abs}}\sum|x_i|)$ 或等价形式。这样在 $|s|$ 大时用相对容差、在 $|s|$ 小时用基于 $\sum|x_i|$ 的绝对容差兜底，避免病态输入被误判。代价是容差参数从一维变成二维，标定需要两类输入样本：良态样本定 $\tau_{\text{rel}}$，病态样本定 $\tau_{\text{abs}}$。若只用单一相对容差，病态 kernel 的正确实现会被判失败（假阴性），而错误实现可能因为误差恰好落在相对容差内被判通过（假阳性），两种错误方向都会污染 RL 的可验证奖励信号。

另一个机制性细节：条件数大的输入对归约顺序极其敏感，树形归约与串行归约的结果可能相差远超 $\gamma_n\sum|x_i|$ 的预测，因为不同顺序对应不同的相消路径。这意味着对病态输入，重排归约后不能简单用原容差判定，必须重新标定。这是 kernel 优化中“重排改变数值语义”的具体体现，也是正确性 oracle 必须与实现结构解耦的原因。

五 · 从界到 oracle：容差参数怎么由公式反推

给定一个待验证的 kernel 和已知的 $n$、数据类型、归约结构，可以由公式直接算出理论界，再乘以安全系数作为容差。步骤是：确定 $u$（由数据类型和舍入模式定），确定 $\gamma_n$ 的形式（串行用 $nu$，树形用 $\log_2 n\cdot u$），估计 $\sum|x_i|$ 的上界（由输入生成器保证），三者相乘得到 $B_{\text{theory}}$，容差取 $\tau=k\cdot B_{\text{theory}}$，$k$ 是覆盖模型近似（相关性、非最坏叠加）的余量。这个流程的代价是：$\sum|x_i|$ 的上界估计需要输入分布的先验知识，若输入来自真实负载而非合成数据，上界可能难以紧致，导致容差过松、oracle 失去区分力。

反过来，若容差取得比 $B_{\text{theory}}$ 更紧，则任何符合模型的正确实现都可能被误判，因为界是上界而非典型值。这就是“容差不能低于理论界”的硬约束。具体例子：$n=1024$ 的 FP32 树形归约，$\log_2 n=10$，$B_{\text{theory}}\approx 10\times2^{-24}\times\sum|x_i|$，若 $\sum|x_i|=1024$ 则 $B_{\text{theory}}\approx 6\times10^{-4}$，容差取 $10^{-3}$ 量级是合理的；若错误地取 $10^{-6}$，正确 kernel 会被大量误判。

这个反推流程还有一个隐含假设：kernel 的归约结构与公式假设的结构一致。若 kernel 内部做了融合（比如把归约与后续逐元素运算合并），误差会跨算子传播，单一 $\gamma_n$ 不再覆盖，需要按算子链逐段推导再合并。合并规则是各段界的线性叠加（绝对误差可加），代价是界随链长线性变松，长链融合 kernel 的容差会显著大于单算子。这是端到端收益评估中必须计入的正确性成本：融合越多，容差越松，oracle 越难区分正确与近似正确。

$$\tau = k\cdot\gamma_{n}\sum_{i=1}^{n}|x_i|,\qquad \gamma_n=\frac{nu}{1-nu}$$

这个式子把“理论界”和“工程容差”用一个系数 $k$ 连接起来，$k$ 的取值反映的是对模型近似程度的工程判断，而不是数学推导的结果——这是公式与工程之间唯一需要人为裁量的接口。

六 · 界的可组合性与 kernel 评测中的实际落点

误差界最重要的工程性质是可组合：多个算子的绝对误差界可以直接相加，因为绝对误差满足三角不等式。这使得整条 kernel 链的容差可以由各段公式界相加得到，无需重新推导。代价是链越长界越松，且松的速度是线性的，对深融合 kernel 会迅速失去区分力。具体例子：三个连续归约算子，每段界为 $B$，链界为 $3B$，若每段实际误差只有 $0.1B$，则链容差 $3B$ 对单段错误的敏感度下降约 30 倍——一个段的实现错误可能被其他段的余量掩盖。

另一个落点是界的类型依赖性：FP32 与 TF32 的 $u$ 不同（TF32 尾数更短），同一个 kernel 在两种精度下的界相差数量级，容差必须按精度分别标定。BF16 的 $u$ 更大，且动态范围与 FP32 相同但精度低，混合精度模型中的量化误差项占主导，此时 $\gamma_n$ 项反而次要。这解释了为什么跨精度迁移 kernel 时不能沿用原容差：界的两个因子都变了，且主导项可能从累加误差切换到量化误差。

最后，界的存在性本身就是一个可验证信号：若实测误差超出 $\gamma_n\sum|x_i|$，说明要么实现有 bug（比如意外的截断舍入、非规格化数处理错误），要么输入触发了失效条件（溢出、次正规）。这个判据比“误差是否小于某个拍脑袋的容差”更有诊断力，因为它把失败归因到具体的模型假设上。工程上应把理论界作为 oracle 的第一道筛子，超出即报警，而不是直接判失败——报警触发的是对失效条件的检查，这才是可信评测的闭环。

界成立的三道门槛：溢出、次正规与相消

γ_n 的推导依赖一个常被忽略的前提：每一步舍入的相对误差都以 u 为上界。这个前提只在两个条件下成立——中间结果不溢出、不落入次正规区间。一旦归约的累加器在某个时刻越过 FP32 的指数上限，后续所有项都被 inf 吞掉，误差界退化为无意义的 inf ≤ inf；而当部分和进入次正规区，有效位数随指数下降，单步相对误差不再是 u 而是 u 的若干倍，γ_n 的线性叠加假设直接失效。工程上的判别方式是：在重排归约前先做一次量级扫描，估计 max|x_i| 与 n 的乘积是否逼近指数上限，若逼近则改用分段累加或先做缩放。代价是额外一遍全局读，对带宽受限的 kernel 意味着接近一倍的 HBM 流量，通常只在输入动态范围未知的通用路径上启用。

更常见的失效来自相消。界 γ_n·Σ|x_i| 是绝对误差界，它随 Σ|x_i| 增长，而真实结果 s 可能远小于 Σ|x_i|。当输入正负混合且条件数大时，|ŝ−s|/|s| 可以轻易超出 γ_n 数个数量级，此时用相对容差做 oracle 判定会把正确 kernel 判为失败。正确做法是相对-绝对混合容差：|ŝ−s| ≤ atol + rtol·|s|，其中 atol 取 γ_n·Σ|x_i| 的量级。这要求 oracle 端额外保存 Σ|x_i|，等于把一次归约变成两次归约（一次求和、一次绝对值和），在验证流水线上是实打实的时延翻倍，但换来的是判定不随输入符号分布漂移。

FP16/BF16 累加则要换一套模型：低精度加法的舍入单位是 u_h，但累加器若用 FP32，误差由“输入量化误差”与“累加舍入误差”两部分叠加，前者与 Σ|x_i|·u_h 同阶、后者与 γ_n·Σ|x_i| 同阶，不能简单把 u 替换成 u_h 了事。混合精度误差模型的推导关键步是把每次 cast 视为一次独立的相对扰动，再对扰动做一次树形聚合，得到的界比朴素线性界紧一个 log n 因子——这正是 kernel 重排归约后仍能通过容差 oracle 的数学依据。
