一 · 归因分解成立的三条隐含假设

把 C_stall 拆成 C_k 之和、再取占比 f_k，这个操作在数学上只是加法，但在工程语义上依赖三条假设，任何一条松动，占比就不再是“瓶颈份额”。第一条是互斥性：每个未发射周期恰好被记入一个类别。硬件计数器按 warp 调度器的状态机打点，一个周期里 warp 要么因 scoreboard 等待、要么因 barrier 阻塞、要么因 not_selected 被跳过，状态是单值的，所以互斥性在单 warp 粒度上成立。第二条是完备性：K 覆盖了所有未发射原因，没有落入“其他”的暗物质。第三条是可加性：各类周期相加等于总未发射周期，不存在重复计数。第三条最容易被忽视——某些 profiler 在指令取指失败（imc）与 short_scoreboard 之间存在重叠打点，同一个周期被两个计数器各记一次，此时 sum C_k > C_stall，占比之和超过 1，归因表直接失真。

工程上验证这三条假设的成本很低：先算 sum f_k，若显著偏离 1，说明计数器口径不一致或存在未归类 stall，此时任何“某类占比 40% 所以它是瓶颈”的结论都不成立。这个自检应当写进归因流水线的第一步，而不是事后人工比对。代价是每次 profiling 多一次求和与阈值判断，相对 NCU 采集本身的秒级开销可以忽略；但若跳过它，后续所有优化决策都建立在错误的份额上，代价是整轮 kernel 调优的方向性错误。

一个具体例子：某 reduction kernel 的归因表显示 long_scoreboard 占 52%、not_selected 占 30%、barrier 占 12%，三者相加 94%，剩余 6% 落在未列出的类别里。此时不能直接把 long_scoreboard 当作首要优化对象，因为 not_selected 的 30% 意味着调度器有大量周期“有 warp 可发但没发”，这本身就是占用率充足的信号——这一点在失效条件一节展开。

二 · not_selected 的语义陷阱：它不是瓶颈，是余量

not_selected 计数的是“调度器本可以发射某个 warp，但因优先级或轮转策略选择了别的 warp”的周期。它高，说明 SM 上常驻 warp 数量足以让调度器有选择余地，即占用率与延迟隐藏是充分的；它低，才说明 warp 供给不足、调度器被迫空转。因此 not_selected 与访存 stall 在归因语义上方向相反：前者是“资源冗余”的证据，后者是“资源饥饿”的证据。把两者放进同一张占比表按数值排序，是把“余量”误读成“瓶颈”，这是归因分解最常见的失效方式。

正确的处理是把 K 分成两组：饥饿类（long_scoreboard、short_scoreboard、wait、barrier、imc）与冗余类（not_selected）。瓶颈份额应当在饥饿类内部归一化：

$$f_k^{\text{hunger}}=\frac{C_k}{\sum_{j\in\mathcal{K}_{\text{hunger}}}C_j},\qquad \mathcal{K}_{\text{hunger}}=\mathcal{K}\setminus\{\text{not\_selected}\}$$

这样 long_scoreboard 的 52% 在剔除 not_selected 后的分母上会被放大，而 not_selected 的 30% 转化为一条独立诊断：“占用率充足，瓶颈在饥饿侧”。代价是这张归一化表不再满足“占比之和为 1 覆盖全部 stall”的直觉，需要在报表里显式标注分母，否则跨 kernel 比较时会误判。一个具体例子：两个 kernel 的 long_scoreboard 原始占比都是 40%，但 A 的 not_selected 是 5%、B 的是 45%；A 的真实饥饿份额约 42%，B 约 73%，B 的访存依赖问题远比 A 严重，而原始表把它们排成同一档。

三 · 采样误差：小 kernel 上占比是随机变量

采样型 profiler 并不逐周期记录，而是按固定间隔抽样并乘以放大系数还原计数。设采样周期为 s、kernel 实际执行 N 个周期，则有效样本数约为 N/s。占比 f_k 是二项比例的估计，其标准误近似为

$$\sigma(f_k)\approx\sqrt{\frac{f_k(1-f_k)}{N/s}}$$

当 N/s 只有几十个样本时，f_k 的置信区间宽度可达十几个百分点，两张归因表之间 5% 的差异完全落在噪声内。失效条件因此很明确：小 kernel（执行周期短、被采样次数少）上单次采样的占比不可用于排序，必须多次采样取中位数，并同时报告样本数。代价是 profiling 时间成倍增加——每个配置重复采集若干次，在 autotune 循环里会显著拉长单轮迭代的墙钟时间，进而压缩单位时间内可评估的候选数。

一个具体例子：某 elementwise kernel 单次执行仅覆盖少量采样点，第一次采集显示 barrier 占 18%，第二次显示 9%，第三次 14%。若只看第一次，会误判存在同步瓶颈并去合并 barrier；取中位数后 14% 落在噪声带内，真正的稳定信号是 long_scoreboard 的中位数占比，优化方向应转向访存合并而非同步消除。工程判断是：把“采样次数”和“样本数”作为归因表的一等公民字段输出，低于阈值时直接标记“不可排序”，而不是让下游 agent 拿噪声去驱动代码改写。

四 · 规模上限：当 kernel 短到计数器本身成为扰动

归因分解还有一条与规模相关的硬边界：profiling 插桩本身会改变被观测对象。计数器采集、序列化、flush 都占用周期与带宽，当 kernel 执行时间与插桩开销同量级时，测到的 stall 结构是“被观测的 kernel + 观测行为”的混合体。失效判据可以写成：若插桩开销占实测执行时间的比例超过某个工程阈值（例如一成量级），则归因表反映的是插桩后的行为，不能外推到生产路径。这条边界对小 kernel、高频调用的算子尤其致命——它们恰恰是 launch 开销与批量摊销问题的主战场，而归因分解在这里给出的份额可能整体偏移。

对应的缓解手段不是“更精细地采样”，而是改变观测粒度：把多次调用聚合进一个 profiling 窗口，让插桩开销被摊销到总周期上，代价是丢失单次调用的 stall 结构、只能得到稳态平均。这与批量摊销的取舍同构：观测窗口越长，相对扰动越小，但对瞬态行为的解析力越弱。工程上应显式记录窗口内的调用次数，并在归因表上标注“稳态口径”。一个具体例子：某小 kernel 单次执行极短，逐次 profiling 得到的 not_selected 占比明显偏高——插桩期间调度器被采集逻辑打断，warp 供给被人为压低；改为窗口聚合后 not_selected 回落到与占用率分析一致的水平，归因表才与占用率结论自洽。

五 · 公式失效的判据清单与降级路径

把前述边界收敛成可执行的判据，归因分解在以下情形应被标记为“不可用”而非“给出一个数”：占比之和偏离 1 超过容差（互斥性或完备性破裂）；not_selected 未被单独分组（语义混淆）；有效样本数低于阈值（统计误差主导）；插桩开销占比超过阈值（观测扰动主导）；以及 kernel 存在跨 SM 的全局同步或动态并行，导致 stall 周期在时间上不可简单相加。最后一条的机制是：全局屏障让不同 SM 的 warp 在不同时间段饥饿，把各 SM 的 C_k 直接相加会重复计入等待同一屏障的周期，可加性假设破裂。

降级路径应当分级：一级降级是剔除 not_selected 后重算饥饿份额并附样本数；二级降级是放弃占比排序，只报告绝对周期数与定性方向（“饥饿侧以 long_scoreboard 为主”）；三级降级是放弃归因，改用端到端时延与 roofline 可达上界做粗粒度判断——后者不依赖 stall 分类，代价是失去定位到具体 stall 原因的能力。对 agent 驱动的优化循环而言，降级信号必须作为结构化字段回传，让策略层知道“本轮反馈不可用于精细归因”，否则 RL 会把噪声当成奖励信号，这正是奖励黑客在 profiling 反馈上的一个具体入口。

一个具体例子：某 kernel 含跨 block 的全局同步，归因表显示 barrier 占比异常高且各 SM 求和后总 stall 超过实测未发射周期。按判据清单，可加性破裂成立，直接降到二级：只报告“同步等待是主要饥饿来源”，不给出份额数字，优化动作限定为减少同步点数量而非按占比排序。工程判断落在最后一步——归因分解的价值不在于永远给出一个百分比，而在于它能诚实地报告自己何时不再成立；把失效判据做成流水线里的硬门禁，比事后解释一张失真的表便宜得多。

归因公式在什么条件下才配得上“分解”二字

把 C_stall 拆成若干 C_k 之和，前提是这些计数来自同一个可观测口径：同一 warp、同一采样窗口、同一发射判定。一旦口径漂移，求和式就退化为把不同来源的数字相加，f_k 的物理含义随之消失。最典型的漂移发生在采样型 profiler 上：它按固定周期对 SM 上的 warp 状态做快照，再乘以采样间隔外推成周期数。小 kernel 的存活时间接近采样间隔时，一个 warp 可能只被命中一两次，C_k 的方差会大到让 f_k 在两次运行间跳变。工程上的处置不是相信单次结果，而是对同一 kernel 重复采样取中位数，并把采样间隔压到 kernel 时长的若干分之一；代价是 profile 本身变慢、trace 体积变大，且对极短 kernel 仍无法收敛。判断标准很直接：若同一配置下 f_k 的重复测量离散度超过你准备据此做决策的粒度，这个分解就不该进入优化回路。

第二类失效来自 not_selected 的语义错位。它记录的是 warp 已就绪、但调度器把发射机会给了别的 warp 的周期，本质是占用率与发射带宽的产物，而非某条指令的依赖链在拖后腿。把 not_selected 与 long_scoreboard 放进同一个分母做占比，会系统性压低真实访存瓶颈的权重：一个 occupancy 很高、访存延迟被充分掩盖的 kernel，其 f_not_selected 可以占据主导，此时正确的结论是“发射端口接近饱和或 warp 数偏多”，而不是“访存有问题”。因此在使用 f_k 前应先做一次门控判断：若 not_selected 占比显著，则先看 occupancy 与每周期可发射 warp 数，再决定是否把其余类别纳入归因；否则分解结果只能用于排除法，不能用于定位。

$$\text{valid}\iff \Big(\frac{\sigma(\hat{C}_k)}{\hat{C}_k}\le \epsilon\Big)\ \wedge\ \Big(f_{\text{not\_selected}}\le \theta\Big)\ \wedge\ \big(\text{all } C_k \text{ from one sampling window}\big)$$

第三类是规模上限与结构性假设。求和式隐含“每个未发射周期恰好归入一个原因”，但硬件计数器在 warp 于同一周期满足多个阻塞条件时只记录优先级最高的那个，于是 C_k 之间并非严格互斥而是被优先级裁剪过的投影，C_stall 因此是下界而非精确总量。对长依赖链主导的 kernel 这个偏差可忽略，对 barrier 与 scoreboard 交织的 kernel 则会把 barrier 的真实代价藏进 wait 里。规模上限还体现在统计功效上：block 数极少、单 warp 串行执行尾部的 kernel，其 stall 分布由少数几个 warp 决定，占比失去统计意义，此时应回到逐指令的 SASS 与源码对照，而不是继续摊大饼式地分类。

边界条件公式表现应改用
kernel 时长接近采样间隔f_k 重复测量离散大多次采样取中位数，或延长观测窗口
not_selected 占主导访存类占比被稀释先判 occupancy 与发射带宽，再谈依赖

最后是系统代价这一侧：为了让分解可信，你需要开启计数器采集、拉长 profile 窗口、重复多次运行，这些都会挤占本可用于调优的迭代预算；而在 RL 或自动搜索回路里，把带噪声的 f_k 直接当作奖励信号，会让策略去优化一个测量伪影而非真实瓶颈。稳妥的做法是把分解结果当作假设生成器：由 f_k 提出候选原因，再用一次针对性的改动（改访存布局、调 block 尺寸、拆 barrier）去验证该原因是否真的移动了端到端时延；只有当改动带来的时延变化与预测方向一致时，这次归因才算通过适用性检验。

归因公式在什么条件下失效：占用率、采样噪声与规模上限

分解式 $$C_{\text{stall}}=\sum_{k\in\mathcal{K}}C_k,\qquad f_k=\frac{C_k}{C_{\text{stall}}}$$ 成立的前提是各类计数互斥且完备：同一个未发射周期只能被记入一个原因桶，且所有桶之和覆盖全部未发射周期。NCU 的 warp stall 采样基本满足互斥性，但完备性依赖具体架构的计数器集合——较老的架构上 imc（指令取指）与 branch 类计数可能部分重叠，跨架构比较 $$f_k$$ 时必须先确认桶定义一致，否则占比之和会偏离 1，此时应把残差单列为“未归类”而不是强行归一化。

最典型的失效场景是 not_selected 占比偏高。not_selected 表示 warp 已就绪、只是调度器当周期选了别的 warp，它反映的是占用率充足而非真实瓶颈。若把它与 long_scoreboard 同等归因，会得出“访存是主因”的错误结论。工程判据是：当 $$f_{\text{not\_selected}}$$ 显著高于其他单项时，应先降占用率（减少 block 数或增大每线程寄存器用量）再复测，观察 $$C_{\text{stall}}$$ 是否随占用率下降而上升——若上升，说明此前是被 not_selected 掩盖的真实 stall；若不上升，则瓶颈本就不在 warp 发射侧。这一步的代价是一次额外的编译与 profile 往返，通常占单轮优化迭代时延的主要部分。

采样型 profiler 的计数本身带统计误差，误差量级与采样周期数成反比。小 kernel（总周期数少、SM 上并发 warp 少）上单次采样的 $$f_k$$ 抖动足以让排序翻转，因此必须多次采样取中位数，并只对占比差异超过抖动带的类别下结论。规模上限还体现在另一处：当 kernel 被拆成大量微小 launch（每 launch 只有几十微秒）时，profiler 的固定开销与采样粒度会淹没真实 stall 结构，此时归因应上移到 kernel 序列层面按总周期加权，而不是逐 launch 独立分解。
