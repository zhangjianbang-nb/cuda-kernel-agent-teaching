一 · 一句话直觉与它到底在说什么

多轮 agent 的最终加速比由每一轮编辑共同决定；若只给最后一轮奖励，前面「修对但没提速」的轮次拿不到信号，策略会退化成保守复制。这句话里藏着一个容易被忽略的因果结构：最终 kernel 的加速比是各轮编辑的复合函数，而不是最后一轮编辑的独立产物。第 3 轮把 shared memory 的 bank conflict 修掉、但还没做向量化，此时测速几乎不动；第 5 轮在此基础上把访存宽度从 4B 提到 16B，加速比才跳起来。若奖励只在第 5 轮发放，第 3 轮那次「正确但无收益」的编辑在策略梯度里得不到任何正信号，反而因为它的中间态 kernel 比原始 kernel 慢（多了 swizzle 索引计算）而被隐式惩罚。策略学到的不是「修 bank conflict 有用」，而是「别乱动，复制上一版最安全」。

直觉的另一种表述：多轮信用分配要回答的是「这一轮的编辑，对最终目标的边际贡献是多少」，而这个边际贡献被后续轮次放大或抵消。它本质上是时序上的贡献归因问题，与单轮 RL 中「这个 token 对最终答案贡献多少」同构，但多了一个关键差异——每一轮的中间产物（kernel 源码）是可执行、可测量的，因此中间轮存在可观测的中间奖励，而不像语言模型里中间 token 只有稀疏的最终判分。

二 · 严格定义：奖励、折扣与正确性门

把一次多轮 kernel 优化轨迹记为 $\tau=(s_0,a_1,s_1,\dots,a_T,s_T)$，其中 $s_t$ 是第 $t$ 轮编辑后的 kernel 状态（源码 + 编译产物 + 测量结果），$a_t$ 是 agent 在该轮做出的编辑动作。第 $t$ 轮拿到的聚合奖励定义为从该轮起向后累积的折扣和：

$$R_t=\sum_{k=t}^{T}\gamma^{k-t}r_k,\qquad r_k=\Delta\text{speed}_k\cdot\mathbb{1}[\text{pass}_k]$$

其中 $\gamma\in(0,1]$ 是折扣因子，$r_k$ 是第 $k$ 轮的即时奖励，$\Delta\text{speed}_k$ 是该轮相对上一轮的加速变化（相对 $s_{k-1}$ 的实测加速比之差，而非相对原始 kernel），$\mathbb{1}[\text{pass}_k]$ 是该轮是否通过正确性门的指示函数。这个定义有三个必须写死的工程约定，否则信用分配会失真：

  • $\Delta\text{speed}$ 的基准是上一轮而非基线。若用相对原始 kernel 的绝对加速比作 $r_k$，则第 2 轮修正确性导致的性能回退会被记成负奖励，而第 4 轮的收益会被记成「本来就该有的」，轮次间的贡献被重复计入。用差分才能让 $\sum_k r_k$ 在 $\gamma=1$ 时恰好等于最终加速比减去初始加速比，形成 telescoping 结构。
  • 正确性门是硬门而非软惩罚。$\mathbb{1}[\text{pass}_k]$ 取 0 时该轮奖励直接归零，而不是给一个负值。原因是 kernel 不正确时测出的加速比没有物理意义（可能因为跳过了边界检查而虚假变快），把它当负奖励会让策略学到「避免一切可能引入数值差异的优化」，包括合法的 fast-math 与 Tensor Core 路径。
  • 中间轮的 pass 与最终 pass 不等价。第 $k$ 轮通过正确性门，只说明 $s_k$ 在该轮的测试用例集上正确；后续轮次可能引入新的数值路径使最终 kernel 失败。这意味着 $r_k$ 的正信号可能建立在「后来被推翻的正确性」上，是这套定义固有的误判来源。

代价层面：每轮都要编译并实测一次 kernel，单轮端到端时延由编译时间（CUDA C++ 模板实例化可达数十秒，Triton 编译在秒级）加基准测速（多次 warmup 与重复取中位数）构成；$T$ 轮意味着 $T$ 次编译加 $T$ 次测速，这是多轮信用分配相对单轮评测最直接的开销放大。token 侧同样线性增长：每轮要把源码、编译日志、测速结果回灌进上下文，长轨迹的上下文预算成为实际瓶颈。

三 · 为什么需要它：稀疏终局奖励的三个具体失效

需要多轮信用分配不是因为「理论上更优雅」，而是因为终局稀疏奖励在 kernel 优化这个任务上有三个可复现的失效模式。

失效一：延迟收益被截断。考虑一个两轮轨迹：第 1 轮把全局内存访问改成 `__ldg` 只读缓存路径，正确性通过，但因为该 kernel 是计算密集型、访存不是瓶颈，加速比变化接近零；第 2 轮在此基础上把内层循环展开并改用 FMA，加速比提升明显。只给终局奖励时，第 1 轮的动作与第 2 轮的动作共享同一个正信号，梯度无法区分谁是必要条件。若第 1 轮实际是负贡献（引入了额外的地址计算），终局奖励仍为正，策略会把「引入地址计算」也当作有用动作。信用分配的作用是把终局信号按轮次拆开，让第 1 轮的零贡献被如实记为接近零，而不是被第 2 轮的收益平均掉。

失效二：保守复制作为局部最优。当策略发现「任何编辑都有概率破坏正确性、且破坏后终局奖励归零」时，期望奖励最大化的策略是保持 $s_t=s_{t-1}$。这在数学上是合理的：若编辑的期望收益为负（失败概率乘以归零惩罚大于成功概率乘以收益），不动就是最优。信用分配通过给「修对但没提速」的轮次一个非负的、与最终成败解耦的信号，把「探索性编辑」的期望从负拉回零附近，从而打破这个局部最优。代价是：这种解耦会让策略在中间轮更激进，正确性门的触发频率上升，编译与回滚的时延开销随之增加。

失效三：远端噪声被折扣放大或压制。折扣因子 $\gamma$ 的取值直接决定信用分配的视野。$\gamma$ 过小（如 0.5）时，第 $t$ 轮的奖励只看到其后一两轮，长程的架构级改写（例如把整个 kernel 从 SIMT 改成 warp-specialized 的 producer-consumer 结构，收益要到第 4、5 轮才显现）拿不到信号，策略退化为只做局部微调。$\gamma$ 过大（接近 1）时，远端轮次的测速噪声被完整累加进 $R_t$：单轮测速的方差在 $T$ 轮上累积，$R_t$ 的信噪比随 $T$ 下降。这不是定性担忧，而是方差随 $T$ 线性增长的直接后果，因此需要 baseline 或 TRLOO 之类的降方差手段，而 baseline 本身又要额外的前向评估开销。

四 · 常见误解：把「中间轮通过」当成「最终会通过」

第一个高频误解是把 $\mathbb{1}[\text{pass}_k]$ 理解为「这条轨迹最终会正确」。实际上中间轮的 pass 只是该轮状态在该轮测试集上的局部判定。一个典型例子：第 2 轮为了提速把归约的累加顺序从串行改成树形，在该轮的小规模用例上误差仍在容差内、pass 为真；第 4 轮进一步把树形归约与 split-K 结合，累加顺序再次改变，误差累积越过容差，最终 pass 为假。此时第 2 轮的 $r_2$ 是正的，但它对最终结果的真实贡献是负的——它埋下了一个在第 4 轮才引爆的数值隐患。信用分配若不做回溯修正，就会系统性地高估这类「局部正确、全局有害」的编辑。

第二个误解是把 $\Delta\text{speed}_k$ 当成该轮编辑的「真实加速贡献」。实测加速比是 kernel 整体在特定输入规模、特定 GPU 状态下的表现，它混合了该轮编辑的效果、上一轮遗留的瓶颈、以及测量噪声。第 3 轮把一个占用率受限的 kernel 的寄存器压力降下来，占用率上升但延迟没降（因为瓶颈在别处），$\Delta\text{speed}_3\approx 0$；第 4 轮把瓶颈处的指令依赖链打断，$\Delta\text{speed}_4$ 很大——但第 4 轮的收益有相当部分是以第 3 轮的占用率提升为前提的。差分奖励会把功劳几乎全部记给第 4 轮，这是信用分配在机制上无法完全消除的归因偏差，只能通过多轨迹对比或反事实 baseline 部分校正。

第三个误解是认为折扣因子可以任意调、调大就是「更有远见」。$\gamma$ 不是视野旋钮，它同时是方差放大器。$\gamma\to 1$ 时 $R_t$ 退化为未折扣的回报和，方差最大；$\gamma$ 小则偏差大（系统性忽略长程收益）。工程上更常见的做法不是调 $\gamma$，而是引入与状态相关的 baseline $b(s_t)$ 把 $R_t-b(s_t)$ 作为优势，代价是每个状态多一次评估前向，在 kernel 场景下这意味着额外的编译与测速，直接吃掉多轮带来的时延预算。

误解机制上的真实情况代价
中间轮 pass 等于最终 pass数值路径在后续轮次被改写，误差累积可越界误判正奖励，策略高估局部正确编辑
$\Delta\text{speed}_k$ 等于该轮真实贡献收益依赖前序轮次铺垫，差分归因偏向末轮系统性低估架构级前置工作
$\gamma$ 越大越有远见$\gamma\to1$ 使方差随 $T$ 累积需 baseline/TRLOO，增加评估时延与 token

五 · 定义落地时的两个工程判断

把上面的定义写进 agent 的奖励管线时，有两个必须提前定死的判断。其一是正确性门的测试集是否随轮次演进。若每轮都用同一套固定用例，中间轮的 pass 判定稳定、可复现，但无法捕捉「在小规模上正确、在目标规模上越界」的失效；若每轮动态扩增用例（例如随 kernel 支持的形状增大而增加边界用例），pass 判定更贴近最终部署条件，但每轮的测速与校验时延上升，且历史轮次的奖励会因测试集变化而不可比。工程折中是固定一套覆盖目标形状与边界的主用例集用于奖励判定，另设一套扩展用例只用于最终验收，代价是中间轮的误判风险被保留。

其二是回滚语义。当第 $k$ 轮 pass 为假时，轨迹是继续在错误状态上编辑，还是回滚到 $s_{k-1}$ 再重试？前者让 agent 有机会自我修复，但错误状态上的测速无意义、$\Delta\text{speed}$ 不可信；后者保证每轮起点正确，代价是每轮多一次状态恢复与重编译。多数实现选择回滚，因为这让 $r_k$ 的定义保持干净：$\Delta\text{speed}_k$ 始终是「正确状态到正确状态」的差分。回滚的时延代价在 $T$ 大时不可忽略，且回滚本身会消耗 token（需要把上一版源码重新注入上下文）。这两个判断共同决定了信用分配信号的可信度上限——定义写得再严谨，若测试集与回滚语义没定死，$R_t$ 仍然是在噪声上做归因。

信用分配的边界：什么时候「往回传奖励」会骗人

把多轮信用分配当成「把最终奖励沿轮次往回摊」是一种危险的简化。严格地说，它要解决的是轮次间奖励的可归因性：第 t 轮拿到的聚合奖励 $R_t$ 必须能区分「这一轮编辑本身产生了加速」与「这一轮只是为后面某轮铺了路」。公式 $R_t=\sum_{k=t}^{T}\gamma^{k-t}r_k$ 中，$r_k=\Delta\text{speed}_k\cdot\mathbb{1}[\text{pass}_k]$ 把即时奖励绑定在该轮相对上一轮的加速变化与正确性门上，这意味着信用分配的第一条边界是：它只在「每轮都有可测量的增量」时成立。若某一轮只是重构了 kernel 结构、把寄存器压力降下来却未改变端到端时延，$\Delta\text{speed}_k$ 近似为零，该轮的信号被吞掉，而这恰恰是后续轮次能提速的前提。工程上这表现为策略偏向「保守复制」——不改动能通过的版本，因为改动带来的即时收益不确定，而失败会立刻被 pass 门惩罚。

第二条边界是折扣因子 $\gamma$ 的两难。$\gamma$ 过小，$R_t$ 几乎只反映第 t 轮自身的 $\Delta\text{speed}$，agent 会退化成单轮贪心，放弃需要多轮铺垫的优化路径（例如先改数据布局、再改 tile 形状）；$\gamma$ 过大，远端轮次的噪声被等比放大——一次偶然的 pass 波动会污染前面所有轮次的信用。轮数 $T$ 增大时方差按 $\gamma$ 的幂次累积，单条轨迹的 $R_t$ 估计不再可信，必须引入 baseline 或 TRLOO 之类的留一法降方差，代价是每个训练 step 需要多采样几条轨迹，token 消耗与编译时间成倍上升。这里的系统代价是实打实的：多轮 rollout 意味着每轮都要真实编译并跑正确性 oracle，一条 $T$ 轮的轨迹在编译队列上占用的时间远大于单轮样本。

第三条边界最容易被忽视：中间轮的 pass 变化不等于最终 pass。某一轮把数值误差压到门限内但引入了新的边界条件失败，$\mathbb{1}[\text{pass}_k]$ 为真而最终版本不可用；反之，某轮暂时破坏了正确性却在后续轮被修复，该轮的负奖励会错误地惩罚一条本应被鼓励的探索路径。表格给出三种典型误判及其代价：

情形奖励误判工程代价
中间轮通过、最终失败正奖励被错误保留策略学到不可靠的中间形态，后续验证成本上升
中间轮失败、最终通过负奖励压制探索丢失需要多轮修复的优化路径，收敛变慢
$\Delta\text{speed}$ 为负但为后续铺路该轮被判为无效策略退化为保守复制，加速比停滞

因此信用分配的适用前提是：每轮编辑的增量可被独立测量、正确性门在轮次粒度上可信、且 $T$ 与 $\gamma$ 的组合不使方差压过信号。一旦这些前提不成立，与其说信用分配在「分配信用」，不如说它在放大测量噪声——此时更稳的做法是把奖励锚定在最终可验证的端到端加速上，用轮次级的过程信号只做辅助约束，而不是直接当作训练目标。
