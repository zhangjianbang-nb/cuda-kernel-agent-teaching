一 · 一句话直觉与它为什么反直觉

把“迁移增益”压缩成一句话：在源任务上把 kernel 写对、写快所积累的能力，搬到目标任务上时，收益既可能为正也可能为负，且正负号与幅度都由源–目标之间的分布距离决定，而不是由源任务上的绝对水平决定。这句话之所以需要被反复强调，是因为它与工程直觉相冲突。工程直觉默认“更强的模型在源任务上得分更高，因此迁移到目标任务也应该更好”，这是一种把能力水平与能力可移植性混为一谈的推理。MetaKernelBench 的实测给出了直接反例：双向迁移的增益区间是 −19%~+29%，并且在每一个模型、每一个迁移方向上，仍有 16%–45% 的题目出现退化。也就是说，即使整体均值为正，退化题的比例依然接近半数——均值正并不等于“迁移可靠”。

这个反直觉现象有一个具体的机制来源：kernel 生成不是自然语言任务，它的“知识”高度绑定在具体的硬件约束、dtype、shape 分布与访存模式上。源任务上学到的是“在 A100 上对 fp16 的某个 reduction 用 128 线程块 + float4 向量化能打满带宽”这类条件化的策略，而不是“如何写好 reduction”这类去条件化的抽象规则。当目标任务把 dtype 换成 bf16、把硬件换成 H100、把 shape 从规则变成不规则时，这条被记住的策略就从资产变成了负债：模型会自信地套用它，而套用的结果比从零探索更差。这正是负增益的物理来源，也是为什么“迁移”必须被当作一个需要被测量的量，而不是一个默认成立的假设。

代价在这里第一次显形：迁移的收益是以验证成本换来的。任何一次跨域迁移，若不做目标域上的重新验证，就等于把源域的过拟合风险无对冲地引入目标域。在 token 预算上，这意味着迁移省下的探索 token 必须有一部分被重新投入到目标域的验证采样中；在时延上，这意味着迁移不能省掉目标域的正确性 oracle 与 profile 环节。省掉验证的迁移，其期望增益会被退化题目的负增益吃掉，甚至反号。

二 · 严格定义：相对增益、取值域与分母的陷阱

把直觉形式化，迁移增益定义为目标任务得分在迁移前后的相对变化：

$$G_{\text{transfer}}=\frac{s_{\text{target}}^{\text{after}}-s_{\text{target}}^{\text{before}}}{s_{\text{target}}^{\text{before}}},\qquad G\in[-1,+\infty)$$

其中 $s_{\text{target}}^{\text{before}}$ 是模型在未接触源任务、直接在目标任务上求解时的得分，$s_{\text{target}}^{\text{after}}$ 是经过源任务训练或上下文注入之后在目标任务上的得分。这个定义有三个必须被显式对待的结构性特征，它们决定了后续所有统计推断的口径。

其一，取值域不对称。$G$ 的下界是 $-1$（迁移后得分归零，即完全失效），上界是 $+\infty$（迁移前得分趋近于零而迁移后为正）。这种不对称意味着 $G$ 的算术平均会被正侧的长尾拉高，而负侧被硬性截断在 $-1$。用均值汇报迁移增益，本质上是在汇报一个被上界污染的统计量。工程上正确的做法是同时汇报退化题比例与分位数，而不是只汇报均值——16%–45% 的退化率正是这种汇报方式的产物。

其二，分母是迁移前的目标域得分，不是源域得分。这是一个极易被写错的实现细节。若误把分母取成源域得分，得到的量衡量的是“源域水平在目标域上的折损率”，与“迁移是否让目标域变好”是两个完全不同的问题。前者可以很大而后者为负：一个在源域接近满分的模型，迁到目标域后折损 30%，但如果它迁移前的目标域得分本来就低，迁移后仍可能是净增益。分母选错会让整个增益界失去可解释性。

其三，$s$ 必须是同一评分口径下的可比量。若 $s_{\text{before}}$ 与 $s_{\text{after}}$ 分别来自不同的计时口径、不同的正确性判定严格度、不同的输入分布采样，则 $G$ 的分子是两个不可比之差的差，增益界退化为噪声。这一点与 SOL 归一化评分口径、计时噪声与置信区间两个主题直接耦合：增益界的可信度上限，由评分口径的一致性上限决定。一个具体的实现约束是，$s_{\text{before}}$ 与 $s_{\text{after}}$ 必须共享同一套正确性 oracle、同一批输入样本、同一套计时统计量（同一次 warmup 策略、同一置信区间构造），否则 $G$ 的符号不可信。

把定义写成可执行的伪代码思路，一次增益测量应当是这样的结构：固定目标域题目集合与输入采样种子；对每个题目分别在“无源域上下文”与“有源域上下文”两种条件下各采样 $n$ 次；对每次采样跑正确性 oracle，仅对通过的样本计入得分；对每个题目计算配对差，再在题目层面聚合，并同时输出退化题计数与分位数。配对设计是关键：同一题目、同一输入、同一评分口径下的前后对比，才能把题目难度这一混杂因子消掉。若改用非配对的组间均值，题目难度分布的任何偏移都会直接污染 $G$。

三 · 为什么需要一个“界”而不是一个“数”

工程上真正需要的不是“迁移增益等于多少”这个点估计，而是一个能支撑决策的区间：给定源任务、目标任务、硬件与 dtype 配置，迁移的增益落在什么范围内，以及在什么条件下它会翻负。原因在于迁移增益是一个依赖配置的函数，而不是模型的固有属性。同一个模型，在源与目标同分布时增益为正，在分布差异大时增益为负；同一对任务，在相同 dtype 下增益为正，在 dtype 变化后增益可能翻负且需要重新验证。把这种配置依赖性压缩成单一数字，等于丢掉了决策所需的自变量。

失效条件因此必须被写进界的定义里，而不是作为脚注。三条失效条件对应三类工程风险：分布差异——源与目标的任务分布差异大时增益为负，这是负增益的主要来源，也是 16%–45% 退化题的成因；硬件或 dtype 变化——这类变化会破坏迁移，且破坏方式是静默的，模型不会报告“我的策略失效了”，它只会给出一个能编译、能跑、但性能更差的 kernel，因此必须重新验证；样本量小——置信区间很宽，不能只看均值。第三条尤其致命：在小样本下，一个 $+29\%$ 的均值完全可能与 $0$ 不可区分，而一个 $-19\%$ 的均值也可能只是少数几道灾难性退化题拉出来的。

代价在这里体现为测量本身的成本。要得到一个可信的界，需要对每个题目做配对采样，采样数 $n$ 决定了置信区间宽度；而 kernel 的每次采样都包含编译时间、启动开销与计时噪声。编译时间在小规模题目上是主要成本项：一个 Triton kernel 的 JIT 编译可能远长于其执行时间，导致“多采样几次以收窄置信区间”的边际成本被编译而非执行主导。这与 Launch 开销与批量摊销的结论方向一致——摊销的对象不只是执行，还包括编译。工程判断是：增益界的采样预算应当按题目粒度分配，把编译缓存命中率作为采样成本的一等公民来优化，否则收窄区间的代价会超过迁移本身省下的探索成本。

四 · 常见误解：把相关当因果、把均值当保证、把正增益当可复现

误解一：源域得分越高，迁移增益越大。这是把“能力水平”误读为“可移植性”。增益的分子是目标域的前后差，源域得分根本不进入公式。一个在源域刷到极高分的模型，其策略可能过度特化于源域的 shape 与 dtype，迁移到目标域时负增益反而更大。正确的因果图是：源域得分 → 策略特化程度 → 目标域增益，中间这一环是负向的调节变量。要检验这一点，需要的是源–目标分布距离的度量，而不是源域得分本身。

误解二：均值为正就意味着迁移可用。在 $G$ 的不对称取值域下，均值正可以由少数题目的大幅正增益撑起，同时多数题目退化。16%–45% 的退化率说明，均值正与“多数题目变好”之间没有必然联系。工程上应当把退化率作为与均值并列的一等指标：一个 $+10\%$ 均值配 40% 退化率的迁移方案，在生产端到端收益上是不可接受的，因为退化题目往往落在长尾 shape 上，而长尾正是生产负载的主要构成。这与批不变性定义所关心的问题同源——聚合指标掩盖了分布尾部的行为。

误解三：正增益是可复现的模型属性。增益依赖硬件与 dtype 配置，任何一次配置变更都会使已测得的正增益失效，且失效是静默的。因此“这个模型迁移增益 +20%”这句话在没有附带配置坐标时是没有信息量的。可复现的单位不是模型，而是（模型，源任务，目标任务，硬件，dtype，评分口径，采样预算）这个七元组。把增益挂在模型名下传播，是奖励黑客式汇报的一种温和变体：它选择了一个有利于自己的聚合口径，并隐去了失效条件。

误解四：迁移增益可以脱离正确性单独谈。$s$ 的定义域只包含通过正确性 oracle 的样本。若把编译失败或数值错误的样本按零分计入，$G$ 会被人为压低；若把它们排除在分母之外，$G$ 会被人为抬高。两种处理都会让增益界失去意义。正确做法是在汇报 $G$ 的同时汇报正确性通过率的变化，因为迁移可能以牺牲正确性换取速度——一个把 fp32 累加换成 fp16 累加的“迁移”能显著提速，但它改变的是数值语义而非调度策略，这类增益必须与浮点误差累积界一起读。

五 · 一个具体例子：dtype 翻转如何让正增益变负

考虑一个具体的迁移路径：源任务是 fp16 下的大规模 reduction，目标任务是同一算子在 bf16 下、shape 更不规则。模型在源任务上学到的策略是“128 线程块 + float4 向量化 + 无分支累加”，这套策略在源域上得分很高。迁到目标任务后，float4 向量化在 bf16 下对齐要求改变，不规则 shape 使无分支累加的尾部处理缺失，结果是能编译、能通过正确性 oracle（因为 bf16 的容差较宽）、但带宽利用率显著下降。此时 $s_{\text{after}}$ 低于 $s_{\text{before}}$，$G$ 为负——而这个负增益并非因为模型“忘了怎么优化”，恰恰是因为它太记得源域的优化。

这个例子的工程含义是：迁移增益的符号可以在不改变任务语义的前提下被 dtype 单独翻转。因此任何跨 dtype 的迁移都必须重新跑目标域的 profile，而不能复用源域的 NCU 结论。代价是明确的：一次重新 profile 意味着目标域上的完整采样预算，迁移省下的探索 token 被这部分验证成本部分抵消。判断迁移是否划算的标准因此不是“源域得分高”，而是“迁移省下的探索成本 > 目标域重新验证的成本 + 退化题带来的期望损失”。退化题的期望损失由退化率与退化幅度共同决定，而这两者都只能通过配对采样测得。

把这一判断写成可操作的形式：设退化题比例为 $r$，退化题上的平均负增益为 $-\delta$，正增益题上的平均正增益为 $+\epsilon$，则整体期望增益近似为 $(1-r)\epsilon - r\delta$。这个式子说明，当 $r$ 接近 0.4 时，即使 $\epsilon$ 很大，整体期望也可能被 $\delta$ 吃掉。它同时说明为什么“只看均值”是危险的：均值恰好就是 $(1-r)\epsilon - r\delta$ 的估计，但它把 $r$ 与 $\delta$ 这两个可分别干预的量压缩成了一个数，从而剥夺了工程上最重要的干预手段——针对退化题做定向重验证。

六 · 定义落地时的三个实现约束

把上述定义落到可运行的评测管线里，有三个约束必须在代码层面被强制，否则增益界会在无人察觉的情况下失真。约束一：配对采样必须共享输入种子。同一题目的 before/after 两次采样必须喂入完全相同的输入张量与相同的随机种子，否则输入分布的任何抖动都会进入分子。这在实现上要求评测框架把“题目 + 种子”作为采样单元的主键，而不是把“模型 + 题目”作为主键。约束二：分母不得为零或近零。当 $s_{\text{before}}$ 趋近于零时，$G$ 会被数值放大到失去意义，此时应改用绝对差而非相对增益汇报，或直接标记为“不可比”。这一条在目标任务极难、迁移前得分接近地板时频繁触发。约束三：编译失败与正确性失败必须分开计数。前者反映的是策略与目标域 API/语法的兼容性，后者反映的是数值语义，两者对增益的解释完全不同，混在一起计数会让 $G$ 的符号无法归因。

这三个约束的共同代价是评测管线的复杂度上升：配对主键要求缓存层按（题目，种子）索引编译产物，分母保护要求聚合层做逐题的可比性判定，失败分类要求 oracle 返回结构化的失败原因而非布尔值。这些复杂度换来的是 $G$ 的可归因性——当增益为负时，管线能回答“是分布差异、是 dtype 破坏、还是样本量不足”，而不是只给出一个负数。这正是“界”相对于“数”的全部价值所在：界携带失效条件的坐标，数不携带。后续对增益界的收紧，本质上就是在这三个约束下，把分布距离、配置差异与采样预算三个自变量显式地写进界的表达式里，而不是把它们留在脚注中。
