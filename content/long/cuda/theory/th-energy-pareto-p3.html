一 · 平均功耗近似的误差结构：采样窗口与功率包络

公式 $E\approx\bar P\cdot T$ 成立的前提，是功率在执行窗口内近似平稳，且 $\bar P$ 的采样窗口覆盖了全部瞬态。这两条在真实 GPU 上都不自动满足。瞬时功率由 SM 的开关活动、HBM 的读写突发、L2 命中率波动共同驱动，其包络在 kernel 启动的头几十微秒内通常存在一个爬升段（时钟从空闲档位抬升、供电模块响应），在尾部存在一个拖尾段（写回、缓存清理、时钟回落）。若采样窗口只截取中段稳态，$\bar P$ 会被系统性低估；若窗口跨越了 kernel 边界，则会把相邻 kernel 或 host 侧同步开销计入。

工程上可把误差拆成两项：窗口截断误差与采样粒度误差。设真实功率为 $P(t)$，采样得到的分段常值为 $\hat P(t)$，则

$$\Delta E=\int_0^T \big(P(t)-\hat P(t)\big)dt \;=\; \underbrace{\int_{\text{head/tail}}\big(P-\hat P\big)dt}_{\text{截断}}+\underbrace{\sum_k \int_{I_k}\big(P-\hat P_k\big)dt}_{\text{粒度}}$$

截断项在短 kernel 上占主导：一个执行时间仅数微秒的 kernel，其爬升段可能占到总时长的可观比例，此时“平均功耗 × 时间”给出的能耗与真实积分偏离，且偏离方向取决于采样起点，不可用常数修正。粒度项则在长 kernel 上占主导，取决于片上功率传感器的采样率与是否做时间加权。代价是明确的：把采样率提高一个量级，profile 本身的侵入性上升，采样线程与 kernel 争抢 SM 资源，反而改变被测量的对象；用外部功率计则受限于板级采样率与串口带宽，无法分辨 kernel 级事件。

具体例子：对一个以 HBM 流式读为主、算术极少的 kernel，稳态功率主要由内存子系统决定，SM 侧的空转使其功率包络相对平坦，平均近似误差小；而对一个计算密集、occupancy 逐步爬升的 kernel，功率随活跃 warp 数单调上升，前段被低估、后段被高估，两项部分抵消但残差仍随 kernel 时长缩短而放大。判断准则不是“采样够不够快”，而是“被测量窗口内功率的相对变化幅度是否小于你愿意接受的能耗误差预算”。

二 · DVFS 与温度：同一 kernel 的能耗不是常量

把某个 kernel 的能耗当作固定属性写进帕累托表，是这套方法论最容易被误用的地方。GPU 的时钟由 DVFS 控制器根据利用率、功耗上限与温度动态调整，同一份 SASS 在两次执行中可能跑在不同频率上。频率变化对时间与功率是双向的：$T$ 近似与 $f$ 成反比（在非访存受限时），而 $P$ 中动态功耗项近似与 $f$ 和 $V^2$ 同向，电压又随频率档位抬升。于是 $E=\bar P\cdot T$ 在频率扫描下并非单调，存在一个能效最优点，越过它继续提频，时间收益被功率上升吃掉，能耗反而增加——这正是“更快不一定更省电”的物理来源之一。

温度是第二条漂移通道。结温上升会触发降频或风扇策略变化，使同一 kernel 在冷机与热机下的 $\bar P$ 与 $T$ 同时改变。更麻烦的是测量顺序效应：连续跑一组候选 kernel 时，后测的那些天然处于更高的热基线，若不做交错与预热归一，帕累托前沿上会出现由测量顺序而非算法差异造成的伪支配关系。

代价体现在实验设计上：要得到可比较的能耗点，必须固定或至少记录频率档位、做足够长的预热使热稳态达成、并对候选做交错重复测量以摊平漂移。这直接把单点测量成本抬高数倍，也让“每个候选只跑一次”的快速筛选在能耗维度上不可信。具体例子：一个通过减少指令数获得提速的 kernel，在固定高频档位下能耗下降；但若它同时把 occupancy 推高、使 SM 长时间处于高活跃态，DVFS 可能把它锁在更高频档，此时它的能耗相对基线未必更优——两次测量若一次冷机一次热机，结论会直接反转。

三 · 跨硬件不可比：能效曲线的形状依赖微架构

不同 GPU 的能效曲线不可直接比较，这不是“数值不同”这么简单，而是曲线的自变量与拐点结构不同。功耗对 occupancy 的敏感度取决于每 SM 的供电与时钟域划分、warp scheduler 的调度开销、寄存器堆与共享内存的静态功耗占比；对访存模式的敏感度取决于 HBM 通道数、L2 分区与压缩能力。因此在一个器件上测得的“低 occupancy 更省电”结论，换到另一个器件上可能因为静态功耗占比更高而失效——低 occupancy 下大量 SM 空转仍消耗可观的漏电与时钟功耗，省下来的动态功耗不足以抵消。

可比性还受限于测量口径。板级功率计包含风扇、VRM 损耗与显存供电，片上传感器只覆盖部分轨；两者给出的 $\bar P$ 不可混用。跨器件比较若一方用板级、一方用片上，差异会被误读为能效差异。

工程判断应落在“同一器件内的相对排序”而非“跨器件的绝对数值”。帕累托前沿是器件局部的：候选 A 支配候选 B 的结论只在特定器件、特定频率策略、特定热状态下成立。要把结论外推，必须把微架构参数（SM 数、每 SM 供电域、HBM 带宽与通道、静态功耗占比）作为协变量显式建模，而不是假设能效曲线形状可迁移。具体例子：一个为高带宽器件调优的流式 kernel，其能耗最优点落在较高 occupancy；移植到静态功耗占比更高的器件上，同一 occupancy 下的空转成本上升，最优点向低 occupancy 移动，原先的帕累托支配关系不再保持。

四 · 规模上限：固定开销摊薄失效与小尺寸 regime

帕累托分析隐含一个“规模足够大”的假设：launch 开销、爬升段、尾部清理相对于总执行时间可忽略。当问题规模缩小，这些固定项占比上升，能耗与时间的关系从“由稳态功率决定”切换为“由固定开销决定”。设固定能耗为 $E_0$、稳态功率为 $P_s$、稳态时长为 $T_s$，则

$$E=E_0+P_s T_s,\qquad \frac{\partial E}{\partial T_s}=P_s,\qquad \text{但}\ \frac{E}{T_s}=P_s+\frac{E_0}{T_s}$$

有效能效 $E/T_s$ 随 $T_s$ 缩小而发散，意味着小尺寸下“每单位工作量能耗”这一指标失去意义，任何以它为目标的优化都会退化为压缩固定开销而非改善稳态效率。同理，时间维度上 launch 与同步开销的占比上升，使 latency 与 E 的帕累托前沿被固定项主导，候选之间的差异被淹没在常数里。

规模上限还有另一侧：当工作集超出片上缓存与 L2 容量，访存模式从缓存命中切换为 HBM 流式，功率包络的形状改变，前文推导中假设的稳态段可能根本不存在——整个执行过程都处于带宽饱和与功率爬升的混合态。此时平均近似与稳态假设同时失效。

代价是筛选成本：要确认一个候选在目标规模区间内有效，必须在多个规模点上重复测量并检查前沿是否稳定，而不能只在大规模单点上取数。具体例子：一个通过批量摊销 launch 开销获得优势的 kernel，在大规模下能耗与时间双优；缩小到单次小批量时，其固定开销与基线相同，稳态段又太短以致功率未达稳态，测得的能耗差异落在噪声内，帕累托支配关系消失。工程上应把“最小有效规模”作为候选的属性记录下来，而不是把单点结论当作全域结论。

五 · 失效条件的联合判定：什么时候该放弃这套公式

上述失效条件不是独立的，它们在同一实验里往往同时出现：短 kernel 既有截断误差，又处于固定开销主导的 regime，还更容易受 DVFS 爬升影响。因此需要一个联合判定流程，而不是逐条打勾。可操作的判据是三步：先测功率包络的相对波动幅度，若超过能耗误差预算则平均近似不可用；再测固定项占比，若 $E_0/E$ 或 launch 时间占比超过阈值则规模假设不成立；最后检查测量序列的频率与热基线是否受控，若不受控则任何跨候选比较都不可信。

伪代码思路如下，用于在评测流水线里自动标记不可信点：

  • 对每个候选采集功率时间序列，计算稳态段方差与头尾段能量占比；
  • 若头尾占比超过预算，标记“规模不足”，不进入帕累托排序；
  • 交错重复 K 次并记录每次的频率档位与入口温度，若档位不一致则标记“DVFS 漂移”；
  • 仅对通过上述检查的点计算 $\bar P\cdot T$，并在同一器件同一频率策略下做支配判定；
  • 跨器件结果只保留相对排序的方向性结论，不合并绝对能耗数值。

这套判定的代价是吞吐：大量候选会在第一步就被剔除，可排序的点变少，前沿变稀疏。但保留不可信点进入排序的代价更大——它会让 RL 或搜索过程把奖励分配给测量伪影而非真实能效改进，这与奖励黑客的激励问题同源，只是发生在测量层而非目标层。

具体例子：一个候选在单次测量中显示出比基线更低的能耗，但它的执行时间落在爬升段内，头尾能量占比高；按上述流程它被标记为规模不足，不参与支配判定。若跳过这一步直接排序，搜索会倾向于生成更多“短而测不准”的 kernel，而非真正降低稳态功率的实现。落在具体机制上：帕累托表的每一行都应携带其有效域标签——器件、频率策略、热状态、规模区间、采样口径——没有这些标签的能耗数字不具备可比性，也不应进入任何以能耗为奖励信号的优化回路。

当“平均功率乘时间”不再可信：采样、DVFS 与跨卡外推的三重失效面

本方案把一次执行的能耗压缩成 $$E=\int_0^T P(t)\,dt\approx\bar P\cdot T$$ 的乘积形式，帕累托前沿则写成 $$\text{Pareto}:\ \min\ (\text{latency},E)$$。这个近似成立的前提是 P̄ 在整个执行窗口内对时间平稳。而 GPU 的瞬时功率恰恰是强非平稳的：kernel 启动瞬间的电流冲击、warp 逐批退出导致的 occupancy 阶梯式下降、以及尾部少量 CTA 独占 SM 时的低效区间，都会让 P(t) 呈现尖峰加长尾的形状。用平均功率乘总时间，等于把尖峰的能量摊平到整段窗口，对短 kernel 尤其失真——一个几十微秒的 kernel，其功率爬坡段可能占到窗口的相当比例，此时 P̄·T 系统性低估或高估真实积分，取决于采样窗口是否把 idle 段计入。工程上的直接代价是：要拿到可信的 E，必须做高频功率采样（板级或片上功耗计），采样率不足时只能退回平均近似，而高频采样的采集与对齐开销本身会拉长测量时延，使“每候选 kernel 一次能耗评估”的吞吐下降，直接压缩多轮搜索里可评估的候选数量。

第二个失效面来自 DVFS 与温度。同一份 SASS、同一 grid 配置，在冷卡与热卡上跑出的 E 可以相差一个可观测的幅度：boost 频率随温度回落，电压随频率档位跳变，而功率近似正比于频率与电压平方的乘积，于是 T 变长、P̄ 下降，两者乘积并不守恒。这意味着能耗不是 kernel 的固有属性，而是 kernel 与当前频率/温度状态的联合函数。把能耗当作可验证奖励信号时，这会直接污染 RL 的信用分配：同一候选在不同热状态下得到不同的 E，策略会把噪声当成真实梯度。可行的缓解是把测量协议固定下来——预热到稳态、锁定频率档、记录测量时的温度与时钟，并把 E 与这些状态量一起入库；代价是每次评估前的稳态预热要消耗固定时延，且锁频会牺牲一部分真实部署条件下的代表性。

第三个失效面是跨硬件外推。不同架构的能效曲线不可直接比较：SM 数量、显存类型、功耗墙与频率策略都不同，同一个 occupancy 在 A 卡上是甜点、在 B 卡上可能已进入带宽饱和区。因此帕累托前沿必须按卡分别构建，不能把一张卡上测得的 (latency, E) 点集直接搬到另一张卡上做支配关系判断。更隐蔽的是 occupancy 与访存模式的耦合：提高 occupancy 往往提升 latency 表现，却同时抬高静态功耗与漏电占比，于是出现“更快但更费电”的非支配点——这正是前沿存在的意义，也是它不能被单目标排序替代的原因。

把边界收拢成一张判据表，比记公式更实用：

条件近似是否可信系统代价
kernel 时长远大于功率爬坡与尾部可信测量时延随 kernel 时长线性增长
短 kernel、频繁启动失真，需高频采样采样与对齐开销压缩候选吞吐
未锁频、未预热漂移，不可作奖励预热时延 + 代表性损失
跨架构直接比较不成立需按卡重建前沿，评估成本翻倍

由此得到一个工程判断：能耗-性能帕累托只在“测量协议受控、候选时长足够长、且前沿按卡独立维护”的三角内成立；一旦越出，E 就从可验证信号退化为带噪观测量，此时应把 E 降级为排序辅助而非硬约束，把正确性与 latency 留在 oracle 侧，避免用漂移的能耗数字去驱动搜索方向。
