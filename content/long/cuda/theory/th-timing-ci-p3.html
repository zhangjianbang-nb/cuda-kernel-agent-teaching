一 · 独立同分布假设在 GPU 计时上如何被破坏

自助法置信区间的全部合法性来自一个前提：样本 $t_1,\dots,t_n$ 近似独立同分布。这个前提在 CPU 上做微基准时勉强能维持，在 GPU kernel 计时上几乎必然被破坏，而且破坏方式不止一种。要判断公式何时失效，先要能定位破坏源。

第一类破坏是时间相关性。连续两次重复测量之间，GPU 的时钟状态、L2 残留、DRAM 行缓冲打开情况都不是独立的：第 $i$ 次测量的结果会影响第 $i+1$ 次测量的初始条件。典型表现是样本序列出现慢漂移而非白噪声，此时自助法重采样把相邻样本当作可交换的，会系统性低估区间宽度。第二类破坏是分层结构：同一 kernel 在不同 SM 上、不同 warp 调度顺序下，耗时的方差来源不同，把全部样本混在一起重采样，等于把组间方差当成组内方差，区间偏窄。第三类破坏最隐蔽——预热阶段的样本分布与稳态分布不同，如果剔除预热不彻底，前几个样本会把中位数往高值拉，而自助法无法识别这种“分布切换”。

判断是否可用的操作性检验：把样本按时间顺序切成前后两半，分别算中位数，若两个中位数的差超过合并区间半宽的一半，说明存在系统性漂移，此时自助法区间不可信。这个检验不引入新统计量，只用已有的 $\bar{t}$ 与 $CI$，代价是样本量至少翻倍才能让每半有足够样本，直接推高测量时延。

$$\text{drift}=\left|\operatorname{median}\{t_1,\dots,t_{n/2}\}-\operatorname{median}\{t_{n/2+1},\dots,t_n\}\right|,\qquad \text{flag}=\mathbb{1}\left[\text{drift}>\tfrac{1}{2}\cdot\text{half\_width}\right]$$

具体例子：一个做规约的 kernel，前一半样本中位数落在较低值，后一半因持续高负载触发降频而抬高，drift 超过半宽，flag 置位。此时正确做法不是加大 $n$ 硬压区间，而是插入空闲间隔或固定时钟，把漂移源消掉再重测。

二 · DVFS 漂移：区间覆盖不了的系统性偏移

DVFS 是失效条件里最需要单独讲的一条，因为它和随机噪声的性质根本不同。随机噪声围绕真值对称分布，重复测量取中位数能收敛；DVFS 造成的是单向偏移——频率下降使所有样本整体抬高，中位数跟着抬高，置信区间忠实地包住了这个被抬高的中位数，却包不住“无降频时的真实耗时”。也就是说，区间宽度再窄，覆盖的也是一个偏移后的目标。

机制上，DVFS 的触发取决于功耗与温度的时间积分，而不是单次 kernel 的瞬时负载。这意味着测量序列本身在改变被测对象：你测的次数越多、越密集，越容易把 GPU 推进低频档，后段样本系统性变慢。这与“多测几次更准”的直觉相反。工程上的判别方法是看样本的时序包络：若耗时随测量序号单调上升并在某点后平台化，几乎可以断定是频率档位切换而非随机波动。

代价体现在两个方向。若为了规避 DVFS 而在每次测量间插入冷却间隔，测量总时延按间隔长度线性膨胀，一个原本秒级的基准可能变成分钟级，这对需要成千上万次评测的 agent 搜索循环是不可接受的。若选择固定时钟（锁频），则测得的数字不再代表生产环境的真实表现，与部署端到端收益的评估口径脱节。这是一个无法同时满足的三角：测量稳定性、测量吞吐、生产代表性。

具体例子：同一 kernel 在锁频下测得中位数稳定、rel_err 很小；解锁后重测，中位数抬高且区间依然很窄——两个区间互不重叠。这不是统计错误，而是两个不同总体的区间。报告时必须声明时钟策略，否则跨提交比较会拿锁频数字和解锁数字对比，得出虚假的性能差异。

三 · 样本量下限：n<10 时中位数与区间同时失效

中位数的稳健性有代价：它依赖样本在真值两侧的分布对称性来抵消极端值，样本太少时这种抵消不成立。$n<10$ 时，中位数只由中间一两个样本决定，任何一个样本的抖动都会整体平移 $\bar{t}$；同时自助法重采样的可能组合数极其有限，重采样分布是离散且稀疏的，得到的区间上界下界本身就是高方差的随机量。此时报告 $CI$ 会给出一种虚假的精确感。

正确的处理不是“算一个更宽的区间”，而是放弃区间、退回原始样本。把 $t_1,\dots,t_n$ 全部列出，让读者自己看离散程度。这牺牲了简洁性，但保留了唯一可信的信息。判断门槛可以直接写成规则：$n<10$ 时不报 $CI$，只报 $\min$、$\max$ 与全部样本；$n\ge 10$ 才进入区间口径。

$$\text{report}=\begin{cases}\{t_1,\dots,t_n\}, & n<10\\ \left(\bar{t},\ CI_{1-\alpha},\ \text{rel\_err}\right), & n\ge 10\end{cases}$$

代价是 token 与传输开销：原始样本列表在 agent 的执行反馈里占用上下文，$n$ 越大占用越多。这与“多测”的诉求冲突——测得多是为了稳，但报得多会挤占推理预算。折中是报 $n<10$ 时的全样本、$n$ 较大时只报中位数与区间，并把样本序列的时序图作为可选附件。

具体例子：某次快速筛查只跑了 5 次，样本为四个接近值加一个明显偏高的值。中位数落在接近值区间，但自助法区间被那个高值拉宽，rel_err 很大。此时若只报区间，读者会以为测量很 noisy；报全样本则一眼看出是单次异常而非普遍抖动，处置方式完全不同——重跑那一次，而不是加大 $n$。

四 · 规模上限：n 增大后收益递减与新的偏差源

公式本身没有规模上限，但工程上有。随着 $n$ 增大，中位数的标准误按 $1/\sqrt{n}$ 收缩，区间半宽同步收缩，rel_err 看起来越来越好。然而这个收缩只对随机噪声成立；一旦存在第二节说的系统性漂移，增大 $n$ 不会缩小偏移，只会让区间越来越窄地锁在一个错误的位置上——精度提升掩盖了准确度丧失。这是规模上限的第一层含义：$n$ 的有效上限由漂移时间尺度决定，超过这个尺度，新增样本跨过了频率档位切换，反而引入新的分层。

第二层是测量总时延。总耗时约等于 $n\cdot(\text{单次 kernel 时间}+\text{间隔})$，在 agent 的多轮循环里，这个乘积直接决定单轮反馈的墙钟时间。当单次 kernel 只有微秒级而间隔是毫秒级时，$n$ 从 30 加到 300 带来的区间收窄可能远小于它带来的时延膨胀，性价比在某个 $n$ 之后转负。这个拐点取决于 kernel 时长与间隔之比，没有普适数字，需要在具体基准上标定。

第三层是缓存与内存状态的饱和。大量重复测量会反复冲刷 L2，使后续样本的缓存命中模式偏离首次运行；当 $n$ 大到足以让工作集在多次测量间稳定驻留时，测得的其实是“热缓存稳态”，与冷启动场景不可比。这要求报告里明确缓存预热策略，否则 $n$ 越大越偏离目标场景。

具体例子：一个访存密集 kernel，$n=20$ 时区间半宽已收敛到可接受比例；继续加到 $n=200$，半宽几乎不变（说明噪声已被前 20 次覆盖），但总测量时延翻了十倍，且后段样本因 L2 稳态而系统性偏快。此时的正确判断是停在 $n=20$ 附近，把省下的预算用于多次独立会话而非单会话内堆样本。

五 · 公式成立的边界条件清单

把上述散落的失效条件收拢成可执行的判据，便于在评测流水线里做前置检查。每条判据对应一个可观测信号，而不是靠经验感觉。

边界条件可观测信号失效后果处置
样本近似独立时序自相关显著区间偏窄加间隔或分会话
无系统性漂移前后半中位数差超半宽一半区间锁在偏移值锁频或声明时钟策略
$n\ge 10$有效样本计数中位数与区间均不稳报原始样本
预热已剔除首样本显著偏离稳态中位数被拉高显式声明剔除规则
缓存状态可比后段样本系统性偏快偏离目标场景声明预热策略

这张表的价值在于把“公式是否适用”从判断题变成检查题。流水线在算出 $\bar{t}$ 与 $CI$ 之前先跑这几项，任一项不通过就降级报告口径。代价是前置检查本身要消耗样本与时间——漂移检验要求至少分两半，等于把最小样本量从 10 提到 20 量级，这与第三节的下限规则叠加，实际可用的最小 $n$ 被进一步抬高。

具体例子：一个 agent 提交的 kernel 在自动评测里算出很漂亮的 rel_err，但前置检查发现首样本明显偏高且未剔除，drift 检验也置位。流水线拒绝采信该区间，退回原始样本并标记“测量条件不满足”。这不是否定 kernel 的性能，而是否定这次测量的可信度——两者必须分开，否则会把测量噪声误判成 kernel 缺陷，污染后续的优化信号。

六 · 何时应当放弃区间口径

有一类情形不是“区间偏了”而是“区间这个工具本身不适用”：被测对象的耗时分布是多峰的。当 kernel 存在两条明显不同的执行路径（例如数据依赖导致的分支、不同 tile 配置的调度差异），样本会聚成两簇，中位数落在两簇之间或落入其中一簇，而自助法区间会横跨两簇、给出一个没有任何样本实际取到的“中间值”。此时中位数不代表任何真实执行模式，rel_err 也失去意义。

判别方法是看样本的离散结构而非只看宽度：若样本在某个值附近出现明显空隙，且两侧各有稳定聚集，即为多峰。处置是分组报告——按执行路径拆成子样本，各自算中位数，而不是合并成一个区间。代价是每组样本量下降，可能触发第三节的下限规则，于是又回到报原始样本。这条链路说明：区间口径的适用边界不是单一条件，而是几个条件串联，任一环断裂都会把报告降级到更原始的形式。

具体例子：一个带数据依赖分支的 kernel，样本明显分成快慢两簇。合并算出的中位数落在两簇之间，rel_err 看似温和，但没有任何一次测量接近这个中位数。分组后快簇的中位数与慢簇的中位数差距远大于合并区间的半宽，说明性能差异来自输入分布而非测量噪声。此时正确的工程判断是把输入分布纳入评测口径，而不是继续在合并样本上打磨区间宽度。

当自助法区间开始说谎：独立同分布假设、DVFS 漂移与样本下限

自助法区间的合法性完全建立在「样本近似独立同分布」这一前提上，而 GPU 计时恰恰是最容易违反它的场景之一。重采样只能刻画样本经验分布内部的随机波动，无法感知分布本身的系统性平移：如果 DVFS 在测量窗口内把 SM 时钟从一档降到另一档，前一半样本落在高频区、后一半落在低频区，中位数会落在两段之间的某个位置，而区间宽度只反映段内抖动，看起来又窄又稳——$$CI_{1-\alpha}=\left[t_{(k_1)},t_{(k_2)}\right]$$ 会把一个偏倚过的中心包装成高置信结论。判别手段不是看区间宽度，而是看时间序：把 ti 按采集顺序画出来，若出现单调爬升、阶跃或与温度/功耗采样同步的漂移，就说明样本不满足交换性，此时应改为分段统计或直接锁定时钟后再测，而不是加大 n 硬扛。

第二个失效条件是样本量。n<10 时，中位数的抽样方差本身很大，自助法重采样只是在十几个点上反复抽样，区间的端点由个别极端样本决定，$$\text{rel\_err}=\frac{\text{half\_width}}{\bar{t}}$$ 会呈现剧烈跳变：同一 kernel 两次测量的 rel_err 可以相差数倍，而这不是 kernel 变了，是估计量还没收敛。工程上的处理是设一条硬门槛——有效重复次数（剔除预热后）低于阈值时不报区间，只报原始样本序列与中位数，并显式标注「区间不可用」；把原始 ti 一并落盘，让下游能自行判断是抖动还是漂移。

规模上限还体现在测量成本与信噪比的权衡上。单次 kernel 时延越短，固定开销（launch、事件记录、同步）占比越高，相对抖动的分母越小，达到目标 rel_err 所需的 n 就越大；当 kernel 本身只有微秒级，重复测量带来的总墙钟时间与编译/预热成本会迅速压过收益。此时正确做法是改测「批量循环 N 次的总时间再除以 N」以摊薄固定开销，但这又引入新的假设：批内缓存状态已被前几次迭代预热，测到的是热缓存稳态而非冷启动语义——所以声明「是否剔除首轮冷启动」不是格式要求，而是决定这组区间能否被复用的语义标签。

边界条件失效表现系统代价
