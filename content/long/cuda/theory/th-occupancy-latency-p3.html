一 · 延迟受限前提：占用率公式的适用域

公式 $$\text{hide}:\;N_{\text{warp}}^{\text{res}}\cdot L_{\text{mem}}\ge L_{\text{lat}}$$ 的成立有一个不可省的前提：kernel 确实处于延迟受限（latency-bound）区间。这个前提不是修辞，而是一个可判定的工程条件——只有当 SM 的发射端口因等待访存返回而出现气泡时，增加驻留 warp 才能转化为吞吐。若 kernel 已经进入带宽受限区，SM 的访存队列与 L2/DRAM 通道饱和，此时再多驻留 warp 只会加深排队深度，吞吐不变而尾延迟变差。判定方法不是看占用率数字，而是看 stall 归因：若 `long_scoreboard`（等全局访存）在 warp stall 采样中占主导，公式有效；若 `mio_throttle`、`lg_throttle` 或 DRAM 利用率接近通道上限，则公式的左边已经不再是瓶颈项。

代价体现在误判的方向上。把带宽受限 kernel 当作延迟受限来调占用率，典型动作是降寄存器、缩 block，换取更多驻留 warp——这会让每个 warp 的有效工作量变少，指令发射总量上升，L1/L2 请求数增加，反而把本已紧张的通道压得更满。一个具体例子：逐元素向量加（elementwise add）在较大规模下是纯带宽受限，其最优配置往往不是最高占用率，而是每线程处理多个元素（ILP 提升）配合中等占用率，用更少的 warp 发出更少的合并请求。反过来，一个依赖链长的规约或扫描 kernel，在低占用率下 `long_scoreboard` 占比高，此时把 R_thread 从高位压下来换 warp 数是正确方向。

二 · L_mem 的测量依赖：标称延迟为何误判

公式右侧的 L_lat 是目标访存延迟，左侧的 L_mem 是每 warp 可重叠的访存延迟量。工程上最容易出错的地方是把 L_mem 当成常量。它实际取决于访问模式：合并度决定一次 warp 指令产生多少个 32B sector，L2 命中率决定这些 sector 有多少落在片上，两者共同决定一条访存指令从发射到数据可用的真实跨度。用厂商文档的标称全局访存延迟去代入，会在两种情形下系统性误判：高 L2 命中率的 kernel 实际 L_mem 远小于标称值，公式给出的所需 warp 数偏高，导致过度压寄存器；低合并度（如跨步访问、AoS 布局）的 kernel 实际每次请求拆成多个 sector，等效延迟被拉长，公式给出的 warp 数偏低，气泡仍然存在。

可操作的替代做法是把 L_mem 当作待测量而非待查表：用 NCU 采集 `lts__t_sectors` 与 `l1tex__t_sectors` 的比值估算合并效率，用 `lts__t_sector_hit_rate` 估算 L2 命中，再把有效延迟按命中/未命中两段加权。伪代码思路是：对每个 warp 的每条访存指令，统计其 sector 数与命中层级，得到该指令的有效延迟估计，再对整个 kernel 的指令流取加权平均，得到 L_mem 的实测值。这一步的代价是 profile 采集本身——NCU 全量指标采集会显著拉长 kernel 执行时间（串行 replay 模式下可达数十倍），因此只适合离线标定，不适合放进自动调优的内循环。工程折中是先用少量 replay 标定 L_mem 与合并度的关系，再在调优循环里用合并度这一廉价代理量推算 L_mem。

三 · 寄存器与共享内存约束：上限不是软约束

公式第一项 $$\left\lfloor\frac{R_{\text{SM}}}{R_{\text{thread}}\cdot 32}\right\rfloor$$ 是硬上限，不是建议值。R_thread 每增加一个寄存器，每 SM 可驻留的 warp 数就按 32 个寄存器为一档整体下移——分配粒度是 warp 级，不是线程级，因此 R_thread 的微小增加可能跨过档位边界，造成驻留 warp 数跳变式下降。这个非线性是调优中最常见的陷阱：把 R_thread 从 40 调到 41，驻留 warp 数可能从 48 掉到 40，延迟隐藏能力骤降，而寄存器压力只换来极小的收益。共享内存项 $$\left\lfloor\frac{M_{\text{SM}}}{M_{\text{blk}}}\right\rfloor N_{\text{warp}}^{\text{blk}}$$ 同理，M_blk 的分配粒度通常是固定字节档（如按 256B 或更大对齐），实际占用常大于声明值。

代价是双向的。压 R_thread 换取 warp 数，代价是编译器被迫把活跃变量溢出到本地内存（local memory），而 local memory 走的是与全局访存相同的路径，溢出访问本身又制造新的延迟——这等于用增加 L_mem 需求的方式去满足延迟隐藏不等式，可能净效果为负。判断依据是看 `local_load`/`local_store` 的指令计数是否随寄存器压缩而上升。一个具体例子：一个含多个中间累加器的卷积 kernel，若强行把 R_thread 压到很低，编译器会把部分累加器放到 local memory，每次迭代多出两次访存，此时即便驻留 warp 数翻倍，实际吞吐也可能不升反降。正确做法是先确认寄存器压力来自哪里，用 `__launch_bounds__` 给出目标驻留 warp 数让编译器在该约束下调度，而不是盲目压 R_thread。

四 · 规模上限：小 grid 与尾部的失效

公式隐含假设 SM 数量足够多、grid 足够大，使每个 SM 都能被填满到 N_warp^res。当 grid 的 block 总数小于 SM 数乘以每 SM 可驻留 block 数时，部分 SM 处于空闲，公式描述的“每 SM 驻留 warp 数”在全局意义上不成立——此时瓶颈是并行度不足而非延迟隐藏不足。小规模 kernel（如 batch 很小、序列很短的推理算子）常落在这个区间，表现为占用率数字好看但 SM 利用率低。这类情形下增加每线程工作量（ILP）或合并多个小 kernel 比调占用率更有效，而合并的代价是 launch 开销摊销与依赖关系变复杂。

尾部效应是另一个失效面。grid 不能被 SM 数整除时，最后一波 block 只填满部分 SM，其执行时间由单 block 的关键路径决定，而非由驻留 warp 数决定。此时整 kernel 的时延近似为“满波次数 × 单波时间 + 尾部单 block 时间”，占用率公式只对满波部分有效。工程判断是：当尾部时间占比可观时，应优先调整 block 粒度使波次更整齐，或改用 persistent kernel 让每个 SM 循环取任务，把尾部摊薄。代价是 persistent kernel 需要显式的工作队列与同步，引入额外的原子操作与栅栏开销，且对不规则负载的负载均衡不如动态调度。

五 · 跨架构与跨精度：常数项的漂移

公式中的 R_SM、M_SM、N_warp^max 是架构常量，L_lat 是架构相关的延迟量级。把在一代架构上标定出的“所需驻留 warp 数”直接搬到另一代，是失效的常见来源：寄存器文件容量与共享内存容量的比例关系变化，会改变两项约束中哪一项先起作用；L2 容量与命中行为变化，会改变有效 L_mem。跨精度同理：半精度与 bf16 的访存事务尺寸不同，同一访问模式下的 sector 数与合并效率不同，L_mem 随之漂移。因此占用率调优的结论必须绑定到具体的（架构，精度，访问模式）三元组上，跨三元组迁移时需要重新标定而非直接复用数值。

代价是标定成本。每换一个三元组就重跑一轮 profile 与调优，在 kernel 数量多的场景下不可忽略；折中做法是把公式当作筛选器而非求解器——先用公式粗筛出候选配置区间（例如判断寄存器约束还是共享内存约束先起作用），再用少量实测在区间内定参。这样公式的价值在于缩小搜索空间、解释失败原因，而不是直接给出最优占用率数值。一个具体例子：同一规约 kernel 在共享内存容量更大的架构上，M_blk 约束放松，公式第一项（寄存器）成为主导，此时调优重点应从共享内存切分转向寄存器用量与 `__launch_bounds__` 设置。

把上述边界收敛成可执行的检查项，比记住公式本身更有用。以下清单按判定顺序排列，任一项不满足即说明公式当前不适用，应转向其他优化杠杆。

这张表的关键在于顺序：延迟受限判定排第一，因为它是公式成立的总开关；L_mem 实测排第二，因为它决定公式右边的数值可信度；寄存器档位与 grid 填充排在其后，因为它们决定公式左边的可达值。工程上最常见的错误是跳过前两项直接调 R_thread，把一次本应诊断为带宽受限的问题误诊为占用率不足，结果在错误方向上反复压寄存器、缩 block，吞吐不动而溢出访问增加。公式的正确用法是作为诊断工具：当不等式不成立时，它告诉你缺的是驻留 warp 数还是每 warp 的重叠量；当不等式成立而吞吐仍不达标时，它告诉你瓶颈已不在延迟隐藏，应转向 roofline 与 SOL 口径去定位真正的上界。

公式成立的三条隐含假设与它们的破口

隐藏不等式 N_warp^res · L_mem ≥ L_lat 把 L_mem 当成一个标量，这一步本身就埋了三个假设：其一，驻留 warp 的访存请求在时间上均匀错开，任意时刻都有足够多的 warp 处于“已发射、等数据”的状态；其二，每个 warp 的访存延迟可以被其他 warp 的指令完全覆盖，即 warp 切换本身不产生额外停顿；其三，L_mem 是访问模式的常量，与数据布局无关。三条中任何一条被打破，公式给出的占用率目标就会系统性偏高或偏低。均匀错开假设在 kernel 入口和尾部尤其脆弱：启动阶段所有 warp 几乎同时发出第一批 load，形成请求风暴，此时有效并发请求数受限于 LSU 队列深度与 MSHR 条目数，而非 warp 数；尾部则相反，剩余 warp 少、指令流稀疏，气泡无法靠增加占用率消除。工程上判断这一点不需要跑 NCU，看 SASS 里 load 指令的密度和分支结构即可：若一个 warp 的指令窗口里连续出现多条独立 load，错开假设基本成立；若 load 之间夹着长依赖链，增加 warp 只是把等待从一个 warp 搬到另一个。

第二条假设的代价体现在 warp 切换开销上。每 SM 的 warp 调度器在每个 cycle 只能发射有限条指令，当驻留 warp 数逼近 N_warp^max 时，调度器需要在更多候选 warp 间做选择，寄存器 bank 冲突与 scoreboard 查询的压力上升，切换本身占用发射槽。这意味着隐藏不等式的右边实际应是 L_lat + L_switch，而 L_switch 随驻留 warp 数增长而非线性下降。把占用率从 50% 推到 100% 换来的额外隐藏能力，可能被调度开销吃掉一部分，表现为吞吐不升反降。这类退化在寄存器用量接近 R_SM 上限的 kernel 上最容易观察到：编译器为压低 R_thread 而插入的 spill/reload 又会引入新的访存延迟，形成“降寄存器→增占用率→增访存→需更高占用率”的循环，此时公式的输入 R_thread 本身已不可信。

第三条假设的破口最隐蔽。L_mem 依赖合并度与 L2 命中率，用标称延迟代入不等式会把“合并良好、L2 命中高”的场景误判为需要高占用率。一个 32 线程访问连续 128 字节的 warp，其请求在 L2 命中时延迟远低于跨页、非合并访问；若按最坏延迟设定 N_warp^res 目标，就会为并不存在的长延迟预留大量寄存器预算，反过来压低每线程可用寄存器数，损害指令级并行。更合理的做法是把 L_mem 拆成两档：命中路径延迟与缺失路径延迟，按缺失率加权，得到有效延迟 L_eff = p_hit·L_hit + (1−p_hit)·L_miss，再代入隐藏不等式。p_hit 无法从源码静态推出，只能靠 profile 或对访问模式的定性分析给出区间；这也意味着占用率调优本质上是带不确定输入的搜索，而非解方程。

适用边界最终落在 kernel 的受限类型上。带宽受限时，SM 的吞吐由 DRAM 带宽与请求队列决定，增加驻留 warp 只会加深队列、拉长延迟，吞吐不变而尾延迟变差；此时隐藏不等式的左边再大也无意义，因为瓶颈不在等待数据返回，而在数据返回得太慢。判断方法是对比增加占用率前后的 DRAM 利用率与 SM 发射率：前者饱和、后者空闲，即为带宽受限，公式失效。规模上限还有一层：当问题规模小到每个 SM 分不到足够多的 block 时，⌊M_SM/M_blk⌋·N_warp^blk 这一项由 block 数而非资源决定，公式退化为“有多少 block 就有多少 warp”，此时提高占用率的唯一手段是减小 block 尺寸，而这会牺牲共享内存复用与合并访存的粒度。一个具体例子：共享内存用量接近 M_SM 的 tiled GEMM，其 M_blk 项把驻留 block 数压到个位数，公式算出的 N_warp^res 远低于隐藏所需，但实际 kernel 因数据复用充分而并不缺隐藏能力——这说明公式只对“访存主导且复用低”的 kernel 有指导意义，对计算密集或复用充分的 kernel，应改用指令级并行与流水线深度作为调优变量。
