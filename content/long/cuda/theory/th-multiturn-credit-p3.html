一 · 折扣因子的双刃：γ 的有效区间

公式 $R_t=\sum_{k=t}^{T}\gamma^{k-t}r_k$ 把第 t 轮的信用摊到后续所有轮次上，γ 是唯一的调节旋钮，但它同时调节两件互相冲突的事：信号的回传深度与远端噪声的放大倍数。把 γ 写成 $e^{-\Delta/\tau}$ 的形式（Δ 为轮间隔，τ 为有效记忆长度）能看清边界：τ 必须显著大于「一次修复所需的平均轮数」，否则修对但尚未提速的中间轮拿不到任何梯度；而 τ 一旦逼近 T，远端轮次的噪声方差以 $\sum_k \gamma^{2(k-t)}\sigma_k^2$ 的速度累积，当 γ→1 时退化为等权平均，方差随 T 线性增长。工程上的可行区间由两个不等式夹住：下界来自「修复延迟」——若某类 kernel 的典型修复需要 m 轮（例如先改 tile 形状、再改 shared memory 布局、最后调 unroll），则 τ ≳ m，否则 γ^{m} 已把该轮信号衰减到噪声以下；上界来自「噪声累积」——若单轮奖励的标准差为 σ，则聚合奖励的标准差约为 $\sigma\sqrt{(1-\gamma^{2(T-t+1)})/(1-\gamma^2)}$，当 γ 接近 1 时该值趋近 $\sigma\sqrt{T-t+1}$，此时若不给 baseline，策略梯度的信噪比会随 T 恶化。代价是具体的：γ 偏小导致策略退化为保守复制（只做能立刻提速的编辑，放弃需要多轮铺垫的重构），γ 偏大导致远端某一轮的偶然 pass 波动被错误地归因到早期决策上，训练时表现为同一 prompt 下奖励方差居高不下、需要更多 rollout 才能压住。一个具体例子：把 reduction kernel 从 128 线程改为 256 线程本身不提速（甚至略慢），但为后续引入 warp shuffle 铺路；若 γ 取 0.5 且该铺垫发生在第 3 轮、提速发生在第 6 轮，则第 3 轮拿到的信用只剩 0.5³≈0.125 的份额，几乎不可学。

二 · pass 指示函数的错位：中间轮通过 ≠ 最终通过

$r_k=\Delta\text{speed}_k\cdot\mathbb{1}[\text{pass}_k]$ 里的指示函数看似无害，实则引入了两类系统性错位。第一类是「假阳性通过」：中间轮为了提速改动了边界处理（例如去掉 tail 分支的越界检查），在小 shape 上 pass、在大 shape 上失败，该轮的 Δspeed 为正且 pass 为真，奖励被全额发放，而错误直到后续轮才暴露——此时信用已经发给了错误的编辑。第二类是「假阴性通过」：中间轮为了正确性引入了额外的同步或冗余计算，pass 为真但 Δspeed 为负，奖励为零甚至为负，策略学到的是「不要做正确性修复」。这两类错位的共同根源是：pass 是逐轮独立判定的布尔量，而最终正确性是对整条编辑链的合取。工程上的缓解不是改公式，而是改判定口径——把 pass 判定放在「累积编辑后的完整 kernel」上而非「本轮增量」上，代价是每轮都要重新编译并跑完整正确性套件，编译时间与验证时延随 T 线性增长（Triton 的 JIT 编译在中等规模 kernel 上通常是秒级，CUDA C++ 的 nvcc 编译更慢，若每轮都全量验证，T=10 的多轮采样会把单条轨迹的墙钟时间推高一个量级）。另一个代价是 token：把完整验证结果写回上下文会挤占后续编辑的上下文预算，尤其在需要保留 NCU profile 摘要时。具体例子：某轮把 softmax 的 max-subtraction 从两次遍历合并为一次，pass 在 fp32 下成立，但 fp16 累加下数值溢出，直到最终评测才暴露；若按逐轮 pass 发奖，这一轮的 Δspeed 奖励被错误保留。

三 · 轮数 T 的规模上限：方差累积与 baseline 的必要性

当 T 增大，$R_t$ 的估计方差按前述 $\sigma\sqrt{T-t+1}$ 量级增长，而策略梯度的有效样本量受 rollout 预算约束，二者相除就是信噪比的上限。这不是「可能需要 baseline」的软建议，而是硬约束：在无 baseline 的 REINFORCE 形式下，梯度估计的方差随 T 线性上升，若每 prompt 只采少量轨迹，梯度方向会被远端轮次的偶然波动主导。TRLOO（留一法基线）之所以在此处必要，是因为它把每个轮次的奖励减去「同一 prompt 下其他轨迹的均值」，从而消掉与具体轨迹无关的共同偏移；其代价是 rollout 数量必须 ≥2 才能构造留一估计，且每条轨迹的存储与回放成本翻倍。规模上限还有第二重来源：上下文长度。多轮 agent 的每一轮都要把历史编辑、编译错误、profile 摘要塞回 prompt，token 消耗随 T 近似线性增长，当 T 超过某个阈值后，早期轮次的细节被截断或摘要化，信用分配所依赖的「哪一轮做了什么」的信息本身开始丢失——此时公式在数学上仍成立，但输入 $r_k$ 的归因已经不可靠。工程判断是：T 的有效上限由「上下文能无损容纳的轮次数」与「方差可接受的最大 T」两者取小，前者通常先到。具体例子：一个 matmul kernel 的调优轨迹若走到第 12 轮仍在改 pipeline stage 数，前 5 轮的编译错误信息早已被挤出上下文，此时即便 γ 取 0.9，第 3 轮的信用也无从校准。

四 · Δspeed 的可测性边界：噪声底与最小可分辨加速

$\Delta\text{speed}_k$ 是相邻两轮的加速差，它的可用性受计时噪声底限制：当某一轮的编辑带来的加速小于测量噪声的置信区间半宽时，Δspeed 的符号本身不可信，奖励变成随机量。这不是公式的失效，而是输入的失效——公式假设 $r_k$ 是真实信号，而实际拿到的是带噪估计。后果是系统性的：在接近 roofline 的后期轮次，每次编辑的边际收益本就很小（受限于可达上界），Δspeed 频繁落在噪声带内，此时若不加阈值，策略会把噪声当成信号去拟合，表现为后期轮次编辑方向漂移。工程上的做法是给 Δspeed 设一个最小可分辨阈值（由计时噪声的置信区间决定，而非拍脑袋），低于阈值的轮次奖励置零并标记为「不可分辨」，代价是这些轮次不再提供梯度，有效 T 缩短，修复铺垫类编辑更难被学到。另一个代价是测量成本：要把噪声压到能分辨小加速，需要增加重复计时次数或固定时钟/关闭 boost，单轮评测时延上升。具体例子：某轮把 shared memory bank conflict 从 4-way 降到 2-way，理论收益有限，实测加速落在计时抖动范围内，若强行发奖，策略会重复做同类微调而忽略更大的结构性机会。

五 · 跨轮编辑的非可加性：公式隐含的线性假设

公式把总加速拆成逐轮 Δspeed 之和，这隐含了「编辑效果可加」的假设，而 kernel 优化恰恰经常违反它：两次编辑单独看各提速 10%，合在一起可能因占用率骤降而净减速；反之，单独看减速的编辑（如增加寄存器压力）可能为后续编辑创造前提。当编辑间存在强交互时，逐轮 Δspeed 的归因是路径依赖的——同一编辑在不同前缀下的 Δspeed 不同，$r_k$ 因此不是编辑的固有属性而是「编辑+前缀」的联合属性。这直接冲击信用分配的语义：策略学到的是「在这个前缀下做这个编辑好」，而非「这个编辑好」，后者才是可迁移的知识。失效条件是交互强度超过单轮收益量级，此时线性分解的残差与信号同阶。工程上的缓解是成对采样（同一前缀下采样多个后继编辑做对比），代价是 rollout 数量按分支因子指数增长，实际只能对关键决策点做局部成对比较。具体例子：先增大 tile 再引入双缓冲，单独增大 tile 会因寄存器溢出而减速，但它是双缓冲生效的前提；若按逐轮 Δspeed 发奖，增大 tile 那一轮拿到负奖励，策略会永久避开这条正确路径。

六 · 何时该放弃该公式：切换到轨迹级或过程级判定

综合上述边界，公式失效的判据可以收敛为三条可检查的条件：其一，修复延迟 m 与有效记忆长度 τ 之比接近或超过 1，即铺垫轮无法被信用覆盖；其二，中间轮 pass 与最终 pass 的判定分歧率不可忽略，即指示函数系统性错位；其三，编辑间交互强度与单轮收益同阶，线性分解残差淹没信号。任一条成立时，继续调 γ 是在错误的参数空间里搜索。替代口径有二：轨迹级判定（只对最终 kernel 的 pass 与总加速发奖，放弃逐轮归因，代价是信用完全摊薄、学习信号极稀疏，需要大量轨迹才能收敛）；过程级判定（用编译成功、无越界、profile 指标改善等可验证的中间里程碑替代 Δspeed，代价是里程碑设计与奖励黑客风险，需与正确性 oracle 绑定）。工程判断落在具体机制上：先测量修复延迟分布与 pass 分歧率这两个量，若前者大则优先改 γ 与 baseline，若后者大则优先改 pass 判定口径（累积验证），只有当两者都正常而交互残差仍大时，才值得付出轨迹级判定的样本代价。这三步的顺序本身即是本公式适用边界的操作化表达。

折扣窗口的物理含义与失效边界

公式 $$R_t=\sum_{k=t}^{T}\gamma^{k-t}r_k,\qquad r_k=\Delta\text{speed}_k\cdot\mathbb{1}[\text{pass}_k]$$ 的成立依赖一个隐含假设：第 k 轮的即时奖励 rk 是「该轮编辑」的可归因增量。一旦某轮编辑的正确性门通过状态与加速变化解耦，这个假设就崩了。典型场景是 tiling 重构：某一轮把 shared memory 分块从 32×32 改成 64×64，pass 仍为真但 Δspeed 为负（bank conflict 恶化），下一轮再调 swizzle 把 Δspeed 拉正。此时第 k 轮拿到负奖励、第 k+1 轮拿到正奖励，但真正起作用的是两轮联合决策。折扣因子 γ 在这里不是调节「看多远」的旋钮，而是决定「把联合决策拆给谁」的分配器：γ 接近 1 时，k+1 轮的正向信号会回流到 k 轮，等于事后追认一次当时看起来更差的编辑；γ 偏小时，k 轮独自背下负奖励，策略学到的是「不要动 tiling」，而不是「动 tiling 后要配 swizzle」。前者导致保守复制，后者导致对结构性编辑的系统性回避——两者都不是我们想要的信用分配。

失效的第二个边界是 pass 的单调性假设。中间轮 pass 变化不等于最终 pass：某轮为了压 register 压力把 unroll 因子从 8 降到 2，pass 仍真但 Δspeed 显著为负；随后一轮发现 occupancy 提升带来的 latency hiding 抵消了 unroll 损失，Δspeed 转正。若只看最终 pass，中间那轮的负奖励会被 γ 衰减掉，策略无法学到「降 unroll 是通往高 occupancy 的必要中间态」。反过来，某轮 pass 从真变假（越界写 shared memory），但 Δspeed 因为 kernel 提前退出而虚高——rk 里的指示函数把这一轮直接归零，看似安全，实则丢掉了「这次编辑方向对但实现错」的信息，下一轮从零开始重新探索同一方向。奖励函数对 pass 的硬门控在这里是双刃的：它挡住了错误加速比污染，也抹掉了「接近正确」的梯度。

轮数规模与方差累积的系统代价

T 增大时，Rt 的方差按 γ 的幂次加权累积。设每轮奖励独立同分布、方差 σ²，则 Var(Rt) = σ²·(1−γ2(T−t+1))/(1−γ²)。γ=0.9、T=20 时，远端 10 轮的贡献仍占可观的权重，而远端奖励恰恰来自「当时看不出效果、事后才被追认」的编辑——这类奖励的信噪比最低。工程上的直接代价是 baseline 的必要性：不做 baseline 或 TRLOO 降方差，策略梯度在 T 超过十几轮后基本被噪声淹没，表现为同一 prompt 多次采样得到互相矛盾的编辑方向。TRLOO 的代价是每轮要多一次前向（或至少一次价值估计），在 agent 循环里这意味着 token 开销与编译/验证时延的叠加：一次 Triton kernel 的多轮编辑若每轮都跑正确性 oracle 加 NCU profile，单条轨迹的墙钟时间随 T 线性增长，而方差下降只随 √T 改善，规模上限由此被算力预算而非算法本身卡住。

第三个失效条件是 Δspeed 的可测性下限。当单轮编辑带来的加速变化落在测量噪声内（同一 kernel 多次 profile 的抖动、GPU 时钟波动、编译产物微差），rk 的符号本身不可信，γ 加权求和只是把噪声放大成「伪信用」。此时正确做法不是调 γ，而是把奖励粒度从「每轮」抬到「每若干轮」或引入最小可检测效应阈值：Δspeed 低于阈值时该轮奖励置零并顺延归因，代价是信用分配的时延增加、策略更新频率下降。规模上限因此有三重：T 受方差与 baseline 成本限制，γ 受联合决策拆分需求限制，Δspeed 分辨率受 profile 噪声限制——三者共同决定这套多轮信用分配在什么 kernel 复杂度上还能给出可信信号，超出后应退回单轮或分段奖励。

边界条件：折扣聚合在什么地形上失效

把逐轮奖励按 \(R_t=\sum_{k=t}^{T}\gamma^{k-t}r_k\) 回填，本质是把「最终加速比由每轮编辑共同决定」这一因果链，用几何衰减折算成每轮的信用。它成立的前提是：每一轮的 \(\Delta\text{speed}_k\) 与 \(\mathbb{1}[\text{pass}_k]\) 都能被独立、稳定地测出，且轮间贡献近似可加。一旦这个可加性被打破，公式给出的就不再是信用，而是噪声的加权和。最典型的破坏来自「延迟生效」：某轮把 kernel 改成 tiling 结构，当轮 pass 但速度持平甚至略降，真正的收益要等下一轮调整 shared memory 布局才释放。此时 \(r_k\) 记为零贡献，而 \(r_{k+1}\) 吞下全部增益，折扣因子越大，这笔被错记的功劳越会被反复放大到前序轮次的梯度里。

折扣因子 \(\gamma\) 的两侧都是悬崖。\(\gamma\) 偏小，回填视野被压到最近一两轮，前面「修对但没提速」的轮次彻底拿不到信号，策略退化成保守复制——这正是只给最后一轮奖励的病症，只是换了个更隐蔽的形式。\(\gamma\) 偏大，远端噪声被等权放大：正确性门本身有抖动（浮点容差、边界 shape、benchmark 预热不充分），一次偶然的 pass 翻转会沿着 \(\gamma^{k-t}\) 污染整条轨迹。轮数 \(T\) 增大时，方差按有效视野长度累积，没有 baseline 或 TRLOO 之类的降方差手段，梯度信噪比会随 \(T\) 单调恶化。工程上的判断是：\(\gamma\) 不该按「回合长度」拍脑袋定，而应由「一次编辑的收益平均延迟几轮兑现」这个物理量反推。

失效源机制系统代价
收益延迟兑现\(\Delta\text{speed}\) 跨轮错位归属前序轮梯度被稀释，收敛轮数上升
pass 抖动中间轮 pass ≠ 最终 pass误判奖励，需重跑 oracle 校验
\(T\) 过大方差沿 \(\gamma^{k-t}\) 累积需 baseline/TRLOO，采样 token 翻倍

规模上限还有一层常被忽略的代价：为了给每轮算出可信的 \(\Delta\text{speed}_k\)，必须在每轮编辑后真实编译并跑 NCU/SASS profile，而不是只在终点测一次。这意味着编译时间与 profiling 时延随 \(T\) 线性堆叠，显存则被多份中间 kernel 的测量上下文占用；当 \(T\) 到几十轮量级，测量开销本身就会超过策略更新的计算开销。更硬的边界是正确性 oracle：中间轮的 pass 只是「当前版本能过」，不等于「这条编辑路径通向最终 pass」，把中间 pass 当作独立奖励项会奖励那些碰巧过门却把搜索引向死胡同的编辑。可行的收敛做法是把 \(r_k\) 拆成「门控项」与「增益项」分别聚合，门控项用最终 pass 回填、增益项只在该轮 profile 可信时计入——代价是每轮多一次 oracle 复验，换来的是折扣公式在长轨迹上仍然指向真实因果。
