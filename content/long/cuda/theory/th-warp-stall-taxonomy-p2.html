一 · 逐项拆解：C_k 到底在数什么

公式的第一层不是数学，而是计数口径。C_stall 定义为「warp 未发射的总周期数」，注意主语是 warp 而不是 SM：一个 SM 上并行驻留多个 warp，每个 warp 在每一个调度机会上要么发射一条指令，要么因某个原因被挡回。C_k 就是被第 k 类原因挡回的次数，按 warp 累加。因此 C_stall 的量纲是「warp·周期」，不是墙钟周期。这一点决定了后面所有占比 f_k 的解释力边界：它描述的是调度器视角下的供给损失，而不是 SM 的空转时间。

逐项含义需要按 stall 的触发位置区分。long_scoreboard 对应长延迟依赖：warp 的下一条指令要读的寄存器，其生产者是一条尚未返回的全局/局部访存指令，记分牌未置位，warp 被挂起。short_scoreboard 对应短延迟依赖，典型是共享内存访问与部分固定延迟的 MIO 路径。wait 对应执行依赖，即生产者是另一条算术或特殊功能指令，结果尚未写回。barrier 对应屏障同步，warp 已到达但同 CTA 内其他 warp 未到。imc 对应指令取指缺失，指令缓存未命中导致没有可发射的指令。not_selected 则是另一类：warp 本身已就绪，但同一调度周期内有更高优先级或更早排队的 warp 被选中，它被「挤掉」。

关键在于 not_selected 与其余五类在语义上不同构。前五类是 warp 自身不可发射，not_selected 是 warp 可发射但未被选中。把它放进同一个求和式里，等于把「供给不足」与「供给过剩」两种相反的信号混在一个分母下。公式在形式上允许这样做（它们确实都是「未发射」），但在归因上必须切开，这正是失效条件的第一条。

一个具体例子：一个以全局访存为主的 elementwise kernel，若 C_long_scoreboard 占主导，说明延迟隐藏不足，方向是提高并行度或做预取；若同一个 kernel 的 C_not_selected 占主导，说明驻留 warp 已经足够多、调度器有得挑，此时再去提高占用率是无效投入，真正的瓶颈可能在别处（比如发射带宽或指令组合）。同一个 C_stall 总量，两种 f_k 分布指向完全相反的动作。

二 · 求和式的成立条件与推导关键步

把 C_stall 写成 Σ C_k 并不是恒等式，而是一个建模假设：每个未发射的调度机会被且仅被一个原因解释。推导的关键步在于「互斥且完备」这两条。

互斥性来自硬件 stall 原因的编码方式：性能计数器在每个调度周期对 warp 的阻塞原因做一次判定，输出一个原因标签，而不是多个。因此单次未发射事件只落入一个 C_k。这一步在硬件层面基本成立，但在 profiler 聚合层面会松动——采样型 profiler 不是逐周期记录，而是按固定间隔采样计数器快照，再把增量归到采样窗口内。窗口内的多次事件被压缩成一个增量，原因标签取的是窗口结束时刻的状态。于是「一次事件一个标签」在聚合后变成「一段增量一个标签」，互斥性在时间维度上被粗糙化了。

完备性更脆弱。K 集合写成 {long_scoreboard, short_scoreboard, wait, barrier, imc, not_selected, …}，末尾的省略号是诚实的：真实硬件还有 sleeping、membar、drain、misc 等类别，以及某些微架构上无法归类的残留。若 profiler 只暴露前六项而把其余折叠进 misc 或直接丢弃，则 Σ C_k < C_stall，差额就是未归因部分。工程上应把「未归因比例」当作一个诊断量：若它显著，说明当前 profiler 的原因分类与目标微架构不匹配，此时任何 f_k 都是在残缺分母上算出来的。

$$\hat{C}_{\text{stall}}=\sum_{k\in\mathcal{K}_{\text{obs}}}C_k,\qquad \rho=\frac{C_{\text{stall}}-\hat{C}_{\text{stall}}}{C_{\text{stall}}}$$

ρ 是未归因率。它的代价是显存的：要算 ρ 必须同时采集总 stall 计数与分项计数，两套计数器并行开启会占用更多硬件计数通道，而 SM 上可用的计数器组数有限，多路复用会拉长采集时间、增加 replay 次数，进而放大采样误差。这是「完整性」与「采集开销」之间的直接交换。

一个具体场景：在小 kernel 上做单次采集，ρ 看似很小，但这是因为分母 C_stall 本身就被采样误差压低了，两个误差同向抵消，制造出虚假的完备性。正确做法是同时报告 ρ 与采样次数，而不是只报 f_k。

三 · 占比 f_k 的归一化与它的信息损失

f_k = C_k / C_stall 是一个归一化，把绝对周期数变成相对份额。归一化的好处是跨 kernel、跨规模可比：一个大 kernel 与一个小 kernel 的绝对 stall 周期不可直接比较，但份额可以。代价是丢失了绝对量级信息——两个 kernel 的 f_long_scoreboard 都是 0.6，一个总 stall 是十万级、一个是千级，工程含义完全不同。

更细的一层损失在于分母的选择。用 C_stall 做分母，得到的是「在已发生的 stall 中各类占多少」；若改用总调度机会数 C_issue + C_stall 做分母，得到的是「发射效率被各类原因侵蚀了多少」。前者回答「瓶颈是什么」，后者回答「损失有多大」。两者不可混用：把 f_k 当作损失比例去估算性能上限，会把「占比高」误读成「改进空间大」，而实际上占比高只说明该类原因是当前的主要阻塞，不说明消除它能换来多少吞吐。

推导上还有一个隐含步骤：f_k 的可加性。Σ f_k = 1 只在完备性成立时成立。若 ρ > 0，则 Σ f_k < 1，剩余份额属于未归因。工程上应显式保留这一项而不是把 f_k 强行归一到 1，否则会把 profiler 的分类缺口伪装成某一类的份额。

具体例子：对一个以 shared memory 为主的 kernel，若 short_scoreboard 与 barrier 各占三成、not_selected 占两成、ρ 为两成，则真实可动的空间集中在前两项，而 not_selected 那两成是「占用率充足」的证据而非瓶颈。此时若把 not_selected 也当作待消除的 stall 去优化，方向就错了——它恰恰说明调度器有富余。

四 · 离散化与近似发生在哪三个位置

公式看起来是连续求和的恒等式，实际落地要经过三层离散化/近似，每一层都引入可控但不可忽略的偏差。

第一层是时间离散化。硬件计数器按调度周期递增，profiler 按采样间隔读取。设采样间隔为 Δ，单次采样得到的是区间内的计数增量。若 stall 事件在区间内非均匀分布（例如 kernel 启动初期与稳态差异大），则区间平均值不能代表瞬时行为。这是把连续过程压成离散快照的代价，表现为时间分辨率与采集开销的交换：Δ 越小分辨率越高，但 replay 次数增加、总采集时间线性上升。

第二层是空间离散化。计数器按 SM 或按 SM 子分区聚合，warp 级原因在向上聚合时被平均。若同一 SM 上不同 warp 的阻塞原因分布差异大（例如一个 CTA 在等 barrier、另一个在等访存），聚合后的 f_k 是混合分布，不能代表任一 warp 的真实处境。要拿到 warp 级归因需要 per-warp 采集，代价是采集通道与存储的成倍增长。

第三层是原因判定的近似。硬件在每个周期只能给出一个原因标签，当多个条件同时成立时（例如指令既缺取指又缺操作数），标签取优先级最高的那个。这意味着 C_k 是「在优先级规则下被判定为该原因」的计数，而不是「该原因独立贡献」的计数。优先级规则本身是微架构相关的，跨代比较 f_k 需要谨慎。

$$C_k^{\text{obs}}=\sum_{t\in\Delta}C_k(t)+\varepsilon_k,\qquad \mathbb{E}[\varepsilon_k]\neq 0\ \text{当原因判定有优先级偏置}$$

ε_k 的期望不为零，说明这不是无偏噪声而是系统性偏差。工程含义是：f_k 的绝对值不可跨微架构直接比较，但同一微架构内的相对排序通常稳健。这也是为什么归因分解适合做「同一 kernel 的多版本对比」而不适合做「跨平台绝对评分」。

具体例子：一个 kernel 在两种实现下 f_long_scoreboard 分别为 0.55 与 0.35，即使采样误差存在，排序结论（前者访存依赖更重）仍然可信；但若把这两个数拿去和另一块 GPU 上的 0.5 比较，优先级规则差异可能吞掉这个差距。

五 · 采样误差与中位数的工程口径

失效条件明确指出：采样型 profiler 的 stall 计数存在统计误差，小 kernel 上需多次采样取中位数。这句话背后是一个具体的估计问题。小 kernel 的总周期数少，单次采样窗口内的事件数少，相对误差被放大；同时 kernel 启动/收尾阶段的非稳态占比高，单次采样很容易落在非稳态区间。

取中位数而非均值，是因为 stall 计数的误差分布是右偏的：偶发的 replay 抖动、上下文切换、时钟频率波动都会把个别采样值推高，均值被长尾拉偏，中位数对长尾稳健。代价是采样次数 N 的线性开销：N 次采集意味着 N 倍的采集时间与 N 份计数器读取，若每次采集都要 replay kernel，则总耗时是单次的 N 倍，这在长 kernel 上不可接受，只在小 kernel 上划算。

工程上应把 N 与离散度一起报告。若 N 次采样的 f_k 中位数稳定但四分位距大，说明归因结论本身不稳，此时应增大 N 或改用确定性计数（若硬件支持）而非继续解读 f_k。另一个具体判断：当某类的 f_k 中位数与某次单采样值差距超过采样间离散度时，不应以单次采样下结论。

这里还有一个与分母耦合的陷阱：C_stall 本身也是采样量，f_k 是两个采样量之比，比的误差不是两个误差的简单相加，在分母接近零时会被急剧放大。小 kernel 上 C_stall 小，正是分母接近零的区域，因此 f_k 的方差在小 kernel 上天然更大——这与「小 kernel 需多次采样」是同一件事的两种表述。

六 · 从公式到动作：归因结论的可用边界

公式的最终用途是定位瓶颈而非猜测，因此它的可用边界必须写清楚。三条边界直接来自前面的推导。

第一条：not_selected 高时不得与访存 stall 同等归因。它在求和式里合法，在动作层面非法。判据是看 not_selected 与其余项的相对关系：若 not_selected 是最大项，说明就绪 warp 充足，优化方向应转向发射效率、指令组合或减少总指令数，而不是提高占用率或加预取。

第二条：ρ 显著时 f_k 不可作为决策依据。未归因部分可能藏着真正的瓶颈类别，此时应先解决 profiler 与微架构的匹配问题（换计数器组、换采集模式），再谈归因。

第三条：跨微架构不比绝对值，只比同平台内的排序与差值。优先级偏置使 ε_k 有非零期望，绝对份额不可移植。

一个具体工程判断：拿到一份 f_k 分布后，先看 ρ 与 not_selected 两项，再看剩余项的最大者。若 ρ 小、not_selected 不突出，则最大项就是当前瓶颈，动作直接；若 ρ 大或 not_selected 突出，则这份分布只能用于排除某些假设（例如「不是占用率问题」），不能用于选定优化动作。这个判断顺序本身就是公式推导的产物：求和式的完备性与 not_selected 的语义异质性，决定了读表的次序。

归因公式的适用边界：当分母不再代表瓶颈

公式 $$C_{\text{stall}}=\sum_{k\in\mathcal{K}}C_k,\quad f_k=\frac{C_k}{C_{\text{stall}}}$$ 的成立前提是：被计入 Cstall 的每一类周期都确实构成发射阻塞。但 not_selected 这一项恰恰违反该前提——它记录的是 warp 已就绪、却因调度器优先选择了其他 warp 而未被发射的周期。此时 SM 的发射端口并未空闲，占用率充足，fnot_selected 偏高说明的是资源冗余而非瓶颈。把它与 long_scoreboard 同等加权求和，等于把“排队等待”和“无人可用”混为一谈，归因结论会系统性偏向“增加并行度”这一错误方向。工程上应把 not_selected 从分母中剥离，单独作为占用率健康度指标报告，而非并入 stall 分解。

推导的关键近似在离散化：profiler 以固定采样间隔对 warp 状态做快照，每个采样点只能标记一个原因，因此 Ck 是采样计数而非精确周期计数。当 kernel 总时长接近采样周期量级时，单次采样的相对误差被放大，fk 的排序可能在多次运行间翻转。代价是确定的：小 kernel 上必须多次采样取中位数，采样开销本身会拉长测量窗口，且中位数只保证排序稳定、不保证占比数值可跨 kernel 比较。跨 kernel 比较 fk 时，应固定采样频率与 kernel 规模区间，否则分母的统计噪声会污染归因。

项含义失效信号
Cstallwarp 未发射总周期含 not_selected 时被高估
fnot_selected就绪但未选中占比高值≠瓶颈，指示占用率充足
flong_scoreboard访存依赖占比小 kernel 采样噪声下排序不稳

具体例子：一个访存密集 kernel 若 fnot_selected 与 flong_scoreboard 同时偏高，正确解读是“访存延迟已被足够多的 warp 掩盖，瓶颈在别处”，而非“访存 stall 严重”。此时若按 fk 直接排序优化，会把工程投入导向无效的访存合并优化；真正该做的是检查指令取指或屏障项。归因分解的价值在于定位，而定位的可信度取决于分母是否干净——剥离 not_selected、固定采样窗口，是让 fk 具备跨轮次可比性的最低代价。
