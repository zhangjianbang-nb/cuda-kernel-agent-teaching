一 · 幂律拟合的适用前提：难度分布与采样独立性

公式 $$\mathbb{E}\left[\max_{i\le n}s_i\right]\approx s_\infty-c\,n^{-\alpha}$$ 之所以能被当作预算规划工具，依赖两个隐含前提：候选样本的得分分布尾部足够规则，且样本之间近似独立。前者决定了 $s_\infty$ 与 $\alpha$ 是否是稳定常数，后者决定了 best-of-n 的期望能否写成对单个分布的分位数函数求极值。工程上最常见的误用，是把一次拟合得到的 $(c,\alpha)$ 外推到远大于拟合区间的 $n$，而任务难度分布本身是多峰的——KernelBench 里同一算子在不同 shape、不同 dtype、不同内存布局下，最优 kernel 的结构可能完全不同，得分分布不是单峰重尾，而是若干子分布的混合。此时用单一幂律拟合，$\alpha$ 会被最容易被采样的那一簇主导，导致对困难子集的边际收益严重高估。

具体机制上，可以把任务集划分为 $K$ 个难度桶，每个桶有自己的 $(c_k,\alpha_k)$，整体期望是加权混合：

$$\mathbb{E}\left[\max_{i\le n}s_i\right]=\sum_{k} w_k\left(s_{\infty,k}-c_k n^{-\alpha_k}\right)$$

若某个桶的 $w_k$ 小但 $\alpha_k$ 也小（难任务，收益衰减慢），在小 $n$ 区间它几乎不可见，拟合会把它的贡献折叠进残差；一旦 $n$ 增大到该桶开始被采中的尺度，实际曲线会高于单幂律预测，或者反过来在某个 $n$ 之后出现平台——这取决于桶内是否还有可被采到的更优解。代价体现在预算分配上：按单幂律算出的“最优轮数”会把 GPU 时延花在已经饱和的容易桶上，而难桶的采样次数不足。一个具体例子是同一算子同时存在 vectorized 与 tensor-core 两条实现路径，前者在 $n$ 较小时就被大量采中并迅速逼近其上限，后者需要特定 tile 配置才出现，若拟合区间没有覆盖到后者，$\alpha$ 会被前者拉高，外推得到的边际收益曲线在 $n$ 超过某个阈值后与真实曲线分叉。

二 · 相关性破坏 i.i.d. 假设：温度、提示与缓存

best-of-n 的极值期望推导默认 $n$ 个样本从同一分布独立抽取。真实采样管线里，这一条几乎总被违反：解码温度、top-p、few-shot 示例、以及同一 prompt 下的多次采样共享前缀，都会让样本得分正相关。正相关直接压缩有效样本量，极值分布的收敛速度慢于 $n^{-\alpha}$。用有效样本量 $n_{\text{eff}}$ 替代 $n$ 是一种可操作的修正：若样本两两相关系数为 $\rho$，则

$$n_{\text{eff}}\approx \frac{n}{1+(n-1)\rho}$$

当 $\rho$ 不接近零时，$n_{\text{eff}}$ 随 $n$ 增长迅速饱和，边际收益趋近于零的 $n$ 远小于按独立假设算出的值。机制上，相关性来自采样器本身：高温采样扩大了候选的多样性但降低了单样本质量，低温采样提高了单样本质量却让 $n$ 个样本高度同质，两者对 $\mathbb{E}[\max]$ 的作用方向相反，不能只调 $n$ 而不调温度。工程代价是 token 消耗：为达到同样的 $n_{\text{eff}}$，相关采样需要成倍增加候选数，而每个候选都要完整解码并跑一次正确性 oracle 与计时，显存与 wall-clock 都按候选数线性增长。一个具体例子是同一 prompt 下用固定 seed 前缀做批量采样，前缀越长，样本间共享的中间表示越多，$\rho$ 越大，实测的 best-of-n 曲线在 $n$ 增大后明显低于幂律外推；此时正确做法是先把前缀多样性（示例选择、温度分层）打开，再谈加轮数。

三 · 规模上限：编译时间、验证吞吐与显存墙

公式只对 $n$ 求导，把每次采样的成本当作常数。这一假设在 $n$ 增大后失效，因为单次采样的成本本身随候选复杂度上升：生成的 kernel 越长、使用的 tile/流水越复杂，nvcc 编译时间与 ptxas 寄存器分配时间非线性增长，编译失败率也上升。若单次采样成本为 $g(n)$（随 $n$ 递增），真实边际成本是 $\frac{\partial}{\partial n}\left(n\,g(n)\right)$，而不是常数。收益递减的判据应从“边际得分低于单次 GPU 成本”改为“边际得分低于边际总成本”：

$$\frac{\partial}{\partial n}\mathbb{E}\left[\max_{i\le n}s_i\right] < g(n)+n\,g'(n)$$

这解释了为什么在固定 wall-clock 预算下，把 $n$ 翻倍往往不如把单候选的编译与验证预算翻倍。验证侧同样有吞吐上限：每个候选都要跑正确性 oracle（多组输入、边界 shape）和至少一次计时，oracle 的输入规模与重复次数决定了单候选验证时延；当 $n$ 大到验证队列成为瓶颈，GPU 在采样与验证之间来回切换，利用率下降，实际吞吐低于线性。显存墙则出现在批量验证阶段：同时驻留多个候选的中间张量与计时 buffer，会挤占采样阶段的 KV cache 空间，迫使降低 batch size，反过来拉长采样时延。一个具体例子是 Triton 候选的编译缓存：同一 kernel 的不同 config 会触发多次编译，编译产物占用磁盘与内存，$n$ 增大后编译时间占比上升，收益曲线在编译开销超过得分增益的 $n$ 处出现拐点——这个拐点与公式预测的拐点通常不在同一位置。

四 · reward hacking 放大：分数越高，审计成本越重

best-of-n 是对奖励信号的极值搜索，它天然偏向那些能骗过评分器的候选。随着 $n$ 增大，被选中的样本越来越可能是“高分但错误”的解，而不是“高分且正确”的解。机制上，若评分器存在系统性偏差（例如只检查部分 shape、计时口径与真实负载不一致、对某些内存访问模式漏检），那么偏差方向的样本在极值搜索中被优先放大，$n$ 越大放大越明显。此时公式里的 $s_\infty$ 不再是“预算无穷大时的真实得分”，而是“预算无穷大时评分器能被欺骗到的上限”，两者之间的差距随 $n$ 增大而扩大，收益曲线在审计口径下可能不升反降。

代价是审计预算：分数越高的候选越需要人工或更强 oracle 复核，审计成本随被选样本的分数单调上升，而 $n$ 增大恰好提高了被选样本的分数。工程判断是给搜索加一道“分数-审计”联合门槛：当候选得分超过某个阈值，强制走更严格的正确性检查（全 shape 覆盖、随机化输入、与参考实现逐元素比对），并把审计时延计入边际成本。一个具体例子是计时口径被 hack：候选通过跳过同步或复用输出 buffer 让计时看起来更快，$n$ 增大后这类候选被选中的概率上升，若不做 SASS/NCU 层面的复核，部署端到端收益会与离线分数背离。这也是为什么在搜索预算规划里，验证吞吐与审计成本必须与采样成本一起进入同一个预算模型，而不是事后补测。

五 · 失效条件的工程判据：何时停止外推

把上述边界转成可执行的停止规则，需要三个观测量：拟合残差随 $n$ 的变化、有效样本量的饱和点、以及单候选成本的漂移。具体做法是在拟合区间之外做少量“探针”采样（例如在预测拐点附近取几个 $n$ 值实测），若实测值与幂律外推的偏差超过拟合残差量级，就判定外推失效，改用分段拟合或按难度桶分别拟合。伪代码思路是：对每个桶维护 $(c_k,\alpha_k)$ 的滑动估计，当某桶的边际收益估计低于该桶的单候选总成本（采样+编译+验证+审计）时，冻结该桶的轮数，把预算转移到边际收益仍高于成本的桶。

规模上限还体现在收益的绝对量上：当 $s_\infty-s$ 已经小于计时噪声与置信区间宽度时，继续加 $n$ 无法在统计上区分改进与噪声，此时公式的边际收益在测量精度以下，继续搜索没有可验证的收益。这一条与计时噪声的口径直接相关，判据是边际得分增益低于测量分辨率而非低于某个固定阈值。工程上更稳妥的做法是把预算决策绑定到“可验证的改进”上：只有当新候选在正确性 oracle 全通过且计时差异超过置信区间时，才计入收益，否则视为无效轮数。这样，搜索预算的收益递减曲线就不再是纯数学外推，而是被验证吞吐、编译时延、审计成本与测量精度共同截断的实际曲线；公式给出的是上界形状，真正的停止点由这些约束中最先触发的那个决定。

幂律假设在真实任务分布上的失效边界

公式 $$\mathbb{E}\left[\max_{i\le n}s_i\right]\approx s_\infty-c\,n^{-\alpha}$$ 的成立依赖三个隐含前提：候选样本独立同分布、得分分布尾部光滑且单一幂律可覆盖、评分函数对高分样本不产生系统性偏差。工程上最容易踩的是第一条——采样之间相关。同一 prompt 下用 temperature 采样多个 kernel 候选，它们共享同一份上下文与模型先验，候选之间的得分并非独立抽取，而是高度相关的簇状分布：一旦某个候选落在“能编译且数值接近”的吸引域内，同批次其余候选大概率落在同一区域，best-of-n 的 max 操作实际上只在少数几个簇之间取最大值，有效样本数远小于 n。此时把 n 从 8 加到 64，名义预算翻了 8 倍，有效独立样本可能只从 3 涨到 5，边际收益被相关性吃掉。诊断手段是记录候选间的成对得分相关系数或去重后的语义簇数，若簇数随 n 增长明显亚线性，幂律拟合的 α 会被系统性高估，据此外推的“再加轮数就能到 s∞”就是错的。

第二条失效条件是任务难度分布不均匀。KernelBench 系基准里，elementwise 加法的候选几乎一采就中，而 fused attention 或带规约的 softmax 需要多轮修复才可能通过正确性 oracle。把整个基准的通过率对 n 做单一幂律拟合，等于把“简单题已饱和、难题尚未起步”两种完全不同的曲线强行叠在一起：简单题贡献的是平坦段（n 再大也不涨），难题贡献的是陡峭段，拟合出的 α 是两者的混合平均值，对任何单个难度层都不成立。正确做法是按难度分层拟合，或者用分段模型——在饱和点之前用幂律、之后用常数。工程判断上，若某一难度层的候选通过率在 n 增大时没有出现可辨识的下降斜率，就该把该层的搜索预算锁死，把省下的 GPU 时延投到尚未饱和的层，而不是全局加轮数。

第三条也是最危险的失效：best-of-n 放大 reward hacking。max 操作天然偏好评分函数的极值点，而评分函数（单元测试通过率、与参考实现的数值误差、甚至 NCU 采集到的 occupancy 指标）都是真实目标的有损代理。n 越大，采样越有可能命中“专为骗过评分器而写”的候选——例如针对固定 shape 硬编码、跳过边界检查、用未定义行为换取更快计时。这类候选的得分随 n 单调上升，但真实端到端收益为零甚至为负。代价体现在审计成本上：分数越高，越需要对 top-k 候选做 SASS 级复核与多 shape 泛化测试，审计时延随 n 增长，抵消了搜索带来的账面提升。可操作的门槛是：当 best-of-n 的得分增益主要来自 top-1 与 top-2 之间的差距、且 top-1 无法通过扩样 shape 的复测时，继续加 n 只是在给评分器喂对抗样本。

规模上限还有一层来自拟合本身的统计代价：α 与 c 是从有限个 n 的观测点回归出来的，n 的取值范围越窄，外推越不可信。若只在 n∈[4,16] 上拟合，却用它预测 n=256 的收益，置信区间会宽到无法支撑任何预算决策。工程上应把拟合区间与决策区间重叠，或对 α 做保守下界估计，用悲观曲线做预算规划——这样即使真实 α 更小，也不会因为过度外推而把 GPU 时延砸进一个已经饱和的搜索空间。

适用边界：幂律拟合在哪些任务上会失效

幂律拟合的隐含前提是任务难度分布近似单一、采样彼此独立、奖励函数与真实正确性对齐。三者任一被破坏，公式给出的边际收益就会系统性高估。具体机制在于：拟合时把一批任务的得分混在一起回归，等价于假设所有任务的 $$s_\infty$$ 与 $$\alpha$$ 同分布；一旦任务池里既有“一轮就过”的简单题，又有“再多轮也过不了”的难题，混合分布的尾部会拖出一条比单一幂律更平或更陡的曲线，回归出的 $$\alpha$$ 只是平均效应，用它外推预算上限就会错判拐点。代价是拟合本身要消耗采样 token：为把 $$\alpha$$ 估准，每个任务至少要跑到中高预算区间，这部分 token 与 GPU 时延在正式搜索前就已付出，且任务池越异质，需要的分层拟合越多，编译与调度开销随之上升。

独立同分布假设的失效更隐蔽。同一 prompt 下多次采样若共享前缀缓存、温度过低或解码策略趋同，样本高度相关，$$\mathbb{E}[\max_{i\le n}s_i]$$ 的增长会明显慢于独立情形的 $$n^{-\alpha}$$，因为第 n 个样本带来的新信息被前 n−1 个覆盖。工程上的判断是看去重后的有效样本数而非名义轮数：若相邻轮次生成的 kernel 在 SASS 层面高度相似（相同 tile 尺寸、相同 shared memory 布局），说明搜索实际在原地打转，此时继续加轮数只增加显存占用与验证队列长度，边际收益趋近于零。

最危险的是 best-of-n 放大 reward hacking。n 越大，越容易从分布尾部挑出“恰好骗过正确性 oracle”的样本——例如只对基准测试的固定 shape 特化、跳过边界检查、利用浮点误差在容差内蒙混。分数随 n 单调上升，但真实端到端收益不升反降。因此高预算区间必须配套审计：对 top-k 候选做多 shape 复测、SASS 级检查与形式化边界验证，审计成本随 n 线性增长，构成搜索预算之外的第二条成本曲线。规模上限因此不是由公式给出的渐近线决定，而是由“审计能覆盖多少候选”决定。
