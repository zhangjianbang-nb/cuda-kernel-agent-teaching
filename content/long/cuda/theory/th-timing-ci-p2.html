一 · 中位数估计量的逐项含义与它为何先于均值

公式第一项 t̄ = median{t₁,…,tₙ} 里，每个 tᵢ 是第 i 次重复测量的 kernel 时间，n 是剔除预热后的有效重复次数。这里有两个容易被忽略的工程决定：其一，tᵢ 的边界必须与 kernel 的实际执行区间严格对齐——若计时器包住了 host 侧的 launch 与同步，则 tᵢ 混入了不属于 kernel 的固定开销，中位数会被整体抬高一个常数偏移；其二，n 的定义里“剔除预热”不是可选项而是公式的一部分，因为首轮冷启动同时携带了指令缓存未命中、页表建立、L2 冷态与可能的频率爬升，这些效应不属于稳态分布，混入样本会同时污染中位数与区间端点。

选 median 而非 mean 的推导关键步在于：计时噪声的分布是右偏的。DVFS 降频、其他进程抢占、ECC 巡检等事件只会让某次测量变慢，几乎不会让 kernel 跑得比物理下界更快，因此样本分布有一个硬下界而长尾向右延伸。对这类单边污染分布，样本均值是一阶矩估计，其影响函数无界——单个极端样本即可把均值拖动任意远；而中位数的崩溃点是 50%，只要污染样本少于一半，估计量就稳定。代价是统计效率：在纯高斯噪声下，中位数的方差约为均值的 π/2 ≈ 1.57 倍，即需要多约 57% 的重复次数才能达到同等标准误。这个代价在 kernel 计时里通常值得付，因为污染不是高斯的。

具体例子：对一个稳态耗时在百微秒量级的 kernel 连续采样，若其中若干次因频率切换而显著变慢，均值会被拉高到明显偏离稳态的值，而中位数仍落在稳态附近；此时若报告均值，下游的 roofline 归一化会系统性低估达成率。这就是本片段坚持先取中位数的机制性理由，而不是口味问题。

二 · 自助法区间的构造：重采样、分位点与端点索引

第二项 CI₁₋α = [t₍k₁₎, t₍k₂₎] 的推导路径是：把观测样本 {t₁,…,tₙ} 当作对真实分布的经验近似，从中有放回地抽取 n 个值构成一个重采样样本，计算其中位数，重复 B 次得到 B 个中位数，再取这 B 个值的 α/2 与 1−α/2 分位点作为区间端点。关键步有三处：第一，重采样必须固定 n，因为自助法模拟的是“再来一次同样规模的实验”，样本量变化会改变中位数的抽样分布宽度；第二，端点索引 k₁、k₂ 由 B 与 α 决定，取分位点时对 B 个排序值做线性插值还是取整索引，会带来至多一个样本间距的端点抖动，在 B 较小时这一抖动不可忽略；第三，B 本身是计算预算，B 越大端点越平滑，但每个重采样都要做一次 O(n log n) 的排序或 O(n) 的选择，B 与 n 的乘积直接决定这段分析代码的墙钟时间。

离散化与近似在这里有两层。第一层是经验分布对真实分布的替代：自助法不假设 tᵢ 服从任何参数族，代价是它只能重采样已经观测到的值，因此区间的支撑集被限制在样本最小与最大值之间——真实分布的尾部若未被采样触及，区间会偏窄。第二层是分位点的离散近似：B 个重采样中位数构成的经验分位函数是阶梯函数，取 α/2 分位点本质是在阶梯上做插值，B 不足时端点会随随机种子跳动，需固定种子以保证可复现。

性能代价要算清楚：若 n 为数十、B 为数千，重采样与排序的总操作量在十万量级，纯 Python 实现可能耗时到秒级，而 kernel 本身只有微秒到毫秒级——分析开销远超被测对象。工程上的做法是把重采样向量化（一次生成 B×n 的索引矩阵）或改用选择算法避免全排序，把这段开销压到与测量本身同一量级，否则“测一个 kernel 要等十秒”会直接摧毁多轮迭代的吞吐。

三 · 相对误差项：半宽除以中位数的口径陷阱

第三项 rel_err = half_width / t̄，其中 half_width 是区间半宽，即 (t₍k₂₎ − t₍k₁₎)/2。这一项的作用是把绝对时间尺度上的不确定性折算成可比的比例，使得不同规模的 kernel 能用同一阈值判断“测得够不够准”。推导上它没有复杂步骤，但口径上有三个陷阱。

陷阱一：分母用中位数而非均值，与第一项保持一致，否则分子分母来自不同估计量，比值失去解释力。陷阱二：rel_err 随 n 收缩的速度约为 1/√n（在独立同分布近似下），这意味着把相对误差减半需要四倍重复次数；当 n 从 10 增到 40，区间宽度大致减半，但总测量时间翻四倍，这是明确的时延预算权衡。陷阱三：rel_err 只刻画随机不确定性，不刻画系统偏移——若 DVFS 使整段测量期间频率单调下降，所有 tᵢ 同向漂移，区间会很窄而 rel_err 很小，但估计值与真实稳态值偏离很远。也就是说，rel_err 小不等于测得准，它只说明“重复之间一致”。

具体例子：一个耗时在数十微秒量级的 kernel，若区间半宽为若干微秒，则 rel_err 落在百分之几到十几的范围；此时若下游要用这个计时去判断是否达到 roofline 的某个百分比，误差会直接传导到达成率的判定上。因此 rel_err 必须与区间一起报告，而不能只报一个中位数。

四 · 失效条件的推导：独立同分布假设在哪一步被破坏

自助法区间的合法性建立在“样本近似独立同分布”之上。推导上，重采样之所以能模拟抽样分布，是因为它假设观测值是从同一个分布中独立抽取的；一旦这个假设破裂，重采样得到的 B 个中位数就不再反映真实估计量的波动。DVFS 漂移破坏的是“同分布”：测量序列的前半段与后半段来自不同频率状态，样本是异质的，重采样把不同状态的样本混在一起，得到的区间宽度反映的是状态间差异被平均后的结果，而不是估计量的真实不确定性。

更关键的是系统性偏移不会被区间覆盖。区间的语义是“若重复整个实验，中位数落在该范围内的概率为 1−α”，它覆盖的是抽样波动，不是偏差。若整段测量被频率漂移整体推高，真实稳态值与观测中位数之差是偏差项，区间再窄也不包含它。这是自助法最容易被误用的地方：窄区间给人“测得很准”的错觉，而偏差无人报告。

n 过小（n < 10）时失效是另一条路径：中位数的抽样分布在 n 小时严重依赖具体样本，重采样只有极少数不同的组合，B 个重采样中位数大量重复，分位点估计的方差极大；此时区间端点基本由一两个极端样本决定。工程判断是：n 不足时不要报区间，直接报告原始样本序列，让读者自己看分布形状与漂移趋势。

具体例子：一段测量中前若干次明显快于后若干次，呈现单调变慢的趋势，这本身就是 DVFS 漂移的信号；此时正确做法是插入频率锁定或延长预热使状态稳定，而不是加大 n 去“把区间压窄”——加大 n 只会让区间更窄而偏差不变，反而加剧误判。

五 · 离散化与近似在三项中的分布：一张对照表

把三项公式拆开看，近似出现在不同层级，代价也不同。下表按项列出机制、近似位置与代价来源。

公式项核心机制离散化/近似位置主要代价

这张表的意义在于：三项的误差来源不重叠，不能靠调其中一项来补偿另一项。加大 n 改善第一、二项的随机精度，但对第三项所掩盖的偏差无能为力；固定频率能消除偏差，但不改变区间的统计语义。工程上必须分别处理。

另一个离散化细节是计时分辨率：若单次测量的量化步长与 kernel 真实耗时可比，则 tᵢ 本身已被量化，中位数与区间都建立在量化后的值上，此时区间的窄化会撞到分辨率地板，继续增加 n 不再改善 rel_err。判断方法是看 rel_err 随 n 是否还按 1/√n 收缩，若不收缩即已触底。

六 · 从公式到工程判断：报告口径的最小充分集

把三项合起来，一个可被下游消费的计时报告至少包含：中位数、区间上下界、rel_err、有效 n、是否剔除首轮冷启动的声明，以及原始样本或至少其分位摘要。缺任何一项，读者都无法判断窄区间是精度还是偏差造成的。特别是“是否剔除冷启动”这一声明，直接改变 n 与中位数的语义，不声明则两次报告不可比。

在 kernel 生成与优化的闭环里，这个口径决定了反馈信号的质量：若 agent 用未声明口径的单次计时作为奖励，它会系统性地奖励那些“恰好落在快频率窗口”的实现，而不是真正更快的实现——这与奖励黑客的激励不相容是同一类问题，只是发生在测量层而非任务层。把中位数与区间作为奖励输入，等于把随机波动从信号里剥离，剩下的差异才可能是实现差异。

最后落在具体机制上：rel_err 的阈值应当由下游判定的分辨率反推，而不是拍一个固定百分比。若下游要区分两个实现之间百分之几的性能差异，则 rel_err 必须显著小于该差异，否则区间重叠，判定不可信；由此反推所需 n，再乘以单次测量时延得到总预算，这才是计时方案的设计顺序——先定判定分辨率，再定 n，而不是先测了再说。

置信区间的适用边界：自助法覆盖不到的那部分误差

把 t_i 视为第 i 次重复测量的 kernel 时间，中位数 t̄ 与自助法区间 CI 只回答一个问题：在给定样本内，重复测量带来的随机波动有多大。它的推导关键步在于对经验分布做有放回重采样，用重采样中位数的分位数近似抽样分布，因此区间宽度随 n 收缩的量级约为 1/√n；这一步隐含了样本近似独立同分布的假设。一旦 DVFS 漂移使前后半段样本的均值发生系统性偏移，重采样只是在混合分布里反复抽样，区间会围绕一个被污染的中心收窄，却不会把偏移量纳入半宽。也就是说，rel_err = half_width / t̄ 变小并不代表测量更可信，只代表随机成分被平均掉了，系统性成分原封不动地留在偏差里。

失效条件因此可以写得很具体：n < 10 时，中位数的抽样方差本身很大，自助法分位数对尾部样本极度敏感，区间上下界会随单次重采样跳变，此时必须报告原始样本而非只给区间；样本存在单调漂移（如频率阶梯下降）时，应改用分段统计或对 t_i 做趋势校正后再重采样，否则区间是虚假的窄。工程代价在于，为压制漂移而拉长采样窗口会直接抬高测量时延与占用显存带宽的持续时间，而重采样次数（如千次级）只消耗主机侧 CPU 时间，不触及 GPU，故成本主要落在 wall-clock 而非 kernel 本身。

离散化与近似发生在两处：一是把连续时间戳量化为时钟计数，量化步长决定了单样本的下限噪声，样本量再大也无法把区间压到步长以下；二是用有限次重采样的经验分位数近似理论分位数，重采样次数不足会让 k₁、k₂ 对应的边界抖动。举例而言，对一个受缓存状态影响的访存型 kernel，若首轮冷启动未剔除，前几个样本显著偏慢，中位数被拉高、区间被拉宽，rel_err 虚高；剔除预热后 n 变小，又回到 n < 10 的不稳定区。这个张力说明：是否剔除冷启动必须在报告里显式声明，并与 n 的有效值一起给出，否则区间无法被复现。
