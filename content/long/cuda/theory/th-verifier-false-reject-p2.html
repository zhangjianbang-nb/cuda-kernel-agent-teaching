一 · 逐项拆解：分子分母各自在数什么

把 FRR 的分子写成集合基数是第一步，真正要问的是“correct→reject”这个箭头两端各由谁定义。分母 #{correct} 不是“所有提交的 kernel”，而是“被正确性 oracle 判为正确的 kernel 集合”——这个集合本身是参考实现与容差共同构造出来的产物。于是 FRR 的分母不是客观常量，而是一个随 oracle 配置漂移的量。工程上必须把 FRR 写成条件概率形式才不歧义：

$$\text{FRR}=\Pr\big[\,\hat{V}(k)=\text{reject}\;\big|\;k\in\mathcal{K}_{\text{correct}}\,\big],\qquad \mathcal{K}_{\text{correct}}=\{k:\ \mathrm{err}(k,k^\star)\le\tau\}$$

这里 $\hat{V}$ 是验证器（可能是数值比对、也可能是形式化检查器），$k^\star$ 是参考实现，$\mathrm{err}$ 是误差度量，$\tau$ 是容差。关键推导步在于：$\mathcal{K}_{\text{correct}}$ 的定义里已经含了 $\tau$，而 $\hat{V}$ 内部通常又有一个独立的判定阈值 $\tau'$。FRR 的大小本质上是 $\tau$ 与 $\tau'$ 两个阈值的相对位置决定的，不是验证器“本身”的固有属性。这就是为什么同一个 validator 在不同 benchmark 上 FRR 可以差一个量级——不是 validator 变了，是 $\tau$ 变了。

代价在这里第一次显形：收紧 $\tau$ 会让分母缩小（更多实现被踢出 correct 集合），同时让 $\hat{V}$ 更难通过，FRR 上升；放宽 $\tau$ 则分母膨胀、FAR 上升。二者不是独立的两个旋钮，而是同一根轴的两端。KernelAudit 报告 6 个 validator 存在不可忽视的 false-reject，其可操作含义正是：这些 validator 的 $\tau'$ 相对其服务的 benchmark 的 $\tau$ 偏紧，且紧得没有随误差分布形状调整。

二 · 从误差分布到 FRR：一个可推导的积分表达

设正确实现的误差 $e=\mathrm{err}(k,k^\star)$ 服从某个分布 $f_e$（支撑在 $[0,\tau]$ 上，因为超出 $\tau$ 就不算 correct）。验证器拒绝的条件是它自己算出的误差估计 $\hat{e}$ 超过 $\tau'$。若 $\hat{e}=e+\eta$，$\eta$ 是验证器自身的测量噪声（浮点重排、不同 reduction 顺序、不同精度路径都会贡献），则

$$\text{FRR}=\int_0^{\tau} f_e(e)\cdot \Pr[\eta>\tau'-e]\ \mathrm{d}e=\int_0^{\tau} f_e(e)\,\big(1-F_\eta(\tau'-e)\big)\,\mathrm{d}e$$

这个积分把 FRR 拆成两个可分别攻击的因子：误差分布 $f_e$ 的尾部质量，以及噪声分布 $F_\eta$ 在阈值附近的形状。推导关键步是变量替换——把“验证器判错”翻译成“噪声把估计推过阈值”，从而把 validator 的行为归因到 $\eta$ 上。工程含义直接：若 $\eta$ 是零均值且方差为 $\sigma^2$，则 $\tau'$ 每向 $\tau$ 靠近一个 $\sigma$，积分区间内的 $1-F_\eta$ 就显著抬升；反过来，把 $\tau'$ 设为 $\tau+\alpha\sigma$ 可以把 FRR 压到可控水平，代价是 FAR 按 $1-F_e$ 的对应尾部增长。

具体例子：一个 reduction kernel 的正确实现因线程块内累加顺序不同，误差在 $10^{-6}$ 量级波动，而验证器用严格 $10^{-7}$ 相对容差比对，则 $\tau'-e$ 对相当一部分正确实现为负，$1-F_\eta$ 接近 1，FRR 被推到接近“所有顺序敏感实现都被拒”的程度。这不是数值 bug，是阈值与噪声尺度不匹配。代价是搜索预算：每次误拒都让 agent 丢掉一个本可用的候选，并把“往哪个方向改”的信号污染成噪声。

三 · 离散化与近似：连续积分在工程里怎么落地

上面的积分在实践中不可直接算，因为 $f_e$ 未知。工程做法是用有限测试用例集做蒙特卡洛估计：对 $N$ 个输入，每个输入上跑 $M$ 个正确实现（或同一实现的不同合法调度），统计拒绝次数。于是 FRR 的估计量是

$$\widehat{\text{FRR}}=\frac{1}{NM}\sum_{i=1}^{N}\sum_{j=1}^{M}\mathbf{1}\big[\hat{V}(k_{ij})=\text{reject}\big],\qquad \mathrm{Var}(\widehat{\text{FRR}})\approx\frac{\text{FRR}(1-\text{FRR})}{NM}$$

离散化在这里引入两层近似。第一层是输入采样：$N$ 个测试输入只覆盖了输入空间的一小片，若误拒集中在特定 shape（例如非对齐的尾块、奇数长度的 reduction），采样偏差会让 FRR 被系统性低估。第二层是“正确实现”的采样：$M$ 通常远小于合法实现空间，尤其当正确性对调度顺序不敏感、对累加树形状敏感时，$M$ 个样本根本探不到误差分布的尾部。方差公式给出的是采样代价的量化：要把标准误压到 $0.01$ 量级，在 FRR 约 $0.1$ 时需要 $NM$ 达到数百量级；若每个用例要跑一次完整 kernel 加一次参考比对，这就是实打实的时延预算。

还有一层更隐蔽的近似：$\hat{V}$ 内部的误差估计本身可能是近似的（例如用低精度累加去估高精度结果的误差），此时 $\eta$ 不是纯噪声而是带偏的，积分表达里的零均值假设失效，FRR 会被单向推高或压低。工程判断是：任何 FRR 数字都必须附带“在什么 $\tau$、多少 $N,M$、用什么误差度量”的三元组，否则不可比。

四 · 容差耦合：FRR 与 FAR 的同轴代价

把 FAR 写成对称形式后，两者的耦合立刻清楚：

$$\text{FAR}=\int_{\tau}^{\infty} g_e(e)\,\Pr[\hat{e}\le\tau']\,\mathrm{d}e,\qquad \frac{\partial\,\text{FRR}}{\partial\tau'}<0,\quad \frac{\partial\,\text{FAR}}{\partial\tau'}>0$$

其中 $g_e$ 是错误实现的误差分布。两个偏导符号相反，说明 $\tau'$ 是一个零和旋钮：降低 FRR 必然抬高 FAR，除非改变 $\eta$ 的方差或 $f_e$ 的形状。这就是为什么“把容差调松一点”不是免费的修复——它把误拒换成了误放，而误放的代价在 agent 搜索里更贵：一个被误放的错误 kernel 会进入后续优化轮次，污染信用分配，让 agent 学到错误的改写方向。KernelAudit 的 6 个 validator 之所以值得单独审计，正是因为它们的 $\tau'$ 选择没有显式记录这条耦合曲线。

可操作的推导结论是：给定 $f_e$、$g_e$、$F_\eta$，存在一个使加权总错误率最小的 $\tau^\star$，其位置由两类错误的相对代价决定。若误拒的代价是“浪费一次搜索预算”，误放的代价是“污染后续 $T$ 轮信用分配”，则权重比大致是 $1:T$，最优阈值应偏向宽松一侧。这个推导不给出具体数字，但给出方向：在多轮 RL 场景里，FAR 的单位代价高于 FRR，因此不应把 FRR 压到极限。

五 · 失效条件的公式化：标签依赖与对抗抬升

“正确性标签依赖参考实现”这句话在公式里对应一个替换：把 $k^\star$ 换成有缺陷的 $\tilde{k}^\star$，则 $\mathcal{K}_{\text{correct}}$ 的定义整体偏移，FRR 与 FAR 同时失真，且失真方向不可从数据里自检——因为 oracle 和被检验对象共享同一个错误源。形式上，若参考实现自身误差为 $\delta$，则真实正确实现被判为 correct 的概率变成 $\Pr[\mathrm{err}(k,\tilde{k}^\star)\le\tau]$，它与 $\mathrm{err}(k,k^\star)$ 的关系依赖 $\delta$ 与 $\tau$ 的相对大小；当 $\delta$ 接近 $\tau$ 时，分母几乎随机化，FRR 退化为噪声。

对抗样本同时推高两种错误率的机制也能在积分式里读出：构造一个 $k$ 使 $\hat{e}$ 的估计被人为压低到 $\tau'$ 以下（骗过 FAR），同时让合法实现的 $\eta$ 分布被同一输入推到阈值之上（抬高 FRR）。这在数值上表现为 $f_e$ 与 $F_\eta$ 被同一个输入特征耦合，积分不再可分离。代价是验证器必须引入与输入相关的阈值或多种子重复测量，而多种子重复直接把每个候选的验证时延乘以种子数——这是 FRR 可信度与吞吐之间的硬 trade-off。

量公式位置工程代价典型触发场景
FRR分子 #{correct→reject}浪费搜索预算、污染改写信号阈值偏紧、顺序敏感 kernel
FAR分子 #{wrong→accept}污染后续 T 轮信用分配阈值偏松、近似误差估计带偏
$\tau,\tau'$分母定义与判定阈值同轴零和，调一个动两个跨 benchmark 复用 validator
$N,M$蒙特卡洛估计量验证时延线性增长尾块 shape、奇数长度 reduction

落到具体机制上：一个 validator 若只报告单一 FRR 数值而不报告 $\tau$、$N,M$ 与误差度量，就无法判断它是“阈值偏紧”还是“采样不足”，这两种病因的修复方向完全相反——前者调 $\tau'$，后者加 $N,M$。工程判断应落在“先测 $\eta$ 的方差，再定 $\tau'$ 相对 $\tau$ 的偏移量”，而不是先调容差再看 FRR 降没降。

分母的构造方式决定了 FRR 的可信边界

把 FRR 写成比值只是第一步，真正决定这个指标能否用于工程决策的是分母 #{correct} 的构造方式。分母不是“所有提交”，而是“被判定为正确的那批实现”，而“正确”这一标签几乎总是由参考实现加容差比较给出。于是 FRR 的测量链条上出现了两个耦合环节：参考实现本身是否忠实于语义，以及容差阈值是否落在数值噪声与真实误差之间。若参考实现存在边界条件错误（例如归约维度上的初始化遗漏、非对齐尾块处理不当），那么一批语义正确的 kernel 会被系统性地划入“错误”集合，从分母中被剔除；此时 FRR 的分子不变而分母缩小，指标被动抬高，看起来“验证器很保守”，实则测量对象已经偏移。反过来，若参考实现过于宽松（例如在浮点比较时使用过大的相对容差），错误实现被吸收进分母，FRR 被稀释，验证器真实的误拒行为被掩盖。这就是失效条件的第一层：标签噪声不是随机扰动，而是与验证器行为相关的选择性偏差。

容差选择是第二个耦合点，它同时移动 FRR 与 FAR，且移动方向相反。设比较函数为 |a−b| ≤ atol + rtol·|b|，当 rtol 收紧，更多数值上略有差异但语义正确的实现被判错，FRR 上升；当 rtol 放松，更多带有累积误差甚至逻辑偏差的实现被放行，FAR 上升。两者不是独立的旋钮，而是一条权衡曲线上的两个坐标。工程上不能只报告一个点的 FRR，必须报告“在给定容差策略下的 FRR”，否则跨验证器比较毫无意义。KernelAudit 发现 6 个 validator 存在不可忽视的 false-reject，这一事实的解读必须绑定各自所用的容差与参考实现版本，否则无法判断是验证器逻辑缺陷还是容差配置过紧。

$$\text{FRR}=\frac{\#\{\text{correct}\to\text{reject}\}}{\#\{\text{correct}\}},\qquad \text{FAR}=\frac{\#\{\text{wrong}\to\text{accept}\}}{\#\{\text{wrong}\}}$$

从系统代价看，FRR 的每一次误拒都不是免费的。在搜索式 agent 流程中，一个被误拒的正确 kernel 会触发重采样或重写，消耗额外的生成 token 与编译时间；若验证器还附带 NCU/SASS profile 作为辅助证据，误拒意味着一次完整的 profile 采集被浪费，其时间开销远高于单纯的编译。更隐蔽的代价是反馈信号污染：agent 从“被拒”这一结果中学习到的梯度指向错误方向，多轮 RL 中可验证奖励被系统性压低，正确策略被惩罚。对抗样本则把两种错误率同时推高——精心构造的输入可以既让正确实现落在容差之外，又让错误实现在参考点上巧合通过，此时 FRR 与 FAR 不再此消彼长，而是同向恶化，单看任一指标都会低估验证器的脆弱性。

环节对 FRR 的作用系统代价
参考实现偏差分母选择性缩小，指标失真正确 kernel 被剔除，搜索预算空转
容差收紧FRR 上升重采样 token、重复编译与 profile
容差放松FRR 下降但 FAR 上升错误实现进入部署路径，返工成本后移
对抗输入FRR 与 FAR 同向恶化指标失去区分度，RL 奖励信号不可信

因此 FRR 的适用边界应当明确写成三条：其一，分母必须来自独立于被测验证器的正确性 oracle，至少要用形式化或差分测试对参考实现做交叉校验；其二，FRR 必须与容差策略、输入分布一起报告，脱离上下文的单一比值不具备比较价值；其三，当输入分布包含对抗性或极端数值范围时，FRR 不能作为唯一判据，需要与 FAR 联合观察其相关性。越过这三条边界，FRR 就从“验证器保守程度的度量”退化为“参考实现与容差配置的联合伪影”，此时用它来指导 agent 的搜索策略，等于把测量误差当成优化目标。

误拒率的分母陷阱与容差耦合

FRR 的分母是“正确实现”的集合，而这个集合的成员资格由参考实现与容差共同裁定，因此 FRR 从来不是验证器单独的函数，而是三元组（validator, reference, tolerance）的联合指标。把 FRR 写成条件概率更便于定位失效点：设 C 为“实现确实正确”的事件，R 为“验证器拒绝”的事件，则 FRR = P(R|C)，FAR = P(accept|¬C)。关键推导步在于把 P(R|C) 展开为对输入分布与数值偏差的积分——验证器实际比较的是输出张量在给定容差 τ 下的逐元素偏差，于是 P(R|C) = ∫ 1[ d(x) > τ(x) ] p(x|C) dx，其中 d(x) 是候选与参考在该输入上的偏差度量。这一步暴露了两个离散化/近似位置：其一，输入分布 p(x|C) 在实践中被有限测试集替代，采样偏差直接进入 FRR 估计；其二，d 与 τ 的比较通常在浮点舍入后的离散网格上进行，边界样本的判定对累加顺序、规约树形状敏感，同一 kernel 换一种 tile 划分就可能跨过 τ。

容差 τ 是 FRR 与 FAR 的公共旋钮，二者沿同一条曲线反向移动，不能独立调优。放宽 τ 降低 FRR 却抬高 FAR，收紧则相反；工程上把这一权衡记为一条隐式约束 FAR ≤ ε 下的 FRR 最小化，但 ε 本身依赖下游对错误 kernel 的容忍度，而非验证器可自证的量。更麻烦的是参考实现错误的情形：若参考在某个输入上本身就偏离真值，则“正确”标签被污染，FRR 与 FAR 同时失真——原本正确的候选被判拒（虚增 FRR），原本错误的候选因贴近错误参考而被放行（虚增 FAR），两个方向同向恶化，指标失去诊断力。对抗样本则把这种耦合推到极端：构造同时贴近参考又在边界外抖动的输入，可让两类错误率一并上升，说明单一标量 FRR 不足以刻画验证器的可信边界。

系统代价体现在三个可测维度。其一是搜索预算：每次 false reject 都让 agent 丢弃一个可用 kernel 并重新采样，等价于把有效候选率乘以 (1−FRR)，在固定采样预算下直接削减可用解的数量，KernelAudit 发现的 6 个存在不可忽视 false-reject 的 validator 正是这类预算泄漏点。其二是判定时延：为压低 FRR 而扩大测试集或加密容差网格，验证成本随时延线性增长，与 kernel 本身的执行时间无关，成为流水线中的固定开销。其三是编译与复现成本：边界样本的判定依赖规约顺序，为稳定 FRR 估计需固定编译选项与 launch 配置，牺牲了部分优化自由度。具体例子：一个正确的 reduction kernel 因改变 warp 内累加顺序，在 τ 附近的若干元素上偏差翻转，被同一 validator 判拒——这不是 kernel 错，而是离散化边界与容差耦合的产物，修复方式应是报告偏差分布而非单点布尔判定。
