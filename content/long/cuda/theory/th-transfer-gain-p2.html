一 · 增益公式的逐项解剖：分母为何是 before

迁移增益的分子是差值，分母是迁移前的目标任务得分，这个选择本身就是一个工程判断。若分母取 after，则同一份绝对提升在强基线上会被压扁，弱基线上会被放大，跨模型比较立刻失去可比性；若分母取源任务得分，则公式回答的是“源任务视角的回报率”，与目标任务部署收益脱钩。取 before 的含义是：以目标任务未受迁移影响时的水平为基准，衡量迁移这一动作带来的相对变化。它的值域是 [-1, +∞)：下界来自得分非负，迁移把目标任务打到接近零时增益趋近 -1；上界无约束，因为 before 可以很小。

逐项看，s_before 不是“模型在目标任务上的原始能力”这么简单，它必须与 s_after 在同一评测口径下测得——同一套 KernelBench 系题面、同一正确性 oracle、同一计时协议、同一硬件与 dtype。任何一项漂移都会污染分母。s_after 则是同一模型在经历源任务训练或上下文注入之后，在目标任务上的得分。这里有一个容易忽略的细节：s_after 的评测必须在迁移流程完全结束后一次性进行，不能边训边测取峰值，否则增益公式度量的是“训练过程中的最好瞬间”，而不是可部署的稳态。

把公式写成绝对量分解更利于推导：设目标任务基线为 b，迁移带来的绝对提升为 Δ，则 G = Δ/b。于是增益对 Δ 是线性的，对 b 是反比的双曲关系。这解释了一个反复出现的现象：同一个 Δ 在弱基线上给出可观的正增益，在强基线上却接近零甚至为负——因为强基线本身已逼近该硬件的 roofline 可达上界（该上界口径见另篇），剩余空间被压缩，而迁移引入的额外开销（编译时间、寄存器压力、occupancy 变化）并不会因为基线强而消失。公式在这里不是描述性的，它是约束性的：它要求任何声称的增益都必须同时报告 b 的绝对水平，否则 G 不可解释。

$$G_{\text{transfer}}=\frac{s_{\text{target}}^{\text{after}}-s_{\text{target}}^{\text{before}}}{s_{\text{target}}^{\text{before}}},\qquad G\in[-1,+\infty)$$

具体例子：MetaKernelBench 实测双向迁移落在 −19%~+29%，这个区间正是 G 的取值区间而非得分区间。−19% 意味着目标任务得分从 b 掉到 0.81b，+29% 意味着升到 1.29b。注意这两端并不对称，负端的绝对值上限受 1 约束，正端却可以更大，因此“均值接近零”完全可能掩盖一批 −19% 的退化和一批 +29% 的跃升同时存在——这正是每个模型/方向仍有 16%–45% 的题退化的直接后果。均值在此不是充分统计量。

二 · 推导关键步：从期望增益到分布意义上的界

把单题增益记为随机变量 G_i，题目 i 的基线得分为 b_i，绝对提升为 Δ_i。总体增益若按题等权平均，则 Ḡ = (1/n)Σ Δ_i/b_i；若按得分加权，则得到另一个量。推导的第一个关键步是明确加权方式，因为 1/b_i 的倒数结构会让弱基线题目主导均值：一道 b=0.1 的题提升 0.05 就贡献 0.5 的单题增益，而一道 b=0.9 的题提升 0.05 只贡献 0.056。这意味着等权平均的 Ḡ 在统计上被少数低分题绑架，报告均值时必须同时给出按题分布的分位数，否则 +29% 可能只是两三道弱基线题的艺术效果。

第二个关键步是把“增益非单调”形式化。设源任务分布为 P_S、目标任务分布为 P_T，迁移的作用可视为把在 P_S 上获得的先验注入目标任务的求解过程。若把求解视为在假设空间 H 上的搜索，源任务先验把搜索起点从 h_0 移到 h_S，则目标任务上的期望得分差可写成 E_{T}[s(h_S)] − E_{T}[s(h_0)]。这个差的符号不由 P_S 上的表现决定，而由 P_S 与 P_T 的重叠程度决定：当两个分布对 kernel 结构的要求一致（同样的访存模式、同样的并行分解、同样的 dtype 语义），h_S 落在目标任务的有利区域，差为正；当硬件或 dtype 变化改变了最优分解（例如向量化宽度、shared memory 容量、tensor core 可用性），h_S 可能落在目标任务的次优甚至错误区域，差为负。这就是失效条件“源/目标任务分布差异大时增益为负”的推导来源，它不是经验观察，而是先验错位在期望上的直接体现。

第三个关键步是引入样本量。设单题增益的样本方差为 σ²，则 n 题均值 Ḡ 的标准误为 σ/√n，置信区间半宽约为 z·σ/√n。这一步给出了“样本量小时置信区间很宽”的定量机制：σ 由题目间的异质性决定，而 16%–45% 的退化率说明异质性很大，因此在小 n 下区间很容易跨过零。工程判断由此而来：当区间跨零时，不能宣称正增益；当区间整体为负时，迁移是净损害，应回退到不迁移的基线。这里不引入任何具体数值，因为 σ 与 n 未被给定，但机制是确定的——区间宽度与 √n 成反比，与题目异质性成正比。

代价维度：这条推导链的每一步都对应可观测的开销。按题等权平均需要逐题跑 before 与 after 两轮评测，评测轮数翻倍直接抬高计时噪声的累积（噪声口径见另篇），并使总评测时延翻倍；引入置信区间需要 n 足够大，n 增大线性抬高评测的 GPU 小时数；而按得分加权虽然省去部分低分题的重复测量，却改变了 Ḡ 的语义，使跨报告比较失效。这是一个典型的“统计严谨性换评测吞吐”的权衡，没有免费选项。

三 · 离散化与近似：连续增益如何落到题目集合上

公式本身是连续的比值，但工程上它只能落在有限题目集合上，这一步离散化引入了三类近似。第一类是题目采样近似：MetaKernelBench 的题目集合是目标任务分布的一个样本，Ḡ 是 G 的样本估计而非真值，其偏差来自题目难度谱的覆盖不全——若采样偏向易题，b 偏大，G 被系统性压低；偏向难题则相反。第二类是得分离散化：KernelBench 系评分通常是“通过正确性 + 达到某加速阈值”的分档，s 取离散档位而非连续时延比，于是 Δ 的最小分辨率是一档，小提升会被舍入抹平，G 在低 b 处出现量化跳变。第三类是计时近似：s 的测量含计时噪声，b 与 after 各自带误差，比值误差在 b 小时被放大——因为分母的绝对误差不变而分母变小，相对误差上升。这三类近似叠加，使得小 n、低 b、短计时的组合下 G 的估计极不稳定。

伪代码思路可写成：对每题 i，先在统一口径下测 b_i，再执行迁移流程，测 a_i；计算 g_i = (a_i − b_i)/b_i；随后不是直接取均值，而是先按 b_i 分层（例如按基线得分分位分桶），在桶内取均值再加权汇总，以抑制 1/b_i 的放大效应；最后对汇总值给出 bootstrap 区间。这个流程的关键在于分层发生在求均值之前，而不是之后——因为 1/b_i 的非线性使得“先平均再算增益”与“先算增益再平均”不等价，前者在数学上更稳，后者才是公式的字面执行。工程上必须明确报告用的是哪一种，否则同一批数据可以给出符号相反的结论。

具体例子：假设某方向有 20 道题，其中 3 道基线得分极低（b 接近 0.05），迁移后提升到 0.1，单题增益接近 +100%；其余 17 道题基线在 0.6 以上，迁移后普遍下降 5%–10%。按公式逐题算再等权平均，Ḡ 可能仍为正；但按得分加权或分层汇总，结论是净退化。MetaKernelBench 报告的 16%–45% 退化率正是这种结构的宏观表现——退化题占比高，但退化题的 b 大、单题增益绝对值小，被少数低 b 题的正增益抵消。离散化近似在这里不是技术细节，而是决定结论符号的关键。

代价：分层汇总需要每道题至少两次完整评测，评测时延与 GPU 显存占用（并发跑多题时）同步上升；bootstrap 区间需要重采样计算，纯 CPU 开销但拖长报告生成时间；分档评分下若要提高分辨率，需改用连续时延比，但这又引入计时噪声的更大方差。三者不可同时优化。

四 · 失效条件的公式化：负增益从哪里进入

把失效条件翻译成公式语言：负增益等价于 a_i < b_i，即迁移后的得分低于基线。在期望层面，这要求 E_T[s(h_S)] < E_T[s(h_0)]。前面已推导其来源是先验错位，但工程上还需要一个可操作的判据。一个可行的判据是分布距离的代理量：若源任务与目标任务在关键结构维度（访存模式类别、并行分解粒度、dtype、目标硬件架构）上的取值不一致，则先验错位的风险上升。硬件或 dtype 变化会破坏迁移，需要重新验证——这句话的公式含义是：h_S 是在旧硬件/旧 dtype 的最优点附近取得的，新硬件改变了 roofline 的位置与可达上界，旧最优点不再最优，甚至可能触发正确性问题（例如 dtype 降精度导致的数值误差越过 oracle 阈值，误差累积界口径见另篇），此时 a_i 不只是低，而是被判为不正确，直接归零。

这里有一个容易被忽视的推导细节：正确性 oracle 是硬阈值，而得分是软度量。当迁移导致数值误差越过阈值时，该题得分从 b_i 直接跳到 0，单题增益为 −1，这是 G 的下界。一批题同时触发阈值会迅速把 Ḡ 拉到负值。因此失效条件的严重程度不是渐变的，而是由阈值附近的题目密度决定的——密度高则小扰动引发大批归零，密度低则退化表现为温和的百分比下降。这解释了为什么硬件/dtype 变化后的重新验证不能只看均值：均值可能温和，但归零题的存在意味着部署风险是离散的、突发的。

具体例子：同一 kernel 在一种 dtype 下通过 oracle，切换到更低精度 dtype 后，累加误差越过阈值，该题得分归零，G = −1；而同方向其他题因访存模式未变而保持正增益。整体 Ḡ 可能仍在 −19%~+29% 区间内，但 −1 的单题是部署时必须单独处理的。工程判断：报告增益时必须同时报告归零题数量，它是比 Ḡ 更强的风险信号。

五 · 从公式到工程判断：何时该信这个界

这个公式给出的是一个界而非一个点估计，其可信度取决于三个前提同时成立：评测口径一致、样本量足以让区间不跨零、题目分布覆盖目标任务的难度谱。三者缺一，G 就只能作为方向性信号。工程上可操作的判断规则是：先看区间是否跨零，跨零则不做迁移决策；再看归零题数量，非零则先修正确性再谈增益；最后看分层后的桶内增益符号是否一致，若高 b 桶为负而低 b 桶为正，说明增益来自弱基线而非真实能力提升，不应部署。这条规则把公式从报告指标变成了准入门槛。

还有一个推导层面的边界值得强调：G 的分母是 before，因此它天然奖励“从低基线起步”的场景，而惩罚“已经接近 roofline 可达上界”的场景。这意味着跨模型比较 G 时，必须同时比较 b 的绝对水平，否则会把“基线弱”误读为“迁移强”。MetaKernelBench 的 −19%~+29% 是跨模型、跨方向的聚合区间，单看这个区间无法判断某个模型是否真的从迁移中获益——必须落到每个模型/方向的 b 分布与退化题占比上。公式的用途不是给出一个可排名的标量，而是给出一个必须与基线水平、退化率、归零题数联合解读的三元组。

代价的最后一项是编译与验证时间：每次迁移后的重新验证都要重跑正确性 oracle 与计时，若目标任务题目多、硬件新，验证时间可能超过训练本身。这使得“小步快跑、频繁验证”的策略在时延上不可行，工程上更常见的是分批验证加早停：先在小子集上估 G 的符号，符号为负即回退，为正再扩样本。这个策略的统计代价是子集估计的区间更宽，但时延代价显著下降——这是在公式的严谨性与工程吞吐之间的实际取舍点。

增益界的分母陷阱与失效面

公式 $G_{\text{transfer}}=(s_{\text{target}}^{\text{after}}-s_{\text{target}}^{\text{before}})/s_{\text{target}}^{\text{before}}$ 的分子是得分差，分母是迁移前的目标任务得分，这个分母选择直接决定了界的形状：$G\in[-1,+\infty)$ 的下界 −1 来自“迁移后得分归零”这一物理极限，而上界无界则意味着当 $s_{\text{before}}$ 很小时，同样的绝对提升会被放大成夸张的相对增益。推导的关键一步是把“迁移”定义为同一目标题集上、同一评测口径下的前后配对差分，而不是两组独立样本的均值差——只有配对差分才能消掉题目难度这一混杂因子。代价在于：配对要求迁移前后使用完全相同的题集、相同的正确性 oracle 与相同的计时口径，任何一处口径漂移都会让分子混入评测噪声而非真实增益。

离散化与近似发生在两处。其一，$s_{\text{target}}$ 是离散题集上的通过率或归一化得分，样本量小时其标准误按 $1/\sqrt{n}$ 量级收缩，置信区间宽度与 $n$ 的平方根成反比，因此小样本下均值 ±29% 完全可能与 0 不可区分，必须报告区间而非点估计。其二，kernel 得分本身是“正确性 × 性能”的复合量，把 roofline 上的 SOL 比例压成单一标量时，任何对时延的近似（如用单次测量代替多次中位数）都会以非线性方式传导进 $G$。

失效条件可以整理成一张判据表：源/目标分布差异大时分子为负，硬件代际或 dtype 变化会破坏已迁移的 kernel 知识（需重新验证正确性与性能），样本量小则区间过宽。MetaKernelBench 实测双向迁移落在 −19%~+29%，且每个模型/方向仍有 16%–45% 的题退化，说明增益界的正区间并不保证逐题安全。
