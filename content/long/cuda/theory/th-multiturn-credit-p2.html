一 · 逐项拆解：$R_t$ 的四个角色

把 $R_t=\sum_{k=t}^{T}\gamma^{k-t}r_k$ 摊开看，它不是一个"总分"，而是四类量被强行压进一个标量的结果。第一项是索引结构：求和从 $t$ 到 $T$，意味着第 $t$ 轮拿到的信号只覆盖"它之后发生的事"，第 $t$ 轮自身的编辑效果被记在 $r_t$ 里，而 $r_t$ 又依赖第 $t-1$ 轮的产物——这是一个隐式的马尔可夫链，状态是"当前 kernel 源码 + 当前正确性状态 + 当前计时基线"。第二项 $\gamma^{k-t}$ 是时间贴现，它决定了远端轮次对当前决策的权重；第三项 $r_k$ 是即时奖励，其内部由 $\Delta\text{speed}_k$ 与 $\mathbb{1}[\text{pass}_k]$ 的乘积构成，这两者量纲不同、噪声结构不同，相乘之后语义变得含混；第四项是求和本身，它假设各轮奖励可加，而实际上第 $k$ 轮的加速变化是相对于第 $k-1$ 轮基线的差分，差分序列求和会退化为望远镜求和——$\sum_k \Delta\text{speed}_k = \text{speed}_T - \text{speed}_{t-1}$，如果 $\gamma=1$ 且 pass 恒为真，$R_t$ 就等价于"最终加速比减初始加速比"，中间轮次的信息被完全抹平。这是公式最容易被误读的地方：它看起来在分配信用，实际在 $\gamma=1$ 时退化成一个终点差值。

$\Delta\text{speed}_k$ 的定义必须绑定基线。若基线是"上一轮实测加速比"，则 $\Delta$ 可正可负，负值代表该轮编辑造成回退，此时 $r_k$ 为负，$R_t$ 会惩罚导致回退的中间决策——这是公式唯一能表达"中间轮次有害"的通道。若基线是"初始 kernel 的加速比"，则 $\Delta$ 恒为非负增量，公式退化为对最终收益的重复计数。两种基线选择对应完全不同的信用语义，工程实现里必须显式声明，否则同一份轨迹在两种实现下产出相反的梯度方向。$\mathbb{1}[\text{pass}_k]$ 是硬门，它把"跑得快但算错了"的轮次直接归零，代价是该轮的一切探索信号被丢弃：一个把 kernel 改到 3 倍速但边界条件写错的轮次，其 $\Delta\text{speed}$ 为正而 pass 为假，$r_k=0$，策略收不到"这个方向有性能潜力、只是正确性没兜住"的信息。这是硬门最实质的信息损失，也是后续需要软门或分层奖励的动因。

$$R_t=\sum_{k=t}^{T}\gamma^{k-t}\underbrace{\Delta\text{speed}_k}_{\text{差分，需绑定基线}}\cdot\underbrace{\mathbb{1}[\text{pass}_k]}_{\text{硬门，二值}}\qquad \text{有效视界}\approx\frac{1}{1-\gamma}$$

有效视界 $\frac{1}{1-\gamma}$ 是推导出的第一个关键量：$\gamma=0.9$ 时约 10 轮，$\gamma=0.99$ 时约 100 轮。多轮 kernel 优化的典型轨迹长度在个位数到十几轮，这意味着 $\gamma$ 取 0.9 以下时，远端轮次对早期决策的贡献被压到 1% 量级，早期"修对但没提速"的轮次几乎拿不到梯度；$\gamma$ 取 0.99 时视界远超实际轮数，等价于 $\gamma=1$ 的望远镜退化，同时把远端计时噪声按 $\gamma^{k-t}$ 几乎不衰减地灌进早期梯度。这个矛盾是公式的内生缺陷，不是调参能解决的。

二 · 推导关键步：从轨迹似然到差分奖励

信用分配的推导起点是策略梯度：对轨迹 $\tau=(s_t,a_t)_{t=1}^{T}$，梯度为 $\nabla_\theta \log \pi_\theta(\tau)\cdot R(\tau)$。多轮场景下，第 $t$ 轮的动作 $a_t$ 只影响 $t$ 之后的状态与奖励，因此对 $a_t$ 的梯度应只乘以"$t$ 之后"的回报，这就是 $R_t$ 的求和下界从 $t$ 开始的原因——它不是设计选择，是因果性的直接推论。关键推导步在于把 $R(\tau)$ 拆成 $\sum_k r_k$ 后逐项归因：$r_k$ 对 $a_t$ 的依赖通过状态链 $s_t\to s_{t+1}\to\cdots\to s_k$ 传递，链越长，$r_k$ 对 $a_t$ 的敏感度越弱，$\gamma^{k-t}$ 正是这一衰减的指数近似。这一步的近似在于：真实的敏感度衰减取决于编辑的"半衰期"——一次正确的重构可能影响后续所有轮次，一次局部调参可能只影响下一轮，而 $\gamma$ 是全局统一的，无法表达这种异质性。

第二个推导步是 baseline 的引入。原始 $R_t$ 的期望含有一个与动作无关的常数项，方差正比于 $R_t$ 的量级；减去 baseline $b(s_t)$ 后方差降低而不引入偏差，条件是 $b$ 不依赖 $a_t$。多轮场景的难点是 $b$ 应取"从 $s_t$ 出发、按当前策略采样得到的期望回报"，而这个期望需要对后续所有轮次积分，计算代价是每轮一次 rollout 展开——这就是 TRLOO 类方法的成本来源：它用留一法构造无偏 baseline，每条轨迹需要 $T$ 次前向评估，编译与计时开销按 $T$ 倍放大。工程上更常见的是用"上一批同状态轨迹的均值"做 baseline，偏差可控但方差降低有限，尤其在轮数 $T$ 大时，远端噪声的累积使 $R_t$ 的方差随 $T$ 线性增长，而 baseline 只能削掉均值项、削不掉 $\gamma^{k-t}$ 加权后的噪声叠加。

$$\mathrm{Var}(R_t)\approx\sum_{k=t}^{T}\gamma^{2(k-t)}\mathrm{Var}(r_k)+2\sum_{j<k}\gamma^{(j-t)+(k-t)}\mathrm{Cov}(r_j,r_k)$$

这个方差展开式给出第三个关键步：$\gamma$ 接近 1 时，协方差项的权重不衰减，而相邻轮次的 $r_j,r_k$ 高度相关——它们共享同一份计时基线噪声、同一份 GPU 频率漂移、同一份缓存状态。相关性使方差不是简单相加而是被放大，这正是"轮数大时方差累积"的定量来源。一个具体例子：若每轮计时噪声的标准差为 $\sigma$，且相邻轮次相关系数为 $\rho$，则 $T$ 轮、$\gamma=1$ 时 $R_t$ 的标准差约为 $\sigma\sqrt{T(1+(T-1)\rho)}$，$\rho$ 接近 1 时按 $T$ 而非 $\sqrt{T}$ 增长，梯度信噪比按 $1/T$ 恶化。这解释了为什么长轨迹必须配 baseline 或 TRLOO，而不是靠调 $\gamma$ 硬扛。

三 · 离散化与近似：三处必须显式声明的地方

公式在落地时有三个离散化/近似点，每一处都改变信用语义。第一处是时间离散化本身：轮次是人为切分的编辑单元，一次提交可能包含多个文件的改动，也可能只是一行常量调整，$r_k$ 把这一整块编辑压成一个标量，等于假设块内所有改动共享同一信用。代价是块内信用不可分——若一次提交同时修了正确性和加了向量化，$\Delta\text{speed}$ 无法归因到哪一半，策略学到的是"这个组合有效"，而非"向量化有效"。工程缓解手段是把提交粒度压细，代价是轮数 $T$ 上升，直接触发上一节的方差累积。

第二处是 $\mathbb{1}[\text{pass}_k]$ 的二值化。正确性 oracle 的输出本是"通过/失败 + 失败类型"，压成二值后丢失了失败严重度：一个越界写和一个精度偏差在 $r_k$ 里都是 0，但前者应被强惩罚、后者可能只是容差问题。近似代价是策略无法区分"接近正确"与"完全错误"，探索效率下降。具体例子：某轮把 reduction 的累加顺序改了，浮点结果在 $10^{-6}$ 相对误差内，oracle 判定失败，$r_k=0$，而实际上该改动是后续提速的前置条件；硬门把这条有价值的中间路径判死。

第三处是 $\Delta\text{speed}_k$ 的测量离散化。计时本身有噪声，$\Delta$ 是两个带噪测量之差，其信噪比低于单次测量——若单次测量相对噪声为 $\epsilon$，差分的相对噪声约为 $\sqrt{2}\epsilon$（独立噪声情形），而真实提速可能只有几个百分点，$\Delta$ 的符号可能被噪声翻转。这直接导致 $r_k$ 符号错误，$R_t$ 的梯度方向被污染。工程上的近似是设一个死区：$|\Delta\text{speed}_k|<\delta$ 时置 $r_k=0$，$\delta$ 取计时噪声的置信上界；代价是小于 $\delta$ 的真实提速被系统性忽略，多轮累积的小步改进拿不到信用，策略偏向"憋大招"而非渐进优化。

近似点被压掉的信息代价缓解
轮次=编辑块块内改动不可分信用归因粒度粗，$T$ 上升则方差涨细粒度提交 + baseline
pass 二值化失败类型与严重度接近正确的探索被判死分层奖励或软门
$\Delta$ 测量小于死区的真实提速渐进改进无信号死区 + 重复计时取中位数

四 · 失效条件的定量画像

"折扣因子过小只看短期"可以定量化：当 $\gamma^{T-t}$ 小于某个阈值（例如 0.05）时，第 $T$ 轮对第 $t$ 轮决策的梯度贡献可忽略，等效于把轨迹截断在 $t+\frac{\ln 20}{-\ln\gamma}$ 轮。$\gamma=0.5$ 时截断在 4 轮左右，若实际轨迹有 10 轮，前 6 轮的决策只看到 4 轮内的后果，任何"先重构再提速"的两阶段策略都学不到——重构轮本身不提速，$r$ 为 0 或负，而提速轮的收益落在截断窗外。这是"策略退化成保守复制"的机制：保守复制每轮 $\Delta\text{speed}\approx 0$ 但 pass 恒真，$r_k=0$ 稳定无风险；激进重构有负 $r$ 风险且收益不可见，期望梯度把策略推向零改动。

"折扣因子过大放大远端噪声"同样可定量：$\gamma\to 1$ 时，远端轮次的计时噪声以几乎全权重进入早期梯度，而远端轮次的 $\Delta\text{speed}$ 恰恰是最不确定的——它建立在多轮累积的基线之上，基线漂移（GPU 热状态、频率、同机干扰）被逐轮放大。一个具体例子：第 1 轮的决策梯度里混入了第 8 轮因频率下降导致的负 $\Delta$，策略会把"第 1 轮的正确重构"错判为有害，因为 $R_1$ 被远端负奖励拉低。这不是假设性风险，而是 $\gamma$ 接近 1 时协方差项不衰减的直接后果。

"中间轮 pass 变化不等于最终 pass"是第三类失效：某轮 pass 为真、下一轮 pass 为假，$r_k$ 在真轮为正、假轮为零，但最终交付的是假轮之后的产物——若轨迹在假轮后继续修复并最终 pass，中间那次失败被记为 0 而非负，公式无法表达"这次失败是必要的中间步骤"。反之，若轨迹在中间轮 pass、后续轮引入隐蔽错误而 oracle 未捕获（oracle 覆盖不全），$r_k$ 会给出虚假正信号，信用被错误分配。这两类误判的根源是 pass 是逐轮独立判定，而正确性是轨迹级的属性，公式缺少一个"轨迹终态一致性"的约束项。

五 · 工程判断：公式该改哪里、不该改哪里

不该改的是求和结构与因果下界：从 $t$ 到 $T$ 的求和是因果性的直接编码，任何把 $k<t$ 纳入的变体都会引入未来信息泄漏，在离线训练里看似降方差，在线部署时不可实现。该改的是三处：其一，把 $\Delta\text{speed}_k$ 的基线显式化为"上一轮实测中位数"，并对差分做死区处理，使 $r_k$ 的符号可信；其二，把二值 pass 换成带严重度的分级门，例如"编译失败/运行崩溃/数值不符/通过"四级，前两级给强负奖励，数值不符给弱负或零，通过给正——代价是需要 oracle 输出结构化失败信息，而多数正确性检查器只返回布尔值，改造工作量落在 oracle 侧而非公式侧；其三，对 $T$ 大的轨迹引入显式 baseline，用同状态的历史均值而非留一法，接受少量偏差换取方差从 $O(T^2)$ 降到 $O(T)$。

一个可落地的折中是分段折扣：把轨迹按"重构阶段/调优阶段"切段，段内 $\gamma$ 取小值（抑制段内计时噪声累积），段间用段级奖励传递（段末的加速比作为下一段起点的基线），等效于把望远镜求和的分段化。这样做的代价是段边界的信用仍然粗糙，但避免了全局 $\gamma$ 在"看太短"与"噪声灌入"之间的两难。判断标准很具体：若轨迹中位数轮数 $T_{50}$ 满足 $\frac{1}{1-\gamma}\gg T_{50}$，说明 $\gamma$ 过大、噪声主导；若 $\frac{1}{1-\gamma}\ll T_{50}$，说明 $\gamma$ 过小、远端信号丢失；工程上取 $\frac{1}{1-\gamma}\approx T_{50}$ 作为起点，再用实测梯度信噪比微调。这个判断不依赖任何编造的数字，只依赖轨迹长度分布这一个可观测量。

折扣聚合的边界：γ 把噪声放大到哪一步

把 R_t 展开成逐轮求和之后，真正决定这套信用分配能否落地的不是公式形式，而是 γ 与 T 的乘积：γ^{k-t} 对远端轮次的权重衰减，和 T 轮内 r_k 的方差累积，是同一个旋钮的两端。r_k 里的 𝟙[pass_k] 是硬门，Δspeed_k 是软信号，两者相乘意味着一次 pass 翻转会把该轮奖励直接归零——但归零不等于“该轮无贡献”，它只是把“修对了但没提速”与“提速了但没修对”压成同一个零值，策略无法区分该复制哪种编辑。工程上必须把 pass 门与 speed 增量拆成两路统计，否则 γ 再精细也只是在零值上做加权。

推导的关键近似发生在离散化：连续时间上的信用衰减被写成按轮离散的几何级数，隐含假设是“每轮编辑的边际贡献可加且与轮次位置无关”。真实 kernel 编辑不是这样——一次 tiling 改动会改变后续所有轮的可行编辑空间，Δspeed_k 因此是路径依赖的，把它当独立增量求和会系统性高估早期轮次的功劳。失效条件由此明确：γ 过小，R_t 退化成只看最后一两轮，前面“修对但没提速”的轮次依旧拿不到信号，策略退化为保守复制；γ 过大，远端 r_k 的噪声（pass 抖动、测量抖动）被几乎等权放大，T 很大时方差按轮数累积，没有 baseline 或 TRLOO 类降方差手段，梯度信噪比会掉到无法训练。

$$\mathrm{Var}(R_t)\approx\sum_{k=t}^{T}\gamma^{2(k-t)}\,\mathrm{Var}(r_k)+2\sum_{j<k}\gamma^{j+k-2t}\,\mathrm{Cov}(r_j,r_k)$$

协方差项是这套方案最容易被忽略的代价：相邻轮的 r_k 高度相关（同一份 profile 反馈驱动连续编辑），γ 接近 1 时协方差被同权累加，方差上界远高于独立假设下的估计。系统代价体现在三处：为压方差需对同一轨迹多次采样，token 消耗随 T 线性上升；每轮都要跑正确性门与计时，端到端时延被 T 次编译加 T 次 profile 支配；若用 TRLOO 做留一 baseline，需保存每轮中间产物（源码、编译缓存、计时样本），显存与磁盘占用随 T 增长。一个具体例子：某轮把 shared memory 占用从超限改到合规，pass 由 0 翻 1 但 Δspeed 为负，r_k=0，公式判它“无功”，而它恰恰是后续提速的前置条件——这正是离散化把“必要但不充分”的编辑误判为零贡献的典型边界。

参数区间主要失效系统代价
γ 偏小早期修正轮无信号，策略保守复制采样轮数增加，token 上升
γ 偏大、T 大远端噪声等权放大，方差累积需 baseline/TRLOO，中间产物存储膨胀
pass 门硬截断必要非充分编辑被判零贡献需额外拆分 pass 与 speed 两路统计
