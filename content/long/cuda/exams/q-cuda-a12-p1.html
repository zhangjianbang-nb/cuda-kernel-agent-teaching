一 · 题干的三层结构：把一句话拆成可执行的判据

这类题面通常只给一句话：“解释 MCTS/进化 keep-revert 搜索的核心公式，并用一个算例说明它如何影响搜索预算或上线判断。”它看起来是两问，实际是三层。第一层是符号层：公式里每个量的定义域、量纲、由谁计算、在什么时刻被读取。第二层是机制层：keep 与 revert 这两个动作在搜索树上分别对应哪条边、哪次状态写入、哪份缓存失效。第三层是决策层：这个量如何折算成 GPU 时间、显存占用或编译次数，进而改变预算分配或上线门槛。答题时若只停在第一层，写出的是一份符号表；只有把三层串起来，才算读懂了题干。

拆题的第一动作是识别“核心公式”指哪一个。keep-revert 搜索的骨架是一个带剪枝的树搜索，其选择准则通常写成置信上界形式：

$$U(s,a)=Q(s,a)+c\sqrt{\frac{\ln N(s)}{N(s,a)}}$$

其中 $Q$ 是该动作对应候选 kernel 的实测收益（例如相对基线的加速比或 SOL 利用率），$N(s)$ 是父节点访问次数，$N(s,a)$ 是该子节点被展开并评测的次数，$c$ 是探索系数。keep-revert 的独特之处不在这个式子本身，而在于 $Q$ 的更新规则被替换成“保留最优、回退劣化”：只有当新候选在正确性 oracle 通过且性能优于当前保留者时，才写入 keep 槽位；否则整棵子树被 revert，其统计量作废或降权。因此题干问的“逐项解释”，实质是要求你说清 $Q$ 的非平滑更新、$N$ 的计数口径（是编译次数还是 profile 次数）、以及 $c$ 与预算的耦合。

二 · 考点定位：四个必须命中的判据

阅卷视角下，这道题有四个硬考点，缺一个就会失分。考点一：$Q$ 的估计对象是离散的、带噪的、有正确性门控的。GPU kernel 的实测时延受频率、占用率、缓存状态影响，单次测量方差不可忽略；而 keep-revert 只在通过正确性检查的候选上更新 $Q$，这意味着 $Q$ 的样本集是被截断的，不能当作无偏均值直接代入 UCB。答题要指出这一点，并给出处理方式，例如对同一候选重复 profile 取中位数、或对未通过 oracle 的候选只增加 $N$ 而不更新 $Q$（即“访问但不算收益”）。

考点二：$N$ 的计数单位决定预算语义。在 LLM 生成 kernel 的场景里，一次“访问”可能是一次 LLM 采样（消耗 token）、一次编译（消耗编译时间）、一次 NCU profile（消耗 GPU 小时）。三者代价差一个数量级以上。若公式里的 $N$ 混用这三种口径，UCB 的探索项就失去意义：编译失败率高的分支会因为编译次数多而被人为抬高。正确做法是把 $N$ 定义为“有效评测次数”，编译失败与 oracle 拒绝单独计入失败计数，不进入 $N$。

考点三：revert 的代价是显存与状态回滚，不只是时间。keep-revert 需要在候选之间保存最佳 kernel 的源码、编译产物与 profile 记录。revert 一棵子树意味着丢弃其缓存条目；若实现为“保留全部历史以便回溯”，显存随搜索宽度线性增长，在长上下文或多候选并行时成为瓶颈。答题应给出一个具体的记账方式，例如每个候选固定占用若干字节的源码与元数据，搜索宽度 $W$ 与深度 $D$ 下的驻留量为 $O(WD)$，并说明何时触发淘汰。

考点四：算例必须落到“预算或上线判断”上。题干明确要求算例说明影响，因此不能只算一个 UCB 数值。算例应展示：给定一组 $Q$、$N$、$c$，选择准则把下一次评测分配给哪个候选；以及当该候选被 revert 后，剩余预算如何重新分配；或者当保留者的 SOL 利用率低于某阈值时，上线判断如何从“继续搜索”翻转为“放弃该 kernel 走 fallback”。

三 · 解题路径：从符号到预算的五步

建议按以下顺序作答，每步都留下可核对的中间量。第一步，定义状态与动作。状态 $s$ 是当前保留的 kernel 及其父级变换历史（例如 tile 大小、流水深度、是否用 TMA）；动作 $a$ 是一次具体的代码变换或一次 LLM 生成的候选。明确动作空间是离散且不可微的，因此不能用梯度类方法，只能用采样加评估。第二步，写出 keep 判据。keep 的条件是一个合取式：正确性 oracle 通过、实测时延优于保留者、且资源占用（寄存器、共享内存）不突破上限。三者任一不满足即 revert。这里要强调 oracle 是硬门控，性能比较只在通过门控的候选间进行。第三步，写出 revert 后的统计修正。被 revert 的子节点不应简单删除，否则父节点的 $N(s)$ 与子节点计数不一致，UCB 的探索项会被系统性高估。常见修正为把该子节点的 $N$ 保留但把 $Q$ 置为保留者的值（悲观初始化），或将其标记为“已耗尽”不再被选择。第四步，给出选择与预算的耦合。每一轮从根到叶按 UCB 选择，叶节点展开产生 $k$ 个候选，评测预算 $B$ 按候选数均分或按先验分配；当某分支连续 revert 次数超过阈值，剪掉该分支并把预算让给兄弟节点。第五步，代入算例。用具体数字走一遍选择、keep/revert、预算重分配，最后给出上线判断的翻转点。

这条路径的关键在于：每一步都产生一个可被后续步骤消费的量。若第一步没有把动作空间离散化，第三步的统计修正就无从谈起；若第三步没有处理计数不一致，第四步的预算分配会偏向失败率高的分支。答题时把这五步的依赖关系写出来，比单独罗列公式更能体现工程理解。

四 · 需要调用的公式与它们的适用边界

除 UCB 主式外，还有三组公式需要准备。收益归一化：不同 kernel 的绝对时延不可比，需折算为相对量，例如 $Q=\frac{t_{\text{base}}}{t_{\text{cand}}}$ 或 $Q=\frac{\text{achieved}}{\text{SOL}}$。前者无量纲、便于跨形状比较，后者直接对应 roofline 上限，便于上线判断。二者不可混用：用加速比做 $Q$ 时，SOL 利用率只作为门控；用 SOL 做 $Q$ 时，基线选择必须固定。预算约束：总预算可写成

$$\sum_{i} N_i \cdot (c_{\text{gen}}+c_{\text{compile}}+c_{\text{prof}}) \le B$$

其中三项分别是生成 token 成本、编译时间与 profile 时间。这个式子说明 $N$ 不能无限增长，也说明为什么要把编译失败排除出 $N$——否则失败分支会以零收益消耗预算。剪枝阈值：当子节点连续 revert 次数 $r$ 满足 $r \ge r_{\max}$，或其后验上界低于保留者下界时剪枝。剪枝的代价是可能错过“需要多次变换才见效”的候选，因此 $r_{\max}$ 的设定要与变换的复合深度匹配：单步变换可设小，多步流水线重构需设大。

适用边界要写清：UCB 的探索项假设各臂收益独立同分布，而 keep-revert 下候选间存在强相关性（同一父节点的变体共享大部分代码），因此 $c$ 的实际有效值应偏小，否则会在相关臂上重复采样。这一点在纯 bandit 题里不会出现，是本类题的特有考点。

五 · 算例骨架：让数字推动判断

设根节点保留一个基线 kernel，$Q_0$ 归一化为 1.0（即基线自身），$N(s)=8$，探索系数 $c=0.5$。根下有三个候选：A 已评测 4 次，$Q_A=1.3$；B 已评测 2 次，$Q_B=0.9$；C 未评测，$N_C=0$。按 UCB 计算，A 的探索项为 $0.5\sqrt{\ln 8/4}\approx0.5\times0.72=0.36$，总分约 1.66；B 为 $0.5\sqrt{\ln 8/2}\approx0.5\times1.02=0.51$，总分约 1.41；C 因 $N_C=0$ 探索项发散，按实现通常赋予最大优先级或一个先验上限。于是本轮预算分配给 C。C 展开后编译失败，按前述口径只增加失败计数、不增加 $N_C$，预算回流。下一轮 A 与 B 竞争，A 胜出，对 A 再做一次变换得到 A'，实测 $Q_{A'}=1.25$，低于保留者 A 的 1.3，触发 revert：A' 的 $N$ 保留、$Q$ 置为 1.3 的悲观值，A 继续保留。

这个骨架展示了三件事：未评测节点因探索项发散获得预算；编译失败不污染 $N$；revert 后用悲观初始化维持计数一致。接着把它推到上线判断：若保留者的 SOL 利用率经 profile 确认低于目标阈值，且剩余预算不足以再展开一轮，则判断从“继续搜索”翻转为“放弃该 kernel，走库函数 fallback”。翻转点是预算剩余量与单轮评测成本之比，而不是某个固定迭代数——这正是题干要求“影响上线判断”的落点。

六 · 常见失分点与工程判断

失分点集中在四处。其一，把 $Q$ 当作连续可微的均值直接代入，忽略 oracle 门控造成的截断偏差。其二，$N$ 的口径混用，把编译次数当评测次数，导致探索项失真。其三，revert 只写“丢弃”，没有交代计数一致性如何维持，使 UCB 在后续轮次系统性偏向失败分支。其四，算例只算选择不算预算，或只算预算不给上线翻转条件，没有回应题干的第二问。

工程判断上，keep-revert 的价值在于把“生成—编译—评测”这条昂贵链路中的失败样本转化为结构信息：失败分支被剪掉，其预算让给兄弟节点，搜索宽度得以在固定预算下扩大。代价是状态驻留与计数维护的复杂度，以及剪枝阈值设定不当带来的漏检。一个可操作的判断是：当单次评测成本（编译加 profile）远高于单次生成成本时，应减小 $c$、增大剪枝阈值，把预算集中在少数深分支上；反之当生成便宜而评测昂贵时，应扩大宽度、快速淘汰。这个判断直接来自预算约束式中三项成本的相对大小，而不是经验口号。

读题先拆“预算守恒”这一项：keep-revert 公式里最容易被忽略的边界

面对“核心公式逐项解释”这类题干，第一件事不是去背公式，而是把题干拆成三个可判定的子问题：公式里哪些量是搜索树的状态量（节点访问数、深度、分支因子），哪些是决策量（keep 或 revert 的判据），哪些是预算量（token、编译次数、NCU 采样次数、墙钟时延）。考点通常落在第三类上——因为 keep-revert 的收益从来不是“找到更好的 kernel”这一句能概括的，而是“在固定预算下，把预算从无效分支挪到有效分支”。解题路径应当是：先写出 keep-revert 的判据不等式，再把它改写为“每次 revert 节省的预算 ≥ 每次 keep 消耗的预算”这一守恒形式，最后才代入算例。需要调用的公式只有两条：判据侧的收益比较式，以及预算侧的期望消耗式；其余都是这两条的变形。

判据侧的典型形式是：当子节点相对父节点的评估增益 Δ 低于阈值 τ，且该子节点的已投入预算 b 超过其剩余可探索预算的某个比例时执行 revert。把它写成可操作的不等式，就是 Δ/b < τ 与 b > β·Bnode 同时成立才回退，其中 Bnode 是该分支的预算上限。这里的边界条件很硬：τ 若按“绝对性能提升”设定，则在 roofline 上已接近 SOL 的 kernel 上几乎必然触发 revert，因为剩余可提升空间本就很小；τ 若按“相对提升”设定，则在低基线 kernel 上会过度 keep，把预算耗在注定被淘汰的分支上。失效条件是评估噪声——单次 NCU 采样或单次编译运行的方差若与 Δ 同量级，判据就退化为抛硬币，此时 revert 会误杀那些“首次实现慢、但结构上可优化”的分支。代价体现在编译时间与 token 上：每次 keep 都要付出一次完整编译加一次 profile 的固定开销，revert 省下的是后续展开的预算，但已付出的那一次不可回收。

预算侧的期望消耗式可写成 E[C] = Nkeep·(ccompile+cprof) + Nexpand·cgen，其中 cgen 是每次生成候选 kernel 的 token 与时延成本，Nexpand 是实际展开的节点数。keep-revert 的作用就是压低 Nexpand 而不同比例压低 Nkeep；但若 revert 判据过于激进，Nkeep 下降的同时会把搜索树压成一条链，丧失并行分支带来的多样性，最终在“需要跨结构跳变才能达标”的算例上直接失效。一个具体算例：给定分支因子 4、深度 3、单节点编译加 profile 固定开销远大于单次生成的 token 成本时，revert 的节省主要来自砍掉浅层宽展开，而不是砍掉深层节点；此时若把 β 设得过大，浅层分支全部保留，预算守恒式右端反而膨胀。工程判断是：β 应与 ccompile/cgen 的比值挂钩，而不是拍一个常数；上线判断则要看 revert 后剩余预算是否仍足以覆盖至少一条完整深度路径，否则搜索在预算耗尽前就结构性失败。

量角色失效条件系统代价
τ（增益阈值）判据与评估噪声同量级误杀可优化分支，浪费已付编译
β（预算比例）判据与编译/生成成本比脱钩浅层宽展开不被裁剪，预算膨胀
