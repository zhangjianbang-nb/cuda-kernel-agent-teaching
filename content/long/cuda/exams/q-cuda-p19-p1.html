一 · 把题干拆成四个可判定的子问题

题干问的是“方法在跨硬件、跨 shape、跨 dtype 迁移时最可能在哪里失效”，并要求给出判断、验证方案与回退条件。这不是一个可以靠复述论文摘要回答的问题，它至少包含四个必须分别作答的子问题：其一，这套 trace-driven benchmark 与优化 agent 的“迁移”具体指什么对象在迁移——是被测 kernel 本身、是 agent 的搜索策略、还是 benchmark 的评分口径；其二，“失效”的判据是什么——是正确性 oracle 判错、是性能收益归零、还是 agent 收敛到不可用解；其三，跨硬件/跨 shape/跨 dtype 三类迁移的失效机理是否同源，若不是，就不能用一句“泛化不足”打包；其四，回退条件必须可观测、可触发，而不是“效果不好就回退”。答题时若把四者混为一谈，就会写出看似周全实则无法验证的答案。

拆题的第一刀落在“trace-driven”这个词上。Trace 驱动的含义是：benchmark 的输入分布、调用序列、shape 组合来自真实负载的轨迹采样，而非人工枚举。这带来一个直接后果——benchmark 的覆盖面由轨迹的采样域决定，agent 的优化目标也被这个采样域隐式约束。于是“跨 shape 迁移失效”的第一嫌疑点不在 kernel 代码本身，而在采样域与目标域的形状分布错配：轨迹里高频的小 shape 主导了评分，agent 为这些小 shape 做出的启发式选择（例如 tile 尺寸、是否走 split-K、是否融合）在轨迹未覆盖的大 shape 上不再成立。这个判断可以用一句话表述：失效首先发生在“评分函数所代表的形状分布”与“部署形状分布”的支撑集不重合处，而不是发生在某条指令上。

第二刀落在“optimization agent”上。Agent 的搜索空间由它可调用的动作集定义：改 tile、改向量化宽度、改流水级数、改 Triton/CuTe 表达层级、插入 PTX 内联。跨硬件迁移时，动作集的语义发生变化——同一个 tile 配置在另一张卡上对应不同的 SM 数量、不同的 shared memory 容量、不同的 L2 分块行为，动作的“物理含义”被硬件参数重写。因此跨硬件失效的机理与跨 shape 不同源：前者是动作语义漂移，后者是评分分布漂移。答题必须把这两条分开写，否则验证方案会设计成同一个实验。

第三刀是 dtype。跨 dtype 迁移的独特之处在于它同时触碰正确性与性能两条线：低精度路径引入的舍入与累加顺序改变会移动数值误差，而误差是否越界取决于 oracle 的容差设定；同时 dtype 改变会改变每字节的运算密度，从而改变 roofline 上的工作点位置，使原本 compute-bound 的调优结论在 memory-bound 区间失效。把 dtype 迁移当成“换个类型跑一遍”是最常见的失分点。

$$\text{fail}(m)=\underbrace{\Delta_{\text{shape}}(D_{\text{trace}},D_{\text{deploy}})}_{\text{评分分布漂移}}+\underbrace{\Delta_{\text{action}}(\theta_{\text{HW}_1},\theta_{\text{HW}_2})}_{\text{动作语义漂移}}+\underbrace{\Delta_{\text{num}}(\text{tol},\text{dtype})}_{\text{容差-精度错配}}$$

上式是本部分的解题骨架：三项分别对应三类迁移的主失效通道，答题时应逐项给出机理、验证手段与回退阈值，而不是笼统地谈“泛化”。下面四节按这个骨架展开，只给路径与公式，不给结论性答案。

二 · 考点一：评分口径的可迁移性——benchmark 代表什么

第一个考点是“benchmark 的评分口径能否代表部署目标”。Trace-driven 的评分通常由三部分构成：正确性 oracle 的通过判定、相对基线的加速比、以及轨迹加权的聚合方式。三者中任何一项在迁移后失去代表性，agent 的“最优解”就会变成部署端的次优解。具体机制在于加权聚合：若轨迹按调用频次加权，则高频小 shape 的权重压倒低频大 shape，agent 会优先优化前者；而部署端若以大 shape 为主，权重结构反转，此前的最优动作排序被推翻。这不是 kernel 写错了，是目标函数换了。

验证方案应设计成“权重敏感性实验”：固定 agent 产出的候选解集合，只改变聚合权重（从轨迹频次加权切换到部署分布加权，或切换到等权），观察候选解的排名是否发生翻转。排名翻转的幅度就是评分口径可迁移性的度量。若翻转后原第一名跌出前若干名，说明评分口径不可迁移，agent 的结论只在原分布内成立。这个实验的代价很低——不需要重新训练或重新搜索，只需重算聚合，代价是若干次离线评估的时延；但它能直接暴露“跨 shape 失效”的第一层。

与之配套的公式是加权加速比的分解。设轨迹含 $N$ 个 shape 桶，第 $i$ 桶权重 $w_i$、加速比 $s_i$，则聚合得分为 $\sum_i w_i s_i$。迁移到部署分布 $w'_i$ 后得分变为 $\sum_i w'_i s_i$，两者之差可写成：

$$\Delta S=\sum_i (w'_i-w_i)\,s_i=\sum_i \Delta w_i\,s_i$$

该式的工程含义是：失效不取决于 $s_i$ 的绝对值，而取决于 $\Delta w_i$ 与 $s_i$ 的协方差——即 agent 恰好在被降权的桶上收益最大时，迁移损失最大。答题时给出这个分解，比空谈“分布偏移”有力得多。具体例子：某 fused elementwise 类 kernel 在小 shape 上因 launch 开销占比高而获得较大相对加速，在大 shape 上加速比趋近于带宽上限带来的固定倍数；当权重从“小 shape 为主”切到“大 shape 为主”，聚合得分下降的主要贡献来自小 shape 桶的权重坍缩，而非任何单点性能退化。

代价面必须写清：权重敏感性实验本身廉价，但它不能替代真实部署测量；若部署分布未知，只能用轨迹的尾部近似，此时聚合得分的置信区间随尾部稀疏度迅速变宽，agent 的排序结论在统计上不可区分。回退条件由此产生：当排名翻转导致原最优解跌出可接受集合，或尾部桶样本数不足以支撑排序时，回退到“按桶分别报告、不做跨桶聚合”的口径，并把选择权交还给部署侧。

三 · 考点二：动作语义漂移——agent 的动作集在另一张卡上还是不是同一件事

第二个考点是 agent 动作集的跨硬件语义一致性。Agent 的动作通常抽象为若干旋钮：tile 尺寸、线程块形状、向量化宽度、流水深度、是否启用张量核心路径、是否内联 PTX。这些旋钮在源硬件上经过搜索形成一条“动作—性能”映射曲线，agent 学到的是这条曲线的形状。跨硬件时，曲线的自变量含义被重写：同一 tile 在 SM 数更少、shared memory 更小的设备上会触发占用率下降或寄存器溢出，曲线从单峰变为多峰甚至断裂。失效点因此不在 agent 的搜索算法，而在动作到物理资源的映射函数。

验证方案应做“动作回放”而非“重新搜索”：把源硬件上 agent 选出的 top-k 动作配置原样搬到目标硬件，测量其性能与正确性，得到迁移后的动作排名；再在目标硬件上重新搜索，得到目标硬件的真实排名。两组排名的秩相关系数就是动作语义漂移的量化指标。若秩相关接近零，说明 agent 在源硬件上学到的动作偏好不可迁移，必须重新搜索；若秩相关较高但 top-1 不一致，说明只需局部修正。这个实验的代价是目标硬件上的若干次编译与 profiling 时延，以及重新搜索所需的编译次数——后者在 Triton 路径上体现为编译时间，在 PTX 内联路径上体现为正确性风险。

公式层面，把动作映射写成资源约束下的可行域收缩。设源硬件资源向量 $\theta_1=(\text{SM}, \text{SMEM}, \text{reg}, \text{L2})$，目标 $\theta_2$，动作 $a$ 的可行判定为 $g(a,\theta)\le 0$。迁移后失效的动作集合是：

$$\mathcal{F}=\{a\mid g(a,\theta_1)\le 0,\; g(a,\theta_2)>0\}$$

工程上更常见的是“可行但退化”而非“不可行”：动作仍能编译运行，但占用率从多波降到单波，或 shared memory 容量刚好卡在边界导致 bank 冲突模式改变。因此验证不能只看编译是否通过，必须看 NCU 侧的占用率与访存效率指标是否发生阶跃。具体例子：某 reduction kernel 在源硬件上选用较大 tile 以摊薄同步开销，迁移到 SMEM 更小的设备后该 tile 触发占用率下降，单波执行无法隐藏访存时延，性能反而低于未调优的基线——此时 agent 的“优化”变成负收益，这是跨硬件失效最典型的形态。

回退条件应写成可触发的规则：当动作回放的秩相关低于阈值、或 top-k 配置在目标硬件上出现占用率阶跃下降、或重新搜索的编译预算超出上限时，回退到“保守动作集”——即只允许那些在两类硬件上都满足资源约束且不改变占用率档位的动作，放弃激进的 tile 与流水配置。回退的代价是放弃一部分潜在收益，换取可预测性。

四 · 考点三：正确性 oracle 的容差在 dtype 迁移下是否仍然有效

第三个考点是正确性判定的可迁移性。跨 dtype 迁移时，oracle 的容差设定往往沿用源 dtype 的经验值，而低精度路径的误差结构完全不同：累加顺序、舍入模式、是否使用 fused multiply-add、是否走张量核心的截断累加，都会改变误差的分布形状。失效机制有两层：第一层是容差过松导致错误解通过，第二层是容差过紧导致正确解被拒——后者在 agent 搜索中更致命，因为它会让 agent 把数值上更稳但性能稍差的候选误判为失败，从而系统性地偏向不稳定实现。

验证方案是“误差分布对照”：对同一组输入，分别在源 dtype 与目标 dtype 下计算输出，与高精度参考解比较，统计误差的分位数而非单一最大值。若目标 dtype 下的误差上分位数相对源 dtype 显著抬升，且抬升集中在特定 shape（如长归约维度），说明容差需要按 shape 分桶设定，而非全局统一。代价面：高精度参考解的计算本身可能比被测 kernel 慢一个数量级以上，验证时延不可忽略；因此工程上常用抽样输入加分层容差来摊薄，但这会引入漏检风险，需在回退条件中体现。

公式上，把容差判定写成相对误差与绝对误差的混合判据，并显式暴露 dtype 依赖：

$$\text{pass}=\bigl(|y-\hat y|\le \tau_{\text{abs}}+\tau_{\text{rel}}\cdot|y|\bigr)\ \wedge\ \bigl(\text{err}_{p99}\le \tau_{p}\bigr)$$

其中第二项的分位数约束是跨 dtype 迁移时真正起作用的那一项：单点最大误差受离群值支配，不稳定；分位数约束对分布形状敏感，能捕捉累加顺序改变带来的系统性偏移。答题时应指出，agent 的搜索若只以第一项为奖励信号，会在 dtype 迁移后奖励那些“单点过关但分布尾部超标”的实现。具体例子：某 softmax 类 kernel 在 fp32 下误差集中在末位，切换到低精度后长行归约的累加误差随行长度增长，单点最大误差仍可能落在容差内，但 p99 误差已整体抬升——此时全局容差判定通过，分位数判定失败，两者结论相反，正好构成验证方案的判别点。

回退条件：当目标 dtype 下误差分位数超出源 dtype 校准出的阈值、或分层容差所需的参考解计算预算不可接受时，回退到“以高精度路径为正确性基准、仅对性能做低精度评估”的双轨口径，即正确性判定不随 dtype 放松，性能评估允许低精度。这样做的代价是失去对低精度实现性能收益的完整度量，但保住了 oracle 的可信度。

五 · 考点四：roofline 工作点迁移与性能收益的归零判据

第四个考点是性能收益在迁移后是否仍然存在。Roofline 给出的是工作点位置：算术强度 $I$ 决定落在 compute-bound 还是 memory-bound 区间，峰值由硬件的算力与带宽共同界定。跨 shape 与跨 dtype 都会移动 $I$：shape 变大时归约维度的复用增加，$I$ 上升；dtype 变窄时每字节承载的运算增多，$I$ 上升。工作点跨过屋脊点后，原本有效的优化手段（提高占用率以隐藏访存时延）收益归零，而另一类手段（提高指令级并行、减少同步）才开始起作用。Agent 若在源工作点上学到的是“占用率优先”的策略，迁移到屋脊另一侧就会失效。

验证方案是“工作点扫描”：在目标硬件上对一组代表性 shape 与 dtype 组合计算 $I$ 与实测吞吐，标出屋脊点位置，再检查 agent 产出的解是否落在与源硬件相同的区间。若区间不同而解的动作偏好未变，即可判定策略未随工作点迁移。这个扫描的代价是若干次 profiling 与带宽/算力标定测量，属于离线成本，可复用。

$$I=\frac{\text{FLOPs}}{\text{Bytes}},\qquad P_{\text{roof}}=\min\bigl(P_{\text{peak}},\; I\cdot B_{\text{peak}}\bigr)$$

归零判据可以写得更可操作：设源硬件上 agent 解相对基线的加速比为 $s_1$，目标硬件上同一解的加速比为 $s_2$；若 $s_2$ 落入测量噪声带内（即与基线不可区分），则判定收益归零，触发回退。噪声带的宽度由重复测量的离散度决定，而不是拍脑袋取一个百分比。具体例子：某矩阵乘类 kernel 在源硬件上处于 compute-bound 区间，agent 通过提高流水深度获得收益；迁移到带宽相对更紧的目标硬件后工作点移向 memory-bound，同样的流水深度不再摊薄访存，加速比落入噪声带——此时正确的工程判断不是继续调流水，而是切换到以访存为中心的动作集。

回退条件由此明确：当工作点区间判定与源硬件不一致、且 agent 的动作偏好未随之改变时，回退到“按区间分派动作集”的策略——compute-bound 区间用一套动作，memory-bound 区间用另一套，而不是让单一策略跨区间通用。代价是策略空间变大、搜索预算上升，但避免了在错误区间上做无效调优。

六 · 解题路径：从判断到验证到回退的三段式写法

把上述四个考点组织成答案，需要一条明确的书写路径，而不是并列罗列。建议的三段式是：先给判断，判断必须指名失效通道（评分分布漂移、动作语义漂移、容差-精度错配、工作点迁移四者之一或组合），并说明为什么该通道在三类迁移中占主导；再给验证方案，验证方案必须包含一个可执行的对照实验、一个量化指标、一个预算估计；最后给回退条件，回退条件必须写成可观测的触发规则加明确的代价陈述。

判断部分的写法要点是“分迁移类型作答”。跨硬件的主通道是动作语义漂移，辅以工作点迁移；跨 shape 的主通道是评分分布漂移，辅以工作点迁移；跨 dtype 的主通道是容差-精度错配，辅以工作点迁移。三者不可用同一句话概括，否则验证方案会退化成“在目标环境重跑一遍”——那既不是验证，也没有回退阈值。

验证部分的写法要点是“对照而非单跑”。每个通道都应有源域与目标域的成对测量：评分口径用权重敏感性对照，动作语义用动作回放与重新搜索的秩相关对照，dtype 用误差分位数对照，工作点用区间判定对照。四组对照的预算各不相同：权重敏感性最廉价（离线重算聚合），动作回放中等（目标硬件编译与 profiling），误差分位数较贵（高精度参考解），工作点扫描可复用（一次标定多次使用）。答题时给出这个预算排序，本身就是工程判断力的体现。

回退部分的写法要点是“阈值可观测、代价可陈述”。四个通道对应的回退规则分别是：排名翻转超出可接受集合或尾部样本不足时，回退到分桶报告；动作回放秩相关过低或出现占用率阶跃时，回退到保守动作集；误差分位数超标或参考解预算不可接受时，回退到双轨口径；工作点区间不一致且动作偏好未变时，回退到按区间分派动作集。每条回退都要写清放弃了什么——潜在收益、搜索预算、还是低精度性能的完整度量。

最后一段落在具体机制上：这套三段式写法的核心不是给出一个“方法不够泛化”的结论，而是把“失效”定位到可测量的中间量——聚合权重的协方差、动作排名的秩相关、误差分布的分位数、工作点所在的区间。这四个中间量任一发生漂移，agent 的优化结论就不再可信；而它们都可以在不需要重训、不需要重写 kernel 的前提下被测量。工程判断因此可以写成一句可执行的话：先测中间量，再决定是局部修正、重新搜索还是回退口径，而不是在迁移失败后笼统地归因于泛化。
