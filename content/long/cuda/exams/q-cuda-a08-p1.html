一 · 题干拆解：三个必须分离的判据

「Batch 不变性门」这个题面在考场上常被误读成一道“性能题”，实际上它是一道判据分离题。题干通常给出一个 kernel 在若干 batch 规模下的实测时延（或吞吐），要求判断该 kernel 能否通过“batch 不变性门”，并说明它如何影响搜索预算或上线判断。拆题的第一步是把题干里混在一起的三件事拆开：语义不变性（不同 batch 下计算结果是否逐元素一致）、性能标度性（时延随 batch 变化的形状是否符合预期）、门限判定（在给定容差下是否放行）。三者共用同一批测量数据，但判据不同、失败模式不同、修复代价也不同。考场失分绝大多数来自把“数值不一致”当成“性能不达标”来答，或反过来。

第二步是识别题干中隐含的“门”结构。所谓门（gate），在工程上是一个带容差的布尔判据，它把连续的测量量压缩成一个离散的放行/拦截决定。因此题干里必然存在三个要素：被测量的量、参照基准、容差。读题时要逐字确认这三者的定义域——是逐元素比较还是聚合比较，基准是 CPU 参考实现还是同 kernel 的 batch=1 自比较，容差是绝对误差、相对误差还是 ULP 计数。这三项定义不同，同一批数据可以得出相反的结论，这是本题的第一个考点。

第三步是识别题干给出的算例属于哪一类。算例若给出的是“batch 从 1 到 N 的时延序列”，考点落在标度性拟合与搜索预算的换算；若给出的是“同一输入在不同 batch 分组下的输出差异”，考点落在归约顺序与浮点结合律；若同时给出两者，则考的是两个判据的耦合——性能门通过但语义门失败时，上线判断应如何处置。读题时必须先给算例归类，再决定调用哪组公式，否则会把归约误差公式套到标度性问题上，得出量纲都不对的结论。

二 · 核心公式的逐项定位：门函数、标度指数、预算换算

本题需要调用的公式有三组，分别对应三个判据。第一组是门函数本身。设第 b 个 batch 规模下 kernel 输出为 yb，参照输出为 rb，则语义门可写为逐元素的示性函数之合取：

$$G_{\text{sem}}=\bigwedge_{b\in\mathcal{B}}\ \bigwedge_{i}\ \Big[\ \big|y_{b,i}-r_{b,i}\big|\le \tau_{\text{abs}}+\tau_{\text{rel}}\,\big|r_{b,i}\big|\ \Big]$$

逐项解释：外层合取遍历题干给定的 batch 集合 B，内层遍历元素下标 i；容差是绝对项与相对项的混合形式，这是工程上最常用的写法，因为纯相对容差在参照值接近零时会爆炸，纯绝对容差在大幅值处过严。考点在于：合取意味着门是“全称判据”，任一 batch、任一元素越界即整体拦截，因此门的失败信息量极低——它只告诉你“没过”，不告诉你“哪里没过、差多少”。这就是为什么工程上要同时记录越界元素计数与最大越界幅度，作为门的伴随诊断量，否则搜索环节拿不到梯度方向。

第二组是标度性公式。设时延 T(b) 在双对数坐标下拟合为幂律：

$$\log T(b)=\log T_{1}+\alpha\log b+\varepsilon(b),\qquad \hat{\alpha}=\frac{\sum_{b}(\log b-\overline{\log b})(\log T(b)-\overline{\log T})}{\sum_{b}(\log b-\overline{\log b})^{2}}$$

逐项解释：T1 是 batch=1 的外推截距，α 是标度指数，ε 是残差。对访存受限的 kernel，理想 α 接近 1（时延随 batch 线性增长，吞吐恒定）；对计算受限且并行度充足的 kernel，α 可小于 1（batch 增大摊薄了启动开销与尾部效应）。考点在于：α 的估计对采样点分布敏感，若题干只给两个端点，α 退化为两点斜率，残差恒为零，无法判断拟合是否可信；若给出多点，则应报告残差范数以判断是否存在分段标度（小 batch 受启动开销支配、大 batch 受带宽饱和支配，两段斜率不同）。这一点直接决定搜索预算的分配方式。

第三组是预算换算公式。设搜索空间按 batch 规模分层，第 b 层候选数为 nb，单次评估成本为 c(b)（含编译、运行、校验），则总预算为：

$$C_{\text{total}}=\sum_{b\in\mathcal{B}} n_{b}\,c(b),\qquad c(b)=c_{\text{compile}}+c_{\text{run}}(b)+c_{\text{verify}}(b)$$

逐项解释：编译成本与 batch 无关但在 Triton/CuTe 场景下不可忽略（每个候选都要走一次编译流水线），运行成本随时延增长，校验成本随输出元素数增长（逐元素比较是 O(b·d)）。考点在于：门失败会改变预算的有效利用率——被门拦截的候选，其运行与校验成本已经付出却未产生可用信号，等价于预算的沉没。因此搜索策略应在低 batch 层先做粗筛（成本低、能快速暴露语义错误），再向高 batch 层收敛，而不是均匀分配。

三 · 算例的读法：把数字放进哪一项

给定算例的典型形式是：某归约类 kernel 在 batch=1、8、64、256 下的时延序列，以及同一逻辑输入在不同 batch 分组方式下的输出与参照的偏差。读题时要做的是把每个数字归位到上述三组公式的具体项上，而不是急于算出一个“通过/不通过”。

第一步归位时延序列。把四个 batch 点代入标度公式，先看相邻点的局部斜率 αi=ΔlogT/Δlogb。若局部斜率在小 batch 段明显大于 1（时延增长快于 batch 增长），说明该段被固定开销或低并行度支配；若在大 batch 段趋近 1 并稳定，说明进入带宽饱和区。这一步的产出不是单一 α，而是一条分段斜率序列，它告诉搜索环节：哪些 batch 区间的候选值得加密采样——斜率转折点附近的候选最容易被误判，因为门限容差在该处对测量噪声最敏感。

第二步归位偏差数据。算例给出的偏差若表现为“随 batch 增大而单调增长”，则指向归约顺序改变导致的浮点累积误差，此时应调用误差上界思路：串行归约与树形归约的结合律差异，其偏差量级与归约深度和元素量级相关，而非与 batch 本身线性相关。若偏差表现为“与 batch 无关的固定偏移”，则指向 kernel 实现中的常量错误（如索引偏移、掩码边界），这类错误在小 batch 下可能因元素少而恰好落在容差内，在大 batch 下才暴露——这正是“batch 不变性门”存在的理由：它用 batch 维度的扫描把隐藏的边界错误逼出来。

第三步是耦合判断。算例往往同时给出“时延标度良好”与“某 batch 下偏差越界”这两条信息，考的是上线判断的优先级。工程判断是：语义门是一票否决，性能门是优化目标。性能不达标可以标注为“可上线但需继续优化”，语义不达标则必须拦截，因为前者是收益问题，后者是正确性问题。这一判断不需要任何数字，只需要判据的序关系，但考场上有大量答案把它写反。

四 · 解题路径：从题干到可执行步骤

把上述拆解固化成一条可复用的路径，共五步，每一步都有明确的产出物与代价项。

  • 步骤一：定义域确认。逐字提取题干中的 batch 集合、参照定义、容差形式。产出：一张三元组表。代价：若题干未明确容差形式，需在答案中显式声明假设，否则后续所有计算都失去依据。
  • 步骤二：判据分离。把题干数据分成“语义偏差”与“时延序列”两堆，分别对应门函数与标度公式。产出：两条独立的判定链。代价：分离后若发现题干只给了聚合偏差（如最大相对误差），则逐元素门无法严格求值，只能给出保守上界判断。
  • 步骤三：标度拟合与分段检验。计算局部斜率序列与残差，判断是否存在分段标度。产出：转折点位置与各段斜率。代价：多点拟合的计算量可忽略，但若题干只给两端点，必须声明 α 的置信度不足。
  • 步骤四：预算换算。按分层候选数与单次评估成本计算总预算，并指出门失败导致的沉没成本比例。产出：预算分配建议（低 batch 粗筛、高 batch 精筛）。代价：编译成本在候选数大时成为主导项，这是 Triton/CuTe 路线相对手写 CUDA 的固有开销。
  • 步骤五：上线判断。按“语义门一票否决、性能门分级”的序关系给出结论，并注明若语义门失败应回退到哪一层的诊断量（越界元素计数、最大越界幅度、越界所在的 batch 与元素下标分布）。产出：一个带诊断附件的布尔结论。代价：诊断量的采集需要额外的校验代码与显存（保存参照输出与逐元素差异），在大 batch 下这部分显存开销与输出本身同阶。

这条路径的关键在于每一步都产出可检验的中间物，而不是直接跳到结论。考场上的高分答案通常呈现为“三元组表 + 分段斜率 + 预算分配 + 带诊断的布尔结论”这样的结构，而不是一段定性叙述。

五 · 需要调用的公式清单与调用时机

把本部分涉及的公式按调用时机列成一张表，便于在解题时按序取用。表中“触发条件”一列是判断何时该用该公式的依据，缺了它就会出现“公式都会背但不知道用哪个”的典型失分。

公式触发条件主要代价项
语义门合取式题干给出逐元素或可分解的偏差数据校验显存与比较时延，随 batch 与元素数增长
混合容差判据参照值分布跨越零附近与大幅值需同时记录绝对与相对越界计数
幂律标度与斜率估计题干给出三个及以上 batch 的时延两点退化时残差不可估，需声明置信度
分段斜率检验局部斜率序列出现单调转折转折点附近采样需加密，增加评估次数
预算换算求和式题干给出候选规模或要求给出搜索建议编译成本与 batch 无关，候选多时主导总预算
沉没成本比例门失败且已付出运行与校验成本直接削减有效搜索预算，需重排采样顺序

调用时机的判断有一条简洁的规则：先问“题干给的是偏差还是时延”，再问“给的是单点还是序列”，最后问“是否要求给出预算或上线结论”。三个问题的答案组合起来唯一确定公式子集。例如“偏差 + 单点 + 要求上线结论”只需语义门与混合容差两项，标度公式不应出现，出现即为冗余；反之“时延 + 序列 + 要求预算”则必须调用标度与预算两组，语义门仅作为前置过滤提及。

六 · 算例影响的落点：搜索预算与上线判断各自被什么改变

算例对搜索预算的影响，落在预算换算公式的 nb 与 c(b) 两项上。若算例显示小 batch 段斜率异常陡峭，说明该段时延被固定开销支配，则 c(b) 在小 batch 处并不低——固定开销摊不薄，粗筛的性价比下降，预算应更多投向中段 batch。若算例显示大 batch 段已饱和且语义偏差随 batch 增长，则高 batch 层的候选必须附带更严的校验（逐元素而非聚合），cverify 上升，等价于高 batch 层的有效候选数被压缩。这两种情形下预算的重新分配方向相反，读题时必须区分，不能笼统地说“向低 batch 收敛”。

算例对上线判断的影响，落在门的合取结构上。由于门是全称判据，算例中只要有一个 batch 的一个元素越界，结论就是拦截；但拦截之后的上线判断并非终止，而是要区分“可修复的边界错误”与“不可修复的数值不稳定”。前者表现为越界集中在特定 batch 或特定元素区间（如尾部元素、非对齐边界），修复方式是改索引或掩码，代价是一次编译与重测；后者表现为越界幅度随 batch 单调增长且无集中区间，修复方式是改归约树形结构或提升累加精度，代价是时延上升（更高精度累加通常意味着更多寄存器或更慢的指令），这会反过来影响性能门。因此算例的真正作用是把“拦截”细分为“拦截且可修”与“拦截且需权衡”，这一细分直接决定上线判断是“打回重写”还是“带性能折损放行”。

最后落到一个具体的工程判断上：门的设计应把诊断量与布尔结论一起输出，因为搜索环节需要的是梯度而非判决。一个只输出布尔的 batch 不变性门，在 RL 或迭代优化回路中提供的是零信息奖励——通过则无信号，失败则无方向。把越界元素计数、最大越界幅度、越界所在的 batch 与元素下标分布作为门的伴随输出，等价于把一次布尔判定扩展为一个稀疏的、可归因的信号向量，这才是“门”在 kernel 生成回路中真正承担的角色：它不是终点裁判，而是把正确性约束压缩成可搜索信号的那一层接口。
