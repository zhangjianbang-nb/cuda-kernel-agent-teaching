一 · 拆题干：这道题真正在问什么

题干只有一句话：“算法「策略协同多智能体进化」的核心公式逐项解释；给定一个具体算例，说明它如何影响搜索预算或上线判断。”这句话里藏着三个可分离的作答对象，读题的第一步是把它们拆开，而不是急着回忆公式。对象一是“核心公式”——题目要求的是逐项解释，即把公式拆成若干有物理或统计含义的项，说明每一项在算法里承担什么职责、由什么量决定、量纲是什么。对象二是“具体算例”——必须给定一组具体输入（种群规模、策略数、每轮采样预算、验证通过率等），把公式代进去算出一个数，而不是停在符号层面。对象三是“影响搜索预算或上线判断”——这是本题的落点，要求把算例结果翻译成工程决策：预算该加还是该减，候选该上线还是该打回。

三个对象之间存在依赖顺序：不逐项解释公式，就算不出算例；不算出算例，就无法谈预算与上线。因此解题路径是单向的，不能跳步。题干用“或”连接“搜索预算”与“上线判断”，意味着算例只需落在其中一个决策上即可，但必须明确说明落在哪一个，并给出该决策的阈值来源。常见失分是把“逐项解释”写成公式复述——把符号念一遍却不说明该项由什么实验量测、在什么条件下会退化。

二 · 考点定位：四个必须命中的能力点

这道题在评测体系里对应的是“公式—算例—决策”三段式能力，具体可拆成四个考点。考点 A：项级语义。要求对公式中每一项给出“它度量什么、它由哪些可观测量估计、它的取值范围与退化条件”。例如协同项若以策略间输出的一致性度量，则必须指出一致性用何种距离或相关性估计、在策略数趋于 1 时该项如何退化。考点 B：量纲与预算耦合。公式中若含预算变量，必须说明该项随预算增长是线性、次线性还是饱和，以及饱和点由什么决定。考点 C：算例可复现。给定算例的每个输入都必须来自题干或明确假设，代入过程要写出中间量，避免只给最终数。考点 D：决策阈值。上线判断必须绑定一个可观测的判据（如验证通过率下限、单位预算下的收益增量下限），并说明该判据为何能替代“感觉差不多”。

四个考点中，B 与 D 是区分度所在。多数作答能把 A 做对，却在 B 上把预算当作常数处理，导致算例中预算变化时公式各项不联动；在 D 上则给出无阈值的定性结论。评分时通常按考点给分，因此即便算例数字算错，只要量纲分析与阈值来源正确，仍能拿到 B、D 的分。

三 · 公式骨架与逐项职责

“策略协同多智能体进化”的核心公式可写成如下骨架，其中每一项都对应一个可观测的实验量：

$$\mathcal{G}(t)=\underbrace{\frac{1}{M}\sum_{i=1}^{M} r_i(t)}_{\text{个体收益均值}}\;+\;\underbrace{\lambda\,\frac{1}{M(M-1)}\sum_{i\neq j}\mathrm{sim}\big(\pi_i(t),\pi_j(t)\big)}_{\text{策略协同项}}\;-\;\underbrace{\mu\,\frac{C(t)}{B(t)}}_{\text{预算惩罚项}}$$

逐项拆解：第一项是个体收益均值，$r_i(t)$ 为第 $i$ 个策略在第 $t$ 轮获得的验证收益（例如该策略生成的 kernel 通过正确性 oracle 的比例），$M$ 为策略数。该项直接由评测流水线给出，量纲为通过率，取值在 $[0,1]$。第二项是协同项，$\mathrm{sim}(\cdot,\cdot)$ 为两个策略输出的相似度（可用输出分布的总变差距离的补、或生成 kernel 的结构相似度），$\lambda$ 为协同权重。该项度量“种群是否在收敛到同一有效解族”，当 $M=1$ 时无定义，实现中通常置零，这是一个必须指出的退化条件。第三项是预算惩罚，$C(t)$ 为截至第 $t$ 轮累计消耗的采样或编译预算（以 GPU 小时或 token 计），$B(t)$ 为该轮可用预算上限，$\mu$ 为惩罚系数。该项随预算消耗单调上升，作用是抑制“用预算换收益”的短视策略。

三项的量纲并不一致：第一、二项是无量纲比例，第三项是比值，因此 $\lambda$ 与 $\mu$ 本质上是量纲调和系数，其取值必须通过标定实验确定，而不能任意设定。这一点是逐项解释中最容易被忽略的工程细节：若 $\mu$ 过大，公式会被预算项主导，进化退化为“省预算”而非“找好 kernel”；若 $\lambda$ 过大，种群会过早同质化，丧失探索能力。协同项的计算代价也需说明：$\mathrm{sim}$ 对 $M(M-1)/2$ 个策略对逐一计算，当 $M$ 增大时该开销呈二次增长，在每轮预算有限时会挤占实际采样预算，这是公式本身携带的隐性成本。

四 · 算例代入：从符号到具体数

给定算例：$M=4$ 个策略，某轮个体收益分别为 $r=(0.6,0.5,0.4,0.3)$，策略两两相似度矩阵的上三角均值为 $0.55$，取 $\lambda=0.5$、$\mu=1.0$，该轮累计消耗 $C=30$ GPU 小时，预算上限 $B=40$ GPU 小时。代入公式：

$$\mathcal{G}=0.45+0.5\times0.55-1.0\times\frac{30}{40}=0.45+0.275-0.75=-0.025$$

中间量必须写出：个体收益均值 $=(0.6+0.5+0.4+0.3)/4=0.45$；协同项 $=0.5\times0.55=0.275$；预算惩罚 $=30/40=0.75$。最终 $\mathcal{G}$ 为负，说明在该轮配置下，预算惩罚已经压过收益与协同的正贡献。这个结果本身就是决策信号：继续以当前消耗速率推进，$\mathcal{G}$ 会进一步变负。

算例的关键在于展示“联动”：若把 $B$ 提高到 $60$（追加预算），预算惩罚降为 $0.5$，$\mathcal{G}=0.45+0.275-0.5=0.225$，由负转正；若把 $\lambda$ 提高到 $1.0$ 而预算不变，$\mathcal{G}=0.45+0.55-0.75=0.25$，同样转正，但代价是种群同质化风险上升。两种调整路径对搜索预算的含义完全不同：前者是加预算，后者是改权重。题目要求说明“如何影响搜索预算”，正是要求作答者指出这两条路径的取舍——加预算提高的是采样量，改权重改变的是搜索方向，二者不可互换。

五 · 从算例到上线判断：阈值从哪来

算例给出的 $\mathcal{G}=-0.025$ 不能直接当作上线判据，因为 $\mathcal{G}$ 是种群层面的综合分，而上线判断针对的是单个候选 kernel。正确的做法是把 $\mathcal{G}$ 与候选级指标绑定：以算例中收益最高的策略（$r=0.6$）为例，其个体收益高于均值，但协同项与预算惩罚是种群共享的，因此该策略的“有效分”应写成 $r_i-\mu C/B$，即 $0.6-0.75=-0.15$，仍为负。这说明在预算已消耗 75% 的情况下，即便最好的策略也不足以支撑上线。

阈值来源必须可观测：一种做法是以“单位预算收益增量”为判据，即 $\Delta r/\Delta C$ 需高于某个由历史基线标定的下限；另一种是以验证通过率的下置信界为判据，要求候选在留出集上的通过率下界高于部署门槛。两种判据都要求作答者说明标定来源——例如基线来自同任务此前轮次的通过率分布，而非拍脑袋设定。算例中若把 $B$ 追加到 $60$，候选有效分变为 $0.6-0.5=0.1$，由负转正，此时上线判断应从“打回”翻转为“有条件上线”，条件是追加预算后的边际收益增量仍为正。这一翻转点就是搜索预算与上线判断的耦合处，也是本题最想考察的判断力。

六 · 解题路径与需调用的公式清单

完整解题路径可固化为五步：第一步，写出公式骨架并标注每一项的观测量来源；第二步，指出退化条件（$M=1$ 时协同项、$B\to0$ 时惩罚项）与量纲调和系数的标定要求；第三步，代入给定算例，写出全部中间量；第四步，做至少一次单变量扰动（改 $B$ 或改 $\lambda$），观察 $\mathcal{G}$ 的符号与幅度变化；第五步，把扰动结果翻译为预算决策或上线判断，并给出阈值来源。五步中第三步与第四步是算例的核心，第五步是落点。

需调用的公式除主公式外，还包括：协同项的成对相似度定义 $\mathrm{sim}(\pi_i,\pi_j)$ 的具体形式（若用总变差距离，则 $\mathrm{sim}=1-\mathrm{TV}$，需说明 $\mathrm{TV}$ 的估计需要多少采样输出）；预算惩罚的累计形式 $C(t)=\sum_{\tau\le t} c_\tau$，其中 $c_\tau$ 为单轮消耗，需说明 $c_\tau$ 是否含编译时间；以及候选级有效分 $r_i-\mu C/B$ 的推导，它由主公式在固定 $i$ 时剥离种群平均得到。这三条公式共同支撑算例的可复现性。

最后需要点明一个易错处：协同项中的 $\mathrm{sim}$ 若用生成 kernel 的文本相似度估计，会与真实执行行为脱节——两个文本不同但语义等价的 kernel 相似度低，导致协同项低估。工程上应以执行反馈（通过率向量、NCU 采集的吞吐与占用率）作为相似度输入，代价是每对策略需额外一次 profile，使协同项的计算开销从纯文本比较的微秒级上升到分钟级，直接挤占采样预算。这一代价必须在逐项解释中交代，否则公式的预算耦合分析就是不完整的。

公式适用边界的读题拆解：从题干条件反推失效面与系统代价

题干给的是「核心公式逐项解释 + 具体算例影响搜索预算或上线判断」，考点不在推导公式本身，而在识别公式成立所依赖的假设，以及假设被破坏时搜索预算与上线判断如何被反向污染。解题路径分三步：先拆出公式中每一项对应的物理量（策略协同项、多智能体贡献项、进化选择项），再逐项标注其成立前提（如各 agent 的评估信号可比、协同增益可加、选择压力不因并行采样而失真），最后把算例代入前提检验，看哪一项前提最先失效。需要调用的公式是协同增益的可加性假设：

$$G_{\text{team}}=\sum_{i=1}^{N} g_i + \Delta_{\text{syn}},\quad \Delta_{\text{syn}}\ \text{仅在}\ \mathrm{Var}(g_i)\ \text{受控时可估}$$
其中 $\Delta_{\text{syn}}$ 的可估性依赖各 agent 回报方差的受控程度；方差一旦随 agent 数量膨胀，协同项就从「增益」退化为「噪声放大项」，搜索预算被错误地分配到高方差 agent 上。

边界条件有三类，读题时必须逐条对照题干是否给出。第一类是信号可比性边界：多智能体各自产出的 kernel 候选若来自不同抽象层（CUDA C++ 与 Triton），其执行反馈的粒度不同，协同项的可加性不成立，此时公式退化为按层分组的独立进化，搜索预算需按层切分而非按 agent 均分。第二类是选择压力边界：并行采样使每轮候选数上升，若选择算子仍按单 agent 时代的淘汰率执行，则有效选择强度被稀释，进化停滞而预算照常消耗。第三类是评估成本边界：协同评估要求跨 agent 交叉验证正确性 oracle，每次交叉验证引入额外的编译与执行时延，当候选数超过阈值时，评估时延成为预算的主导项而非搜索本身。三类边界中任何一类被题干触发，解题路径就必须从「代入公式算增益」转向「先判定公式是否适用」。

失效条件的系统代价可用一张最小对照表刻画，读题时应把算例映射到其中一行：

具体算例的读法：题干若给出「若干 agent、每轮若干候选、协同评估需交叉验证」的组合，解题时先算交叉验证次数随 agent 数的增长阶，再判断该增长是否超过搜索轮次预算的增速；若超过，则协同项在预算方程中应被降权，上线判断应改用单 agent 基线加分层验证，而非直接采信团队增益。此处不给出数值答案，只给出判定顺序：先验可比性，再验选择强度，最后验评估时延占比，三者任一不满足即触发降级路径。该顺序本身即是考点，也是后续算例代入时的唯一合法入口。
