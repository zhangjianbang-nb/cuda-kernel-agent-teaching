一 · 把题干还原成三个可判定的子命题

《EvoEngineer》这类工作的题干看似只有一句“用 LLM 自动演化 CUDA kernel”，但作为考题它实际包含三个必须分别作答、且判定标准互不相同的子命题。第一是演化机制的有效性：以什么为搜索算子、以什么为适应度、以什么为终止条件。第二是迁移的泛化性：同一套演化流程在换硬件（SM 数量、shared memory 容量、warp 调度粒度）、换 shape（M/N/K 比例、batch 维）、换 dtype（fp32/fp16/bf16/fp8）之后是否仍然收敛到可用 kernel。第三是失效定位与回退：题目明确要求“给出判断、验证方案与回退条件”，这意味着答案必须包含可执行的诊断路径，而不是一句“泛化性不足”。

读题时最容易犯的错误是把三个子命题压成一个。演化机制的有效性可以用编译通过率、正确性 oracle 通过率、相对基线的加速比来判定；迁移泛化性必须用跨域留出集来判定，即演化阶段从未见过的硬件配置、shape 组合与 dtype；而失效定位要求把“性能退化”拆解到具体资源维度上，否则无法给出回退条件。三者的证据来源不同：前者靠演化日志，中者靠留出评测，后者靠 NCU/SASS 层面的计数器。答题结构应当显式对应这三层，任何一层缺失都会被判为“只复述摘要”。

一个具体的拆题例子：题干若给出“在 A100 上对 fp16 GEMM 演化出优于 cuBLAS 的 kernel”，考点并不在于这个加速比本身，而在于该 kernel 的 tile 配置、pipeline 深度、swizzle 方式是否被硬件常量绑死。若 tile 大小取自 shared memory 容量上限、pipeline 深度取自寄存器压力上限，那么这套配置在 shared memory 更小或寄存器文件更窄的硬件上就不是“性能下降”而是“编译失败或正确性破坏”。这就是把题干从“结果”翻译成“结果所依赖的隐含前提”的过程。

二 · 考点：演化搜索的适应度函数与搜索空间设计

第一个考点是适应度函数的构造。自动 kernel 演化的典型适应度是带惩罚的加速比，其形式可写为

$$\mathcal{F}(k)=\frac{t_{\text{ref}}}{t_k}\cdot\mathbb{1}[\text{pass}_{\text{correct}}(k)]-\lambda\cdot c_{\text{compile}}(k)-\mu\cdot r_{\text{resource}}(k)$$

其中 $t_{\text{ref}}$ 是基线（如 cuBLAS 或 PyTorch eager）时延，$\text{pass}_{\text{correct}}$ 是正确性 oracle 的布尔输出，$c_{\text{compile}}$ 是编译耗时，$r_{\text{resource}}$ 是寄存器/shared memory 占用超限的惩罚项。考点在于：$\lambda$ 与 $\mu$ 的取值决定了搜索是偏向“快速出活”还是“稳健可迁移”。若 $\lambda$ 过大，演化会收敛到结构简单但性能平庸的 kernel；若 $\mu$ 缺失，搜索会大量产出占用超限、在目标硬件上无法启动的候选，浪费 token 与编译时间。

第二个考点是搜索空间的表达粒度。LLM 演化 kernel 的变异算子通常作用在三个层次：参数层（tile 尺寸、unroll 因子、block 维度）、结构层（是否使用 double buffering、是否做 split-K、是否用 warp specialization）、指令层（是否改用 `cp.async`、是否用 tensor core 的 MMA 形状）。参数层的变异廉价但天花板低；结构层变异收益大但极易破坏正确性；指令层变异需要 PTX/SASS 级反馈才能有效引导。考点的判断标准是：演化日志中三类变异的成功率与收益分布是否被显式统计——若没有，就无法回答“失效发生在哪一层”。

代价维度必须写清：参数层变异一次的成本约等于一次编译加一次正确性校验，结构层变异往往触发多次编译失败（编译时间成为主要开销），指令层变异则需要 NCU profile 才能判定收益，单次 profile 的时延远高于编译。token 成本上，结构层变异需要更长的上下文（完整 kernel 源码加错误信息），指令层变异需要注入 SASS 片段，二者都会推高每轮演化的 token 消耗。一个具体例子：若变异算子只允许改 tile 尺寸，那么在 K 维很短的 shape 上，无论怎么调 tile 都无法掩盖 global memory 访问的固定开销，此时适应度曲线会平坦化，演化停滞——这不是 LLM 能力问题，而是搜索空间设计问题。

三 · 考点：跨硬件迁移的失效点与判据

跨硬件迁移最可能失效的位置，按可能性排序，第一是资源常量绑定的配置。kernel 的 occupancy 由寄存器数、shared memory 用量、block 大小共同决定，其约束可写为

$$\text{occ}=\min\left(\left\lfloor\frac{R_{\text{reg}}}{r\cdot B}\right\rfloor,\left\lfloor\frac{S_{\text{smem}}}{s\cdot B}\right\rfloor,\left\lfloor\frac{W_{\text{max}}}{w\cdot B}\right\rfloor\right)$$

其中 $R_{\text{reg}}$ 是每 SM 寄存器文件大小，$r$ 是每线程寄存器数，$B$ 是 block 线程数，$S_{\text{smem}}$ 是每 SM shared memory 容量，$s$ 是每 block 用量，$W_{\text{max}}$ 是每 SM 最大常驻 warp 数。演化在源硬件上找到的 $(r,s,B)$ 组合恰好把某一项顶到上限时，换到该项更小的硬件上 occupancy 会骤降，表现为时延成倍上升而非小幅退化。判据是：检查演化最优解的 occupancy 是否由单一约束主导，若是，则该解对硬件常量高度敏感。

第二是warp 调度与内存层级差异。源硬件上有效的 pipeline 深度依赖 global memory 时延与 shared memory 带宽的比值；换硬件后该比值变化，固定的 double buffering 深度会导致要么等待不足（stall 增加），要么 shared memory 超限。第三是指令集可用性：演化出的 kernel 若依赖特定 MMA 形状或 `cp.async` 变体，在缺少该指令的硬件上直接编译失败，这类失效是硬失败而非性能退化，回退条件应当明确为“编译失败即回退到结构层模板”。

验证方案应当设计成受控单变量迁移：固定 shape 与 dtype，只换硬件，记录 occupancy、stall 比例、DRAM 吞吐三项计数器；再固定硬件，只换 shape；再只换 dtype。单变量迁移能把失效归因到具体维度。代价上，每次迁移评测需要一次完整的正确性校验加一次 NCU profile，profile 的时延开销使得全组合扫描不可行，因此验证方案必须做正交采样而非穷举。一个具体例子：若某 kernel 在源硬件上 DRAM 吞吐接近峰值而 stall 比例很低，换硬件后 stall 比例显著上升而吞吐不变，则失效点在 pipeline 深度与内存时延的匹配，而非 tile 尺寸。

四 · 考点：跨 shape 与跨 dtype 的失效点

跨 shape 失效的核心是tile 配置与问题尺寸的比例关系。当 M 或 N 小于 tile 边长时，边界处理分支占比上升，warp 内有效 lane 数下降，有效算力利用率为

$$\eta=\frac{M\cdot N\cdot K}{(\lceil M/t_m\rceil t_m)(\lceil N/t_n\rceil t_n)\,K}\cdot\frac{1}{1+\beta_{\text{boundary}}}$$

其中 $t_m,t_n$ 是 tile 边长，$\beta_{\text{boundary}}$ 是边界分支带来的额外开销比例。演化在源 shape（通常是方阵、较大尺寸）上优化的 tile，在小 M 或小 N 上会因 $\eta$ 骤降而失效。更隐蔽的是 split-K：源 shape 上 K 很大时 split-K 能提升并行度，但 K 很小时 split-K 引入的 reduction 开销与原子操作会成为主导，此时性能退化来自同步而非计算。

跨 dtype 失效的核心是向量化宽度与精度路径。fp32 到 fp16 的迁移不只是数据宽度减半，还涉及累加精度路径的选择：若演化出的 kernel 在 fp16 上用 fp16 累加，正确性 oracle 的容差判定会失败；若改用 fp32 累加，寄存器压力上升，occupancy 下降。bf16 与 fp8 的迁移还涉及指数位宽变化带来的动态范围问题，正确性 oracle 必须按 dtype 设定不同容差，否则会把“精度可接受”误判为“正确性失败”，污染适应度信号。代价维度：dtype 变窄通常降低带宽压力但提高对累加器精度的要求，寄存器占用上升会抵消带宽收益；正确性校验的容差设置不当会导致演化在错误方向上被奖励。

一个具体例子：某 kernel 在 fp16、K 为数百的 shape 上使用 split-K 获得加速；迁移到 K 很小、batch 很大的 shape 时，split-K 的 reduction 步骤占比超过主计算，时延反而高于不分裂的版本。此时失效点是“结构层变异对 K 维的隐式假设”，验证方案是扫描 K 的取值并记录 split-K 开关的收益交叉点，回退条件是当 K 低于该交叉点时禁用 split-K。

五 · 解题路径：从题干到可执行验证序列

解题路径应当写成一条可执行的判定链，而不是罗列可能性。第一步是提取演化最优解的隐含前提：从 kernel 源码中读出 tile 尺寸、pipeline 深度、occupancy 主导约束、所用指令集，把它们写成一组显式的不等式约束。第二步是构造单变量迁移矩阵：硬件、shape、dtype 三个维度各取源域与至少一个目标域，正交组合后按代价排序，优先执行最可能触发硬失败（编译失败、正确性失败）的组合。第三步是用计数器归因：对每个退化样本记录 occupancy、stall 类型分布、DRAM 吞吐、shared memory bank conflict 次数，把退化映射回第一步的某条不等式。

第四步是设定回退条件。回退条件必须是可判定的布尔表达式，例如“若目标硬件上 occupancy 低于源硬件的某一比例且 stall 由 memory 主导，则回退到结构层模板并重新演化 pipeline 深度”；“若正确性 oracle 在目标 dtype 上失败且失败模式为累加溢出，则回退到 fp32 累加路径”。回退的代价是重新演化所需的编译时间与 token 消耗，因此回退条件应当尽量在参数层解决，避免触发结构层重搜。

这条路径的工程判断在于：演化系统的价值不在于单点加速比，而在于退化时能否快速定位到一条不等式。若演化日志没有记录候选解的资源配置与编译结果，那么任何迁移失效都只能被观察到而无法被归因，回退条件也就无从设定。因此读题时应把“日志与计数器是否可追溯”当作独立考点，它决定了后两部分答案是否成立。

一个具体例子：把第一步得到的不等式组写成检查清单，对每个迁移样本逐条打勾，若某条不等式在目标域被违反且该条正是源域 occupancy 的主导约束，则直接判定该样本为“资源绑定型失效”，无需再做 profile 即可给出回退建议；只有当不等式全部满足而性能仍退化时，才进入计数器归因阶段。这样可以把昂贵的 profile 调用限制在少数样本上，控制验证总时延。

六 · 公式与判据的调用清单

本部分需要调用的公式按用途归类：适应度公式用于判断搜索是否被惩罚项扭曲；occupancy 公式用于判断配置是否被单一资源常量绑死；有效算力利用率公式用于判断 tile 与 shape 的比例是否失配；roofline 判据用于判断退化是带宽受限还是计算受限——即比较实际吞吐与 $\min(\text{peak}_{\text{flop}},\text{peak}_{\text{bw}}\cdot\text{AI})$，其中 AI 为算术强度。四者构成一条从“搜索信号”到“资源配置”到“shape 匹配”到“瓶颈类型”的判定链。

调用清单的工程意义在于把“判断”变成“可复核的检查项”。每个检查项都对应一个具体机制、一个可测输入和一个明确的回退动作，三者缺一不可。若某检查项只有机制没有可测输入，它就不是判据而是猜测；若只有回退动作没有失效信号，回退就会在没有证据的情况下被触发，浪费演化预算。读题时应逐项核对题干是否提供了这些输入：题干若只给加速比而不给资源配置与计数器，则答案必须指出证据不足，并把“补齐日志与 profile”列为验证方案的前置步骤，而不是凭空给出失效位置。

迁移失效的判据：把“跨”拆成三个可观测的断裂点

跨硬件、跨 shape、跨 dtype 不是同一类迁移，失效机制也不同，读题时要先把题干里的“跨”拆成三条独立判据。跨硬件失效的典型位置是 occupancy 与访存层级假设：进化出的 kernel 常把 tile 大小、shared memory 用量、寄存器压力按某一代 SM 的 smem/SM 与寄存器文件容量写死，换卡后要么编译期资源超限，要么 occupancy 从多块/SM 掉到一块/SM，掩盖不了延迟。跨 shape 失效集中在边界与规约路径：进化过程倾向针对基准里的固定 M/N/K 做特化，尾块处理、非整除的 split-K、mask 分支在真实 shape 上退化成串行尾段。跨 dtype 失效在数值与指令选择：fp32 累加换成 tf32/bf16 后，进化出的累加顺序与 Kahan 类补偿被删掉，误差随 K 线性放大。

验证方案要给出可判定的量而不是“跑一下看看”。对每个候选 kernel，在目标硬件上采集三组量：编译期资源（regs/thread、smem/block、是否 spill）、运行时 occupancy 与 achieved bandwidth 占 SOL 的比例、以及相对参考实现的数值偏差界。跨 dtype 的判据可用前向误差的一阶估计约束：若累加链长为 K、单次舍入相对误差为 u，则最坏相对误差约 γK ≈ K·u/(1−K·u)，当 K·u 逼近 1 时该估计失效，必须改用分块补偿或更高精度累加，这就是回退条件之一。跨 shape 的回退条件可写成：尾块占比超过某阈值或 split-K 的分片数不再整除 K 时，放弃特化路径回退到通用 tiling。

迁移维度最可能失效点可观测量回退条件

系统代价必须计入判断：跨硬件重调 tile 会拉长编译与 autotune 时间，跨 shape 增加分支会抬高指令 cache 压力与寄存器占用，跨 dtype 引入补偿累加会牺牲吞吐换正确性。因此工程判断是：把“跨”的失效定位到上述三个断裂点中可观测的那一个，再用对应的回退条件切换路径，而不是让进化循环在不可判定的目标上继续搜索。
