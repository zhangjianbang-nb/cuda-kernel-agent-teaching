一 · 题干的三层结构：从“公式逐项”到“关键一步”再到“手算算例”

这道题看似是背诵 Roofline 公式，实际上题干包含三个递进的要求，拆不开就会答成三段互不相干的文字。第一层是“逐项含义”：要求把公式里每一个符号对应到一个可测量的硬件量或算法量，而不是复述“算术强度”这个名词。第二层是“推导的关键一步”：要求指出从“访存受限”到“计算受限”的转折是如何在数学上被形式化的，也就是那个 min 或分段函数是怎么来的、为什么必须取 min 而不是相加。第三层是“可手算的数值算例”：要求把公式代入一组具体数字，得到以 FLOP/s 为单位的可达上界，并说明这个上界与实测性能之间的差距来自哪里。三层之间是依赖关系：逐项含义不清，关键一步就说不清“转折点由谁决定”；关键一步不清，算例就只能套公式而无法解释结果。

考点因此可以归为四类。其一是量纲一致性：公式左边是 FLOP/s，右边两项必须都是 FLOP/s，峰值算力项天然满足，带宽项则必须乘以“每字节访存对应的浮点运算次数”才能升维，这一步是大多数错误答案的失分点。其二是“上界”的语义：Roofline 给的是可达上界而非预测值，它假设了完美重叠、无额外开销、无缓存抖动，因此任何实测值高于它都意味着模型假设被违反（例如数据被缓存复用导致实际带宽需求低于模型估计），而低于它是常态。其三是转折点的物理意义：转折点对应的算术强度等于峰值算力除以峰值带宽，这个比值是硬件的固有属性，与 kernel 无关，但 kernel 落在转折点哪一侧由算法决定。其四是算例的可复现性：手算要求所有输入量都写明来源（峰值 FLOP/s、峰值带宽、实际搬运字节数、实际浮点运算次数），任何一项含糊都会让结果失去意义。

二 · 逐项拆解：每个符号对应一个可测或可估的量

标准形式写作 P ≤ min(P_peak, B · I)，其中 I = F / M，F 是 kernel 完成的浮点运算次数（FLOP），M 是 kernel 与片外存储之间搬运的字节数（Byte），B 是可持续访存带宽（Byte/s），P_peak 是峰值浮点吞吐（FLOP/s）。逐项看：P_peak 不是标称的 boost 时钟乘 SM 数乘每时钟 FLOP 的乘积，而是要在目标精度下、考虑指令发射与流水线占用后的可持续值；对 Tensor Core 路径还要区分稠密与稀疏、是否含累加器溢出回退。B 同理，标称 HBM 带宽是理论峰值，可持续带宽要扣除刷新、读写转向、行冲突带来的损耗，工程上常以 STREAM 类拷贝核的实测值作为 B 的估计。F 与 M 必须来自同一个 kernel 的同一次执行语义：F 按算法实际执行的乘加计（一个 FMA 记两次浮点运算），M 按该 kernel 真正跨越片外存储边界的字节计，而不是按张量逻辑大小计——被 L2 命中的重复读不进入 M，这直接决定了 I 的取值。

这里有一个容易被忽略的细节：M 的定义决定了 Roofline 是“片外”上界。若把 L2 或共享内存的流量也算进 M，带宽项会被高估，上界失去意义；若只算片外而 kernel 实际大量复用片上数据，则模型给出的上界偏保守，实测可能贴近甚至局部超过它。因此逐项含义的作答必须明确声明 M 的边界，这是评分点而非可选项。

$$P \le \min\left(P_{\text{peak}},\; B \cdot \frac{F}{M}\right),\qquad I = \frac{F}{M}$$

代价维度上，逐项拆解本身不产生运行时开销，但它决定了后续优化的方向判断：若 I 远小于转折点，则任何提升 P_peak 利用率的努力（更深的流水、更大的 tile）都无效，唯一有效的是减少 M 或提高数据复用；反之若 I 远大于转折点，减少 M 的收益趋近于零，应转向指令级并行与占用率。误判这一侧的代价是整轮优化白做，这是 token 与工程时间层面的真实代价。

三 · 关键一步：为什么是 min，以及转折点如何被解出来

推导的关键一步不是写出 min，而是论证两条约束为何必须同时成立且取较紧者。访存子系统在单位时间内最多交付 B 字节，因此 kernel 在时间 T 内最多搬运 B·T 字节；要完成 F 次浮点运算，若每次运算平均需要 M/F 字节的片外数据，则所需时间为 (M/B)，而计算所需时间为 F/P_peak。两者是并行资源，理想情况下总时间取二者较大值，于是吞吐取二者较小值——这就是 min 的来源。关键论证在于：这两条约束不是相加关系，因为计算与访存在时间上是重叠的，把时间相加会得到悲观下界而非上界；也不是相乘关系，因为二者不构成串联瓶颈。取 min 表达的是“木桶最短板”语义，而“短板”由 I 与转折点的相对位置决定。

转折点由令两项相等解出：B·I* = P_peak，故 I* = P_peak / B。这个量的单位是 FLOP/Byte，物理含义是“硬件每搬运一字节所能支撑的浮点运算数”。I < I* 时带宽项更小，kernel 处于访存受限区；I > I* 时峰值算力项更小，处于计算受限区。关键一步的另一半是说明 I* 与 kernel 无关、只由硬件决定，因此同一硬件上不同 kernel 的 Roofline 图共享同一个转折点，只是各自落在不同位置。若答成“转折点由 kernel 的算术强度决定”，就是把自变量与因变量搞反了。

伪代码层面的解题路径可以写成三步：第一步，确定目标精度与执行路径，查得可持续 P_peak 与可持续 B；第二步，对给定 kernel 统计 F 与跨片外边界的 M，算出 I；第三步，比较 I 与 I*，取对应分支的表达式算出上界，并注明该上界对应的假设（完美重叠、无缓存复用收益、无尾效应）。这条路径的代价在于 F 与 M 的统计需要 profile 或手工分析，对融合 kernel 尤其繁琐，M 的边界划分会引入估计误差，误差会直接传导到上界的可信度上。

四 · 算例的构造原则：让每个输入量都可追溯

手算算例的价值不在于数字好看，而在于每个输入量都能说清来源，且运算规模小到可以在纸上完成。构造时应选一个访存特征清晰的 kernel，例如逐元素向量加法或小规模矩阵乘的一行分块，使得 M 与 F 可以按定义直接写出而无需 profile。以向量加法为例，读两个向量、写一个向量，若每个元素 4 字节、长度 N，则 M = 12N 字节，F = N 次加法（若按 FMA 计则为 2N，需在算例中声明计数约定，这是评分点）。算术强度 I = F/M 是一个与 N 无关的常数，这一点本身就值得在算例中点出：它说明该 kernel 无论规模多大都固定在访存受限区，扩大 N 不会改变其受限性质，只会线性放大时间。

算例中必须显式给出 P_peak 与 B 的取值口径，例如“按目标精度下的可持续峰值算力”与“按拷贝核实测带宽”，而不能只写标称值。代入后得到两个候选值，取较小者即为上界。此时应进一步说明：实测性能通常低于该上界，差距来自三处——启动与尾效应使小规模算例无法打满、写分配与读改写使实际 M 高于模型值、以及指令发射受限导致计算侧未达 P_peak。把这三处差距写出来，算例才从“套公式”变成“解释模型边界”。代价维度上，算例规模过小会使固定开销占比过高、上界失去参考意义；规模过大则手算不便，因此选取的 N 应使两个候选值量级可比，便于展示转折点附近的行为。

输入量口径要求常见错误
P_peak目标精度、可持续、含流水线占用用标称 boost 时钟直接相乘
B拷贝核实测、扣除刷新与转向用 HBM 理论峰值
F声明 FMA 计一次还是两次与 M 的计数约定不一致
M仅计跨片外边界字节把 L2 命中流量计入

五 · 解题路径中的分叉判断：先判区再算值

实际作答时最容易犯的顺序错误是先代公式再解释，正确顺序是先判区再算值。判区只需比较 I 与 I*，这一步不依赖具体数值精度，只需知道 I 的量级；判区完成后，只需计算对应分支的那一项，另一项仅作为对照写出。这样做的好处是答案结构清晰：先给出 I* 的表达式与物理含义，再给出该 kernel 的 I，指出落在哪一侧，最后代入该侧表达式得到上界。若 I 与 I* 接近，则应两个分支都算出并指出此时上界对输入量的微小误差敏感，这是模型在转折点附近的固有脆弱性。

分叉判断还牵涉到一个工程判断：当 I 略小于 I* 时，提升数据复用（提高 I）与提升带宽利用率（提高有效 B）哪个更划算，取决于二者各自的实现代价。提高 I 通常意味着改变分块策略、增加片上驻留，代价是占用率下降与寄存器压力上升；提高有效 B 通常意味着改善访问模式与合并度，代价是代码复杂度。这一判断无法由公式单独给出，但公式给出了判断的坐标系。算例中若能展示 I 提高一档后上界的变化，就能把“关键一步”的工程含义讲透，而这需要的只是重算一次 min，不引入新的事实。

最后需要点明的是，Roofline 上界的可信度依赖于 F 与 M 的统计口径，而这两者在融合 kernel 与带规约的 kernel 中往往难以精确划分。因此解题路径应包含一句限定：上界是在给定口径下的上界，口径变化会移动上界本身。这不是回避，而是把模型的适用边界写进答案，属于评分中的严谨性得分点。

把“可达上界”读成一道带约束的优化题

题干里“可达上界”四个字是考点所在：它问的不是 roofline 那条折线本身，而是折线在给定 kernel 语义下能被推到多高。拆题干要拆出三层约束——算法层给出最小数据搬运量（字节数 B）与最小浮点运算量（FLOPs），机器层给出峰值算力 P 与峰值带宽 W，实现层给出实际能达到的算力比例 η 与带宽比例 β。公式写成 $$T_{\min}=\max\left(\frac{F}{\eta P},\ \frac{B}{\beta W}\right),\quad \text{AI}=\frac{F}{B}$$ 时，逐项含义就清楚了：F/(ηP) 是计算侧下界，B/(βW) 是访存侧下界，AI 与机器平衡点 P/W 的大小关系决定哪一项占优。关键一步不在代数，而在把“可达”翻译成 η、β 两个小于 1 的折减系数，并说明它们不是常数而是随 tile 形状、占用率、访存模式变化的函数——这一步决定了上界是紧的还是松的。

解题路径因此是四步而非一步：先由 kernel 语义定 F 与 B 的下界（注意 B 要按最小必要流量算，缓存复用只能降低实际流量、不能降低下界）；再算 AI 并与 P/W 比较，判定瓶颈侧；然后对占优侧引入折减系数，写出可达上界；最后做敏感性检查——把 η 或 β 扰动一档，看 T_min 是否换边。换边点附近是这套方案最脆弱的地方：当 AI 接近 P/W 时，两侧下界几乎相等，η 与 β 的任何估计误差都会让“哪一侧是瓶颈”的判断翻转，上界随之失去意义。这是本方案第一个失效条件：平衡点邻域内，roofline 上界对参数估计的鲁棒性极差，工程上应直接报告两侧各自的界而不是单一数值。

第二个失效条件是折减系数的可加性假设。η 与 β 若被当作独立常数相乘进分母，等于默认计算与访存的重叠是完美的；实际 kernel 中指令发射、同步、tile 边界填充都会侵蚀重叠窗口，使有效时间高于 max 而非低于 max。此时正确写法应是 $$T\ge \frac{F}{\eta P}+\frac{B}{\beta W}-\Delta_{\text{overlap}}$$ 的加性形式上界，Δ 为无法重叠的部分。代价是显式的：多一个需要 profile 才能定的量，且 Δ 对 tile 尺寸高度敏感，手算算例里必须把它单列成一行而不是并进 η。第三个边界是精度与数据类型——F 按哪种精度计、P 取哪种精度的峰值，二者不匹配会让 AI 与 P/W 的比较失去物理意义，这是纯定义层面的坑，却常被跳过。

读题动作产出失效信号
定 F、B 下界AI 数值B 里混入可复用流量
比 AI 与 P/W瓶颈侧两者同量级
引入 η、β单侧上界折减系数当常数
敏感性扰动区间而非点值换边即失效

系统代价落在评测口径上：这套读法要求同时给出 F、B、η、β 与 Δ 五个量，其中后三个只能靠 NCU 或 SASS 计数获得，采集成本与编译/重放时间直接计入单次评测预算；若只报一个 T_min 数值而不附这五个量，读者无法判断上界是紧是松，也无法复现换边判断。可手算算例的设计因此要刻意让 AI 落在 P/W 的一侧而非邻域内，并单独列出 Δ 项，否则算例本身就在演示失效条件而非上界。
