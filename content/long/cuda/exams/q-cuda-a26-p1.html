一 · 题干的三层结构：门、公式、搜索

这道题的题干只有一句话，但它压缩了三层信息，读题的第一件事是把这三层拆开，而不是急着写公式。第一层是对象：所谓「生产端到端回归门」不是单点 kernel 的微基准，而是把候选 kernel 放回真实推理链路后，用端到端指标决定「能不能上线」的判定装置。第二层是要求：逐项解释核心公式，意味着答题者必须能说清每一个符号在工程上对应什么可观测量、由谁采集、在什么时间尺度上稳定。第三层是任务：给定一个具体算例，说明公式的输出如何改变搜索预算分配或上线判断，也就是把静态公式接到动态搜索回路上去。

三层之间是单向依赖的：不懂门的语义，公式的每一项都会被解释成纯数学符号；不懂公式的分解，算例就只能给出一个数而说不出它为什么改变搜索。因此解题路径应当是「门的判定语义 → 公式的因子分解 → 算例代入 → 搜索/上线决策的敏感性分析」，四步不可跳。考点也正在这四步的衔接处：多数人能把公式抄对，却说不清某一项在端到端链路里由哪一段 kernel 主导，也说不清当该项变化一个量级时搜索该往哪个方向收缩。

需要预先调用的公式有三类：一是端到端时延的加性分解（各段 kernel 时延与调度、同步开销之和），二是加速比的比值定义与其分母选择（相对哪个基线、是否含框架开销），三是门判定中的裕度/阈值比较式。这三类公式在本片段只做定位，具体展开留给后续部分；此处要建立的是「哪一项归哪一类」的映射，避免在算例里把框架开销错记到 kernel 时延上。

二 · 「门」的判定语义：不是通过率，是决策函数

把回归门理解成「跑一遍测试看是否通过」是最常见的读题偏差。工程上它是一个决策函数：输入是候选实现的一组端到端观测量，输出是三值决策——放行、拒绝、退回搜索。三值而非二值，是因为「拒绝」与「证据不足」在工程上代价完全不同：前者意味着该候选方向应被剪枝，后者意味着需要增加采样或换测量点。题干要求「影响搜索预算或上线判断」，本质就是要求答题者说明这个三值函数的边界如何随公式中各项的方差移动。

判定语义里有一个必须点明的机制：门的比较对象不是绝对时延，而是相对基线的加速比与一个由业务侧给定的最小可接受增益。写成不等式就是候选加速比不低于阈值，且端到端时延的置信区间上界不越过回归红线。这里的关键在于「置信区间」——端到端测量受调度抖动、缓存状态、并发负载影响，单次测量不足以支撑放行。因此门的输入实际是一个估计量而非点值，公式中的每一项都要带自己的不确定度，门的判定是对这些不确定度做保守合成后再比较。

代价在这里第一次出现：为了把置信区间压到可用宽度，需要对同一候选重复多次端到端运行，每次运行都包含完整链路的前向，其时间成本远高于单 kernel 微基准。若一次端到端回归耗时是单 kernel 基准的数十倍量级（定性表述，不引用具体数字），那么门的采样次数就直接吃掉了搜索预算。这就是为什么公式的逐项解释必须包含「哪一项的方差最大」——方差最大的项决定了需要多少次重复才能让门做出稳定判断，而重复次数就是预算。

具体例子：某候选把注意力段的 kernel 换成更低占用率的实现，单 kernel 微基准显示时延下降，但端到端测量中该段之后的归一化与残差段因数据布局变化产生了额外的重排开销，导致端到端加速比落在阈值附近且方差偏大。此时门不应给出「放行」，而应给出「退回搜索」并指明需要针对布局转换段再做一次候选生成。这个例子说明：门的输出不是标量通过/不通过，而是带定位信息的决策，定位信息正是公式逐项分解的产物。

三 · 公式的因子骨架：四项与它们的可观测量

核心公式的骨架可以写成端到端加速比等于基线端到端时延除以候选端到端时延，而分母再分解为四部分之和：候选 kernel 计算时延、数据搬运与布局转换时延、kernel 间调度与同步开销、框架侧固定开销。分子同理，只是基线在这四项上的取值不同。逐项解释的任务，就是把这四个加数分别对应到可采集的量上，并说明每一项在什么条件下会成为主导项。

$$S=\frac{T_{\text{base}}}{T_{\text{cand}}},\qquad T=\sum_{i\in\{\text{comp},\text{move},\text{launch},\text{fw}\}} t_i$$

第一项计算时延由目标 kernel 的指令吞吐与占用率决定，可由硬件计数器直接归因，是搜索最常优化的对象。第二项搬运与布局转换时延包括显存读写、共享内存换入换出、以及因张量布局不匹配引入的重排；它常常不体现在单 kernel 基准里，却在端到端链路里被放大。第三项调度与同步开销随 kernel 数量和依赖深度增长，是「把一个大 kernel 拆成多个小 kernel」这类候选的隐性税。第四项框架固定开销与候选实现无关，它在分母中占比越大，加速比越被稀释——这正是端到端门与微基准门结论分歧的主要来源。

逐项解释还必须给出每一项的敏感性：当某一项在分母中占比为 p 时，该项自身改善 r 倍所带来的整体加速比上限受 1/(1−p+p/r) 约束。这个式子不需要复杂推导，但它是答题者说明「为什么继续优化某一项收益递减」的唯一工具。若 p 很小，即便该项改善到接近零，端到端加速比也几乎不动；此时搜索应把预算转向占比大的项，而不是继续在该项上做多轮变异。

具体例子：若框架固定开销在分母中占比较大，而候选只优化了计算项，则即便计算项时延减半，端到端加速比的变化也被压缩在很小的范围内。答题者应据此指出：该算例下门的判定对计算项不敏感，搜索预算应从「生成更多计算变体」转向「减少 kernel 数量以压低调度项」或「消除布局转换以压低搬运项」。这就是公式逐项解释与搜索决策之间的桥。

四 · 算例的代入方式：先定基线，再定主导项

题目要求「给定一个具体算例」，读题时必须明确算例的代入顺序，否则会把比值算反。正确顺序是：先固定基线配置（同一硬件、同一批输入形状、同一并发度），再测基线四项的分布，然后对候选测同样四项，最后才做比值。跳过基线分布直接比较候选总时延，会让「哪一项是主导项」失去参照，搜索方向也随之失去依据。

代入时有一个容易被忽略的机制：四项的测量时间尺度不同。计算项可在微秒级稳定，调度项受队列深度影响，框架项受主机侧调度影响，搬运项受缓存命中率影响。因此算例中应当声明每一项的采集方式与重复次数，并说明哪些项需要与端到端总时延同批采集以避免跨批次漂移。答题者若不声明这一点，算例就退化成算术练习，无法支撑「影响搜索」的结论。

代价在此处体现为测量预算：对四项分别做稳定测量所需的端到端重复次数，往往由方差最大的那一项决定。若搬运项的方差最大，则需要更多重复才能把它与噪声区分开，而这部分重复不产生任何搜索进展，纯粹是门的基础设施开销。工程判断是：当某一项方差长期居高不下时，应优先改造测量方法（例如固定输入布局、预热缓存）而不是增加重复次数，因为后者的预算消耗是线性的而前者是一次性的。

具体例子：算例给出候选在计算项上改善明显、在调度项上因 kernel 拆分而恶化、在搬运项上因布局转换而小幅恶化、框架项不变。代入后总时延可能仅小幅下降甚至持平。答题者应据此得出：该候选的端到端加速比不足以越过门阈值，门应判「拒绝」而非「退回搜索」，因为恶化项是结构性的（拆分带来的调度税），继续在同一方向变异不会改变符号。这一判断直接改变了搜索预算的流向——从该候选家族剪枝，把预算移向不增加 kernel 数量的优化路径。

五 · 从公式到搜索：敏感性决定预算，符号决定剪枝

公式对搜索的作用可以归结为两条规则，读题时应把它们显式写进解题路径。第一条是敏感性规则：整体加速比对某一项的偏导近似正比于该项在分母中的占比，因此预算应优先分配给占比大且仍有改善空间的项。第二条是符号规则：若候选在某项上相对基线恶化，且该项是结构性的（由候选的构造方式决定而非偶然噪声），则该候选家族应被剪枝，而不是继续在其上做参数微调。

这两条规则共同决定了搜索回路中「生成—评估—剪枝」的节奏。生成阶段产生的候选若在公式分解上呈现同一主导项，则它们应被批量评估后统一剪枝，而不是逐个做多轮迭代；反之，若候选在不同项上各有改善，则应保留多样性以覆盖不同的占比结构。这里有一个预算分配的伪代码思路：按主导项对候选分桶，对每桶先做少量端到端采样估计符号，仅对符号为正且敏感性高的桶追加采样与变异预算。这样做的代价是分桶本身需要一次端到端测量，但换来的是避免在符号为负的桶上浪费多轮迭代。

上线判断则比搜索剪枝更保守：搜索允许在方差大的区域多采样，上线判断必须在置信区间上界越过红线时拒绝，即便点估计显示加速。这意味着同一个公式在搜索回路与上线门中使用不同的比较方式——前者用点估计排序，后者用保守界判定。答题者若混淆这两者，就会得出「搜索认为好但上线被拒」的矛盾结论而无法解释。

具体例子：算例中两个候选的端到端加速比点估计相近，但一个的方差主要来自调度项（可通过固定并发度压低），另一个的方差来自搬运项（受输入布局影响，难以压低）。搜索阶段两者可并列保留，上线阶段应优先放行前者，因为其置信区间更窄、更可能稳定越过阈值。这一区分正是公式逐项解释的工程价值所在：它把「加速比是多少」升级为「加速比由什么构成、因而有多可信」。

六 · 读题时应预先标记的三个陷阱

第一个陷阱是把微基准的加速比直接当作端到端加速比。公式的分母含四项，微基准只覆盖第一项，因此微基准结论在框架项占比大时会系统性乐观。读题时应标记：算例是否给了四项分布，若未给，答题者必须声明假设并说明该假设如何影响结论，而不能默认框架项为零。

第二个陷阱是忽略基线选择对阈值判定的影响。加速比是比值，分母（基线）若选用了未经优化的参考实现，则候选的加速比会被高估，门阈值看似轻易越过；若基线已是生产调优版本，则同样的候选可能不达标。题干未指定基线时，答题者应把基线选择作为一个显式决策点写入解题路径，并说明它如何改变搜索的起点预算——基线越强，搜索越应聚焦于结构性改动而非参数微调。

第三个陷阱是把「退回搜索」当成「拒绝」的同义词。二者在预算上的含义相反：拒绝是剪枝，释放预算；退回搜索是追加采样，消耗预算。公式中方差项的估计质量决定了门能否区分二者，因此逐项解释必须包含方差来源的归因，否则门的输出会退化为二值，搜索回路也就失去了根据不确定性调整预算的能力。具体到算例，若候选的总时延改善落在噪声范围内，正确输出是退回搜索并要求更窄的测量，而不是直接拒绝该方向。

这三个陷阱的共同点是：它们都发生在公式与工程语义的接缝处，而不是公式本身。读题时把接缝标出来，解题路径才不会写成纯代数推导；算例的代入也才有决策含义，而不是一个孤立数字。
