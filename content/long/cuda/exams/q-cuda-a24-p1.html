一 · 拆题干：这道题到底在问什么

题干表面是一个“解释公式 + 算例”的复合问句，实际包含三层可分离的作答义务。第一层是公式逐项解释：要求把成功轨迹蒸馏 SFT 的损失函数拆到每一个符号，说明每个符号在数据管线里对应什么张量、什么 mask、什么归一化分母。第二层是算例代入：给定一个具体配置（轨迹条数、每条轨迹的 token 数、成功/失败比例、蒸馏温度或权重），要求算出损失值或梯度尺度，并说明这个数值在工程上意味着什么。第三层是决策影响：算例结果如何改变搜索预算（采样多少条轨迹才够）或上线判断（这个 SFT 检查点是否值得进入后续 RL 或部署）。三层义务的评分权重不同，但第三层最容易失分，因为它要求把损失数值翻译成预算与风险的判断，而不是停在算术上。

题干的措辞里藏着两个约束条件，读题时必须圈出来。其一，“成功轨迹”是筛选后的子集，不是全量 rollout，因此公式里的分母与采样总数之间存在一个接受率因子；忽略它会把损失尺度算错一个量级。其二，“蒸馏”在此处不是 logit 匹配意义上的 KD，而是把成功轨迹当作硬标签做监督，因此公式里出现的是交叉熵而非 KL 散度——这个区分决定了逐项解释时温度参数是否进入公式。题干没有给温度，说明考点不在此，不要在答题时自行引入。

还有一个隐含的读题陷阱：题干说“说明它如何影响搜索预算或上线判断”，用的是“或”，意味着两条路径只需打通一条，但打通的那条必须给出可执行的判据。若只写“损失小则上线”，属于未作答；必须落到具体阈值来源、具体预算换算。

二 · 考点定位：命题人想筛掉哪类回答

这道题的核心考点是符号与数据管线的对应能力。成功轨迹蒸馏 SFT 的损失写成求和形式时，每个下标都对应一次具体的张量切片操作：轨迹索引、token 位置索引、以及成功掩码。命题人想看到的是答题者能否指出“分母是成功轨迹上的有效 token 总数，而非 batch 内全部 token 数”，因为这是实现中最常见的错误来源——把 padding token 或失败轨迹的 token 计入分母，会让损失被稀释，梯度变小，训练早期表现为 loss 曲线“好看但学不动”。

第二个考点是归一化口径与梯度尺度的耦合。同一个公式，按 token 平均与按轨迹平均会给出不同的梯度量级，进而影响学习率的选择与梯度裁剪阈值。答题者若只写“对损失取平均”而不指明平均的维度，等于没有解释清楚。这一点与序列级目标（如 RL 中的序列对数概率）形成对照：序列级目标按轨迹归一化，token 级目标按 token 归一化，两者在变长轨迹上的差异随长度方差放大。

第三个考点是算例的工程解读。给定接受率与轨迹长度分布后，算出的损失数值本身没有意义，有意义的是它与“全量监督”损失之间的比值，以及这个比值如何随接受率变化。命题人希望看到答题者把算例结果映射为“需要采样多少条 rollout 才能凑够一个 batch 的有效 token”，这正是搜索预算的直接来源。

第四个考点是正确性代价的意识。成功轨迹筛选依赖一个判定器（单元测试、数值比对或参考实现），判定器本身有假阳性与假阴性。假阳性会把错误轨迹送进 SFT，损失下降但能力不升；假阴性会丢弃正确轨迹，降低有效样本量。答题时若不提判定器的代价，公式解释就停留在数学层面，没有落到工程可信度上。

三 · 解题路径：从符号到判据的四步

建议的作答路径是四步递进，每步产出一个可检查的中间结果，避免直接跳到结论。

  • 第一步，写出损失的通式并标注每个符号的张量形状。通式是成功轨迹集合上的 token 级交叉熵：对每条被判定为成功的轨迹，对其每个有效 token 位置，取模型在该位置的 log-probability 与目标 token 的负对数似然，求和后除以有效 token 总数。符号包括：轨迹集合大小、单条轨迹有效长度、成功掩码、有效 token 掩码、模型参数。形状标注要写清哪个维度被求和、哪个维度被平均。
  • 第二步，写出两个归一化变体并给出选择理由。按 token 归一化与按轨迹归一化在变长轨迹下方差不同；给出选择理由时要联系梯度尺度与学习率，而不是泛泛说“按 token 更稳定”。
  • 第三步，代入算例，算出损失与梯度尺度。算例需给出轨迹条数、平均有效长度、接受率、成功轨迹内长度方差。计算分两步：先算有效 token 总数，再算加权平均损失。若算例给出每 token 的平均负对数似然，则损失就是该值；真正要算的是分母，以及分母随接受率的变化率。
  • 第四步，把数值翻译成预算或上线判据。预算路径：由目标 batch 的有效 token 数除以单条轨迹平均有效 token 数再除以接受率，得到所需采样轨迹条数；接受率下降时预算按反比上升。上线路径：比较蒸馏损失与基线（全量监督或前一检查点）损失的比值，若比值未随接受率改善而下降，说明筛选没有带来信息增益，应暂缓上线。

四步中，第三步最容易出错的是单位。损失是每 token 的纳特数，预算的单位是轨迹条数，两者之间隔着“每 token 成本”这一换算因子；答题时把这个因子显式写出，可以避免量纲混乱。

四 · 需要调用的公式与伪代码骨架

核心公式是成功轨迹上的 token 级负对数似然均值。设成功轨迹集合为 S，轨迹 i 的有效 token 位置集合为 T_i，模型在位置 t 对目标 token y 的输出概率为 p，则：

$$L_{\text{distill}} = -\frac{1}{\sum_{i \in S} |T_i|} \sum_{i \in S} \sum_{t \in T_i} \log p_\theta(y_{i,t} \mid x_{i,<t})$$

逐项解释时，分母是成功轨迹的有效 token 总数，这是与“全量 SFT”唯一的实质差别；分子对轨迹与位置双重求和。若改用按轨迹归一化，则外层除以 |S|、内层每条轨迹先除以 |T_i|，得到的是轨迹平均损失，其梯度对长轨迹的权重更高。两种口径的比值等于“轨迹长度倒数的均值”与“长度倒数的倒数”之比，在长度方差大时偏离明显。

伪代码骨架用于说明掩码与分母的构造顺序，答题时可用文字描述该顺序而不必写出完整代码：先对每条 rollout 计算判定器结果得到成功掩码；再对每条轨迹计算有效 token 掩码（排除 padding 与截断位置）；两者相乘得到参与损失的 token 集合；对该集合计数得到分母；最后在集合上做交叉熵求和并除以分母。顺序颠倒（先算损失再乘掩码）会导致分母包含被屏蔽的 token，这是实现层面的典型错误。

预算换算公式同样需要写出：设目标每步有效 token 数为 B，单条轨迹平均有效 token 数为 m，接受率为 a，则每步所需采样轨迹条数 N 满足：

$$N = \frac{B}{m \cdot a}$$

该式表明预算对接受率是反比关系，接受率减半则采样量翻倍。上线判据可写成比值形式：设当前蒸馏损失为 L，基线损失为 L0，若 L/L0 在接受率提升后没有下降，则筛选的信息增益可疑。这里的代价是：判定器每次调用都消耗执行时间与算力，接受率越低，单位有效样本的判定开销越高；在搜索预算固定时，判定器开销会挤占 rollout 预算。

五 · 算例的构造与它暴露的工程代价

给定一个具体算例：一批 rollout 共若干条轨迹，判定器筛出其中一部分为成功，成功轨迹的平均有效长度为某个值，成功轨迹内部长度存在方差。算例要求算出三件事：有效 token 总数、蒸馏损失（在给定每 token 平均负对数似然的前提下）、以及为凑够目标 batch 所需的采样条数。

第一件是分母。有效 token 总数等于成功轨迹条数乘以平均有效长度，再按长度分布做修正——若长度方差大，均值乘以条数会高估或低估真实总数，因为长轨迹贡献的 token 数远超其条数占比。这一步暴露的代价是显存：分母对应的激活张量规模随有效 token 总数线性增长，长轨迹尾部会拉高峰值显存，迫使减小 micro-batch，进而改变梯度累积步数与有效 batch 的等价关系。

第二件是损失值。若每 token 平均负对数似然给定，损失即为该值，与接受率无关；真正随接受率变化的是损失的估计方差。接受率低时，成功轨迹条数少，损失的批间方差大，单步梯度噪声高，需要更小的学习率或更大的累积步数。这一步暴露的代价是时延：为压低方差而增大累积步数，直接拉长每次参数更新的墙钟时间。

第三件是预算。由 N = B/(m·a) 算出采样条数后，要再乘以单条轨迹的生成时延，得到每步的 rollout 墙钟成本；再加上判定器对每条轨迹的验证开销，得到总成本。若接受率低到使 N 超过单机并发上限，就必须引入跨节点采样或降低目标 batch，前者增加通信开销，后者改变训练动态。这一步暴露的代价是编译与调度：跨节点采样要求 kernel 的 grid 配置与通信原语匹配，调试周期变长。

算例的工程意义在于把“公式里的一个分母”翻译成“显存峰值、累积步数、采样条数、墙钟成本”四个可测量的量。答题时若只算出数值而不指出这四个量中至少一个的变化方向，算例部分就只是算术练习。

六 · 上线判断的判据与不可省略的正确性代价

上线判断不能只看蒸馏损失绝对值，要看三个量的组合：蒸馏损失相对基线的比值、接受率、以及判定器的假阳性率。比值下降说明模型在成功轨迹上拟合更好；但若接受率同时下降，说明成功轨迹变得更稀缺，比值下降可能只是样本变简单，而非能力提升。假阳性率则决定这个下降是否可信：假阳性高时，损失下降部分来自拟合错误标签，上线后会在分布外输入上暴露。

一个可执行的判据是：在接受率不低于某个工程下限的前提下，蒸馏损失比值相比前一检查点下降，且判定器在留出验证集上的假阳性率未上升，才进入下一阶段（RL 或部署）。这里的代价是验证开销：留出验证集上的判定器调用是纯开销，不产生训练信号，但它是上线判断的唯一可信来源。若省略这一步，搜索预算会被虚假的成功轨迹持续消耗，表现为采样量上升而下游指标不动。

另一个判据与搜索预算耦合：若单位有效样本的判定开销已经超过 rollout 开销，说明筛选管线本身成为瓶颈，此时应优先优化判定器（例如用编译后的参考 kernel 替代解释执行），而不是继续加大采样量。这个判断的依据是成本结构而非损失数值，答题时点出这一点，能把“公式解释”与“工程决策”真正接上。

最后落在具体机制上：成功轨迹蒸馏 SFT 的损失分母是一个由判定器与掩码共同决定的随机量，它同时受接受率、长度分布与判定器误差影响；因此任何基于该损失的预算或上线判断，都必须把分母的估计方差一并纳入，否则数值本身不构成决策依据。

蒸馏SFT的边界：当“成功轨迹”本身成为噪声源

该方案的核心公式可拆成三项：轨迹筛选指示函数、token级交叉熵加权、以及KL锚定项。筛选项假设“成功”可由最终奖励二值判定，但工程上奖励往往来自一个与策略分布耦合的验证器——当验证器本身有漏判（把正确解判错）或误判（把错误解判对）时，蒸馏目标就从“模仿正确推理”退化为“模仿验证器偏好”。失效条件很具体：一旦误判率与漏判率不对称，且被误判的轨迹在token分布上系统性偏离真实正确解（例如靠猜测命中答案），加权交叉熵会把这种捷径分布放大。代价是双重的：训练侧token消耗不变但有效梯度被污染，部署侧表现为pass@1上升而pass@k在k增大时反而下降——因为多样性被捷径分布挤压。

$$\mathcal{L}=\sum_{i}\mathbb{1}[r_i=1]\cdot\sum_{t}-\log \pi_\theta(y_t\mid y_{<t})+\beta\,\mathrm{KL}(\pi_\theta\|\pi_{\text{ref}})$$

系统代价还体现在搜索预算上。若把该蒸馏用于在线自博弈采样，筛选指示函数会诱导策略快速收敛到验证器的高分盆地，采样温度需被迫调高以维持探索，而高温下的token生成时延与显存占用随序列长度平方增长（注意力部分），单条轨迹的墙钟成本上升。一个具体算例：某kernel生成任务中，验证器以“编译通过且数值误差在容差内”为成功判据，某条轨迹靠关闭边界检查侥幸通过，蒸馏后模型在需要边界检查的变体上编译通过率不变但运行时越界访问比例上升——此时上线判断应看NCU报告的访存越界计数，而非仅看基准通过率。
