一 · 题干的两个问句其实是两种不同性质的判断

题干“理论浮点误差累积界在什么假设下失效？如果线上出现相反现象，你怎么判断是公式错了还是负载变了？”表面是一个问题，实质是两类判断被压缩在一句话里。第一问是前提审计：任何累积界都是“在若干假设下成立”的命题，问它何时失效，等价于把这些假设逐条列出并给出各自的破坏条件。第二问是归因判断：线上观测到的误差与理论界方向相反（实测小于界、或实测超出界但随负载漂移），此时要区分“界本身推导有误”与“界没错、但实际负载已不在界的适用域内”。这两问共用同一套假设清单，但推理方向相反——前者从假设出发找反例，后者从观测出发反查被破坏的假设。答题时若把两问混作“误差为什么变大”，就会丢掉归因这一半的分。

考点因此可拆为四层：其一，能否写出一个具体的累积界形式（而不是笼统说“误差会累积”）；其二，能否指出该界依赖的假设类别（运算顺序、归约规模、指数范围、舍入模式、数据分布）；其三，能否给出“假设失效”的可观测征兆与代价（时延、带宽、显存、编译时间、token）；其四，能否设计一个可执行的判别路径，把“公式错”与“负载变”在工程上分开。阅卷视角下，第四层是区分度所在：只答前三层是背书，答出第四层才是工程判断。

二 · 必须先落地的公式骨架：累积界长什么样

讨论“界失效”之前，得先把界写成可审计的形式。浮点误差累积界的典型骨架是前向误差界：对长度为 n 的归约（点积、求和、范数），在标准模型下逐次舍入的误差被界定为与 n 和单位舍入 u 成正比的量。写成公式即：

$$ \left|\hat{s} - s\right| \;\le\; \gamma_{n}\, \sum_{i=1}^{n} |x_i| ,\qquad \gamma_{n} = \frac{n u}{1 - n u} $$

其中 u 是单位舍入（与精度格式绑定），γ_n 随 n 线性增长。这个式子的每一处都埋着假设：求和按固定顺序串行进行、中间结果不溢出也不下溢、舍入是就近舍入且无异常值、|x_i| 的量级不导致灾难性抵消被放大。树形归约把 n 换成 log n 量级的深度，界随之收紧，这本身就是一个“假设变了、界也变了”的例子。答题时应把界写成“误差 ≤ 系数 × 数据规模度量”的乘积结构，因为归因判断正是围绕这两个因子分别做文章：系数侧对应公式与假设，数据规模度量侧对应负载。

需要强调代价：这个界是最坏情况界，不是期望误差。它给出的保证以“牺牲紧致性”为代价——真实误差通常远小于界，于是“实测远小于界”本身不构成公式错的证据，只说明最坏情况未发生。反过来，若实测超出界，则一定存在某条假设被破坏，因为界在假设成立时是硬上界。这一条不对称性是整个归因路径的支点：低于界不证明错，高于界必证明假设破了。把这条写进答案，第二问就有了逻辑起点。

三 · 假设清单：五类破坏条件与各自的观测征兆

把界的假设逐条拆开，每类都对应一种失效机制和一种可观测征兆。答题时用表格组织最省字数，也最便于阅卷对照。

假设类别破坏机制可观测征兆主要代价
运算顺序固定并行归约/重排改变结合律路径，深度与系数不再匹配误差随线程块划分、split-K 策略跳变时延与占用率变化，编译期 kernel 变体增多
规模 n 有界序列长度或 batch 超出界推导时的 n 上界，γ_n 线性项主导误差随 n 近似线性抬升显存与带宽压力上升，分块策略被迫改变
指数范围安全中间量溢出/下溢，界推导中的“无异常”前提破缺出现 inf/nan 或突然的量级塌缩需插入缩放或分段，增加一次额外遍历

这张表的关键用法是“征兆—假设”的反向索引：线上观测到哪一种征兆，就优先怀疑对应那一行的假设，而不是先怀疑公式。举例来说，若误差随序列长度呈近似线性增长而非对数增长，指向的是“规模 n 有界”与“运算顺序固定”两行同时被破坏——并行归约本应把深度压到 log 级，实测却表现出串行特征，说明实际执行路径与界推导时假设的路径不一致。再如混合精度场景下误差出现台阶式跳变，指向舍入模式一行，此时公式系数里的 u 已不再是推导时用的那个 u，界的形式没错但参数错配。

每一行都要配一个具体例子才算答到位。运算顺序一行可举 split-K：当 K 维被切分到多个块再由原子加合并，合并顺序不确定，界的系数不再是一个确定值而是一个随调度波动的区间，这直接动摇“界是硬上界”的表述方式。数据分布一行可举大数相减：两个量级相近的大数相减，绝对误差界仍成立，但相对误差被放大若干数量级，若线上指标是相对误差，就会看到“界没破、指标却崩”的假象——这正是“相反现象”的一种来源。

四 · 归因路径：把“公式错”与“负载变”做成可判别的实验

归因不能靠猜，要靠可控变量。核心思路是固定一侧、扰动另一侧：先固定负载（同一输入分布、同一 n、同一精度档），只改变执行路径（线程块大小、split-K 开关、归约树形状），观察误差是否随路径系统性变化；再固定执行路径，只改变负载（n、动态范围、异常值比例），观察误差是否随负载系统性变化。若误差只随路径变，问题在“界的假设与实现路径不匹配”，属于公式适用域问题；若误差只随负载变，问题在负载漂移，公式本身仍成立。伪代码思路如下：

  • 构造两组对照：A 组锁负载、扫路径参数；B 组锁路径、扫负载参数。
  • 每组记录（误差实测值、界预测值、比值），比值定义为实测/界。
  • 若 A 组比值方差显著大于 B 组，判为路径/假设错配；反之判为负载漂移。
  • 对判为负载漂移的样本，回代界的规模因子，检查实测是否仍落在界内；落在界内则公式无罪。

代价必须写清：这套对照实验需要额外的 kernel 变体编译与多轮 profiling，编译时间与 token 消耗随变体数线性上升；若用 NCU 采集逐指令指标，采集本身会引入时延扰动，需在离线复现环境做而非线上直采。另一个代价是正确性 oracle 的阈值设定——对照实验要求 oracle 能区分“界内偏差”与“真错误”，阈值定得过紧会把正常舍入噪声判成错误，定得过松则漏掉假设破坏。工程上通常把 oracle 阈值与界的系数挂钩，使阈值本身随假设清单联动。

一个具体例子：线上发现某归约 kernel 的相对误差在长序列上反而比短序列小，与“误差随 n 增长”的直觉相反。按上述路径，先锁负载扫路径，发现误差对 split-K 开关极敏感；再锁路径扫负载，发现误差随 n 非单调。结论指向运算顺序假设被破坏——长序列触发了不同的分块策略，实际归约深度反而更浅，界推导时的串行假设不再成立。此时不是公式错，而是界的适用域被实现策略绕开了，正确做法是把界改写成以实际归约深度为参数的版本，而不是推翻原公式。

五 · 解题路径的书写顺序与得分点分布

落到答题纸上的顺序应是：先写界的形式与它的假设清单（对应第二、三节），再写不对称性判据（低于界不证错、高于界必证假设破），再写对照实验设计（第四节），最后才谈具体征兆与例子。这个顺序的理由是：归因路径的逻辑依赖不对称性判据，而不对称性判据又依赖界的形式，倒着写会出现“先给结论再补前提”的结构性失分。得分点通常分布在三处：界的形式是否写对（含 γ_n 的规模依赖）、假设清单是否覆盖运算顺序与数据分布两类（这两类最易被漏）、对照实验是否体现“固定一侧扰动另一侧”的可控变量思想。只列假设不给判别实验，第二问拿不到分；只给实验不写界的假设，第一问拿不到分。

还需点明一个易错处：把“实测小于界”直接当作公式错的证据。由于界是最坏情况界，实测小于界是常态，不构成反例；真正构成公式错证据的是“在假设明确成立的受控条件下，实测仍系统性超出界”。因此归因实验里必须有一组“假设被验证成立”的基线，否则任何超出都可被辩解为“某条假设恰好破了”。基线的代价是额外的受控运行与 oracle 校准，但这部分开销换来的是归因的可证伪性，属于必须支付的成本。写答案时把这条基线要求写进去，等于向阅卷人表明你理解“界是条件命题”而非“界是经验拟合”。

六 · 把“相反现象”翻译成假设坐标

“相反现象”在题干里是模糊词，答题时要把它翻译成可操作的坐标：是误差随规模单调性反了，还是误差与界的比值反了，还是精度档位与误差的排序反了。三种翻译指向不同假设行。单调性反了，查运算顺序与规模两行；比值反了（实测/界在负载增大时下降），查界是否用了过保守的系数，即公式侧问题；精度排序反了（低精度档反而误差小），查舍入模式与数据分布两行，常见于低精度触发了不同的累加路径。把这三类翻译写出来，等于把题干的定性描述拆成了可检验的子命题，这也是本部分要求“拆题干”的落点。

最后落在工程判断上：归因的终点不是宣布“公式错”或“负载变”，而是给出界的适用域修订——若判为负载漂移，则把界的规模参数从固定 n 改为随实际分块策略变化的有效深度；若判为公式错配，则把系数里的 u 替换为实际精度档位对应的单位舍入，并在界旁标注所依赖的舍入模式。修订后的界必须能被下一次线上观测直接证伪，否则归因没有闭环。这一步的代价是维护两套界（理论界与实现域界）并保持同步，编译期需为每个 kernel 变体绑定对应的界参数，token 开销体现在变体文档与 oracle 阈值的联动更新上；但不做这一步，下一次出现相反现象时仍然只能从零开始猜。

把题干拆成可证伪的假设清单

题干里“误差累积界”不是单一命题，而是一组假设的合取：舍入模型（每步相对误差 ≤ u）、运算次序固定、归约规模与数据分布稳定、无编译器重关联与 FMA 收缩。任一假设被打破，界就不再是上界而是空话。考点因此落在“界的前提是否在线上负载中成立”，而非界本身推导。解题路径：先写出界的形式，例如对长度 n 的顺序归约，最坏前向误差满足 |ŝ−s| ≤ γ_{n−1}·Σ|x_i|，其中 γ_k = ku/(1−ku)；再逐条核对假设，把每条假设映射到一个可观测的系统量（编译选项、归约树深度、数据动态范围、并发分块方式），最后判断“相反现象”属于界失效还是负载漂移。

需要调用的公式除上述 γ_k 界外，还有条件数放大因子 κ = Σ|x_i| / |Σx_i|：当正负相消严重时 κ 暴涨，界随之前移，这解释“理论说没问题、线上却超界”的一大类现象。代价维度上，验证假设要付编译时间（检查是否启用 fast-math 与重关联）、显存带宽（复算高精度参考解）、时延（多轮 profile 采样）。例如同一归约 kernel 在关闭 FMA 收缩与开启后，SASS 指令序列不同，误差界对应的 u 取值随之改变，若仍套用旧界即误判。

假设失效信号系统代价
运算次序固定编译器重关联、分块大小随 occupancy 变化编译时间、需固定 launch 配置
数据分布稳定κ 随 batch 内容漂移带宽复算参考解

判断“公式错还是负载变”的工程判据是：在受控输入上重放同一 kernel，若误差仍落在界内则公式无误，线上偏离只能归因于负载或编译路径变化；反之在受控输入上即超界，才怀疑界推导漏项（如忽略分块归约的两级累加）。这一步需要固定 seed 与 launch 参数的对照实验，代价是额外一轮端到端时延，但能把归因从猜测变成可复现证据。
