一 · 拆题干：三个问句其实是三层不同的判断

题干只有一句话，但它压缩了三个必须分别作答的问题，混在一起答就会失焦。第一层是「占用率与延迟隐藏」这对概念在教科书里成立时所依赖的假设集合；第二层是这些假设在什么条件下被打破，也就是「失效」的判据；第三层是线上观测到与理论相反的现象时，如何把「公式错了」与「负载变了」这两种归因区分开。这三层的证据来源完全不同：第一层是体系结构与排队论的前提，第二层是微架构资源约束与访存模式，第三层是测量方法论与因果推断。答题时若把第三层直接写成「重新测一遍」，就等于放弃了这道题真正的考点。

需要立刻点明的是，题干问的是「假设」而不是「公式推导」。占用率本身只是一个比值：活跃 warp 数除以硬件支持的最大 warp 数，即 Occupancy = ActiveWarps / MaxWarps。它不含任何性能承诺。真正承载「占用率越高、延迟隐藏越好」这一因果的是 Little 定律形式的吞吐关系：在稳定状态下，系统中同时在处理的请求数等于到达率乘以平均驻留时间。把它套到 SM 上，就是「在飞 warp 数 ≈ 发射率 × 平均 stall 时长」。这个等式成立需要稳态、需要请求彼此独立可重叠、需要 stall 期间确有别的 warp 可发射。题干问的正是这些前提什么时候不成立。

二 · 考点拆解：命题人想看你区分哪几类东西

这道题的考点可以拆成四组，每组都对应一个容易被含糊过去的边界。

  • 考点 A：占用率的分母与分子分别由什么决定。分母受寄存器文件、共享内存、warp 槽位、block 槽位共同约束，取最紧的那一个；分子是实际驻留的 warp，受调度器分配策略与尾部效应影响。把「理论占用率」当成「实际占用率」是常见错误。
  • 考点 B：延迟隐藏的两种机制——指令级并行（ILP，同一 warp 内多条独立指令重叠）与线程级并行（TLP，多 warp 轮转）。占用率只作用于 TLP。若内核本身 ILP 很高，低占用率仍可隐藏延迟；反之高占用率也可能因依赖链过长而空转。
  • 考点 C：瓶颈迁移。占用率提升会同时抬高对寄存器、共享内存、L1/L2 带宽、DRAM 带宽的需求。当瓶颈从「发射槽空闲」迁移到「带宽饱和」时，继续加占用率不再带来收益，甚至因缓存抖动而变差。
  • 考点 D：测量口径。线上「相反现象」可能来自采样窗口、时钟频率波动、同卡多进程干扰、输入分布漂移，而非公式本身。归因必须先排除测量伪影。

这四组考点的共同结构是：每一个「占用率→性能」的论断，都隐含一个「其他条件不变」的从句。答题的核心动作就是把那些从句逐条写出来并检验。

三 · 解题路径：从假设清单到可证伪的判据

推荐路径是「列假设—找反例—定判据—设计区分实验」，四步递进，不要跳步。

第一步，把延迟隐藏的成立条件写成一张可检验的清单。至少要覆盖：稳态（内核运行时长足够长，启动与收尾的瞬态可忽略）；warp 独立性（不同 warp 之间无长时同步、无屏障串行化）；资源不冲突（warp 增多不引起寄存器溢出到本地内存、不引起共享内存 bank 冲突加剧）；瓶颈不在存储层级（DRAM 或 L2 带宽未饱和）；调度器能真正轮转（warp 处于 eligible 状态而非全部卡在同一屏障或同一长延迟指令上）。

第二步，为每条假设构造反例场景。例如屏障密集的内核中，所有 warp 在同一 __syncthreads() 处排队，此时增加占用率只是让更多 warp 一起等，TLP 无法转化为重叠；又如寄存器压力接近上限时，编译器为降低占用率反而减少 spill，性能提升，这与「占用率越高越好」方向相反。

第三步，把「失效」翻译成可观测的判据。判据不能是「性能没提升」这种模糊表述，而应落到计数器上：SM 的 issue slot 利用率、warp 处于 eligible 但因无发射槽而等待的比例、DRAM 吞吐占峰值比例、L2 命中率随占用率变化的斜率。若占用率上升而 issue 利用率不升、DRAM 吞吐已接近峰值，则瓶颈迁移成立。

第四步，设计能区分「公式错」与「负载变」的实验。关键手法是控制变量：固定内核与输入形状，只改占用率（通过 launch bounds 或共享内存占用调节），观察性能曲线形状；再固定占用率，只改输入分布（如序列长度、稀疏度、batch 组成），观察同一占用率下性能是否漂移。若前者曲线单调但线上相反，说明负载变了；若前者曲线本身就非单调，说明公式的适用域被越过。

$$\text{Speedup} \approx \frac{\min(\text{Occupancy},\,1)\cdot W_{\text{issue}}}{\text{StallCycles per Warp}}\quad\text{仅在 } BW_{\text{used}} < BW_{\text{peak}} \text{ 时成立}$$

这条式子不是精确模型，而是把假设显式化的工具：分子代表可发射的并行度，分母代表单 warp 的平均停顿，右侧的不等式就是「瓶颈不在带宽」这一从句。写答案时把它作为假设清单的锚点，比背诵占用率定义有用得多。

四 · 需要调用的公式与它们的适用边界

本题至少要调用三组公式，且必须说明每组在什么条件下失效。

其一是占用率约束式。给定每线程寄存器数 R、每 block 线程数 T、每 SM 寄存器总量 R_max、共享内存 S 与 S_max，可驻留 block 数受 ⌊R_max/(R·T)⌋ 与 ⌊S_max/S⌋ 及 warp/block 槽位上限共同约束，取最小值。这条式子的失效点是：它算的是「上限」而非「实际」，且未考虑分配粒度（寄存器按 warp 对齐分配、共享内存按块对齐），粒度损失会让理论值系统性偏高。

其二是 Little 定律的 SM 版本：在飞 warp 数等于发射率乘以平均 stall 时长。失效条件是稳态被打破——内核太短、存在全局屏障、或存在跨 kernel 依赖时，系统不在稳态，等式两边不可比。

其三是 roofline 判据：可达算力为 min(峰值算力, 带宽 × 算术强度)。当算术强度低时，性能由带宽决定，此时占用率的作用被带宽上限截断。这条式子的失效点是它假设带宽可被充分利用，而实际带宽利用受访存合并度、bank 冲突、TLB 命中影响，占用率过高反而可能降低合并度。

公式回答的问题失效触发条件代价维度
占用率约束式最多能驻留多少 warp分配粒度、实际调度偏差寄存器/共享内存占用
Little 定律并行度能否转化为吞吐非稳态、屏障串行化时延与尾延迟
Roofline瓶颈是否已迁移到带宽合并度差、缓存抖动DRAM 带宽

三组公式的联合使用方式是：先用约束式算出理论上限，再用 Little 定律判断该上限能否兑现为吞吐，最后用 roofline 判断兑现后的吞吐是否已撞上带宽墙。任何一步的假设不成立，结论就不能直接搬到线上。

五 · 一个具体例子：屏障密集内核的反向现象

设想一个分块归约内核，每个 block 内多轮 __syncthreads()，每轮之间只有少量计算。按占用率公式，减小共享内存占用可以提高每 SM 驻留 block 数，理论占用率上升。但实测性能下降。原因不是公式算错，而是公式的隐含假设「warp 彼此独立可重叠」被打破：屏障把所有 warp 对齐到同一时间点，增加 block 数只是让更多 warp 在同一屏障处排队，eligible warp 数在屏障前后骤降，TLP 无法转化为发射槽填充。此时正确的判据是观察「因屏障等待而不可发射的周期占比」随占用率的变化，若该占比同步上升，则失效归因于负载结构而非公式。

这个例子的工程价值在于它给出了区分方法：把内核换成无屏障版本、保持相同占用率，若性能随占用率恢复单调，则原现象由负载（屏障）引起；若仍非单调，则需怀疑公式中的资源约束项被粒度损失扭曲。代价方面，屏障密集内核的尾延迟对占用率更敏感，因为最后一个 block 的收尾时间被拉长，这在线上表现为 P99 时延恶化而平均吞吐不变——只看平均吞吐会误判为「公式错了」。

六 · 归因框架：把「相反现象」拆成可判定的分支

线上出现相反现象时，建议按以下顺序排除，每一步都有明确的判定信号。

  • 先排除测量伪影：采样窗口是否覆盖了内核启动瞬态；同卡是否有其他进程争用；时钟是否因功耗墙降频。信号是同一配置多次测量方差过大。
  • 再确认负载是否漂移：输入形状、batch 组成、稀疏度是否与离线基准不同。信号是固定占用率下性能随输入分布系统性变化。
  • 然后检验瓶颈是否迁移：DRAM 吞吐占峰值比例、L2 命中率、issue 利用率三者随占用率的斜率。信号是占用率升而 issue 利用率平、带宽接近饱和。
  • 最后才怀疑公式适用域：检查是否存在屏障串行化、寄存器 spill、分配粒度损失。信号是把占用率作为唯一变量做扫描时曲线本身非单调。

这个顺序的依据是：测量伪影与负载漂移的排查成本低且能解释大多数「相反现象」，而公式适用域的越界需要构造受控实验才能确认。把顺序倒过来，容易把负载变化误判为理论破产。工程判断上，只要占用率扫描曲线在受控条件下仍单调，就应优先归因于负载；只有当受控扫描本身呈现非单调，才需要回到假设清单逐条检验，并考虑把公式替换为带屏障项或带宽项的分段模型。

先拆题干：这道题问的不是占用率公式本身，而是它的适用边界

题干里“在什么假设下失效”与“线上相反现象怎么归因”是两问共用一条证据链：前者要求把占用率—延迟隐藏模型还原成一组可逐条检验的前提，后者要求用线上可观测的量去判定是哪条前提被负载打破了。拆题时先做三件事：把“理论”写成显式不等式，把“相反现象”定义为与不等式预测方向相反的观测，把“公式错了/负载变了”翻译成两类可区分的残差来源。解题路径是：写出隐藏条件→列出前提清单→为每条前提指定一个可测代理量→给出归因判据。需要调用的公式是延迟隐藏的吞吐上界形式，即有效吞吐不超过“在飞访存字节数除以访存延迟”与峰值带宽的较小者：

$$\text{Throughput}_{\text{eff}} \le \min\left(\text{BW}_{\text{peak}},\ \frac{\text{Bytes}_{\text{in-flight}}}{\text{Latency}_{\text{mem}}}\right),\quad \text{Bytes}_{\text{in-flight}} \approx \text{Occupancy}\times \text{Per-thread MLP}\times \text{Access Size}$$

这条式子暴露了三个被“占用率越高越好”这句话吞掉的假设：单线程访存并行度（MLP）与占用率可独立调节；访存延迟对在飞请求数不随占用率上升而恶化；以及被隐藏的延迟确实是瓶颈延迟而非指令发射或同步延迟。任一假设不成立，占用率与吞吐的单调关系就断掉。举例：一个以共享内存广播为主的 kernel，提高占用率只是增加同一 SM 上争用同一 bank 的 warp 数，在飞字节数几乎不增，吞吐反而因 bank 冲突与调度抖动下降——这正是“公式没错、负载的瓶颈项换了”的典型形态。

归因判据要落到代价上。判断“公式错了”需要看到在受控条件下（固定负载、仅改占用率）预测与实测系统性偏离，且偏离不能用任何一条前提的代理量解释；这类验证要付出编译与 profiling 的迭代成本，每轮改动都要重跑 NCU 采集，时间开销以小时计。判断“负载变了”则要求线上出现至少一个前提代理量的显著漂移，例如每线程 MLP 下降、L2 命中率结构改变、或同步/屏障等待占比上升；采集这些量本身要占用带宽与片上计数器资源，采样过密会扰动被测负载。表格给出判据的最小集合：

观测指向公式错指向负载变
仅改占用率、预测单调而实测反向是否
MLP 或访问粒度代理量漂移否是
偏离随负载版本切换而出现/消失否是

解题时不要急着给结论，而要把“占用率”这个自变量拆成可独立操纵的量：寄存器上限、shared memory 配额、block 尺寸三者共同决定占用率，但它们同时改变 MLP 与同步频率，因此单变量实验在设计上就存在混淆。正确路径是先固定 block 尺寸与每线程工作量，只通过寄存器压力或 smem 配额调占用率，再观察吞吐是否落在上式预测的 min 分支上；若落在带宽分支，占用率本就不是有效杠杆，反向现象不构成对公式的反驳。这一节只完成拆题与判据搭建，具体到“哪类 kernel 的哪条前提最先崩”留给下一节按负载族展开。
