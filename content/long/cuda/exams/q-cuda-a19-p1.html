一 · 题干不是需求文档：把自然语言压成可判定的约束集

一次 kernel 生成任务的输入通常是一段混合了三种东西的自然语言：算子语义（要算什么）、性能意图（要多快、在什么形状上快）、以及隐含的验收口径（怎么算对）。问题驱动诊断式优化的第一步不是写代码，而是把这三者分离成可判定的约束集。判据是：每条约束都能被一个具体的检查动作消费——要么是正确性 oracle 的一条断言，要么是 profiler 的一个计数器阈值，要么是编译期的一个静态属性。不能落到检查动作上的句子，一律标记为“未定”，进入待澄清队列，而不是让模型自行脑补。

具体机制上，把题干拆成四张表：张量契约表（dtype、layout、stride 是否连续、是否允许原地写、广播语义）、形状域表（哪些 shape 是评测会扫的、是否有动态维度、是否有极端小 shape）、数值契约表（累加精度、是否允许 TF32、归约顺序是否影响结果、NaN/Inf 传播规则）、性能口径表（测的是端到端还是单 kernel、是否含 launch 开销、bandwidth 还是 latency 主导）。四张表的并集就是考点的载体：任何一个空单元格都是一个必须被诊断的考点。

代价在这里已经发生：读题阶段消耗的是 token 与人工澄清轮次。把题干拆成四张表，通常要多花一轮模型调用（或多一次人工确认），换来的是后续少掉一整轮“生成—编译—跑错—重写”的循环。以一次 kernel 生成动辄数十秒编译加数秒基准运行为计，读题阶段多花的 token 是廉价的，而一次错误方向的实现迭代是昂贵的。反过来，若跳过拆解直接生成，模型会默认 PyTorch 语义（连续 layout、fp32 累加、无广播），这些默认值在评测形状上往往正好是错的。

一个具体例子：题干写“实现一个 softmax，要求在大词表上快”。拆解后应得到——语义约束：沿最后一维归约、数值稳定需减最大值；形状域：评测会扫 vocab 从数百到数十万，且存在 batch=1 的行向量；性能口径：这是 memory-bound，评价指标是有效带宽而非 FLOPs；隐含考点：单行长度超过一个 block 能覆盖的范围时，需要多 pass 或 online softmax。这些都不是“答案”，而是把“快”翻译成“在哪个 roofline 位置上快”。

二 · 考点识别：把约束集映射到已知的性能瓶颈类别

拆完题干后，第二步是给每个约束打上瓶颈标签。这一步的输出不是代码，而是一张“考点—瓶颈—证据”的三元组清单。瓶颈类别应当收敛到有限几种，否则诊断无法复用：访存受限（有效带宽接近峰值）、计算受限（受限于 FMA 吞吐或特殊函数单元）、延迟受限（并行度不足、occupancy 低、尾效应）、同步受限（跨 block 归约、原子操作、grid sync）、编译受限（寄存器压力导致 spill、unroll 失败、模板实例化爆炸）。每一类都对应一组可观测证据，例如访存受限看 DRAM throughput 占比与 sector 效率，延迟受限看 achieved occupancy 与 warp stall 原因分布。

公式层面，考点识别要落到可算的量上。对访存受限算子，先算算术强度：

$$I=\frac{\text{FLOPs}}{\text{Bytes moved}},\qquad P_{\text{bound}}=\min\left(P_{\text{peak}},\, I\cdot B_{\text{peak}}\right)$$

把 I 与机器平衡点（峰值算力除以峰值带宽）比较，就能判定该考点是否根本不该优化计算部分。对归约类算子，要算通信下界：若一次归约需要 log 级或两阶段的跨 block 合并，则额外的一次全局读写就是不可省的成本，考点应落在“能否用单 pass online 方法消掉中间张量”上，而不是“能否把循环展开得更漂亮”。

代价体现在诊断精度与诊断开销的权衡上。给每个考点都跑一次完整 NCU profile 是准确的，但一次采集会带来可观的运行时扰动（多 pass 重放、时钟锁定），在候选实现多的时候成本线性叠加。工程判断是分层：先用静态分析（看生成的 PTX/SASS 里有无 spill、有无 shared memory bank 冲突模式、循环是否被展开）做零成本筛查，只对通过静态筛查仍无法归类的候选付一次 profile 的钱。静态筛查的代价是编译时间与反汇编阅读的 token；profile 的代价是运行时与采集配置的复杂度。

具体例子：一个 layernorm 题干要求“支持 hidden 从 256 到 8192”。考点识别应产出两条不同路径——hidden 较小（单 block 可覆盖一行）时，考点是访存合并与 warp 内归约的 shuffle 次数；hidden 很大时，考点变成两阶段归约的中间缓冲写回带宽，以及是否值得用 persistent kernel 摊掉 launch 开销。同一句题干，两个形状域对应两个互斥的优化方向，若不在读题阶段分开，生成的实现会在其中一个域上系统性劣化。

三 · 解题路径：从考点清单到可执行的实验序列

第三步是把考点清单排成一条有依赖关系的实验序列，而不是一张待办列表。路径的组织原则是：先用最便宜的实验排除整类假设，再逐步收紧。典型序列为——(a) 正确性基线：用最朴素的实现（哪怕慢）建立 oracle，确认语义理解无误；(b) 形状扫描：在形状域表的边界点上跑基线，记录时延随形状的变化曲线，识别是否存在分段行为（分段点往往就是考点切换点）；(c) 瓶颈归类：对分段后的每一段做静态筛查加一次定向 profile；(d) 定向改写：只针对已确认的瓶颈做单点改动，每次改动后重跑同一组形状，形成差分。

这条路径的关键机制是“单变量差分”。每次改写只动一个决策（例如只改 tile 大小，不改归约策略），否则性能变化无法归因，诊断退化为猜测。伪代码思路如下：

  • 对每个候选实现 h，记录三元组 (shape, latency, counters)；
  • 若 latency 变化超过噪声带而 counters 未变，判定为调度/尾效应类；
  • 若 counters 中 DRAM 吞吐上升而 latency 未降，判定为已触及带宽上限，停止该方向；
  • 若出现 spill 或 occupancy 下降，判定为编译受限，回退该改写。

代价在这条路径上是复合的：正确性基线本身可能很慢（朴素实现可能是最优实现的数十倍时延），形状扫描的点数直接乘以单次运行时间，profile 采集再乘一层。因此路径设计要控制“实验预算”：形状域表不应穷举，而应取分段边界加少量内部点；差分实验应复用同一份输入张量分配，避免把分配开销混进时延。另一个常被忽略的代价是编译时间——模板化实现每改一个 tile 参数就触发一次重编译，若路径中安排了十几次参数扫描，编译时间可能超过实际运行时间，此时应改用运行时参数或 JIT 缓存策略。

具体例子：题干要求“实现一个 GEMM，M/N/K 在评测中从 128 到 4096 变化”。路径不应是“先写一个 tiled GEMM 再调参”，而应是先用 cuBLAS 或一个朴素实现建立每个形状的参考时延，找出小 M（瘦长矩阵）与大 M 的行为分界；在小 M 段，考点是 tile 划分导致的尾块浪费与 occupancy，路径指向“按 M 分块并允许 K 方向 split”；在大 M 段，考点转为 shared memory 带宽与寄存器分块，路径指向“增大每线程累加器数量”。两条路径的实验预算独立核算。

四 · 需要调用的公式：把“快”变成可比较的数

解题路径上每一步都要有可比较的量化锚点，否则“优化了”只是主观判断。最常用的三个锚点是：有效带宽、有效算力、以及相对 roofline 的位置。对一次 kernel，若测得时延 t、搬运字节数 B、浮点运算数 F，则：

$$B_{\text{eff}}=\frac{B}{t},\qquad F_{\text{eff}}=\frac{F}{t},\qquad \eta=\frac{\max(B_{\text{eff}}/B_{\text{peak}},\,F_{\text{eff}}/P_{\text{peak}})}{1}$$

η 接近 1 表示已贴近该机器上该算子的 roofline，继续微调 tile 的边际收益迅速衰减，此时应把预算转向算法层改写（减少搬运字节数或减少运算数），而不是指令层调优。这个判断本身就是诊断的一部分：它告诉你“该停止在哪”。

对归约与扫描类算子，还要调用一个通信量下界公式来判定中间张量是否可省。若输入元素数为 N、每元素 s 字节，单 pass 方案的下界是读 N·s 加写输出；两 pass 方案则额外引入一次中间写与一次中间读，代价约为 2N·s 量级。当 N 很大时，这个差额直接体现在有效带宽上，成为区分“看起来并行度很高”与“真的少搬了数据”的判据。

代价维度上，公式给出的是理想上界，而实际达成率受三个具体开销侵蚀：launch 开销（小 shape 时占比可达主导）、尾块浪费（形状不能被 tile 整除时的空转）、以及同步开销（跨 block 归约的屏障等待）。因此公式的用途不是宣布“达到了百分之多少”，而是定位差距属于哪一类开销。例如 η 明显低于 1 但 DRAM 吞吐已高，差距应归因于尾效应或 launch，而非访存模式。

具体例子：一个向量加法的题干，F 很小而 B 很大，I 远低于平衡点，公式直接判定为访存受限，任何增加计算复杂度的改写（例如手工向量化以外的技巧）都不该进入路径。反之，一个含 exp 的算子，特殊函数单元的吞吐可能成为实际瓶颈，此时 Feff 应按特殊函数吞吐而非 FMA 吞吐折算，否则 η 会被高估，导致误判为“已接近 roofline”而过早停止优化。

五 · 读题阶段的失败模式：错题比错代码更贵

把读题与考点拆解独立成一步，是因为这一阶段的错误具有放大性：一个错误的考点判断会让后续所有生成、优化、验证都朝着错误方向收敛，而且验证阶段未必能发现——实现可能是正确的，只是在错误的维度上被优化。典型失败模式有三类。其一是语义默认值错配：把非连续 stride 当作连续、把 fp32 累加当作可换成 fp16、把确定性归约顺序当作可重排，这些在正确性 oracle 上会以偶发的不一致暴露，排查成本极高。其二是形状域误判：只按题干里出现的示例形状优化，忽略评测会扫的边界形状，导致在极端 shape 上出现尾块灾难或 occupancy 崩塌。其三是性能口径错配：把端到端时延当成单 kernel 时延来优化，结果优化了 kernel 却被人为的同步或拷贝开销吃掉收益。

对抗这三类失败的具体机制是“可证伪的读题产出”。读题阶段的输出应当包含至少一条能被后续实验直接证伪的预测，例如“该算子在 hidden=8192 时应为访存受限，有效带宽应接近峰值的一个较高比例；若实测明显偏低，则说明存在未被识别的额外搬运”。有了这条预测，验证阶段就不只是“跑通”，而是“跑通并检验读题假设”。这条预测的代价很低（一句话），但它把读题从主观理解变成了可检验的工程假设。

另一项代价是 token 预算的分配。多轮 agent 流程中，读题阶段若占用过多上下文（把题干逐字复述、把四张表写得过细），会挤压后续生成与诊断的上下文空间，导致模型在改写阶段丢失关键约束。工程判断是：四张表只保留会被检查动作消费的条目，其余压缩为一句“未定项清单”，并在每次改写前重新注入最关键的 3 至 5 条约束，而不是整表重贴。

具体例子：题干写“实现一个 attention 的前向，要求支持变长序列”。若读题阶段把“变长”简单理解为“加一个 mask”，考点就会被误判为访存合并；实际考点是序列长度不均导致的负载不均与尾效应，解题路径应指向按序列长度分桶或 persistent 调度，而非 mask 的位运算优化。这个误判不会让实现跑错，但会让优化完全落空——这正是读题阶段必须独立成步的理由。

六 · 从约束集到诊断假设的交接物

读题与考点拆解的终点不是一份“理解”，而是一份可交接的诊断假设清单：每条假设包含约束来源、瓶颈标签、预期证据、以及若被证伪时应转向的备选方向。这份清单是后续生成与优化阶段的输入契约——生成阶段据此选择实现骨架（例如访存受限则优先保证合并访问与足够在飞请求，计算受限则优先保证指令级并行与寄存器分块），优化阶段据此决定先动哪个旋钮。没有这份交接物，生成阶段只能按训练分布里的“常见写法”出牌，诊断就退化为对既有偏见的重复确认。

交接物的粒度要控制在可执行的层面：一条假设对应一个可观测计数器或一个可测时延差分，而不是一个抽象判断。例如“该 kernel 在小 batch 下受 launch 开销主导”应写成“当 batch 低于某分段点时，时延不随 batch 线性下降，且 kernel 自身时延占比低于端到端时延的显著比例”，这样后续只要跑一次分段扫描就能确认或否定。粒度太粗的假设无法被单次实验消费，粒度太细的假设则让清单膨胀到无法在上下文里维持。

代价上，这份交接物本身消耗的是结构化输出的 token 与一次人工或自动的合理性检查；它换来的是生成阶段的搜索空间收缩。把候选实现从“任意写法”收缩到“符合瓶颈标签的写法”，等价于在生成前就砍掉了大量必然失败的候选，省下的是编译时间与基准运行时间——这两项在多轮流程里是真正的稀缺资源。工程判断是：宁可让交接物少而硬（每条都能被一次实验证伪），也不要多而软（每条都正确但无法指导下一步动作）。

具体例子：一个题干要求“在给定显存预算下实现一个大矩阵的原地转置”。读题产出应包含一条硬假设：该算子受写模式导致的非合并访问支配，证据是 sector 效率偏低而 DRAM 吞吐未达峰；备选方向是分块转置加 shared memory 中转以恢复写合并。这条假设直接决定了生成阶段是否引入 shared memory tile，以及 tile 尺寸的选择依据是 bank 冲突而非寄存器压力。至此，读题阶段交出的不是答案，而是一个能被下一步直接消费、也能被一次 profile 直接推翻的工程判断。
