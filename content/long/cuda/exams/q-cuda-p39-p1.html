一 · 题干的三层结构：从“迁移失效”反推考点

题干表面问的是“跨硬件、跨 shape、跨 dtype 迁移时最可能在哪里失效”，但它实际上把三个独立维度压进了一个问句：硬件维度（SM 架构、寄存器文件、L2 容量、内存带宽比）、shape 维度（M/N/K 的整除关系、tile 边界、batch 规模）、dtype 维度（fp32/fp16/bf16/fp8 的累加精度、指令吞吐、向量化宽度）。三者不是并列的，而是通过 LEAP 的核心机制——自适应剪枝（adaptive pruning）产生的环境反馈——耦合在一起。因此读题的第一步不是回忆 LEAP 的摘要，而是识别出题干在问：当反馈信号本身随环境漂移时，剪枝策略的判据是否还成立。

考点可拆为四个层次。第一层是机制层：LEAP 用环境反馈（编译是否通过、运行是否正确、profile 是否达标）来剪掉低价值的候选 kernel 或低价值的反馈通道，从而降低 RL 的 rollout 成本。第二层是判据层：剪枝依赖某个打分函数，该函数必然含硬件相关量（如实测时延、带宽利用率）与 shape 相关量（如有效 FLOPs）。第三层是分布层：RL 的策略在训练分布上收敛，迁移即分布偏移。第四层是验证层：题干要求“验证方案与回退条件”，意味着答案必须包含可执行的判别实验与明确的放弃阈值，而不是定性判断。

解题路径因此是：先定位 LEAP 中哪一处引入了环境相关量，再论证该量在迁移时如何改变剪枝决策的排序，最后设计一个能把这三种偏移分离的实验矩阵。需要调用的公式集中在三处：roofline 的算术强度判据、剪枝打分的加权形式、以及正确性 oracle 的误差传播界。

二 · 剪枝判据里的环境耦合项：失效点的形式化定位

LEAP 的自适应剪枝若写成可分析的形式，其打分函数大致是“收益/成本”之比：收益来自候选 kernel 相对基线的加速比，成本来自生成与验证该候选所消耗的 token 与时延。关键在于，加速比不是策略网络的内部量，而是由真实硬件实测或由模型预测得到的量。设候选 $k$ 在环境 $e$ 下的打分为

$$ S(k,e)=\frac{\hat{a}(k,e)}{c_{\text{gen}}(k)+\lambda\, c_{\text{val}}(k,e)},\qquad \hat{a}(k,e)=\frac{T_{\text{base}}(e)}{T_k(e)} $$

其中 $T_{\text{base}}(e)$ 是基线时延，$T_k(e)$ 是候选时延，$c_{\text{val}}$ 是验证成本（编译时间、正确性检查、profile 采集），$\lambda$ 是权重。剪枝即保留 $S$ 排名靠前的候选。失效的第一现场就在这里：$T_k(e)$ 对硬件、shape、dtype 都敏感，而 $c_{\text{val}}$ 对编译时间与 profile 采集开销敏感。当环境从 $e_{\text{train}}$ 切到 $e_{\text{test}}$ 时，$\hat a$ 的排序可能整体翻转，导致被剪掉的恰是新环境下最优的候选——这是剪枝误杀，而非策略网络本身的泛化失败。

第二个耦合项是 roofline 判据。若 LEAP 用算术强度来决定是否值得为某候选付出验证成本，则

$$ I=\frac{\text{FLOPs}}{\text{Bytes}},\qquad P_{\text{bound}}=\min\left(P_{\text{peak}},\; I\cdot B_{\text{mem}}\right) $$

跨硬件迁移时 $P_{\text{peak}}$ 与 $B_{\text{mem}}$ 的比值改变，同一个 kernel 会从 compute-bound 滑向 memory-bound，其“值得优化”的结论随之改变。跨 dtype 时，fp16 的峰值吞吐通常是 fp32 的数倍而带宽不变，$I$ 的有效值因向量化与累加精度要求而变化；bf16 与 fp8 还引入累加器精度问题，使正确性 oracle 的容差必须重设。跨 shape 时，当 M 或 N 不能被 tile 整除，边界 tile 的利用率下降，实测 $T_k$ 相对理论值的偏离被放大，$\hat a$ 的方差上升，剪枝排序更不稳定。

代价是明确的：剪枝误杀的直接代价是搜索空间被不可逆地缩小，RL 在后续轮次中无法再采样到被剪掉的候选，等效于把探索预算花在了错误的子空间上；间接代价是验证成本 $c_{\text{val}}$ 的浪费——被保留的候选在新环境下仍需编译与 profile，而编译时间在跨架构时（不同 SM 版本、不同指令集可用性）显著上升。一个具体例子：某候选在训练硬件上因高占用率（occupancy）取得加速，被剪枝判据判为高价值；迁移到寄存器文件更小或 shared memory 更紧张的硬件上，同一候选因寄存器溢出（spill）导致时延反超基线，但此时它已被保留并消耗了多轮验证预算，而真正适配新硬件的低占用率候选早已在早期轮次被剪掉。

三 · 正确性 oracle 在 dtype 迁移下的失效路径

题干把 dtype 单列，是因为正确性 oracle 的判据本身是 dtype 相关的。若 oracle 采用逐元素相对误差判据 $\|y-\hat y\|/\|y\|\le \tau$，则 $\tau$ 的合理取值随累加精度变化：fp32 累加与 fp16 累加的舍入误差量级不同，fp8 还涉及缩放因子（scale）的选择。设累加长度为 $K$，浮点累加的相对误差上界粗略随 $\sqrt{K}\cdot u$ 增长（$u$ 为单位舍入误差），则

$$ \tau_{\text{req}}\gtrsim \sqrt{K}\cdot u_{\text{acc}},\qquad u_{\text{fp16}}\gg u_{\text{fp32}} $$

若 LEAP 在训练时用 fp32 校准出的 $\tau$ 去验证 fp16 候选，oracle 会把数值上完全合法的 kernel 判为错误，剪枝随即把这些候选归入低价值通道——这是假阴性导致的剪枝，与上一节的误杀机制不同：前者是打分排序翻转，后者是二值判据错判。假阴性的代价是双重的：一方面正确候选被丢弃，另一方面 RL 收到错误的负奖励，策略被推向规避合法的低精度实现，从而在 dtype 迁移时系统性丧失 fp16/bf16 路径的探索能力。

验证方案应把 dtype 偏移做成受控变量：固定 shape 与硬件，仅切换 dtype，比较同一批候选在两种精度下的 oracle 判定与实测时延，观察判定翻转率与 $\hat a$ 的秩相关。若翻转率超过预设阈值，说明 $\tau$ 未随 dtype 重标定，回退条件即为“在切换到新 dtype 前必须重估 $\tau$ 并重跑一轮校准集”。这里不需要编造具体阈值数字，工程判断的依据是翻转率是否已使剪枝排序的 Kendall 秩相关系数降到不可用区间——秩相关是比绝对误差更稳健的判据，因为它直接对应剪枝所依赖的排序。

四 · 跨 shape 迁移：tile 边界与验证成本的放大

shape 迁移的失效点不在大 shape，而在边界与不规则 shape。GPU kernel 的性能对整除关系极度敏感：当 M、N、K 是 tile 尺寸的整数倍时，流水线无尾块，实测时延接近 roofline 预测；当存在尾块时，最后一个 tile 的有效计算占比下降，且 predicate 与分支引入额外指令。设 tile 尺寸为 $b$，则尾块利用率近似为

$$ \eta=\frac{MN}{b^2\left\lceil M/b\right\rceil\left\lceil N/b\right\rceil} $$

$\eta$ 在训练 shape 上接近 1，在迁移 shape 上可能明显小于 1。LEAP 的剪枝若以实测加速比为依据，则在不规则 shape 上，所有候选的 $T_k$ 都被尾块开销污染，$\hat a$ 的区分度下降，剪枝退化为近似随机——这不是剪枝判据错了，而是信号被噪声淹没。此时保留更多候选反而更优，因为排序不可信。代价体现在验证预算：为不可信排序付出更多 $c_{\text{val}}$，编译与 profile 次数上升，RL 的每轮 wall-clock 时延增加。

具体例子：训练集以 4096×4096 的方阵为主，候选普遍采用 128×128 tile；迁移到 M=4097、N=4096 的 shape，尾块只占一行，但该行的 predicate 开销与不合并访存使实测时延偏离预测，导致两个候选的排序互换。验证方案是构造一组“整除/非整除”配对的 shape，固定硬件与 dtype，测量同一候选集合的排序稳定性；若排序在配对间不可复现，回退条件是把剪枝判据从“绝对加速比排序”切换为“相对基线的分组排序”，即按 shape 类别分组后再剪枝，避免跨类别比较。

五 · 跨硬件迁移：编译时间与 profile 可得性作为隐性变量

硬件迁移最容易被忽略的失效点是 $c_{\text{val}}$ 中的编译时间与profile 可得性。不同 SM 架构对指令的支持不同，同一份 CUDA C++ 或 Triton 源码在新架构上可能触发不同的编译路径、不同的寄存器分配结果，编译时间随之变化；NCU 采集的指标集与采样开销也随架构与驱动而变。若 LEAP 的剪枝把“验证成本低”作为保留候选的理由，则在新硬件上这一理由可能不再成立：编译更慢、profile 更贵，导致本应保留的高价值候选因成本项过大而被剪掉。

更隐蔽的是反馈通道的失效：LEAP 的自适应剪枝会剪掉“低信息量”的反馈通道（例如某类 profile 指标在多数候选上无区分度）。跨硬件后，原本无区分度的指标可能变得有区分度（如 shared memory bank conflict 相关指标在新架构上权重上升），而原本有区分度的指标可能饱和。剪枝通道的判据是基于训练硬件上的信息增益估计的，迁移后信息增益的排序改变，被剪掉的通道恰是新硬件上最需要的诊断信号。代价是 RL 在迁移后失去定位瓶颈的能力，只能收到粗粒度的通过/失败信号，样本效率下降。

验证方案需要把“反馈通道”当作可观测对象：在新硬件上对一小批固定候选采集全量 profile，计算各指标与实测时延的互信息或秩相关，与训练硬件上的同一统计量对比。若某被剪通道在新硬件上的秩相关显著上升，回退条件是解冻该通道并重跑剪枝校准，而不是直接沿用训练时的通道集合。工程判断的依据是：剪枝通道的收益来自降低采集开销，而采集开销在迁移后若已不再是瓶颈（例如新硬件的 profile 工具更快），则剪枝通道的收益本身消失，保留全通道反而更划算。

六 · 解题路径的收束：三因子实验矩阵与回退条件的写法

把上述三条失效路径统一起来，解题路径应写成三因子分离实验：硬件、shape、dtype 各取两个水平，构成 2×2×2 的受控矩阵，每个格子上跑同一批候选（数量足以计算秩相关），观测三个量——剪枝保留集合与全量最优集合的交集比例、oracle 判定翻转率、以及单位候选的验证成本。三个量分别对应误杀、假阴性、成本失控三类失效。判据不需要编造数字：交集比例下降与秩相关下降同向即为剪枝判据失效的信号；翻转率上升即为 oracle 未重标定的信号；验证成本上升而保留集合质量不升即为成本项权重 $\lambda$ 失配的信号。

回退条件应写成可执行的分支，而不是“效果不好就回退”。具体形式是：若秩相关低于可用区间，回退到分组剪枝（按 shape 类别或 dtype 分组，组内比较）；若 oracle 翻转率超限，回退到按 dtype 重标定 $\tau$ 并重跑校准集；若验证成本项主导打分，回退到解冻被剪反馈通道或降低 $\lambda$。每条回退都对应一个明确的机制——分组剪枝消除跨类别比较的不可比性，重标定 $\tau$ 消除精度相关的假阴性，解冻通道恢复诊断信号的信息增益。

最后落在工程判断上：LEAP 的剪枝本质是用环境反馈的排序替代全量评估，其正确性前提是排序在目标环境上可迁移。跨硬件、跨 shape、跨 dtype 的迁移失效，几乎都可以归约为“排序的可迁移性”被破坏——要么是打分里的环境量变了，要么是 oracle 的判据变了，要么是反馈通道的信息量变了。因此读这道题的关键不是判断 LEAP 好不好，而是识别出它把哪一部分环境假设写进了剪枝判据，并在迁移时优先验证那一部分。这也是本部分不给答案的原因：答案的形式必须是上述实验矩阵的输出，而不是对摘要的复述。

迁移失效的三条断层线：反馈剪枝的判据漂移

LEAP 的剪枝依据是环境反馈的“信息量”，而信息量本身是硬件与输入的函数，不是 kernel 代码的固有属性。跨硬件迁移时最先崩的是 profiler 反馈的尺度：同一 kernel 在 A 卡上 NCU 报出的 stall 分布与 B 卡不同，剪枝器学到的“哪些反馈值得保留”直接失效，被剪掉的恰好是新硬件上的关键信号。跨 shape 迁移时，失效点落在 occupancy 与 tile 边界的拐点上——小 shape 下 launch 开销与尾块浪费主导反馈，大 shape 下转为带宽饱和，剪枝阈值若按前者标定，就会把后者唯一有效的带宽证据判为冗余。跨 dtype 迁移则卡在吞吐换算：fp32 与 bf16 的峰值算力比不等于实测比，反馈里隐含的“算术强度”判据随 dtype 漂移。

$$\text{keep}(f)=\mathbb{1}\!\left[\frac{\lVert \nabla_\theta \ell(f)\rVert}{\text{cost}(f)}>\tau\right],\quad \text{cost}(f)=t_{\text{prof}}(f)+c_{\text{tok}}(f)$$

上式是剪枝的隐含判据：保留一条反馈的收益是其对策略梯度的贡献，代价是 profile 时延加 token 开销。迁移时分子与分母同时变——新硬件上 t_prof 因计数器复用与 replay 次数上升而膨胀，分子却因反馈分布偏移而缩小，比值整体跌破 τ，剪枝率被动升高，可验证奖励的信号被削薄。验证方案应是分层对照：固定 kernel 与 dtype 只换硬件、固定硬件只扫 shape、固定 shape 只换 dtype，各跑一组“剪枝开/关”的配对实验，看正确性 oracle 通过率与 SOL 利用率的差值是否随迁移维度单调恶化；若关掉剪枝反而更稳，说明判据已漂移。回退条件写成硬阈值：当新配置下被剪反馈中事后被证明影响最终正确性或 SOL 的比例超过保留集的有效比例，即退回不剪枝的全反馈基线，并把 τ 改为按配置在线标定而非全局常数。
