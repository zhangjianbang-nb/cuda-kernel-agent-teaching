一 · 题干拆解：三个必须分开回答的问题

题干把「TRLOO 留一法优势估计」和「搜索预算或上线判断」压在同一句里，这本身就是考点：它要求答题者先证明自己知道 TRLOO 在算什么，再证明自己知道这个量在工程决策链条上被谁消费。拆题干要拆成三层，缺一层就会写成公式默写。第一层是估计对象：TRLOO 估计的是某个采样动作相对于「去掉它之后剩余样本」的优势，而不是相对于一个固定 baseline 的优势。第二层是估计量的构造：留一法意味着对每个样本都要重算一次参照量，因此它是一个 O(n²) 量级的朴素实现，工程上必须问「能不能增量算」。第三层是下游消费方：优势估计进入策略梯度或拒绝采样打分后，会改变候选 kernel 的排序，排序改变搜索预算的分配，分配结果又决定上线判断的置信度。三层对应三种不同的错误：把估计对象说错是概念错，把构造复杂度说错是工程错，把消费方说错是决策错。阅卷时这三层是分开给分的，答题时也应显式分段，让每一层都有独立的落点。

题干的另一个陷阱在「如何影响」四个字。它不是在问 TRLOO 的数值大小，而是在问这个数值的符号与量级如何改变一个离散决策。因此解题路径必须包含一次「从连续估计量到离散判断」的跨越：优势为正说明该样本优于留一参照，为负说明劣于参照，而决策阈值不是零，是由预算约束和风险容忍度共同定出的一个边界。把这一步写清楚，才算回答了题干的后半句。

二 · 考点清单：公式逐项、留一构造、预算映射

考点可以列成一张可核对的清单，答题时逐项打勾，避免漏项。第一项是逐项解释能力：TRLOO 的核心公式里通常出现样本奖励、留一均值、样本数与缩放因子，每一项都要说清它的统计含义与工程来源——奖励来自哪里（正确性 oracle 的通过与否、profile 得到的时延分档），留一均值为什么必须排除自身，缩放因子为什么随样本数变化。第二项是留一构造的等价变形：能写出「全量均值减去自身再除以 n−1」这种 O(1) 更新形式，并指出它与朴素重算在数值上的差异来源（浮点累加顺序、大 n 时的抵消误差）。第三项是方差与偏差的权衡：留一法降低的是自身项对参照量的污染，代价是每个样本的参照量各不相同，组内比较失去共同基准，方差上升。第四项是预算映射：优势估计如何转成「多采几个候选」或「提前停止」的规则。第五项是上线判断：估计量的置信区间宽度如何决定「这一版 kernel 能否替换线上实现」。

这五项里，前两项是公式层，第三项是统计层，后两项是决策层。答题时若只写前两项，得分上限被压在公式复述档；若只写后两项而不给公式，则无法证明估计量确实产生了那个符号。正确路径是「公式 → 变形 → 方差代价 → 决策规则」的单向链条，每一环都用上一环的输出作为输入。

三 · 解题路径：从符号到阈值的四步

给出可执行的解题路径，四步，每步都有明确的产出物。第一步，写出 TRLOO 的优势表达式并逐项标注。产出物是一张「符号—含义—来源」的对照表，至少覆盖样本奖励、留一参照、样本数、缩放系数四行。第二步，把留一参照改写成增量形式，产出物是一段伪代码思路：先累加全量和与全量平方和，再对每个样本做减法得到留一统计量；这一步要顺带说明为什么不能直接对每个样本重跑一遍循环。第三步，讨论该估计量的方差随样本数的变化方向，产出物是一个定性判断加一个代价陈述：样本数增大时留一参照更稳，但每轮搜索的候选评估次数线性上升，编译与 profile 的时延随之上升。第四步，把优势符号映射为预算动作与上线判断，产出物是一条规则：优势超过正阈值则追加预算继续搜索，落在死区则维持当前候选集，低于负阈值则淘汰该候选并回收预算。

四步之间的关系是单向依赖：第二步的增量形式决定了第三步能否在预算内完成，第三步的方差判断决定了第四步的阈值该宽还是该窄。答题时把这层依赖写出来，比单独罗列四个步骤更能体现工程判断。需要调用的公式集中在第一步和第二步：优势定义式、留一均值式、增量更新式。第三步只需要方向性结论，不需要闭式方差；第四步需要的是一个不等式形式的阈值规则，而不是精确的最优阈值。

$$\hat{A}_i = r_i - \frac{1}{n-1}\sum_{j \neq i} r_j,\qquad \mu_{-i}=\frac{S-n\,r_i}{n-1}$$

上式左半是优势定义，右半是留一均值的增量写法，其中 $S$ 为全量奖励和。两式合起来就是第一、二步的全部公式需求；答题时若把 $S$ 的维护方式说清楚（每加入一个样本做一次加法），就已经覆盖了增量构造的考点。

四 · 逐项含义与一个具体算例的入口

逐项解释要落到工程语义上，而不是统计教科书语义。$r_i$ 是第 $i$ 个候选 kernel 的标量奖励，它的构造通常是把正确性通过与否、相对基线时延、以及 profile 得到的资源占用压成一个数；这一项的考点是「奖励必须是可复现的标量」，否则留一法失去意义。$\mu_{-i}$ 是排除自身后的组内均值，它承担 baseline 的角色，考点是「为什么不能用全量均值」——用全量均值会让自身项同时出现在被减数与减数里，优势被系统性压缩，组内排序失真。$n-1$ 这个分母是留一法的标志，考点是「样本数为 1 时公式退化」，此时留一参照无定义，必须走单独分支。缩放系数在部分写法里以 $n/(n-1)$ 形式出现，作用是补偿留一均值与全量均值之间的尺度差，考点是「缩放不改变符号，只改变量级」，因此对预算决策的符号判断无影响，但对阈值标定有影响。

具体算例的入口应当这样设计：给定一组候选 kernel 的奖励序列，先算全量均值，再对其中一个候选算留一均值，比较两者差值，观察优势符号是否因「是否留一」而翻转。翻转是最有信息量的情形，因为它直接证明留一法不是形式上的修饰。算例还要带一个预算参数：当前剩余搜索预算允许再评估多少个候选，以及单次评估的编译加 profile 时延。把这两个量与优势符号放在一起，才能演示「优势为正则追加、为负则回收」的规则如何消耗或释放预算。上线判断则用一个阈值区间收尾：优势落在死区内时不改变线上实现，落在正区外时才触发替换评估。

公式项统计含义工程来源漏答代价
$r_i$样本自身奖励正确性 oracle + profile 分档无法说明可复现性
$\mu_{-i}$留一参照组内其余候选的均值混淆 baseline 定义
$n-1$留一分母样本计数漏掉退化分支

五 · 代价核算：预算、时延与置信度三本账

代价必须分三本账记，混在一起写会失去工程说服力。第一本是搜索预算账：留一法本身不消耗额外候选，但为了让留一参照稳定，组内样本数不能太小，样本数每加一，就多一次候选生成与评估，token 消耗与编译时间同步上升；朴素 O(n²) 实现还会让每轮的打分阶段多出一次全组遍历，这在候选池大时表现为打分时延的二次增长。第二本是评估时延账：每个候选的奖励要经过编译、运行、profile 三步，单次时延由工具链决定，留一法不改变单次时延，但改变「需要评估多少次才能得到可信参照」，因此总时延是单次时延乘以有效样本数。第三本是置信度账：留一参照的方差随 $n$ 减小而增大，参照越不稳，优势符号越容易被噪声翻转，翻转会导致预算在正负之间来回摆动，形成无效搜索。三本账的共同结论是：留一法用「参照更干净」换「参照更嘈杂」，净收益取决于组内样本数与奖励噪声的相对大小。

把三本账写成一条判断规则：当单次评估时延高、候选池小的时候，留一参照的方差代价占主导，优势符号不可信，此时应扩大组内样本数或退回全量均值 baseline；当候选池大、单次时延低的时候，留一法的干净参照占主导，符号可信，预算可以按优势大小分档追加。这条规则不需要精确数字，只需要方向正确，答题时用定性表述即可，但必须把「哪本账占主导」说清楚。

六 · 从优势符号到上线判断的最后一跳

最后一跳是把连续的优势估计量压成离散判断，这一步的机制是阈值加死区。设正阈值为 $\tau_+$、负阈值为 $\tau_-$，规则是：$\hat{A}_i > \tau_+$ 时追加预算并保留候选进入下一轮；$\tau_- \le \hat{A}_i \le \tau_+$ 时不动作，维持当前候选集；$\hat{A}_i < \tau_-$ 时淘汰并回收预算。死区的宽度由留一参照的方差决定，方差大则死区宽，避免噪声驱动的预算摆动。上线判断复用同一套阈值：只有当某个候选的优势稳定超过 $\tau_+$，且其正确性 oracle 全通过、profile 显示端到端收益为正时，才进入替换评估；否则维持线上实现。这里的关键工程判断是「优势估计只提供排序，不提供绝对收益」，绝对收益必须由端到端测量给出，两者不能互相替代。

把这一跳与前面的公式接上：$\hat{A}_i$ 的符号来自 $r_i$ 与 $\mu_{-i}$ 的比较，而 $\mu_{-i}$ 的稳定性来自 $n$ 与增量更新的数值质量。因此上线判断的可信度不是由阈值单独决定的，而是由「样本数—方差—死区宽度」这条链决定的。答题时若能把这条链写成一句话——样本数不足则参照方差大，死区必须放宽，上线判断退化为保守维持——就已经把题干后半句答到了工程层。收束在一个具体机制上：增量维护全量和 $S$ 与全量平方和，用减法得到每个留一参照，再用参照方差反推死区宽度，这条流水线是 TRLOO 从公式走到上线判断的唯一通路。

留一法优势估计的适用边界与系统代价

TRLOO 的留一法优势估计在「同组内每个候选都能被独立重打分」这一前提下才成立：它把组内某个样本的优势定义为该样本奖励与其余样本平均奖励之差，从而在不引入额外基线网络的情况下消除组内共同偏移。公式上可写成 $$A_i = r_i - \frac{1}{K-1}\sum_{j\neq i} r_j$$，其中 K 为组大小。这个式子看似只做一次减法，但它隐含两个强假设：组内样本必须来自同一 prompt 且可比较；每个 r_j 必须是无偏、可复现的标量奖励。一旦组内混入不同 prompt 或不同验证器版本，留一均值就不再是合法基线，优势估计会系统性偏移。

失效条件集中在三类场景。其一是组大小 K 退化为 1 或 2：K=1 时留一均值无定义，K=2 时优势退化为 $$A_i = r_i - r_j$$，方差极大，等价于成对比较，搜索预算会被噪声吞掉。其二是奖励含离散或截断（如通过/不通过、超时记零），留一均值对离群值不稳健，一个异常样本即可污染整组优势。其三是奖励依赖执行环境（NCU 计数、SASS 指令数、时延抖动），同一 kernel 多次测量的方差若接近组内真实差异，优势信号将被测量噪声淹没。此时应改用组内中位数或截断均值作为基线，代价是引入额外排序开销。

系统代价方面，留一法本身是 O(K) 的标量运算，真正昂贵的是为每个候选重复执行验证 oracle 与 profile。若组内 K 个候选各跑一次正确性检查与一次 NCU 采集，验证时延随 K 线性增长，且显存需同时容纳多份中间张量。工程判断是：当单次验证时延已接近搜索单轮预算的显著比例时，应降低 K 或复用缓存的重打分结果，而不是盲目扩大组规模；K 的取值应由「组内真实差异 / 测量噪声」的比值决定，而非固定常数。

组规模 K优势信号质量验证时延适用判断
1无定义最低不可用
2高方差低仅作粗筛
较大 K稳健但易被噪声主导线性增长需先估测量方差
