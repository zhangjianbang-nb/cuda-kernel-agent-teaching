一 · 从“分数”到“时间去哪了”：硬件反馈的信号层级

基准演化史里有一条常被忽略的暗线：当基准从公开集迁到私有 held-out，分数不再虚高之后，agent 的失败模式立刻从“抄答案”变成“跑不快”。此时评测口径必须从单一的正确性/加速比，扩成一组可归因的硬件信号。工程上把这些信号按“距离硅片的远近”排成层级：最远的是 roofline 模型给出的理论上界，中间是 warp stall 与 occupancy 这类调度层统计，最近的是 SASS 指令流与二进制插桩得到的逐指令周期。层级越近，信息越贵——采集成本、存储体积、对被测 kernel 的扰动都在上升。agent 需要的不是全量采集，而是按失败类型选择层级：结构性慢（算术强度错配）看 roofline，调度性慢（延迟隐藏不足）看 stall，指令性慢（寄存器压力、分支、访存合并）看 SASS。

一个具体机制是“信号-假设映射表”：评测流水线在拿到一次失败样本后，先算 roofline 位置，若实测吞吐落在上界的固定比例之外，则判定为结构性问题，直接给出“换 tile 形状/换数据布局”的假设；若落在上界附近但延迟高，则转 stall 分析。这张表把 profile 从“给人看的报告”变成“给 agent 的决策输入”，是基准能否驱动优化的分水岭。

$$ \text{AI} = \frac{\text{FLOPs}}{\text{Bytes}},\quad P_{\text{roof}} = \min\left(P_{\text{peak}},\ \text{AI}\cdot B_{\text{peak}}\right) $$

代价在于：roofline 只需要算子级的 FLOPs 与字节数，几乎零采集成本，但它对“同一算子不同实现”没有分辨力；stall 统计需要一次 NCU 级别的 replay，单次采集会让 kernel 时延膨胀数倍到数十倍，且 replay 次数受限于 profiler 的采样预算；SASS 级插桩则要改二进制、重跑，编译时间与显存占用都要额外付。基准若对每个样本都做全层级采集，吞吐会塌到无法支撑多轮 RL 的采样量。

二 · Roofline 作为筛选器：先判“值不值得优化”

在私有 held-out 上，agent 最常见的浪费是把一个已经贴着带宽上界的 memory-bound kernel 反复重写。roofline 的第一个用途不是指导优化，而是否决优化：若实测吞吐已达 roofline 上界的较高比例，则剩余空间不足以抵消重写引入的正确性风险，评测应直接判“无需优化”并转入下一题。第二个用途是分类：把样本按算术强度分到 memory-bound 与 compute-bound 两簇，两簇的优化动作集合完全不同——前者动的是合并访存、向量化宽度、shared memory 复用；后者动的是指令级并行、张量核利用、累加器布局。

具体做法是把 roofline 判定写成基准元数据的一部分：每个任务在入库时记录其 FLOPs 与最小必要字节数（由问题定义决定，而非由某个实现决定），评测时只测实测吞吐，比值现场算。这样基准版本升级时，roofline 上界随硬件规格变化而重算，历史分数仍可比——因为比较的是“距上界的比例”而非绝对时延。这正是基准演化史里保证历史分数可比的关键决策之一：把绝对性能指标换成归一化指标。

代价是归一化会掩盖实现间的绝对差距：两个都贴着上界的实现，比例相同但绝对时延可能差出一截，而这截差距在真实负载里是钱。因此基准需要双轨记录：归一化比例用于跨版本比较，绝对时延用于同版本内排序。另一个代价是 FLOPs 口径本身有歧义——融合算子、稀疏算子、带数据依赖的算子，其“必要字节数”需要人工裁定并写入变更记录，否则 roofline 会变成新的分数虚高来源。

  • 机制：任务入库时冻结 FLOPs/字节口径，评测时只测吞吐，比值现场计算。
  • 代价：口径裁定的人力成本；归一化掩盖绝对差距，需双轨记录。
  • 例子：一个逐元素归一化 kernel 若实测已接近带宽上界，agent 的任何 tile 重写都只是把同一份带宽换个用法，评测应否决而非奖励。

三 · Warp stall：把“延迟藏不住”拆成可行动的类别

roofline 说“你该多快”，stall 说“你为什么没到”。NCU 的 warp state 统计把每个 warp 的发射停顿归到若干原因：等待内存依赖、等待屏障、等待指令取指、执行管线忙、以及 no eligible warp（可发射 warp 数为零）。对 agent 最有价值的是最后一类与内存依赖类的区分：前者说明 occupancy 或寄存器压力导致并行度不足，后者说明访存延迟未被足够多的在途请求覆盖。这两类的修复动作相反——前者要减寄存器、增 occupancy，后者要增 ILP、放宽依赖链。

一个可操作的伪代码思路是“stall 指纹”：把各 stall 原因的周期占比排成向量，与预置的几类指纹做最近邻匹配，直接映射到动作。指纹库由人工在少量样本上标注，之后作为基准的一部分固化，agent 只读指纹标签而不读原始计数器——这既降低了 token 消耗，也避免了 agent 对着几十个计数器自由发挥。

$$ \text{stall\_share}_i = \frac{c_i}{\sum_j c_j},\quad \text{eligible} = \frac{\text{cycles with } \geq 1 \text{ eligible warp}}{\text{total cycles}} $$

代价很直接：stall 采集需要 profiler replay，单次 kernel 的观测时延远高于正常执行，且 replay 会改变缓存状态，测出的 stall 分布与真实负载不完全一致。基准若对每个候选实现都跑 stall，采样吞吐会掉一个量级；折中做法是只在“roofline 判定为可优化但实测未达标”的样本上触发 stall 采集，把采集预算集中在有信息量的样本上。另一个代价是 stall 统计的粒度是 SM 级聚合，对细粒度指令重排的反馈偏弱，agent 容易把“等待屏障”误读为“同步写多了”而做出错误的合并决策。

四 · SASS：当高级语言不再解释性能时

CUDA C++ 与 Triton 的源码在编译后与 SASS 之间隔着寄存器分配、指令调度、谓词化、循环展开等多层变换。当 stall 指纹指向指令级问题时，源码层已经无法给出因果——agent 看到的 `float4` 加载在 SASS 里可能被拆成多条、可能被谓词化、可能因寄存器压力被溢出到 local memory。此时必须让 agent 读 SASS。可读的不是全量反汇编，而是几个关键切片：访存指令的宽度与合并情况、寄存器数量与 spill 计数、分支与屏障指令的位置、以及循环体的指令数。

具体机制是“SASS 摘要器”：从反汇编中抽取指令直方图、每线程寄存器峰值、spill 字节数、以及访存指令的地址步长模式，压成结构化字段喂给 agent。这样 agent 不需要理解整段汇编，只需要在“寄存器峰值接近上限且存在 spill”时选择降 tile 或改累加器布局，在“访存步长非连续”时选择改布局。基准演化史里这一步的意义在于：它把“优化技巧分层”落到了可观测的指令特征上，使难度分层不再依赖人工标注的技巧名，而依赖可自动抽取的 SASS 特征。

代价是三重：编译时间——为拿到 SASS 需要完整走一遍编译流程，若基准对每个候选都编译并反汇编，编译开销会超过执行开销；显存与存储——反汇编文本体积远大于源码，私有 held-out 若全量留存 SASS 会撑爆存储预算；可移植性——SASS 与架构绑定，跨架构的 SASS 特征不可直接比较，基准升级换硬件时历史 SASS 记录失效。因此工程判断是：SASS 只在“同架构、同版本”内作为诊断信号，不进入跨版本分数口径。

五 · 二进制插桩：把周期数钉到指令上

比 SASS 静态摘要更近一步的是二进制插桩：在指令边界插入计数或时间戳，得到逐指令或逐基本块的周期归属。它对 agent 的价值在于消除归因歧义——stall 统计说“等内存”，插桩能指出是哪一条加载指令、在哪个循环迭代上等。实现路径通常是在编译产物上做指令级改写，保留原语义的同时记录进入/退出时间，或者利用硬件计数器在基本块粒度上做归属。

代价是扰动：插桩本身增加指令数与寄存器压力，测出的周期包含插桩开销，绝对时延不可信，只有相对归属可信。因此插桩结果只能用于“哪段代码占比大”的排序，不能用于“这个 kernel 多快”的判定。基准若把插桩时延写进分数，等于把测量工具的成本算到被测实现头上，是口径污染。正确做法是把插桩限定在离线诊断阶段，其输出只作为 agent 的上下文，不进入评分。

一个具体例子：一个 reduction kernel 在 stall 指纹上表现为内存依赖主导，agent 尝试增大 ILP 无效；插桩显示周期集中在最后一次跨 warp 归约的屏障等待上，真正的瓶颈是归约树的深度而非访存。没有插桩，agent 会在错误的方向上反复试探，多轮 RL 的样本效率被这种错误归因吃掉。这正是“让 agent 看见时间去哪了”的核心价值：不是给更多数字，而是给可归因的因果。

层级回答的问题采集代价进入分数口径
roofline值不值得优化、属哪一簇近零，仅需口径是（归一化比例）
warp stall延迟为何藏不住replay，时延膨胀否，仅诊断
SASS 摘要指令级瓶颈在哪编译+反汇编+存储否，同架构内诊断
二进制插桩周期归属到哪条指令改写+扰动，绝对时延失真否，离线诊断

六 · 采集预算与防污染：profile 也要进变更记录

把四层信号接进基准，真正的工程约束不是“能不能采”，而是“采多少”。多轮 RL 的采样量由候选实现数乘以每题轮数决定，若每轮都触发 profiler replay，端到端吞吐会被采集吃掉。可行的预算策略是分层触发：roofline 全量、stall 抽样、SASS 与插桩仅在“连续多轮无提升”的样本上触发，且触发次数计入该样本的采集配额。配额耗尽的样本转入“已诊断未解决”集合，作为下一版基准的难度分层依据——这正好呼应基准演化史里“难度按优化技巧分层”的决策：一个样本若在四层信号都可见的情况下仍无法被 agent 优化，它就是一个高难度样本，而不是一个坏样本。

防污染在这里有第二重含义：profile 数据本身会泄漏答案。若私有 held-out 的 stall 指纹或 SASS 摘要被 agent 的记忆带走，下一版基准的同一算子就会因“见过诊断结论”而虚高。因此 profile 产物的留存策略必须与题目去重、时间切分一致：诊断产物按版本隔离，跨版本不共享；agent 的上下文里只出现当前样本的诊断，不出现历史同族样本的诊断。这一条要写进基准变更记录，与口径变更、难度分层规则并列。

最后一个工程判断落在“可归因”与“可比较”的分离上：roofline 比例进入分数，保证跨版本可比；stall/SASS/插桩只进入诊断上下文，保证 agent 拿到因果但不污染口径。这条分离线一旦模糊，基准就会重演公开集时代的分数虚高——只不过这次虚高来自测量工具，而不是来自训练数据。二进制插桩的扰动、SASS 的架构绑定、stall 的 replay 膨胀，三者共同决定了它们只能停在诊断层；而 roofline 之所以能进分数，恰恰因为它几乎不扰动被测对象。测量越靠近硅片，越可信于归因，越不可信于绝对性能——这条不对称是 profile 接入基准时不可让渡的约束。

当 profile 本身成为污染源：硬件反馈通道的失效边界

把 NCU/SASS 反馈接进 agent 的观测回路，代价首先不是采集开销，而是反馈通道与基准私有 held-out 的同构性风险。若 agent 在私有集上反复读取 stall 分布、roofline 落点与 SASS 指令序列，它实际优化的是“这套硬件+这套输入形状下的 profile 指纹”，而非算子语义。一旦 held-out 的 shape、dtype 或 SM 架构发生偏移，历史分数便不可比——这正是公开集迁移到私有集时分数虚高被揭穿的同一机制，只是污染源从题目泄漏变成了 profile 泄漏。工程上必须把 profile 采集限制在训练侧可见的采样窗口内，held-out 侧只回传标量正确性与端到端时延，不返回 stall 明细。

失效条件可以形式化为一个可观测性预算：设单次 kernel 的 profile 采集引入的额外时延为 Δtprof，回传给 agent 的 token 数为 Tfb，则有效迭代吞吐近似为

$$\text{吞吐}_{\text{eff}} \approx \frac{1}{\Delta t_{\text{prof}} + \alpha\, T_{\text{fb}} + \Delta t_{\text{compile}}}$$

其中 α 是每 token 的解析与推理成本。当 Δ tprof 与编译时间同量级时，多轮 RL 的样本效率被采集开销吞掉；当 Tfb 过大（例如把整段 SASS 反汇编塞进上下文），上下文窗口挤占会直接压低有效轮数。更隐蔽的失效是插桩扰动：二进制插桩改变指令调度与寄存器压力，测得的 stall 分布不再代表原始 kernel，agent 据此做的优化在生产端回退。

反馈通道可见信息主要代价失效条件
roofline 落点带宽/算力利用率上界需精确 flops 与字节计数算子含不规则访存时上界失真
warp stall 采样停顿原因分布采样窗口与重放开销短 kernel 采样不足，噪声主导
SASS 静态读指令混合与寄存器占用反汇编 token 量大编译器版本漂移导致模式失配
二进制插桩细粒度时序调度扰动、编译时间上升扰动改变被测行为本身

具体例子：一个 L2 级别的 reduction kernel 在私有 held-out 上换用非 2 的幂的归约长度，agent 依据训练侧 profile 学到的“向量化加载+固定 unroll”模式直接套用，warp stall 从访存等待转为分支发散，端到端时延反而上升；此时若 held-out 仍回传 stall 明细，agent 会把这次回退误判为可修复的局部问题，继续在错误的形状假设上迭代。工程判断是：profile 反馈应作为训练侧诊断信号而非评测侧奖励信号，且每次基准版本升级必须同步冻结 profile 采集口径（工具版本、采样率、插桩开关），否则分数可比性无从保证。
