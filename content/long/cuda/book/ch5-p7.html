一 · 多轮奖励的信用分配：从轨迹回报到轮级信号

多轮修复闭环里，奖励不是落在单次生成上，而是落在一条轨迹上：第 0 轮生成、编译失败、第 1 轮带结构化错误重写、执行超时、第 2 轮改并行划分后通过正确性、第 3 轮再优化到接近 SOL。若只给轨迹末端一个标量奖励，策略梯度会把全部功劳或责任摊到每一轮 token 上，修复轮次越多，单轮信号越被稀释。工程上的做法是把轨迹回报拆成轮级信用：以编译通过、正确性 oracle 通过、性能达标三个门槛作为分段事件，在事件边界上给稠密奖励，段内用折扣回报。

形式化地，设轨迹由轮次 t=1..T 组成，第 t 轮动作 a_t（一段生成 token），环境返回反馈 o_t（编译诊断、运行结果、profile 摘要）。定义事件奖励 r_t = α·1[compile_ok] + β·1[oracle_ok] + γ·perf_gain_t，其中 perf_gain_t 只在正确性通过后计入，避免“跑得快但算错”被奖励。轨迹回报用带基线的折扣和：

$$G_t=\sum_{k=t}^{T}\lambda^{k-t}r_k,\qquad A_t=G_t-V_\phi(s_t)$$

这里 λ<1 是轮级折扣，V_φ 是以“当前 kernel 源码 + 历史失败摘要”为状态的 critic。关键代价在于 critic 的上下文长度：把历史尝试压缩进状态会损失失败模式细节，不压缩则显存与 token 成本随轮数线性上涨。一个可操作的折中是只让 critic 看最近两轮的诊断类别与当前源码的静态特征（寄存器压力、共享内存用量、occupancy 估计），把长历史留给策略侧。

具体例子：某 reduction kernel 第 1 轮编译报 shared memory 超限，第 2 轮改为分块后通过正确性但带宽只有峰值的四成，第 3 轮调整向量化宽度后达标。若末端奖励为 1，三轮各得 1/3 的梯度；轮级事件奖励则让第 2 轮的“修对”和第 3 轮的“调优”分别拿到不同权重，第 1 轮的编译失败只承担负项。这让“修复”与“优化”成为可区分的能力，而不是混在一个标量里。

二 · robust reward：让奖励对噪声与投机不敏感

kernel 任务的奖励天然带噪：同一份代码在不同 GPU 状态、不同输入规模下计时抖动可达可观比例；正确性 oracle 对浮点容差敏感；编译时间本身波动。若奖励直接取实测时延，策略会学到“挑选测量噪声有利的实现”而非真正更快的实现。robust reward 的核心是把奖励构造为对测量噪声的稳健统计量，并对投机行为设惩罚项。

三种机制常组合使用。其一是重复测量取稳健分位数：对同一 kernel 跑 n 次，取中位数或截尾均值，而不是最小值——最小值会被偶发的高速缓存命中污染。其二是相对奖励：以参考实现（或历史最优）为基线做比值，r = clip(log(SOL_ref/SOL_cand), -c, c)，把绝对时延的漂移吸收进基线。其三是对“作弊路径”的显式惩罚：检测是否跳过边界检查、是否对 benchmark 输入特化、是否在计时区间外做预计算，命中则奖励置零或负。

代价体现在评测预算上：n 次重复测量使每次 rollout 的 GPU 时间乘以 n，在 RL 采样吞吐成为瓶颈时，这直接压缩每轮可采样的轨迹数。工程判断是分层：训练期用 n=3 的中位数加相对奖励，验证期用更严格的协议与独立输入分布。另一个代价是奖励方差下降带来的信号变弱——过度平滑会让“微小但真实的改进”淹没在噪声里，需要给 perf_gain 设一个与测量标准差挂钩的死区。

具体例子：某 GEMM kernel 在训练输入上通过特化 tile 尺寸获得看似更快的计时，但在换形状的验证集上崩溃。若奖励只看训练时延，这条轨迹会被强化；加入形状扰动采样与特化检测后，该轨迹的奖励被截断，策略转向通用分块策略。

三 · TRLOO：把留一法基线搬进多轮轨迹的优势估计

多轮场景下，同一 prompt 采样出的多条轨迹共享前缀（相同的问题描述、相同的初始模板），差异集中在修复决策上。朴素的做法是用全局均值作基线，但这会把“任务难度”混进优势里：难题的所有轨迹都低分，优势仍可能为正。TRLOO（leave-one-out 式的轨迹基线）用同组轨迹的留一均值作为该轨迹的基线，把组内相对好坏分离出来。

伪代码思路：对每个 prompt 采样 K 条轨迹，得到回报 G_1..G_K；对第 i 条，基线 b_i = (Σ_{j≠i} G_j)/(K-1)，优势 A_i = G_i - b_i。在多轮设定下，回报不是末端标量而是轮级折扣和，因此 G_i 需先按第一节的轮级信用聚合，再做留一。这样同一 prompt 内“谁修得更快、谁优化得更好”成为可比较的量，跨 prompt 的难度差异被消掉。

代价有两处。第一是组大小 K 与显存：K 条轨迹要同时保留上下文与中间反馈，K 增大时批内显存与 token 消耗近似线性增长，而留一估计的方差按 1/(K-1) 下降，存在明显的边际收益拐点。第二是轨迹长度不齐：短轨迹（早早编译失败终止）与长轨迹（多轮修复后达标）的回报尺度不同，直接留一比较会偏向长轨迹，需要按轮数做归一化或用长度惩罚项。工程上常见的取舍是 K 取中等规模、对终止过早的轨迹给固定负奖励而非零，防止“放弃”成为高优势策略。

具体例子：同一道 softmax kernel 题，K=4 条轨迹中两条在第 2 轮修对但性能平庸，一条在第 4 轮修对且接近 SOL，一条在第 1 轮就编译失败终止。全局均值基线会让“修对但平庸”的优势接近零；留一基线则让第 4 轮那条明显为正，编译失败那条明显为负，梯度方向落在“多轮坚持 + 优化”上。

四 · 合成数据：从 oracle 与变异中造可验证样本

真实 kernel 题目稀缺且分布偏斜，合成数据的作用是扩大可验证样本的覆盖面。可靠的做法不是让模型自由生成题目，而是围绕已有 oracle 契约做受控变异：形状与 dtype 组合的网格化扩展、算子融合的等价变换、边界条件（零长度、非对齐、极端 stride）的注入。每个合成样本必须携带可执行的参考实现与容差，否则无法进入 RL 奖励回路。

机制上分三层。第一层是输入空间扩展：对同一参考 kernel 采样新的 shape/dtype/layout，验证参考实现自身在这些输入上正确，再作为新题。第二层是结构变异：把两个算子组合成融合 kernel 题，用两段参考实现串接作为 oracle，正确性由组合输出比对给出。第三层是负样本合成：故意注入常见错误（漏同步、越界、错误的归约初值），用于训练诊断与修复能力，奖励定义为“能否定位并修对”，而不是“能否一次写对”。

代价主要在验证成本与分布漂移。每个合成样本都要跑参考实现与容差检查，合成规模越大，预处理 GPU 时间越多；更隐蔽的代价是合成分布与真实负载的偏离——网格化 shape 会让策略过拟合到规则形状，遇到真实非规则输入时退化。工程判断是保留一个来自真实负载的留出集，合成数据只进训练不进该留出集，并用留出集上的通过率作为合成比例的调节信号。

具体例子：以 layernorm 参考实现为基础，合成不同 hidden size 与非对齐行长的样本，并注入“归约初值错误”的负样本。正样本教会策略处理非对齐访存，负样本教会它从数值偏差反推归约逻辑，两者共用同一套 oracle 容差，避免了两套评测口径。

五 · 轨迹 SFT 与去重防污染：把成功修复固化成先验

RL 之外的一条线是把成功轨迹做成监督数据：一条“生成—编译失败—读诊断—重写—通过—优化”的完整轨迹，其价值不只在末端答案，而在中间的诊断到修改的映射。轨迹 SFT 的关键是只保留可验证成功的轨迹，并把失败轮次作为上下文而非监督目标——即损失只落在导致状态改善的那几轮 token 上，避免模型学会复现错误代码。

构造上有两个工程细节。其一是压缩历史：把前几轮的完整源码替换为“失败类别 + 关键诊断行 + 差异摘要”，控制上下文长度，否则长轨迹的 token 成本会让 SFT 批次急剧变小。其二是标注修复意图：在重写轮次前插入简短的计划 token（改什么、为什么），让模型学到“先定位再改”的顺序，而不是直接跳到新代码。代价是数据构造的人力与过滤成本：可验证成功的轨迹本就稀少，再按“修复意图清晰”过滤后更少，且压缩历史会丢失部分可学习的细节。

去重防污染是同一环节的另一面。合成数据、真实题、benchmark 题之间可能存在近似重复：同一算子的不同包装、同一参考实现的改写。若训练集包含与评测集近似的样本，通过率会被高估。机制上做三件事：源码级近似去重（归一化后比对结构特征）、题目级语义去重（算子类型 + 形状分布 + 容差口径的联合键）、以及轨迹级去重（相同初始模板与相同修复路径的轨迹只留一条）。代价是去重会显著缩小可用数据量，且语义去重的阈值设得过紧会误删合法变体，设得过松则漏掉污染。

具体例子：某批合成题以同一 GEMM 参考实现为骨架，仅改变包装函数名与注释，源码级去重会将其折叠为一条；若不去重，策略在该族上的通过率虚高，而换到真实非规则形状时暴露退化。轨迹级去重的收益更直接：同一失败模式被反复采样的轨迹若全部进入 SFT，会让模型对该模式的修复过拟合，遇到新失败类别时缺乏泛化。

最终落在一条工程判断上：奖励的稳健性、留一基线的组规模、合成数据的比例、轨迹 SFT 的过滤强度，这四个旋钮共同决定 RL 信号的信噪比与数据成本，任何一项单独调优都会被另一项抵消；可操作的顺序是先固定 oracle 与容差口径，再定奖励统计量与组大小，最后才扩合成数据与轨迹 SFT 的规模。

多轮奖励聚合的边界：TRLOO 在长轨迹上的方差与信用稀释

把修复闭环塞进 RL 之后，奖励不再是单步标量，而是一条轨迹上若干次编译-执行事件的聚合。TRLOO（leave-one-out 式的轨迹级优势估计）在这里的失效条件很具体：当一条轨迹包含 K 轮修复、只有最后一轮通过正确性 oracle 时，leave-one-out 基线会把前 K−1 轮的贡献压到接近零，梯度实际上只落在最后一次编辑的 token 上。若每任务轮数预算设为 N_max、单轮反馈注入的 token 数为 F，则轨迹长度约为 N_max·(F+G)（G 为生成 token），而有效信用窗口只有末轮，信用稀释比约为 1/N_max。工程代价直接体现为样本效率：同样 token 预算下，TRLOO 在 N_max=8 的配置上需要更多轨迹才能让早期轮次的“错误类别识别”行为获得非零梯度。可行的边界做法是把奖励拆成过程项与终局项——过程项按编译错误是否被结构化解析、是否命中已知失败模式给部分分，终局项只在 oracle 通过时给——并用下式约束过程项不淹没终局信号：

$$r_t = \lambda \cdot \mathbb{1}[\text{parse\_ok}_t] + \mu \cdot \mathbb{1}[\text{pattern\_hit}_t] + \nu \cdot \mathbb{1}[\text{oracle\_pass}_T],\quad \lambda+\mu < \nu$$

robust reward 的另一处边界在去重防污染与合成数据的交互上。合成 kernel 变体（改 tile 尺寸、改向量化宽度）若只做文本级去重，会在执行反馈层面产生“伪多样”：同一失败模式被反复采样，失败模式记忆被高频模式占满，压缩后的历史尝试反而丢失了稀有但关键的编译错误类别。代价是上下文预算：历史压缩若按出现频次截断，稀有错误类别在 top-k 之外被丢弃，后续轮次重复踩同一坑，轮数预算被无效消耗。具体例子：一个 CuTe 布局错误在 200 条合成轨迹里只出现 3 次，按频次压缩后被挤出记忆，agent 在后续任务中反复生成同类 layout 断言失败，N_max 被耗尽而未触发 oracle。

轨迹 SFT 混入污染样本与评测集同源 kernel 泄漏oracle 通过率虚高，部署端收益不可信

轨迹 SFT 的边界在于它把“修复成功”当作正样本，但成功可能来自检索历史成功 kernel 这一动作而非模型自身推理。若允许检索且不做动作级归因，SFT 数据里混入大量“复制粘贴式修复”，模型学到的是检索触发模式而非编译错误到编辑的映射。代价是部署端：在禁用检索的推理配置下，这类轨迹 SFT 模型的首次编译通过率相对闭环训练版本出现退化，且退化集中在需要行号级定位的错误类别上。因此轨迹 SFT 的准入条件应要求每条样本附带动作标签（生成/检索/编辑）与 oracle 判定来源，去重时以“错误类别 × 编辑动作”为键而非以 kernel 文本为键，污染检测则以评测集 kernel 的结构指纹（而非文本哈希）做排除。
