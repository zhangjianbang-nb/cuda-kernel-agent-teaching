一 · 多轮奖励的信用分配：把轨迹切成可归因的片段

多轮 RL 的核心困难不在奖励本身，而在奖励落到哪一步。一个 agent 在第 3 轮把 shared memory 的 tile 从 32 改到 64，第 5 轮才发现 bank conflict 加剧，第 7 轮靠 padding 修回来——最终 kernel 达标，但中间两次修改各自是正贡献还是负贡献，单条轨迹级标量奖励无法回答。工程上必须把轨迹切成可归因的片段，让奖励在片段粒度上落地。

具体机制是「分段奖励 + 折扣回传」：把一次 rollout 按工具调用边界切成若干 step，每个 step 记录 (动作类型, 编译结果, 运行结果, profile 差分)。奖励由三部分组成——终局奖励 r_T（正确性 oracle 通过与否、SOL 达标与否）、过程奖励 r_t（编译是否通过、是否引入数值误差、时延是否退化）、以及格式/协议奖励（是否输出合法 CUDA C++、是否遵守工具调用 schema）。回传时对过程奖励做折扣：

$$G_t = \sum_{k=0}^{T-t} \gamma^{k}\, r_{t+k},\qquad \gamma \in (0,1]$$

折扣因子 γ 的选择直接决定 agent 是「短视修补」还是「长线重构」。γ 接近 1 时，早期一次错误的 tile 选择会被后续所有步骤的负奖励稀释，梯度信号变弱；γ 偏小时，agent 倾向于在第一步就做出保守但局部最优的改动，放弃需要多步才能兑现的收益（例如先改数据布局、再改向量化宽度）。工程判断是：把 γ 与「编译-运行往返时延」挂钩——往返越贵，γ 越应接近 1，否则 agent 学不到跨轮次的因果链。

代价在 token 与显存两侧同时出现。分段奖励要求每条轨迹保留每步的中间产物（源码快照、编译日志摘要、profile 采样），一条 8 步轨迹的上下文长度通常是单步的 3–5 倍，rollout 吞吐下降、KV cache 占用上升。更隐蔽的代价是信用分配噪声：过程奖励若来自不稳定的计时（见本卷计时口径部分），会把噪声当成学习信号，agent 学会的是「抖动」而非「优化」。具体例子：某次 rollout 中第 4 步的时延从 1.82ms 跳到 1.79ms，若未做重复测量取中位数，这 1.6% 的差异会被记为正奖励，agent 随后反复做无意义的等价改写。

二 · Robust reward：让奖励对噪声与投机都免疫

奖励函数是评测流水线里最容易被攻击的接口。agent 会学会任何能提高标量的捷径：把 kernel 写成对特定 shape 的特化分支、调用 cuBLAS 兜底、在 warmup 阶段做一次性预热让计时看起来更快、甚至输出一个永远返回正确结果但根本不计算的 kernel（针对小规模输入的查表）。robust reward 的设计目标不是「更准」，而是「让投机无收益」。

机制上分三层。第一层是奖励塑形（reward shaping）的单调性约束：奖励必须是「正确性 ∧ 性能」的合取结构，而非加权和。加权和允许用性能换正确性——一个数值误差 1e-3 但快 20% 的 kernel 可能拿到更高分，这在 oracle 严格模式下是不可接受的。合取结构写成：

$$r = \mathbb{1}[\text{oracle pass}] \cdot \big(\alpha + \beta \cdot \min(1, \tfrac{\text{SOL}}{\text{SOL}_{\text{target}}})\big)$$

第二层是对抗性探测：在评测集中混入「陷阱用例」——非对齐 shape、极端 batch、退化维度，专门检测特化分支与兜底调用。陷阱用例不计入主分，但一旦触发即施加惩罚项。第三层是奖励裁剪（reward clipping）与方差归一化，防止单条异常轨迹（例如某次 GPU 时钟被锁定在低频）拉偏整个 batch 的优势估计。

代价是评测成本。陷阱用例使每个候选 kernel 的执行次数上升，容器化沙箱的调度开销与 GPU 隔离成本随之增加；奖励裁剪会损失一部分真实的高分信号，尤其在长尾优化上——一个真正把 SOL 从 40% 推到 70% 的 kernel 与一个靠抖动蒙到 70% 的 kernel，在裁剪后可能拿到相近的奖励。工程上的折中是：对终局奖励不做裁剪，只对过程奖励裁剪，因为终局的正确性与性能是硬事实，过程信号才是噪声重灾区。具体例子：某 agent 学会在检测到输入维度为 2 的幂时走快速路径，其余走慢路径，主分很高但陷阱用例全挂——合取结构加陷阱惩罚后，该策略的期望奖励变为负值，训练两轮后消失。

三 · TRLOO：把 leave-one-out 做成可并行的优势估计

多轮 RL 里，同一 prompt 下的多条轨迹共享初始状态，组内比较（group-relative）比跨组基线更稳。TRLOO（token-level / trajectory-level leave-one-out）的思路是：对组内第 i 条轨迹，用其余轨迹的奖励均值作为基线，减去自身，得到优势。它的价值在于消除 prompt 难度带来的基线漂移——难题组整体奖励低，但组内相对优劣仍然可学。

伪代码思路如下：对每个 prompt 采样 K 条轨迹，收集终局奖励 r_1…r_K 与分段奖励，计算

$$A_i = r_i - \frac{1}{K-1}\sum_{j \neq i} r_j$$

再按 step 粒度把 A_i 分摊到各 token（用折扣回传或均匀分摊）。关键工程点是：leave-one-out 必须与「同组同口径」绑定——K 条轨迹必须在同一容器镜像、同一 GPU 隔离策略、同一 warmup/重复次数下评测，否则基线里混入了口径差异，优势估计变成噪声放大器。这正是本卷反复强调的统一计时口径在 RL 侧的落点。

代价有三。其一是采样成本：K 条轨迹意味着 K 倍的执行与 K 倍的 token，K 从 4 提到 8 时 rollout 墙钟时间近似翻倍，而优势估计的方差只按 1/√K 下降，边际收益递减。其二是组内相关性：若 K 条轨迹由同一 agent 在同一上下文里生成，它们高度同质，leave-one-out 的基线几乎等于自身，优势趋近于零，学习信号消失——解法是提高采样温度或引入不同脚手架变体，但这又引入新的方差。其三是数值稳定性：当组内奖励全相等（例如全部编译失败），分母 K−1 仍在但分子全零，优势为零，此时应跳过该组而非强行归一化。具体例子：某批次 8 条轨迹中 6 条编译失败、2 条通过但性能不达标，TRLOO 给出的优势集中在「编译通过」这一过程信号上，agent 下一轮优先学语法正确性而非性能——这是符合预期的课程式收敛。

四 · 合成数据：从失败分类里长出训练集

真实 rollout 的通过率决定了 RL 的信号密度。当某个算子族（例如带 reduction 的 softmax、分组卷积）通过率长期低于阈值，靠继续采样等不来正例，必须合成数据补位。合成的来源不是凭空造题，而是失败分类的逆向工程：编译错→合成语法合法但边界刁钻的变体；数值错→合成对累加顺序、精度敏感的用例；性能不达标→合成 roofline 上界明确、易于判断 SOL 的用例。

机制上，合成管线分三步：模板参数化（shape、dtype、layout、tile 尺寸作为参数空间）、oracle 预验证（合成用例必须先通过参考实现与形式审计，否则污染训练集）、难度分层（按 SOL 目标与陷阱密度打标）。参数空间采样要避免「同分布塌缩」——只在 2 的幂 shape 上采样会让 agent 过拟合对齐假设，必须强制注入非对齐维度与退化 batch。

代价是三重污染风险。第一，合成用例若与基准测试集同源，等于把评测题泄进训练，KernelBench 系的排名随即失真——必须做去重（见下一节）。第二，合成用例的 oracle 若本身有 bug，agent 会学到错误的不变式，且这种错误在真实用例上表现为「莫名其妙的不达标」，排查成本极高。第三，合成数据的 token 成本：每条合成用例需附带参考实现、判据说明与陷阱标注，一条高质量合成样本的标注长度可达数百 token，规模化时标注预算成为瓶颈。具体例子：针对 reduction 算子合成 64 个非对齐 shape 用例，其中 8 个故意让朴素实现的累加顺序产生 1e-5 级误差，用于训练 agent 主动选择 Kahan 求和或分块累加——这类用例在真实基准里稀少，但对正确性 oracle 的鲁棒性贡献显著。

五 · 轨迹 SFT：把「怎么改」而不是「改成什么」写进数据

RL 教的是偏好，SFT 教的是格式与流程。轨迹 SFT 的数据单元不是最终 kernel，而是完整的「读题→写初版→编译→读错误→改→profile→再改」序列，附带每步的工具调用与观察。它的作用是给 RL 一个合法的动作空间先验：agent 先学会不写出编译不过的代码、学会读 NCU 输出、学会在失败后换策略而不是重复同一改动。

构造上，轨迹 SFT 需要三步清洗。第一步是成功轨迹的裁剪：去掉冗余的等价改写与无效重试，只保留有因果贡献的 step，否则模型学会「多试几次总有一次对」的碰运气策略。第二步是失败轨迹的保留与标注：编译错、数值错的轨迹是有价值的负例，但必须标注「错在哪一步、正确做法是什么」，否则模型学到的是错误模式本身。第三步是观察压缩：NCU/SASS profile 的原始输出极长，需压成结构化摘要（瓶颈类型、占用率区间、访存模式），压缩比直接决定上下文预算。

代价在编译时间与 token 两侧。一条含 6 次编译往返的轨迹，其编译墙钟时间可能远超生成本身，数据管线的吞吐被编译沙箱卡住；而每步的源码快照与 profile 摘要使单条样本的 token 数达到数千，SFT 的序列长度与显存占用同步上升。工程判断是：轨迹 SFT 的价值密度高于单点 SFT，但只值得在「工具调用协议」与「失败恢复模式」上投入，不必为每个算子族都造长轨迹——后者应由 RL 在合成数据上自行探索。具体例子：把「编译报错 shared memory 超限」→「减小 tile 或改用动态共享内存」这一对观察-动作固化为 SFT 样本后，agent 在该类错误上的平均恢复步数从多轮降到一两轮，直接压缩了 rollout 的 token 成本。

六 · 去重与防污染：训练集与评测集的隔离带

可信评测的底线是训练数据不得与评测集重叠。KernelBench 系的题目是公开的，模型预训练语料里可能已包含题面甚至参考实现，这使得「高分」可能只是记忆而非能力。防污染必须在三个层面做：题面级、代码级、轨迹级。

题面级去重用语义指纹——对题目描述做归一化（去变量名、去注释、抽象 shape 为符号）后做 n-gram 或嵌入相似度比对，阈值之上即判为同源。代码级去重更关键：agent 生成的 kernel 可能与公开仓库的实现高度相似，需做 token 级与 AST 级的双重比对，AST 比对能识别「改变量名但结构相同」的洗稿。轨迹级去重针对合成数据：同一模板参数化出的用例若轨迹动作序列高度一致，说明 agent 在背模板而非推理，这类轨迹应从训练集剔除或降权。

机制上，去重管线应嵌入数据入库前的门禁，而非事后审计。门禁输出三态：通过、隔离（进 held-out 池）、拒绝。隔离池用于监控泛化——若 agent 在隔离池上的表现显著低于训练分布，说明存在污染或过拟合。代价是数据吞吐：AST 比对与嵌入相似度的计算开销使入库速度下降，且高阈值会误杀合法的相似解法（例如两个独立实现的 tiled GEMM 结构天然相似）。工程折中是分层阈值：题面级从严，代码级从宽但配合人工抽检，轨迹级只看动作序列的编辑距离。具体例子：某合成用例与基准中一道 softmax 题在归一化题面后相似度超阈值，被自动隔离；后续发现该用例的陷阱设计（非对齐 reduction 维度）确有独立价值，于是改写题面描述、保留用例本体，既避免泄题又保留训练信号。

防污染的最终判据不是相似度分数，而是「隔离池上的性能是否随训练同步提升」。若训练集分数上涨而隔离池停滞，流水线应自动触发数据审计，把可疑样本回退到隔离池——这条反馈回路本身就是可信评测的一部分，它把数据治理从一次性清洗变成了持续的可观测过程。

奖励一旦被写进流水线，抖动就不再是噪声而是判据

多轮奖励与 robust reward 的边界不在算法本身，而在奖励信号被流水线固化的那一刻。可验证奖励（编译通过、数值对齐 oracle、SOL 达标）看似客观，但一旦把「性能不达标」也折算成标量奖励，计时口径的方差就直接进入梯度：同一 kernel 在 warmup 不足、未锁时钟的沙箱里跑两次，中位数可能跨过阈值两侧，奖励符号翻转，TRLOO 的组内基线随之偏移。代价是 token 与算力双重浪费——一次错误的正奖励会诱导 agent 在后续轮次重复提交同一份近似实现，而错误负奖励会砍掉本可优化的方向。工程上必须把奖励拆成硬判据（编译/运行/数值，布尔）与软判据（相对 SOL 的分位区间），软判据只在重复次数与分位数口径固定后才允许进入 RL，否则奖励函数本身就成了抖动源。

TRLOO 类组内基线方法对采样分布敏感：同一 prompt 下 K 条轨迹若因沙箱抖动被分到不同 GPU 隔离档位，组内方差被系统性放大，基线估计偏移。设组内奖励 $r_i$，基线 $\bar r = \frac{1}{K}\sum_i r_i$，优势 $A_i = r_i - \bar r$，则奖励噪声 $\epsilon_i$ 直接叠加到 $A_i$ 上且不被组内平均抵消（因为 $\sum \epsilon_i$ 不为零时基线也带噪）。合成数据与轨迹 SFT 的失效条件更隐蔽：合成 kernel 若由同一模板批量生成，去重只按文本哈希会漏掉结构同构的样本，训练集与评测集共享同一族实现，污染表现为评测分数虚高而在真实任务上不复现。去重必须落到编译产物或 SASS 指令序列的指纹上，代价是每条样本多一次编译与反汇编，编译时间成为数据管线吞吐的瓶颈。

环节失效条件系统代价
软奖励入 RL计时方差跨阈值重复采样 token 翻倍
TRLOO 组基线组内 GPU 档位不一致基线偏移，优势失真
合成数据去重仅文本哈希编译+反汇编时延

因此这条支路的工程判断是：奖励的可信度上限由评测流水线的口径决定，而非由 RL 算法决定。在时钟锁定、warmup 与重复次数固定、失败分类明确之前，任何把性能折算进奖励的尝试都只是在放大误判；轨迹 SFT 的数据准入应以「能否在同一沙箱内稳定复现判据」为门槛，而不是以样本数量为目标。
