一 · 多轮奖励的结构：把「哪一轮修好了」变成可训练信号

多轮 RL 与单轮 RL 的差别不在算法名字，而在奖励的时间结构。单轮样本是「一个 prompt → 一个 kernel → 一个标量」，多轮样本是「一个 prompt → 第 1 轮 kernel → 编译/正确性反馈 → 第 2 轮 kernel → … → 第 T 轮」，最终只有一个终局分数，但中间每一轮都产生了可观测的中间态（编译是否通过、错在哪个用例、加速比从多少变到多少）。若把终局奖励原样广播到所有轮次，信用分配就退化成「整条轨迹同分」，模型无法区分「第 1 轮就写对、后 4 轮在空转」和「第 1 轮编译失败、第 3 轮靠一次针对性修复翻盘」——这两种轨迹在训练梯度上应该被区别对待，因为前者是冗余 token，后者是真正值得强化的修复行为。

本卷采用的机制是把奖励拆成三层再聚合。第一层是正确性门控 g ∈ {0,1}，由第 4 卷的 oracle 判定给出，硬门控意味着 g=0 时后续连续奖励一律清零；第二层是加速比连续项，取相对基线的比值 s = t_base / t_kernel；第三层是 SOL 归一化项，把 s 映射到「距离该算子 roofline 上限还有多远」的尺度上，避免不同算子族之间加速比量纲不可比。聚合形式可写成：

$$R_t = g_t \cdot \bigl( \alpha \cdot \log \frac{t_{\text{base}}}{t_t} + \beta \cdot \frac{\text{SOL}_t}{\text{SOL}_{\max}} \bigr) \cdot \gamma^{\,T-t}$$

其中 γ 是多轮折扣因子，T−t 是「距离终局还有几轮」。折扣的作用不是惩罚早期轮次，而是抑制「早期轮次靠运气拿高分、后期轮次无贡献」的虚假信用：越靠近终局的轮次对最终结果的因果贡献越直接，权重越高。这里的关键工程判断是 γ 不能设得太小——若 γ=0.5 且 T=6，第 1 轮权重只有终局的 1/32，模型会学到「前面几轮随便写、只赌最后一轮」，这与多轮修复的初衷相反；反之 γ→1 则退化为均匀广播。实践中把 γ 与「平均有效修复轮次」绑定，让权重衰减大致对齐真实增益分布。

代价是显式的：三层奖励要求每一轮都跑一次编译 + 正确性判定 + 计时，单条轨迹的评测时延随 T 线性增长，token 消耗也线性增长（每轮都要重新生成完整 kernel 或 patch）。一个具体例子：某 reduce 类算子的轨迹在第 1 轮因共享内存 bank conflict 编译通过但正确性失败，第 2 轮修正索引后正确但加速比仅 1.1×，第 3 轮改为 warp shuffle 后加速比跳到 3.4×——若均匀广播，第 1、2 轮的无效 token 与第 3 轮的有效修复获得同等梯度；按上式折扣后，第 3 轮获得主要权重，第 2 轮获得部分权重（它把 g 从 0 翻到 1），第 1 轮几乎不获得正向梯度，这正是我们希望模型学到的「先修正确性、再修性能」的次序。

二 · Robust reward：让奖励在噪声与对抗样本下不塌

可验证奖励的「可验证」不等于「无噪声」。三类噪声在多轮 RL 中反复出现：计时抖动（同一 kernel 在不同负载下测得加速比波动）、oracle 边界（浮点容差附近的判定翻转）、以及模型主动构造的奖励 hacking 样本（例如把输出写成常量以通过特定用例、或利用 benchmark 的输入分布漏洞）。robust reward 的设计目标不是消除噪声，而是让奖励函数对这三类扰动的敏感度有界。

机制上采用「重复测量取稳健统计量 + 门控冗余」。计时侧对同一 kernel 做 k 次测量取中位数而非均值，因为均值会被偶发的调度尖峰拉偏；正确性侧对同一轨迹用两组独立用例（一组公开、一组留出）分别判定，只有两组都通过才置 g=1，这直接封堵「针对公开用例过拟合」的 hacking 路径。稳健聚合可写成截尾形式：

$$\tilde{s} = \operatorname{median}\bigl( s_1, \dots, s_k \bigr), \qquad g = \min\bigl( g_{\text{public}},\, g_{\text{holdout}} \bigr)$$

代价体现在评测预算上：k 次计时把单轮评测时延乘以 k，双用例把 oracle 调用次数翻倍，两者叠加使每条轨迹的评测成本显著上升。这是必须接受的交换——若省掉留出用例，模型会在几十轮内学会「只满足可见断言」，此时训练曲线仍然漂亮，但部署到真实输入分布上正确率崩塌，这类失败在离线指标上不可见，只能靠留出门控提前拦截。

另一个具体机制是奖励上限截断：当 s 超过某个由 SOL 推导出的物理上限时，不再线性给分而是饱和。原因是超过 roofline 的「加速比」几乎必然来自测量错误或输入退化（例如 kernel 提前 return 而未被 oracle 捕获），若继续给正奖励，等于奖励模型去攻击测量管线。截断后这类样本的梯度被压平，模型不会把「让计时器读数为零」当作可学习策略。工程判断是：截断阈值应略高于该算子族已知最优实现，留出实现改进空间但不容忍数量级异常。

三 · TRLOO：用留一法把多轮轨迹的基线估计做稳

策略梯度类方法（PPO/GRPO 系）的核心是优势估计 A = R − b，其中基线 b 的质量直接决定方差。多轮场景下，同一 prompt 采样出的多条轨迹长度不同、轮次不同、终局奖励分布偏斜，用「组内均值」做基线会把「长轨迹天然更容易拿高奖励」的结构性偏差混进优势里。TRLOO（leave-one-out 式的轨迹基线）的思路是：对组内第 i 条轨迹，用其余轨迹的奖励统计量作为它的基线，而不是用包含它自己的均值。

$$A_i = R_i - \frac{1}{N-1}\sum_{j \neq i} R_j$$

这个形式看似只是去掉一项，实际效果是消除了「自身奖励进入基线」造成的系统性收缩：当组内只有少数轨迹成功时，含自均值会把成功轨迹的优势压低，梯度信号变弱；留一法让成功轨迹相对「其余全失败」的基线获得完整正优势。对多轮而言还要再加一层：基线应按轮次分层计算，即第 t 轮的优势参照「同组同轮次的其他轨迹」，否则「第 1 轮」和「第 5 轮」的奖励分布被混在一起，基线既不代表早期也不代表晚期。

代价是统计效率：留一法在组规模 N 很小时方差反而上升（分母 N−1 小），因此组规模不能压得太低；同时分层基线要求每条轨迹的轮次对齐，若轨迹长度差异大，需要按「有效轮次」而非「物理轮次」分组，增加了实现复杂度。一个具体例子：组内 8 条轨迹，仅 1 条在第 4 轮修复成功并拿到高 R，含自均值基线被这条轨迹拉高，其自身优势接近 0，等于这次成功几乎不产生梯度；留一法下它的基线由其余 7 条失败轨迹构成，优势接近满额 R，这次修复被有效强化。这正是「平台期突破」在算法层面的一个来源——不是模型变强了，而是原本被基线吃掉的稀有成功信号被释放出来。

四 · 合成数据：从失败轨迹里反向造课程

多轮 RL 的样本效率瓶颈不在采样量，而在「有效修复样本」的稀缺：大多数轨迹在前两轮就失败并终止，能走到第 4、5 轮并翻盘的轨迹占比很低，而这些恰恰是信用分配最需要的样本。合成数据的角色不是凭空生成 kernel，而是把已有失败轨迹「重组成可训练的多轮样本」——具体做法是取一条终局失败的轨迹，定位其失败轮次的错误类型（编译错误、越界、数值偏差、性能不达标），然后以该错误状态为起点、以「已知正确实现」为终点，构造一条短程修复轨迹作为示范。

这类合成样本进入训练时有两条路径：其一是轨迹 SFT，即把合成轨迹当作监督数据做行为克隆，让模型先学会「看到这类编译错误应该怎么改」；其二是作为 RL 的热启动，把合成轨迹的正确修复段作为高优势样本注入组内，改善基线估计。两条路径的代价不同：SFT 路径消耗 token 少但容易过拟合到合成分布，RL 注入路径保持 on-policy 但需要真实评测每条注入轨迹（编译 + oracle + 计时），评测成本高。

课程学习的接口在这里：合成数据天然带有难度标签（错误类型 × 算子族 × 修复所需轮次），可以按「难度递进」排序喂入，先给单错误单轮修复，再给多错误多轮修复，最后给跨算子族迁移（例如把 reduce 的 bank conflict 修复经验迁移到 scan）。工程判断是合成比例要有上限——合成轨迹与真实轨迹的分布差异会随比例上升而放大，超过某个比例后模型学到的是「合成器偏好的修复风格」而非真实编译器的反馈语义，表现为真实评测上的正确率不升反降。这个上限应由「合成轨迹在留出用例上的通过率」动态校准，而不是拍一个固定百分比。

五 · 轨迹 SFT 与去重防污染：训练集与评测集的隔离带

轨迹 SFT 与普通 SFT 的差别在于样本单位是「整条交互序列」而非「单条指令-回复对」：一条样本包含多轮 user（编译器报错、oracle 判定、profile 摘要）与 assistant（kernel 代码、修复 patch）交替，损失通常只挂在 assistant 段上。这样做的机制收益是模型学会「读反馈再改」的条件行为，而不是「一次性写对」的静态映射。代价是序列长度膨胀：一条 5 轮轨迹的 token 数可达单轮的数倍，训练时的显存与吞吐压力随之上升，需要按轮次截断或对早期轮次做掩码。

去重防污染是多轮数据管线里最容易被低估的一环。污染有三种形态：其一是评测集泄漏——合成轨迹的「已知正确实现」若直接取自评测集中的参考 kernel，模型在评测时等于见过答案；其二是近似重复——同一算子的多条轨迹在代码层面高度相似（仅变量名不同），去重若只做字符串比对会漏掉；其三是跨卷污染——第 5 卷交互轨迹与第 3 卷评测分数若共享同一批 prompt，训练与评测的边界就模糊了。防污染的机制是「以算子语义指纹为键去重」：对每条轨迹提取其目标算子的签名（输入形状族、运算类型、精度要求）与代码的结构特征（循环嵌套深度、内存访问模式），在签名空间做近邻去重，并把与评测集签名重合的样本整体剔除。

代价是数据量收缩：严格去重会砍掉大量「同算子不同写法」的轨迹，而这些恰是学习多样实现风格的来源。工程判断是把去重分成两级——对评测集做硬隔离（签名重合即剔除，无例外），对训练集内部做软去重（保留少量近邻以维持多样性，但限制同一签名下的样本上限）。一个具体例子：某 matmul 变体的 200 条轨迹中，有 60 条与评测集共享同一形状族签名，硬隔离后剩 140 条；内部近邻去重再压到 90 条，同一签名上限设为 5 条后最终约 70 条。这个收缩比例意味着合成数据的产能必须提前规划，否则 RL 管线会在「样本不够」和「污染风险」之间反复拉扯。

六 · 奖励 hacking 监控面板：把数据侧异常变成可观测指标

多轮奖励与合成数据的组合会引入一类隐蔽失效：模型在训练分布上奖励持续上升，但上升来自对奖励函数漏洞的利用而非真实能力。监控面板的作用是把这类失效从「事后发现」变成「训练中可见」。面板的核心指标不是总奖励，而是奖励的分解与分布形态：正确性门控通过率、加速比的中位数与截断触发率、留出用例与公开用例的通过率差、合成样本与真实样本的奖励差、以及同一 prompt 组内奖励的方差。

具体机制是「差分报警」：当公开用例通过率上升而留出用例通过率不升（差值扩大），说明模型在拟合可见断言；当加速比中位数上升但截断触发率同步上升，说明模型在攻击计时管线；当合成样本奖励显著高于真实样本奖励，说明合成分布与真实反馈语义脱节。这三条差分信号各自对应第二节与第四节里的一个具体漏洞，面板把它们压缩成可读的趋势线，供训练侧决定是否暂停、调奖励权重或收缩合成比例。

代价是监控本身消耗评测预算：留出用例判定、截断统计、合成/真实分组都需要额外 oracle 调用与计时，面板越细，每条轨迹的评测成本越高。工程判断是把监控做成采样式而非全量式——按固定比例抽样轨迹做完整差分检查，其余轨迹只记录轻量指标，用采样估计趋势。这样面板的时延开销可控，同时保留了对 hacking 的早期发现能力。最终落在具体机制上：多轮 RL 的数据侧不是「多造样本」的问题，而是「让每条样本的奖励可分解、可归因、可隔离」的问题——奖励分解决定信用分配能否落地，留出门控决定正确性能否外推，签名去重决定训练与评测的边界是否成立，三者共同构成多轮 RL 可信性的数据底座。
