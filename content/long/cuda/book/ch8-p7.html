一 · 轨迹清洗：把 RL 日志变成可训练资产

第 7 卷留下的 RL 轨迹是原始矿石，不是数据资产。一条轨迹里同时混着：agent 的思考文本、工具调用参数、kernel 源码的多个版本、编译器的 stderr、NCU 的指标 dump、最终判定结果。直接拿去做 SFT，模型学到的是“日志格式”而不是“修复策略”。清洗规则要按“可验证信号密度”分层：第一层是判定结果（编译通过/失败、数值对/错、roofline 达标与否），第二层是失败原因归类（编译错误、数值偏差、越界、性能不达标），第三层才是自然语言解释。清洗的第一步是把每条轨迹切成“状态-动作-观测”三元组，只保留观测中包含可验证信号的那些步。

具体机制上，用一条判定函数 V(τ) 给轨迹打分：V(τ)=1 当且仅当最终 kernel 通过正确性 oracle 且达到性能阈值，否则为 0。清洗时按 V 分桶，但桶内还要按“修复步数”排序——同样是成功轨迹，三步修好的比十步试错的价值高得多，因为后者混入了大量无效探索。代价在这里：轨迹清洗是离线批处理，单条轨迹的解析成本主要是 NCU 文本的解析（正则匹配指标行），一条 50 步的轨迹解析耗时在毫秒级，但一个卷的轨迹量级是万条，清洗流水线的吞吐瓶颈在磁盘 IO 而非 CPU。工程判断是：清洗规则必须版本化，因为下游 SFT 配比一旦变化，需要回溯“这条样本当时是按哪版规则留下的”。

一个具体例子：某条轨迹里 agent 先写了越界的 shared memory 索引，编译通过但运行时报 illegal memory access，随后它把索引改成 blockIdx.x*blockDim.x+threadIdx.x 并加了边界判断。清洗时这条轨迹被切成两步：第一步的观测是运行时报错文本，第二步的观测是通过 + 性能达标。两步都保留，但打上不同的标签——第一步进负例池，第二步进正例池。这样同一条轨迹既贡献了“错误长什么样”，也贡献了“怎么修”。

二 · 多轮奖励与 robust reward：让奖励不被单步噪声绑架

多轮 RL 的奖励设计难点在于：最终 reward 是稀疏的（只有最后一步有判定），而中间步骤的观测（编译错误、数值偏差）本身携带信息。朴素做法是只给终局 reward，结果是信用分配完全靠 policy gradient 自己猜，冷启动阶段方差极大。robust reward 的做法是把终局 reward 拆成“可验证的硬信号”和“过程性的软信号”，并对软信号做截断与归一化，防止某一轮的工具输出格式异常（比如 NCU 因权限失败返回空文本）把整条轨迹的 reward 拉偏。

$$r(\tau)=\mathbb{1}[V(\tau)=1]\cdot(1+\lambda\cdot s(\tau))-\mu\cdot\sum_{t}\mathbb{1}[\text{invalid}(o_t)]$$

其中 s(τ) 是性能相对 roofline 的归一化得分，invalid(o_t) 标记观测是否为空或格式损坏，μ 是惩罚系数。关键在于 invalid 项只惩罚“工具坏了”而不惩罚“模型试错了”——后者是学习信号，前者是噪声。robust reward 的另一层是奖励裁剪：把 s(τ) 截断到 [0,1]，避免某个 kernel 因为偶然的 cache 命中把 reward 推到异常高，导致策略过拟合到那一个形状。代价是裁剪引入了偏差，最优策略可能被低估，但换来的是冷启动阶段方差下降，训练曲线不再剧烈震荡。

具体例子：某轮 agent 调用了三次 NCU，前两次因为容器权限返回空，第三次成功。如果不做 invalid 惩罚，模型会把“调用 NCU”这个动作和最终成功关联起来，学到“多调几次 NCU 就行”的错误策略。加了 invalid 项后，前两次空观测被标记为负贡献，模型学到的是“确保 NCU 可用的前提下再调用”。这里的时延代价是：每次工具调用都要做一次格式校验，单次校验在微秒级，但多轮 RL 的 rollout 吞吐会因此下降几个百分点——这是为奖励稳定性付的固定税。

三 · TRLOO：用留一法估计基线，压低冷启动方差

REINFORCE 类算法的方差来自基线估计。多轮 kernel 任务里，同一个 prompt 采样出的多条轨迹，其终局 reward 分布高度偏斜——大部分是 0，少数是 1。用均值做基线时，基线被大量 0 拉低，导致成功轨迹的 advantage 被放大到不稳定。TRLOO（leave-one-out）的思路是：对每个样本，用同组其他样本的 reward 均值作为基线，而不是全局均值。这样每条轨迹的 advantage 只和“同题的其他尝试”比较，天然做了题目难度归一化。

$$A_i=r_i-\frac{1}{K-1}\sum_{j\neq i}r_j$$

其中 K 是同组采样数。TRLOO 的代价是：它要求同组样本必须来自同一个 prompt 且同一轮策略，否则基线不可比。这意味着 rollout 阶段要维护分组结构，采样器不能随意打乱。另一个代价是 K 不能太小——K=2 时基线就是另一条轨迹的 reward，方差反而大；工程上 K 取 4 到 8 是常见折中，但每增加一倍的 K，rollout 的 GPU 时延就翻倍，因为同一 prompt 要跑更多次生成。TRLOO 在冷启动阶段的价值在于：它让“这题太难，全组都失败”的情况自动产生零 advantage，而不是让模型去拟合一个不可能的任务。

具体例子：同一道“实现 fused softmax”的题，采样 6 条轨迹，5 条编译失败，1 条通过但性能只有 roofline 的 40%。均值基线是 0.067，那条通过的轨迹 advantage 是 0.93，被过度放大。TRLOO 下，那条轨迹的基线是其余 5 条的均值 0，advantage 是 0.4（归一化后），梯度更新温和得多。代价是这条轨迹的学习信号变弱，但换来的是不会因为一条偶然成功就把策略带偏。

四 · 合成数据：从 profile 文本反推 SFT 样本

第 6 卷的 profile 文本是合成数据的富矿，但直接喂给 SFT 会让模型学会“背诵指标”而不是“解释指标”。合成数据的构造要围绕“因果链”而不是“指标清单”：给定一段 NCU 输出，样本的输入是“这段 profile 对应的 kernel 源码 + 指标摘要”，输出是“瓶颈归因 + 下一步修改建议”。构造时用规则模板生成候选，再用一个更强的模型（或人工）做过滤，只保留归因正确的样本。这里的关键机制是“反事实增强”：对同一个 kernel，人为改动一个参数（比如把 tile size 从 128 改成 64），重新 profile，得到一对“改前/改后”的样本，让模型学习参数与指标之间的因果而非相关。

代价在合成数据的验证成本：每条合成样本都要经过一次真实编译 + profile 才能确认标签正确，单条样本的端到端时延是秒级（编译 + 运行 + NCU 采集），万条样本就是数小时的集群占用。另一个代价是分布偏移——合成数据来自规则模板，模板覆盖不到的 kernel 形状（比如非常规的 reduction 维度）在 SFT 后仍然表现差。工程判断是：合成数据只用于“冷启动打底”，不追求覆盖全部形状，覆盖率的缺口留给 RL 在线探索去补。具体例子：用 200 条“shared memory bank conflict”的合成样本做 SFT 后，模型在面对新的 transpose kernel 时能主动提到 padding 策略，但对 swizzle 的细节仍然要靠 RL 阶段的试错才能学会。

五 · 轨迹 SFT 与去重防污染：配比、隔离与版本对齐

轨迹 SFT 的核心决策是配比：成功轨迹、失败轨迹、合成 profile 样本三者的比例。失败轨迹做负例的价值在于让模型见过“错误长什么样”，但比例过高会让模型学会“如何失败”。工程上的做法是失败轨迹只保留“有明确修复路径”的那些——即同题存在成功轨迹、且失败轨迹的观测能指向具体错误类型。没有修复路径的失败（比如题目本身超出硬件能力）直接丢弃，因为它们只贡献噪声。

去重与防污染是数据资产可信度的底线。去重分两层：文本级去重（同一 kernel 源码的多次出现）和语义级去重（不同写法但同一优化策略的样本）。防污染的关键是评测集隔离——SFT 数据里不能出现任何评测集的 prompt 或其变体，否则评测分数虚高。具体机制是维护一个 prompt 指纹表（对 prompt 做规范化后哈希），SFT 样本入库前查表，命中即剔除。代价是哈希碰撞会误杀少量合法样本，工程上接受这个代价，因为漏杀的代价（污染评测）远大于误杀。

版本对齐是最后一个工程判断：数据版本必须和基准版本绑定。基准的口径一旦变化（比如 roofline 的算法更新），旧数据里的“达标”标签就不再可信，必须重新判定或打上版本标签隔离。具体例子：某批 SFT 样本是在旧版 roofline 下标记为“性能达标”的，新版口径收紧后这批样本的标签失效，如果不做版本隔离，SFT 后的模型会系统性地低估性能门槛。代价是每次基准版本升级都要触发一次数据重判，重判的算力成本与初次清洗相当，但这是数据资产可复用性的前提——没有版本对齐，数据资产就是一次性的。

当奖励信号本身不可信：robust reward 的边界与轨迹数据的系统代价

多轮 RL 的奖励并不总是来自一个干净的 oracle。在 kernel 生成场景里，奖励往往由“编译通过 + 正确性校验 + 相对加速比”三段拼成，任何一段的判定抖动都会把梯度带偏。robust reward 的核心机制不是把奖励调平滑，而是把奖励拆成可审计的分项并显式建模其置信度：设第 i 条轨迹的分项奖励为 ricompile、ricorrect、riperf，则合成奖励写成加权下确界而非简单求和：

$$R_i = \min\Big(w_c\, r_i^{\text{compile}},\; w_k\, r_i^{\text{correct}},\; w_p\, \hat{s}_i\Big) - \lambda\,\mathbb{1}[\text{flaky}_i]$$

其中 ŝi 是经过多次重复计时取中位数后的加速比估计，flakyi 标记该轨迹在重复校验中出现过判定翻转。取下确界而非加权和，是为了让“编译过但算错”的轨迹无法用高加速比补偿——这是 kernel 场景与通用 RLHF 最本质的差异：正确性是硬门，性能只是软门。失效条件很明确：当正确性 oracle 本身依赖浮点容差、而不同 GPU 架构的归约顺序又不同时，同一份 kernel 在不同卡上可能一次通过一次失败，此时 flaky 标记会把大量本可用的轨迹打成负例，奖励分布整体左移，策略退化为“只生成保守的、几乎不改写的小 kernel”。系统代价体现在校验预算上：每条轨迹重复校验 k 次，正确性验证的时延随 k 线性增长，而 NCU profile 若也纳入奖励则单条轨迹的采集开销可达毫秒到秒级，直接压缩了每轮可采样的轨迹条数。工程上的折中是分层校验——先用廉价编译与形状检查筛掉大部分，再对幸存者做重复正确性校验，profile 只在偏好对构造阶段对少量样本采集。

TRLOO（token-level 或 trajectory-level 的 leave-one-out 基线）解决的是另一类偏差：同一 prompt 下采样 n 条轨迹时，用组内均值作基线会引入自我包含偏差，让高奖励轨迹的 advantage 被自身拉低。留一法基线 bi = (Σj≠i Rj)/(n−1) 使每条轨迹的 advantage 只与同伴比较，代价是当 n 很小（受显存与校验预算限制，实际往往只有 4–8）时基线方差极大，单条异常轨迹会污染整组的 advantage 符号。更隐蔽的失效条件是奖励尺度漂移：不同轮次之间 ŝi 的分布随基准版本变化，若 TRLOO 基线跨轮复用，advantage 会系统性地偏向早期容易的任务。因此数据版本必须与基准版本对齐——评测集的 kernel 形状、dtype、容差一旦改动，历史轨迹的奖励就不可直接比较，只能作为 SFT 语料而非 RL 信号。这里的 token 代价不在生成端而在存储端：每条轨迹要连同其分项奖励、校验次数、flaky 标记、profile 摘要一起落盘，一条完整轨迹的元数据体积可达源码本身的数倍，去重时不能只对源码做哈希，还要对“奖励指纹”做聚类，否则同一 kernel 在不同容差下的多次通过会被误判为独立样本而放大其权重。

合成数据与轨迹 SFT 的边界在于：合成数据能补形状覆盖，但补不了“失败模式”。用模板批量生成的 kernel 变体在语法与形状上分布很广，却极少落在真实编译器的边界行为上（寄存器溢出、shared memory bank conflict、warp divergence 的具体触发条件），因此纯合成冷启动会让策略学会“看起来对”的写法而在真实校验下大面积失败。可行的配比是把合成数据定位为形状与 API 覆盖的底座，把清洗后的真实轨迹（含失败轨迹作负例）定位为行为纠正层。失败轨迹进 SFT 时必须带“错在哪”的标注，否则模型学到的是错误模式本身；而 profile 文本进 SFT 还是仅进 RL 上下文，取决于它是否可被语言化——能写成“该 kernel 的 occupancy 受限于寄存器压力”的 profile 摘要适合进 SFT，原始 NCU 计数器表则只适合作为 RL 上下文里的检索片段，因为后者 token 密度低且噪声高。去污染是这套资产可复用的前提：评测集 kernel 的任何变体（改名、改 tile 大小、改循环顺序）都必须在训练前被剔除，否则 SFT 基座会把评测答案背下来，RL 阶段的奖励提升就变成记忆复现而非能力提升。去重的代价是编译时间——对每条轨迹做规范化后重新编译以确认语义等价，在万级轨迹规模下会把数据准备从分钟级推到小时级，因此实践中用 AST 规范化加形状签名做粗筛，只对疑似重复的小簇做编译确认。
