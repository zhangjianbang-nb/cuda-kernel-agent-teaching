一 · 从一次“分数对不上”的线上事故说起

设想一个具体的服务场景：某团队把 agent 生成的 Triton 融合算子（LayerNorm + 残差 + 量化）接进推理链路，内部基准报告显示端到端吞吐提升，回归测试全绿。上线两周后，真实流量下的 P99 时延反而变差，显存峰值抬高，且同一批 kernel 在另一张卡型上直接触发数值不一致告警。复盘时发现两件事：其一，内部基准的测试用例与公开 KernelBench L2 的若干题面高度重合，agent 在训练/检索环节已经“见过”这些形状，分数被系统性抬高；其二，基准只记录了“是否通过 + 相对加速比”，没有记录测试输入的形状分布与容差口径，导致无法判断这次退化是 kernel 本身的问题还是评测口径漂移。这个事故不是模型能力问题，而是基准本身的可信度问题——它恰好是本卷要处理的对象。

把这件事抽象成一句话：当 agent 的优化目标函数（基准分数）与被优化的真实目标（生产端到端收益）之间出现系统性偏差，且这种偏差不可被现有记录追溯时，整个“生成—优化—验证”闭环的梯度方向就是错的。本卷不讨论怎么让 agent 更会写 kernel（那是上一卷的脚手架与反馈问题），而是讨论那把尺子本身如何演化、如何防污染、如何保证升级后历史分数仍可比。

二 · 上一卷留下的三个缺口

第 1 卷交付的是任务分类法与公开基准的用法：KernelBench L1–L3 的算子粒度划分、TritonBench 的 Triton 原生任务形态、CUDA-lib 系的库级调用约束。它回答的是“有哪些题、怎么把题喂给 agent、怎么拿到执行反馈”。但它刻意没有回答三个问题，而这三个问题在本卷变成主线。

  • 缺口一：公开集的污染不可观测。第 1 卷把公开基准当作静态题库使用，默认题面与参考实现是干净的。但 agent 的生成过程会引入检索、few-shot 示例、以及多轮 RL 中的记忆效应；一旦题面或等价变体进入上下文，分数就不再是泛化能力的度量。第 1 卷没有提供任何检测手段，因为检测需要“私有 held-out”这个第 1 卷不存在的对象。
  • 缺口二：难度是平的。L1–L3 的分层按算子语义（elementwise、reduction、matmul 类）划分，但 agent 的实际失败模式更多取决于优化技巧的组合——是否需要 shared memory 分块、是否需要 warp 级规约、是否要处理非对齐 stride、是否要在 Triton 里手写 mask。同一算子在不同技巧约束下难度差异远大于跨算子差异。第 1 卷的分类法无法支撑“按技巧分层”的课程式评测。
  • 缺口三：分数没有版本坐标。第 1 卷的评测输出是一个标量或一组标量，没有绑定“这是哪一版基准、哪一版容差、哪一版硬件画像”。当基准题面修订、容差收紧、或新增私有题时，旧分数与新分数被混在一张表里比较，产生不可解释的“能力跃迁”。

这三个缺口的共同结构是：第 1 卷给了题库，没给题库的元数据与生命周期。本卷的产出——内部基准版本谱系、难度分层规则、防污染策略、基准变更记录——正是把这三种元数据补齐。

三 · 本卷的赌注：私有 held-out 是唯一可信的坐标系

本卷的核心赌注可以写成一个判断：在 agent 参与优化的条件下，任何被公开、被反复引用、被写进 prompt 的题面，其分数都会随时间单调失真；唯一能提供稳定梯度的，是一个持续轮换、不可被 agent 检索到的私有 held-out 集，以及一套让公开集与私有集分数可换算的锚定机制。这个赌注有代价，代价必须写清楚。

代价之一是统计功效。私有 held-out 不能公开，意味着它不能像公开集那样被社区大规模复现与讨论，题目数量受限于人工构造与审计成本。设公开集题量为 $N_p$、私有集题量为 $N_h$，若用通过率 $\hat{p}$ 估计能力，则两套集子的标准误分别约为 $\sqrt{\hat{p}(1-\hat{p})/N_p}$ 与 $\sqrt{\hat{p}(1-\hat{p})/N_h}$。当 $N_h \ll N_p$ 时，私有集上的分数抖动显著更大，单次评测的排序结论不可靠，必须靠重复采样与置信区间来补偿——这直接抬高评测的 token 与 GPU 时延成本。

$$\mathrm{SE}(\hat{p})=\sqrt{\frac{\hat{p}(1-\hat{p})}{N}},\qquad \Delta_{\text{detect}}\approx 2.8\sqrt{\frac{2\hat{p}(1-\hat{p})}{N_h}}$$

代价之二是可比性维护成本。私有集轮换后，新旧两版之间的分数不能直接相减，必须通过一组“锚题”（anchor tasks）建立桥接：锚题同时存在于新旧两版，且其参考实现与容差冻结不变。设新版整体难度相对旧版的偏移为 $\delta$，则可用锚题上的分数差估计 $\delta$，再把旧分数平移到新坐标系。这个过程本身要写进变更记录，否则半年后没人能解释为什么同一 agent 的分数跳变。

代价之三是编译与验证时延。私有集的每题都要携带独立的正确性 oracle（含边界形状、非对齐 stride、极端数值），oracle 的构造与形式审计成本远高于“跑一遍参考实现比对”。这部分在第 1 卷的 Oracle 与形式审计条目里已有方法论，本卷只关心它如何被绑定进基准版本，成为版本不可分割的一部分。

用一个具体例子锚定这个赌注：某融合算子（softmax + top-k + 散射写回）在公开 KernelBench L2 上的通过率长期维持在较高水平，但把它放进私有 held-out 并替换为生产流量里真实出现的“词表截断 + 变长序列”形状后，通过率明显回落。回落不是能力退化，而是公开集从未覆盖该形状分布。这个落差本身就是本卷要量化的对象——它衡量的是基准覆盖度，而不是 agent 水平。

四 · 难度按“优化技巧”分层的具体机制

本卷不做“按算子分层”的复述，而是给出按技巧分层的可执行规则。核心机制是：为每道题标注一组技巧标签（tiling、warp reduce、mask/边界处理、异步拷贝、layout 变换、数值稳定性技巧），并定义技巧标签之间的偏序关系，形成难度格。一道题的难度不是标量，而是它在格中的位置；agent 的能力画像也不是标量，而是它在各技巧维度上的通过率向量。

伪代码层面的分层判定可以写成：给定题目 $t$ 的技巧标签集合 $S_t$，若存在另一题 $t'$ 使 $S_{t'}\subset S_t$ 且 $t'$ 在相同形状下通过，则 $t$ 的难度不低于 $t'$；若 $S_t$ 与 $S_{t'}$ 不可比，则两题分属不同难度分支，分数不可直接平均。这个偏序让“难度分层规则”从拍脑袋变成可审计的构造：每新增一题，必须声明它相对已有题的标签包含关系，否则不予入库。

代价在这里体现为标注成本与评测 token。技巧标签需要人工或半自动审计，标签越细，入库越慢；而按技巧维度报告分数意味着每次评测要跑完整的技巧×形状矩阵，评测 token 与 GPU 时延按维度乘积增长。工程判断是：技巧维度控制在可管理的数量级，用偏序而非全序来避免组合爆炸——只报告“在 tiling 维度通过、在 mask 维度未通过”这样的向量，而不是要求每个维度都有独立题集。

具体例子：同一 reduction 算子，标注为“无 mask、对齐形状”的版本与标注为“含 mask、非对齐、需 warp reduce”的版本，在公开集里可能被归为同一难度档，但 agent 在前者上的通过率不能用来预测后者。按技巧分层后，这两个版本进入难度格的不同位置，评测报告直接暴露 agent 在 mask 处理上的系统性弱点——这正是第 1 卷扁平分层看不到的信号。

五 · 防污染策略的三个动作与它们的代价

防污染不是一句口号，本卷把它拆成三个可执行动作，每个动作都绑定一个代价。

  • 去重：对题面做语义等价判定（形状约束、参考实现的数学等价变形、注释与变量名归一化），把等价变体折叠为同一题族。代价是去重本身要跑参考实现的等价性检查，等价判定过松会漏掉污染变体，过紧会误杀合法的新题；工程上以“参考实现在一组随机输入上输出一致”作为等价的操作定义，并记录判定所用的输入分布。
  • 私有 held-out：题面、参考实现、oracle 与容差全部不进入任何 agent 可见的上下文，且按时间轮换。代价是前面算过的统计功效下降与锚定维护成本；此外私有集的存储与访问要隔离，防止通过日志或缓存侧信道泄漏。
  • 时间切分：按题目的入库时间划出训练可见窗口与评测窗口，评测窗口内的题在 agent 优化期间不可见。代价是时间切分会让“旧题新解”无法被公平比较——同一 agent 在不同时间点的分数差异混入了题目新鲜度因素，必须靠锚题桥接来剥离。

三个动作共同构成一个可观测的污染检测信号：若 agent 在公开集上的分数显著高于其在同题族私有变体上的分数，且该差距随训练轮次扩大，则判定为污染嫌疑。这个信号不需要证明 agent 真的“见过”题，只需要证明两套集子之间的分数差超出了统计噪声——它是一个可操作的工程判据，而不是道德判断。

具体例子：某 agent 在公开 L3 题族上的通过率与其私有同族变体上的通过率出现持续扩大的差距，触发污染嫌疑后，团队没有直接下结论，而是先检查该题族是否被写进了 few-shot 示例池；确认后把该族移出示例池并重建私有变体，差距回落。这个过程被完整写入基准变更记录，成为后续版本谱系的一个节点。

六 · 版本谱系与变更记录：让历史分数可比的最小机制

本卷的产出物是“内部基准版本谱系”，它不是一堆快照，而是一个带桥接边的有向图。每个版本节点记录：题集清单（含技巧标签与难度格位置）、容差与 oracle 版本、硬件画像、锚题集合、以及相对上一版的偏移估计 $\delta$。边记录桥接方式：哪些锚题被复用、$\delta$ 如何估计、估计的置信区间。没有这条边，两个版本的分数就不可比；有了这条边，旧分数可以被平移到新坐标系再比较。

变更记录的粒度必须到“单题级”：任何一题的题面修订、容差收紧、oracle 修正都要留下记录，并标注它是否影响锚题。若某题被选为锚题，其容差与参考实现冻结，不允许随版本漂移——这是锚定机制成立的前提。代价是锚题不能随能力提升而加难，长期看锚题会变得过于简单、区分度下降；工程上的处理是定期轮换锚题集，并在轮换时用重叠锚题做二次桥接，避免一次性断链。

具体到工程判断：版本谱系的维护成本主要不在存储，而在每次升级都要重新估计 $\delta$ 并验证桥接，这需要跑一遍锚题全集，消耗评测 token 与 GPU 时延。因此版本升级不应频繁到每次题集微调都触发，而应按“题集变更累积到影响难度格结构”或“污染检测触发重建”这两个条件来触发。这也解释了本卷故事映射里的转折：分数虚高被污染检测揭穿之后，倒逼的不是一次简单的题集替换，而是一次带锚题桥接的基准重建——重建后的分数与重建前不可直接比较，必须通过变更记录里的 $\delta$ 来换算。

把这条机制落到开头那个服务场景：如果当时团队已经维护了版本谱系与变更记录，复盘时就能回答“这次退化是 kernel 问题还是口径漂移”——查该 kernel 评测所绑定的基准版本、该版本的容差与形状分布、以及它与上一版之间的 $\delta$，三者一对，退化来源即可定位。基准演化史的意义不在于记录历史，而在于让每一次“分数变了”都能被拆解成能力变化与尺子变化两部分。

当分数开始说谎：基准迁移的边界与系统代价

以 LayerNorm 反向为例：KernelBench L2 上某版本把 shared memory 分块从 32 改到 64，公开集分数抬升，但同一 kernel 在私有 held-out 的变体形状（非 2 的幂 hidden、跨 stride 的 batch）上正确性 oracle 直接失败。这说明公开基准的分布覆盖不到“分块假设成立”的边界——一旦 hidden 不是 2 的幂，向量化加载退化为标量路径，带宽利用率掉到 roofline 的零头，而分数只反映公开集那一段。基准迁移的第一条边界因此不是“难度”，而是分布：公开集能测出 kernel 在已知形状上的峰值，测不出它在形状扰动下的退化斜率。防污染策略里的时间切分正是针对这一点——用提交时间晚于基准发布日的样本做 held-out，能暴露“对公开集过拟合”的 kernel，代价是这部分样本永远无法参与历史分数回溯，基准版本谱系必须同时记录“可比区间”和“不可比区间”。

迁移到私有 held-out 的系统代价可以写成一条约束：设公开集规模为 N_pub、私有集为 N_priv，单次评测的编译与 profile 开销为 c，则每轮 RL 的验证预算近似为 B = (N_pub + N_priv)·c·r（r 为重复采样次数）。私有集越大，污染检测的统计功效越高，但 token 与 GPU 时延线性上升；若把 N_priv 压到很小以省预算，去重后的 held-out 又会因样本稀疏而无法区分“真优化”与“记忆”。工程判断是：私有集按算子族分层抽样，每族保留足以覆盖形状扰动的最小样本数，把省下的预算投到多轮采样上——因为污染检测的假阴性代价（把污染 kernel 判为干净）远高于假阳性。

失效条件还有一条常被忽略：私有 held-out 本身会随时间腐化。若私有集来自内部历史提交，早期 kernel 的写法会渗入样本分布，使新 kernel 在“旧风格”上得分虚高。基准变更记录必须显式标注每次私有集重建的切分点，并冻结旧切分点上的历史分数，否则版本谱系里的可比性链条断裂。表里给出三类迁移方案的代价对照：

方案污染检测功效每轮验证开销历史可比性
纯公开集低低连续
公开+私有混合中中需标注切分点
全私有 held-out高高断裂，需重建谱系

因此本卷的赌注不是“私有集一定更好”，而是把基准当作有版本的软件工件来维护：每次升级都付出可比性断裂的代价，换取污染检测的统计功效。这个代价最终落在评测流水线的时延与 token 预算上，而不是落在 kernel 本身。
