一 · 多轮奖励的信用分配与轨迹级折扣

多轮 RL 在 kernel 生成上的核心难点不是“有没有奖励”，而是奖励落在哪一步。一次 agent rollout 里，模型可能先写一版朴素 CUDA、被 NCU 指出 occupancy 不足、再改 Triton 版本、最后才通过正确性 oracle。若把最终可验证奖励（编译通过 + 数值对齐 + 达到 SOL 阈值）平摊到所有 token，梯度会被大量无效探索稀释；若只给最后一步，前面真正有效的诊断与改写动作得不到强化。工程上常用的做法是把奖励拆成回合级：每个 turn 结束时由工具链给出一个结构化信号 r_t = (compile_ok, correct, speedup_bucket, profiler_flags)，再按轨迹做折扣聚合。

$$R(\tau)=\sum_{t=0}^{T}\gamma^{T-t}\,r_t,\qquad \gamma\in(0,1]$$

折扣因子 γ 的选择直接对应 token 预算：γ 接近 1 时，早期探索动作也能拿到梯度，但方差大、需要更多 rollout 才能收敛；γ 偏小时，模型倾向于“一次写对”，牺牲了多轮修复能力。代价是显式的——每多一轮工具调用就多一次编译（秒级到十秒级）与一次 profile（NCU 采集本身有 replay 开销），rollout 时延随 T 线性增长，而 GPU 显存被并行的多个 rollout 会话占住。具体例子：一个 L2 级别的 fused softmax 任务，第一轮编译失败（缺 shared memory 边界处理），第二轮修正后正确但带宽只有峰值的四成，第三轮引入向量化 load 后达标；若 γ=0.5，第三轮的奖励对第一轮的贡献被压到 1/4，模型学到的更可能是“别犯编译错”而非“会做向量化”。这正是把 profiler_flags 作为独立回合信号、而不是塞进最终标量的理由。

二 · Robust reward：让可验证信号抗噪

可验证奖励看似客观，实则有三类噪声源：其一，计时抖动——同一 kernel 在同一卡上重复测速的方差可达百分之几，若奖励用连续 speedup 直接回归，模型会去拟合测量噪声；其二，编译器的非确定性——同一份源码在不同 nvcc 版本、不同 -arch 下生成的 SASS 不同，正确性 oracle 通过但性能档位漂移；其三，oracle 自身的边界——浮点容差设得松，近似错误的 kernel 也能过。

robust reward 的工程手段是“分档 + 置信下界”。把连续 speedup 映射到离散桶（如相对基线的 1x/2x/4x/8x），桶边界留迟滞区间，避免在边界附近来回震荡导致奖励翻转；同时对重复测量取保守估计，用下界而非均值入账。

$$\tilde{r}=\min_{k\in\{1..K\}}\big(\text{bucket}(s_k)\big),\qquad s_k=\frac{t_{\text{base}}}{t_{\text{kernel}}}}$$

取 K 次测量的最差档位，等价于把“偶尔跑得快”排除在奖励之外，逼迫策略产出稳定实现。代价是采样成本：K 次重复计时意味着 K 倍的 GPU 时间占用，在共享集群上直接转化为排队时延；若 K 取 5、单次测量含 warmup 与多次迭代，一个 rollout 的评测环节就从百毫秒级升到秒级。另一个代价是奖励稀疏化——分档后梯度信号变成阶梯函数，需要配合优势归一化（组内减均值除标准差）才能稳定。具体例子：某 reduction kernel 在 K=3 测量中两次落在 4x 桶、一次落在 2x 桶（因 L2 命中差异），取 min 后记 2x；策略若想稳定拿 4x，必须消除对 cache 状态的隐式依赖，这恰好是工程上想要的鲁棒性。

三 · TRLOO：把留一法用在轨迹优势估计上

组相对策略优化（GRPO 类）用同一 prompt 下多条 rollout 的组内均值作基线，省掉 critic。但当组内样本数少、奖励分档粗时，均值基线会被“幸运样本”拉偏，优势估计的方差反而上升。TRLOO（leave-one-out 的轨迹级变体）的思路是：对组内第 i 条轨迹，用其余 n−1 条的奖励均值作基线，而不是含自身的全组均值。

$$A_i=R(\tau_i)-\frac{1}{n-1}\sum_{j\neq i}R(\tau_j)$$

这个改动在数学上把基线从“有偏的组均值”变成“对第 i 条无偏的对照”，在 n 较小（如 4 或 8）时对梯度噪声的抑制更明显。伪代码层面，采样阶段收集 rewards[n]，计算阶段对每个 i 求排除自身的均值，再做组内标准化后乘到 token 级 log-prob 上。代价有两块：一是实现上要维护每条轨迹的完整 token 序列与对应 reward，显存占用随 n×序列长度增长，长轨迹（多轮工具调用产生上万 token）时尤其明显；二是当组内奖励全同（全失败或全成功）时，留一均值与全组均值退化为同一值，优势全为零，该组样本被浪费——这要求采样端保证组内至少有一条成功、一条失败，否则 token 预算白花。具体例子：n=4 的组里三条轨迹因编译错误得 0、一条达标得 4x 桶奖励，全组均值为 1x 档，达标轨迹的优势被压到 3 档；留一法下该轨迹的基线为 0，优势为满档 4，梯度方向更干净。

四 · 合成数据：从算子签名反推任务与测试

私有 held-out 集不可能靠人工无限扩充，合成数据是维持基准规模的主力。对 kernel 任务而言，合成的最小单元不是自然语言 prompt，而是“算子签名 + 形状约束 + 参考实现”。生成流程通常是：从算子分类法（elementwise / reduction / matmul 系 / attention 系）采样一个模板，随机化 dtype、layout、shape 分布与边界条件（非对齐长度、空 tensor、极大 stride），再用高精度参考实现（CPU 或 PyTorch float64）生成期望输出与容差。

合成数据的质量门槛在于“可判定”：每个合成任务必须自带能区分正确与近似错误的测试用例，否则它只是给 RL 提供了噪声奖励。工程上会给每个任务生成一组边界形状，其中至少一个专门触发 mask 与尾块处理——这正是 kernel 最容易写错的地方。代价是生成与验证成本：一个合成任务要通过参考实现自检、在至少一种合法实现上跑通、并确认错误实现会被 oracle 拒绝，这三步都要占 CPU/GPU 时间；若批量合成上万任务，验证流水线本身就成为瓶颈。另一个代价是分布偏移：合成分布若过度集中在规整形状，策略会学到“只处理 2 的幂长度”的捷径，到了真实 held-out 的非对齐形状上崩溃。具体例子：合成一个 layer_norm 任务，shape 取 (B=17, N=1000)，N 非 2 的幂且不能被向量宽度整除，参考实现用 float64 计算均值方差；任何忽略尾块 mask 的实现都会在 oracle 上失败，这类任务对训练信号的价值远高于 (1024, 1024) 的规整样本。

五 · 轨迹 SFT 与去重防污染

RL 之外的另一条数据线是轨迹 SFT：把 agent 成功完成任务的完整交互（读题、写码、编译报错、修正、profile、再修正）作为监督样本。它的价值在于教会模型“工具调用的节奏”，而不是单纯模仿最终代码。构造时要做两件事：一是轨迹筛选，只保留最终通过 oracle 且中间步骤无作弊（如直接调用库函数绕过题目约束）的轨迹；二是步骤裁剪，把冗长的重复编译失败折叠，否则序列长度爆炸、训练 token 成本线性上升。

去重防污染是这条线最容易被忽视的环节。污染有三种形态：测试用例泄漏（合成任务的期望输出被模型在预训练中见过）、任务重复（同一算子的不同措辞导致训练集与 held-out 实质重叠）、轨迹重复（同一 prompt 的成功轨迹被多次采样后全部入池，造成过拟合）。工程手段是分层去重：任务级用签名与形状分布的指纹做近邻去重；轨迹级用工具调用序列的编辑距离或动作 n-gram 做聚类，每簇只保留一条代表；测试级则要求 held-out 的测试用例在训练阶段完全不可见，且用时间切分保证新合成的任务不与旧训练集同源。

代价体现在基准可比性上：每次去重与重建都会改变 held-out 的构成，历史分数不再可直接比较，必须靠基准变更记录（版本谱系 + 难度分层规则）来锚定。具体例子：某次合成批次里，同一个 softmax 任务以“row-wise softmax”“按行归一化”“stable softmax”三种措辞出现，任务级指纹去重后合并为一；若不合并，训练集里该算子的样本量被放大三倍，策略在其上的表现会虚高，而 held-out 上并无对应增益——这正是分数虚高被污染检测揭穿、倒逼基准从公开集迁移到私有 held-out 的那类转折的微观机制。防污染的最终判断标准不是“训练集干净”，而是“held-out 上的提升能被独立复现”，因此每次基准升级都要同时冻结测试用例、记录去重前后的样本计数与难度分布，让历史分数在版本谱系内可比、跨版本时明确标注不可比。

私有 held-out 的边界：当 RL 奖励本身成为污染源

把基准从公开集迁到私有 held-out，只解决了“题目被背下来”这一层污染。RL 阶段引入的是第二层：策略在训练中反复查询同一批 held-out 题目的执行反馈，奖励信号本身就带上了对这批题目的过拟合。此时分数虚高不再来自数据泄漏，而来自优化压力对评测集的定向拟合——模型没有背答案，但它学会了在这批特定形状、特定 dtype、特定规模上凑出能过 oracle 的 kernel。防污染策略若只做去重与时间切分，对这一层完全失效，因为题目从未出现在训练语料里，却出现在每一轮 rollout 的 reward 计算里。

机制上要把“训练可见的验证集”和“评分用的 held-out”在物理上切开。多轮 RL 的每一轮采样产生一批轨迹，奖励由正确性 oracle 加性能项构成：

$$ r = \mathbb{1}[\text{oracle 通过}] \cdot \big( \alpha \cdot \min(1, \frac{t_{\text{ref}}}{t_{\text{cand}}}) + \beta \cdot \mathbb{1}[\text{profiler 无异常}] \big) $$

其中 $t_{\text{ref}}$ 是参考实现时延，$\alpha,\beta$ 是权重。这个式子的失效条件很具体：一旦 oracle 只做数值容差比对而不做边界形状覆盖，策略会收敛到“在评测规模上正确、在邻近规模上越界”的 kernel；一旦性能项用固定参考时延做归一，策略会针对该时延对应的硬件状态过拟合，换卡即崩。工程代价是可量化的：每轮 rollout 若对 N 条轨迹各跑一次 NCU profile，profile 本身的开销远超 kernel 执行，采样吞吐被 profile 串行化拖垮，token 预算被大量消耗在重复验证而非探索上。因此 robust reward 的做法是把 oracle 拆成快速数值校验与低频全形状校验两层，前者每轮必跑，后者按轨迹采样率触发，用采样方差换吞吐。

TRLOO（leave-one-out 式的轨迹级基线）针对的是多轮奖励的方差问题。同一 prompt 下采 K 条轨迹，用其余 K−1 条的均值作基线估计优势，避免单条轨迹的极端奖励把梯度带偏。它的边界在于 K 很小时基线噪声大，K 很大时显存与采样成本线性上升；且当奖励是稀疏的 0/1 正确性信号时，LOO 基线退化为常数偏移，对优势估计几乎没有收缩作用，真正起作用的是把正确性信号与性能信号解耦后分别归一。合成数据的角色在这里变得微妙：用强模型生成参考 kernel 再让弱策略模仿，能快速填充正确性为正的轨迹，但这些轨迹的分布偏向“能写对的写法”，而非“写得快的写法”，轨迹 SFT 若直接吃这批数据，会把策略锚定在保守实现上，性能项长期不涨。去重防污染在合成数据上必须做语义级而非文本级：同一算子的不同写法在 token 层面差异巨大，但在执行语义上等价，文本去重放行、语义去重才拦得住。

一个具体例子能说明这套边界的代价结构：某算子族在私有 held-out 上有 12 个形状变体，训练侧只暴露其中 3 个作为多轮奖励的验证形状，其余 9 个仅在最终评分时出现。若不做这层切分，策略在这 3 个形状上的通过率会随轮次单调上升，而 9 个隐藏形状上的通过率在若干轮后开始回落——这不是随机波动，是优化压力把 kernel 推向了对固定形状的硬编码分支。检测手段是在每轮结束时对隐藏形状做一次低成本抽样执行，把“训练形状通过率”与“隐藏形状通过率”的差值作为污染告警指标；差值超过阈值即触发基准重建，而不是继续加轮次。系统代价是每轮多一次抽样执行与一次版本比对，换来的是历史分数可比性——基准变更记录必须同时记录形状集合的哈希与 oracle 容差参数，否则两次升级之间的分数差无法归因于模型能力还是评测口径。

私有 held-out 的污染检测为何会失效：奖励信号、去重粒度与轨迹 SFT 的三重耦合

把基准从公开集迁到私有 held-out，最容易被误判为“一劳永逸”的一步。实际失效点在于：污染检测本身依赖一个可计算的相似度阈值，而 RL 多轮奖励会把模型推向阈值附近的“合法擦边”样本。设去重判据为算子级签名 $$s(o)=\mathrm{hash}(\text{op\_type},\text{dtype},\text{shape\_bucket})$$，则私有集只保证 $$s(o_i)\neq s(o_j)$$ 不重复，却完全不约束优化技巧层面的同构——两个签名不同的算子可以共享同一段 tiling 或同一套 bank-conflict 规避写法。于是模型在私有集上仍能靠“技巧记忆”而非“算子推理”拿分，污染检测报告显示低重复率，分数却继续虚高。这是本卷基准谱系里最隐蔽的一类失效：去重粒度选在算子层，而奖励实际奖励的是技巧层。

第二个失效条件是 robust reward 的方差塌缩。多轮 RL 中若每轮奖励取 $$r_t=\mathbb{1}[\text{correct}_t]\cdot \mathrm{speedup}_t$$，一旦某条轨迹在第二轮就编译失败，后续轮次的奖励恒为零，TRLOO 式的留一估计会把这条轨迹的整体优势压到负值并连带污染同批次的其他轨迹——因为留一基线用的是批内均值，一条零奖励轨迹会把均值拉低，使真正有效的慢速正确解被误判为劣质。代价是 token：为修复这一偏差需要额外采样重放轨迹，单条样本的 rollout 长度从固定轮次膨胀到自适应轮次，编译时间与显存占用随重放次数线性上升。

第三个边界在轨迹 SFT 与合成数据的接口处。合成数据用于补足私有 held-out 覆盖不到的算子类别时，若合成器只按签名生成、不按优化技巧分层，产出的轨迹会系统性地偏向某几类写法，SFT 后的模型在 held-out 上表现为“会写但不会选”。一个具体例子：私有集里一个 reduction 算子要求跨 warp 规约，合成器却只生成单 warp 版本的正确轨迹，模型学到的是“正确但慢”的模式，speedup 奖励无法把它推过阈值。此时应把合成数据的准入条件从签名去重升级为技巧标签去重，并在基准变更记录里显式登记“技巧覆盖度”这一维度，否则历史分数在基准升级后不可比。
