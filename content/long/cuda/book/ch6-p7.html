一 · 从单轮标量到多轮向量：奖励的时序结构

硬件反馈进入 RL 之后，最先崩掉的不是策略，而是奖励的形状。单轮设定里奖励是一个标量 r∈ℝ，多轮设定里 agent 在第 t 轮拿到 NCU 指标、改一版 kernel、再测一次，奖励天然是一条轨迹 r₁…r_T，而这条轨迹里每一轮的观测都依赖上一轮的动作。把这条轨迹压成一个末端标量（最终 speedup）会丢掉一个关键信号：哪一轮的编辑真正带来了 occupancy 提升、哪一轮只是噪声。工程上必须把奖励拆成可归因的分量，否则 credit assignment 在 T 较大时退化成随机游走。

具体机制是逐轮差分奖励：设第 t 轮 kernel 的实测时延为 L_t，基线为 L₀，则

$$r_t = \alpha \cdot \frac{L_{t-1}-L_t}{L_0} + \beta \cdot \mathbb{1}[\text{correct}_t] - \gamma \cdot \text{tok}_t$$

第一项是时延改进的边际贡献，第二项是正确性门控，第三项惩罚 token 消耗。α、β、γ 的量级关系决定了 agent 是倾向于“稳扎稳打小步改”还是“赌一把大重构”。代价很直接：逐轮差分要求每一轮都真实跑一次计时，T 轮就是 T 次编译加 T 次 benchmark，编译时间与 GPU 占用随时延线性增长；若 T=8、单次编译 20 秒量级，一条轨迹的墙钟成本就落在分钟级，这是采样吞吐的硬约束。

一个具体例子：agent 第一轮把 global memory 访问合并，L 从基线降到 0.7 倍，r₁ 为正；第二轮试图加 shared memory 分块但 bank conflict 严重，L 反弹到 0.85 倍，r₂ 为负。若只给末端奖励，这一负反馈被淹没；逐轮差分则明确告诉策略“分块方向对、但 bank conflict 是坑”，这正是后续规则库要捕获的模式。

二 · Robust reward：让奖励对噪声与作弊都不敏感

GPU 计时本身有方差：同一 kernel 连续跑，受 clock throttle、L2 残留、并发干扰影响，时延分布有拖尾。把单次测量当奖励，等于把测量噪声直接灌进梯度。robust reward 的第一层是统计稳健性：对每个候选 kernel 取 k 次测量的中位数而非均值，并用 MAD 归一化离散度，只有当中位数改进超过噪声带才给正奖励。第二层是对“作弊式优化”的抵抗：agent 可能通过跳过边界检查、降低数值精度、甚至缓存输出来骗过计时，因此正确性 oracle 必须是硬门控而非软惩罚——一旦 oracle 失败，该轮奖励直接置零而非打折。

第三层是尺度稳健：不同 kernel 的绝对时延差几个数量级，若直接用毫秒做奖励，大 kernel 的梯度会压死小 kernel。归一化到相对基线的比值（speedup）并对数化，能把奖励压到有界区间。代价是信息损失：对数化后“从 2 倍到 4 倍”和“从 1 倍到 2 倍”奖励相同，但对 roofline 而言前者往往已接近 SOL、后者还在带宽瓶颈区，二者的优化价值并不等价。工程判断是：在 reward 里额外挂一个基于 SOL 利用率的项，让接近 roofline 的改进获得递减但非零的边际奖励。

具体例子：某 reduction kernel 的候选版本把 shared memory 用量翻倍换取 occupancy 提升，NCU 显示 occupancy 上去了但 memory throughput 反而下降，计时中位数只快了 3%，落在噪声带内。稳健奖励判定为“无显著改进”，避免策略把一次侥幸采样当成方向；同时规则引擎记录下“occupancy 与 throughput 背离”这一模式，供后续 prompt 注入。

三 · TRLOO：把 leave-one-out 用在轨迹级优势估计上

多轮 RL 里，同一 prompt 采样出多条轨迹，轨迹间共享前缀、分叉于不同编辑动作。若用朴素的 group-relative 优势（整组均值做基线），前缀部分的 token 会被多条轨迹重复计入，优势估计被前缀主导，分叉点的信号被稀释。TRLOO（trajectory-level leave-one-out）的思路是：对每条轨迹的优势，用“去掉该轨迹后的组内均值”做基线，使基线不包含被评估轨迹自身，从而消除自比较偏差；同时按轮次对齐，只在分叉之后的段落上计算优势，前缀段落的优势置零或按共享权重摊薄。

伪代码思路：对组内轨迹 i，令 R̄₋ᵢ 为除 i 外所有轨迹末端奖励的均值，Aᵢ = Rᵢ − R̄₋ᵢ；再按轮次把 Aᵢ 分配到第 t 轮的动作 token 上，分配权重正比于该轮相对前一轮的奖励差分。这样前缀 token 不获得梯度，分叉动作获得与其边际贡献成比例的信号。代价是方差：leave-one-out 在组规模小时基线噪声大，组内轨迹数少于 4 时优势估计抖动明显，需要更大的采样批次来压方差，直接推高 GPU 时延预算与 token 成本。

具体例子：同一 matmul 优化 prompt 采 6 条轨迹，4 条走 tiling 路线、2 条走向量化路线。朴素组均值基线会让 tiling 前缀吃掉大部分优势；TRLOO 下每条轨迹的优势只落在其独有的编辑动作上，tiling 组内部的“谁先合并访存”与向量化组的“谁先调 ILP”各自获得独立信号，策略不会因为组内多数派而压制少数派探索。

四 · 合成数据：从 profile 轨迹反向生成训练样本

真实 agent 轨迹昂贵：每条都要编译、跑 NCU、跑 SASS 提取。合成数据的价值在于把已经采集到的 profile 片段重组为新的训练样本，而不必每次都真跑。具体机制是“指标—动作”配对合成：从历史轨迹中抽出（NCU 指标快照，编辑动作，时延变化）三元组，按指标模式聚类，再对同类模式做动作替换与组合，生成“给定这份 stall reason 分布，应该做哪类优化”的问答对。SASS 片段同理，抽取关键指令窗口与对应的优化动作配对。

代价是分布偏移：合成样本的指标快照来自真实 kernel，但动作组合是人工拼接的，可能产生真实硬件上不成立的组合（例如在 occupancy 已饱和时建议继续加 block）。因此合成数据必须带一个可执行性过滤：把合成动作回放到真实 kernel 上跑一次正确性与计时，通过的才进训练集，这一步又把成本拉回真实执行，合成只节省了“采样探索”的部分而非“验证”的部分。token 成本上，合成样本的 prompt 更短（只含指标摘要与 SASS 窗口，不含完整对话历史），单样本 token 数显著低于真实轨迹，适合做大规模冷启动。

具体例子：把“stall reason 以 long scoreboard 为主、memory throughput 低”这一模式与“合并访存 + 提高 ILP”动作配对，合成数十条变体；回放过滤时发现其中一部分在已合并访存的 kernel 上无效，被剔除，留下的样本教会 agent 区分“访存未合并”与“访存已合并但延迟隐藏不足”这两种同表象不同因的场景。

五 · 轨迹 SFT 与去重防污染

轨迹 SFT 是把多轮成功轨迹直接做监督微调，关键在于选哪些轮进损失。全轨迹进损失会让模型学会“复述 NCU 报告”这种低信息密度的中间步骤；只取最终答案又丢掉硬件反馈的因果链。工程做法是按“决策点”采样：只对发生编辑动作的轮次计算损失，观测轮（读 profile、读 SASS）作为上下文不计算损失。这样模型学到的是“看到这份 stall 分布之后该做什么”，而不是“如何把指标抄一遍”。代价是有效 token 利用率下降，一条长轨迹里可能只有两三轮的 token 进损失，训练吞吐按轨迹数计而非按 token 数计，需要更大的轨迹池。

去重防污染是这条流水线的守门环节。KernelBench 系基准的题目有限，agent 探索出的高分 kernel 极易与评测集重叠，若把评测集里的 kernel 或其近似变体混进 SFT 或 RL 训练数据，评测分数就失去意义。具体机制是三层去重：源码级（对 CUDA 源码做归一化后哈希，去掉注释与空白）、结构级（对 SASS 关键片段做指令序列指纹，捕获换皮不改结构的变体）、语义级（对输入输出做数值指纹，捕获改了实现但等价于参考解的样本）。三层都过才算干净。

代价是召回与精确的权衡：结构级指纹过严会误杀合法的独立实现（两个人都写了标准的 shared memory tiling，指令序列相似但并非抄袭），过松则漏掉换皮样本。工程判断是结构级只做“高相似度告警”而非硬删除，把疑似样本隔离到 held-out 池，用它们在训练中做负样本或干脆不用。具体例子：某轨迹产出的 kernel 与基准参考解在源码级哈希不同，但 SASS 指令序列指纹高度重合，被隔离；复查发现它只是把循环展开因子从 4 改成 8，属于同一优化家族，进训练集会让模型对该题过拟合，隔离是正确的。

把这几层接起来看，硬件反馈驱动的 RL 数据流水线的真实瓶颈不在算法而在验证带宽：每一条进训练的轨迹都要过一次真实编译与计时，合成数据省掉探索但省不掉验证，去重省掉污染但省不掉指纹计算。工程上能压缩的只有 prompt 侧的 token（指标摘要、SASS 窗口裁剪）与采样侧的重复（TRLOO 让同一前缀的轨迹共享观测），而正确性 oracle 与计时这两步必须真跑。判断一条流水线是否可信，看的是它能不能说清“哪一轮的奖励来自真实硬件测量、哪一轮来自合成回放”，混在一起的数据集无法支撑可信评测的结论。

当硬件反馈成为奖励信号：多轮奖励的可信边界与系统代价

把 NCU 指标直接当奖励，最容易踩的坑是“指标可被优化却不代表 kernel 变快”。occupancy 从 25% 抬到 50% 可能只是把寄存器压力挪给了 shared memory，memory throughput 上升可能来自无效重复读，stall reason 里 long scoreboard 减少也可能只是把访存挪到了别的 warp 上等待。因此多轮奖励必须分层：第一层是硬约束（正确性 oracle 通过、无越界、无 race），第二层是计时数据（第 3 卷的 kernel 时延与端到端占比），第三层才是 NCU 派生指标（SOL 利用率、bank conflict 次数、stall 分布）。伪代码上，奖励可写成 r = 1[correct] · (α·speedup + β·ΔSOL − γ·regression_penalty)，其中 regression_penalty 对“时延变差但 SOL 变好”的样本施加惩罚，防止 agent 学会刷指标。代价是每轮都要跑正确性 oracle 与至少一次稳定计时，单条轨迹的验证时延从秒级升到分钟级，采样吞吐直接决定 RL 的 batch 规模上限。

TRLOO（token-level reward leave-one-out）在这里的作用不是替代 PPO，而是给“同一 prompt 下多条轨迹共享同一份 profile 反馈”解耦信用。当 agent 在一轮里同时改了 shared memory 分块和合并访存，最终 speedup 是两者叠加，若把整条轨迹的奖励平均分给所有 token，模型学不到“哪一步动作真正有效”。TRLOO 的做法是对每个 token 位置做 leave-one-out 基线：用同组其余轨迹的奖励均值作为该 token 的 advantage 基线，等价于 A_t = r(τ) − mean_{τ'≠τ} r(τ') 的 token 级分解。失效条件是组内轨迹高度同质（都卡在同一个 stall 上），基线方差趋近于零，advantage 退化为噪声；此时需要按 stall reason 分桶采样，保证组内至少有一条走了不同优化路径。系统代价是每组要采样 k 条完整轨迹并各自跑 profile，k 越大基线越稳，但 NCU 采集本身有开销预算（采样频率越高、指标越多，单次 replay 越慢），k 与采样频率构成直接的算力竞争。

合成数据与轨迹 SFT 的边界在于“profile 反馈的可迁移性”。把一次成功的 NCU stall 报告到 shared memory 分块的修改轨迹做成 SFT 样本，模型学到的是“看到 long scoreboard 高就调分块”的表面映射；换一个 bank conflict 主导的 kernel，这条轨迹就是负迁移。稳健做法是只保留“指标→假设→验证”的三元组，丢掉具体代码 diff，让模型在推理时重新生成动作。去重防污染在这个环节尤其关键：同一 kernel 的多次 profile 采样会产生大量近重复轨迹（仅时间戳和采样噪声不同），若不去重，SFT 数据会被单一 kernel 主导，RL 的 prompt 分布也会偏斜。去重粒度应落在“kernel 语义指纹 + 优化动作序列”上，而不是文本相似度，否则会把“同一动作在不同 stall 上下文下的合法变体”误删。代价是去重本身要维护指纹索引，且指纹碰撞会悄悄丢掉稀缺的正样本，需要在离线阶段用正确性 oracle 回放抽查。

反馈层级可信来源失效条件系统代价
正确性oracle 回放浮点容差过松每轮一次全量回放
时延第 3 卷计时噪声大于收益多次重复取中位数

落到工程判断：硬件反馈进入 RL 数据管线时，真正稀缺的不是指标数量，而是“指标变化与端到端收益之间的因果链”被正确归因的次数。agent 首次看懂 NCU stall 报告并自主改 shared memory 分块的那个拐点，之所以能成为性能跃迁，是因为那一轮里正确性、时延、SOL 三者同向变化，奖励信号没有歧义；一旦三者背离，多轮奖励就必须降级为“只信正确性与时延，NCU 指标仅作诊断上下文进 prompt”，否则 RL 会把模型训练成指标刷子而非 kernel 优化者。
