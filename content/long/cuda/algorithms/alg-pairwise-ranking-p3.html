一 · 评分公式的三层结构：从时延到概率

成对排序奖励的评分公式不是单一函数，而是一条从物理量到概率量的三级链路：原始时延 T_i → 对数归一化得分 s_i → 成对胜率 P(i≻j)。每一级都承担不同的工程职责，拆开看才能定位误差来源。

$$s_i=\log\frac{T_{\text{ref}}}{T_i},\quad P(i\succ j)=\sigma\left(\frac{s_i-s_j}{\tau}\right),\quad \mathcal{L}=-\sum_{(i,j)\in\mathcal{P}}\log P(i\succ j)$$

第一级 s_i 的作用是尺度消解：除以 T_ref 把绝对时延变成无量纲比值，再取对数把乘性误差转成加性误差。这一步的关键性质是：若两个 kernel 的测量时延同时被同一硬件系数 k 缩放（T_i'=kT_i），则 s_i'-s_j'=\log(T_j'/T_i')=\log(T_j/T_i)，与 k 无关——跨架构的时钟频率、SM 数量差异在差分中被约掉。这正是绝对时延奖励做不到的：绝对奖励下 k 直接进入奖励尺度，导致策略在不同架构间无法比较。

第二级 σ((s_i-s_j)/τ) 把得分差映射为 (0,1) 区间内的胜率。这里 τ 是温度参数，控制概率曲线的陡峭程度：τ 越小，微小时延差被放大为接近 0/1 的硬判决；τ 越大，曲线越平缓，胜率对噪声更宽容。工程上 τ 的选取必须与测量噪声的方差匹配——若测量抖动在 s 空间的标准差为 σ_n，则 τ 应显著大于 σ_n，否则两个实际等价的 kernel 会被随机判出接近 0 或 1 的胜率，梯度信号变成噪声。代价是 τ 过大时 P≈0.5 对所有对成立，损失梯度趋近于零，训练停滞。这是一个显式的偏差-方差权衡，不是可以“大概调一调”的超参。

第三级是负对数似然损失。对每个偏好对 (i,j)，若标注 i 胜，则损失为 -log σ((s_i-s_j)/τ)。关键推导一步：对 s_i 求梯度，

$$\frac{\partial \mathcal{L}}{\partial s_i}=-\frac{1}{\tau}\left(1-P(i\succ j)\right),\quad \frac{\partial \mathcal{L}}{\partial s_j}=+\frac{1}{\tau}\left(1-P(i\succ j)\right)$$

即梯度大小正比于模型当前判错的置信度 1-P。当模型已经以高置信度判对（P→1），梯度趋零，该对不再贡献学习信号；当模型判错或犹豫（P→0.5），梯度最大。这解释了为什么成对排序在 RL 中稳定：它自动把学习预算集中在“排序尚未学会”的对上，而不是像绝对回归那样对每个样本都施加同等量级的梯度。代价是：一旦偏好模型对某类对过早饱和，后续同分布的对全部失效，需要靠 held-out 一致性校验发现这种“过早收敛”。具体例子：两个候选 kernel 时延分别为 T_ref/2 与 T_ref/4，则 s 差为 log 2≈0.69；取 τ=0.5 得 P=σ(1.39)≈0.80，梯度系数 0.2/τ=0.4，仍有可观学习信号；若 τ=0.05，P≈1，梯度几乎消失——同一对数据在不同 τ 下贡献差异巨大。

二 · 时延项的稳健化：为什么用比值而非均值

公式里的 T_i 不是单次测量值，而是稳健统计量。若直接用算术平均，一次异常慢的 launch（例如被其他进程抢占 SM）会把 T_i 拉高，进而把 s_i 压低，制造一个虚假的“劣于”标注。工程上取 T_i 为中位数或截尾均值，并显式记录测量次数 n 与离散度。

推导的关键一步在于误差传播。设单次测量噪声标准差为 σ_m，取 n 次的中位数，其标准误近似 1.25σ_m/√n（中位数相对均值的效率损失因子）。进入 s 空间后，由 s=log(T_ref/T) 得 ∂s/∂T=-1/T，故 s 的噪声标准差为 σ_m/(T√n) 量级。这给出一个可执行的采样预算判据：要让 s 噪声低于 τ/3，需 n ≳ (3σ_m/(Tτ))²。注意 T 越小（kernel 越快），同样的绝对抖动在 s 空间被放大得越厉害——快 kernel 的相对测量误差更大，这是成对比较在高速区间必须加密采样的原因。

性能代价直接体现在采样成本上：每个偏好对需要两个候选各自编译、验证、测速，且测速需 n 次重复。相比单候选绝对奖励，采样开销约翻倍再乘以 n。在 RL 训练循环中，这意味着每步可用于策略更新的偏好对数量受限于 GPU 机时，而不是受限于策略网络吞吐。一个具体例子：若单候选测速需 n=30 次重复以压住噪声，则一个偏好对的成本是 60 次 kernel 执行加上两次编译；当候选来自 Triton 或 CuTe 生成、编译时间本身在秒级时，编译时间而非执行时间成为采样瓶颈，此时偏好对的吞吐由编译队列长度决定。

另一个代价是时延不可比的场景。当两个候选的正确性状态不同（一个通过、一个失败），时延比较无意义，必须走正确性优先分支（见下节）。当两个候选运行在不同的隐藏 shape 上，比值 T_ref/T 仍可比，但前提是 T_ref 对同一 shape 取——跨 shape 的 T_ref 不同，s 差不再纯粹反映 kernel 质量。这要求偏好对构造时锁定 shape，把 shape 分布抽样交给上游的数据管线，而不是让评分公式去吸收 shape 差异。

三 · 正确性优先的硬门槛与奖励构造

偏好标注不是简单的“谁快谁赢”，而是两级字典序：先比正确性，正确性相同才比时延。这一条把正确性从软惩罚变成硬约束，直接改变奖励的几何形状。

设候选 i 的正确性判定为布尔量 c_i∈{0,1}（由 fp64 参考 oracle 与合约校验给出，判定机制不在本节展开）。偏好构造伪代码如下：

  • 若 c_i≠c_j：胜者取 c=1 的一方，标注为确定性对，不进入时延比较。
  • 若 c_i=c_j=0：双方均错，该对丢弃，不产生偏好信号——避免模型学习“哪个错误更快”这种无意义排序。
  • 若 c_i=c_j=1：进入时延比较，按 s_i-s_j 与 τ 判定胜者；若 |s_i-s_j| 小于噪声阈值，标注为平局或丢弃。

关键推导一步：把正确性写成对损失的乘性门控。定义有效对集合 P_eff = {(i,j): c_i=c_j=1 且 |s_i-s_j|>θ}，则训练损失只在 P_eff 上求和。这样做的效果是，损失函数对“快但错”的候选不产生任何正梯度——它既不会因为快而被奖励，也不会因为错而被单独惩罚（惩罚由正确性门控在采样阶段完成，错误候选根本不进入时延对）。这从结构上堵死了奖励黑客的一条主路径：策略无法通过牺牲正确性换取时延得分，因为错误候选在偏好对构造阶段就被剔除。

代价有两个。其一是信号稀疏：当候选池中正确率低时，P_eff 很小，每轮采样产生的有效对数量骤降，训练吞吐下降。其二是确定性对的梯度特性：对 c_i=1, c_j=0 的对，若仍用同一 σ 公式，则 s 差无定义（错误候选的时延不可信），必须改用常数间隔的 hinge 形式或直接以固定大间隔标注，否则会把不可信的时延引入梯度。工程判断：正确性对应当作独立的分类头或独立的奖励通道处理，而不是硬塞进同一个 Bradley-Terry 似然里。具体例子：候选 A 正确但时延 2T_ref，候选 B 错误但时延 T_ref/2；若误用纯时延比较，B 胜，策略会学到“牺牲正确性换速度”；正确性优先下 A 胜，且 B 根本不进入时延对，梯度只推动 A 类候选的时延优化。

四 · 显存与批内归约：损失计算的实现约束

损失公式看似是逐对求和，但在 GPU 上实现时，P 集合的组织方式决定了显存占用与归约效率。设一轮采样产生 N 个候选、构成 M 个偏好对，若朴素地为每对物化 s_i、s_j、P、梯度中间量，显存为 O(M) 个标量加上反向传播的激活缓存。

关键推导一步：Bradley-Terry 损失的梯度只依赖得分差 d=s_i-s_j，而不依赖 s_i、s_j 各自的值。因此可以把每对压缩为单个标量 d 参与前向，反向时再按 ∂L/∂s_i=-∂L/∂s_j=g(d) 散射回两个端点。这把每对的激活缓存从两个得分降为一个差值，显存减半；更重要的是，归约可以在 d 空间完成，避免为每对保留独立的 σ 输出。

批内归约的实现要点是按候选索引聚合梯度：一个候选可能出现在多个对中（作为胜者或败者），其总梯度是各对贡献之和。伪代码思路：

  • 前向：对每个对计算 d_k，得到 g_k = -(1-P_k)/τ（若第 k 对中 i 胜）。
  • 反向：用 index_add 把 g_k 累加到 grad[s_i]，把 -g_k 累加到 grad[s_j]。
  • 归约后按候选去重，得到每个候选的净梯度，再回传至策略。

代价是 index_add 的原子操作在候选被高频引用时产生写冲突，显存带宽成为瓶颈；当 M 远大于 N（每个候选参与多对）时，散射写放大的带宽开销可能超过前向计算本身。工程上按候选分桶、先做局部归约再合并，可把原子冲突降到可接受水平。具体例子：N=64 个候选、M=256 个对，平均每候选参与 8 对；若直接对 256 个对做原子散射，每个对的两次写共 512 次原子操作，而分桶后每桶 8 个对先串行累加再单次写回，原子操作降到 128 次，写带宽降为四分之一。这个量级的差异在每步训练都发生时，直接决定偏好模型能否与策略更新同步推进。

五 · 一致性校验的误差界与 held-out 判据

偏好模型可能学到与真实时延排序不一致的偏差——例如偏好某种代码风格、某种 tile 尺寸写法，而非真实速度。一致性校验的目的不是证明模型正确，而是给出一个可操作的误差界，决定该偏好模型能否继续驱动策略优化。

设 held-out 对集合为 H，每对带真实时延排序标签。定义排序一致率 ρ = (1/|H|)Σ 1[模型判胜方 = 真实胜方]。关键推导一步：把 ρ 与 τ 联系起来。若模型对某对的得分差为 d，则判对概率为 σ(d/τ)；真实标签由时延差决定。当 τ 过大，σ(d/τ)→0.5，ρ 趋近随机猜测；当 τ 过小，模型对噪声过拟合，held-out 上 ρ 下降。因此 ρ 对 τ 呈单峰，存在最优 τ。工程判据：在 held-out 上扫描 τ，取 ρ 最大处；若最大 ρ 仍低于预设阈值（例如显著高于 0.5 但未达可用水平），则偏好模型不可信，应暂停其驱动策略更新，回退到更保守的排序规则或增加采样。

误差界还有一层：ρ 的置信区间宽度随 |H| 缩小，约为 1/√|H| 量级。这意味着 held-out 对太少时，ρ 的波动本身就可能掩盖真实退化。代价是 held-out 对不参与训练，占用采样预算；若每轮训练抽 M 个对、其中固定比例划给 held-out，则训练信号按比例减少。具体例子：若 |H| 只有几十对，ρ 的抽样波动可达数个百分点，无法区分“模型退化”与“抽样噪声”；此时应优先扩大 |H| 而非调 τ，因为 τ 的扫描在噪声主导下会选出虚假的最优点。

一致性校验还必须区分两种不一致：系统性偏差（模型稳定偏好某类代码风格）与随机不一致（噪声导致）。前者表现为 ρ 在特定子群上显著低于整体，可通过按代码特征分桶检测；后者表现为 ρ 随 |H| 增大而回升。工程判断：系统性偏差一旦检出，不能靠调 τ 修复，必须回到偏好对构造阶段检查标注是否引入了与代码风格相关的伪相关——例如编译时间被误计入时延、或某种写法的 kernel 在测速时被优先调度。

六 · 奖励尺度漂移的抑制：从公式到训练稳定性

成对排序规避了绝对时延的尺度问题，但引入了新的漂移源：s 的参考点 T_ref 若随轮次变化，s 的绝对位置漂移，虽然差分 s_i-s_j 不受影响，但策略若同时使用绝对得分作为辅助信号，漂移会渗入。更隐蔽的漂移来自偏好对分布的偏移：随着策略变强，候选池整体变快，s 差分布向零集中，P 趋近 0.5，梯度信号减弱——这是成对排序的“饱和漂移”。

关键推导一步：设候选池时延分布的对数标准差为 σ_s，则随机一对的 |d| 期望正比于 σ_s。策略优化会压缩 σ_s（好候选聚集），导致 E[|d|] 下降，P 向 0.5 靠拢，梯度系数 (1-P)/τ 的期望下降。抑制手段是让 τ 随 σ_s 自适应缩放：τ ∝ σ_s，保持 d/τ 的分布形状不随训练漂移。这不是调参技巧，而是维持损失函数几何形状不变的必要条件。

代价是自适应 τ 需要每轮估计 σ_s，估计本身消耗采样；且 τ 变化会改变历史对的损失权重，若与经验回放混用，旧对的梯度与新 τ 不匹配，产生偏置。工程判断：τ 的自适应应缓慢（低通滤波），且只在 held-out 一致性校验通过后生效，避免 τ 的快速抖动把训练引入振荡。具体例子：训练初期候选池时延跨度大，σ_s 大，τ 取较大值使 P 分布展开；训练后期候选聚集，σ_s 缩小，若 τ 不变则 P 全部挤向 0.5，梯度消失；τ 随 σ_s 缩小后，P 分布恢复展开，梯度信号维持。这一条把“奖励尺度漂移”从一个定性担忧变成了可测量的量：监控 E[|d|]/τ 的滑动均值，偏离设计区间即触发 τ 重估。

成对偏好的边界：何时失效、代价落在哪里

成对排序奖励的稳定性来自“同 prompt 同环境下的相对比较”，它的失效条件也正藏在这个前提里。第一类失效是时延差落入噪声带：当两个候选的稳健时延差小于测量抖动（多次重复的方差、时钟与占用率波动），标签本身接近随机，Bradley-Terry 的似然梯度会把噪声当信号拟合。此时损失对 $\Delta=s_i-s_j$ 的敏感度由 $\sigma'(\Delta/\tau)=\sigma(\Delta/\tau)\bigl(1-\sigma(\Delta/\tau)\bigr)$ 给出，在 $\Delta\approx 0$ 处取最大值 $1/4$——恰好是信噪比最差的区间梯度最强，这是需要显式设“平局带”（$|\Delta|<\epsilon$ 的对直接丢弃或标为 tie）的数学理由，而不是工程洁癖。第二类失效是偏好模型学到风格偏差：若训练对中某种代码形态（如更长的 unroll、特定 tile 尺寸）恰与胜者相关，模型会把“像赢家”误当“更快”，在 held-out 对上表现为排序一致性下降，而策略侧会朝该风格收敛——这是奖励黑客在成对设定下的变体，校验只能靠定期用真实时延重排 held-out 对来发现。

系统代价要分三笔算。采样侧：每对偏好需要两个候选都完成编译、正确性验证与测速，成本相对单候选评估翻倍，且编译时间在 Triton/CuTe 变体上往往占大头，偏好对吞吐受编译队列而非 GPU 吞吐限制。训练侧：pairwise ranking loss 的每个样本只提供一次比较，信息量低于带绝对值的回归，达到同等排序精度需要更多对，token 与算力开销上升。部署侧：偏好模型是策略优化的在线打分器，其前向时延进入 RL 内循环，若模型本身是 LLM 判官，单次打分时延可与 kernel 测速同量级，必须异步批处理。

落到可实现层面，标签生成应写成带门控的伪代码：先跑正确性，任一方失败则按“正确优先”直接定胜者且不进入时延比较；双方均正确时取 $k$ 次重复的中位数时延 $T_i,T_j$，仅当 $|T_i-T_j|/\min(T_i,T_j)>\epsilon$ 才产出偏好对，否则标记 tie 并从损失中屏蔽。这一条门控同时压掉噪声标签与“快但错”的奖励黑客，代价是有效对数量下降、需要更多采样来补足训练集规模——这是本方案在数据效率上必须支付的固定税。
