一 · 评分门控的代数骨架：从 Δ_BI 到 R_final

Batch 不变性门的全部语义压缩在三行式子里：

$$\Delta_{\text{BI}}=\max_i\left|y_i^{(B=1)}-y_i^{(B)}\right|,\quad \text{Invariant}=\mathbb{1}\left[\Delta_{\text{BI}}\le \tau_{\text{BI}}\right],\quad R_{\text{final}}=R\cdot\text{Invariant}$$
第一项是度量，第二项是判决，第三项是执行。三者不是并列关系，而是严格串行的：度量决定判决，判决决定奖励的乘性因子。这个结构的关键一步在于把“不变性”从布尔谓词提升为奖励的乘子，而不是加法惩罚项。加法惩罚（如 R − λ·𝟙[失败]）在 RL 里会被策略利用——只要基础奖励 R 足够大，策略宁可牺牲不变性换取更高的单 batch 性能分。乘性因子则把不变性变成硬约束：任何 Δ_BI 超阈的候选，其梯度贡献直接归零，搜索无法用性能收益“赎买”非确定性。

逐项拆解。Δ_BI 取的是逐元素最大绝对差，而非均值或范数。选 max 而非 L2 的理由是：batch 不变性破坏往往只发生在少数位置——归约顺序改变时，绝大多数元素仍然逐位相同，只有跨 tile 边界的累加项出现偏差。用均值会把这类稀疏故障稀释到噪声水平以下。用 max 则保证“最坏的那个 token”拥有一票否决权。代价是 max 对浮点噪声极度敏感：两个数学上等价但指令序列不同的 kernel，其 max abs diff 可能落在 1e-6 量级，因此 τ_BI 必须与数据量级挂钩，而不是固定常数。工程上通常取相对形式 Δ_BI / max(|y^{(B=1)}|, ε) ≤ τ_rel，把绝对阈值换成量级归一化的阈值，否则大数值输出（如 logits 未归一化时）会天然放大绝对差。

判决项 𝟙[·] 的边界是 τ_BI，这个阈值的选取本身就是一笔性能与正确性的交易。τ_BI 收紧，误杀率上升——本身允许非确定性的算子（atomicAdd 归约、动态 split-K）会被判死；τ_BI 放宽，漏杀率上升——真实的归约顺序 bug 被浮点噪声掩盖。这笔交易无法用单一常数解决，必须按算子类型分层：确定性算子用紧阈值（接近 fp32 舍入误差量级），允许非确定性的算子进豁免名单并在判决时短路。奖励公式 R_final = R·Invariant 因此不是纯函数，它依赖一张算子级豁免表，这张表是门控系统里唯一需要人工维护的状态。

一个具体例子：某候选 kernel 在 B=1 时走单 block 归约，在 B=8 时因 occupancy 触发 split-K，两条路径的累加树形状不同。逐元素比对发现 8 个输出位置中有 1 个的 Δ_BI 超出紧阈值两个数量级，其余 7 个在 1e-7 量级。max 聚合把信号从“7 个正常 + 1 个异常”中提取出来，若换成均值则异常被摊薄到 1/8，判决可能翻转。这就是 max 聚合的工程价值：它把稀疏故障的信噪比从 1/8 提升到“异常值本身”。

二 · 时延与显存：门控自身的成本核算

门控不是免费的。它的成本结构由两次 kernel 启动、一次 padding 构造、一次逐元素比对组成。时延上，B=1 那次运行是纯串行开销，无法与 B 那次并行摊销；显存上，B 那次需要为 padding 位置分配完整的激活与中间缓冲，实际占用接近满 batch 的峰值。这两笔开销必须计入每轮 RL 的预算，否则门控会把训练吞吐拖垮。

关键的一步推导在于：门控的时延不能直接相减得到“batch 不变性带来的性能损失”。因为 B 那次运行的 padding 位置参与了实际计算——kernel 并不知道哪些位置是 padding，它按 B 的完整形状调度 tile、分配 shared memory、发起归约。这意味着 T(B) 含 padding 的计算量，而逻辑上只有 1 个有效序列。因此 T(B) − T(1) 既包含真实的 batch 扩展成本，也包含 padding 的浪费，两者不可分离。工程判断是：门控只用于正确性判决，其时延数据不进入性能评分，性能分仍由独立的 SOL 归一化通道给出（该通道的主题在其他片段，此处不展开）。

显存代价更隐蔽。B 那次运行需要构造逻辑等价输入：同一序列放在 batch 的第 0 位，其余 B−1 位填充。填充值的选择影响正确性——若填零，某些 kernel 的归约会因零元素改变累加顺序的数值行为；若填 NaN，则可能触发 kernel 内部的 mask 分支走不同路径。稳妥做法是填充与目标序列同分布的哑数据，使 kernel 走与真实 batch 相同的调度路径，但这又要求门控系统持有分布采样能力（该能力属于隐藏 shape 分布抽样的范畴）。显存峰值因此是 B × 单序列激活 + padding 缓冲，在小显存卡上，门控可能成为整个 RL 循环里最占显存的环节，迫使 B 的取值上限受显存而非正确性需求约束。

一个具体例子：某 attention kernel 在 B=1 时 fused 了 softmax，在 B=16 时因寄存器压力拆成两个 kernel。门控跑 B=16 时，padding 的 15 个序列让第二个 kernel 的 grid 维度拉满，显存占用达到单序列的十几倍。若门控与训练主循环共享显存池，这一峰值会挤掉主循环的优化器状态。解法是把门控放到独立的 stream 并在比对完成后立即释放，代价是引入一次同步点，时延上增加一个 kernel launch 的间隔。

三 · 误差项的分解：归约顺序、split-K 与 tile 边界

Δ_BI 是一个标量，但它的来源是三个可分离的机制。诊断信息要能定位到具体机制，否则门控只给出“失败”而不给出“为什么失败”，回归集就无法针对性防复发。关键的一步是把 Δ_BI 拆成三项贡献：

$$\Delta_{\text{BI}} \le \Delta_{\text{reduction}} + \Delta_{\text{splitK}} + \Delta_{\text{tile}}$$
这个不等式不是严格上界，而是诊断上的分解框架——三项各自对应一种调度差异，工程上通过控制变量逐项归因。

归约顺序项：同一组浮点数，串行累加与树形累加的舍入误差不同。fp32 下，N 项求和的误差上界随 N 增长，树形归约把误差从 O(N) 压到 O(log N)。当 B 变化导致 block 内线程数变化，归约树深度改变，同一 token 的输出就出现系统性偏移。这一项的典型量级是几个 ULP 乘以累加深度，属于“可容忍但不可忽略”的区间。split-K 项：B 增大触发 split-K 时，部分和先写回全局内存再二次归约，多了一次 fp32 舍入和一次内存往返，误差量级跳升一个数量级，且与 split 数成正比。tile 边界项：tile 划分改变导致边界元素被不同的向量化指令处理，尾块处理路径与主块不同，误差集中在序列长度不能被 tile 整除的余数位置。

代价在于：逐项归因需要额外的受控运行——固定 B 但强制不同的归约策略、固定 split-K 数但改变 tile 大小——每次受控运行都是一次完整的 kernel 启动加比对，时延是基础门控的三到四倍。因此逐项归因不应嵌入每轮 RL，而应在门控首次失败时触发一次，把归因结果写入回归集，后续轮次只做基础判决。这是一个典型的“一次性诊断、常态化门控”分层。

一个具体例子：某 reduction kernel 在 B=1 与 B=32 下 Δ_BI 超标。逐项归因发现：把 B=32 的 split-K 强制设为 1 后 Δ_BI 下降一个数量级，说明 split-K 是主因；再把 tile 大小固定为整除序列长度后 Δ_BI 再降一半，说明 tile 边界是次因；剩余残差归为归约顺序。诊断输出直接指明“split-K 的二次归约缺少与单 batch 路径一致的累加顺序”，修复方向随之明确——让 split-K 的部分和按与单 batch 相同的树形顺序合并。

四 · 伪代码：门控的可实现骨架

门控的实现必须满足三个约束：可嵌入每轮 RL 奖励计算、失败时输出可归因的诊断、成功时不引入额外同步。下面给出骨架，关键设计是把“构造输入”和“判决”分离，判决是纯函数，便于单元测试。

构造阶段：取目标序列 s，构造两个逻辑等价输入——x1 = batch_of(s, B=1) 与 xN = batch_of(s 在第 0 位, 其余 B−1 位填哑数据, B)。两次运行分别提取第 0 位的输出切片 y1、yN。判决阶段：计算逐元素绝对差，取 max，与算子级阈值比较；若失败，进入归因分支，依次强制 split-K=1、固定 tile 整除、固定归约树深度，每次重跑并记录 Δ_BI 的下降量，按下降量排序输出主因。奖励阶段：R_final = R if Invariant else 0，并把失败样本的 (算子类型, 主因, Δ_BI 量级) 写入回归集。

伪代码层面的关键一步是归因分支的短路：不是所有失败都需要跑满三次受控运行。若算子类型已在豁免名单，判决直接返回 Invariant=True 并跳过全部比对；若 Δ_BI 超出紧阈值两个数量级以上，说明不是浮点噪声而是结构性错误，归因分支可以跳过受控运行直接标记“结构性”，因为这种量级的差异不可能由舍入顺序解释。短路把平均门控成本压到“两次运行 + 一次比对”，只有少数失败样本付出三到四倍代价。

代价核算：每次门控的 token 成本接近于零（不涉及 LLM 调用），但 GPU 时延成本是两次 kernel 启动加一次比对 kernel，比对 kernel 本身在 B 较大时也要做一次全量扫描，其带宽开销与输出张量大小成正比。若输出张量是 logits 量级（vocab 维度），比对 kernel 的带宽可能超过被门控 kernel 本身的带宽，此时应改为抽样比对——只比对目标位置的 top-k 或固定步长采样，用统计显著性替代全量 max，代价是漏杀率上升。这是一个明确的工程取舍：全量比对保证零漏杀但带宽翻倍，抽样比对省带宽但引入概率性漏杀。

一个具体例子：门控嵌入 RL 循环后，每轮对 8 个候选各跑一次门控，其中 6 个通过、2 个失败。通过的 6 个各付出两次启动成本；失败的 2 个中，1 个因 Δ_BI 量级过大走短路直接标记结构性，另 1 个跑满归因分支。整轮门控的额外时延约为候选 kernel 本身时延的 2.5 倍，这个倍数决定了 RL 循环里门控与训练的时间配比，也决定了 B 的取值不能太大——B 越大，比对 kernel 的带宽开销越接近甚至超过被门控 kernel。

五 · 奖励公式的梯度语义与豁免名单的形式化

R_final = R·Invariant 在 RL 里的语义不是“奖励打折”，而是“动作空间裁剪”。当 Invariant=0 时，该候选在策略梯度里的贡献为零，等价于该动作从未被采样。这与“给负奖励”有本质区别：负奖励会让策略学会“避免这类动作”，而零乘子让策略根本无法从该动作学到任何东西——它只是被丢弃。关键的一步是认识到：乘性门控把不变性从“可优化的目标”变成“可行域约束”，策略只能在可行域内做性能优化，不能以不变性为代价换取性能。

这个语义带来一个副作用：如果某类算子的可行域过窄（大量候选因豁免名单缺失而被误杀），策略会退化为“只生成保守的、单 batch 路径的 kernel”，性能优化停滞。豁免名单因此不是补丁，而是可行域的定义的一部分。形式化地，豁免名单是一张从算子类型到判决策略的映射：确定性算子走紧阈值全量比对；允许非确定性的算子走“结构等价”判决——不比对逐元素输出，而比对归约树的形状、split-K 的合并顺序、tile 划分的整除性，这些结构属性与 batch 无关，可以静态检查。结构等价判决的成本远低于数值比对（无需运行 kernel），代价是它只能捕获结构性差异，无法捕获同一结构下的舍入噪声——但对允许非确定性的算子，舍入噪声本来就是合法的。

代价在于豁免名单的维护成本：每新增一类算子，都要判断它是否允许非确定性、若允许则定义其结构等价谓词。这个判断无法自动化，因为它依赖对算子语义的理解。工程判断是：豁免名单应尽量小，只覆盖 atomicAdd 归约、动态 split-K、以及依赖硬件调度顺序的少数算子；其余一律走数值比对。名单越大，门控的漏杀面越大。

一个具体例子：某 softmax kernel 使用 atomicAdd 做跨 block 归约，数值上天然非确定。若走数值比对，每次门控都失败，候选被系统性误杀。加入豁免名单后，判决改为检查“跨 block 归约的合并顺序是否与 B 无关”——该 kernel 的合并顺序由固定的 block 索引决定，与 B 无关，结构等价通过，门控放行。代价是该 kernel 的逐元素输出在不同运行间仍有微小抖动，但这属于算子语义允许的范围，不影响可复现性的定义（可复现性要求的是同一逻辑输入在同一配置下的确定性，而非跨配置的逐位一致）。

六 · 阈值 τ_BI 的标定与回归集的闭环

τ_BI 不是拍脑袋的常数，它必须由数据标定。标定方法：取一批已知正确的确定性算子，在 B=1 与 B 之间跑门控，记录 Δ_BI 的分布，取分布的高分位作为紧阈值。这个分布的形状决定了阈值的可信度——若分布是重尾的，说明存在少量算子即使正确也有较大 Δ_BI，紧阈值会误杀它们；若分布是窄的，说明浮点噪声被良好控制，紧阈值可以贴近舍入误差量级。

关键的一步是把标定与回归集闭环：每次门控失败并归因后，失败样本进入回归集；回归集在后续轮次被优先重跑，若同一 (算子类型, 主因) 组合反复出现，说明该类算子的阈值或豁免策略需要调整。回归集的规模有上限——它占用门控预算，规模过大时每轮重跑回归集的时延超过新候选的门控时延。工程上通常限制回归集只保留最近若干轮的高频失败模式，低频模式归档而不重跑。

代价在于标定本身需要一次离线批量运行，其显存与时延开销是一次性的，但标定数据的质量决定了后续所有轮次的误杀率与漏杀率。标定不足的直接后果是：紧阈值过松导致真实 bug 漏过，或过紧导致可行域萎缩、策略退化。这笔一次性成本无法省略。

一个具体例子：标定发现某类 elementwise 算子的 Δ_BI 分布集中在 1e-7 量级且无重尾，紧阈值设为该量级的两倍；某类 reduction 算子的分布有重尾，紧阈值设为高分位而非中位数，代价是漏杀率略升，但避免了把合法的树形归约差异误判为 bug。回归集随后记录了一次 reduction 算子的 split-K 失败，该模式在后续三轮中重复出现，触发豁免策略调整——把 split-K 的合并顺序纳入结构等价检查，而非数值比对。闭环在此完成：标定给出初始阈值，门控产生失败样本，归因定位主因，回归集检测复发，策略调整收窄可行域或放宽判决。
