一 · 接受判据的推导：从相对增益到带符号的接受域

诊断式优化每一轮都要回答一个二值问题：这次改动是否值得保留。工程上最自然的量是相对时延变化 Δ_opt，但直接用它做判据会在两个方向出错。先看定义：

$$\Delta_{\text{opt}}=\frac{T_{\text{after}}-T_{\text{before}}}{T_{\text{before}}},\quad \text{accept if }\ \Delta_{\text{opt}}<-\epsilon\ \land\ \text{correct}$$

关键一步在于把“更快”翻译成“负得足够多”。Δ_opt 的符号约定是 after 减 before，所以性能改善对应负值；若写成 Δ_opt > \epsilon 就会把变慢的版本当成赢家。第二关键一步是 ε 的存在：它不是一个拍脑袋的容差，而是测量噪声的显式建模。设同一 kernel 在相同输入下重复测量的时延标准差为 σ_T，则 Δ_opt 的标准差近似为 σ_T√2 / T_before（两次独立测量之差）。要让接受判据的假阳性率可控，ε 至少应取该量的若干倍，否则 agent 会把纯粹的 run-to-run 抖动当成优化成果，问题库被噪声污染，后续提问全部建立在错误证据上。

代价在这里第一次显形：ε 取得越大，接受门槛越高，单轮有效改动的召回率下降，轮次预算被消耗在“明明有改善却不被接受”的候选上；ε 取得越小，接受域被噪声淹没，保留的修改在下一轮复测时回退，形成 keep-revert 抖动。工程判断是让 ε 随测量重复次数自适应：重复 k 次取中位数后，噪声按 1/√k 收缩，ε 可以同步收紧。具体例子：某 kernel 基线 T_before 抖动幅度在重复测量间可见，若不做重复测量就直接以极小 ε 判定，agent 会把一次 shared memory padding 改动判为有效，而该改动实际只改变了 L2 命中时序，复测即失效——正确性门通过、性能门却是假阳性。合取项 ∧ correct 不可省：正确性 oracle 的结论必须与性能判据同时成立，任何“快了但错”的候选在合取下自动出局，这是把正确性从软约束提升为硬门的最小代价写法。

二 · 时延分解：把 T_after 拆成可归因的项

仅有 Δ_opt 的标量值不足以支撑提问，agent 需要知道时间花在哪里。把单次 kernel 时延写成可加分解：

$$T = T_{\text{launch}} + T_{\text{mem}} + T_{\text{comp}} + T_{\text{stall}} + T_{\text{tail}}$$

推导的关键一步是把 T_stall 从“剩余项”变成“可测量项”：它不是残差，而是由 warp 调度器在等待依赖时累积的空转周期，可由 NCU 的 stall 采样直接归因到具体原因（bank conflict、long scoreboard、barrier 等）。这一步决定了微实验的设计方向——如果 T_stall 占比高且归因指向 bank conflict，那么“是否 shared memory bank conflict 导致 stall”就是一个可证伪问题，对应的最小实验是加 padding 或改 swizzle，只动一个变量，观察 T_stall 是否下降、T 是否随之下降。若 T_mem 占主导而 T_stall 很低，则同一实验大概率无效，问题被回答为“否”，agent 应转向 tile 形状或 pipeline 深度。

伪代码落到可实现层面，需要把分解项与实验绑定：

  • 读入本轮 profile，计算各项占比 r_i = T_i / T，取最大项作为提问锚点；
  • 生成 1–3 个候选问题，每个问题附带“若为真，则指标 X 应变化方向 d”的预测；
  • 对每个问题构造单变量实验，记录实验前后的 T_i 向量而非仅标量 T；
  • 用预测方向与实际方向是否一致来判定问题答案，一致记“是”，相反记“否”，部分变化记“部分”。

代价是每轮多出至少一次编译加一次完整测量，编译时间在小 kernel 上可能与时延本身同量级，微实验的固定开销因此不可忽略；当预算紧张时，问题数量应压到 1 个，把单变量约束守死，而不是并行做三个实验导致变量混淆。具体例子：一个 reduction kernel 的 T_stall 占比高，agent 提问“是否 barrier 等待主导”，实验只把 pipeline 深度加一，观察到 T_stall 下降而 T_mem 不变，答案“是”，于是下一轮动作锁定在流水线重叠而非 tile 重排——证据链完整，避免了对内存布局的无效折腾。

三 · 显存与带宽项：容量约束如何进入判据

时延判据之外必须并行维护一个显存判据，否则 agent 会收敛到“用更多 shared memory 换更低时延”的局部最优，在真实部署 shape 上直接 OOM。把每线程块的占用写成：

$$M_{\text{block}} = S_{\text{tile}} \cdot b + M_{\text{pipe}} \cdot d + M_{\text{aux}}$$

其中 S_tile 是 tile 元素数、b 是每元素字节、d 是流水线深度。推导的关键一步是把占用与 occupancy 联系起来：每 SM 可驻留的块数 n = ⌊M_SM / M_block⌋，而 n 直接决定可用于隐藏访存时延的并发 warp 数。于是“加 padding 消除 bank conflict”与“padding 抬高 M_block 降低 n”构成一对冲，微实验必须同时报告 T_stall 与 n，否则会把 occupancy 下降带来的时延上升误判为 padding 无效。

带宽侧的判据是有效带宽与可达带宽之比，它与 roofline 归一评分共享同一套量纲，此处只强调它在诊断闭环中的角色：当 T_mem 占主导且有效带宽已接近可达上限时，任何减少访存次数的改动（融合、复用、改变数据布局）才有物理空间；反之若有效带宽远低于上限，瓶颈更可能在访问模式而非数据量，提问应转向合并访问与 bank 分布。代价体现在显存预算上：d 每加一，M_pipe 线性增长，在长序列或大 batch 的隐藏 shape 上，这一项足以把原本可接受的配置推到 OOM 边缘；因此显存判据应作为接受判据的前置过滤，先算 M_block 与目标 shape 下的总占用，再谈时延。具体例子：agent 为消除 bank conflict 把 tile 宽度加一列 padding，T_stall 确实下降，但 M_block 越过 SM 容量阈值使 n 减半，整体 T 反而上升；若判据只看 Δ_opt 会拒绝该改动，但拒绝的理由被记录为“padding 有害”，这是错误的结论——正确记录应是“padding 有效但 occupancy 代价超过收益”，问题库据此改写为“在保持 n 不变的前提下能否消除冲突”，下一轮实验方向随之改变。

四 · 误差项：正确性 oracle 的判定式与假阴性代价

正确性门不能写成“输出相等”，必须写成带容差的逐元素判定，否则浮点重排、融合乘加、TF32 基线差异都会把合法优化判死。判定式取：

$$\text{pass} \iff \max_i \frac{|y_i - \hat{y}_i|}{\max(|y_i|, \tau)} \le \delta$$

分母里的 τ 是防零除的下限，它同时承担了“接近零的元素用绝对误差衡量”的语义。推导的关键一步是把相对误差与绝对误差统一到一个式子里：当 |y_i| 远大于 τ 时判据退化为相对误差，当 |y_i| 很小时退化为绝对误差除以 τ，避免了“大值宽容、小值苛刻”的偏置。δ 的取值必须与参考实现的精度档位一致：若参考是 fp64 而候选在 fp32 下计算，δ 需覆盖累加顺序改变带来的误差放大，尤其在 reduction 类 kernel 上，误差随累加长度增长，固定 δ 会在长序列上产生假阴性。

假阴性的代价是直接的：一个数值上合法、性能上更优的候选被正确性门拒绝，agent 收到“错误”信号后可能回退到更差的版本，并把“该优化方向不可行”写入问题库，污染后续所有提问。假阳性的代价更隐蔽：容差过松会让实际有精度缺陷的候选通过，部署端在隐藏 shape 上暴露偏差。工程判断是让 δ 随归约长度或累加规模做温和放大，并对每个候选同时记录最大相对误差与误差分布的分位数，把“刚好压线通过”的候选标记为脆弱，在后续轮次优先复测。具体例子：一个 softmax kernel 的候选把两次遍历融合为一次在线归约，最大相对误差在分母很小的元素上跳升，若 τ 设得过小则判据退化为纯相对误差而误杀；把 τ 抬到与输入量级匹配后，该候选通过，且其 Δ_opt 为负，正确进入保留集。

五 · 奖励合成：把诊断质量写进可验证奖励

多轮闭环需要一个标量奖励来驱动保留/回退决策，但奖励若只由 Δ_opt 构成，agent 会学到“多改多试”而非“先问再改”。合成式取：

$$R = -\Delta_{\text{opt}} \cdot \mathbb{1}[\text{correct}] - \lambda_c \cdot C_{\text{round}} + \lambda_q \cdot Q_{\text{diag}}$$

三项各自对应一个可验证信号。-Δ_opt 在正确时为正，直接奖励时延下降；C_round 是本轮消耗的编译与测量成本（可用编译次数、测量次数、token 数折算），惩罚无节制的实验；Q_diag 是诊断质量分，由“问题是否被实验明确回答”“答案是否与后续指标变化方向一致”两项构成，奖励有证据支撑的提问。推导的关键一步是把 Q_diag 写成可自动核验的形式而非主观打分：每个问题在提出时附带预测（指标 X 应向方向 d 变化），实验后比对实际方向，一致得正分、相反得负分、无变化得零分。这样奖励不需要人工标注，且与变异测试审计 checker 的思路同源——都是把“声称”与“实测”对齐。

系数选择本身是工程判断。λ_c 过大时 agent 倾向不提问、直接改代码，退化为无诊断的盲目搜索；λ_c 过小时微实验泛滥，轮次预算在低信息量的实验上耗尽。λ_q 过大则 agent 会生成大量容易回答的琐碎问题来刷分，问题库膨胀但瓶颈定位无进展；对策是要求问题必须锚定当前占比最大的时延项，且同一瓶颈的重复提问不重复计分。代价体现在 token 与编译时间上：每轮提问加实验的文本开销与编译开销都要计入 C_round，在预算紧张的场景下，直接搜索的期望收益可能高于诊断闭环，这也是适用边界所在。具体例子：agent 提出“是否 long scoreboard 主导”，预测 T_stall 应随预取深度增加而下降，实验证实后 Q_diag 得正分，随后基于该结论的改动使 Δ_opt 为负，两项奖励同向叠加；反之若 agent 未提问题直接改 tile 且性能无变化，Δ_opt 为零、C_round 为负、Q_diag 为零，总奖励为负，该行为在多轮中被压制。

六 · 伪代码闭环：判据、实验与问题库的落地结构

把上述公式组装成一轮可执行的循环，需要三个数据结构：指标向量、问题记录、保留集。伪代码思路如下（以文字描述控制流，不落具体语法）：读入 profile 得到 T 分解与占比，选最大项；生成候选问题并附预测；对每个问题执行单变量实验，采集实验后指标向量；用方向一致性判定答案并计算 Q_diag；据答案选动作、改 kernel；跑编译、正确性判定式、时延测量；用 Δ_opt < -ε ∧ correct 与显存前置过滤共同决定保留或回退；更新问题库（记录问题、答案、证据、结论），进入下一轮直到最大占比项低于阈值或预算耗尽。

这个结构里有三个容易写错的点。其一，实验必须只变一个变量，否则方向一致性判定失去因果含义，Q_diag 变成噪声。其二，回退必须恢复到实验前的完整状态（代码、编译产物、保留集），否则下一轮的 T_before 基准被污染，Δ_opt 的符号失去意义。其三，问题库的更新要记录“被证伪的问题”，因为证伪同样是信息：一个被回答为“否”的问题能排除一整类优化方向，其价值不低于被证实的问题，而奖励式里 Q_diag 应对明确证伪给正分，只对“无法判定”给零分。

代价的最终形态是轮次成本与问题质量的乘积：每轮固定付出一次提问、一次实验、一次编译验证，若问题提错，这些成本全部沉没且可能把 agent 引向错误方向——问题质量依赖模型对 GPU 微架构的理解，这是本机制最脆弱的一环，也是把 Q_diag 写进奖励的原因。具体例子：某轮 agent 提问“是否 L2 容量不足导致重复访存”，预测增大 tile 会降低 T_mem，实验显示 T_mem 不变而 T_stall 上升，答案“否”，问题库记下“该 shape 下 L2 非瓶颈”，下一轮提问转向流水线深度，避免了在缓存策略上继续投入。工程判断落在阈值上：当最大占比项已低于可观水平、或连续若干轮 Δ_opt 均未越过 -ε 且问题答案全为“否”，闭环应停止而非继续消耗预算——停止条件本身也是判据的一部分，写进伪代码而不是留给调用者临时决定。

假设闭环的失效边界与轮次成本核算

该机制把优化决策绑定在可证伪命题上，但它的收益并非无条件成立。失效的第一种情形是指标不可分辨：当 NCU 采集到的 stall 分布本身噪声与信号同量级，微实验的“是/否”回答就退化为随机标签。此时单变量实验的判别力取决于效应量与采样方差之比，若把一次微实验的观测时延记为 $$T_{\text{obs}}=\bar{T}+\sigma/\sqrt{n}$$，则只有当改 tile 或 swizzle 带来的真实差值与 $$\sigma/\sqrt{n}$$ 可比时，结论才可信；否则 agent 会把噪声当成因果证据，连续几轮朝错误方向收敛。工程上的对策是要求每个问题附带一个最小可检测差异阈值，低于阈值直接判“证据不足”而非“否”。

第二种失效是问题库的语义漂移。agent 依据上一轮结论更新问题库，但结论本身是“部分成立”时，问题会被改写成更宽泛的形式（例如从 bank conflict 漂到“访存效率不足”），下一轮微实验就不再是单变量，而是同时动了 tile 与 pipeline 深度，证据链断裂。代价直接体现在轮次预算上：每轮固定支出为一次提问生成、1–3 个微实验的编译与运行、以及一次完整正确性验证，编译时间与正确性 oracle 的调用是主要固定成本，而微实验的显存占用又限制了并行批量执行，使轮次成本近似线性于问题数而非 kernel 规模。

第三种失效是接受判据的边界。判据 $$\Delta_{\text{opt}}<-\epsilon\ \land\ \text{correct}$$ 中，$$\epsilon$$ 若设得过小，微小的测量抖动会让无效修改被保留并污染后续基线；设得过大，则真实但幅度有限的改进被丢弃，多轮边际收益提前归零。因此 $$\epsilon$$ 应与基线重复测量的离散度挂钩，而不是固定常数。下表给出三类失效的判别信号与处置：

失效类型判别信号处置
指标不可分辨重复实验结论翻转提高采样数或判“证据不足”
问题语义漂移单轮改动变量数 > 1回退问题库，强制单变量
判据失配保留项在复测中不显著按离散度重设 ε

结论落在工程判断上：这套闭环适合瓶颈明确、指标信噪比高的场景；当预算紧张或 profile 分辨率不足时，直接搜索的期望收益反而更高，因为提问与微实验的固定开销无法被摊薄。真正决定成败的不是问题数量，而是每个问题是否被约束为单变量、可复现、且带阈值。
