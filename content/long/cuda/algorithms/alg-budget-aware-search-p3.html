一 · 潜力评分：从静态特征到后验概率的映射

公式里的 \(\hat{p}_i\) 不是一个“准确率”，而是候选 \(i\) 在剩余预算内产出合法且更优 kernel 的**后验概率估计**。它的输入是特征向量 \(\phi_i\)，由静态分析产出：访存模式分类（连续/跨步/广播）、tile 尺寸与寄存器压力估计、理论占用率上界、共享内存占用、以及该候选所属“策略族”（如 split-K、persistent、warp-specialized）的历史成功率。线性项 \(w^\top\phi_i\) 是可学习的权重，\(\beta\cdot\text{UCB}_i\) 是探索项，\(\text{UCB}_i=\sqrt{\frac{2\ln N}{n_i}}\)，\(N\) 为总评估轮次、\(n_i\) 为该候选已被评估的次数。关键一步在 \(\sigma\)：把无界线性打分压到 \((0,1)\)，使 \(\hat{p}_i\) 可以直接当作“预算份额权重”使用，而不必再做归一化裁剪。

推导上要注意一个易错点：\(\hat{p}_i\) 与 \(\text{alloc}_i\) 之间不是线性关系。因为分母 \(\sum_j\hat{p}_j^{\alpha}\) 对所有存活候选求和，单个候选的份额对自身 \(\hat{p}_i\) 的偏导为

$$\frac{\partial\,\text{alloc}_i}{\partial\,\hat{p}_i}=\frac{B\,\alpha\,\hat{p}_i^{\alpha-1}\left(\sum_j\hat{p}_j^{\alpha}-\hat{p}_i^{\alpha}\right)}{\left(\sum_j\hat{p}_j^{\alpha}\right)^2}$$

当 \(\alpha>1\) 时该导数随 \(\hat{p}_i\) 单调增，意味着高潜力候选的份额增长快于其概率增长——这是“集中预算”的数学来源；当 \(\alpha=1\) 退化为按概率线性分配；\(\alpha<1\) 则趋于平均，用于先验不可信时的保守模式。工程上 \(\alpha\) 常取 2 附近，但跨架构迁移时先验失准，应下调 \(\alpha\) 并抬高 \(\beta\)，否则会过早把预算锁死在错误方向上。

代价体现在粗筛阶段：\(\phi_i\) 的静态分析本身要花编译前端时间（模板实例化、PTX 生成但不 launch），对一个大候选池（数十到上百个变体）来说，这一步的编译时间可能已经超过若干次小 shape 试跑的 GPU 时间。因此实现上应把静态特征抽取做成惰性、可缓存的：同一策略族共享特征，只对差异维度重算。具体例子：一个 GEMM 候选族里，tile 尺寸从 128×128 变到 256×128 时，寄存器压力与占用率估计变化剧烈，但访存模式分类不变，缓存后者即可省掉重复的 IR 遍历。

二 · 预算分配公式：份额、下限与终止条件

\(\text{alloc}_i=B\cdot\frac{\hat{p}_i^{\alpha}}{\sum_j\hat{p}_j^{\alpha}}\) 中 \(B\) 是剩余总预算，单位可以是“编译+profile 轮次”或折算后的 GPU 秒。直接按此式分配会产生两个工程问题：份额过小的候选拿到不足一次完整评估的预算，以及份额在轮次间抖动导致反复启停。解法是引入下限 \(\text{alloc}_i\leftarrow\max(\text{alloc}_i,\;\text{alloc}_{\min})\)，其中 \(\text{alloc}_{\min}\) 等于一次“快速编译 + 小 shape 正确性 + 单次时延测量”的最小成本；同时对 \(\text{alloc}_i<\text{alloc}_{\min}\) 的候选直接标记为“本轮不投入”，而不是给它一个无法执行的碎片预算。

终止条件必须显式写进分配器，否则 bandit 会无限给低潜力候选喂探索预算。常用三条：其一，后验置信区间上界低于当前最优候选的下界（即“即使乐观估计也赢不了”）；其二，连续 \(k\) 轮评估未产生合法 kernel 或未改进时延；其三，该候选的累计已花预算超过 \(\text{alloc}_i\) 的若干倍而边际收益（时延改进/预算）低于阈值。第一条是纯统计判据，后两条是工程护栏，防止 profile 噪声或编译抖动导致误判。

性能代价在这里是**预算碎片化**：下限机制会让存活候选数 \(m\) 满足 \(m\cdot\text{alloc}_{\min}\le B\)，一旦 \(m\) 超过 \(B/\text{alloc}_{\min}\)，分配器必须强制淘汰尾部候选，这个淘汰是“预算约束驱动的”，而非“证据驱动的”，因此存在把慢热型好候选误杀的风险。具体例子：某个 persistent kernel 候选在小 shape 上时延平庸（因启动开销占比高），但静态特征显示其在大 shape 下占用率稳定，若 \(\text{alloc}_{\min}\) 设得过大导致它在粗筛后被强制淘汰，就丢失了这条路径。缓解手段是给“策略族多样性”保留一个最小配额，即从 \(B\) 中切出固定比例 \(B_{\text{div}}\) 专供每个未验证策略族至少一次细粒度评估。

三 · 时延与显存项：为什么评分不能只看单次测量

细粒度阶段的候选评分需要把时延测量转成可比量。单次 launch 时延 \(t_i\) 受启动开销与测量噪声污染，因此用重复测量取稳健统计量（如中位数）并扣除空 kernel 基线 \(t_0\)：\(\tilde{t}_i=\text{median}(t_i)-t_0\)。但仅此不够——kernel 的时延随 shape 变化，粗筛用小 shape 得到的 \(\tilde{t}_i\) 不能直接外推到目标 shape。工程做法是把时延建模为 shape 参数的函数，至少记录两个尺度点 \((s_{\text{small}},s_{\text{target}})\) 的测量，用比值 \(r_i=\tilde{t}_i(s_{\text{target}})/\tilde{t}_i(s_{\text{small}})\) 作为“尺度敏感度”特征回灌到 \(\phi_i\)，让后验在下一轮自动下调那些小 shape 表现好但尺度敏感度异常高的候选。

显存项进入评分的方式是**约束而非奖励**：候选 \(i\) 的峰值显存 \(M_i\)（含 workspace、临时缓冲、双缓冲）必须满足 \(M_i\le M_{\text{cap}}\)，否则直接判为不可行，不参与 \(\hat{p}_i\) 竞争。这条硬约束的代价是：某些高占用率候选（如大 tile + 多级流水）恰恰因 workspace 超限被剔除，而它们在时延上可能最优。因此 \(M_{\text{cap}}\) 应按目标部署场景设定，而不是按当前设备最大显存设定——后者会让搜索偏向“能吃满显存”的激进配置，部署时反而不可用。

具体例子：一个 split-K GEMM 候选在小 shape 上因 reduction 开销时延偏高，但其 \(r_i\) 接近 1（尺度不敏感），而一个非 split 候选小 shape 更快但 \(r_i\) 随 K 增大而恶化。若评分只看小 shape 的 \(\tilde{t}_i\)，会错误淘汰前者；把 \(r_i\) 作为特征回灌后，后验会在目标 shape 证据到来前就给 split-K 候选更高权重。这里的性能代价是**测量轮次增加**：每个候选至少两个尺度点意味着粗筛成本翻倍，需与 \(\text{alloc}_{\min}\) 一起纳入预算下限计算。

四 · 误差项与奖励：合法性与改进量的联合塑形

奖励函数必须同时编码“合法”与“更快”，且两者不可交换。设 \(c_i\in\{0,1\}\) 为合约校验通过标志（数值误差在容差内、无越界、无非法指令），\(\Delta_i=\max(0,\;t_{\text{ref}}-\tilde{t}_i)/t_{\text{ref}}\) 为相对参考实现的时延改进比例，则单轮奖励可写为

$$R_i=c_i\cdot\left(\Delta_i-\lambda\cdot\frac{\epsilon_i}{\epsilon_{\text{tol}}}\right)-\mu\cdot(1-c_i)$$

其中 \(\epsilon_i\) 是实测数值误差（如相对 Frobenius 范数），\(\epsilon_{\text{tol}}\) 是容差，\(\lambda\) 惩罚“贴着容差线”的实现——这类实现往往在隐藏 shape 或不同输入分布下越界，属于正确性 oracle 之外的鲁棒性风险。关键一步是 \(c_i\) 作为乘子而非加项：非法候选的改进量被完全屏蔽，避免“快但错”的候选靠时延刷分。\(\mu\) 项则让非法候选得到负奖励，使 bandit 后验主动下调其 \(\hat{p}_i\)，而不是仅仅“不得分”。

误差项的推导要注意量纲：\(\epsilon_i/\epsilon_{\text{tol}}\) 是无量纲比值，与 \(\Delta_i\) 同尺度，因此 \(\lambda\) 可以直接解释为“误差用满容差时抵消多少时延收益”。工程上 \(\lambda\) 取 0.5 附近意味着：一个误差达到容差上限的候选，需要比参考实现快 50% 以上才能获得正奖励。这个设定把“正确性余量”变成了可交易的预算，而不是二元门。

代价是**奖励塑形的 token 成本**：每轮评估都要生成误差诊断文本（哪些元素越界、误差分布形态）回灌给 agent，长诊断会挤占上下文预算。实现上应只回灌聚合量（最大相对误差、越界元素计数、误差分位数）而非逐元素列表。具体例子：一个用 TF32 近似的候选在 \(\epsilon_{\text{tol}}\) 边缘反复震荡，若奖励只看 \(c_i\) 会把它当作合法候选持续投入预算；加入 \(\lambda\) 项后，其奖励被压到负值区间，bandit 在一到两轮内就会把它降权，省下的预算转给 fp32 累加的稳定候选。

五 · 伪代码：把分配器写成可实现的循环

下面给出与上述公式一一对应的主循环骨架，重点是状态机边界：粗筛、细粒度、终止三个相位共享同一个候选表，预算账本单调递减。

  • 初始化：候选池 \(C\)，对每个 \(i\) 计算 \(\phi_i\)（缓存策略族共享部分），初始化 \(n_i=0\)、\(w\) 为历史先验、预算账本 \(B\)。
  • 粗筛：按 \(\hat{p}_i\) 排序取 top-\(k\)，对每个执行“快速编译 + 小 shape 正确性 + 单次时延 + 目标 shape 单点时延”，扣减 \(B\)，更新 \(n_i\) 与 \(\phi_i\)（加入 \(r_i\)、\(M_i\)）。
  • 重算份额：对存活集 \(S\) 计算 \(\text{alloc}_i\)，应用下限与多样性配额 \(B_{\text{div}}\)，剔除 \(\text{alloc}_i<\text{alloc}_{\min}\) 者。
  • 细粒度循环：对 \(S\) 中每个候选，在 \(\text{alloc}_i\) 内做 NCU/SASS 调优迭代；每轮更新 \(c_i,\Delta_i,\epsilon_i\)，计算 \(R_i\)，用 bandit 更新 \(w\) 与 \(\hat{p}_i\)；触发任一终止条件则移出 \(S\)。
  • 收敛：\(B\) 耗尽或 \(S\) 为空时，输出最优合法 kernel 及其 profile 证据链（每轮 \(R_i\)、\(\tilde{t}_i\)、\(\epsilon_i\)、NCU 关键指标快照）。

伪代码里最容易写错的是 \(n_i\) 的更新时机：\(\text{UCB}_i\) 依赖 \(n_i\)，若在粗筛后立即把 \(n_i\) 加一，探索项会过早衰减，导致细粒度阶段对未充分评估的候选过于保守。正确做法是 \(n_i\) 只在“产生了一次可用于后验更新的证据”时递增，即完成一次带正确性判定的评估，而非仅仅编译成功。这个细节的代价是**收敛速度**：\(n_i\) 增长慢意味着 \(\text{UCB}_i\) 衰减慢，探索期拉长，同等 \(B\) 下用于利用的轮次减少；但换来的是对慢热候选更公平的评估，避免因编译失败或测量噪声导致的误淘汰。

具体例子：一个候选在粗筛阶段编译成功但小 shape 正确性未通过（\(c_i=0\)），若此时 \(n_i\) 递增，其 \(\text{UCB}_i\) 下降而 \(\hat{p}_i\) 也因负奖励下降，双重惩罚会让它几乎不可能再被分配预算——这对“编译通过但边界条件写错”的候选是合理的，但对“小 shape 触发未定义行为、大 shape 反而正确”的候选则是误杀。工程判断是：\(c_i=0\) 时 \(n_i\) 递增但 \(\mu\) 项减半，给一次“换 shape 重试”的机会，且这次重试计入 \(\text{alloc}_{\min}\) 而非额外预算。

六 · 权重更新与先验迁移：公式的可信边界

\(w\) 的更新用带正则的逻辑回归增量步：\(w\leftarrow w+\eta\,(R_i-\hat{p}_i)\,\phi_i-\eta\,\gamma\,w\)，其中 \(\eta\) 是学习率、\(\gamma\) 是 L2 系数。这一步的推导关键在梯度形式：\(\sigma\) 的导数 \(\sigma'=\hat{p}_i(1-\hat{p}_i)\) 与残差 \((R_i-\hat{p}_i)\) 相乘后，若把 \(\sigma'\) 吸收进 \(\eta\) 就得到上式——这是工程上常用的近似，代价是当 \(\hat{p}_i\) 接近 0 或 1 时更新步被高估，容易在极端候选上震荡。稳妥做法是对 \(\hat{p}_i\) 做截断 \([\delta,1-\delta]\) 后再算残差。

先验迁移的可信边界必须写清楚：\(w\) 是在特定算子族、特定架构、特定 shape 分布下学到的，跨算子复用时只有 \(\phi_i\) 中与算子无关的维度（访存模式、占用率上界）可信，策略族成功率维度不可信。因此迁移时应对 \(w\) 做维度级缩放：无关维度保留，策略族维度收缩到接近零并抬高 \(\beta\)，让探索项主导前若干轮。这个操作的代价是**冷启动轮次增加**：新算子上前几轮几乎纯探索，预算利用率低；但不做迁移则每轮都从零学 \(w\)，在预算紧张时更糟。

具体例子：在 A 架构上训练出的 \(w\) 强烈偏好大 tile + 高占用率策略，迁移到寄存器文件更小的 B 架构时，该偏好会导致粗筛把大量预算给到编译即失败的候选。维度级缩放后，策略族维度权重被压低，\(\phi_i\) 中的寄存器压力估计重新主导排序，粗筛命中率恢复。这里的工程判断是：迁移不是“复制权重”，而是“复制特征语义 + 重置策略先验”，公式里的 \(\beta\) 就是控制这个重置程度的旋钮——\(\beta\) 越大，先验越不重要，搜索越接近无信息 bandit。

预算分配公式的失效边界与系统代价

分配公式 $$\text{alloc}_i=B\cdot\frac{\hat{p}_i^{\alpha}}{\sum_j \hat{p}_j^{\alpha}},\quad \hat{p}_i=\sigma\left(w^\top\phi_i+\beta\cdot\text{UCB}_i\right)$$ 的关键一步在指数 α 的作用：α=1 时预算严格正比于潜力，α>1 则把预算向头部候选倾斜，α→∞ 退化为赢者通吃。α 越大，粗筛误判的代价越高——一个被低估的候选拿到的预算按 α 次幂衰减，几乎不可能翻身。因此 α 的取值必须与粗筛代理指标的可信度匹配：静态特征（访存模式、tile 尺寸、占用率估计）在跨算子迁移时先验失准，此时应压低 α 并抬高 β（UCB 探索项），用真实编译证据而非先验来纠正排序。β 本身是 token 与 GPU 时间的直接开销：每个 UCB 采样意味着一次快速编译加小规模正确性试跑，β 过大等于把预算浪费在明知低潜力的候选上。

公式的第二个失效条件是 σ 的饱和。当 $$w^\top\phi_i+\beta\cdot\text{UCB}_i$$ 落入 σ 的平坦区，不同候选的 $$\hat{p}_i$$ 差异被压缩到数值噪声量级，归一化后分配比例趋近均匀——coarse-to-fine 退化为均匀分配，正是该方案要避免的浪费。工程上应对 logit 做温度缩放或改用 softmax 前的排名归一化，代价是额外一次全候选打分，相对 NCU 采集的毫秒级开销可忽略，但每轮都做会累积成可观的调度时延。

粗筛漏检是本方案最实质的正确性代价。小 shape 试跑可能掩盖大 shape 才暴露的瓶颈，典型如 occupancy 骤降：小 shape 下 block 数足以填满 SM，静态占用率估计漂亮，候选通过粗筛；放大到目标 shape 后寄存器压力或共享内存限制使活跃 warp 数掉档，时延远超预期，而此时预算已按潜力比例流向别处，该候选被提前终止。这类漏检不会产生错误 kernel（正确性 oracle 仍会拦截非法输出），但会让搜索在同一预算下错过更优解，属于召回率损失而非正确性损失。

系统代价还体现在证据链的完整性上：低潜力候选提前终止意味着其 profile 证据不完整，最终输出最优 kernel 时无法对“为何淘汰某方向”给出可复核的 NCU/SASS 依据。若下游需要审计搜索决策，就必须为被淘汰候选保留粗筛阶段的静态打分与小 shape 时延记录，这部分存储与 token 开销随候选池规模线性增长，是预算调度器必须显式计入的固定成本。
