一 · 从“判定”到“可度量”：KillRate 与 CheckerOK 的逐项拆解

把 checker 当作被测对象，而不是当作公理，是这一部分所有公式的出发点。设参考实现为 R，变异算子集合为 \mathcal{O}，对 R 施加算子 o\in\mathcal{O} 得到变异体 m=o(R)。变异体集合记为 \mathcal{M}，规模 |\mathcal{M}| 通常落在 50–200 之间。核心评分只有两个量：

$$\text{KillRate}=\frac{|\{m\in\mathcal{M}: \text{Checker}(m)=\text{Fail}\}|}{|\mathcal{M}|},\quad \text{CheckerOK}=\mathbb{1}[\text{KillRate}\ge \kappa]$$

逐项看：分子是“被 checker 判为错误”的变异体个数，分母是变异体总数。注意分子统计的是 Checker 的输出，不是“变异体是否真的错”——因为变异体由已知算子构造，其语义偏离是构造时确定的，所以“真的错”是前提而非待测量。这一点决定了 KillRate 与普通测试覆盖率的分野：覆盖率度量“代码被执行到”，KillRate 度量“偏离被识别到”。\kappa 是准入阈值，事实给定为 95%，即 \text{CheckerOK} 是一个硬门，未过门的 checker 不得进入 RL 奖励管线。这个门的工程含义是：奖励信号的信噪比由 checker 的检错能力上界决定，一个漏检率 20% 的 checker 会让 RL 把“错误但通过”的 kernel 当作正样本反复强化，而这种污染在策略梯度里是不可逆的。

推导的关键一步在于把 KillRate 写成条件概率的加权和。按变异类型 t 分组，令 \mathcal{M}_t 为类型 t 的变异体子集，p_t=|\mathcal{M}_t|/|\mathcal{M}|，k_t 为该组被 kill 的比例，则

$$\text{KillRate}=\sum_{t} p_t\cdot k_t$$

这个恒等式是分组报告的数学依据：总体 KillRate 达标不代表每一组都达标。若边界条件类变异体占比 p_{\text{bound}} 很小而 k_{\text{bound}} 接近 0，总体数字仍可能被容差类的高 k_t 拉过 95%，此时 checker 在边界上完全失效却拿到了准入资格。因此工程上应把门设在“总体 ≥ κ 且每个类型 k_t\ge\kappa_t”的合取上，\kappa_t 可按类型单独设定。代价是评测成本：每个变异体都要完整跑一遍 checker，成本随 |\mathcal{M}| 线性增长，而分组门要求每组样本量足够，进一步推高 |\mathcal{M}| 的下限。一个具体例子：dtype 截断类变异体若只有 3 个，k_t 只能取 0、1/3、2/3、1 四个离散值，统计分辨率不足以支撑 95% 的判定，必须扩到至少 20 个才能让 1/20 的粒度有意义。

二 · 变异算子库的构造式与“等价变异体”污染

事实给出的四类算子是：边界条件翻转、累加顺序打乱、dtype 截断、索引偏移 ±1。把它们写成可实现的构造式，需要一个“变异点定位”的前置步骤：从参考 kernel 的 AST 或 IR 中提取三类锚点——循环边界表达式、归约树节点、类型转换与索引算术。设锚点集合为 \mathcal{A}，算子 o 是 \mathcal{A}\to\mathcal{M} 的映射，则

$$\mathcal{M}=\bigcup_{o\in\mathcal{O}}\{\,o(a)\mid a\in\mathcal{A}_{\text{compat}(o)}\,\}$$

其中 \mathcal{A}_{\text{compat}(o)} 是算子 o 语义上可施加的锚点子集——索引偏移只能打在索引算术上，dtype 截断只能打在类型转换或累加器声明上。这个兼容性约束是变异体质量的第一道闸：把 dtype 截断打在无关的常量上会产生语义等价的变异体，它永远不被 kill，从而人为压低 KillRate 并制造“checker 有漏洞”的假象。

等价变异体是这一环节最主要的正确性代价。判定一个变异体是否等价，严格做法是跑 fp64 高精度参考并比对变异体输出与参考输出的差异是否落在数值噪声内；但这一步本身就要花一次完整评测的时延，且对归约顺序打乱这类变异体，差异可能只在最后几位有效数字上，判定边界模糊。工程折中是：对每个变异体记录“构造时期望的偏离幅度” \delta_o（如索引偏移 ±1 期望造成至少一个元素的错位读取，dtype 截断期望造成相对误差量级 2^{-b}，b 为截断位宽），若 checker 未 kill 且实测偏离小于 \delta_o 的下界，则标记为疑似等价变异体并进入人工复核队列，而不是直接计入漏检。这一步把“漏检”与“等价”分开，避免修补方向被误导。

具体例子：对一个做行归约的 kernel，累加顺序打乱算子把顺序累加改为成对树形归约。在 fp32 下两者结果的相对差异通常在 10^{-7} 量级，若 checker 的容差设为 10^{-5}，该变异体不被 kill 是正确行为而非漏洞——因为树形归约在数值上是合法实现。但若同一算子在 fp16 累加器上施加，差异可达 10^{-3}，此时不被 kill 就是容差过松的真实漏洞。同一个算子在不同 dtype 下语义合法性不同，这就是为什么变异体必须携带“期望偏离幅度”元数据，而不能只按算子名分组统计。

三 · 单变异体评测的时延与显存账

每个变异体跑一遍 checker 的成本，可以拆成三段：变异体编译、变异体执行、参考输出比对。设编译时延 T_c、执行时延 T_e、比对时延 T_v，则单变异体成本 T_m=T_c+T_e+T_v，全量审计成本

$$T_{\text{audit}}=|\mathcal{M}|\cdot(T_c+T_e+T_v)+T_{\text{ref}}$$

其中 T_{\text{ref}} 是参考实现只跑一次的成本，可摊薄。三项的相对量级决定了优化方向：T_c 在小 kernel 上往往是主导项（编译一个 Triton 或 CUDA 变体动辄数百毫秒到数秒），T_e 取决于 kernel 规模，T_v 取决于输出张量大小与比对实现。因此把 200 个变异体串行编译会把审计时延推到不可接受，工程做法是编译流水化——变异体之间无依赖，可并行提交编译，用编译缓存按“算子 + 锚点 + dtype”三元组做键，重复锚点直接命中。显存侧的账则是：若并行 P 个变异体执行，峰值显存约为 P 倍单变异体工作集加上参考输出常驻，需在调度时按 P\le \lfloor M_{\text{free}}/M_m\rfloor 限流，否则 OOM 会让审计中途失败、已完成的 kill 记录作废。

伪代码落到可实现，核心是一个带分组统计与疑似等价标记的循环：

对每个 o\in\mathcal{O}：枚举兼容锚点 a，生成 m=o(a)，写入元数据 (\text{type}=o,\ \delta_{\min},\ \text{anchor}=a)；将 m 提交编译队列，键为三元组，命中缓存则跳过 T_c；编译成功后提交执行，取输出 y_m；调用 \text{Checker}(y_m,y_{\text{ref}}) 得 \text{pass/fail}；若 fail，计入 \text{killed}[o]；若 pass，计算实测偏离 d=\|y_m-y_{\text{ref}}\|，若 d<\delta_{\min} 则计入 \text{suspect}[o]，否则计入 \text{missed}[o]；循环结束后按 k_t=(\text{killed}[t])/(\text{killed}[t]+\text{missed}[t]+\text{suspect}[t]) 与不含 suspect 的两种口径分别报告。两种口径并列是必要的：含 suspect 的口径偏保守，不含 suspect 的口径偏乐观，二者的差就是等价变异体污染的上界。

性能代价在这里体现为一个具体的工程判断：|\mathcal{M}| 从 50 扩到 200，审计时延近似四倍，但如果这四倍能把某个类型的统计分辨率从 1/10 提到 1/40，那么它换来的是一次性成本对长期奖励信号质量的提升。反之，若 T_c 主导且编译缓存命中率低，扩样本量的边际收益会被编译时延吃掉，此时应先做算子库的精简——砍掉高 suspect 率的算子，而不是盲目加量。

四 · 漏检归因：容差问题还是覆盖问题

分组报告的价值在于把漏检归因到两类根因。设某变异体 m 未被 kill，观察其输出与参考输出的偏离形态：若偏离集中在少数元素且幅度超过容差，说明 checker 的容差对该类偏离不敏感（例如用了相对误差而变异体造成的是绝对偏移，或用了 L2 范数而变异体只污染单个元素，范数被稀释）；若偏离为零或落在未被比对的输出区域，说明是覆盖问题（checker 只比对部分输出、未覆盖边界切片、或跳过了某个 dtype 分支）。判别式可写成

$$\text{root}(m)=\begin{cases}\text{tolerance}, & \max_i |y_m^i-y_{\text{ref}}^i|>\tau \ \text{且}\ \|y_m-y_{\text{ref}}\|_2\le\tau\sqrt{n}\\[2pt]\text{coverage}, & \text{比对掩码在偏离位置为 }0\end{cases}$$

第一个分支刻画的是“逐元素超差但范数未超”的典型容差漏检：L2 范数把单点大偏差摊薄到 \sqrt{n} 个元素上，n 越大越容易漏。这就是为什么对归约类 kernel 的 checker，逐元素最大值判据比范数判据更敏感，代价是前者对合法数值噪声更脆弱，需要配合 dtype 相关的逐元素阈值。第二个分支是覆盖漏检，它要求 checker 显式记录比对掩码，否则无法区分“比对了且通过”与“根本没比对”。

具体例子：索引偏移 +1 的变异体在边界切片上造成错位读取，若 checker 只比对输出张量的中间区域（为规避边界上的实现自由度），该变异体落在掩码外，偏离为零，归因为覆盖问题，修补方向是扩大比对掩码或对边界单独设判据；而 dtype 截断变异体造成全局性的小幅偏移，逐元素均超差但范数未超，归因为容差问题，修补方向是把范数判据换成逐元素判据或收紧 \tau。两类根因的修补动作完全不同，混在一起统计会让“修补容差”这种动作被错误地应用到覆盖漏洞上，修完 KillRate 不升反降。

归因的代价是人工复核的 token 与时延：每个漏检变异体都要人看偏离形态，200 个变异体里若有 20 个漏检，复核成本不可忽略。降低这部分成本的办法是把判别式自动化，只把两个分支都不命中的模糊案例送人工——这类案例通常正是等价变异体的候选。

五 · 准入阈值与奖励管线的耦合

\text{CheckerOK} 作为硬门，其阈值 \kappa 不是孤立参数，它与 RL 奖励的方差直接耦合。设 checker 的漏检率为 \epsilon=1-\text{KillRate}，则奖励管线中以概率 \epsilon 把错误 kernel 标为正奖励。若奖励为二值 r\in\{0,1\}，被污染的正样本比例为 \epsilon，策略在污染样本上的梯度方向与真实改进方向相反，且这种反向梯度会随训练步数累积。把 \kappa 从 95% 提到更高，\epsilon 下降，但达到更高 KillRate 需要更细的变异算子库与更严的 checker 判据，后者会引入假阳性——把合法实现判为错误，从而压低真实正样本的通过率，同样损害奖励信号。这是一个双向代价，\kappa 的选择是在漏检污染与假阳性抑制之间的折中，而不是单调越严越好。

$$\mathbb{E}[\text{reward}]=(1-\epsilon)\,r_{\text{true}}+\epsilon\,r_{\text{false}},\quad \text{Var}[\text{reward}]\propto \epsilon(1-\epsilon)$$

第二式说明污染不仅偏移均值，还抬高方差，而高方差奖励在策略梯度里表现为有效学习率下降。这给出一条工程判断：当 \epsilon 无法进一步压低时，与其继续收紧 checker，不如在奖励侧做降权——对通过 checker 但落在“疑似等价”或“偏离接近阈值”的样本给部分奖励而非满额，用连续奖励吸收残余的不确定性。这个动作不需要改 checker，只需要 checker 额外输出偏离幅度，把二值判定升级为带置信度的判定。

具体例子：一个 KillRate 恰为 95% 的 checker 过门，其 \epsilon=0.05。若每轮 RL 采样 1000 个候选 kernel，约 50 个错误样本被误判为正，这些样本若集中在某个变异类型上（比如边界类 k_t 只有 0.7），则策略会系统性地在该类型对应的写法上过拟合，表现为训练中该类 kernel 的通过率虚高而真实基准上不涨。这正是分组门要独立于总体门的原因：总体 95% 掩盖了单组 70% 的系统性偏差，而系统性偏差比随机漏检对 RL 的伤害更大。

六 · 变异体数量与统计功效的下界推导

最后一个可推导的量是 |\mathcal{M}| 的下界。KillRate 是二项比例的估计，其标准误为 \sqrt{k(1-k)/|\mathcal{M}|}。若要求对真实 KillRate 的估计在置信水平 1-\alpha 下误差不超过 e，则所需样本量近似为

$$|\mathcal{M}|\ge \frac{z_{1-\alpha/2}^2\,k(1-k)}{e^2}$$

取 k 接近 1（checker 较好时 k(1-k) 小），该式给出的下界偏小，但分组后每组样本量按 p_t 摊薄，最小组的样本量才是约束。设最小类型占比 p_{\min}，则要求 p_{\min}|\mathcal{M}|\ge n_{\min}，即 |\mathcal{M}|\ge n_{\min}/p_{\min}。这就是为什么事实给出的 50–200 区间在工程上偏向下沿：若变异类型分布均匀（四类各 25%），50 个变异体每组仅 12–13 个，分辨率不足以支撑 95% 的分组门；200 个时每组 50 个，分辨率才够。代价是审计时延按第三节的公式线性上升，因此实际做法是按类型配额而非均匀随机生成——对历史上 k_t 偏低的类型多分配变异体，把有限的 |\mathcal{M}| 预算投到最需要分辨率的组上。

这条推导还揭示了一个容易被忽略的陷阱：KillRate 虚高。当变异算子库覆盖不全时，\mathcal{M} 里缺少那些 checker 恰好不擅长的变异类型，p_t 被人为扭曲，总体 KillRate 上升但检错能力并未提升。这与第三节的等价变异体污染是同一枚硬币的两面——一个是分母里混入了不该算的样本，一个是分母里漏掉了该算的样本。两者的共同解药都是持续扩充算子库并维护每个算子的 suspect 率与 miss 率历史，用历史数据反推配额，而不是一次性生成固定集合后长期复用。审计的结论必须绑定到具体的算子库版本，否则 KillRate 这个数字在算子库变更后失去可比性。

变异算子库的覆盖缺口与评测预算的硬约束

KillRate 的分母是变异体集合本身，而非真实错误空间，这是该方案最根本的边界：kill rate 度量的是“checker 对已构造变异体的敏感度”，不是“checker 对任意错误 kernel 的检错概率”。若变异算子库只覆盖索引偏移 ±1、累加顺序打乱、dtype 截断与边界翻转四类，则一个把归约维度写反、却恰好落在容差内的变异体根本不会进入分母，KillRate 被系统性高估。工程上必须把分母的构造过程本身当作审计对象：每类变异算子应记录其生成变异体占全集的比例，并对漏检变异体做人工复核后回填新算子，否则 kill rate 只是一个自洽的循环论证。阈值 κ 的选取同样受此约束——κ 越高，越逼迫算子库扩充，但也越容易因分母过小而虚高。

评测成本是线性项而非常数项。设变异体数量为 N、单次 checker 执行时延为 t_c（含参考输出比对与容差判定），则审计总时延约为 N·t_c，且每个变异体通常还需一次参考 kernel 重跑以生成比对基准，实际开销接近 2N·t_c。N 取 50–200 时，若 t_c 在毫秒量级，单轮审计尚可接受；但若 checker 内部含多次 device 同步或 host-device 拷贝，t_c 会被同步开销主导，审计时延随 N 线性膨胀到秒级，直接挤压 RL 奖励管线的采样预算。可行的折中是分层抽样：对高价值变异类型（如精度截断、归约顺序）全量跑，对低价值类型按比例抽样，并用分组 kill rate 的置信区间决定是否补跑，而非盲目扩大 N。

$$\text{AuditCost}\approx N\cdot(2t_c+t_g),\quad \text{KillRate}_g=\frac{|\{m\in\mathcal{M}_g:\text{Checker}(m)=\text{Fail}\}|}{|\mathcal{M}_g|}$$

分组 kill rate 的价值在于把“容差过松”与“覆盖不足”两类失效分开：若某组变异体（如边界翻转）kill rate 显著低于全局，且人工复核发现 checker 根本没比对边界元素，则是覆盖问题，修补方向是扩大比对范围；若某组（如 dtype 截断）kill rate 低但比对范围完整，则是容差问题，需收紧相对误差阈值。一个具体例子：归约顺序打乱的变异体在浮点累加下产生末位差异，若 checker 用固定绝对容差 1e-6 判定，则大数值输出下该变异体被误判为通过，kill rate 虚低——此时应改用相对容差并记录该组漏检，而非直接调低 κ。只有 kill rate ≥ κ 且分组漏检类型已归因的 checker 才允许进入奖励管线，否则错误 kernel 会被奖励信号正向强化，污染整轮 RL 数据。
