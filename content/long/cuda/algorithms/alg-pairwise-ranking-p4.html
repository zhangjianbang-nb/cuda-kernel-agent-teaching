一 · 负载筛选：先决定“哪些 kernel 值得配对”

成对排序奖励的第一道工程门槛不是模型，而是负载筛选。并非所有 kernel 都适合做偏好对：如果一个算子的候选实现之间时延差异落在测量噪声带内，配对标注就会退化为抛硬币，偏好模型学到的只是噪声。筛选准则应当以“可分辨性”为核心——同一 prompt 下两个候选 kernel 的稳健时延差必须显著超过该 shape 下的测量抖动，且两者都通过正确性门槛。可分辨性可以用一个无量纲量刻画：设同一候选重复测速的时延标准差为 σm，两候选稳健时延之差为 Δ，则配对信息量近似正比于 Δ/σm。当 Δ/σm 低于阈值时，该对要么丢弃，要么降级为“平局”样本，不参与 ranking loss。

适合配对的算子具有三类特征：其一，实现空间宽，同一语义存在多种 tiling、向量化、流水线策略，例如 GEMM 变体、softmax、layernorm、attention 的 fused 版本、reduce 类算子；其二，性能对 shape 敏感，候选之间在不同 shape 上互有胜负，能提供非平凡的排序信号；其三，正确性可被廉价 oracle 判定，使“正确性优先”的硬门槛不至于成为采样瓶颈。相反，纯访存且实现空间狭窄的算子（如简单 copy、逐元素加）在多数 shape 上候选差异微弱，配对收益低。

shape 维度要显式分层，而不是均匀抽样。大 shape 往往受带宽或 SOL 约束，候选差异被压缩；小 shape 受 launch 开销与占用率支配，候选差异被放大但噪声也放大。工程做法是按 shape regime 分桶（小/中/大、方阵/瘦长、对齐/非对齐），在每个桶内单独构造偏好对并单独校验一致性，避免一个大桶的稳定偏好淹没另一个桶的噪声。硬件维度同理：跨架构配对（如同一算子分别在两种 SM 配置上测）会引入不可比的绝对时延，但成对比较本身只关心“同一硬件上谁更快”，因此偏好对必须绑定硬件，跨硬件只做偏好一致性审计，不做直接配对。

代价在这里体现为采样预算：每个偏好对需要两个候选都完成编译、验证、测速，采样成本相对单候选翻倍；若再叠加 shape 分桶与重复测速以压低 σm，单位有效偏好对的成本进一步上升。一个具体例子：对 attention 的 fused 候选与朴素候选配对时，小 shape 下 launch 开销主导、差异明显，大 shape 下两者都逼近带宽上限、Δ 缩小，若不分桶直接把两类样本混在一起训练，偏好模型会偏向“小 shape 更快的那一方”，在 held-out 大 shape 上排序一致性下降。

二 · 基线选择：配对里的“锚”决定奖励是否有意义

成对排序不要求绝对时延可比，但要求配对双方处在同一“参照系”。基线选择因此不是随便挑一个旧版本，而是决定偏好信号指向什么。常见三类锚：参考实现锚（如 PyTorch/cuBLAS 调用或朴素 Triton 版本），用于回答“候选是否真的比生态基线快”；历史最优锚（同一 prompt 下当前策略产出的最佳候选），用于回答“新候选是否在改进”；同代候选锚（同一轮采样中的两个候选互配），用于回答“策略内部谁更优”。三类锚的偏好语义不同，混用会让 ranking loss 的目标漂移。

工程上建议分层使用：正确性门槛用参考实现锚做硬判定，速度偏好用同代候选锚构造主训练对，历史最优锚只用于 held-out 一致性与回归检测。原因是参考实现锚的绝对时延受编译选项、库版本影响，容易把“基线本身被优化过”误读为“候选变差”；而同代候选锚天然共享编译与测量条件，Δ 更干净。基线还必须与候选走同一套编译与测速合约（同一优化等级、同一 warmup/重复次数、同一时钟状态），否则配对比较的是编译差异而非 kernel 质量。

一个具体机制：构造偏好对时先做正确性过滤，只有双方都通过 oracle 的对才进入速度比较；速度比较用稳健统计量（如重复测速的中位数或截尾均值）而非单次测量，降低 σm。若一方正确性失败，则该对直接标为“正确方胜”，不进入速度排序——这正是正确性优先的硬门槛，防止“快但错”的候选通过偏好模型获得奖励。代价是：正确性过滤会丢弃大量对，尤其当策略早期产出大量错误候选时，有效偏好对产出率低，采样成本中用于“无效对”的比例上升；同时参考实现锚若本身编译时间长，会拉高每对的编译时间开销。

基线选择失误的典型后果是偏好模型学到“代码风格偏好”而非性能偏好。例如基线固定为某朴素实现，而候选普遍采用向量化写法，偏好模型可能把“是否向量化”当作胜负特征，即使在某些 shape 上向量化版本因占用率下降而更慢。held-out 一致性校验正是用来捕获这种偏差：若偏好模型在 held-out 对上的排序与真实稳健时延排序不一致，说明锚或分布设置有问题。

三 · 输入分布：shape、dtype 与数据值的联合设计

输入分布决定偏好对覆盖哪些性能 regime，也决定偏好模型是否过拟合到单一 shape。分布设计要同时管三个维度：shape 采样、dtype/布局、数据值。shape 采样应覆盖候选之间“互有胜负”的区域，而不是只采候选稳定获胜的区域——后者会让偏好模型退化为一侧恒胜，ranking loss 梯度消失。dtype 与布局（行主/列主、对齐/非对齐、转置视图）会改变访存模式，同一候选在不同布局下胜负可能反转，因此布局应作为分布的一个显式因子。

数据值维度常被忽略但对正确性与性能都有影响：含 NaN/Inf 的输入会触发不同的分支路径，极端值会影响 reduce 类算子的数值稳定性，稀疏或重复值会影响缓存行为。偏好对的数据值应至少覆盖常规随机、边界值、退化形状（如维度为 1、非 2 的幂），使正确性 oracle 的判定有意义，也使速度比较不被单一数据模式主导。分布还应包含“隐藏 shape”留出集，用于一致性校验，防止偏好模型记住训练 shape 的胜负表。

指标计算上，偏好模型的质量不能只看训练 loss。核心指标是 held-out 对上的排序一致性：对每个 held-out 对，比较偏好模型打分排序与真实稳健时延排序是否一致，统计一致比例；辅以按 shape 桶、按 dtype 桶分解的一致性，定位分布偏差。另一个指标是“平局率”——真实 Δ/σm 低于阈值的对被标为平局的比例，平局率过高说明分布中可分辨对不足，需要调整 shape 采样或增加重复测速。

代价体现在 token 与采样预算：分布越宽，覆盖每个桶所需的偏好对越多，采样成本与标注成本线性上升；隐藏 shape 留出集又占用一部分预算而不直接参与训练。一个具体例子：在 reduce 类算子上，若分布只采大 shape 对齐输入，候选差异被带宽压缩，偏好对大量落入平局带，有效对产出率低；加入小 shape 与非对齐输入后，候选胜负出现分化，但小 shape 的 σm 更大，需要更多重复测速才能把 Δ/σm 抬到阈值以上，单位有效对的测速时延随之上升。

四 · 指标与一致性校验：把偏好模型钉回真实时延

偏好模型的输出是打分，不是时延。要让奖励可信，必须定期把打分排序钉回真实稳健时延排序。校验协议：从 held-out 分布抽样若干对，双方都实际编译、验证、测速，得到真实胜负；再用偏好模型对同一对打分，统计一致率。一致率按 shape 桶与硬件分别报告，任何桶的一致率显著低于整体，说明该桶的偏好信号不可信，应回灌到分布设计或锚选择。校验频率不必每轮都做，但必须在策略显著漂移后触发，否则偏好模型与真实性能脱钩而无人察觉。

指标还要区分“排序正确”与“幅度正确”。成对排序只保证谁更快，不保证快多少；若下游用偏好打分做加权或做 DPO 的隐式奖励，打分的相对幅度会被放大。工程上应把偏好打分仅用于排序与胜者选择，幅度信息由真实稳健时延差提供，避免偏好模型虚构的分数间隔污染策略梯度。一个伪代码思路：对每个候选，收集其在多个 held-out 对中的胜负记录，用 Bradley-Terry 拟合出的分数只做排序键；策略更新时用真实 Δ 的符号与量级做加权，分数仅用于打破平局或做候选筛选。

代价是校验本身消耗采样：每个 held-out 对都要双候选实跑，且为压低 σm 需重复测速，校验预算与训练预算竞争。若校验过频，采样成本中校验占比过高；若过疏，偏好模型偏差累积。一个具体例子：偏好模型在训练分布上一致率高，但在非对齐 dtype 桶上一致率低，原因是该桶样本稀少、模型学到了对齐输入的风格特征；若不分解报告，整体一致率会掩盖这一桶的失效，策略在该桶上被错误奖励驱动。

五 · 负载不对时的失效形态

负载与分布设置错误不会以“训练 loss 不降”这种显式方式报警，而是以几种隐蔽形态出现。第一种是偏好退化：候选之间差异长期落在噪声带，偏好对大量平局或随机胜负，ranking loss 梯度微弱，偏好模型输出接近常数，策略失去改进方向。第二种是分布过拟合：偏好模型在训练 shape 上一致率高，在隐藏 shape 上崩塌，策略产出在训练 shape 上“更优”但在真实负载上无收益甚至回退。第三种是锚漂移：基线被悄悄优化或编译条件变化，偏好语义从“是否改进”变成“是否匹配新基线风格”，奖励尺度漂移重新出现——这正是成对比较本想规避的问题。

第四种是正确性门槛被绕过：若偏好对构造时正确性过滤不严，或 oracle 覆盖不足，错误候选可能因“更快”进入胜者侧，偏好模型学到“激进优化风格”的偏好，策略随后产出更多快但错的 kernel。这类失效的代价最大，因为它在评测上表现为速度提升，在端到端收益上却是正确性回退。防御手段是把正确性作为硬门槛前置，并用变异测试审计 oracle 的检出能力（该主题在其他片段展开，此处只作指路）。

失效形态的检测应嵌入常规流程：平局率监控偏好退化，分桶一致率监控分布过拟合，基线版本与编译合约的哈希监控锚漂移，正确性失败率监控门槛绕过。每种监控都对应一个采样代价——平局率需要记录 Δ/σm，分桶一致率需要 held-out 实跑，锚哈希需要固定编译环境。一个具体例子：策略在若干轮后平局率上升，排查发现 shape 采样被策略自身产出分布带偏，候选趋同于同一 tiling 家族，差异缩小；恢复分层采样后平局率回落，但采样成本上升，因为需要强制覆盖策略不常产出的 shape regime。

六 · 配方落点：把负载、锚、分布、指标写成可执行合约

把上述选择固化为一份可执行配方，是让成对排序奖励可复现的前提。配方至少包含：算子与 shape regime 白名单、每桶的采样配额、dtype/布局因子、基线锚的类型与版本锁定、正确性 oracle 与硬门槛、稳健时延统计量与重复次数、Δ/σm 阈值与平局处理、held-out 分布与一致性校验频率、分桶指标报告格式。这份配方本身应作为合约校验的一部分，任何字段变更都要触发重新校验，防止分布或锚在无人察觉时漂移。

配方中的每个数值都对应一个工程权衡：重复测速次数压低 σm 但抬高采样时延；每桶配额抬高覆盖度但抬高 token 与编译时间；校验频率抬高可信度但挤占训练预算。这些权衡没有普适最优，只能按算子族与硬件档位分别标定，并把标定结果写进配方而非留在个人经验里。一个具体机制：把每桶的 Δ/σm 分布作为配方健康度指标，若某桶长期低于阈值，自动降低该桶配额或提高重复次数，而不是继续产出无效对。

最终判断落在具体机制上：成对排序奖励的可信度不取决于 ranking loss 的形式，而取决于偏好对是否落在可分辨的性能 regime、锚是否锁定在同一参照系、分布是否覆盖候选互有胜负的区域、指标是否把打分钉回真实时延。负载不对时，成对比较规避尺度漂移的优点会被噪声、过拟合与锚漂移抵消，奖励重新变得不可信；因此配方设计应先于模型训练，把“哪些对值得采、拿什么当锚、怎么算胜负、怎么校验”写成合约，再让偏好模型在这份合约约束下学习。
