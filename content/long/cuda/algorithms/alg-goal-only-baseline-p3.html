一 · 能力评分公式：指示函数与阈值的耦合

基线的主评分是逐样本通过率的均值，形式极简，但每一项都对应一个可被工程实现直接落地的判定：

$$\text{capability}=\frac{1}{N}\sum_{i=1}^{N}\mathbb{1}\left[\text{correct}_i\land \text{SOL}_i\ge \theta\right]$$

推导的关键一步在于把“正确”与“够快”压成一个合取项再取指示，而不是先分别算正确率与性能均值再相乘。若拆成 acc·mean(SOL)，一个正确但极慢的 kernel 会以高 SOL 拉高均值、稀释失败样本的惩罚；合取指示则要求每个样本同时越过两道门，任何一项不达标该样本即记 0。这使得 capability 的语义是“达标样本占比”，而非“平均质量”，与“是否具备在给定硬件上交付可用 kernel 的能力”这一判断严格对齐。

阈值 θ 的选取直接决定分数的分辨率。θ 取得过高（接近 1.0 的参考 SOL），大量正确但调度粗糙的实现被判负，分数塌缩到接近 0，区分度丧失；θ 取得过低，则正确性门成为唯一有效约束，性能维度退化。工程上应把 θ 设为参考 kernel SOL 的一个固定比例，并在同一批样本上扫描若干 θ 值给出曲线，而不是只报单点。代价在于：每个 θ 都要重跑一遍判定，若 SOL 已在 profile 阶段采集则可离线重算，否则重复 profile 的 NCU 采集时延会成倍增长。具体例子：某样本正确性通过、SOL 为参考的 0.62，在 θ=0.5 时记 1、θ=0.7 时记 0，同一份代码在两条曲线上的贡献完全不同，因此报告必须绑定 θ。

指示函数的另一个工程含义是它天然抗离群：单个样本的 SOL 从 0.9 崩到 0.1，只要仍 ≥θ 就不改变分数，只有跨过阈值才翻转。这降低了 profile 噪声（时钟波动、共享 SM 干扰）对总分的敏感度，但也意味着阈值附近的样本对测量噪声极敏感，需要在判定时对 SOL 做多次采集取稳健统计量。

二 · 成本公式：token 均值的口径与陷阱

成本项定义为每样本消耗 token 的均值：

$$\text{cost}=\frac{1}{N}\sum_i \text{tokens}_i$$

推导的关键一步是明确 tokens_i 的统计边界：它必须包含该样本从首次读入语义到最终判定为止的全部模型交互 token，包括 agent 自主决定读取文档、撰写测试、分析 profile 输出所引发的每一轮对话，而不仅是代码生成那一次调用的输出长度。若只计生成侧 token，会系统性低估无提示基线的真实开销——因为剥离提示后，模型把大量 token 花在自我诊断与假设生成上，这部分恰恰是基线成本的主体。

均值口径还有一个结构性陷阱：tokens_i 的分布是重尾的。少数难题样本可能消耗数倍于中位数的 token（反复编译失败、profile 读不懂、假设被证伪后重来），均值会被这些样本拉高，而 capability 是 0/1 计数，两者对同一批样本的敏感方向不同。因此单看 cost 均值会掩盖“多数样本便宜、少数样本极贵”的结构，工程上应同时给出分位数（如 P50 与 P90）以及 cost 与 capability 的联合分布，否则无法判断成本是被普遍抬高的还是被少数样本拖累的。

代价层面，cost 直接换算为推理时延与费用：token 越多，单样本墙钟时间越长，且在多轮 RL 场景下 token 预算就是采样预算，cost 高的基线在同等算力下能跑的样本数更少，反过来压缩了 capability 的统计置信度。具体例子：两个模型 capability 相同，但一个 P90 token 是另一个的数倍，则在固定预算下前者可评估的样本数更少，其 capability 的方差更大，直接比较分数是不公平的，必须把 cost 作为配对维度一起报。

三 · 时延与显存：SOL 归一的分母从哪来

SOL_i 不是绝对时延，而是相对参考 kernel 的归一量。设参考实现在同一输入上的实测时延为 T_ref，候选实现为 T_cand，则最朴素的归一写法是：

$$\text{SOL}_i=\frac{T_{\text{ref}}}{T_{\text{cand}}}$$

推导的关键一步是把 T_ref 固定为同硬件、同输入、同精度下的实测值，而非理论 roofline 下界。用理论下界做分母会把所有实现都压到远小于 1 的区间，阈值 θ 失去物理意义；用实测参考做分母，SOL=1 意味着追平参考，SOL>1 意味着超越，语义直观且与“达到参考 kernel 的 x%”这一目标表述一致。这也解释了为什么 θ 常取 0.5~0.9 这类比例：它直接读作“达到参考的百分之多少”。

时延测量的代价在于必须控制测量噪声：单次 kernel 启动的墙钟受 launch 开销与时钟抖动支配，需用多次迭代取中位数并扣除固定开销；若候选实现包含 host 侧同步或多次 launch，T_cand 应计入端到端而非单 kernel 时间，否则会奖励把工作拆成多次 launch 的取巧写法。显存维度则作为硬约束而非评分项：候选实现的峰值显存超过输入规模允许的上界即判失败，因为显存超限的 kernel 在真实部署中不可用，把它算进 capability 会污染“可用性”语义。

具体例子：某算子参考实现 T_ref 对应 SOL=1，候选实现因未做向量化访存导致带宽利用率低，T_cand 约为 T_ref 的数倍，SOL 落在 0.3 附近，在 θ=0.5 下记 0；同一候选若仅调整 tile 尺寸使访存合并，SOL 可越过阈值而无需改变算法结构——这说明 SOL 对微调敏感，阈值附近的样本正是能力区分的主战场。

四 · 误差项：正确性判定的容差与传播

correct_i 不是布尔真值，而是带容差的数值比较。对浮点输出，逐元素判定写作：

$$\text{ok}_i=\bigwedge_{j}\left(|y_j-\hat{y}_j|\le a_t+b_t|\hat{y}_j|\right)$$

推导的关键一步是采用相对+绝对混合容差而非单一相对误差：当参考值接近 0 时，纯相对容差会因分母趋零而爆炸，把微小绝对误差误判为失败；混合形式在近零处退化为绝对容差 a_t，在大值处由相对项 b_t 主导，覆盖两种尺度。a_t 与 b_t 的取值必须与算子精度契约绑定（fp32 与 tf32 的容差不同），否则正确性门本身就成了过拟合源。

误差传播的代价体现在归约类算子上：求和、softmax 分母、矩阵乘的累加顺序改变会放大舍入误差，候选实现若采用不同的分块归约树，其误差可能超出逐元素容差而被判错，即便算法在数学上等价。工程上应对归约结果采用更宽的容差或改用统计型判据（如整体相对误差范数），并对中间张量做抽样比对以定位误差来源，而不是一刀切收紧容差——收紧会误杀合法实现，放宽会放过真实错误。具体例子：某 softmax 候选在分母归约时用 fp32 累加但分块顺序不同，逐元素最大绝对误差落在容差边缘，若按逐元素严格判定则失败，按范数判据则通过；判定口径的选择直接改变该样本的 capability 贡献。

五 · 奖励与伪代码：把公式落到可执行循环

若基线轨迹用于 RL，奖励需与 capability 同构，避免训练目标与评测目标错位。一个与上述公式一致的稠密奖励可写为：

$$r_i=\mathbb{1}[\text{correct}_i]\cdot\min\left(1,\frac{\text{SOL}_i}{\theta}\right)-\lambda\cdot\frac{\text{tokens}_i}{\text{budget}}$$

推导的关键一步是把 SOL 对 θ 做截断归一：达到阈值即封顶为 1，未达阈值按比例给部分信用，从而使“接近阈值”的改进获得梯度，而不是在 0/1 门下完全无信号；同时减去 token 惩罚项，把成本公式并入奖励，防止策略靠无限轮次刷分。λ 控制成本与性能的权衡，budget 为单样本 token 上限。

对应的可实现伪代码如下，落到最小工具集（编译、运行、profile）三原语：

  • 读入算子语义、输入输出契约、目标硬件与 θ；初始化 tokens_i=0、round=0。
  • 循环：agent 产出候选源码 → 编译（失败则回灌编译错误，计 token）→ 运行正确性检查（按混合容差判 ok_i）→ 若 ok_i 为假，回灌首个失配元素与误差量级。
  • 若 ok_i 为真，调用 profile 采集 T_cand 与峰值显存 → 计算 SOL_i → 若 SOL_i≥θ 且显存合规，记达标并跳出；否则回灌 SOL 与瓶颈指标（带宽/占用率）供下一轮假设。
  • 每轮累加 tokens_i；达到 budget 或轮次上限仍未达标则记失败，保留轨迹供 SFT/RL。

代价在于该循环的墙钟由编译与 profile 主导：每次 NCU 采集引入固定开销，若每轮都全量 profile，轮次多时总时延远超纯生成；工程上可对未通过正确性的轮次跳过 profile，仅在 ok_i 为真后采集，把 profile 次数压到与达标尝试次数同阶。具体例子：某样本前若干轮均编译失败，跳过 profile 使该样本的采集开销趋近于零；一旦编译通过，首次 profile 即给出 SOL，若已越阈值则一轮收敛，token 与采集成本都被这条短路规则压住。

伪代码中还有一个必须显式处理的判定顺序问题：先正确后性能，且正确性失败时不计算 SOL。这不仅是成本优化，更是语义要求——对错误输出测性能毫无意义，若允许错误 kernel 进入性能评分，策略会学会输出快速但错误的实现来骗取 SOL 信号。把 correct_i 作为 SOL_i 计算的前置门，等价于在奖励结构里硬编码了合取公式的短路语义。

六 · 公式间的耦合与工程判断

四个公式并非独立：capability 的 θ 决定奖励中 SOL 的截断点，cost 的 budget 决定奖励的惩罚斜率，误差容差决定 correct_i 的松紧进而改变哪些样本能进入 SOL 计算。调任何一个参数都会同时移动另外三项的语义。工程判断的核心是冻结口径：θ、容差、budget 必须在评估前固定并写入合约，跨模型比较时不得逐模型调参，否则 capability 之间的差异无法归因于模型能力本身。

耦合的另一个表现是方差传递：capability 是 N 个伯努利指示的均值，其标准误随 N 增大而收缩，但当 θ 落在大量样本 SOL 分布的密集区时，单个样本的判定翻转会显著改变总分，此时增大 N 比调 θ 更能稳定分数。cost 的重尾则要求报告配对差值而非独立均值，把同一批样本上两套配置的 token 差与 capability 差一起给出，才能回答“多花的 token 换来了多少达标率”。

最终落到一个具体机制上：把 capability、cost、SOL 分布、误差余量四者写入同一份逐样本记录，评估脚本只做聚合不做重算，任何口径变更都体现为对记录的离线重放而非重跑 agent。这样 θ 扫描、容差敏感性分析、budget 调整都不再触发昂贵的编译与 profile 循环，公式的每一次改动都可追溯到具体样本的具体数值，基线的可信度由此建立在可复算的记录之上，而不是一次性的汇总数字。

能力基线的边界：阈值门控、轮次成本与失效条件

该基线的第一个边界藏在能力公式的指示函数里：$$\text{capability}=\frac{1}{N}\sum_{i=1}^{N}\mathbb{1}\left[\text{correct}_i\land \text{SOL}_i\ge \theta\right]$$ 它把连续的性能分布压成 0/1，正确性与阈值必须同时满足才计分。关键一步在于 θ 的取法：若 θ 直接取参考 kernel 的某个百分比，则任何在正确性上过关、但 SOL 差一点的 kernel 与完全跑错的 kernel 得分相同，梯度信号被抹平。工程上应把该指示函数拆成两层——硬门控（correct）与软余量（SOL−θ），后者用于诊断“差多少”而非计分；否则在 N 较小（如 KernelBench 单级仅数十题）时，单题翻转即可让 capability 跳动数个百分点，基线不可比。代价是评测时延：每题都要跑到稳定态才能测 SOL，profile 采集本身引入额外开销。

成本公式 $$\text{cost}=\frac{1}{N}\sum_i \text{tokens}_i$$ 看似简单，却掩盖了轮次结构。真正决定基线可用性的是“达到 θ 所需轮次”的分布而非均值：无提示条件下 agent 需自行提出假设、改代码、编译、跑 NCU、再读 profile 回改，单题轮次可能从个位数拉到几十，token 消耗随之非线性上升。伪代码上应记录每轮的 (round, tokens, SOL, correct) 四元组，而不是只累加总量：

  • 若某题在 k 轮后仍未达 θ，应标记为“未收敛”并从 capability 分母中单列，避免用 0 稀释均值；
  • token 成本需按“有效轮次”归一，剔除编译失败、语法错误导致的空转轮，否则会高估模型探索成本。
这里的系统代价是显存与编译时间：每轮重编译产生 cubin 与临时 buffer，长轮次轨迹在显存上累积中间张量，若不做复用会挤占 profiling 所需空间。

失效条件有三类。其一是工具原语不足：只暴露编译、运行、NCU 三个原语时，agent 无法读取 PTX/SASS 反汇编或做指令级计数，遇到需要寄存器压力分析才能突破的 kernel（如 occupancy 受限的 reduction），它会反复试错而无法定位瓶颈，此时低分反映的是工具边界而非模型能力。其二是先验缺口：若算子涉及 CuTe 的 layout 代数或 TMA 描述符，模型缺乏对应知识时 SOL 会停在较低水平，基线偏低但不可归因于“不会优化”。其三是阈值过紧：θ 设为参考 kernel 的极高百分比时，正确但次优的解全部归零，capability 退化为“是否复现参考实现”的二值判断。因此该基线适合作为对照下界，用于量化脚手架增益，而不适合作为生产部署候选——其收敛慢、token 高的代价在端到端收益评估中必须与带提示脚手架分开计量。
