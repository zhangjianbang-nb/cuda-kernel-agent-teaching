一 · 根节点与动作空间的构造

搜索树的根节点不是空白，而是一个可运行的基线：参考实现（PyTorch 原生算子或 cuBLAS/cuDNN 调用）或一份朴素 CUDA kernel。根节点的作用有两个：提供正确性对照的语义锚点，以及提供计时分母。根节点的输出必须包含三样东西——可编译的源码、一份固定的输入张量集合（shape/dtype/layout 三元组）、以及一次基线计时 T_base。缺少任何一项，后续节点的 reward 都无法归一化。工程上常犯的错误是把根节点做成“最优已知 kernel”，这会让 UCT 的 Q 值从一开始就贴近 1，探索项被压制，树退化为对单一分支的微调。

动作空间是搜索的结构性约束，也是本机制最贵的人工成本。给定事实列出的动作维度是 tile 大小、unroll 因子、split-K 切分、swizzle 布局、向量宽度。把这些维度形式化为一个动作集合 A = {a_1, …, a_m}，每个动作是一个对当前 kernel 源码的确定性变换（或带参数的变换族）。动作空间的设计直接决定搜索的可达集：未纳入的动作——例如 CuTe 的 layout 代数、warp-specialized 流水、TMA 描述符——永远不会被任何节点生成，这是结构性盲区，不是靠增加预算能弥补的。动作空间还必须是可组合的：从节点 s 施加动作 a 得到子节点 s'，再从 s' 施加 a'，语义上应等价于在 s 上施加复合动作，否则 keep/revert 的路径记录无法复现。

代价在这里第一次出现：动作空间的设计与实现需要人工编写变换器与合法性检查，每个动作都要保证生成的 kernel 能通过编译。以 tile 大小为例，若动作允许 tile ∈ {32, 64, 128, 256}，则必须同时约束 shared memory 占用不超过硬件上限，否则大量子节点在编译或启动阶段即失败，白耗预算。一个具体例子：对 GEMM 类 kernel，从 128×128 tile 施加“split-K=4”动作后，若未同步调整累加缓冲的 reduction 逻辑，生成的 kernel 数值正确但性能退化——这类“语法合法、语义退化”的子节点正是 keep/revert 要剪掉的对象，但它们仍消耗了一次完整的正确性门与计时。

二 · UCT 选择：从访问计数到节点选取

选择阶段的输入是当前树的统计量：每个节点的访问次数 N(s)、每个边 (s,a) 的访问次数 N(s,a) 与累计 reward。输出是被选中展开的节点及其待施加的动作。核心公式为

$$\text{UCT}(s,a)=Q(s,a)+c\sqrt{\frac{\ln N(s)}{N(s,a)}},\quad Q(s,a)=\frac{1}{N(s,a)}\sum_{i}R_i,\quad R_i=\frac{T_{\text{base}}}{T_{\text{gen}}}\cdot\mathbb{1}[\text{Correct}]$$

三个量各有工程含义。Q(s,a) 是这条边的经验价值，用 T_base/T_gen 做归一化意味着 reward 是“相对基线的加速比”，跨不同 shape 可比；指示函数 𝟙[Correct] 把正确性作为硬门，错误节点 reward 归零而非负值——这一点很关键，因为负 reward 会让 UCT 主动回避某类动作，而错误往往来自实现 bug 而非动作本身不可行。探索常数 c 控制利用与探索的平衡：c 偏大时搜索会在低访问边上游走，单节点成本被摊薄但收敛慢；c 偏小时树迅速收敛到首个高 reward 分支，陷入与线性重试相同的局部最优。

选择的一个具体机制细节：N(s) 取父节点访问数而非全局，保证同一父节点下的兄弟边在同一尺度上比较；当 N(s,a)=0 时 UCT 项发散，实现上通常给未访问边一个极大值以强制先展开，或用 1/(N(s,a)+ε) 平滑。伪代码思路是：从根开始，每层在子边中取 argmax UCT，直到抵达一个未完全展开的节点或叶节点，返回该路径。代价是选择本身几乎零成本（纯 CPU 计算），但选择质量决定了 GPU 预算的分配效率——一次错误的选择可能把一个 5 GPU 分钟的节点花在注定被 revert 的分支上。

举例：根节点基线 T_base 已知，第一次迭代所有边 N=0，按实现约定展开第一个动作（如 tile=64）；若该子节点正确且 T_gen = T_base/1.3，则 R=1.3，该边 Q=1.3、N=1。第二次迭代时，这条边的 UCT 因 Q 高而领先，但探索项随 N(s,a) 增大而衰减，于是搜索会转向同层未访问的 tile=128 边。这就是“利用高 reward 分支”与“探索未访问修改”在同一公式里的耦合。

三 · 生成、正确性门与计时：单节点流水线

展开一个节点要走三段流水线，每段的输入输出与代价都不同。第一段是 agent 生成：输入是父节点源码、动作描述、以及可选的编译/运行反馈（来自父节点或兄弟节点的失败信息），输出是子节点 kernel 源码。这一段消耗的是 LLM token 与时延，通常几十秒到数分钟量级，且失败模式是“生成不可编译代码”——语法错误、缺失头文件、维度不匹配。第二段是正确性门：输入是子节点源码与固定输入张量集合，输出是布尔判定。第三段是计时：输入是通过正确性门的 kernel，输出是 T_gen（多次运行取中位数或最小值，需固定 warmup 与迭代次数）。

正确性门的代价被严重低估。它不是“跑一次比对”那么简单：需要编译（nvcc 编译时间对模板密集的 kernel 可达数十秒到数分钟）、分配输入输出、执行、与参考实现逐元素比对并处理浮点容差。给定事实中的“单节点成本约 1–5 GPU 分钟”主要就花在这三段上，其中编译时间在 CuTe/模板重的 kernel 上占比很高。一个具体例子：一个 split-K 动作生成的 kernel 若 reduction 顺序改变，浮点结果与参考的差异会随 K 增大而累积，容差设置过紧会把正确 kernel 误判为错误（假阴性），过松则放过真实 bug（假阳性）——这正是变异测试审计 checker 要处理的问题，此处只需知道正确性门本身有误判代价。

计时段的代价是 GPU 时间与测量噪声。固定输入集合意味着计时只反映该 shape 下的性能，若隐藏 shape 分布与固定集合偏离，节点 reward 会系统性偏移。因此单节点流水线的输出应附带“该计时对应的 shape 标识”，供后续回传时按 shape 分组归一化。三段流水的失败要分级处理：生成失败（不可编译）应低成本记录并降低该动作先验，不必进入正确性门；正确性失败要进入门并归零 reward；计时失败（如启动配置非法）视为退化。分级的意义在于把最贵的 GPU 段留给最可能成功的节点。

四 · reward 回传与统计量更新

回传的输入是叶子节点的 R_i，输出是路径上每个节点与边的更新后统计量。更新规则是沿选择路径自底向上，对每条边执行 N(s,a) ← N(s,a)+1、累加 R_i 到该边的 reward 和、并对节点执行 N(s) ← N(s)+1。价值估计 Q 随之刷新。这里有一个容易被忽略的机制细节：R_i 是相对根节点基线归一化的，但路径上中间节点的 Q 表示的是“从该节点继续搜索的期望收益”，二者语义不完全一致。工程上常用两种处理：一是把叶子 reward 直接回传给整条路径（Monte Carlo 式），实现简单但中间节点的 Q 有偏；二是只更新被展开边的直接统计，父节点价值由子节点价值聚合（如取最大子节点 Q），更贴近“这条路径最好能到多快”。

回传的代价是数值稳定性与预算记账。若某条路径上多个节点都返回 R=1.0（与基线持平），Q 会稳定在 1 附近，探索项成为唯一驱动力；若某节点返回极高 R（如 1.8），其 Q 会长期主导，除非 c 足够大或该边被反复访问稀释。给定事实中“树搜索比线性重试最终 speedup 高 1.2–1.8×”是最终结果的量级，而单节点 reward 的分布通常更宽——这意味着回传时必须防止单次异常计时（如 GPU 被其他进程干扰）污染 Q。常见做法是计时取多次最小值而非均值，或在回传前对 R 做截断。

具体例子：一条路径根→tile=128→split-K=2→unroll=4，叶子 R=1.45。回传后 tile=128 边 N=1, Q=1.45，split-K=2 边同样 Q=1.45，unroll=4 边 Q=1.45。下一次选择时，tile=128 的探索项因 N(s,a)=1 仍较大，可能被再次选中去展开它的另一个子动作（如 swizzle），也可能被同层 tile=64 的未访问边以更大探索项压过。预算记账在此刻发生：每回传一次，预算计数器减一，剩余预算决定是继续加深还是转向广度。

五 · keep/revert 判定与先验调整

keep/revert 是边的剪枝规则，其输入是子节点相对父节点的 reward 比较，输出是“保留该边并允许继续扩展”或“回退到父节点并降低该动作先验”。判定阈值不是简单的 R>1：由于计时噪声，R 略大于 1 可能是测量波动。工程上常用“相对父节点提升超过某比例”或“连续两次测量均改善”作为 keep 条件。revert 的代价是把已花的 GPU 预算记为沉没成本，但收益是阻止搜索在该分支上继续加深——一个退化的 tile 配置往往在其上叠加更多动作也不会变好，继续扩展只是浪费。

先验调整是 keep/revert 与 UCT 的接口。给定事实说“若子节点退化则 revert 到父节点并降低该动作的先验”。实现上，先验体现为 UCT 中的 Q 初值或一个额外的偏置项：对被 revert 的动作，将其初始 Q 设为低于中性的值（如 0.8），使得即使 N(s,a)=0 时该边也不被优先展开；或者维护一个动作级的失败计数，在选择时对失败率高的动作施加惩罚。这与纯 UCT 的“未访问边优先”相冲突，因此需要显式区分“未访问”与“已访问且失败”——前者应探索，后者应回避。

一个具体机制细节：revert 后父节点仍是可扩展的，搜索会从父节点选择另一个动作。这形成“同一父节点下的兄弟动作竞争”，正是树搜索相对线性重试的优势所在——线性重试在失败后从同一状态重新生成，没有记忆；树搜索记住了哪个动作失败，并在兄弟间重新分配预算。代价是动作空间的组合爆炸：若父节点有 m 个动作，每个动作又引出 m 个子动作，深度 d 的树节点数为 m^d，预算 100 节点只能覆盖极浅的树。因此实际系统通常限制深度（如 3–4 层）并依赖 keep 剪枝把预算集中到有希望的分支。

举例：tile=256 动作生成的 kernel 因 shared memory 超限而启动失败，正确性门直接判负，R=0。该边被 revert，动作 tile=256 的先验被下调。后续选择中，即使 tile=256 边 N=0，其被选中的概率也低于其他未访问动作。这就是“有记忆的搜索”的具体形态：失败被编码进统计量，而不是被遗忘。

六 · 预算终止与最优路径输出

终止条件是预算耗尽：轮次上限或 GPU 小时上限。给定事实给出的量级是单节点 1–5 GPU 分钟、100 节点即 2–8 GPU 小时。终止时输出的是“最优路径上的 kernel 与修改序列”——注意是路径而非单节点，因为路径记录了从根到叶的完整动作序列，可复现、可审计、可作为下一次搜索的种子。选择最优路径的准则通常是路径上叶节点的 R 最大，而非路径上某中间节点 Q 最大；后者可能指向一个被后续动作拖累的分支。

终止阶段的一个工程判断是：预算应如何在深度与广度间分配。若动作空间大而单动作收益不确定，广度优先（浅树、多兄弟）能在早期快速筛掉退化动作；若已知某类动作（如 split-K）在特定 shape 上有效，深度优先（沿高 Q 边加深）能挖出组合收益。给定事实中“动作空间需人工设计，未纳入的动作无法被搜索到”意味着广度受限于动作集合的大小，而深度受限于预算。一个具体例子：预算 100 节点、动作空间 5 维、每维 3–4 个取值，若全部广度展开第一层就需 15–20 个节点，剩余 80 个节点用于在 keep 的分支上加深，深度约 3–4 层——这正好匹配实际系统的深度限制。

输出的另一部分是修改序列的可读性。路径上的每个边对应一个动作描述（“tile 128→256”“加 split-K=2”），序列即一份人类可读的优化日志。这份日志的代价是它只对当前 shape 与当前基线有效，换 shape 后路径可能失效——这正是隐藏 shape 分布抽样要处理的问题，此处只需知道路径输出不是普适配方。最后落在机制上：终止时若最优路径的叶节点 R 与根节点持平（即搜索未找到任何改善），系统应输出根节点并标记“该 shape 下动作空间未覆盖有效修改”，这是结构性盲区的信号，而非搜索失败。

节点评估成本如何吃掉搜索预算

这套流程里最贵的不是 agent 生成 kernel 的 token，而是每个候选节点都要完整跑一遍正确性门与计时。生成侧一次修改通常只涉及几十到几百 token 的 diff，但验证侧要编译、启动、跑多组输入形状、再做计时，单节点落在 1–5 GPU 分钟量级。这意味着预算 100 节点就是 2–8 GPU 小时，而 UCT 的探索项 $$c\sqrt{\ln N(s)/N(s,a)}$$ 恰恰鼓励访问计数低的子节点——每探索一个新动作就实打实烧掉一份验证成本。于是搜索的边界由“能负担多少次完整评估”决定，而不是由树有多深决定：在固定 GPU 小时下，分支因子越大，每条路径被走到的次数越少，价值估计 $$Q(s,a)=\frac{1}{N(s,a)}\sum_i R_i$$ 的方差就越大，keep/revert 的判据也就越容易被单次噪声带偏。

失效条件集中在两类。其一是 reward 的稀疏性：$$R_i=\frac{T_{\text{base}}}{T_{\text{gen}}}\cdot\mathbb{1}[\text{Correct}]$$ 中正确性指示函数一旦为 0，整条分支的价值归零，而正确性门本身要花掉与计时相当的时间；若某类修改（如激进 split-K）正确率极低，树会把大量预算花在反复证伪同一族动作上，此时应降低该动作先验而不是继续按 UCT 展开。其二是动作空间的结构性盲区：动作空间由人工枚举 tile 大小、unroll、split-K、swizzle、向量宽度，未纳入的动作——典型如 CuTe layout 的定制——根本不在树的边集合里，搜索再充分也碰不到。这不是采样不足，而是可达集合被截断，任何 keep/revert 策略都无法弥补。

系统代价还体现在回传链路上。一次退化触发的 revert 不只是丢弃子节点，还要更新父节点的访问计数、下调该动作先验，并保证后续 UCT 选择不再被同一高估分支吸走；若回传实现为异步批处理，多个并发节点共享同一父节点时会出现计数竞争，导致 Q 值短暂不一致，进而让 keep/revert 判定抖动。工程上的判断是：把单节点评估成本压到可接受范围（缩小计时输入集、复用编译缓存、正确性门分级）比增大树宽更划算，因为前者直接放大可负担的节点数，后者只是把同样的预算摊薄到更多未验证的边上。
