一 · 负载画像：什么模型、算子、shape 与硬件才配得上隐藏分布

隐藏 shape 分布抽样不是通用评测器，它只对“shape 敏感、且真实负载存在长尾”的对象有判别力。选负载的第一条判据是算子对 shape 的敏感度：GEMM 的 M/N/K 三维、Attention 的 batch/heads/seq_len/head_dim、LayerNorm 的归一化维与行数、卷积的 NCHW 与 kernel 组合，这些量变化会同时改变 tiling 可行性、occupancy 与访存模式，因而在固定 shape 上过拟合的 kernel 一旦换 shape 就会暴露。相反，逐元素算子（elementwise、简单 reduction）对 shape 的敏感度低，隐藏抽样带来的分数方差主要来自测量噪声而非泛化差异，把它们放进隐藏集只是浪费 GPU 小时。

第二条判据是分布本身是否可拟合。生产 trace 里 shape 元组通常呈重尾：小 batch 的低时延请求占多数，大 seq_len 的离线批处理占少数但耗时占比高。拟合时要保留联合分布而不是各维边缘分布相乘——batch 与 seq_len 在真实负载中强相关（长序列往往配小 batch），独立采样会造出生产中不存在的组合，使隐藏集失去代表性。工程上以经验联合分布（直方图或核密度）分桶采样，并对每维做条件约束，保证采样出的元组落在 trace 支撑集内。

硬件侧的选择决定隐藏集能否区分“泛化好”与“碰巧快”。在 H100 级 GPU 上，tail 中的极端小 shape（如 batch=1、seq_len 很小）往往落入 launch 开销与 wave 量化主导的区间，此时 kernel 差异被固定开销淹没；而在 A100 或更小显存的卡上，tail 的大 shape 会直接触发显存不足或 spill，退化倍数被放大。因此隐藏集的硬件档位应与部署目标一致，跨档位复用同一批 shape 会引入与 kernel 质量无关的系统偏差。

一个具体例子：对 FlashAttention 类算子，head 段是 seq_len 在 512–2048、batch 适中的常见训练配置，tail 段包含 seq_len 为质数（如 1000、1023）与极短序列（如 17、64）。前者检验 tiling 在非 2 的幂边界上的正确性与浪费率，后者检验固定开销摊薄能力。若某 kernel 只在 2 的幂 seq_len 上做过特化分支，它在 tail 上的退化会直接体现在惩罚项里，而这正是生产端混合长度请求会遇到的情形。

二 · 基线选择：锚定在同一硬件、同一精度语义上的对照

隐藏分布评测的分数是相对量，基线的选择直接决定结论方向。基线必须满足三条：与待测 kernel 跑在同一硬件与同一驱动栈上；精度语义对齐（fp32 累加还是 tf32、是否允许 fast math）；输入分布与隐藏集完全一致。把厂商库（cuBLAS、cuDNN、CUTLASS 参考实现）作为基线时，要注意库函数自身对小 shape 有启发式分支，它在 tail 上的表现未必是“最优”而只是“可用”，因此基线分数在 tail 段天然偏低，惩罚项的分母被抬高，容易把中等退化误判为严重退化。更稳的做法是同时报告两组基线：库基线用于判断是否值得替换，手写参考实现（朴素但正确）用于判断退化是否来自算法而非实现细节。

基线锚定还有一个隐蔽代价：编译基线。若基线是 Triton 或 CuTe 实现，其编译时间与 autotune 缓存会影响首次评测时延；若基线是预编译 CUDA C++，则没有这一项。评测配方应把编译时间从 kernel 时延中剥离，单独记录，否则一个 autotune 激进的基线会在小 shape 上被编译开销拖累，使待测 kernel 的相对分数虚高。这与 TF32/编译基线锚定的处理是同一类问题，此处只强调：隐藏集上每个 shape 的基线时延必须是稳态测量（warmup 后多次取中位数），而不是首次调用。

基线还要覆盖“同一语义的不同实现路径”。以 LayerNorm 为例，基线可以是 fused 单 kernel，也可以是 decompose 成 reduction + elementwise 的两段式；后者在大行数、小归一化维时反而更快。若只锚定一种基线，隐藏集上某些 shape 的“加速”可能只是实现路径选择的差异，而非真正的优化。配方上要求基线在 head 与 tail 两段都跑一遍，并把基线自身的 shape 敏感度记录进审计日志，作为解释分数波动的参照。

具体代价：一条基线在 200–500 个隐藏 shape 上跑 fp64 参考加计时，若每个 shape 做 5 次 warmup 与 20 次计时，单卡 GPU 小时数会随 shape 数量线性增长；双基线（库 + 手写参考）意味着这部分开销翻倍。工程判断是：库基线必跑，手写参考只在 tail 段跑，因为 tail 段才是退化判定的关键区间，head 段的正确性已由公开集覆盖。

三 · 输入分布设定：head/tail 划分、抽样规模与 seed 治理

输入分布的设定分三步。第一步从 trace 提取 shape 元组并拟合经验分布；第二步按分位数划出 head 与 tail，常用 90%/10% 分位，即累计概率前 90% 的 shape 归入 head，剩余 10% 归入 tail，tail 内再按“极端程度”排序以便报告；第三步从 head+tail 按联合分布抽样 200–500 个 shape 组成隐藏集，公开集只暴露 head 段少量样例。抽样规模的下界由统计功效决定：tail 占 10%，200 个样本期望只有 20 个 tail shape，若 tail 内部还要按子类（极端小、极端大、非 2 的幂）分层报告，每层样本会少到无法给出稳定通过率，因此 200 是下限而非推荐值，500 更接近可用的分层粒度。

抽样必须带 seed 且 seed 加密，目的是让 agent 无法通过反复提交探测隐藏集内容。每轮评测重新抽样，使跨轮记忆失效：同一 agent 在第 k 轮记住的 shape 在第 k+1 轮不再出现，它只能学到分布层面的规律而不能背具体元组。seed 与分布参数（分位点、桶边界、各维条件约束）写入审计日志，保证复现性与事后归因。这里有一个工程权衡：重新抽样会让分数带轮间方差，若方差大于待测改进幅度，多轮比较就失去意义；缓解办法是固定分布参数、只变 seed，并在报告中给出跨 seed 的均值与离散度，而不是单轮分数。

分布设定还要处理“冷启动无 trace”的场景。此时只能人工构造分布，代表性存疑，配方上应明确标注为合成分布，并把 tail 的定义从“低概率”改为“工程上已知的困难区间”（非 2 的幂、跨 wave 边界、显存临界）。合成分布的隐藏集不应与公开集共享任何具体 shape，否则过拟合通道依旧存在。代价是：合成分布下的惩罚项只能说明“在该人造 tail 上退化”，不能直接外推到生产风险，报告里必须把这一局限写进结论而不是藏在附录。

公式上，加权聚合与惩罚项共同定义单轮得分：

$$\text{Score}=\sum_{s\in\mathcal{S}_{\text{hid}}} w_s\cdot\frac{T_{\text{base}}(s)}{T_{\text{gen}}(s)},\quad w_s=\frac{p(s)}{\sum_{s'}p(s')},\quad \text{Penalty}=\frac{1}{|\mathcal{S}_{\text{tail}}|}\sum_{s\in\mathcal{S}_{\text{tail}}}\max\left(0,1-\frac{T_{\text{base}}(s)}{T_{\text{gen}}(s)}\right)$$

权重 \(w_s\) 取自经验分布概率 \(p(s)\)，使高概率 shape 主导分数、低概率 shape 只做稀释；惩罚项只对 tail 中“比基线慢”的部分计分，快于基线的 tail shape 不产生负贡献，避免把 tail 优化奖励与退化惩罚混在一个符号里。一个具体例子：某 kernel 在 head 段平均 1.8× 加速，但在 seq_len=1023 的 tail shape 上只有 0.7×，若该 tail shape 权重很小，Score 仍可能为正，而 Penalty 会单独把它标出——这正是配方要两个指标并列的原因。

四 · 指标计算：正确性门、时延统计与退化倍数的口径

正确性在隐藏集上以 fp64 参考为 oracle，逐 shape 比对，容差按算子类型设定（归约类看相对误差，逐元素看绝对误差），任一 shape 不通过即该 shape 记为零分而不是跳过——跳过会让 agent 学会在难 shape 上“失败得安静”。批量跑正确性与时延的顺序有讲究：先跑正确性再计时，因为错误 kernel 可能触发非法访存或极慢路径，先计时会污染时延样本；同时正确性失败不应中断整批，否则一个坏 shape 会掩盖其余 shape 的表现。

时延统计的口径要写死：warmup 次数、计时次数、取中位数还是最小值、是否包含 kernel launch 与同步。隐藏集上 shape 多、单 shape 时长差异大，用最小值会系统性高估小 shape 的性能（受噪声下偏），用中位数更稳。退化倍数定义为 \(T_{\text{gen}}(s)/T_{\text{base}}(s)\)，报告时对 tail 段取几何平均而非算术平均，因为退化倍数跨数量级时算术平均会被单个极端值主导。通过率单独报告，不折进 Score，使“正确但慢”与“快但错”在报告里可区分。

指标聚合还要防止权重塌缩：若某个 head shape 的概率极高（例如占 40%），加权 Score 几乎由它决定，其余 shape 的改进被淹没。配方上对权重做上限截断（单 shape 权重不超过总权重的某个比例），或对 head 段按桶分层后再加权，保证分数对分布形状不过度敏感。代价是截断后 Score 不再严格等于期望加速比，解释时需注明这是“分层加权”而非“分布期望”。

具体例子：一个 Reduction kernel 在 500 个隐藏 shape 上跑，head 段通过率 100%、tail 段通过率 92%，tail 失败集中在非 2 的幂的归约长度上；其 Score 为正但 Penalty 显示 tail 几何平均退化 1.4×。报告结论应是“该 kernel 可用于 head 分布覆盖的负载，tail 需回退到基线”，而不是笼统的“加速 1.x 倍”。这种口径差异正是隐藏分布评测相对固定 shape 评测的核心增量。

五 · 负载不对时会发生什么：三种失效模式与工程判断

失效模式一：分布与部署不符。隐藏集从训练集群 trace 拟合，而部署在推理服务上，前者 batch 大、seq_len 长，后者 batch 小、请求短。此时 head 段全落在部署中不出现的区间，Score 再高也不预示线上收益，tail 惩罚项指向的“极端小 shape”反而是部署的常态。识别方法是把隐藏集的 shape 直方图与部署 trace 直方图做重叠度检查，重叠低则配方失效，需重新拟合。

失效模式二：tail 定义过窄。只把“非 2 的幂”当 tail，会漏掉“跨 wave 边界”与“显存临界”两类真实困难 shape；agent 可以针对已知 tail 子类做特化，而在未覆盖的困难区间崩溃。缓解是把 tail 分层并每轮在层内重新抽样，使特化成本高于泛化收益。代价是分层后每层样本少、通过率方差大，需要更多轮次或更大抽样规模来稳定。

失效模式三：基线在 tail 上失真。库基线在小 shape 上走启发式慢路径，使待测 kernel 的“加速”来自基线自身的低效而非 kernel 的优秀；一旦部署换用更合适的库分支，加速消失。工程判断是：tail 段的分数只在“待测 kernel 快于同一语义的最优已知实现”时才有部署意义，因此 tail 段应额外锚定一个手工调优的参考实现，而不是只信库基线。

三种失效的共同代价是评测的 GPU 小时被浪费在无判别力的 shape 上：200–500 shape 全量跑 fp64 参考与计时，单次评测约为公开集的 10×，若分布不对，这 10× 换来的是不可外推的分数。因此配方应在正式评测前做一次“判别力预检”：用一个人为退化的 kernel（例如只对大 batch 特化）跑隐藏集，若 Score 与 Penalty 不能把它与正常 kernel 区分开，说明分布或基线设置有问题，应先修配方再评 agent。这一步的预检成本远低于整轮评测，是负载配方里性价比最高的工程动作。

隐藏抽样配方的适用边界与失效代价

这套配方并非通用：它要求目标算子存在可采集的真实调用 trace，且 shape 元组（维度、batch、seq_len）的联合分布在生产中相对稳定。冷启动产品或尚未上线的算子只能人工构造分布，此时 head/tail 的 90%/10% 分位切分失去经验依据，代表性存疑——尾部被人工设定为“极端小/大、非 2 的幂”，可能恰好覆盖 agent 已见过的公开样例，反而削弱区分度。基线选择同样受限：$$\text{Score}=\sum_{s\in\mathcal{S}_{\text{hid}}} w_s\cdot\frac{T_{\text{base}}(s)}{T_{\text{gen}}(s)}$$ 中的 $T_{\text{base}}(s)$ 必须是同一硬件、同一输入分布下测得的参考实现（如 cuBLAS 或厂商 kernel），若基线本身在 tail shape 上退化，惩罚项会把基线的缺陷记到生成 kernel 头上，产生误判。因此基线需按 shape 分段核验，head 段用库实现、tail 段用朴素 fp64 参考计时，二者不可混用同一份时延表。

指标聚合的代价体现在评测预算上：隐藏集从 head+tail 按分布抽 200–500 个 shape，每个 shape 都要跑 fp64 参考的正确性比对与多次计时，单次评测的 GPU 小时数约为公开集的 10×。加权聚合虽稀释了刷单一 shape 的收益，但 $w_s$ 由 $p(s)$ 归一化后，head 段中高频 shape 仍占主导，agent 若把优化集中在少数高权重 shape 上，Score 依旧可观；此时 tail 惩罚项 $$\text{Penalty}=\frac{1}{|\mathcal{S}_{\text{tail}}|}\sum_{s\in\mathcal{S}_{\text{tail}}}\max\left(0,1-\frac{T_{\text{base}}(s)}{T_{\text{gen}}(s)}\right)$$ 才是真正的泛化闸门。它只惩罚退化、不奖励超越，因此一个在 tail 上持平基线的 kernel 惩罚为零，却可能掩盖其在极端 shape 上仅靠 fallback 路径通过的真相——通过率需与退化倍数分开报告，否则“通过但慢十倍”的 kernel 会被误读为泛化良好。

失效条件集中在抽样与记忆的对抗上：每轮重新抽样、seed 加密并写入审计日志，能阻止跨轮记忆，但若 agent 在多轮中观察到 Score 对某些 shape 的敏感度，仍可通过试错反推分布参数。200–500 个 shape 的抽样方差在 tail 段尤其大——tail 仅占 10%，实际抽到的极端 shape 可能只有十几个，单次评测的惩罚项估计噪声显著，需跨轮平均才能稳定。工程判断是：隐藏抽样适合已有生产 trace、且愿意支付 10× 评测预算的团队；对冷启动或算力紧张的场景，应退化为固定 tail 集加人工分布，并明确标注代表性缺口，而不是假装分布可信。
