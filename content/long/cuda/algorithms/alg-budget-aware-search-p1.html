一 · 一次“预算均摊”导致的评测翻车

设想一个典型的 agentic kernel 搜索回合：agent 在 KernelBench 风格的算子任务上生成了 24 个候选实现，评测流水线对每个候选执行“编译 → 小规模正确性 → 单次时延测量 → NCU profile → SASS 剖析”，每轮固定耗时。若按均匀预算，每个候选都拿到同样多的调优轮次，那么真正的问题不是“哪个候选更好”，而是“预算被谁吃掉了”。一次可复现的翻车形态是这样的：24 个候选中有 3 个在静态特征上就明显可疑（访存模式与参考实现的分块策略冲突、tile 尺寸导致共享内存超限、占用率估计过低），但它们仍然各自消耗了完整的编译与 profile 轮次；而另外 2 个在粗筛阶段时延已接近 roofline 的候选，因为剩余预算被摊薄，只来得及做一次 NCU 采集就被迫终止，最终输出的“最优 kernel”其实是那 3 个可疑候选里偶然跑通的一个。

这个事故的代价可以量化到三个维度。其一是 GPU 时间：编译加 profile 是真实占用设备的操作，24 个候选乘以固定轮次，等于把大量 SM 周期花在了注定被淘汰的实现上。其二是 token：每一轮 NCU 指标回灌、SASS stall 解释、agent 的反思与重写都要消耗上下文，均匀分配意味着 token 花在了低信息量的候选上——那些候选的 profile 数据几乎不携带“如何改进”的信号。其三是搜索深度：高潜力方向本应进入细粒度调优循环（改 tile、调 pipeline 深度、换 swizzle），但因为预算被摊薄，它们停留在“能跑但没调透”的状态。事故的本质不是某个候选写错了，而是预算调度策略与候选价值分布不匹配。

这就是预算感知由粗到细搜索要解决的具体问题：在编译与 profile 均有真实成本的前提下，把有限预算从“均摊”改为“按潜力分配”，让昂贵证据只花在少数值得深挖的候选上。它不解决的是：候选生成本身的质量（那是生成策略的问题）、正确性 oracle 的完备性（那是 checker 与形式验证的问题）、以及跨架构性能可移植性的先验校准（那是迁移问题）。换句话说，它优化的是“给定候选池，如何花预算”，而不是“如何生成更好的候选池”。

二 · 适用边界：它管什么、不管什么

这个方法成立的边界由三个前提界定。第一，候选池中存在显著的价值方差——如果所有候选质量接近，粗筛的排序信息量趋近于零，按潜力分配退化为均匀分配，收益消失。第二，存在廉价代理指标能够以远低于完整 profile 的成本对候选排序：静态分析（访存模式、tile 尺寸、占用率估计）、快速编译（只做语法与资源检查）、小 shape 试跑（单次时延）。第三，预算约束是硬的——总轮次、总 GPU 秒数、总 token 有上限，且每次细粒度调优的边际成本高于粗筛。三者缺一，coarse-to-fine 的调度就没有意义。

它明确不覆盖的场景同样重要。当正确性尚未建立时，预算分配毫无意义——一个连 fp64 参考都对不上的候选，其 profile 数据是噪声；这类问题应交给变异测试审计与 Fuzz+fp64 oracle 那条线。当评测合约本身可能被绕过时（例如候选通过特判隐藏 shape 作弊），预算调度无法替代防作弊合约校验。当需要判断“这个 kernel 是否真的跑满了 SOL”时，归一评分与 roofline 口径是另一条线的职责，本方法只负责决定“给哪个候选做这次测量”。

还有一个边界容易被忽略：粗筛的代理指标与细筛的真实瓶颈之间可能存在系统性偏差。小 shape 试跑能暴露 launch 开销与固定开销，却可能掩盖大 shape 才出现的 occupancy 骤降——当 tile 尺寸在小 shape 下恰好填满 SM、在大 shape 下因寄存器压力导致 occupancy 掉档时，粗筛会给出错误的乐观排序。因此本方法的设计必须包含“粗筛结论可被细筛推翻”的回退路径，而不是把粗筛当作一次性判决。

三 · 机制：潜力后验驱动的预算分配

核心机制是把预算分配写成一个带 bandit 修正的潜力估计问题。对候选 $i$，用静态特征向量 $\phi_i$（访存模式类别、tile 尺寸、占用率估计、历史同类算子成功率）与不确定性项构造潜力分数：

$$\text{alloc}_i=B\cdot\frac{\hat{p}_i^{\alpha}}{\sum_j \hat{p}_j^{\alpha}},\quad \hat{p}_i=\sigma\left(w^\top\phi_i+\beta\cdot\text{UCB}_i\right)$$

其中 $B$ 是剩余总预算（以轮次或 GPU 秒计），$\alpha$ 控制分配的集中程度（$\alpha$ 越大越集中于头部候选），$\sigma$ 把分数压到 $(0,1)$，$\text{UCB}_i$ 是置信上界项，$\beta$ 控制探索强度。这个式子的工程含义是：分配不是按“当前最好”而是按“潜力乘以不确定性”——一个静态特征平庸但证据稀少的候选仍能获得少量预算去证伪自己，而一个已被多轮 profile 证实平庸的候选其 UCB 收缩、分配趋近于零。$\alpha$ 与 $\beta$ 是两个必须显式暴露的旋钮：$\alpha$ 过大导致过早集中、漏掉慢热候选；$\beta$ 过大导致预算重新摊薄、退回均匀分配的浪费。

调度流程是四段式的。第一段，生成候选池后用静态特征做廉价打分排序，这一步不碰 GPU，成本是纯 CPU 与 token。第二段，对 top-k 做快速编译、小规模正确性与单次时延测量，淘汰明显劣质者——这一步的代价是编译时间与少量 GPU 秒，但换来了对候选池的第一次真实剪枝。第三段，把剩余预算按上式分配给存活候选，进入 NCU/SASS 细粒度调优循环；每一轮细粒度调优产出的 stall 归因、带宽利用率、指令混合比都回灌为后验更新。第四段，每轮重算 $\hat{p}_i$，低潜力候选提前终止，预算向头部回流；预算耗尽时输出最优合法 kernel 及其完整 profile 证据链。

这里的关键工程判断是“粗筛的淘汰必须是可逆的”。伪代码层面的做法是给每个被淘汰候选保留一个极小的“复活预算”，当某个存活候选在细筛中连续多轮无改进时，用复活预算重新测量一个此前被粗筛淘汰的候选。代价是这部分预算不产生直接收益，但它对冲了代理指标的系统性偏差——尤其是前述小 shape 掩盖大 shape 瓶颈的情形。没有这条回退路径，coarse-to-fine 就变成了“粗筛一锤定音”，而这正是它最容易被误用的形态。

四 · 代价：先验失准与漏检

第一个代价是迁移失准。潜力估计依赖静态特征权重 $w$ 与历史成功率，这些先验是在特定算子族、特定架构上拟合出来的。跨算子迁移时，访存模式的语义可能反转（同一个 tile 策略在规约类算子上是优势、在卷积类算子上是劣势）；跨架构迁移时，占用率估计的阈值随 SM 资源变化而漂移。先验失准的直接后果是过早淘汰好候选：一个在新架构上本应进入细筛的候选，因为静态打分偏低而被剪掉，且它的 profile 证据从未被采集，事后无法复盘。这类错误的代价不是单次 GPU 秒，而是整个搜索回合的最优解丢失。

第二个代价是粗筛漏检。小 shape 试跑的时延测量对小规模输入敏感，对固定开销（launch、初始化）敏感，但对大 shape 下的资源压力不敏感。一个在小 shape 下时延排名前三的候选，可能在大 shape 下因共享内存或寄存器溢出而 occupancy 骤降，实际性能远低于排名。粗筛把它排进头部，细筛才发现问题，此时已经消耗了本可给其他候选的预算。更隐蔽的情形是粗筛把它排进头部、细筛因为轮次不足只测了小 shape 就收工，最终输出一个“在小 shape 上合法且快、在大 shape 上退化”的 kernel——这是正确性 oracle 无法拦截的性能陷阱。

第三个代价是调度本身的开销。每轮重算后验、维护候选状态、记录证据链都要消耗 token 与工程复杂度；$\alpha$、$\beta$、top-k 的 $k$、复活预算的比例都是需要调的超参，调参本身消耗预算。相比之下，均匀分配的实现复杂度几乎为零。因此本方法的净收益必须显著超过这些调度开销才值得引入——在候选池价值方差小的任务上，它反而是负收益。

五 · 一个具体例子：分块规约算子的预算重排

取一个分块规约类算子作为例子。候选池 16 个，总预算设为 40 个调优轮次。均匀分配下每个候选 2.5 轮，实际执行中因为编译失败与正确性淘汰，存活候选的轮次进一步摊薄。粗筛阶段用静态特征打分：候选 A 的 tile 尺寸与共享内存预算匹配、访存模式为合并访问、占用率估计处于中高档，静态分排名第一；候选 B 的 tile 偏大、占用率估计偏低，排名第十二。top-8 进入快速编译与小 shape 试跑，候选 A 时延排名第二，候选 B 因编译通过但小 shape 时延平庸被淘汰。

按潜力分配后，候选 A 获得约三分之一的剩余预算，进入 NCU/SASS 细粒度循环：第一轮 NCU 显示其全局访存带宽利用率已接近 roofline，但 warp stall 集中在共享内存 bank 冲突；第二轮改 swizzle 后 stall 下降，时延改善；第三轮确认改善稳定，后验 $\hat{p}_A$ 上升，预算继续向其集中。与此同时，候选 B 的复活预算被触发一次——因为另一个存活候选连续两轮无改进，调度器把一个复活名额给了 B，在大 shape 下测量发现 B 的 occupancy 并未如静态估计那样骤降，反而因为更大的 tile 减少了循环开销，在大 shape 上时延优于 A。这个例子说明两件事：粗筛的静态打分可以正确地把 A 送进头部，但也会错误地剪掉 B；而复活预算的存在让 B 有机会用一次大 shape 测量翻案。代价是这次复活消耗了一个本可给 A 的轮次，A 的细筛深度因此少了一轮——这正是预算调度中“探索与利用”的真实张力，而不是可以两全的优化。

这个例子的工程含义是：预算感知搜索的输出不应只是“最优 kernel”，而应是“最优 kernel 加一条证据链”，说明每个候选在哪个阶段被淘汰、淘汰依据是什么、是否有复活记录。证据链让事后复盘能够区分“候选真的差”与“预算没给够”，也让跨任务迁移时的先验校准有数据可依。

六 · 何时不该用：三个否定判据

第一个否定判据是候选池价值方差不足。当生成策略已经足够强、候选之间的静态特征与时延分布高度集中时，粗筛排序的信息量低于其自身开销，按潜力分配退化为带噪声的均匀分配。此时应直接进入细筛，或改用固定 top-k 策略而不引入 bandit 后验。

第二个否定判据是正确性尚未建立。若候选池中大量实现连基本正确性都未通过，profile 数据不构成有效证据，预算分配失去意义。正确做法是先跑正确性 oracle 与合约校验，把候选池收缩到合法子集，再谈预算。把预算感知搜索用在未验证的候选池上，等于把 GPU 时间花在测量噪声上。

第三个否定判据是单候选调优成本远低于粗筛成本。当编译与 profile 极快、粗筛的代理测量并不比细筛便宜多少时，coarse-to-fine 的分层结构不产生节约，反而增加调度复杂度。此时均匀分配或简单轮转是更诚实的选择。判断这一点需要实测粗筛与细筛的单轮成本比，而不是凭直觉假设“粗筛一定便宜”。

落到工程判断上：预算感知由粗到细搜索的引入门槛是“候选池价值方差显著 + 粗筛代理成本显著低于细筛 + 正确性已建立”三条同时成立。任一不成立时，它带来的调度开销与先验失准风险会吞掉收益。真正需要它的是那些候选池大、单轮 profile 昂贵、且高潜力方向需要多轮细粒度调优才能收敛的 agentic 搜索回合——在这些回合里，预算分配本身就是搜索策略的一部分，而不是评测流水线的一个附属环节。
