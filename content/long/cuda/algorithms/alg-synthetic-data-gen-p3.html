一 · 训练分布扩增的目标式与逐项拆解

合成算子数据扩增的第一性对象是训练分布本身，而不是单个样本。给定算子族 op、形状空间与 dtype 集合，扩增后的训练集写作

$$\mathcal{D}_{\text{train}}=\mathcal{D}_{\text{real}}\cup\{(x_i,y_i,\text{ref}_i,T_{\text{ref},i})\}_{i=1}^{M},\quad x_i\sim p_{\text{synth}}(\cdot\mid\text{op},\text{shape},\text{dtype})$$

逐项看：xi 是算子实例的完整描述（算子语法树、shape、stride、dtype、边界标记），yi 是该实例在参考实现下的期望输出（或输出集合），refi 是可执行的参考实现句柄，Tref,i 是基线时延标签。四项缺一不可：只有 x 与 y 时样本只能做正确性监督，无法做性能奖励；只有 x 与 T 时无法构造可验证奖励。关键一步在于把 psynth 写成条件分解

$$p_{\text{synth}}(x)=\sum_{c\in\mathcal{C}}w_c\,p_{\text{op}}(c)\,p_{\text{shape}}(s\mid c)\,p_{\text{dtype}}(d\mid c,s)\,p_{\text{edge}}(e\mid c,s,d)$$

其中 wc 是算子类别权重（逐元素、归约、矩阵乘、卷积、attention 及其融合组合），pedge 控制边界条件（非对齐长度、奇偶 stride、广播、空张量、极端缩放）的注入概率。这个分解的意义是：扩增的“覆盖度”可以被显式度量，而不是靠随机采样碰运气。代价侧：M 增大直接抬高标注成本——每个样本要跑一次 fp64 参考实现与一次基线，参考实现若用 PyTorch 逐元素语义，单样本时延可达毫秒级，M=105 量级时标注流水线的墙钟时间与显存占用成为瓶颈；同时 pedge 调高会让样本中大量落在慢路径上，基线时延标签的方差变大，奖励信号噪声上升。具体例子：对归约算子，若把 pedge 设为“长度非 2 的幂且非 128 倍数”占三成，则参考实现的 kernel 选择会从向量化路径退化到标量尾循环，Tref 的分布出现双峰，训练时若不按难度分层，模型会学到“归约就是慢”的错误先验。

二 · 评分公式：从时延到可比较的标量

评分必须把绝对时延转成与硬件、shape 无关的可比标量，否则不同实例的奖励不可加。设实例 i 的候选 kernel 时延为 Tcand,i，基线时延为 Tref,i，评分定义为

$$S_i=\mathrm{clip}\!\left(\frac{T_{\text{ref},i}}{T_{\text{cand},i}},\,\epsilon,\,S_{\max}\right)\cdot\mathbb{1}[\text{correct}_i]$$

比值形式的好处是量纲归一：Si=1 表示与基线持平，>1 表示加速。clip 下界 ε 防止候选实现慢到秒级时奖励变成大负数导致梯度爆炸，上界 Smax 防止对某个极端小 shape 的偶然超加速被过度奖励（小 shape 下启动开销主导，比值失真）。指示函数把正确性作为硬门：错误实现得零分而非负分，避免“快但错”的样本污染策略。推导的关键一步是把比值取对数再聚合：

$$\mathcal{R}=\frac{1}{N}\sum_{i=1}^{N}\log S_i=\frac{1}{N}\sum_i\left(\log T_{\text{ref},i}-\log T_{\text{cand},i}\right)$$

对数域聚合让“快 2 倍”与“慢 2 倍”对称，且几何平均对个别离群实例不敏感。代价：clip 与对数变换都会压缩信号——当候选实现普遍落在 Smax 附近时，奖励梯度趋近于零，策略停止改进；当 ε 设得过低，错误但极快的实现（例如跳过部分输出写入）会拿到高比值，必须靠正确性门拦截。具体例子：一个 attention 融合算子，基线 Tref 在长序列下由带宽主导，候选实现若把 softmax 的中间结果留在寄存器中避免回写，比值可稳定大于 1；但若序列长度短到启动开销主导，两者时延都在微秒级，比值在 0.9–1.1 间抖动，此时应把该实例从奖励聚合中降权而不是硬性计入。

三 · 时延与显存公式：把 roofline 约束写进样本标签

为了让合成样本自带“可达上限”的先验，每个实例除 Tref 外还应记录其 roofline 下界。对访存主导的逐元素/归约类，下界为

$$T_{\text{mem}}=\frac{B_{\text{read}}+B_{\text{write}}}{BW_{\text{eff}}},\qquad B=\prod_{k}\text{shape}_k\cdot\text{bytes}(\text{dtype})$$

对计算主导的矩阵乘类，下界为 Tflop=FLOPs/Fpeak，实际下界取两者较大值 Tlb=max(Tmem,Tflop)。BWeff 不是峰值带宽，而是按访问模式打折后的有效带宽：非合并访问、stride 跨步、广播读都会让实际带宽显著低于峰值，折扣因子需按 dtype 宽度与对齐情况分别标定。把 Tlb 写进样本后，评分可改为相对 SOL 的归一形式 Si=Tlb,i/Tcand,i，从而跨硬件可比（该归一化本身在别处展开，此处只借用其形式）。显存侧约束同样要进样本：候选实现的峰值显存 Mpeak 必须满足

$$M_{\text{peak}}\le M_{\text{budget}}=\alpha\cdot M_{\text{ref}},\quad \alpha\in(1,2]$$

否则“用双倍显存换速度”的实现会拿到虚高评分。代价：记录 Tlb 需要额外一次 profile 或解析计算，对融合算子（如 conv+bn+relu）的 FLOPs 与字节数估算本身有误差，标签噪声会传导到奖励；α 设得过紧会误杀合法的分块/双缓冲实现，设得过松则失去约束意义。具体例子：一个 dtype 为 fp16、shape 为 (4096, 4096) 的逐元素加法，读两个张量写一个，字节数约 3×40962×2，若 BWeff 按合并访问取峰值七成，则 Tmem 给出一个明确下界；候选实现若因未对齐导致实际带宽只有四成，其 Si 会明显低于 1，评分正确反映“未达 SOL”。

四 · 误差公式：正确性 oracle 的容差与判据

合成样本的正确性判据不能是逐位相等。设参考输出为 yref（fp64 计算后降精度），候选输出为 ycand，判据写作

$$\text{err}=\frac{\lVert y_{\text{cand}}-y_{\text{ref}}\rVert_2}{\lVert y_{\text{ref}}\rVert_2+\delta},\qquad \text{correct}\iff \text{err}\le\tau(\text{dtype},\text{op})$$

分母加小量 δ 防止参考输出接近零时相对误差爆炸。容差 τ 必须按 dtype 与算子类型分档：fp32 归约因累加顺序不同，误差随归约长度增长，τ 应随 log(归约长度) 放宽；fp16 矩阵乘的累加误差更大，需单独档位。推导的关键一步是把误差预算拆成“算法误差 + 实现误差”：算法误差来自不同的累加树形状，实现误差来自指令选择与舍入，前者不可消除，后者才是要惩罚的对象。因此 τ 的下界应由同一算子的两种合法实现（例如不同 tile 大小的 cuBLAS 调用）之间的误差实测标定，而不是拍脑袋。代价：τ 过松会放过有真实 bug 的实现（例如漏写边界元素但整体范数误差仍小），过紧会把合法的重排实现判错，直接污染奖励信号；相对误差判据对稀疏输出（大量零元素）不敏感，需辅以最大绝对误差与逐元素检查。具体例子：一个长度为 8192 的 fp32 求和归约，顺序累加与树形累加的相对误差可差一个数量级，若 τ 按顺序累加标定，则树形实现会被误判为错误，训练信号把模型推向“模仿参考实现的累加顺序”而非“更快且数值可接受”。

五 · 奖励整形与伪代码落地

把评分、正确性门、显存约束与难度分层合成最终奖励：

$$r_i=\mathbb{1}[\text{correct}_i]\cdot\mathbb{1}[M_{\text{peak}}\le M_{\text{budget}}]\cdot\left(\lambda\log S_i+\mu\,\mathbb{1}[S_i>S_{\text{ref}}]\right)\cdot\omega(\text{difficulty}_i)$$

λ 控制连续信号权重，μ 给“超过基线”一个离散奖励以加速早期学习，ω 是难度分层权重（冷门算子、极端 shape 权重更高，防止模型只刷热门算子）。伪代码落到可实现层面：

对每个采样实例：① 由 psynth 分解依次抽 c、s、d、e，组装算子描述；② 生成 fp64 参考实现并跑一次得到 yref 与 Tref，同时解析计算 Tlb；③ 用候选 kernel 编译执行，捕获 Tcand、Mpeak 与 ycand；④ 按第四节判据算 err 与 correct；⑤ 按本节公式算 ri 并入 buffer。实现要点：编译失败与超时应作为独立的零奖励分支而非异常抛出，否则采样循环会被单个坏实例打断；Tcand 需多次测量取中位数以压制启动抖动；Mpeak 用分配器钩子而非事后估算。代价：每样本一次 fp64 参考 + 一次候选编译 + 多次计时，单样本墙钟成本在百毫秒量级，M=105 时需并行化与缓存（相同 x 的 yref、Tref 可复用）；ω 的引入会让有效样本数下降，方差增大。具体例子：一个冷门算子（例如带 mask 的分段归约）被赋予高 ω，若其参考实现本身有边界 bug，则高权重会把错误 oracle 的影响放大，这正是需要独立审计参考实现的原因。

六 · 公式间的耦合与工程判断

上述公式不是独立的：评分里的 Tref 同时是奖励分母与 roofline 标签的来源，误差判据里的 τ 决定正确性门，而正确性门又乘在奖励最外层。耦合带来的第一个工程判断是：Tref 的测量协议必须与 Tcand 完全一致（同一计时方法、同一预热次数、同一输入驻留状态），否则比值系统性偏移，模型会学到“基线慢”的假象而非“自己快”。第二个判断是难度权重 ω 与 psynth 的 wc 要分开：前者作用于损失聚合，后者作用于采样，混在一起会让“采样多”被误读为“重要”。第三个判断是误差容差 τ 应随 Tlb 的算子类别分档，因为计算主导与访存主导的舍入行为不同，统一 τ 会在两类之间制造不公平。代价层面：任何一项调参都会改变奖励分布的尾部，尾部样本恰是 RL 最敏感的部分，因此调参必须在小规模验证集上先看 Si 的直方图再上线。具体机制上，建议把 ri 的四个因子分别记录为独立字段而非只存标量，这样当训练出现退化时能定位是正确性门误杀、显存门误杀、还是评分压缩导致梯度消失——这是把公式变成可调试系统的最小代价。

合成分布的可信边界：oracle 污染、基线时延偏差与真实端到端失效

把合成算子实例混入训练集，本质是在改变 $$p_{\text{train}}$$ 的支撑集，而奖励信号的可信度取决于标注链路每一环的误差是否被放大。公式 $$\mathcal{D}_{\text{train}}=\mathcal{D}_{\text{real}}\cup\{(x_i,y_i,\text{ref}_i,T_{\text{ref},i})\}_{i=1}^{M},\quad x_i\sim p_{\text{synth}}(\cdot\mid\text{op},\text{shape},\text{dtype})$$ 里最容易被忽视的是 $$\text{ref}_i$$ 与 $$T_{\text{ref},i}$$ 这两个字段：它们不是从真实框架调用中采集的，而是由生成器自动产出的。若参考实现本身在某个边界条件上写错（例如归约在非连续 stride 下的索引映射、attention 在 causal mask 边界上的越界读），那么 oracle 会把错误答案当成正确性标准，RL 的可验证奖励就会奖励错误行为。代价不是单个样本的噪声，而是整批合成样本在同一边界族上的系统性污染——变异测试审计（对参考实现注入等价变异、检查 oracle 是否报错）是唯一能在不依赖人工逐条核对的前提下暴露这类 bug 的手段，其成本是每个算子族的变异体数量乘以参考实现的执行时延，属于离线一次性开销，但必须在扩增规模放大前完成。

第二个边界在 $$T_{\text{ref},i}$$ 的语义上。合成算子跑 PyTorch/cuBLAS 基线得到的时延，是“该 shape/dtype 在该后端上的时延”，而不是“真实框架调用中该算子的时延”。真实框架调用往往伴随 layout 转换、算子融合前后的边界 kernel、以及 stream 同步开销，这些在孤立基线测量中不存在。于是奖励里“相对基线的加速比”在合成样本上偏乐观：模型学到的是在干净输入上打败 cuBLAS，而不是在带 layout 约束的调用链里打败端到端路径。失效条件是合成分布中融合模式与真实框架的融合模式不匹配——生成器若只采样单算子，模型在真实端到端场景里遇到融合算子时会退化到逐算子调用，性能骤降。系统代价体现在评估环节：必须保留一条真实基准（KernelBench/真实框架算子）的监控通道，持续度量合成-真实分布差距，这条通道的评估时延不能计入训练吞吐，属于纯开销。

第三个边界是难度分层采样与 token 预算的耦合。按难度分层采样意味着每个 batch 里长尾算子的比例被人为抬高，而长尾算子的参考实现更长、边界条件更多，生成与验证的 token 消耗显著高于热门算子（GEMM/attention 的参考实现短、模板化程度高）。若不分层，热门算子会淹没长尾；若分层过重，单步 RL 的采样成本上升，且模型在热门算子上的收敛速度被拖慢。可实现的伪代码思路是：对每个算子族维护一个难度桶，采样时按桶权重抽取，桶权重随该族在真实基准上的通过率动态调整——通过率低的族权重上调，但设上限，防止单一冷门族占据过多 token。代价是调度器的状态维护与每轮真实基准评估的时延，收益是跨算子泛化的方差下降。工程判断落在：合成扩增的规模上限不由生成器吞吐决定，而由 oracle 审计覆盖率与真实基准监控频率共同决定，二者任一不足时，扩增带来的分布偏移就会以端到端性能骤降的形式暴露。

合成分布偏移下的奖励失真与审计闭环

扩增集真正危险的不是“合成算子本身写错”，而是合成分布 psynth 与真实框架调用分布之间的偏移被奖励函数悄悄放大。设真实分布为 preal，若训练奖励按合成集均匀加权，则策略实际优化的期望奖励是 𝔼synth[r]，而部署目标是 𝔼real[r]。两者之差可写成重要性重加权形式：

$$\Delta=\mathbb{E}_{p_{\text{real}}}[r]-\mathbb{E}_{p_{\text{synth}}}[r]=\mathbb{E}_{p_{\text{synth}}}\!\left[\left(\frac{p_{\text{real}}(x)}{p_{\text{synth}}(x)}-1\right)r(x)\right]$$

关键一步在于：preal/psynth 在长尾 shape 上往往远小于 1，而在热门 GEMM/attention 变体上大于 1。若合成采样器对 shape 维度做对数均匀采样、对 dtype 做均匀采样，却对融合模式只取少数模板，则比值在融合维度上系统性偏离，Δ 的方差被放大——表现为合成集上 reward 稳步上升，真实 KernelBench 子集上时延却回退。工程上必须把该比值作为采样权重显式写入数据管线，而不是事后补救。

第二个失效条件是 oracle 污染。合成参考实现由生成器自动产出，一旦某个归约边界条件写错（例如非连续 stride 下的越界掩码），错误参考会把“正确但不同”的 kernel 判为失败，奖励信号反向。变异测试是低成本审计手段：对参考实现注入受控变异（偏移索引、漏掉 mask、错用 fp32 累加），要求 oracle 必须判失败；若变异体仍通过，则该算子族的合成样本整批隔离，不进入训练集。代价是每个算子族多一次参考实现编译与两次执行，编译时间与显存占用翻倍，但相比污染整轮 RL 的代价可以接受。

失效源可观测信号系统代价
分布偏移合成 reward 与真实子集 reward 背离需保留真实 holdout，采样权重计算增加数据管线时延
oracle bug变异体通过率异常每族额外编译+执行，显存峰值上升
基线时延失真合成样本 Tref 与真实框架同算子时延差距大需重跑 cuBLAS/PyTorch 基线，token 与 wall-clock 成本增加

因此合成扩增的边界应写成一条工程判据：只有当合成集上的奖励提升能在固定真实 holdout 上被复现，且变异测试通过率高于阈值时，该批合成数据才允许进入 RL 训练；否则只作为 SFT 的课程数据按难度分层降权使用。这把“扩增”从无界生成变成带审计门控的受控注入。
