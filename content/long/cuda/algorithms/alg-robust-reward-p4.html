一 · 负载选择：把测量噪声压到奖励尺度以下

鲁棒奖励塑形的第一道工程决策不是统计量，而是负载本身。公式里那个 $$\tilde{T}=\text{median}(T_1,\dots,T_k)$$ 的方差，直接由被测 kernel 的单次执行时长决定：单次执行越短，频率抖动、噪声邻居、缓存冷热带来的相对扰动越大，中位数与 MAD 估计出来的置信区间就越宽，$$\text{LB}=\tilde{T}-z\cdot\frac{\text{MAD}}{\sqrt{k}}$$ 里的减项就越容易吃掉真实加速。因此负载筛选的第一条判据是：候选 kernel 的单次时延必须显著大于测量系统的时间分辨率与抖动幅度，使 $$\frac{\text{MAD}}{\tilde{T}}$$ 落在可控区间。工程上更稳的做法是把多个 shape 或多次迭代打包成一个测量单元，让每次计时覆盖足够长的 GPU 忙碌窗口，而不是去测一个几微秒的孤立 launch。

第二条判据是负载对优化空间的敏感度。若某算子在目标硬件上已经贴着带宽上限，任何合法 kernel 变体的时延差都落在噪声带内，此时奖励函数退化为常数零，RL 得不到梯度信号，策略只会在等价实现之间随机游走。这类负载应当排除，或者改用对指令级、访存模式更敏感的变体（例如改变 tile 形状、改变数据布局）来放大差异。反过来，若负载过于宽松（例如严重受限于 launch 开销或 Python 侧调度），则 kernel 内部的质量差异被外层开销淹没，同样测不出信号。

第三条判据是正确性 oracle 的可构造性。负载必须允许在合理成本内生成高精度参考结果，否则 $$r=\mathbb{1}[\text{correct}]\cdot\max\left(0,\frac{T_{\text{ref}}}{\text{LB}}-1\right)$$ 中的指示函数无法可靠置位，奖励会被错误的正例污染。数值稳定性差的归约、累加顺序敏感的算子，需要更严格的容差设计与 fp64 参考路径，这部分代价要提前计入评测预算。第四条判据是编译与启动成本：Triton 或 CuTe 候选的首次编译、autotune 扫描会引入与 kernel 质量无关的时延，必须通过 warmup 与缓存预热剥离，否则 $$T_1,\dots,T_k$$ 中混入编译时间，MAD 被虚假放大。

具体例子：一个逐元素激活算子在小 shape 下单次时延处于微秒量级，抖动占比高，适合把 batch 维拼大后测量；而一个已经接近显存带宽上限的大矩阵乘，若候选实现只在寄存器分配上有微小差异，则应改用能暴露这些差异的中间 shape，或直接不作为奖励塑形的训练负载。判断标准不是“难不难”，而是“合法实现之间的时延差是否稳定地大于置信区间宽度”。

二 · 硬件与 shape 分布：让噪声结构可复现

硬件选择决定了噪声的来源结构。共享 GPU 上的噪声邻居会引入与时间相关的干扰，其自相关长度可能超过单轮测量的窗口，导致 $$T_1,\dots,T_k$$ 不满足独立同分布假设，MAD 低估真实方差，置信下界偏乐观。因此评测配方必须规定测量环境：锁定频率、独占或隔离 SM、固定电源策略、关闭会周期性抢占的旁路任务。锁频的代价是牺牲峰值频率下的绝对性能代表性，换来的是跨轮次可比性；对 RL 奖励而言，可比性优先于绝对峰值。

shape 分布的设计要同时满足两个目标：覆盖真实部署的关注区间，以及让奖励信号在训练过程中保持非退化。若所有 shape 都落在同一性能 regime，策略容易过拟合到该 regime 的特定优化；若 shape 跨度过大，则同一批候选在不同 shape 上的加速比符号可能相反，中位数聚合会把信号抹平。可行做法是分层采样：按算子类别与规模档位分层，每层内部独立计算稳健统计量与置信下界，再按层权重合成奖励。这样每层的 $$\text{LB}$$ 都基于同质样本，避免把大 shape 的低方差与小 shape 的高方差混在一个 MAD 里。

硬件与 shape 的匹配还影响基线锚定的有效性。参考时延 $$T_{\text{ref}}$$ 必须在与候选完全相同的硬件、频率、shape、输入分布下测得，任何一项不一致都会把系统偏差注入奖励。工程上应把基线测量与候选测量交错进行，而不是先批量测基线再批量测候选，以抵消环境随时间的漂移。交错测量的代价是调度复杂度上升与总 GPU 时间增加，但换来的是漂移误差的一阶抵消。

具体例子：同一归约算子在较小 shape 上受 launch 开销支配，在较大 shape 上受带宽支配，两者的 MAD 量级差异明显。若不分层，中位数会被大 shape 的稳定样本主导，小 shape 上的真实改进被淹没；分层后，小 shape 层的置信下界更宽，只有明显超出噪声的改进才被奖励，这正是鲁棒塑形想要的行为。

三 · 基线怎么选：参考实现的三个约束

基线不是“随便一个能跑的版本”，它同时承担三个角色：奖励公式中的分母、正确性比对的参照、以及性能归因的锚点。第一个约束是基线必须与候选走同一条测量管线——同样的 warmup 次数、同样的重复次数 k、同样的统计量。若基线只测一次而候选测 k 次，$$T_{\text{ref}}$$ 的噪声未被抑制，比值 $$\frac{T_{\text{ref}}}{\text{LB}}$$ 的方差由分子主导，稳健化只做了一半。第二个约束是基线必须足够强，强到“超过它”意味着真实工程量而非噪声侥幸；过弱的基线会让大量候选轻易获得正奖励，奖励分布右偏，策略学到的是绕过弱基线的捷径而非真正的优化。

第三个约束是基线必须稳定可复现：同一基线在同一环境下重复测量的离散度应显著小于候选间的预期差异。若基线本身抖动大，说明该负载不适合作为奖励塑形的训练对象，应更换负载而非加大 k。基线的选择还要与算子类别匹配：访存受限算子应以接近带宽上限的实现为基线，计算受限算子应以充分利用流水线的实现为基线，避免用错误 regime 的基线制造虚假加速空间。

基线的维护成本常被低估。每次硬件更换、驱动升级、编译器版本变化，基线都需重新测量并记录其 MAD，否则 $$T_{\text{ref}}$$ 携带系统性偏差。工程上应把基线测量纳入版本化流程，与候选测量共用同一套锁频与隔离配置，并把基线的置信区间一并存档，供后续判断奖励漂移是来自策略还是来自环境。代价是每次环境变更都要付出额外的测量轮次，收益是奖励信号的跨时间可比性。

具体例子：若基线是一个未经调优的朴素实现，候选只需做基本的向量化就能获得大幅“加速”，此时奖励函数给出强正信号，但策略学到的是低水平的常规改写；把基线换成同类别中已调优的实现后，同样的候选加速比收缩到噪声带附近，奖励归零，策略被迫去寻找更高阶的优化。这一替换不改变公式，只改变分母，却直接改变了训练信号的难度梯度。

四 · 输入分布怎么设：正确性与时延的双重敏感源

输入分布同时影响正确性判定与时延测量。对正确性而言，分布必须覆盖数值边界：极小值、极大值、接近溢出的累加、稀疏与稠密混合、非对齐长度、退化 shape。仅用均匀随机分布会让大量边界缺陷漏检，$$\mathbb{1}[\text{correct}]$$ 被高估，错误实现获得正奖励，污染策略。对时延而言，输入分布影响访存模式与分支走向：稀疏输入可能让候选走上与稠密输入完全不同的代码路径，测得的时延不能代表目标场景。

因此评测配方应把输入分布显式参数化，并与 shape 分层绑定：每个 shape 层配一组固定的输入种子集合，保证跨轮次可比；同时保留一小部分轮换种子用于探测过拟合。固定种子的代价是策略可能针对特定输入做特化，轮换种子用于检测这种特化——若候选在固定种子上加速显著而在轮换种子上退化，说明优化不具备泛化性，应在奖励上打折或直接判负。

输入分布的规模也影响测量成本。大输入意味着单次时延长、抖动占比低，但每次重复测量的显存占用与数据准备时间上升；小输入抖动占比高，需要更多重复次数 k 才能把 $$\frac{\text{MAD}}{\sqrt{k}}$$ 压到可用水平。这是一个显存、时延与 token 预算的三方权衡：k 增大线性增加 GPU 时间，而数据准备若在 CPU 侧完成还会引入主机到设备的传输开销，必须从计时窗口中排除。

具体例子：一个 softmax 类算子在含大量相同值的输入上，候选可能因分支预测或归约顺序获得与随机输入不同的时延；若只用随机输入测时延，会漏掉这一路径的性能差异。配方应规定输入分布包含至少一类退化输入，并在该分布下单独计算稳健统计量，避免把不同分布的样本混入同一个中位数。

五 · 指标怎么算：从原始时延到可比较的奖励

指标计算的核心是把原始时延分布压缩成一个对噪声不敏感、对真实改进敏感的标量。第一步是异常值处理：在计算中位数之前，按预先声明的规则剔除明显离群点（例如超出四分位距若干倍的样本），但剔除规则必须在测量前固定，不能根据结果事后调整，否则等价于对奖励做选择性裁剪。第二步是稳健中心与离散度：中位数给出中心，MAD 给出离散度，二者都不依赖正态假设，对频率抖动造成的重尾更稳。

第三步是置信下界的构造。$$\text{LB}=\tilde{T}-z\cdot\frac{\text{MAD}}{\sqrt{k}}$$ 中 z 的取值决定了保守程度：z 越大，下界越低，越不容易给出正奖励，漏检真实小幅改进的概率上升；z 越小，噪声驱动的虚假加速越容易通过门槛。z 的选择应与 k 联动——k 增大使标准误下降，可以在保持同等保守度的前提下减小 z，从而在测量成本与灵敏度之间取得平衡。第四步是奖励映射：$$r=\mathbb{1}[\text{correct}]\cdot\max\left(0,\frac{T_{\text{ref}}}{\text{LB}}-1\right)$$ 只在置信下界超过参考时延的倒数关系上给正奖励，且用 max 截断负值，避免对慢于基线的候选施加无界惩罚而导致策略崩溃。

指标还需处理跨 shape 聚合。若各 shape 层的 $$\text{LB}$$ 量级不同，直接平均会让大方差层主导奖励；应按层内归一后再合成，或对每层独立设门槛、只有多数层通过才给整体正奖励。后者的代价是奖励更稀疏，收敛更慢，但能有效阻止“在一个 shape 上大幅加速、在其余 shape 上退化”的投机行为。奖励进入 RL 前还需 normalization 与 clipping，把不同量级的加速比映射到稳定区间，防止个别极端样本主导梯度。

具体例子：某候选在 k 次测量中位数略优于基线，但 MAD 较大，置信下界落在基线之下，按公式奖励为零；另一候选中位数改善幅度小但测量离散度极低，下界稳定超过基线，获得小幅正奖励。前者可能是噪声侥幸，后者是真实但有限的改进，公式的行为符合工程直觉：奖励的是可复现的改进，而非单次亮眼数字。

六 · 负载不对时会发生什么：三类失效模式

第一类是信号淹没。负载的单次时延过短或外层开销占比过高，导致合法实现间的差异小于置信区间宽度，$$\text{LB}$$ 在所有候选上都落在基线附近，奖励恒为零。策略在等价实现间随机震荡，训练曲线平坦但 GPU 时间照常消耗，这是最隐蔽的失效——看起来在训练，实际没有学到任何可迁移的优化。诊断方法是监控奖励方差：若奖励方差随训练轮次收敛到接近零而正确率不变，说明负载已失去区分度。

第二类是虚假奖励。基线过弱或测量环境未隔离，噪声邻居造成的偶发快样本被中位数捕获，置信下界偶然超过基线，错误实现或未真正优化的候选获得正奖励。这类污染比信号淹没更危险，因为它会把策略推向投机行为：例如针对特定输入特化、利用缓存热态、或触发未定义行为来缩短时延。防作弊合约与变异测试审计在这里承担把关角色，但负载层面的防线是确保基线足够强、环境足够隔离、k 足够大。

第三类是过拟合负载。shape 与输入分布过于固定，策略针对该分布做特化，在固定种子上加速显著，在轮换种子或真实部署分布上退化。奖励公式本身无法识别这种特化，因为它只看到固定分布下的时延。防线是在评测配方中内置分布轮换与分层聚合，把泛化性纳入奖励结构，而不是事后补救。代价是每轮测量需要覆盖更多分布，GPU 时间与数据准备成本上升。

三类失效的共同根源是负载与测量系统的匹配度不足，而非统计量本身有缺陷。稳健统计量只能抑制噪声，不能创造信号；置信下界只能过滤虚假提升，不能替代强基线。工程判断应落在负载筛选的前置决策上：先确认合法实现间的时延差稳定大于置信区间宽度，再谈 k 与 z 的调参；先确认基线足够强且环境足够隔离，再谈奖励塑形的收敛速度。负载选错时，加大 k 只会让零奖励更稳定地为零，让虚假奖励更稳定地出现。
