一 · 优势公式的逐项拆解与留一法 baseline 的构造

把公式拆成可实现的量，先看优势项本身：

$$A_i=r_i-\frac{1}{G-1}\sum_{j\ne i}r_j$$
这里 ri 是第 i 个候选 kernel 的标量奖励，求和项是该样本之外其余 G−1 个候选的奖励均值。注意 baseline 的下标是 −i，它随 i 变化，因此组内每个样本看到的对照都不同。这一点是留一法与“组内均值 baseline”的全部差别所在：若把 baseline 写成 r̄ = (1/G)Σrj，则 Ai = ri − r̄ 中 ri 同时出现在被减数与减数里，产生 −(1/G)ri 的自相关项；留一法把 ri 从 baseline 中剔除，自相关项消失。

推导的关键一步是期望无偏性。设同一 prompt 下 G 个候选的奖励为独立同分布、均值 μ 的随机变量（这是把“同一 prompt 的多次采样”视为同分布抽样的建模假设），则

$$\mathbb{E}[A_i]=\mathbb{E}[r_i]-\frac{1}{G-1}\sum_{j\ne i}\mathbb{E}[r_j]=\mu-\mu=0$$
即优势在期望上为零——这正是策略梯度所要求的：baseline 只允许改变方差，不允许改变梯度的期望。若改用组内均值，则 E[Ai] = μ − μ = 0 同样成立，但方差不同。留一法 baseline 与 ri 的协方差为零（因为 j≠i 的样本与 ri 独立），而组内均值 baseline 与 ri 的协方差为 σ²/G，这一项在方差展开中贡献负值以外的交叉项，使得单样本优势方差在 G 较小时被抬高。这就是“无偏且低方差”的定量来源，而不是定性口号。

代价落在采样预算上：每组要凑齐 G 个候选并全部走完编译、验证、测速，GPU 时间随 G 线性增长。G 增大时留一法 baseline 的方差按 1/(G−1) 收缩，但每组编译测速的墙钟时间也线性上升，且组内样本高度同质（全失败或全通过）时 Ai 趋近零，梯度信号被稀释。工程判断是：G 不是越大越好，而是要让组内奖励分布跨越“失败/部分正确/正确且更快”几个档位。

二 · 策略梯度公式中 1/G 因子的来源与裁剪的介入点

梯度公式为

$$\nabla_\theta J=\mathbb{E}\left[\frac{1}{G}\sum_{i=1}^{G}A_i\nabla_\theta\log\pi_\theta(\tau_i)\right]$$
逐项看：τi 是第 i 条采样轨迹（在这里就是一段生成 kernel 的 token 序列及其工具调用），∇θlogπθ(τi) 是该轨迹的对数似然梯度，Ai 是上一节的留一法优势，外层 1/G 是对组内 G 个样本求平均。1/G 因子的作用是把“每组一次更新”归一化为“每样本一次更新”的尺度，使得不同 G 的实验之间学习率可比；若漏掉它，梯度幅值会随 G 线性膨胀，等效于把学习率乘以 G。

推导的关键一步在于把组内平均写成对样本的期望：当 G 个样本来自同一 prompt 的采样分布时，(1/G)ΣiAi∇logπ 是对 Eτ~π[A(τ)∇logπ(τ)] 的蒙特卡洛估计，而 A 的留一法构造保证该估计的期望等于真实策略梯度。这里有一个容易被忽略的实现细节：Ai 在进入乘积前通常要做组内标准化与裁剪。标准化用组内标准差 σgroup 去除，得到 Ãi = Ai/σgroup；裁剪把 |Ãi| 限制在阈值内。裁剪引入的偏差是可控的——它牺牲了严格无偏性换取梯度范数的稳定性，代价是当组内出现极端离群奖励（例如某个候选意外通过全部正确性检查且测速极快）时，其梯度贡献被截断，学习信号被削弱而非被放大。

具体例子：某 prompt 采样 G=8，奖励为 [0,0,0,0.3,0.3,0.6,0.6,0.9]（0 表示编译失败，0.3 表示通过正确性但慢于基线，0.6 表示正确且与基线持平，0.9 表示正确且显著加速）。对 ri=0.9 的样本，baseline 为其余 7 个的均值 ≈0.257，Ai≈0.643；对 ri=0 的样本，baseline ≈0.386，Ai≈−0.386。失败样本获得负优势、加速样本获得正优势，方向正确；若用组内均值 0.3375，则 0.9 样本的优势被压到 0.5625，而 0 样本的优势被抬到 −0.3375，正负样本的区分度同时下降。这就是留一法在数值上的直接收益。

三 · 奖励函数的可分解结构与各分项的时延/显存代价

奖励 ri 在 kernel 生成场景里不是单一标量，而是若干可验证信号的组合。一个可实现的分解是：

$$r_i=w_c\cdot c_i+w_p\cdot p_i+w_s\cdot s_i-\lambda\cdot t_i$$
其中 ci∈{0,1} 是编译通过指示，pi∈[0,1] 是正确性通过比例（对多组测试输入取通过率），si 是相对基线的加速比（经 roofline/SOL 归一后的有界量），ti 是编译加测速的墙钟时间，λ 是时间惩罚系数。这一分解的意义在于：每一项都有独立的验证路径，因而奖励本身是可审计的，而不是由一个不可解释的评分器吐出。

代价逐项说明。编译项 ci 的代价是编译时间——一个中等规模的 CUDA C++ kernel 走 nvcc 全流程，加上模板实例化，编译时间可能达到数秒量级；Triton 的 JIT 编译相对轻，但首次编译同样要付出。正确性项 pi 的代价是显存与执行时间：多组测试输入意味着多次 launch，若测试输入包含大 shape，单次执行就可能占满显存，组内 G 个候选若并行验证会叠加显存压力。加速比项 si 的代价是测速的稳定性——需要重复计时取中位数或最小值，且要控制 GPU 频率与占用，否则噪声会污染奖励。时间惩罚项 λ·ti 的代价是它把“慢但正确”的候选压到负奖励区间，可能误伤那些编译慢但运行时快的模板重候选。

关键的一步是把 si 做成有界量。若直接用原始加速比（如 3.2×），奖励分布会出现长尾，组内方差被少数极快样本主导，留一法 baseline 被拉高，导致多数中等样本获得负优势。工程做法是对 si 取对数或用 tanh 压缩到 [−1,1]，使奖励分布的重尾被削平，组内比较更公平。这一步不改变无偏性（它是对奖励的确定性变换，作用于所有样本），但显著改变优势的方差结构。

具体例子：某候选编译失败，ci=0，pi=0，si=0，但编译耗时 4 秒，ti=4，λ=0.05，则 ri=−0.2。同组另一候选编译通过、正确率 1.0、加速比 1.4×（压缩后 si≈0.34）、测速耗时 2 秒，取 wc=0.2、wp=0.4、ws=0.4，则 ri=0.2+0.4+0.136−0.1≈0.636。两者差距来自正确性与加速比，而非编译时间主导，这正是权重设计要达到的效果。

四 · 组内方差、优势分布与 G 的动态调整

留一法优势的方差可以写成闭式：若组内奖励方差为 σ²，则

$$\mathrm{Var}(A_i)=\sigma^2\left(1+\frac{1}{G-1}\right)$$
推导的关键一步是 Ai = ri − (1/(G−1))Σj≠irj，两项独立，故方差相加：Var(ri)=σ²，Var(其余均值)=σ²/(G−1)。这个式子直接给出 G 的边际收益：G 从 4 增到 8，方差因子从 1.333 降到 1.143，收益递减；G 从 2 增到 4，因子从 2.0 降到 1.333，收益明显。因此小 G 区间是留一法性价比最高的地方，这也是为什么组内比较在 G=4~8 就能工作，而不需要动辄几十个样本。

但方差公式只描述“奖励有方差”的情形。当组内样本高度同质时，σ²→0，Ai→0，梯度信号消失。监控组内奖励方差因此成为必要环节：若某 prompt 连续若干组的 σgroup 低于阈值，说明该 prompt 对当前策略已无区分度（要么全失败、要么全通过），应降低其采样权重或暂时移出训练集。反之，若 σgroup 过大且分布双峰（一半失败一半成功），说明该 prompt 处于学习前沿，值得增加 G 以细化组内比较。

动态调整 G 的伪代码思路：对每个 prompt 维护一个滑动窗口的组内方差估计；当窗口内平均 σgroup 高于上阈值且 GPU 预算允许时，G←min(2G, Gmax)；当低于下阈值时，G←max(G/2, Gmin)。代价是 G 变化会改变 1/G 因子的尺度，若不同 prompt 的 G 不同，梯度幅值不再可比，需要在实现中对每个 prompt 的组内平均单独归一，或在优化器层面按有效样本数加权。具体例子：某 prompt 前 5 组 σgroup 分别为 0.02、0.01、0.03、0.02、0.01，低于阈值 0.05，判定为同质，G 从 8 降到 4，节省一半编译测速开销；另一 prompt σgroup 稳定在 0.3 以上，G 从 4 升到 8，方差因子从 1.333 降到 1.143，梯度噪声下降。

五 · 从公式到可执行伪代码：一次组更新的完整数据流

把前四节的量串成一次组更新的流程，伪代码落到可实现层面（用文字描述控制流，不写代码块）：对给定 prompt，采样 G 条轨迹，每条轨迹产出一个 kernel 候选及其源码；对每个候选依次执行编译、正确性验证、测速，得到 (ci, pi, si, ti)；按第三节的加权公式合成 ri；对每个 i 计算 baseline−i = (Σjrj − ri)/(G−1)，得到 Ai；对组内 A 做标准化（除以组内标准差，标准差为零时跳过）与裁剪；用 Ãi 加权 ∇logπθ(τi)，乘以 1/G，累加得到该组的梯度估计；施加 KL 约束（对当前策略与参考策略的 KL 散度做惩罚或硬约束），执行优化器步。

实现上的关键一步是 baseline 的计算顺序。若先算组内总和再逐样本减去自身，数值上等价于留一法，但要注意浮点累加顺序带来的舍入误差：当 G 较大且奖励量级差异大时，总和减去自身可能损失精度。更稳的做法是对每个 i 单独对 j≠i 求和，代价是 O(G²) 的加法，对 G≤16 完全可接受。另一个细节是标准化用的 σgroup 应基于未裁剪的 A 计算，裁剪在标准化之后，否则标准差被裁剪污染，标准化失去意义。

代价核算：一次组更新的 GPU 开销 = G ×（编译时间 + 验证执行时间 + 测速时间），这是留一法最直接的账单；token 开销 = G × 每条轨迹的生成 token 数，随 G 线性增长；显存开销主要来自验证阶段多组测试输入的并行执行，若串行验证则显存峰值与单候选相当，但墙钟时间翻 G 倍。工程判断是：编译与测速可以流水线化（一个候选在测速时另一个在编译），把 G 的线性墙钟压成接近常数加线性尾，这是留一法在真实训练循环里可行的前提。

具体例子：G=8，单候选编译 3 秒、验证 1 秒、测速 2 秒，串行总墙钟 48 秒；若编译与测速流水线化，墙钟可压到约 3+8×2=19 秒量级（编译阶段重叠），代价是显存中同时驻留多个候选的编译产物与测速上下文，需要按显存预算限制并发度。这一权衡决定了 G 的上限不是由统计公式给出，而是由流水线并发度与显存共同约束。

六 · 误差来源的分解与留一法不能消除的部分

把优势估计的总误差分解为三项：采样误差（组内 G 个样本对真实奖励分布的蒙特卡洛误差，随 G 增大按 1/√G 收缩）、baseline 误差（留一法已消除自相关项，剩余的是 baseline 均值估计的方差 σ²/(G−1)）、以及奖励本身的测量误差（编译/测速的噪声、正确性测试覆盖不足导致的误判）。留一法只作用于第二项，对第一项和第三项无能为力。这是工程上必须说清的事：留一法让优势估计在给定奖励下更准，但如果奖励本身被噪声污染，优势的符号可能翻转。

推导的关键一步是把测量误差传播到优势：设每个 ri 叠加独立噪声 εi，方差为 σε²，则 Ai 的噪声方差为 σε²(1+1/(G−1))，与奖励噪声同阶。也就是说，测速噪声会以与奖励方差相同的比例进入优势，留一法不提供任何降噪。对策不在优势公式里，而在奖励侧：重复测速取中位数、固定 GPU 频率、控制占用，把 σε 压下去。具体例子：某候选真实加速比为 1.05×，测速噪声导致单次测得 0.98×，奖励从正变负，优势符号翻转，策略被推离一个实际更优的 kernel。这类误差只能靠测速协议解决，不能靠 baseline 设计解决。

另一个留一法无法消除的误差是组内样本的相关性。若 G 个候选来自同一 prompt 的采样，它们在 token 层面共享 prompt 前缀，奖励之间可能存在弱相关（例如都倾向生成同一种 tile 尺寸），这违反独立同分布假设，使 Var(Ai) 的实际值偏离闭式。工程上通过温度参数与采样多样性来削弱这种相关，但无法完全消除；这也是为什么组内奖励方差监控要与优势分布监控一起看——若优势分布出现系统性偏斜（例如全部为正），说明 baseline 被相关性拉低，需要检查采样是否退化。

最后落在可实现的一步：把优势的标准化与裁剪做成组内操作而非全局操作，是留一法能够稳定工作的实现前提。全局标准化会把不同 prompt 的难度差异抹平，而组内标准化保留了“同一 prompt 内谁更好”的相对信息，这正是留一法 baseline 的语义所在。工程判断是：奖励合成、留一 baseline、组内标准化三步必须在同一次组更新内原子完成，任何跨组复用都会破坏无偏性所依赖的同分布假设。

留一法在奖励塌缩与组规模上的失效边界

留一法优势的无偏性依赖一个隐含前提：同组 G 个候选的奖励分布存在可分辨的离散度。当 G 个 kernel 候选全部编译失败或全部通过正确性校验且测速落在同一档位时，$$A_i=r_i-\frac{1}{G-1}\sum_{j\ne i}r_j$$ 中 r_i 与留一均值几乎相等，A_i 趋近零，策略梯度项 $$\frac{1}{G}\sum_i A_i\nabla_\theta\log\pi_\theta(\tau_i)$$ 整体塌缩。此时编译与测速的 GPU 时延照常付出，但有效学习信号为零——这是留一法最典型的系统代价：成本随 G 线性增长，收益却在同质组上归零。工程上必须监控组内奖励方差，方差低于阈值时直接丢弃该组梯度，而不是让它以近零优势污染更新。

第二个边界是 G 的取值。G=2 时留一 baseline 退化为对方单个样本的奖励，方差极大且对单点噪声毫无抵抗力；G 增大则 baseline 估计更稳，但每组需编译并测速 G 个候选，编译时间与显存占用随 G 线性上升。kernel 编译本身是秒级到分钟级操作，G 从 4 提到 8 意味着单 prompt 的墙钟成本翻倍，而优势方差只按 1/(G-1) 量级收缩。实践中应把 G 设为可调超参，用组内方差与优势分布的监控量动态升降，而不是固定大 G 硬扛。

第三个失效条件是奖励尺度不一致。不同 prompt 的 kernel 任务难度差异大，绝对时延奖励跨组不可比，留一法只在组内做差，跨组梯度尺度会失衡。因此标准化与裁剪不是可选装饰：需在组内对 A_i 做方差归一后再裁剪，否则高难度组的大奖励差会主导更新。此外，留一法不引入价值网络，省掉了 critic 的训练与显存，但也失去了跨组共享的基线信息——这是它相对全局 baseline 的固有代价，在 prompt 数量少、组内样本稀疏时尤为明显。
