一 · 候选对采样：同一 prompt 下的双路生成与编译

成对排序奖励的第一步不是打分，而是造出可比的两条轨迹。给定一个算子 prompt（例如“对 [M,K]×[K,N] 做 fp16 GEMM 并写回 fp32”），采样器需要从策略中抽出两个候选 kernel，且两者必须落在同一语义约束下：同一输入 shape 族、同一 dtype、同一输出布局、同一容差档位。这一步的输入是 prompt 与采样温度/核数配置，输出是一对源码文本（CUDA C++ 或 Triton），以及各自的编译产物句柄。采样成本在这里第一次翻倍：单候选流程只编译一次，成对流程编译两次，若走 nvcc 全量编译，编译时延与模板实例化显存占用都按 2× 计。工程上常用“先编译后配对”的顺序——两路都编译成功才进入验证，任一编译失败则该对降级为“无效对”，不进入偏好标注，避免把编译失败误当成性能劣势。

采样阶段的关键机制是同 prompt 约束下的多样性控制。若两路采样温度过低，两个候选近乎同质，偏好对的信息量趋近于零，排序损失梯度消失；温度过高则大量候选不可编译或语义偏离，浪费编译预算。一个可操作的判据是对源码做轻量结构指纹（block size、是否用 shared memory、循环展开层数、是否走 tensor core 路径），要求两候选在至少一个指纹维度上不同，否则重采样。伪代码思路：

$$\text{accept}(k_1,k_2)=\mathbb{1}\big[\text{fingerprint}(k_1)\neq\text{fingerprint}(k_2)\big]\ \wedge\ \mathbb{1}\big[\text{compile}(k_1)\wedge\text{compile}(k_2)\big]$$

代价上，指纹计算是纯文本级操作，时延可忽略；真正的开销在编译。以一个含 CuTe 布局推导的 GEMM 为例，模板实例化可能触发数十个 layout 组合，单次编译的墙钟时间与显存峰值都显著高于手写 kernel，成对采样把这份成本直接乘二。因此采样器通常设置编译并发上限，把“编译失败率”作为采样温度的反馈信号：失败率升高即降温，而不是盲目扩大候选池。

二 · 验证闸门：正确性优先的硬门槛

编译通过只说明语法与类型合法，不说明数值正确。验证步骤的输入是两个已编译候选与一组测试输入（含边界 shape、非对齐 stride、极端值），输出是每个候选的通过/失败标记以及失败时的最大相对误差。机制上，正确性判定必须先于任何时延比较：只要一个候选在任一测试用例上超出容差，它就被标记为“错误”，无论其速度多快。偏好构造规则因此是字典序的——先比正确性，再比时延。这直接压制了“快但错”的奖励黑客路径：错误候选不会因为跑得快而在偏好对中获胜。

验证的代价体现在两方面。其一是 oracle 成本：fp64 参考实现或高精度库调用本身要跑一遍，若测试用例数量为 n，则每对候选的验证时延约为 2n 次前向加 n 次参考计算。其二是显存：同时驻留两个候选的中间缓冲与参考输出，峰值显存约为单候选流程的 2–3 倍，对大规模 shape 需要分块验证或串行释放。一个具体例子：对 LayerNorm 类算子，测试集里放一个 N 不是 2 的幂的 shape，错误候选往往在向量化边界处理上越界或漏算，验证阶段直接拦截，避免其进入测速环节污染偏好标签。

这里有一个容易被忽视的工程判断：验证失败的对是否保留？若保留为“负样本”，偏好模型会学到“这类代码风格=错误”，可能泛化成对合法但风格不同的候选的歧视。稳妥做法是把验证失败对单独归档，只用于诊断，不进入排序训练集；排序训练集只收“双双正确”的对，让偏好信号纯粹来自性能差异。

三 · 稳健测速：从原始时延到可比标量

两个候选都通过验证后，进入测速。输入是候选、固定 shape 与预热/重复配置，输出是每个候选的时延统计量。机制核心是稳健化：单次测量受时钟抖动、DVFS、缓存冷热影响，直接取均值会把噪声写进偏好标签。做法是预热若干次后取多次重复的中位数或截尾均值，并记录离散度（如四分位距）。只有当两个候选的时延差异超过由离散度导出的置信阈值时，才判定胜负；否则该对标为“平局”，不进入训练。伪代码思路：

$$\text{winner}=\begin{cases}k_1 & \tilde{T}_1<\tilde{T}_2-\delta\\ k_2 & \tilde{T}_2<\tilde{T}_1-\delta\\ \varnothing & \text{otherwise}\end{cases},\quad \delta=\alpha\cdot\max(\text{IQR}_1,\text{IQR}_2)$$

代价是测速时间线性翻倍：每对候选要跑两轮预热加两轮重复测量，若单候选测速占整条流水线时间的比例本就较高，成对流程会把这一项推到主导地位。工程上通过共享预热、复用同一 shape 批次、把测速与下一对的编译重叠来摊薄。另一个代价是平局率：阈值 δ 设得保守，平局增多，有效训练对减少；设得激进，噪声被当成真实差异，偏好模型学到虚假排序。这个权衡没有普适常数，需要按硬件抖动水平标定，且标定本身要花测量预算。

具体例子：两个 Triton 候选在同一个 reduction 算子上时延中位数相差不到一个测量离散度，此时正确做法是标平局而非硬分胜负——因为下游排序损失对这类对的梯度本就没有信息，强行标注只会引入标签噪声。稳健测速的输出因此不是“谁赢”，而是“赢/输/平”三态，这是与绝对时延奖励最本质的差别之一。

四 · 偏好对构造与 Bradley-Terry 训练

把三态结果转成训练信号。输入是（prompt, 候选 A, 候选 B, 标签），输出是排序模型的一次梯度更新。机制采用 Bradley-Terry 形式，把“A 胜 B”的概率写成得分差的 sigmoid：

$$P(A\succ B)=\sigma\left(\frac{s_A-s_B}{\tau}\right),\quad \mathcal{L}=-\sum_{(A,B)\in\mathcal{P}}\log P(A\succ B)$$

其中得分 s 由偏好模型对候选（源码或编译产物特征）给出，τ 是温度，控制概率曲线的陡峭程度。训练时只对非平局对计算损失，平局对可丢弃或作为低权重正则项。这一步的代价是模型侧的计算与显存：偏好模型若以源码 token 序列为输入，序列长度随 kernel 代码规模增长，单对前向的 token 数约为两倍单候选；若以编译产物特征（寄存器数、shared memory 用量、指令混合）为输入，则特征提取本身要解析二进制，时延不可忽略但远低于重编译。

关键机制是得分函数的选择决定了偏好模型能学到什么。若得分只看静态特征（如占用率、指令数），模型学到的其实是“哪种代码风格通常更快”的先验，而非真实时延；这类先验在分布内有效，跨架构迁移时会失准。若得分接入实测时延的回归头，则退化为绝对奖励的老问题。折中做法是让得分同时吃静态特征与少量实测统计量，并在训练中对该统计量做归一化，避免尺度漂移重新渗入。具体例子：一个偏好模型若发现“使用 128 线程块”的对胜率偏高，它会把这一风格推成高分，但真实原因可能是该批次 shape 恰好适配——这正是需要一致性校验来捕捉的偏差。

五 · 打分驱动策略优化与一致性校验

训练好的偏好模型给新候选打分，驱动策略更新（DPO 直接用偏好对做策略优化，PPO 则把排序奖励作为回报项）。输入是新采样候选与偏好模型，输出是策略梯度或偏好对损失。机制上，打分是相对的：新候选的得分只有与同 prompt 下另一候选比较才有意义，因此策略优化阶段仍需成对采样，采样成本翻倍的代价从训练延伸到在线阶段。若用 DPO，偏好对直接来自流水线产出的三态标签，无需额外奖励模型前向；若用 PPO，则每步要对候选打分，token 开销与偏好模型规模成正比。

一致性校验是这条流水线的安全阀。定期取 held-out 的偏好对，比较偏好模型的排序与真实稳健时延排序的吻合率；吻合率下降说明模型学到的偏差在扩大（例如偏好某种代码风格而非真实速度）。代价是校验本身要跑真实测速，等于在训练循环外再付一次测量预算；但若不校验，偏好模型漂移会通过策略优化被放大，最终表现为策略收敛到“模型喜欢但实际不快”的 kernel。工程判断：校验频率应与策略更新步数挂钩，更新越快，校验越密，因为偏差被放大的速度也越快。

具体例子：策略在若干轮后开始集中产出某类带特定 unroll 因子的 Triton kernel，偏好模型给分很高，但 held-out 真实测速显示这批 kernel 在非对齐 shape 上反而慢——一致性校验捕捉到这一背离，触发回退并把该类对重新标注。这一步的代价是回退造成的训练步数浪费，但相比让偏差进入部署，这个代价是必要开销。

六 · 单步流动的代价账本

把上述步骤串成一次完整流动，可以得到一份清晰的代价账本。每一步的输入、输出与主要开销如下表所示（定性量级，不含具体数字）：

步骤输入输出主要代价
候选对采样prompt、温度、指纹约束两份源码 + 编译句柄编译时延与显存 2×，失败对浪费预算
验证闸门候选、测试用例、参考 oracle通过/失败 + 误差oracle 前向 n 次、峰值显存 2–3×
稳健测速候选、预热/重复配置赢/输/平三态测速时间 2×，平局率与阈值标定成本
偏好训练三态标签、候选特征排序模型梯度双候选 token 前向、特征提取时延
打分与策略更新新候选、偏好模型策略梯度/偏好损失在线仍成对采样，PPO 打分 token 开销
一致性校验held-out 对、真实测速吻合率、回退信号额外测量预算、回退浪费训练步

这张表暴露的核心工程判断是：成对排序奖励用采样与测量的翻倍换奖励尺度的稳定性。绝对时延奖励只需跑一个候选，成对流程要跑两个、验证两遍、测速两轮，流水线总时延大致翻倍；但换来的是跨算子、跨架构可比的偏好信号，以及正确性作为硬门槛带来的抗奖励黑客能力。若采样预算紧张，优先压缩的是候选池宽度而非配对数量——因为配对是这套机制的最小信息单元，砍掉配对等于退回绝对奖励。真正需要盯住的指标是“有效非平局对占比”与“一致性吻合率”：前者低说明测速阈值或采样多样性有问题，后者低说明偏好模型在学风格而非速度。这两个指标任一恶化，都应先停下策略更新去修流水线，而不是加大训练步数。

偏好对构造的边界：正确性门槛、稳健时延与采样翻倍的代价

成对排序奖励的可靠性几乎全部压在前两步上：同一 prompt 下采样两个候选 kernel，编译、验证、测速，再构造偏好对。这里的失效条件很具体。第一，正确性优先意味着只要一方验证失败，偏好标签就由正确性决定，时延比较被跳过；若两个候选都错，该对必须丢弃而不是强行标注，否则奖励模型会把“错得更快”学成偏好。第二，稳健时延比较不能直接用单次测量，需要对同一候选重复测速并取分位数或截尾均值，否则一次调度抖动就能翻转标签。第三，采样成本翻倍不是修辞：每个偏好对要求两个候选都完成编译、验证与测速，编译时间、显存占用与 GPU 时延都按对计，候选池越大，标注吞吐越受限于最慢的那条编译链。

把这一步写成伪代码，边界就清楚了：

$$\text{label}(i,j)=\begin{cases}i\succ j, & \text{verify}(i)=\text{pass}\ \land\ \text{verify}(j)=\text{fail}\\ \text{drop}, & \text{verify}(i)=\text{verify}(j)\\ \arg\min(\tilde{T}_i,\tilde{T}_j), & \text{两者均通过}\end{cases}$$

其中 \(\tilde{T}\) 是稳健时延统计量。该规则的系统代价是标签产出率下降：验证失败率高时大量对被丢弃，偏好数据密度变低，奖励模型在“快但错”区域缺少负样本，反而更容易被策略钻空子。一个具体例子是归约类算子：候选 A 通过全部形状校验但时延偏高，候选 B 在边界形状上越界写显存却快，若按朴素时延标注就会把 B 标为胜者；正确性门槛把这一对直接判给 A，代价是这一对的时延信息完全浪费。

另一个失效条件是偏好模型学到与真实时延无关的偏差，例如偏好某种代码风格、某种 tile 尺寸写法，或对某类编译产物系统性打分偏高。这类偏差在 held-out 对上表现为偏好模型排序与实测时延排序的一致性下降，而一致性校验本身要额外消耗测速预算。工程判断是：偏好对构造必须把“丢弃”当作一等公民，宁可减少对数也不制造矛盾标签；同时把一致性校验的频率与候选分布漂移绑定，而不是固定周期。
