一 · 一次“快 3%”的奖励翻车：绝对时延为什么不可信

设想一个已经上线的 kernel 生成流水线：策略模型对同一算子产出两个候选，A 用 shared memory 分块，B 用寄存器重排。测速脚本跑完，A 的 median 时延比 B 低 3%，奖励函数把 3% 直接写进 advantage，策略被推向 A 的代码风格。三轮之后，评测集上的平均时延确实降了，但线上端到端吞吐没有变化，反而在另一张卡上出现回退。复盘时发现两件事：第一，那 3% 落在同一张卡上重复测量的抖动区间内，换一次 clock 状态就反向；第二，A 的胜出只在某个 batch 形状成立，换到另一个 shape，B 明显更快。奖励函数把“一次测量下的绝对差值”当成了“这个 kernel 更好”，而这两者之间隔着一整条测量链路。

这就是绝对时延奖励的结构性缺陷。它把奖励写成 $$r=T_{\text{ref}}-T_{\text{cand}}$$ 或等价的加速比，于是奖励的数值同时承载了三件事：kernel 本身的优劣、当前机器的状态、以及参考实现 $$T_{\text{ref}}$$ 的选择。三者混在一个标量里，策略无法区分“我改进了代码”和“我今天运气好”。更麻烦的是尺度漂移：同一份策略在不同算子上产生的时延差异量级完全不同，elementwise 算子的绝对差值可能是微秒级，GEMM 是毫秒级，若奖励不做归一，梯度会被大算子主导；若做归一，归一化基准又随算子变化，跨算子的偏好就失去了可比性。

成对排序偏好奖励换了一个提问方式：不问“这个 kernel 有多快”，而问“在同一 prompt 下，这两个 kernel 谁更好”。前者要求一个跨样本可比的绝对标尺，后者只要求一个局部可判定的序关系。序关系对测量噪声的敏感度远低于差值：当两个候选的真实差距小于抖动时，正确的做法是判为平局或丢弃该对，而不是把一个噪声差值放大成奖励信号。这一步转换，正是本方法要解决的具体问题。

需要立刻划清边界：成对排序不解决“如何测得准”。它假设测速环节已经具备基本的重复测量、warmup、clock 锁定与异常值剔除；若测量本身有系统性偏差（例如没有排除首次编译、没有固定 L2 状态），成对比较只会把这个偏差以“稳定的偏好”形式固化进奖励模型，比绝对奖励更难被发现。它也不解决“如何保证正确”。正确性必须作为偏好构造的前置硬门槛，而不是让奖励模型从数据里自己学会“错的更快也算赢”。

二 · 偏好对的构造：正确性优先，时延其次

方法的核心机制是把每个训练样本从“单点打分”变成“同 prompt 下的二元组”。对同一算子采样两个候选 kernel，分别编译、验证、测速，然后标注胜者。标注规则不是简单的“谁快谁赢”，而是一条字典序：先看正确性，再看稳健时延。

  • 两个候选都未通过正确性 oracle：该对作废，不进入训练集。若强行标注，等于教模型在错误空间里排序。
  • 一个通过、一个未通过：通过者胜，且该对的权重应高于纯时延对，因为它携带的是硬约束信息。
  • 两个都通过：进入时延比较。此时不用单次测量值，而用重复测量的稳健统计量（如中位数或截尾均值），并设定一个死区：差值落在死区内判为平局，直接丢弃。

死区的存在是本方法区别于“随便比一下”的关键。设两个候选的稳健时延估计为 $$\hat{T}_i,\ \hat{T}_j$$，测量抖动尺度为 $$\sigma$$，则判胜条件可写成 $$\hat{T}_j-\hat{T}_i>k\sigma$$，其中 $$k$$ 由测速脚本的重复次数与历史方差标定。这不是统计上的严格检验，而是一个工程闸门：它把“不确定谁更好”的样本从奖励信号里剔除，避免奖励模型去拟合噪声。代价直接体现在采样成本上——每个偏好对需要两个候选都实际编译、运行、测速，采样开销相对单点评估翻倍；若再叠加重复测量，测速环节的机时也翻倍。这是本方法最硬的一项成本，无法用算法技巧绕开。

一个具体例子：同一 reduction 算子的两个候选，候选一用两阶段树形归约，候选二用 warp shuffle 单阶段。正确性 oracle 都通过。测速显示候选一在长序列上快，候选二在短序列上快。若按绝对时延取全局平均，两者可能被判为接近平局，信息被抹平；而按偏好对构造，应把它们拆成两个不同 shape 下的对，分别标注胜者，让偏好模型学到“形状条件下的序”，而不是一个被平均掉的标量。这里已经埋下了本方法的一个隐含要求：偏好对必须带着上下文（shape、dtype、架构）进入模型，否则模型只能学到与上下文无关的平均偏好，跨 shape 的排序一致性就无从校验。

三 · Bradley-Terry 与排序损失：把“谁赢”变成可微信号

有了偏好对，下一步是把它变成一个能对新候选打分的模型。标准做法是 Bradley-Terry 模型：给每个 kernel 一个隐分数 $$s_i$$，则 $$i$$ 胜过 $$j$$ 的概率为

$$P(i\succ j)=\sigma\left(\frac{s_i-s_j}{\tau}\right),\quad \mathcal{L}=-\sum_{(i,j)\in\mathcal{P}}\log P(i\succ j)$$

其中 $$\tau$$ 是温度，控制分数差的敏感度；$$\mathcal{P}$$ 是偏好对集合。损失只依赖分数之差，因此对分数的整体平移不变——这正是它规避绝对尺度的数学根源。分数本身不需要对应任何物理单位，它只需要在同一个 prompt 的候选集合内保持正确的序。若把分数取成对数时延比 $$s_i=\log\frac{T_{\text{ref}}}{T_i}$$，则模型退化为对加速比的成对比较，此时 $$\tau$$ 实际上决定了“多大加速比才算显著”，与前面死区的 $$k\sigma$$ 是同一件事的两种表述，工程上应保持一致，否则训练目标与数据标注规则会互相打架。

训练完成后，偏好模型对新候选打分，驱动策略优化：可以直接把分数作为 ranking reward 喂给 PPO，也可以在偏好对上做 DPO 式的直接优化。这里有一个容易忽略的代价：偏好模型是一个学出来的代理，它可能学到与真实时延无关的偏差。最典型的偏差是代码风格偏好——如果训练集里胜者恰好都是某种写法（比如都用了某个 intrinsic），模型会把“像这种写法”当成“更快”，从而在真实时延无差别时给出系统性偏好。这类偏差不会在训练损失上暴露，因为它在训练分布内是自洽的。唯一的防线是定期用 held-out 偏好对校验模型打分与真实时延排序的一致性；一致性一旦漂移，说明模型在拟合风格而非性能，必须回退或重训。

另一个代价是编译时间与 token 预算。偏好对里的每个候选都要真实编译，编译失败的对同样要处理——它们既不能算作时延胜者，也不应简单丢弃，因为编译失败本身是关于候选质量的信息。工程上通常把“编译失败”并入正确性门槛，判为负例，但这会让负例分布偏向语法/模板错误，而非性能劣势，偏好模型可能因此学到“保守写法更安全”的偏差。这需要在数据配比上做控制，而不是靠调温度解决。

四 · 跨算子、跨架构的可比性：序关系能走多远

本方法宣称的优点之一是跨算子、跨架构的偏好更可比。这句话需要精确理解。可比的是“在同一 prompt 内的相对优劣”，不是“A 算子上的胜者比 B 算子上的胜者更优”。Bradley-Terry 的分数只在同一比较集合内有意义，跨集合的分数不可直接相减。因此当策略在多个算子间分配采样预算时，不能直接用偏好分数做跨算子的优先级排序，除非引入一个共享的锚点（例如同一参考实现在各算子上的表现）把分数对齐。这一点与绝对奖励的尺度漂移是同一个问题的另一面：成对比较把尺度问题从“奖励数值”转移到了“比较集合的边界”，边界划错，可比性同样失效。

跨架构的情形更微妙。同一份 kernel 在两张卡上的相对排序可能不同：一张卡上 shared memory 带宽充裕，分块写法胜出；另一张卡上寄存器压力更大，重排写法胜出。若偏好对不加架构标签混在一起训练，模型会学到一个被平均的序，在两张卡上都不准。正确做法是把架构作为上下文特征输入，或者按架构分桶训练再合并。代价是数据稀疏：每个架构桶内的偏好对数量下降，模型方差上升，需要更多采样才能稳定——这又把成本推回到采样环节。

一个具体判断：当算子集合很小、架构单一、测量链路稳定时，绝对时延奖励加归一化其实够用，成对排序的额外采样成本换不来明显收益。成对排序真正划算的场景是：候选之间的真实差距接近测量抖动、算子间时延量级跨度大、或需要跨架构部署同一策略。此时绝对奖励的尺度漂移会让策略在“改进代码”和“拟合噪声”之间无法区分，而成对比较通过死区和平移不变性把这两者分开。反过来说，如果团队还没有能力把测速抖动压到可标定的水平，引入成对排序只是把噪声包装成偏好，不会带来可信的收益。

五 · 不解决的问题与工程前置条件

明确本方法不覆盖的边界，比罗列优点更有用。第一，它不提供正确性 oracle。偏好构造里的“正确性优先”依赖外部 checker，若 checker 本身有漏洞（例如容差过松、未覆盖边界 shape），成对排序会把“通过漏洞 checker 的快 kernel”稳定地判为胜者，且因为序关系稳定，这种奖励黑客比绝对奖励更难通过方差发现。第二，它不解决奖励模型与真实目标的对齐。偏好模型优化的是“在训练分布内预测人类/脚本标注的胜者”，若标注规则本身偏离端到端收益（例如只看单 kernel 时延，不看融合后的整体吞吐），模型会精确地优化一个错误目标。第三，它不降低采样成本，反而翻倍；在采样预算紧张的流水线里，这是一个需要显式权衡的硬约束。

工程前置条件可以列成一张检查表，用来判断当前流水线是否适合切换到成对排序：

条件不满足时的后果本方法的角色
测速抖动可标定，重复测量有稳健统计量死区无法设定，偏好对全是噪声不解决，只消费
正确性 oracle 覆盖边界 shape 与容差快但错的 kernel 被稳定判胜不解决，只消费
偏好对携带 shape/dtype/架构上下文模型学到被平均的序，跨条件失效方法内的设计要求
有 held-out 对做一致性校验风格偏差无法发现，奖励漂移方法内的必要环节
采样预算允许候选翻倍数据量不足，偏好模型方差大方法的固有成本

这张表说明了一件事：成对排序不是把奖励函数换个写法，而是把奖励的可信度责任从“数值标定”转移到了“比较集合的构造与校验”。前者靠归一化和统计技巧，后者靠数据协议和一致性门。若团队只改了损失函数而没有建立偏好对的构造规范与 held-out 校验，收益不会出现，反而会因为采样翻倍而拖慢迭代。

六 · 一个可执行的判定：什么时候该用成对排序

把上面的分析压缩成一个工程判定。设当前流水线的单点评估噪声为 $$\sigma$$，候选间的典型真实差距为 $$\delta$$。当 $$\delta/\sigma$$ 明显大于 1 时，绝对奖励的排序基本可信，成对排序的边际收益低，采样翻倍的成本不划算。当 $$\delta/\sigma$$ 接近或小于 1 时，绝对奖励的差值被噪声淹没，策略会在噪声上过拟合，此时成对排序的死区机制才真正发挥作用——它不是让测量变准，而是让“不确定”的样本不进入奖励，从而把有限的梯度预算集中在可判定的序上。

另一个判定维度是算子间的时延量级跨度。若策略同时覆盖微秒级 elementwise 与毫秒级 GEMM，绝对奖励不做归一必然被大算子主导，做了归一又引入随算子变化的基准，跨算子偏好不可比。成对排序把比较限制在同一 prompt 内，天然回避了这个跨度问题，代价是失去跨算子的分数可比性，需要额外的锚点对齐才能做预算分配。这是一个明确的交换：用“局部可比”换“全局尺度稳定”。

最后落到一个具体机制上：偏好对的死区阈值与 Bradley-Terry 的温度 $$\tau$$ 必须联动标定。若死区设得宽而 $$\tau$$ 设得小，模型会对被判为胜者的微小差距给出极端概率，训练梯度被少数边界样本主导；若死区窄而 $$\tau$$ 大，模型对真实差距不敏感，排序能力退化。工程上的做法是用 held-out 对扫描一组 $$(\text{死区},\tau)$$ 组合，选排序一致性最高且分数分布不塌缩的那一组，并把该组合与测速脚本的重复次数一起版本化。这一步不做，成对排序就只是换了个损失函数，尺度漂移会以“稳定的风格偏好”形式重新出现。
