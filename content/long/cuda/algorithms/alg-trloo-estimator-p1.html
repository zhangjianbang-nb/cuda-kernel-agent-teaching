一 · 一次“全组同分”导致的策略塌缩

考虑一个典型的 kernel 生成 RL 训练回合。同一个算子 prompt（比如一个 fused softmax 加 layernorm 的复合算子）被采样 G 次，得到 G 份 CUDA C++ 候选。这 G 份候选全部经过编译、正确性验证与测速，产出一个奖励向量 r。问题恰恰出在这里：如果这一组里所有候选都编译失败，或者都通过了正确性验证却落在同一个测速档位，那么组内奖励几乎是一个常数。此时若用组内均值作为 baseline，优势 A_i = r_i − mean(r) 会全部趋近于零，策略梯度信号消失，这一组样本对参数更新毫无贡献，却已经消耗了 G 次编译与测速的 GPU 时间。

更隐蔽的翻车发生在“共享参考基线”的场景。工程上常见的简化做法是：为每个 prompt 维护一个跨 batch 的滑动平均奖励作为 baseline，所有采样共享它。这个 baseline 与当前组内样本的奖励分布并不同步——它反映的是历史 prompt 的平均难度，而不是当前这组候选的相对好坏。于是优势估计被系统性地污染：一个本身质量中等、但在“简单 prompt 历史均值”下显得突出的候选会拿到虚高的正优势；反之，一个在“困难 prompt 历史均值”下被压低的优质候选会拿到负优势。策略被推向“讨好历史基线”而非“写出更快的 kernel”。这不是方差问题，而是偏差问题，且偏差方向随 prompt 难度漂移，训练越久越难纠正。

这两类事故指向同一个工程判断：kernel 生成的奖励信号是**组内可比、跨组不可比**的。同一个 prompt 的多个候选共享同一份参考实现、同一套测速环境、同一个 shape 配置，它们之间的奖励差异才有物理意义；跨 prompt 的奖励绝对值混杂了算子难度、shape 规模、内存带宽上限等无关变量。任何把跨组信息混入 baseline 的做法，都在引入与“这个 kernel 写得好不好”无关的信号。

二 · 留一法要解决的具体问题：无偏且组内自洽的对照

留一法（leave-one-out）把 baseline 的定义收紧到“同组其余样本”这一最小可比集合上。对第 i 个候选，其对照不是全局均值，也不是历史均值，而是同组另外 G−1 个候选的奖励均值：

$$A_i=r_i-\frac{1}{G-1}\sum_{j\ne i}r_j,\quad \nabla_\theta J=\mathbb{E}\left[\frac{1}{G}\sum_{i=1}^{G}A_i\nabla_\theta\log\pi_\theta(\tau_i)\right]$$

这个构造的关键性质是：baseline 与 r_i 统计独立（因为它不含 r_i），因此对任意奖励分布，A_i 的期望等于 r_i 的期望减去同组其他样本的期望——在“同组样本同分布”的假设下，这个差为零均值，优势估计无偏。相比之下，用组内均值做 baseline 时，r_i 同时出现在被减数和减数里，引入了 −r_i/(G−1) 的自相关项，优势被系统性压缩，G 越小压缩越严重。这正是“直接用组内均值做 baseline 会引入偏差”的机制来源。

无偏之外还有方差收益。留一法 baseline 只用到 G−1 个同分布样本，其方差随 G 增大而下降，而它扣除的正是组内共同的那部分奖励波动（共享的参考实现、共享的测速噪声、共享的 shape 难度）。剩下的 A_i 只保留“这个候选相对同伴好多少”的差异信号。对 kernel 生成而言，这个差异信号恰好对应我们真正关心的量：同一算子下，谁的 tiling 更好、谁的 shared memory 复用更充分、谁的访存合并更整齐。

代价必须说清楚。每组要采样 G 个候选并**全部**编译、验证、测速，GPU 成本随 G 线性增长；编译时间也是线性项，而 kernel 编译本身可能是分钟级的。这意味着留一法不是免费的方差缩减，它用 G 倍的采样预算换取一个无偏对照。当 G 被成本压到很小（比如 2 或 3），留一法 baseline 只由一两个样本构成，方差缩减效果有限，而无偏性仍然成立——这是一个“保底正确、上限受预算约束”的方法。

三 · 它不解决什么：同质组、跨组比较与信用分配

留一法有一个明确的失效边界：组内样本高度同质时，优势趋近于零。如果 G 个候选全部编译失败，或者全部通过且测速落在同一档，那么 r_i 与其余样本均值几乎相等，A_i ≈ 0，学习信号弱。这不是实现 bug，而是方法的内在限制——留一法只能放大组内差异，无法凭空制造差异。工程上的应对不是修改公式，而是在采样侧提高多样性（不同 tiling 策略、不同向量化宽度、不同流水深度），或监控组内奖励方差并动态调整 G。方差监控本身是一个廉价信号：组内方差持续走低，说明当前 prompt 的采样已经饱和，继续加 G 只是烧 GPU。

它也不解决跨 prompt 的信用分配。留一法把 baseline 限制在同组内，代价是放弃了“这个 prompt 整体太难/太简单”这一层信息。一个 prompt 若所有候选都失败，留一法给出的是“相对失败程度”的优势，而不是“这个 prompt 需要更多采样预算”的判断。后者属于采样调度问题，需要组间统计量来驱动，不能指望优势估计公式本身承担。

它同样不解决奖励本身的正确性问题。留一法假设 r 是可信的：编译成功即正确、测速即真实性能。如果正确性 oracle 漏判（比如只测了少数 shape、没覆盖边界条件），或者测速被缓存效应污染，那么留一法会把这个错误**无偏地**传播到策略梯度里——它保证的是估计量的统计性质，不是奖励信号的物理真实性。这一点必须与验证侧的工作分开对待：oracle 的可靠性由 fp64 参考、变异测试、合约校验那一侧保证，留一法只负责在给定 r 的前提下把对照做对。

还有一个常被忽略的边界：G 的动态调整会改变优势的尺度。不同 G 下 A_i 的方差不同，若在同一 batch 内混用不同 G 的组，梯度尺度会不一致。工程上要么按 G 做归一化，要么在 batch 内固定 G，把 G 的调整放在 batch 之间。

四 · 一个具体例子：三类候选的奖励分布

设某 prompt 采样 G=4，四个候选的奖励分别为 r = [0.9, 0.7, 0.7, 0.3]（奖励可以是归一化后的测速得分，0.9 表示接近 SOL，0.3 表示明显低于 roofline）。用组内均值 baseline：mean = 0.65，优势为 [0.25, 0.05, 0.05, −0.35]。用留一法：对第一个样本，baseline = (0.7+0.7+0.3)/3 ≈ 0.567，A_1 ≈ 0.333；对第四个样本，baseline = (0.9+0.7+0.7)/3 ≈ 0.767，A_4 ≈ −0.467。可以看到留一法把最好与最差的差距拉得更开（0.333 对 −0.467，跨度 0.8），而组内均值把跨度压到 0.6。这个压缩不是均匀的：它对接近均值的样本影响小，对极端样本影响大，导致策略对“明显更好”的候选奖励不足。

再看同质组：r = [0.7, 0.7, 0.7, 0.7]。组内均值 baseline 给出全零优势，留一法同样给出全零优势。两者在此都失效，区别在于留一法至少不会因为自相关项而给出错误的非零信号。这解释了为什么“组内方差监控”必须与留一法配套：公式本身无法区分“真同质”与“采样不足导致的伪同质”。

第三个例子是跨组污染。假设前一个 batch 的 prompt 是一个访存密集的 reduction，历史均值 0.85；当前 batch 的 prompt 是一个计算密集的 GEMM 变体，四个候选奖励 [0.6, 0.55, 0.5, 0.45]。若共享历史 baseline 0.85，四个候选全部拿到负优势，策略被推离这个 prompt 的所有候选——即使其中 0.6 的那个已经是当前组最优。留一法下 baseline 分别为 0.5、0.517、0.533、0.55，优势为 [0.1, 0.033, −0.033, −0.1]，符号正确，梯度方向指向组内更优的候选。这个对比说明：baseline 的“参考系”必须与奖励的“可比范围”对齐，错配的参考系比没有参考系更糟。

五 · 适用边界的工程判据

把上述分析收敛成几条可操作的判据。第一，留一法适用于“同一 prompt 多样本、奖励组内可比”的场景，这是 kernel 生成 RL 的默认形态；不适用于奖励跨组可比且组内样本极少的场景，此时全局 baseline 的方差可能更低。第二，G 的下界由方差缩减需求决定，上界由编译与测速成本决定；G=2 时留一法退化为“两两对比”，无偏但方差大，只适合作为低成本兜底。第三，必须监控组内奖励方差与优势分布：方差趋零时优势塌缩，应触发采样多样性提升或提前终止该组的梯度贡献，而不是盲目增大 G。第四，留一法不替代奖励可信性建设，oracle 的错误会被无偏地放大进梯度，验证侧的门必须独立把关。

还有一个与成本直接相关的判断：留一法的 GPU 开销是 G 倍采样加 G 倍编译测速，而编译时间在 kernel 场景里往往不是可忽略项。若单次编译耗时接近单次测速耗时，那么 G 的增长会同时推高编译队列占用与测速显存占用。工程上应把“编译成功率”作为独立指标监控：若某 prompt 的候选大量编译失败，增大 G 只是增加失败样本数，优势仍然塌缩，此时应优先修 prompt 的约束描述或降低该算子的难度，而不是加预算。

最后落在机制上：留一法的价值不在于公式复杂，而在于它把 baseline 的“参考系”精确地钉在了同组其余样本上，从而同时消除自相关偏差与跨组污染。它的失效边界同样清晰——同质组无信号、奖励不可信则无意义、G 受成本约束。工程判断是：先保证组内可比与奖励可信，再用留一法榨取组内差异；组内方差监控与 G 的动态调度是它的必要配套，而不是可选项。

留一法不是万能基线：从一次“全组编译失败”的评测翻车说起

先看一个真实会发生的翻车形态：某个 prompt 要求实现一个融合 softmax 加 top-k 的 kernel，采样出的 G 个候选里有 6 个编译不过、2 个能编译但数值校验失败、剩下 1 个勉强通过正确性却在测速阶段超时被判零分。若直接用组内均值当 baseline，整组奖励几乎全为零，标准化后优势全部塌缩到零附近，这一条 prompt 对策略梯度的贡献被彻底抹平——但它恰恰是最需要学习信号的那类难例。更糟的是，如果组内恰好有 1 个高分样本、其余全失败，组均值 baseline 会把这个高分样本的优势压得远低于其真实相对价值，梯度方向被系统性稀释。留一法要解决的正是这个具体问题：让每个样本的对照只由“同组其他样本”构成，从而在组内奖励分布极度偏斜时仍能给出可用的相对信号。

机制上，留一法把第 i 个样本的 baseline 定义为其余 G−1 个样本奖励的均值，优势为

$$A_i=r_i-\frac{1}{G-1}\sum_{j\ne i}r_j,\quad \nabla_\theta J=\mathbb{E}\left[\frac{1}{G}\sum_{i=1}^{G}A_i\nabla_\theta\log\pi_\theta(\tau_i)\right]$$

它的无偏性来自一个简单事实：对任意 i，baseline 只依赖其他样本，与 r_i 独立，因此期望上不改变梯度的方向；而方差低于用全局或组均值做 baseline，因为对照项与样本自身的噪声不相关。但这份无偏性有严格前提——组内样本必须来自同一 prompt 的独立采样，且奖励函数对每个候选是确定性的编译、验证、测速流水线。一旦奖励本身带随机性（例如测速受 GPU 时钟抖动、共享显存争用影响），留一法 baseline 与 r_i 就不再独立，无偏性被破坏，此时它退化成一个带噪的对照，方差优势也随之缩水。

边界与代价必须讲清楚。留一法不解决“组内同质”问题：当 G 个候选全部编译失败或全部通过且测速接近，留一法算出的优势同样趋近于零，学习信号弱，这与组均值 baseline 的失效模式一致，只是不会额外引入偏斜。它也不解决跨 prompt 难度差异带来的方差——留一法只在组内做相对比较，难 prompt 与易 prompt 的奖励尺度差异仍需靠标准化与裁剪压制。系统代价是硬的：每组要采样 G 个候选并全部走完编译、正确性校验、测速三段流水线，GPU 时间随 G 线性增长，编译排队与测速重复次数同步上升；G 越大方差越低，但单位 token 的有效梯度产出越贵。工程上的判断是监控组内奖励方差与优势分布，动态调 G：方差高时加采样，同质时早停，而不是把 G 固定成一个拍脑袋的常数。
