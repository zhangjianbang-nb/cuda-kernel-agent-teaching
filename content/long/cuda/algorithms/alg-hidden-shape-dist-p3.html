一 · 加权聚合的推导：为什么刷单一 shape 会被稀释

评分式 $$\text{Score}=\sum_{s\in\mathcal{S}_{\text{hid}}} w_s\cdot\frac{T_{\text{base}}(s)}{T_{\text{gen}}(s)},\quad w_s=\frac{p(s)}{\sum_{s'}p(s')}$$ 的关键一步不在求和，而在权重归一化：分母是隐藏集上抽样所得 shape 的概率质量之和，而不是 1。这一步把“抽样偏差”显式吸收进权重，使得隐藏集即使不是全分布的无偏样本，聚合值仍然逼近 $$\mathbb{E}_{s\sim p}\left[\frac{T_{\text{base}}(s)}{T_{\text{gen}}(s)}\right]$$ 的一个重要性加权估计。推导链条是：设真实负载分布为 $p$，隐藏集 $\mathcal{S}_{\text{hid}}$ 按 $q$ 抽样，则对任意函数 $f(s)=T_{\text{base}}/T_{\text{gen}}$，有 $\mathbb{E}_q\left[\frac{p(s)}{q(s)}f(s)\right]=\mathbb{E}_p[f(s)]$；当抽样即按 $p$ 进行（$q=p$）时，重要性权重退化为 $p(s)/\sum p(s')$，这正是上式。换句话说，$w_s$ 不是“拍脑袋的权重”，而是抽样机制与目标分布一致时的自洽归一化因子。

稀释效应可以直接算：若 agent 只在某一个 shape $s_0$ 上把时延压到基线的 $k$ 倍（$T_{\text{gen}}=T_{\text{base}}/k$，即该项得分 $k$），其余 shape 维持 1.0，则总分 $=w_{s_0}\cdot k+(1-w_{s_0})\cdot 1$。在 head 段 90% 分位划分下，单个 shape 的权重上限被分布本身约束——真实 trace 里高频 shape 的 $p(s)$ 也不会接近 1，因为 batch×seq_len×维度的联合分布是长尾的。于是 $k$ 再大，乘上一个小 $w_{s_0}$ 后对总分的抬升有限；反过来，任何一个 shape 上退化到 0.5 倍，都会以 $w_s$ 的比例直接拉低总分。这就是“按分布加权”对过拟合的结构性惩罚：收益被小权重摊薄，退化被同权重放大。

代价在抽样侧：要算 $w_s$ 必须先有 $p(s)$ 的经验估计，而这要求生产 trace。冷启动场景没有 trace 时只能人工构造分布，此时 $q\neq p$，重要性加权估计的方差会随 $p/q$ 的尾部比值恶化——尾部 shape 若被人工低估，其权重被系统性压低，惩罚项随之失效。工程上应把 $p(s)$ 的拟合参数（分桶边界、平滑系数）与抽样 seed 一起写入审计日志，使任何一次评分的权重可复算。

二 · 时延比的度量误差：单次计时为什么不够

$T_{\text{base}}(s)/T_{\text{gen}}(s)$ 是逐 shape 的比值，分子分母各自带测量噪声。设单次计时噪声为乘性、标准差 $\sigma$，则比值噪声近似为 $\sqrt{2}\sigma$（两个独立测量相除，相对误差方差相加）。若每个 shape 只测一次，$\sigma$ 在 GPU 上受时钟抖动、DVFS、L2 残留状态影响，逐 shape 比值的方差不被任何聚合平均掉——因为每个 shape 的权重不同，噪声按 $w_s^2$ 加权进入总分方差：$$\mathrm{Var}(\text{Score})\approx\sum_s w_s^2\cdot 2\sigma^2$$。当隐藏集有 $N$ 个 shape 且权重近似均匀时，该方差约为 $2\sigma^2/N$，这就是为什么 200–500 个 shape 的批量评测能把总分噪声压到可判别区间；但若权重集中在少数 head shape 上，有效样本量 $N_{\text{eff}}=1/\sum w_s^2$ 远小于 $N$，噪声压不下去。

关键的一步是实现层面的：对每个 shape 取 $R$ 次重复的中位数而非均值，中位数对 DVFS 引起的长尾慢样本稳健；同时分子分母必须用同一轮交错计时（base 与 gen 交替跑），否则两次独立测量的时钟状态漂移会伪装成性能差异。伪代码落到可实现：

对 $s$ in 隐藏集：预热 gen 与 base 各若干次；for $r$ in 1..R：先计时 base，再计时 gen，记录配对样本；取配对比值的中位数作为该 shape 的 $f(s)$；累加 $w_s\cdot f(s)$。配对设计把共模漂移消掉，只剩差分噪声。

代价是评测时延：$R$ 次重复乘以 base+gen 两条路径，单 shape 的 GPU 时间线性增长；若 $R$ 取到能稳定中位数的量级，200–500 shape 全量跑下来，单次评测的 GPU 小时数相对公开集是数量级上升（给定事实：约为公开集的 10×）。这不是浪费，而是把“比值”从单点估计变成可复算统计量的必要开销。

三 · 显存与批量约束：隐藏 shape 抽样必须落在可执行域内

抽样不是无约束的：抽出的 shape 元组必须满足 kernel 的显存与对齐约束，否则评测会退化为“测 OOM 报错”而非“测性能”。设单 shape 的工作集为 $M(s)$（输入、输出、中间缓冲之和），设备可用显存为 $M_{\text{dev}}$，则可行域是 $$\mathcal{S}_{\text{feas}}=\{s: M(s)\le \alpha M_{\text{dev}}\}$$，$\alpha<1$ 留出碎片与临时分配余量。抽样器必须在 $\mathcal{S}_{\text{feas}}$ 上做拒绝采样或截断，且截断会改变 $q$，进而改变重要性权重——这正是第一节里 $q\neq p$ 的一个具体来源。工程判断：把截断记录进审计日志，并在报告里同时给出“截断后权重和”，让读者知道聚合覆盖了多少概率质量。

对齐约束同样进入抽样：非 2 的幂的 seq_len 会触发尾块处理，向量化加载退化，这类 shape 恰恰是 tail 段要检验的泛化点。抽样器应显式构造“维度为奇数、seq_len 非 2 的幂、batch=1”的组合，而不是指望随机抽样自然命中——随机抽样在联合分布的长尾上命中率极低，200–500 个样本里可能一个都没有。具体例子：若 trace 中 seq_len 集中在 2 的幂附近，纯随机抽样几乎抽不到 1000 附近的非对齐长度；必须用分层抽样在 tail 段强制配额。

代价是显存侧的：为容纳最大 tail shape，评测进程的峰值显存由最大可行 shape 决定，而非平均 shape；批量跑时若串行执行，显存峰值不叠加，但计时会被前一个 shape 的释放/分配干扰，因此每个 shape 之间需插入显存同步点。这增加了单 shape 的固定开销，在小 shape 上占比显著——小 shape 的计时必须扣除这段固定开销，否则 tail 段的“极端小”样本会被固定开销淹没，惩罚项失真。

四 · 尾部惩罚项的推导：为什么用 $\max(0,1-\text{ratio})$ 而不是比值本身

惩罚式 $$\text{Penalty}=\frac{1}{|\mathcal{S}_{\text{tail}}|}\sum_{s\in\mathcal{S}_{\text{tail}}}\max\left(0,1-\frac{T_{\text{base}}(s)}{T_{\text{gen}}(s)}\right)$$ 的设计有三处可推导的选择。第一，截断在 0：比值大于 1（gen 比 base 快）不产生负惩罚，否则 tail 段的加速会“抵消”head 段的退化，掩盖真实风险；部署风险是非对称的，慢是问题，快不是。第二，用 $1-\text{ratio}$ 而非 $\text{ratio}$ 本身：当 gen 在 tail 上退化到基线的 $1/m$ 倍（$m>1$），惩罚项贡献 $1-1/m$，随 $m$ 增大饱和到 1，不会因某个极端坏 shape 而爆炸；这使惩罚项有界，可与主分数量纲对齐后线性组合。第三，除以 $|\mathcal{S}_{\text{tail}}|$ 而非加权：tail 段样本少且分布不代表真实频率，等权平均比加权更稳健，避免单个高频 tail shape 主导惩罚。

关键一步是把“退化倍数”与“通过率”解耦：tail 段单独报告通过率（正确性 oracle 是否通过）与相对基线的退化倍数。一个 kernel 在 tail 上可能正确但慢，也可能快但错——两者混在一个标量里会互相抵消。工程实现上，惩罚项只统计“通过正确性检查的 tail shape”的退化，未通过的 shape 单独计入通过率分母，这样惩罚项度量的是“正确前提下的性能泛化”，而不是把错误当成慢来罚。

具体例子：某 kernel 对大 batch 做了分块优化，在 head 段得分接近上限；但在 batch=1、seq_len 非对齐的 tail shape 上，分块逻辑退化为标量循环，$T_{\text{gen}}$ 显著大于 $T_{\text{base}}$，比值小于 1，$\max(0,\cdot)$ 取到正贡献。若 tail 段有若干这类 shape，惩罚项被抬升，总分被拉回——这正是“只对大 batch 优化”的暴露机制。代价是评测必须为 tail 段单独跑一遍 fp64 参考与计时，tail 段样本虽少但每个都要完整验证，单 shape 成本与 head 段相同，这是 10× GPU 小时数的一部分来源。

五 · 奖励塑形：把 Score 与 Penalty 组合成可优化的信号

若把评测结果直接作为 RL 的奖励，需要处理两个问题：Score 的量纲随基线浮动（不同 shape 集的基线时延不同），Penalty 与 Score 的尺度不一致。可实现的组合是 $$R=\text{Score}-\lambda\cdot\text{Penalty}$$，$\lambda$ 由“tail 退化一档应等价于 head 少拿多少分”的工程判断定，而不是拟合出来的。推导上的关键一步：Score 的期望在 $q=p$ 时逼近真实分布的期望加速比，Penalty 的期望是 tail 段平均退化幅度；两者都是 $[0,\cdot)$ 上的有界量（Score 上界受单 shape 加速比上界约束，Penalty 上界为 1），因此线性组合不会因某一项无界而主导梯度。

奖励塑形的陷阱在于跨轮可比性：每轮评测重新抽样，Score 的抽样噪声随 $N_{\text{eff}}$ 波动，若 agent 在多轮 RL 中把“本轮抽到的容易 shape”当成策略改进，奖励信号会被抽样噪声污染。缓解手段是把 seed 加密且每轮更换，使 agent 无法针对特定 shape 集优化；同时审计日志记录每轮的分布参数，使跨轮奖励可比性可事后校验。代价是 token 侧：多轮 RL 中每轮都要重新生成 kernel 并在新隐藏集上评测，评测反馈的 token 消耗与 GPU 时间随轮数线性增长，这是“每轮重新抽样防记忆”的直接成本。

具体机制上，奖励应只回传聚合标量与 tail 段的通过率/退化倍数摘要，不回传逐 shape 的计时明细——逐 shape 明细一旦进入上下文，agent 就能反推隐藏集构成并在下一轮针对性优化，等于把隐藏集泄露成公开集。这是一个信息流设计问题，不是模型能力问题。

六 · 抽样器伪代码与可复算性约束

把前五节的约束落到一个可实现流程：输入是经验分布参数（分桶、平滑）、head/tail 分位阈值、可行域约束 $\mathcal{S}_{\text{feas}}$、样本数 $N$、加密 seed。步骤：按分布抽 $N$ 个候选；对每个候选做可行域检查，不可行则拒绝并重抽；在 tail 段按配额强制注入极端小/大/非 2 的幂组合；计算每个保留 shape 的 $w_s=p(s)/\sum p(s')$；输出 shape 列表、权重、seed、分布参数、截断记录。伪代码的关键一步是“先抽后算权重”：权重必须在拒绝采样之后、基于最终保留集重算分母，否则被拒绝 shape 的概率质量会凭空消失，权重和小于 1，Score 被系统性低估。

可复算性约束：seed 加密但不丢弃，审计日志存 seed 与分布参数的哈希；任何一次评分可由“seed+参数+保留集”完全复现。这使“隐藏”是对 agent 隐藏，对审计者不隐藏——隐藏集的不可见性与评测的可复算性不矛盾，前者靠信息流隔离，后者靠日志。代价是存储与流程开销：每轮评测的日志条目随 shape 数增长，且复算需要重跑 fp64 参考，复算成本与首次评测同量级；工程上只对争议评分做复算，常规轮次只存哈希与聚合结果。

最后落在工程判断上：这套公式体系的可靠性不取决于公式多精巧，而取决于三个可执行约束是否被强制执行——权重在拒绝采样后重算、计时用配对中位数、tail 惩罚只统计通过正确性的 shape。任一约束缺失，Score 与 Penalty 就会退化为可被 agent 利用的代理指标；而约束的执行点不在公式里，在抽样器与计时器的实现里，这也是为什么本部分把伪代码落到“先抽后算权重、配对计时、分账惩罚”这三个具体动作上。

隐藏抽样评分公式的边界：加权稀释、尾部惩罚与冷启动代价

评分公式的每一项都对应一个可失效的假设。加权项 $w_s=p(s)/\sum_{s'}p(s')$ 把收益按真实负载频率折算，其前提是 trace 分布本身稳定；一旦生产流量发生季节性或版本切换式漂移，历史 trace 拟合出的 $p(s)$ 就会把评测重心压在已过时的 shape 上，此时 $\text{Score}$ 与线上真实吞吐的相关性下降，公式本身却不会报警。更隐蔽的问题是权重集中：若经验分布中少数 head shape 占据了绝大部分概率质量，$\sum_s w_s\cdot T_{\text{base}}/T_{\text{gen}}$ 会被这些点主导，agent 只要在这几个 shape 上把比值做高，整体分数仍会显著抬升，稀释效应被概率质量本身抵消。工程上应同时记录权重的有效样本数（如 $1/\sum_s w_s^2$ 之类的集中度指标）并与分数一并入审计日志，否则无法区分“分布加权”与“变相加权少数点”。

尾部惩罚项 $\text{Penalty}=\frac{1}{|\mathcal{S}_{\text{tail}}|}\sum_{s\in\mathcal{S}_{\text{tail}}}\max(0,1-T_{\text{base}}(s)/T_{\text{gen}}(s))$ 的设计意图是只惩罚退化、不奖励超越，因此它对“tail 上偶然更快”完全不敏感，这既是优点也是盲区：一个在极端小 shape 上因 launch 开销抖动而略快的 kernel 不会得到任何正反馈，而一个在 tail 上正确性失败但时延尚可的 kernel 若未先被正确性 oracle 拦截，惩罚项只反映时延比值，无法表达“算错了所以更快”的情形。所以惩罚必须排在 fp64 参考正确性判定之后，且 tail 通过率要作为独立指标与 Penalty 并列报告，不能合并成单一标量。另一个边界是 $|\mathcal{S}_{\text{tail}}|$ 很小时（尾部 shape 天然稀疏），单点退化对均值的影响被放大，方差极大，跨轮比较需固定 tail 抽样规模或改用分位数统计。

$$\text{Score}=\sum_{s\in\mathcal{S}_{\text{hid}}} w_s\cdot\frac{T_{\text{base}}(s)}{T_{\text{gen}}(s)},\quad w_s=\frac{p(s)}{\sum_{s'}p(s')},\quad \text{Penalty}=\frac{1}{|\mathcal{S}_{\text{tail}}|}\sum_{s\in\mathcal{S}_{\text{tail}}}\max\left(0,1-\frac{T_{\text{base}}(s)}{T_{\text{gen}}(s)}\right)$$

系统代价集中在抽样与全量执行两端。200–500 个隐藏 shape 逐个跑 fp64 参考加计时，单次评测 GPU 小时数约为公开集的 10×，这是隐藏抽样最直接的预算约束；若每轮重新抽样以防跨轮记忆，则评测成本随轮数线性增长，多轮 RL 场景下必须把抽样预算纳入 rollout 成本模型，否则 reward 信号会被评测排队时延拖慢。冷启动场景没有真实 trace，只能人工构造维度、batch、seq_len 的联合分布，代表性存疑，此时 $p(s)$ 是人为假设而非观测，Score 的绝对值不可跨任务比较，只适合作同一分布下的相对排序。seed 加密与分布参数写入审计日志解决了可复现性，但加密 seed 与“每轮重抽”结合后，同一 agent 两次提交面对的是不同隐藏集，分数波动中混入了抽样噪声；可行的折中是固定分布参数、仅轮换 seed，并在报告中给出抽样标准误，让泛化判断落在置信区间而非单点分数上。
