一 · 合约的三段式结构：前置、后置与 NoOOB 如何各自承担证明义务

把 kernel 的正确性写成可验证合约，第一步不是选求解器，而是把“正确”拆成三段互不重叠的义务，否则 BMC 的搜索空间会被无关约束污染。前置条件 Pre(x) 只描述合法输入域：shape 的整除关系、dtype 位宽、指针 128 字节对齐、stride 连续性、归约维度的上界。后置条件 Post(y,x) 只描述输出等式：逐元素映射、归约结果与数学定义的等价、写回位置的索引一致性。第三段 NoOOB(x) 独立于数值语义，只约束每一次全局/共享内存访问的地址落在分配区间内。三段分离的工程价值在于：数值等式可以因为浮点建模成本被降级为 fuzz 覆盖，而 NoOOB 必须始终由 SMT 给出确定性结论——越界是安全关键 kernel 唯一不能靠抽样兜底的性质。

关键推导的一步在于把 NoOOB 从“运行时检查”转成“符号地址表达式的可满足性否定”。设第 i 次访存的符号地址为 A_i(x) = base + f_i(x)，分配区间为 [base, base+L)，则证明义务是：

$$\text{NoOOB}(x)\ \equiv\ \neg\,\exists x\in\mathcal{D}_{\text{pre}}:\ \bigvee_i \big(A_i(x) < \text{base}\ \vee\ A_i(x) \ge \text{base}+L\big)$$

求解器返回 UNSAT 即证明成立，返回 SAT 即给出反例 x。注意这里 f_i(x) 必须是关于符号输入的分段线性表达式，循环变量要已被 BMC 展开成有限合取，否则地址表达式含未解释函数，求解器只能退化为抽象解释而丢失精度。代价直接体现在状态空间：一个 128×128 tile 的二维索引展开后地址约束数量随 tile 面积平方增长，BMC 深度每加一层，SMT 查询数量与公式规模同步膨胀，分钟级到小时级的求解时间正是由此而来，这也是它难以进入每轮 RL 循环的根本原因。

具体例子：一个带边界掩码的 softmax 行归约 kernel，前置条件写 N % 4 == 0 && N <= 4096，后置条件写输出行和为 1 的浮点近似等式，NoOOB 则要求 row_off + col < N*H 对所有展开的 col 成立。求解器若在 N=4092 处找到 col 越过尾块的 SAT 赋值，反例就是精确的 shape 与列索引，agent 拿到后无需再猜触发条件，直接改掩码分支即可。

二 · 评分公式的逐项拆解：Proved 谓词如何变成可计算的标量

合约验证的输出不是一个布尔值，而是一个可被 RL 奖励消费的标量。给定公式 Proved = ∀x∈D_pre: Post(Kernel(x),x) ∧ NoOOB(x)，全称量词在有限域上等价于对 D_pre 的合取，但 D_pre 通常是无穷的（任意合法 shape），因此工程上必须做两件事：把 D_pre 切成有限个等价类（按 tile 边界、对齐状态、尾块长度分类），并在每个等价类内用 BMC 做有界全称。于是评分变成三层结构：

  • 已证明层：等价类内 UNSAT，权重最高，因为它是确定性结论而非抽样。
  • 反例层：等价类内 SAT，权重为负且绝对值最大，因为反例可复现、修复路径明确。
  • 未证明层：BMC 深度未覆盖的路径，权重按覆盖深度折扣，并与 fuzz 结果合并成置信度。

推导的关键一步是把“未证明”从二值逻辑里剥离出来。若强行把未覆盖路径记为失败，agent 会被迫为不可达分支写防御代码，浪费 token 且污染 kernel 结构；若记为成功，则等于把有界验证偷换成全称证明。正确做法是引入覆盖深度 d 与目标深度 D 的比值作为折扣因子：

$$\text{Score} = \frac{1}{|\mathcal{C}|}\sum_{c\in\mathcal{C}}\Big(w_p\cdot\mathbb{1}[\text{UNSAT}_c] - w_f\cdot\mathbb{1}[\text{SAT}_c] + w_u\cdot\min(1, d_c/D)\Big)$$

其中 C 是等价类集合，d_c 是该类实际展开深度。这个式子的代价在于 |C| 随分类维度组合爆炸：shape 边界 × 对齐状态 × dtype 三个维度就能产生数十个等价类，每类一次 BMC，总求解时间线性叠加。具体例子：把 N ∈ {4, 64, 4096} 与对齐/非对齐两态组合成 6 个等价类，其中 4 个在深度 8 内 UNSAT，1 个在 N=4092 给出 SAT 反例，1 个因 tile 过大只到深度 3 被标记未证明——最终分数由这三项加权得出，而不是一个笼统的“通过”。

三 · 时延与显存公式：为什么验证成本必须与 kernel 规模解耦

验证的时延不是单一数字，而是求解器查询次数与单次查询代价的乘积，这正是给定公式 Cost = |BMC depth| × |SMT queries| 的含义。逐项看：BMC 深度决定公式中循环展开的层数，每层引入一组新的地址与数值约束；SMT 查询数量决定求解器被调用的次数，通常每个等价类、每个断言、每次反例精化都触发一次查询。两者相乘而非相加，是因为深度增加会让每次查询的公式规模也变大，单次查询时间随深度超线性上升，乘积只是下界估计。

显存侧的代价来自符号执行引擎保存的路径约束与中间状态。每条未合并的分支路径都要保留一份约束集，路径数随分支深度指数增长，因此验证进程的常驻内存往往远大于被测 kernel 本身的显存占用。工程判断是：验证应作为离线门禁运行，而不是塞进每轮 RL 的采样循环——分钟级到小时级的求解时延与 RL 每轮秒级的采样节奏差两个数量级，强行耦合会让训练吞吐被验证完全支配。

具体例子：一个 128×128 tile 的 GEMM 累加 kernel，索引表达式含两层循环与一个条件掩码，BMC 深度取 16 时公式规模已需要求解器做多次 case split，单次查询进入分钟级；若把深度降到 4 只覆盖 tile 首块，则尾块路径全部落入未证明层。这里的取舍不是“能不能证”，而是“证到哪一层还能在门禁预算内返回”。可行的解耦手段是把大 tile 拆成小块等价类分别验证，用分块的全称覆盖替代单次深展开，代价是等价类数量上升、总查询次数增加，但单次查询规模可控。

四 · 误差公式：浮点语义为何被排除在 SMT 之外，以及如何用区间界兜底

浮点运算在 SMT 中并非不可建模，而是建模成本与收益不成比例：IEEE-754 的舍入模式、非规格化数、NaN 传播都要显式编码，归约的结合律在浮点下不成立，导致后置等式必须写成带容差的区间约束，而区间约束又让求解器失去线性算术的判定效率。工程上的折中是：SMT 只证整数索引与结构性质，数值正确性交给 fp64 参考 oracle 与 fuzz，两者在报告层合并。

误差项的推导关键一步是把“输出等式”松弛为区间包含：设参考结果为 r(x)，容差为 ε，则后置条件从 y = r(x) 变为 |y - r(x)| ≤ ε。这个松弛让 SMT 可以只处理 ε 的界而不处理舍入细节，但代价是 ε 的选取本身成为工程判断：取太紧会把合法浮点误差判为反例，取太松则放过真实的数值 bug。归约顺序错误这类 bug 恰恰表现为误差随规模增长而超出固定 ε，因此 ε 应写成规模的函数而非常数。

具体例子：一个跨 block 的两阶段归约，若第二阶段累加顺序与参考实现相反，单 block 内误差仍在 ε 内，但跨 block 累加后误差累积超出界，fuzz 在随机输入下未必命中，而把 ε 写成随归约长度增长的界后，该路径会被区间检查捕获。这里的代价是每次检查都要跑一遍 fp64 参考，显存与算力开销翻倍，因此只对归约类 kernel 启用，逐元素 kernel 仍用等式约束。

五 · 奖励公式：反例如何变成 agent 可消费的修复信号

验证结果进入 RL 奖励时，最容易被浪费的信息是反例的具体性。SAT 赋值给出的不只是“失败”，而是精确的 shape 与输入值，这比 fuzz 报出的随机崩溃更有修复价值。奖励设计应把反例的可复现性作为独立项：

$$R = \alpha\cdot\text{Score} + \beta\cdot\mathbb{1}[\text{counterexample reproducible}] - \gamma\cdot\text{tokens spent}$$

推导的关键一步是认识到 Score 已经含负权，若再对失败额外惩罚会造成双重计数，因此 β 项只奖励“反例可复现”这一属性而非失败本身。可复现性指反例能在真实硬件上以相同输入触发相同越界或相同误差超界，这需要把符号输入落成具体张量再跑一次，代价是一次额外的 kernel 启动与结果比对，时延在毫秒级，相对于 BMC 的分钟级可忽略。

γ 项约束 agent 的修复成本：反例越精确，agent 定位所需的推理 token 越少，因此 γ 与反例质量形成对冲——模糊的失败报告迫使 agent 大量试错，token 消耗上升，奖励被压低。具体例子：同一越界 bug，若报告只给“某 shape 越界”，agent 需枚举 tile 配置；若报告给出 N=4092, col=4095 的精确赋值，agent 一次改动掩码边界即可，token 消耗差一个量级，奖励差异直接体现在 γ 项上。

六 · 伪代码落地：从签名提取到反例回灌的可实现流程

把上述公式落成可运行流程，核心是把“提取—翻译—求解—回灌”四步写成确定性管线，每步的失败都有明确出口。伪代码思路如下（以结构化描述代替代码块）：从 kernel 签名与 PyTorch 语义提取 Pre 与 Post，把循环与索引翻译为符号表达式并按等价类切分，对每类调用 BMC 求解，UNSAT 记证明、SAT 记反例、超预算记未证明，最后把反例具体化为张量回灌给 agent 并合并 fuzz 置信度。

  • 提取：解析签名得到 shape/dtype/对齐约束，从参考实现得到输出等式，两者都写成求解器可接受的断言集。
  • 翻译：循环变量按 BMC 深度展开为有限合取，条件分支保留为路径约束，地址表达式必须化为分段线性形式。
  • 求解：每等价类一次查询，设置深度上限与超时，超时即落入未证明层而非报错。
  • 回灌：SAT 赋值映射回具体张量，跑一次真实 kernel 确认可复现，再作为修复信号送入 agent。

代价落在两处：翻译阶段的分段线性化对含数据依赖索引的 kernel 会失败，此时只能降级为 fuzz；求解阶段的超时阈值决定未证明层的比例，阈值越松证明覆盖率越高但门禁时延越长。具体例子：一个含 atomicAdd 的散射 kernel，地址依赖运行时数据，翻译阶段无法化为线性表达式，管线直接标记该 kernel 不适用 SMT 证明、仅保留 NoOOB 的保守上界检查与 fuzz 数值验证——这个出口本身就是工程判断的一部分，而不是管线的缺陷。

有界证明的边界：BMC 深度、浮点建模与反例回灌

合约验证的产出不是一个布尔值，而是三元组：证明、反例、未证明。$$\text{Proved}=\forall \mathbf{x}\in\mathcal{D}_{\text{pre}}:\ \text{Post}(\text{Kernel}(\mathbf{x}),\mathbf{x})\ \wedge\ \text{NoOOB}(\mathbf{x})$$ 这个全称量词在工程上无法直接兑现——SMT 求解器面对无界循环只能发散。真正可执行的是把 $\mathcal{D}_{\text{pre}}$ 收缩为有界展开的符号路径集合，用 BMC 在固定深度 $d$ 上判定：$\text{Proved}_d=\forall \mathbf{x}\in\mathcal{D}_{\text{pre}}^{(d)}:\ \text{Post}\wedge\text{NoOOB}$。$d$ 必须覆盖典型 tile 的循环次数（如 128×128 tile 在 16×16 线程块下每线程 64 次迭代），否则证明只对“小规模输入”成立，而 OOB 恰恰常出现在边界 tile 的尾块处理上。代价直接体现为 $\text{Cost}=|\text{BMC depth}|\times|\text{SMT queries}|$：深度每加一层，索引符号表达式与路径条件数量近似线性增长，求解时间在分钟级到小时级，无法嵌入每轮 RL 的秒级反馈回路。

失效条件集中在两类。其一是浮点语义：SMT 对 IEEE-754 的建模需要位级展开加法/乘法与舍入模式，归约结合律的证明状态空间随元素数指数膨胀，因此多数合约只覆盖整数索引、对齐与结构性质（NoOOB、shape 一致性、dtype 匹配），数值正确性仍退回 fuzz 抽样。其二是前置条件过窄：若 $\mathcal{D}_{\text{pre}}$ 把 stride、非连续布局或负 stride 排除在外，证明对真实 PyTorch 调用就是空的——合约的“对所有合法输入成立”必须与框架语义对齐，否则是自证同义反复。一个具体例子：归约 kernel 的后置条件写成“输出等于按固定顺序累加”，但 GPU 上 warp shuffle 的归约顺序依赖线程调度，SMT 若把顺序建模为确定序列，证明通过而实际运行可能因重排产生不同舍入结果，这类“证明通过但语义偏离”比 fuzz 漏检更危险。

反例回灌是可实现的关键一步：求解器返回的模型给出具体 shape 与输入值（如 shape=(1,3,127) 的尾块使 idx=127 越界），agent 无需再猜触发条件，直接把该输入作为回归用例写入修复循环。伪代码思路：for d in depths: r = bmc(kernel, pre, post, d); if r.sat: emit_counterexample(r.model); break; elif r.unknown: mark_unproved(d)。未证明路径与 fuzz 结果合并报告置信度——已证明部分给确定性保证，未证明部分标注深度上界，fuzz 覆盖其外的抽样。系统代价是编译与求解时延挤占 RL 吞吐：单次 BMC 分钟级意味着每轮只能验证少量候选，验证必须作为离线门控而非在线奖励项。
