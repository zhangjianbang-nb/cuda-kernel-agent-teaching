一 · 从候选到奖励：一次评测流动的五个阶段

把一次 kernel 候选的评测拆成流动，是为了让每一步的输入、输出与代价都能被单独审计。这条流动不是流水线式的黑箱，而是一条带反馈的链：生成阶段产出的源码文本，编译阶段产出的二进制与编译日志，执行阶段产出的时延样本与正确性判定，统计阶段产出的稳健区间，奖励阶段产出的标量信号。任何一步的产物被污染，下游的奖励就不可信。因此本部分按阶段展开，重点不在定义，而在每步的接口契约与代价结构。

阶段划分如下：生成（候选源码 + 元信息）、编译与合约校验（二进制 + 编译时延 + 静态检查结果）、正确性判定（布尔 + 失败模式标签）、时延采样与稳健统计（样本分布 + 置信下界）、奖励合成与归一（标量 + 方差监控量）。五个阶段的串联顺序有讲究：正确性判定必须早于时延采样，因为错误 kernel 的时延没有意义；合约校验必须早于执行，因为越界写会污染后续测量环境。这个顺序本身就是一种工程判断，而非任意排列。

用一个具体例子贯穿：候选是一个对 fp32 输入做逐元素 sigmoid 的 Triton kernel，参考实现是 PyTorch 的 torch.sigmoid。生成阶段给出的是带 BLOCK_SIZE 参数的 Triton 源码与一个声称的网格配置；编译阶段产出 PTX 与 cubin，同时合约校验检查网格维度是否覆盖全部元素、是否有对输出缓冲的写越界；正确性判定在若干组隐藏 shape 上比对；时延采样在锁频环境下重复 k 次；奖励合成把正确性与置信下界加速比组合成一个标量。每一步的产物都可以被单独记录，形成可回放的单次评测轨迹。

二 · 生成与编译：接口契约与编译时延的预算

生成阶段的输入是任务描述、参考实现签名、以及上一轮的反馈摘要；输出是候选源码加上一份自描述的元信息（声明的网格、块大小、dtype、是否使用共享内存）。元信息不是装饰，它是编译阶段合约校验的输入之一：若声明网格与源码中实际启动配置不一致，合约校验直接判负，无需进入执行。这一步的代价主要是 token 与时延：生成一个候选的 token 消耗取决于源码长度与反馈摘要的长度，而反馈摘要若塞入完整的 NCU 指标会显著拉长上下文，因此实践中反馈摘要是被压缩过的结构化字段。

编译阶段的输入是源码与元信息，输出是二进制、编译日志、以及静态合约检查的结论。编译时延是这一阶段的主要代价，且它对候选的生死有直接影响：编译失败的候选不进入执行，其奖励应为零而非负，因为编译失败往往源于语法或 API 误用，属于可修复的低阶错误，过度惩罚会让策略回避探索。编译日志本身是有价值的反馈：寄存器溢出、共享内存超限、未使用的变量警告，都可以作为下一轮生成的输入信号。这里的关键工程判断是编译预算：单轮内允许编译的候选数受限于墙钟时间，若编译时延方差大（例如模板展开深度不同），则应按编译时延对候选排序，优先编译便宜且元信息完整的候选。

合约校验在编译阶段完成静态部分，在执行阶段完成动态部分。静态部分包括：网格覆盖性、dtype 一致性、是否存在对输入缓冲的写操作。动态部分（越界、未初始化读）需要执行期检测，其代价是额外的地址检查或影子内存，会拖慢被测 kernel 本身，因此通常只在抽样候选上开启。这个抽样策略本身是代价权衡：全量开启动态检查会让时延测量失真，完全不开启则可能让越界写悄悄污染后续候选的测量环境。折中做法是对每个候选的首轮执行开启检查，通过后再关闭检查做时延采样。

三 · 正确性判定：布尔输出背后的失败模式标签

正确性判定的输入是候选输出与参考输出，输出是一个布尔值加上失败模式标签。布尔值进入奖励公式的指示函数，标签则进入反馈摘要供下一轮生成使用。失败模式至少应区分：数值偏差超容差、形状不匹配、非确定性输出、以及执行期异常（非法访存、超时）。区分这些标签的价值在于，它们对应不同的修复路径——数值偏差提示归约顺序或精度问题，形状不匹配提示网格计算错误，非确定性提示缺少同步或原子操作使用不当。把这些标签压成一个布尔值会丢失修复信号。

判定本身的代价是参考实现的执行时间与比对时间。参考实现若在 CPU 上跑，比对时延可能超过被测 kernel 的时延数个量级，成为整条流动的瓶颈；若参考实现在 GPU 上跑，则需保证参考实现本身不被候选污染（独立流、独立缓冲）。比对容差的选择是正确性与奖励噪声之间的耦合点：容差过松会让有微小数值错误的候选通过，进而在时延上获得不应得的奖励；容差过紧会让合法的浮点重排被判负。工程上常见的做法是对每个任务预设容差，并在隐藏 shape 上验证参考实现自身在容差内稳定。

一个具体代价例子：若正确性判定在每组隐藏 shape 上都要跑一次参考实现，而隐藏 shape 有若干组，则参考实现的执行次数是候选数的数倍。把参考输出缓存起来（按 shape 与 dtype 键控）可以把这部分代价从每候选摊薄到每 shape 一次，代价是显存占用。这是一个典型的以显存换时延的权衡，且缓存失效条件必须严格：dtype、shape、参考实现版本任一变化都要失效。

四 · 时延采样：k 次重复的代价结构与 warmup 的作用

时延采样的输入是编译通过的二进制与输入缓冲，输出是 k 个时延样本。采样流程包含 warmup 与正式测量两段：warmup 的作用是把频率拉到稳态、把权重与输入页表预热进缓存，其样本不计入统计。正式测量重复 k 次，每次记录一个时延值。这里的机制细节是：k 的选择不是越大越好，因为每增加一次重复就线性增加 GPU 时间；而统计量的稳健性随 k 增长的边际收益递减。工程上 k 的取值应使得置信区间的半宽相对于待检测的最小加速幅度足够小。

采样阶段的代价可以写成显式预算：单候选的 GPU 时间约为 (warmup + k) × 单次时延，整轮训练的 GPU 时间约为候选数 × 单候选时间 × 轮数。当 k 翻倍，训练吞吐大致减半，这是稳健奖励最直接的代价。另一个隐性代价是测量环境的漂移：k 次重复跨越的时间越长，频率抖动与噪声邻居的干扰越可能侵入样本，因此采样窗口不宜过长，必要时把 k 次重复分散到多个短窗口并在窗口间插入环境检查。

样本分布的形状决定了后续统计量的选择。若分布近似对称，中位数与截尾均值差异不大；若存在偶发的长尾（例如某次测量被邻居抢占），中位数更稳健而均值会被拉偏。这里不重复稳健统计量的公式推导，只强调采样阶段的一个契约：每个样本必须附带时间戳与环境标记（频率、占用率），否则统计阶段无法区分“真实慢”与“环境干扰导致的慢”。缺少环境标记的样本在剔除异常值时只能靠数值阈值，容易误杀真实的性能退化。

五 · 稳健统计与置信下界：从样本到可比较的标量

统计阶段的输入是 k 个时延样本，输出是稳健时延估计与置信下界。机制上，先取中位数作为中心估计，再用 MAD 估计离散度，最后按样本量构造下界。公式如下：

$$\tilde{T}=\text{median}(T_1,\dots,T_k),\quad \text{LB}=\tilde{T}-z\cdot\frac{\text{MAD}}{\sqrt{k}},\quad r=\mathbb{1}[\text{correct}]\cdot\max\left(0,\frac{T_{\text{ref}}}{\text{LB}}-1\right)$$

公式中三个量的角色需要分清：\tilde{T} 是点估计，\text{LB} 是保守估计，r 是最终奖励。奖励用 \text{LB} 而非 \tilde{T} 作分母，意味着只有当置信下界仍然优于参考时延才给正奖励；\max(0,\cdot) 截断了负加速，使奖励不会因测量噪声变成大幅负值而主导梯度。指示函数把正确性作为乘性门，错误候选的奖励恒为零，与它的时延无关——这是防止“快但错”的候选获得奖励的关键结构。

这一阶段的代价体现在两个方面。其一是保守性代价：z 越大、k 越小，下界越低，小幅但真实的提升会被漏掉，策略收敛变慢。其二是统计计算本身的代价，相对于 GPU 时间可忽略，但它引入了一个新的失败模式：若 MAD 为零（所有样本完全相同），下界等于中位数，置信区间退化，此时应视为测量分辨率不足而非真实零方差。工程上应对零 MAD 的做法是引入一个与测量分辨率同量级的下限，避免下界过度乐观。

一个具体例子：某候选的中位时延略优于参考，但样本离散度较大，导致下界低于参考时延，奖励为零。这不是误判，而是该候选在当前测量精度下无法被证明优于参考。若该候选确实更优，则增加 k 或改善测量环境（锁频、隔离）会缩小离散度，使下界上移。因此统计阶段与校准阶段是耦合的：下界上移的路径有两条，一是真实提升，二是测量精度提升，奖励设计必须让前者主导，否则策略会学会“等待测量环境变好”而非“写出更快的 kernel”。

六 · 奖励合成与归一：送入 RL 前的最后一道整形

奖励合成的输入是正确性布尔、置信下界加速比、以及历史奖励的统计量；输出是归一化并裁剪后的标量。机制上，先按任务与参考时延做尺度归一，使不同任务的奖励处于可比量级，再做裁剪以限制单样本奖励的幅度。归一化的必要性在于：不同任务的参考时延差异大，原始加速比在同一策略下会产生量级不同的奖励，导致梯度被少数任务主导。裁剪的必要性在于：偶发的极端加速（可能源于测量异常或缓存侥幸）会主导一次更新，破坏训练的平稳性。

这一步的代价是信息损失。裁剪会削掉真实的大幅提升信号，归一化会抹平任务间的难度差异。工程判断是：裁剪阈值应设在历史奖励分布的高分位之外，使绝大多数真实提升不被削掉；归一化的统计量应使用滑动窗口而非全局累计，以适应策略改进带来的奖励分布漂移。另一个代价是奖励方差监控本身的开销：监控量需要按轮聚合，聚合粒度太细会引入额外噪声，太粗则无法及时发现方差发散。

校准阶段与奖励合成共享同一个监控回路。定期校准测量环境（锁频、隔离噪声邻居）会改变时延分布的离散度，从而改变下界与奖励的尺度；若校准后不重新估计归一化统计量，奖励分布会出现阶跃式漂移，策略会把环境变化误读为自身改进。因此校准事件必须与归一化统计量的重置绑定。监控奖励方差是否收敛，是判断整条流动是否健康的直接指标：方差持续高位说明测量噪声仍主导奖励，方差骤降则需排查是否所有候选都被判负或奖励被裁剪压平。

把五个阶段串起来看，单次评测的代价结构是：生成 token 与时延、编译时延、正确性判定的参考执行与比对、k 次时延采样的 GPU 时间、统计与归一化的可忽略计算。其中 GPU 时间随 k 线性增长，是吞吐的主要约束；编译时延随候选复杂度增长，是单轮墙钟时间的约束；参考执行次数随隐藏 shape 数增长，是显存与时间的联合约束。工程上优化这条流动的方向不是压缩某一步，而是让每一步的产物可被复用与审计：编译产物按源码哈希缓存、参考输出按 shape 缓存、环境标记随样本落盘。这些复用不改变奖励公式，但显著降低每轮的实际代价，使稳健奖励的保守性代价（漏掉小幅真实提升）不至于因吞吐压力而被进一步放大。
