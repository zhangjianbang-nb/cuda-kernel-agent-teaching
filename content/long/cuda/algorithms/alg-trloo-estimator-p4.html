一 · 负载选择的判据：奖励信号必须可分辨

TRLOO 的优势估计依赖组内奖励的相对差异，因此负载的第一判据不是“难”或“热”，而是“同一 prompt 的 G 个候选能否产生可分辨的奖励分布”。一个适合的负载应满足：随机采样下奖励落在中间区间而非两端饱和，且奖励差异主要来自 kernel 实现质量而非编译随机性。若某算子对任何合理实现都只有一种写法（如极简 elementwise 加），组内奖励几乎全等，$$A_i=r_i-\frac{1}{G-1}\sum_{j\ne i}r_j$$ 趋近零，策略梯度没有方向。反之，若算子超出模型能力（如需要跨 SM 精细同步的复杂归约），G 个候选全部编译失败或全部正确性不过，奖励同样退化为常数。工程上应把负载按“可实现解空间宽度”分层：宽解空间（多种 tiling、向量化、流水线策略并存）的算子优先，窄解空间算子只作为负样本或课程后期的稳定性检验。

具体机制上，选负载时要预跑一次“冷采样探针”：用当前策略对每个候选 prompt 采样少量样本，记录奖励的组内标准差与通过率。若通过率接近 0 或 1，或组内标准差低于测速噪声量级，该 prompt 进入淘汰或降权池。代价是探针本身消耗 GPU 编译与测速时间，且探针结果随策略漂移而失效，需要周期性重跑。一个典型例子是 softmax 类算子：朴素实现与在线 softmax 实现并存，数值稳定性处理（减最大值）与 warp 内归约策略都有多种选择，组内奖励天然分层，适合作为 TRLOO 的主负载；而单纯的 copy kernel 解空间窄，只适合做基线校准。

二 · 算子与 shape 的搭配：让奖励差异落在实现维度

同一算子在不同 shape 下会激活不同的实现瓶颈，TRLOO 需要的是“奖励差异由实现选择驱动”的 shape 配置。以矩阵乘为例，小 M 小 N 的 skinny 形状下瓶颈在 launch 开销与尾块处理，大 K 形状下瓶颈在 shared memory 分块与寄存器压力，二者的最优实现策略不同。若一个 prompt 固定单一 shape，模型可能靠记忆某个模板拿高分，组内差异被压缩；若 shape 分布过宽，同一候选在不同 shape 上表现剧烈波动，奖励被 shape 噪声主导，优势估计混入与实现质量无关的方差。

可行做法是为每个 prompt 绑定一组“同族 shape”，即共享同一瓶颈类型的若干尺寸，奖励取这组 shape 的聚合（如按 SOL 归一后的均值，归一方式见 Roofline/SOL 归一评分一节）。这样组内比较仍在同一瓶颈语境下进行，同时抑制单点过拟合。代价是每个候选要在多个 shape 上编译与测速，GPU 时间随 shape 数线性增长；且聚合方式若用简单平均，慢 shape 会淹没快 shape 的信号，需要用几何平均或按调用频率加权。具体例子：一个 reduction prompt 绑定 (4096, 8192, 16384) 三个长度，候选若只在短长度上做满向量化而在长长度上退化为标量循环，聚合奖励会明显低于在各长度都稳健的候选，这正是 TRLOO 想捕捉的实现质量差异。

三 · 硬件档位与基线选择：把绝对性能转成可比优势

TRLOO 的奖励是组内相对量，但基线选择决定了这个相对量是否有工程意义。基线不应是“零”或“理论峰值”，而应是同硬件、同编译选项下的可复现参照实现：库实现（cuBLAS/cuDNN 对应算子）、手写参考 kernel、或上一轮策略的最优候选。用库实现做基线的好处是绝对性能锚点稳定，坏处是部分算子库实现已接近 SOL，候选难以超越，奖励长期为负，梯度信号被压缩；用手写参考做基线则锚点随人漂移。工程判断是：主基线用库实现，辅以“策略历史最优”作为相对进步量，两者分开记录，不混入同一奖励。

硬件档位要匹配负载的瓶颈类型。访存密集算子应在高带宽档位上评测，否则算力瓶颈掩盖了访存优化信号；算力密集算子则需保证 SM 占用不被小显存卡限制。跨档位混评会让同一候选在不同卡上得到相反的优势符号，破坏组内可比性。代价是分档评测增加调度复杂度与机器占用，且低档位卡上的编译时间占比更高，摊薄了有效测速样本。具体机制上，可为每个负载标注“瓶颈标签 + 最低硬件档位”，评测调度器据此路由，避免把访存负载丢到算力受限的小卡上产生虚假优势。

四 · 输入分布设定：正确性与性能的双重覆盖

输入分布同时服务两个目标：正确性 oracle 要能触发边界，测速要能代表真实调用。TRLOO 的奖励里正确性是硬门槛，性能是连续项，因此输入分布的第一层是“正确性覆盖集”：包含非对齐尺寸、极窄/极宽维度、含 NaN/Inf 的数值、以及会触发 bank conflict 或分支发散的取值模式。第二层是“测速代表集”：按真实负载的 shape 与 dtype 分布采样，避免用单一理想 shape 测速导致候选过拟合到该 shape 的缓存行为。

两层分布的比例直接影响奖励构成。若正确性覆盖集过大，编译与验证时间占比升高，G 个候选的 GPU 成本中有效测速比例下降；若测速代表集过小，性能奖励方差大，组内优势被测量噪声污染。一个可操作的配方是：正确性集固定为若干必测边界用例（数量少但覆盖关键路径），测速集按 shape 族抽样若干代表点，奖励 = 正确性通过（布尔门槛）× 测速聚合分。具体例子：一个 transpose kernel 的正确性集必须包含非方阵与非 32 倍数维度，否则转置索引错误可能被方阵对齐掩盖；测速集则覆盖方阵与非方阵各若干，防止候选只优化方阵路径。

五 · 指标计算：从原始时延到可比较的优势

指标计算的核心是把原始测量转成组内可比的标量奖励，同时抑制测量噪声。原始时延需做 warmup 与多次重复取稳健统计量（中位数或截尾均值），并扣除 launch 开销的固定部分；随后按 SOL 归一，得到与硬件档位无关的效率分。归一后的奖励再进入留一法基线，此时组内差异才反映实现质量而非机器抖动。公式上，若记归一效率为 $$e_i=\frac{T_{\text{sol}}}{T_i}$$，则奖励 $$r_i=e_i\cdot\mathbb{1}[\text{correct}_i]$$，优势仍按 $$A_i=r_i-\frac{1}{G-1}\sum_{j\ne i}r_j$$ 计算。标准化与裁剪在优势层面做，不在奖励层面做，避免破坏留一法的无偏性。

代价在于：归一需要可靠的 SOL 估计，而 SOL 本身依赖 shape 与硬件档位，估计偏差会系统性地平移所有奖励，虽然不影响组内相对优势，但会影响跨组可比与课程调度。另一个代价是重复测速带来的时间开销，重复次数越多噪声越低但 G 个候选的总测速时间线性上升。工程上应把重复次数与 G 一起纳入预算：噪声大时增加重复次数比增加 G 更划算，因为前者降低的是测量方差，后者降低的是采样方差，二者对优势估计的贡献不同。具体例子：某候选在两次测速间波动超过组内奖励标准差的一半时，应判定测速不可靠，将该组标记为低置信并降权，而不是直接用于策略更新。

六 · 负载不对时的失效形态

负载配置错误不会报错，只会让训练静默退化。第一种失效是“奖励饱和”：通过率接近 1 或 0，组内奖励方差趋零，优势全为零，策略梯度无更新，表现为 loss 平稳但能力不涨。第二种是“噪声主导”：测速重复不足或 shape 抽样过少，组内奖励差异小于测量噪声，优势符号随机，策略被随机梯度推动，表现为奖励均值不升而方差上升。第三种是“基线错配”：库基线过强导致长期负优势，或基线随硬件档位漂移导致同一候选在不同组得到相反符号，表现为策略在少数易超越算子上过拟合、在难算子上放弃。

诊断手段是监控组内奖励标准差、优势绝对值均值、以及正确性通过率三者的联合分布：标准差低且通过率高说明负载太易，标准差低且通过率低说明负载太难，标准差高但优势均值接近零说明噪声主导。调整动作对应为：换更难/更易的同族算子、增加测速重复或收窄 shape 族、重设基线与硬件档位。代价是这些监控与调整本身需要额外的评测轮次，且调整后的负载分布变化会使历史优势不可比，需要重新校准课程权重。工程判断落在具体机制上：把“组内奖励标准差 / 测速噪声估计”作为一个在线比值，低于阈值即触发负载重采样，而不是等训练曲线变平再事后排查。

留一法配方的适用边界：负载、基线与失效形态

留一法优势估计的收益并非无条件成立，它把“组内相对比较”作为信号来源，因此负载设计的第一原则是：同一 prompt 下的 G 个候选必须真的处在可比较的奖励尺度上，且奖励差异要能被编译、验证、测速这条流水线分辨出来。适合的算子形态是那些存在多条合法实现路径、性能对调度与分块敏感、且正确性可由少量输入确定判定的 kernel——GEMM 变体、reduction、softmax、layernorm、attention 前向这类有明确数值 oracle 的算子，天然能在一个 prompt 内产生“都对但快慢不同”的候选谱系。反过来，形状极小的算子（单 block 即可完成）会让测速噪声压过真实差异，组内奖励挤在噪声带内，留一法减掉的只是噪声均值而非难度差异；而形状极大、单次编译与测速就占满显存的负载，G 个候选无法并行驻留，采样成本直接变成串行时延。硬件侧，留一法要求同组候选在同一设备、同一时钟状态下测速，跨卡或跨代混测会把硬件差异误记成策略差异，污染 baseline。输入分布上，正确性 oracle 的输入应覆盖边界形状与非对齐尺寸，否则“全组都通过”的同质化会系统性出现。

基线的选择直接决定优势的统计性质。用组内均值做 baseline 时，第 i 个样本的对照里含它自己，奖励高的样本会把均值抬高、从而压低自身优势，形成负偏差；留一法把自身剔除，得到 $$A_i=r_i-\frac{1}{G-1}\sum_{j\ne i}r_j$$，在奖励与策略无关的零假设下期望为零，这是它相对全局 baseline 与组内均值 baseline 的核心优势。但无偏不等于低方差：当 G 很小，baseline 本身噪声大，A_i 的方差约为组内奖励方差的 (1+1/(G-1)) 倍量级，G=2 时几乎退化为成对比较，信号极不稳定。工程上应把 G 与组内奖励标准差一起监控，方差高时增大 G，方差塌缩时减小 G 省 GPU 时延。指标计算上，奖励必须是标量且量纲统一：正确性用通过/失败的硬判，性能用以同负载最优实现为参照的加速比或 SOL 占比，二者加权前先做尺度归一，否则编译失败与慢 5% 会落在同一奖励区间，留一法比较的就不是同一件事。

负载不对时的失效形态很具体。其一是同质塌缩：一个 prompt 的 G 个候选全部编译失败或全部通过且速度接近，组内奖励方差趋近零，A_i 全部趋近零，策略梯度更新近乎为零，这一组采样消耗的 G 次编译与测速全部变成沉没成本，token 与 GPU 时延照付而学习信号为零。其二是奖励黑客下的伪差异：若测速只跑一次、不做 warmup 与多次取中位数，缓存命中与时钟抖动会制造出与代码质量无关的快慢差，留一法会把这些噪声当作可学习的优势，把策略推向“更会撞缓存”而非“更好的 kernel”。其三是难度混淆：不同 prompt 的绝对奖励水平差异大，留一法只在组内去均值，跨 prompt 的难度差异仍留在梯度里，若不做按 prompt 的奖励标准化或分层采样，高难度 prompt 会持续贡献大幅度的同号梯度，等效于给策略加了一个与任务无关的偏置项。其四是 G 与显存/编译时间的线性代价：每组 G 个候选都要完整编译、验证、测速，成本随 G 线性增长，而收益随 G 边际递减，配方上应把 G 设为可调并配合组内方差自适应，而不是固定一个大 G 硬扛。

负载特征留一法表现系统代价
多实现路径、有硬 oracle、形状中等组内奖励谱系清晰，优势信号强G 次编译+测速，时延线性
极小 shape、测速噪声主导优势被噪声淹没，近零更新GPU 时延照付，token 浪费
全失败或全通过的同质组方差塌缩，学习信号消失整组采样沉没
超大 shape、单候选占满显存无法并行采样，组内比较失真串行编译，墙钟时间放大
