一 · 阈值的来源：从参考实现反推可接受带宽

合成训练样本时，最容易被滥用的做法是把“看起来像 kernel”的代码直接标成正确。工程上真正需要的是给每个候选样本配一组可测量的阈值，而这些阈值的锚点应当来自参考实现本身，而不是拍脑袋。具体机制是：对每个算子先在目标 GPU 上跑一遍参考实现（PyTorch eager 或 cuBLAS/cuDNN 路径），记录其实际耗时 t_ref、实际搬运字节 B_ref 与实际占用显存 M_ref，再把这三个量作为该样本的“物理基线”。合成样本的阈值全部写成相对基线的比例，而不是绝对值，这样同一套阈值可以跨形状复用，也不会因为换卡而失效。

形式化地，设合成 kernel 的实测耗时为 t_syn，则定义加速比与带宽利用率两个派生量：

$$S=\frac{t_{\text{ref}}}{t_{\text{syn}}},\qquad U=\frac{B_{\text{syn}}/t_{\text{syn}}}{B_{\text{peak}}\cdot\eta}$$

其中 B_peak 是卡的理论带宽，η 是 roofline 上该算子可达的比例上限（由算术强度决定，不是常数）。阈值就落在这两个量上：一个样本若声称“优于参考实现”，则要求 S 落在某个区间内，而不是“越大越好”。原因是合成样本的参考实现往往不是最优实现，S 过大通常意味着测量口径错了（漏同步、缓存命中、形状退化），而不是 kernel 真的更快。代价在这里：每多一个阈值维度，样本生成阶段就要多一次参考实现的 profile 采集，单样本的采集时延随维度线性增长；如果对每个形状都做完整 NCU 采集，生成一万条样本的 profile 开销会远超训练本身，因此实践中只对“边界样本”（S 接近阈值上下沿的样本）做完整采集，其余用计时器粗测。

具体例子：一个 reduction 类算子，参考实现走的是两段式归约，B_ref 约为 2N×4 字节（读一次写一次）。合成样本若写成单段 warp 级归约，B_syn 与 B_ref 同量级，此时 U 的上限由 η 决定；若合成样本报出的 U 明显超过 η 对应的 roofline 上限，就直接判为测量错误而非性能优异。这条判据不依赖任何具体数字，只依赖“搬运字节数不能少于语义所需”这一守恒关系。

二 · 难度分布的工程刻度：形状扰动幅度与算子组合深度

难度分布不能只写“易/中/难”三档，需要可复现的刻度。可用的两个刻度是形状扰动幅度与算子组合深度。形状扰动定义为合成形状与基准形状之间的相对偏移：

$$d=\max_i\frac{|s_i-s_i^{\text{base}}|}{s_i^{\text{base}}}$$

d 的控制方式是分层采样：小扰动层取 d 落在使得 tile 划分不变的区间内（即形状仍能被同一个 block tile 整除或只差一个尾块），中扰动层取 d 使得尾块处理逻辑必须改变，大扰动层取 d 使得原本的向量化宽度失效、必须退化为标量或改变访存对齐。这三层的区分标准是“参考实现是否需要改代码路径”，而不是数值大小本身——这是一个可测量的判据：把扰动后的形状喂给参考实现，看它是否切换到了不同的 kernel 变体（例如 cuBLAS 换了 tile 配置），切换了就算跨层。

算子组合深度指一条样本里串联的算子个数 k。k 的增长带来的代价不是线性的：每增加一个算子，中间张量的显存占用增加一份，且融合机会出现或消失，正确性 oracle 的比对点也要增加。工程上把 k 限制在一个小范围内，并对 k≥2 的样本强制要求给出中间张量的比对，否则无法定位是哪一个子算子出错。具体例子：一个“matmul + bias + activation”的三算子链，若只比对最终输出，当 activation 写错而 bias 恰好补偿时可能通过；加入中间张量比对后，错误注入的检出率才与单算子样本持平。这里的代价是显存：保留中间张量使峰值显存上升，长序列或大 batch 下会直接 OOM，因此中间张量比对只在调试子集上开启。

三 · 泄漏风险的量化：与基准集的去重判据

泄漏不是“看起来像”就能判定的，需要可执行的去重判据。三个层次：文本层、结构层、数值层。文本层用代码 token 的 n-gram 重合率，结构层用算子图同构判定（把 kernel 的访存模式与计算模式抽象成图，比较节点类型与边），数值层用固定输入下的输出指纹比对。三层各自独立，任一层命中即标记为疑似泄漏，进入人工复核队列而不是直接丢弃——直接丢弃会让分布偏向“与基准差异大”的样本，反而扭曲难度分布。

结构层判定的具体机制：把每个 kernel 归一化为“循环嵌套深度 × 访存 stride 模式 × 归约轴”三元组，两个 kernel 三元组相同即视为结构重复，无论变量名与循环顺序如何改写。这个判据的代价是误杀：同一个数学算子的两种合法实现（例如分块与不分块）可能被判为重复，因此结构层只用于“与基准集比对”，不用于样本之间的相互去重。数值层指纹的代价是计算量：每条样本要跑一次固定输入的前向，时延与样本长度成正比；对长上下文样本，这一步的耗时可能超过样本生成本身，所以数值层只对通过文本层与结构层筛查后的候选执行。

具体例子：一个 softmax 样本，若把基准实现的行归约改成列归约再转置，文本层不命中、结构层命中（归约轴相同、stride 模式等价），此时应判为疑似泄漏；若改成两段式 online softmax，结构层不命中，但数值层在极端值输入下输出指纹与基准一致，仍需复核。这说明单层判据不足以定性，必须三层串联。

四 · 错误注入的强度标定：可检出与不可检出的边界

错误注入的目的是让正确性 oracle 有区分度，但注入强度过大会制造大量“显然错误”的样本，浪费训练信号；过小则样本全部通过，oracle 形同虚设。标定方法是：对每一类注入（边界条件、同步缺失、精度截断、索引偏移），先构造一个最小可检出的注入强度，再在其上取若干档，测量 oracle 的检出率随强度的变化曲线，取曲线拐点作为工作点。

同步缺失类注入的机制值得单列：在需要跨 block 归约的 kernel 里删掉一次 barrier，错误只在特定调度下出现，单次运行的检出概率远低于 1。因此这类样本的正确性判定必须重复运行多次并比对，重复次数 n 与单次检出概率 p 的关系是：

$$P_{\text{detect}}=1-(1-p)^n$$

要让 P_detect 达到可接受水平，n 随 p 下降而急剧上升。代价直接体现为验证时延：每条同步缺失样本要跑 n 次，n 大时单样本验证耗时是普通样本的数倍。工程判断是：对 p 极低的注入类型，不追求高检出率，而是把它标为“不稳定样本”，在训练中降权或只用于负样本池，避免把随机通过误判为正确。具体例子：一个跨 block 的 prefix-sum，删掉第二次 barrier 后，在小规模输入下由于 block 调度顺序恰好正确而通过，只有在输入规模跨过某个阈值、block 数超过 SM 驻留数时才稳定失败；这类样本的形状必须落在能暴露错误的区间，否则注入等于没注入。

五 · 测量方法：没有数字时如何建立可复现口径

凡是无法从给定事实中取得具体数值的阈值，都必须写成“测量方法 + 判据形式”，而不是留空或写定性形容词。可复现口径包含四件事：测量对象、测量工具、重复策略、报告形式。测量对象要明确到“是否含 kernel launch 开销、是否含首次调用的上下文初始化”；测量工具要区分墙钟计时器与 NCU 的硬件计数器，前者用于端到端收益，后者用于归因；重复策略要写明预热次数与取统计量的方式（中位数而非均值，因为尾延迟会污染均值）；报告形式要固定字段，使不同批次样本之间可比较。

一个具体的口径模板：对每个样本，预热若干次后连续计时，取中位数作为 t_syn；同时用 NCU 采集一次，记录 dram 吞吐与 SM 占用作为归因字段；若 t_syn 的多次测量离散度超过给定比例，则标记该样本为“测量不稳定”，不进入性能标签。离散度本身就是一个阈值，它的作用是防止把调度抖动当成 kernel 优劣。代价是采集时间：NCU 的单次采集会串行化执行并放大耗时，对大批量样本不可承受，因此归因字段只在抽样集上采集，抽样比例由样本总量与可接受的生成时延共同决定。

具体例子：判断一个合成样本是否“达到 roofline 上限”时，不能只看计时器给出的加速比，必须同时看 NCU 的 dram 吞吐是否接近理论带宽乘以 η。若计时器显示加速但 dram 吞吐远低于上限，说明瓶颈不在带宽而在别处（占用率、指令依赖），此时该样本的性能标签应写成“受限于非带宽因素”，而不是“达到上限”。这条判据把“没有数字”转化成了“有测量路径”，使阈值在换卡、换形状后仍可重建。

六 · 阈值与分布的联动：把经验数字写进生成器

阈值最终要落进生成器的采样逻辑，而不是停留在文档里。联动方式是：生成器为每个样本计算前述的 d、k、S、U 与离散度，然后按目标分布做拒绝采样——落在阈值边界附近的样本被保留并标记为“边界样本”，明显越界的样本被丢弃或改写。拒绝采样的代价是生成吞吐下降，丢弃率越高，单位有效样本的生成时延越大；因此阈值不能设得过紧，否则生成器大部分时间在做无效计算。

工程判断在于区分两类阈值：硬阈值用于正确性（语义守恒、搬运字节下限、输出指纹），越界即判错，不参与采样；软阈值用于性能与难度（S 区间、d 分层、离散度上限），越界只影响权重与标记。硬阈值不可协商，软阈值随目标分布调整。具体例子：一个样本的 B_syn 小于语义所需的最小搬运量，这是硬阈值越界，无论计时多快都判为错误实现；而一个样本的 S 落在区间外但 B_syn 合法，则只降权，仍可作为负样本或边界样本进入训练。把这两类阈值混在一起，是合成数据污染训练信号最常见的方式。

阈值不是拍脑袋：污染判定、难度分档与形状扰动的可测边界

合成管线里每个“经验数字”都必须绑定一个测量口径，否则它在换基准、换模型、换 tokenizer 之后立刻失效。以污染检测为例，常见做法是对合成样本与基准测试集做 n-gram 重叠判定，阈值写成“最长公共子串长度 L 与重叠比例 r 同时超过给定值即判污染”。这个判定的代价是双向的：L 取小会把合法的相似算子结构误杀，L 取大会漏掉改写型泄漏。工程上应把 L 与 r 做成二维网格，在已知的干净样本集与人工注入的泄漏样本集上各跑一遍，取“误杀率不超过可接受上限”前提下的最小 L，而不是直接沿用别处的常数。测量方法是构造注入集：把基准题面按同义改写、变量重命名、注释增删三种方式各生成一批，看判定器能否全部捕获；再把参考实现附近的合法变体作为负样本，看误杀。这一步的 token 成本远低于后续训练，却决定了整个数据集的可用比例。

难度分档同样需要可测锚点。把样本按“参考实现的算子数量、张量维数、是否含规约或转置、形状是否非常规”打分，得到离散档位，再要求各档比例落在预设区间内。失效条件是打分函数与真实求解难度脱钩：模型在低档位上通过率饱和、在高档位上全灭，此时分布再“均匀”也没有梯度信号。判定办法是用小规模 rollout 估计每档的通过率 pk，把有效样本量按 pk(1−pk) 加权，若某档的加权贡献低于总贡献的给定份额，就判定该档失效并回退重采样。这里的代价是 rollout 的时延与显存占用，通常只能抽样估计，因此阈值要留出置信区间余量。

$$\text{有效样本量}\;N_{\text{eff}}=\sum_{k} n_k\, p_k (1-p_k),\qquad \text{档位失效判据：}\ \frac{n_k p_k(1-p_k)}{N_{\text{eff}}}<\tau$$

形状扰动是最容易被经验数字反噬的一环。扰动幅度过大，合成样本落入参考实现未覆盖的边界（如非对齐维度、零长度、极端广播），正确性 oracle 本身先失效；幅度过小，样本与基准形状几乎同构，泄漏风险回升。可操作的做法是把扰动参数化为相对基准形状的倍率区间与维度置换集合，并记录每个样本实际触发的分支。测量上，用参考实现与合成样本在同一输入上的输出差异作为 oracle，差异必须为零；一旦非零，先怀疑扰动越界而非模型错误。系统代价体现在编译与验证时间：形状每变化一次就要重新实例化并编译 kernel，编译时间随变体数量线性增长，因此扰动集合应按“覆盖新分支”而非“数量多”来选取，用分支覆盖率作为停止准则。
