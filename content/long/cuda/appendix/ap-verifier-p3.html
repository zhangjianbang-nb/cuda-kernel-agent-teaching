一 · 容差阈值：把“差不多对”翻译成可判定的数

数值容差是验证器里唯一必须由人拍板的量，因为浮点 kernel 的正确性本质上是“在某个误差预算内与参考实现一致”。工程上把阈值拆成三层：逐元素绝对容差 atol、相对容差 rtol、以及聚合范数容差。逐元素判据写成

$$|y_i - \hat{y}_i| \le \mathrm{atol} + \mathrm{rtol}\cdot|\hat{y}_i|$$

其中 y 是被测 kernel 输出，ŷ 是 oracle 输出。这个式子的关键在于右端随参考值缩放：对接近零的元素，判据退化为绝对容差；对大幅值元素，判据退化为相对容差。若只写 atol，大动态范围张量（例如 attention logits 或归一化前的中间量）会立刻误报；若只写 rtol，则参考值恰为零的位置上任何微小非零输出都判失败，而这类位置在 ReLU、mask、稀疏注意力里极常见。因此验证器必须同时携带两个数，并且对 ŷ=0 显式走绝对分支。

阈值的取值来源只能是 dtype 的机器精度量级，而不是拍脑袋。fp32 的 unit roundoff 约为 2^-24，fp16 约为 2^-11，bf16 约为 2^-8。一个归约长度 N 的 kernel，其误差累积随 √N（随机舍入）或 N（最坏情况）增长，所以经验做法是把 rtol 设为 k·u·√N，k 取个位数。代价是：rtol 每放松一个数量级，漏检的“真实 bug”就多一类——例如把 fp16 的 rtol 放到 1e-2，一个把累加器从 fp32 降成 fp16 的实现会被判为通过，而它在长序列上确实丢精度。反过来，把 fp32 的 rtol 压到 1e-7 以下，任何改变求和顺序的合法优化（分块归约、warp shuffle）都会误报。测量方法很直接：用同一 kernel 的两种合法实现（例如串行参考与分块实现）互比，取误差分布的 p99.9 再乘一个安全系数，得到的就是“合法实现差异”的上界；再把一个故意注入 bug 的版本拿来比，确认它落在这个上界之外。这两个分布之间的间隔，就是阈值的可用区间。

聚合容差用于“整体趋势对但个别元素崩”的场景，常用相对 Frobenius 误差 ‖y-ŷ‖_F / ‖ŷ‖_F。它的代价是掩盖局部错误：一个只在少数通道上溢出的 kernel，Frobenius 误差可能仍然很小。因此工程判断是：逐元素判据为主判据，聚合判据只作为诊断指标输出，不参与 pass/fail。具体例子：一个 softmax kernel 在 fp16 下，若分母归约用 fp16 累加，最大元素附近的相对误差会明显高于 √N·u 量级，逐元素判据能抓住它，而 Frobenius 判据会因为大部分元素仍然准确而放行。

二 · 随机与边界输入：种子、分布与覆盖率的量化

随机输入的作用不是“随便测测”，而是提供一个可复现的、能覆盖数值区间的采样。验证器必须固定种子并把种子写进失败报告，否则同一个 bug 无法复现。分布选择直接决定漏检率：均匀分布 U(-1,1) 会让所有元素落在容差判据的“舒适区”，几乎测不出累加器精度问题；对数均匀分布（跨若干数量级）才能触发大幅值与小值混合的舍入路径。工程上常用的组合是：一组标准正态、一组对数均匀跨 1e-3 到 1e3、一组含大量零与正负号的稀疏模式。

边界输入是漏检率最高的地方，必须枚举而非随机。清单至少包括：N=0（空张量）、N=1、N 恰为 tile 大小、N 为 tile 大小加一、N 为 warp 宽度的非整数倍、以及 N 超过单块共享内存容量需要多块协作的规模。这些点对应 kernel 里的尾块处理、mask 分支、循环边界，是 off-by-one 与越界读写的高发区。代价是测试用例数随时延线性增长：每个边界点都要一次完整的 launch 加一次 D2H 拷贝，若单次验证往返在毫秒级，几十个边界点就是几十毫秒的固定开销，相对于 kernel 本身的微秒级执行时间，验证成本被放大了两三个数量级。因此边界集合要精选，不能穷举所有 N。

形状与 stride 覆盖是另一条独立轴。一个 kernel 在连续张量上正确，不代表在转置视图、切片视图、带 padding 的视图上正确。验证器应显式构造非连续 stride：例如行 stride 大于列数、列 stride 大于 1、以及广播维度。判据是输出与 oracle 在逻辑索引上逐元素一致，而不是在内存线性序上一致。漏检风险在于：很多 kernel 用线性索引推导多维坐标，一旦 stride 非连续，索引映射就错，但连续输入下永远测不出来。测量方法是把 stride 组合做成笛卡尔积的小集合（连续、转置、带 padding 三种），每个形状跑一遍，记录哪些组合失败。

三 · NaN/Inf 处理：三种语义必须显式声明

NaN 与 Inf 不是“异常”，而是 IEEE 语义的一部分，验证器必须明确 kernel 应采用哪一种：传播（propagate）、屏蔽（mask）、还是钳制（clamp）。三种语义对应完全不同的判据。传播语义下，任一输入为 NaN 则输出为 NaN，判据是 isnan(y_i) == isnan(ŷ_i) 且对非 NaN 位置用常规容差；屏蔽语义下（例如 attention 的 mask、归一化的除零保护），NaN 输入被替换为某个中性值，判据要求输出有限且等于替换后的参考结果；钳制语义下（例如 inf 参与比较后被截断），判据要求输出落在预设边界内。

关键陷阱是：常规容差判据在遇到 NaN 时恒为假，因为任何与 NaN 的比较都返回 false。若验证器不显式分支，一个正确传播 NaN 的 kernel 会被判失败，而一个把 NaN 悄悄替换成 0 的错误 kernel 反而通过。因此判据必须先做 NaN/Inf 分类，再在同类元素上做数值比对。伪代码思路是：对每个元素先判 isnan/isinf 是否与参考一致，一致则跳过数值比较，不一致直接失败；仅当两者都有限时才进入容差公式。

代价体现在覆盖率上：NaN 输入会让整个下游计算失效，因此含 NaN 的用例通常只验证“该 NaN 的位置是否 NaN”，无法同时验证数值精度，等于牺牲了这批用例的数值覆盖。工程判断是把 NaN/Inf 用例单独成组，与数值精度用例分开统计通过率，避免一组失败污染另一组的信号。具体例子：一个 layer-norm kernel 在方差为零时产生 0/0，正确实现应输出零或按 eps 保护，错误实现输出 NaN；只有显式声明屏蔽语义并构造全等值输入，才能区分这两者。

四 · 确定性复跑：从“两次一样”到可判定的位级稳定

确定性验证回答的是：同一输入、同一 kernel、同一设备，两次运行是否产生位级相同的输出。这对 agent 生成的 kernel 尤其重要，因为非确定性往往来自未初始化共享内存、竞态条件下的原子累加顺序、以及依赖线程调度顺序的归约。判据是逐位比较（memcmp 级别），而不是容差比较——容差比较会把“每次略有不同”当成合法噪声放过去。

测量方法是固定种子、固定输入、连续 launch 若干次（工程上取一个能覆盖调度抖动的次数，例如数十次），对每次输出做哈希并比对。若哈希不一致，进一步定位是哪些元素在变，通常能直接指向未初始化区域或原子操作的顺序依赖。代价是时延成倍增加：k 次复跑就是 k 倍执行加 k 次 D2H 拷贝，若单次拷贝是主要开销，复跑次数就是验证吞吐的直接分母。因此复跑只对“疑似非确定”的 kernel 开启，或作为抽样检查，而不是每个用例都跑。

需要区分两类非确定性：一类是合法但不可复现的（例如并行归约的浮点加法顺序随调度变化，结果在容差内波动），另一类是真 bug（读到未初始化内存）。前者用容差判据即可，后者必须用位级判据。工程判断是：先跑容差判据确认数值正确，再对同一输入跑位级复跑；若位级不一致但容差内一致，标记为“非确定但数值可接受”，并记录波动幅度；若位级不一致且超出容差，直接判失败。具体例子：一个用 atomicAdd 累加的直方图 kernel，每次运行的加法顺序不同，fp32 下低位会有差异，位级判据必然失败，但容差判据通过——这类 kernel 的正确性判据应显式改为容差加“多次运行的极差上界”。

五 · 形式化与差分 oracle：适用边界与漏检结构

形式化验证（SMT 求解）适用于小规模、整数或位精确语义的 kernel 片段：索引映射、边界条件、mask 逻辑、以及定点运算。它的判据是“对所有满足前置条件的输入，输出满足后置条件”，由求解器给出证明或反例。代价是状态空间爆炸：一旦引入浮点或大规模数组，求解时间不可控，且浮点 SMT 的语义建模本身就可能与硬件舍入不一致。因此工程上只把 SMT 用在索引与边界这类离散逻辑上，把数值部分交给差分测试。

差分 oracle 的思路是用两个独立实现互比：一个是被测 kernel，另一个是可信参考（框架算子、CPU 实现、或另一种算法）。它的漏检结构是“共模错误”：若两个实现共享同一个错误假设（例如同样的索引公式、同样的 eps 取值），互比无法发现。降低共模风险的方法是让参考实现走完全不同的代码路径（例如 CPU 串行 vs GPU 分块），并至少在一个维度上使用不同的数值策略（例如参考用 fp64 累加）。代价是参考实现本身的运行时间可能远高于被测 kernel，尤其在 CPU 上跑大张量时，差分测试的瓶颈从 GPU 转移到主机侧。

具体例子：一个转置加归约的融合 kernel，SMT 可以证明其索引映射在给定 stride 下不越界，但无法证明归约的数值精度；差分 oracle 用 CPU fp64 实现做参考，能抓住 fp32 累加的精度损失，但如果被测 kernel 和参考都用了同一个错误的 mask 条件，两者会同时错，互比通过。因此清单要求：形式化覆盖离散逻辑，差分覆盖数值路径，两者不可互相替代；且差分参考必须显式声明其数值策略，否则“通过”只说明两个实现一致，不说明它们正确。

阈值不是拍脑袋：把容差、样本量与复跑次数写成可测量的判据

数值容差的工程判据应当由误差预算反推，而不是沿用框架默认值。对累加型 kernel（reduction、matmul），浮点误差随归约长度增长，可用 |ŷ−y| ≤ atol + rtol·|y| 的混合判据，并令 atol 与 rtol 随 K 维规模缩放：

$$\mathrm{atol}(K)=\mathrm{atol}_0\cdot\sqrt{K},\qquad \mathrm{rtol}(K)=\mathrm{rtol}_0\cdot\log_2 K$$
其中 atol₀、rtol₀ 由参考实现（FP64 或高精度累加）在同一输入上的实测误差分布定标，取该分布的高分位而非均值——均值会被大量“恰好正确”的样本拉低，导致边界样本漏检。代价是判据越松，漏检的静默错误越多；判据越紧，合法实现的指令重排与 FMA 收缩会被误判为失败，形成假阳性，直接污染 RL 的可验证奖励信号。

随机与边界输入的样本量需要与漏检概率挂钩。若单次随机测试漏检某类缺陷的概率为 p，独立复跑 n 次后的漏检率为 (1−p)ⁿ，因此要压到目标漏检率 ε 以下需 n ≥ ln ε / ln(1−p)。工程上更有效的做法是分层采样：形状维度覆盖奇数长度、非 2 的幂、跨 stride 的非连续视图、单元素与空张量；数值维度注入次正规数、接近溢出的量级、以及 NaN/Inf 的传播路径。NaN 处理必须显式约定——是“任一 NaN 即失败”，还是“NaN 位置需与参考一致”，后者要求逐元素掩码比对，代价是额外一次全量掩码写回与比较，显存带宽翻倍。

确定性复跑的次数同样是可测量量：对同一输入执行 m 次并做逐位哈希比对，m 取到首次出现不一致即停，可快速暴露原子累加顺序、未初始化共享内存、竞态导致的非确定输出；代价是 m 倍执行时延，且对本身合法的非确定性算法（如并行归约的浮点顺序）会给出假阳性，需与容差判据分层使用。形式化 SMT 验证只在小形状、整数或定点语义下可解，浮点理论求解在规模稍大时即超时，因此它适合作为边界形状的补充 oracle，而非全量替代；差分 oracle 则以第二个独立实现为参照，其自身缺陷会与待测实现共谋，必须用不同算法路径（如不同分块策略）构造，代价是维护两套实现与双倍显存。
