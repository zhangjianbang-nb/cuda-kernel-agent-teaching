一 · 条目边界：多轮 RL 可验证奖励配方到底指什么

本条目描述的对象不是某个算法族，也不是某个 benchmark，而是一份可执行的多轮强化学习配方：它把「采样 rollout → 构造编译/运行反馈 → 奖励塑形 → 策略更新约束 → 难度调度 → 作弊监控」这六个环节的超参与工程代价写成可复现的配置面。判据只有一条：给定同一初始策略、同一 kernel 任务分布、同一验证器，按配方执行能得到可比较的奖励曲线与正确率曲线。凡是不进入这条闭环的东西——例如只做单轮 SFT 的数据配方、只做推理时搜索的 best-of-n、只做静态代码生成的 prompt 工程——都不在本条目范围内。

「多轮」在这里有严格所指：同一任务实例上，策略至少被调用两次，且第二次及以后的输入包含第一次的执行反馈（编译错误、运行时报错、正确性比对结果、profile 摘要）。这区别于「多次独立采样后取最优」的并行采样：后者轮与轮之间无信息传递，梯度上等价于单轮高方差估计。多轮的价值在于把反馈作为状态纳入轨迹，使优势估计覆盖「修正行为」而非仅覆盖「首次命中」。

「可验证奖励」指奖励的主体部分由程序化 oracle 给出，而非人类偏好或奖励模型打分。oracle 至少包含两层：正确性门控（对拍参考实现，逐元素或按容差比对）与性能度量（相对基线的加速比或达到 roofline 的比例）。二者串联而非加权求和，这是本条目与「RLHF 式标量奖励」的关键分野——后者允许用性能换正确性，前者不允许。

「配方」强调超参的可迁移性：学习率、KL 系数、rollout 组大小、课程切分阈值、奖励裁剪上下界，这些量必须与任务难度分布绑定描述，否则换一批 kernel 就失效。因此条目正文里每个超参都附带其工程代价口径（时延、显存、编译时间、token 消耗），而不是只给数值。

二 · 分类维度：四个正交切面

把现有配方按四个切面拆开，可以避免把不同层次的选择混为一谈。四个切面彼此正交，任意组合都对应一类具体工程形态。

切面 A：反馈构造的深度。最浅一档只回传编译成败与错误文本；中间档回传运行期断言与正确性差异摘要（例如最大绝对误差、首个失配索引）；最深一档额外回传 NCU/SASS 层面的瓶颈标签（如「访存受限」「occupancy 不足」）作为自然语言或结构化 token。深度越深，单轮 token 成本越高，但修正命中率提升；代价是反馈本身可能引入误导，需要监控「反馈-修正」一致性。

切面 B：奖励塑形的形状。门控式（正确性不过则奖励为固定负值，过了才计性能分）、归一化加速比式（以基线时延为分母做裁剪）、分段式（按达到 roofline 百分比给阶梯分）。三者对 reward hacking 的抵抗力不同：门控式最抗「输出垃圾但碰巧通过弱验证器」，归一化式最抗「只优化某一形状的输入」，分段式最容易诱导策略卡在阶梯边界。

切面 C：轮数与预算分配。固定轮数（每任务恒为 N 轮）与自适应轮数（连续 K 轮无正确性提升则提前终止）。自适应节省 token，但引入轨迹长度与难度的相关性，优势估计必须做长度归一，否则长轨迹任务被系统性低估。

切面 D：课程调度信号。按通过率调度（滑动窗口正确率落在区间内才保留该难度）、按编译失败率调度、按性能分布方差调度。通过率调度最常用，但它对「全对」和「全错」两种极端都无信息量，需要配合重采样。

切面取值主要工程代价典型风险
A 反馈深度编译 / 运行 / profiletoken 线性增长，profile 采集使单轮时延显著上升反馈误导导致错误修正
B 奖励形状门控 / 归一 / 分段归一化需缓存基线时延，显存与 IO 开销阶梯边界吸附
C 轮数固定 / 自适应自适应省 token 但需长度归一难度-长度混杂
D 课程信号通过率 / 编译率 / 方差滑动窗口统计需额外状态极端难度无梯度

举例：一个「编译反馈 + 门控奖励 + 固定 4 轮 + 通过率课程」的组合，与「profile 反馈 + 归一化奖励 + 自适应轮数 + 方差课程」的组合，在同样任务集上的 token 消耗与收敛形态完全不同，前者适合冷启动阶段，后者适合已具备基本正确率的策略。分类的意义就在于让这种选择显式化，而不是把所有配方笼统称为「多轮 RL」。

三 · 与相邻概念的三条分界线

与执行反馈微调（execution-feedback SFT）的区别在梯度来源。SFT 把「错误代码 + 反馈 + 正确代码」三元组当作监督信号，损失是 token 级交叉熵，反馈只影响输入分布；多轮 RL 中反馈进入状态转移，损失是策略梯度，反馈影响的是优势而非标签。工程后果是：SFT 可以用离线数据反复训练、成本可控；RL 必须在线采样，rollout 的编译与运行是主要时延来源，且采样分布随策略漂移，缓存命中率下降。

与 best-of-n 推理时搜索的区别在参数是否更新。best-of-n 用验证器在推理端筛选，验证器质量直接决定收益上限，但不改变策略；多轮 RL 把验证器作为奖励源写进目标函数，策略会主动向验证器偏好的区域移动。这带来一个特有风险：验证器与真实正确性之间的缝隙会被策略放大（reward hacking），因此配方必须包含监控项，而 best-of-n 只需要离线校准验证器。

与课程学习（curriculum learning）的区别在信号来源。经典课程学习按预设难度序列喂数据，难度是静态标签；本条目中的课程由在线通过率驱动，难度是策略当前能力的函数，因此课程分布随训练漂移。代价是难度统计本身要占工程预算：滑动窗口、重采样、去重都要在 rollout 调度器里实现，且窗口长度是一个需要调的超参。

$$ r = \mathbb{1}[\text{pass}] \cdot \min\left(\frac{t_{\text{base}}}{t_{\text{cand}}},\ c\right) - \beta\, \mathrm{KL}(\pi_\theta \,\|\, \pi_{\text{ref}}) $$

上式是本条目奖励塑形的规范形：门控项在前，加速比裁剪在后，KL 作为独立惩罚项而非混入奖励。裁剪上界 c 防止「极端快但数值不稳定」的实现拿到爆炸性奖励；KL 系数 β 的作用是限制策略偏离参考策略的幅度，代价是 β 过大时正确率提升被压制、β 过小则反馈利用不足导致输出分布坍缩到少数模板。工程上 β 与 rollout 组大小耦合：组越大，组内基线估计越稳，β 可以相应放松。

具体例子：若某任务基线时延为 t_base，候选实现通过正确性门控且时延为 t_base/3，裁剪上界取 4，则性能项为 3；若候选实现时延为 t_base/10，性能项被截到 4，多出的 6 倍加速不进入梯度。这一裁剪的代价是放弃了对「超预期优化」的奖励信号，收益是抑制策略为追求时延而牺牲数值稳定性的倾向。

四 · 超参的工程代价口径

配方中的每个超参都应绑定一个代价口径，否则无法在算力预算内做取舍。以下按环节列出，数值只给结构性关系，不虚构实验数据。

  • rollout 组大小 G：组内采样用于估计相对优势。G 增大使优势方差按 1/G 下降，但采样时延线性增长，且显存中同时驻留的轨迹数上升。G 的选取受单卡可容纳的并发编译/运行进程数约束——编译是 CPU 与 IO 密集型，运行是 GPU 密集型，两者瓶颈不同，G 往往由编译队列长度而非 GPU 决定。
  • KL 系数 β：每步更新需计算参考策略对数概率，若参考策略与当前策略共享主干则显存开销小，若独立部署则显存翻倍。β 的调参代价是每改一次都要重跑一段训练观察正确率曲线，属于低频高成本超参。
  • 课程窗口长度 W：通过率估计的滑动窗口。W 过短则难度抖动、任务分布不稳定；W 过长则对策略能力变化反应迟钝，出现「难度停滞」。W 的代价是调度器需维护每任务的历史通过记录，状态存储随任务数线性增长。
  • 轮数上限 N 与提前终止阈值 K：N 决定最坏情况 token 成本，K 决定平均成本。自适应终止节省的 token 与漏掉的「慢热修正」机会是一对权衡；K 过大等于退化为固定轮数。
  • 奖励裁剪上界 c：不增加计算成本，但改变梯度尺度，与学习率耦合。c 调小等价于全局降低性能项权重，需同步检查正确性门控是否仍占主导。

把这些量放在一张表里做预算：token 成本主要由「轮数 × 每轮反馈 token 数 × 组大小」决定；时延成本主要由「编译队列 + 运行 + profile 采集」决定；显存成本主要由「并发轨迹数 + 参考策略副本」决定。三者不是独立可调的——增大 G 同时抬高时延与显存，加深反馈同时抬高 token 与时延。配方的工程价值就在于把这些耦合写清楚，让读者知道改一个超参要付哪几笔账。

五 · reward hacking 监控作为配方的一等公民

本条目把监控项写进配方定义，而不是当作事后补丁。理由是可验证奖励的「可验证」只对验证器成立，对真实工程目标不成立：验证器覆盖不到的输入形状、边界条件、数值容差，都是策略可以钻的缝隙。监控项至少包含三类信号。

第一类是门控通过率与性能分的相关性。正常训练中二者应正相关（正确实现才有资格谈性能）；若出现「性能分高但通过率低」的轨迹占比上升，说明策略在试探门控边界，需要收紧容差或增加对拍样本。第二类是输出多样性，用轨迹间编辑距离或模板命中率度量；多样性骤降往往先于正确率平台期出现，是分布坍缩的早期信号。第三类是反馈利用率，即「第二轮相对第一轮的正确性提升幅度」；若多轮反馈带来的提升趋近于零，说明反馈构造已无信息量，继续加轮数只是烧 token。

监控的工程代价是额外的评估前向：每条轨迹要多跑一次验证器（通常已在奖励计算中完成，边际成本低），但多样性度量需要保存轨迹文本或摘要，存储开销随组大小与轮数增长。工程判断是：监控频率可以低于训练步频，但监控项本身不能省——省掉监控的配方在报告里无法区分「策略变强」与「策略学会骗验证器」。

具体例子：若某配方发现第二轮之后正确率不再提升，而性能分持续上升，同时输出模板命中率上升，三条信号合并指向「策略在复用少数通过门控的模板并微调参数以刷性能分」。处置手段不是调学习率，而是提高对拍样本的输入分布覆盖度并收紧容差，这属于配方层面的修改，而非训练技巧。

六 · 配方的可复现性判据

最后落到一个工程判断：一份配方是否合格，取决于它能否被另一团队在不同任务分布上复现出同方向的结论，而不是复现出同一组数字。因此条目要求每个超参附带三样东西：取值、绑定条件（任务难度区间、基线时延口径、验证器容差）、代价口径。缺任一项，超参就退化为不可迁移的魔法数。

可复现性的最小检查清单是：rollout 组大小与并发编译容量的关系是否写明；KL 参考策略是共享主干还是独立副本是否写明；课程窗口的通过率区间是否写明；奖励裁剪上界与学习率的耦合是否写明；监控项的频率与阈值是否写明。这五项写不清，配方在换任务集后必然需要重新盲调，而盲调的算力成本往往高于配方本身的训练成本。

由此得到本条目与相邻条目的分工：术语表负责定义词汇，基准速查负责任务分布，指标口径负责度量，而本条目负责把这些词汇、分布与度量组装成一条带代价标注的训练闭环。闭环的每个环节都可单独替换（换验证器、换反馈深度、换课程信号），但替换时必须重新核对代价口径，因为环节之间通过 token、时延、显存三条预算线耦合。
