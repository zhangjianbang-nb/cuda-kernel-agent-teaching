一 · 样本来源字段：四类合成入口的登记口径

速查表的第一层是“这条样本从哪来”。字段名固定为 source_kind，取值只有四个枚举：ref_impl（参考实现改写）、op_compose（算子组合）、shape_perturb（形状扰动）、error_inject（错误注入）。每个枚举背后对应不同的登记义务，不能混填。

ref_impl 必须同时登记 upstream_id（上游仓库/文件标识）与 license_class（许可类别），因为改写自参考实现的样本是污染检测的高危对象——它天然与基准测试集同源。口径是：凡 ref_impl 样本，进入训练池前必须过一遍与基准集的去重，且去重结果字段 dedup_verdict 必须为 clean 才可放行。op_compose 需登记 compose_graph（算子组合的拓扑描述，如“reduce→broadcast→elementwise”链）与 fusion_depth（融合层数），后者直接决定难度档。shape_perturb 需登记 base_shape 与 perturb_axis（扰动维度：batch、seq、hidden、head 数等），并记录扰动倍率区间。error_inject 需登记 error_class（越界、竞态、同步缺失、精度截断、mask 错位等）与 inject_site（注入位置：索引计算、共享内存写、归约初值等）。

代价在这里体现为 token 与编译时间：op_compose 的融合层数每加一层，生成侧需要多产出一次中间张量的形状推导与边界条件描述，单样本 token 消耗上升，且候选 kernel 的编译时间随模板实例化数量线性增长；error_inject 样本则要求同时保留“错误版本”与“修复版本”两份代码，显存与存储开销翻倍，但正确性 oracle 的判别力最强。具体例子：一条 op_compose 样本登记为 fusion_depth=3、compose_graph="softmax→matmul→layernorm"，其难度档自动落到中高档，且必须携带至少一个非方阵形状以触发边界分支。

二 · 难度分布字段：分档阈值与配比口径

难度不能靠感觉标注，必须由可计算字段推导。速查表规定三个原始量：op_count（涉及的不同算子数）、fusion_depth、shape_regime（形状档：small/medium/large/irregular）。由这三者合成 difficulty_tier，取值 D1–D4。判定规则写成伪代码思路如下：

$$ \text{tier} = \begin{cases} D1 & \text{op\_count}=1 \land \text{fusion\_depth}=0 \land \text{shape\_regime}\in\{\text{small},\text{medium}\}\\ D2 & \text{op\_count}\le 2 \land \text{fusion\_depth}\le 1\\ D3 & \text{fusion\_depth}\in[2,3] \lor \text{shape\_regime}=\text{irregular}\\ D4 & \text{fusion\_depth}\ge 4 \lor (\text{op\_count}\ge 3 \land \text{shape\_regime}=\text{irregular}) \end{cases} $$

配比口径是速查表最容易被忽略的一栏：训练池的难度分布必须显式声明目标配比 target_mix，并记录实际配比 actual_mix 与偏差 mix_delta。口径要求 mix_delta 的绝对值对每一档不超过一个固定阈值（按百分点计），超出即触发重采样。原因是难度分布偏移会直接改变 RL 奖励的梯度结构：D1 样本过多会让策略退化为模板匹配，D4 样本过多则会让可验证奖励长期为零、优势估计塌缩。

代价是采样时延：为凑齐目标配比，生成侧需要按档位做拒绝采样，D4 样本的接受率天然低（因为融合深、形状不规则，候选 kernel 更容易编译失败或正确性不过），导致单位有效样本的生成时延显著高于 D1。具体例子：某批次 actual_mix 显示 D4 占比低于目标，mix_delta 越界，系统回退到 shape_perturb 入口，用 irregular 形状档把一批 D2 样本重标为 D3，而不是硬造融合链——这是一条明确的工程取舍：改形状比改拓扑便宜。

三 · 泄漏与污染字段：去重判定与阈值

泄漏风险字段分三组：bench_overlap（与基准测试集的直接重叠）、family_overlap（算子家族重叠）、text_overlap（自然语言描述重叠）。三组各有独立判定口径，不能合并成一个布尔值。

bench_overlap 的判定用结构化指纹：对候选样本与基准样本各自抽取 (op_set, shape_signature, dtype_set) 三元组，做精确匹配；命中即 bench_overlap=hit，该样本禁止进入训练池，且要写入污染日志。family_overlap 用算子集合的 Jaccard 相似度：

$$ J(A,B)=\frac{|A\cap B|}{|A\cup B|} $$

其中 A、B 分别为样本与基准条目的算子集合。口径是设一个相似度阈值，超过阈值记为 family_overlap=high，此时样本不直接丢弃，而是降级为“仅可用于难度校准、不进入奖励计算”的隔离池——因为同家族不同形状的样本对能力迁移仍有价值，但对评测可信度是威胁。text_overlap 用描述文本的 n-gram 重合率，阈值更严，因为自然语言描述一旦高度相似，模型可能记住的是题面而非解法。

代价是检测本身的算力与存储：结构化指纹匹配是常数级，但 text_overlap 需要对全量样本做两两比对或建索引，样本量上升时索引内存与查询时延成为瓶颈。工程判断是分层执行——先用 bench_overlap 精确匹配做粗筛（便宜、必做），再对通过粗筛的样本做 family_overlap 与 text_overlap（贵、按批抽样全检）。具体例子：一条 ref_impl 样本的 op_set 与某基准条目完全一致但 shape_signature 不同，bench_overlap 判为 clean，但 family_overlap 的 J 值越过阈值，于是被投入隔离池，只参与难度分布校准，不参与可验证奖励。

四 · 正确性 oracle 字段：验证强度分级

每条样本必须绑定一个 oracle_kind，取值 exact（逐元素精确比对）、tolerance（带容差比对）、property（性质断言，如单调性、守恒性、mask 覆盖完整性）、crash_only（仅要求不崩溃、不越界）。四级强度递减，登记时必须与 dtype_set 联合声明，因为浮点 dtype 决定了 exact 是否可行。

tolerance 的口径要写清三件事：参考值来源（CPU 参考实现还是高精度 GPU 实现）、容差形式（绝对、相对、还是 ULP 距离）、以及归约类算子的累加顺序敏感性处理。对归约算子，逐元素容差比对本身不可靠，口径要求改用性质断言：检查总和守恒或分段和一致，而不是逐元素相等。property 的伪代码思路是：对输出张量施加一组不变量检查，任一失败即判负；这类 oracle 的判别力弱于 tolerance，但能覆盖 error_inject 中“结果看似合理但语义错位”的样本。

代价是验证时延与显存：exact 需要把参考输出完整驻留并与候选输出逐元素比对，显存占用是输出张量的两倍；tolerance 需要高精度参考，参考实现的运行时间可能远超候选 kernel 本身，成为验证流水线的时延主项；crash_only 最便宜但几乎不提供梯度信号，只适合做前置过滤。具体例子：一条 error_inject 样本注入的是“归约初值错误”，逐元素比对会因累加顺序差异产生大量假阳性，正确做法是登记 oracle_kind=property 并断言总和守恒，从而把真正的语义错误与浮点噪声区分开。

五 · 元数据与版本字段：可追溯性的最小集

速查表要求每条样本携带一组不可省略的元数据，否则样本不可复现、不可审计。最小集包括：sample_id（全局唯一）、gen_pipeline_ver（生成流水线版本）、gen_params（关键生成参数，如扰动倍率、融合深度上限）、parent_ids（若由已有样本变异而来，记录父样本）、created_stage（生成阶段标识）、review_state（人工/自动复核状态）。

口径上最容易被违反的是 gen_pipeline_ver 与 gen_params 的绑定：只记版本不记参数，等于无法重放；只记参数不记版本，等于无法判断参数语义是否已变。工程上要求二者成对写入，且 parent_ids 形成有向无环的变异链，任何一条样本都能回溯到最初的 ref_impl 或 op_compose 根节点。这条链是污染检测的第二道防线：当某个根节点后来被判定与基准集重叠，其全部后代可通过 parent_ids 批量隔离，而不必重跑全量去重。

代价是存储与写入时延：变异链的元数据随代数增长而膨胀，深链样本的元数据体积可能超过代码本体；写入时延在批量生成时成为吞吐瓶颈。工程判断是对 parent_ids 做截断存储（只保留最近若干代与根节点），牺牲部分中间追溯能力换取写入吞吐。具体例子：一条经三次 shape_perturb 变异的样本，其 parent_ids 记录根节点与直接父节点，中间代折叠；当根节点被标记 bench_overlap=hit 时，该样本连同同根的其他后代一并进入隔离池。

六 · 速查表本体：字段—阈值—口径三列对照

下表把前述字段压成可直接照抄的三列。左列是字段名，中列是可执行的阈值或枚举约束，右列是判定口径的一句话说明。使用方式是：生成侧按左列填，校验侧按中列判，审计侧按右列解释。

这张表的工程价值在于把“合成策略”从叙述性文档变成可校验的契约：任何一条样本进入训练池前，校验器逐行比对中列约束，任一不满足即打回生成侧。代价是校验本身的时延——全字段校验对每条样本是常数级开销，但在百万级样本批量入库时，校验吞吐会成为流水线瓶颈，因此实践中把 bench_overlap 与 oracle_kind 设为硬门禁（阻塞式），其余字段设为软门禁（异步告警）。具体例子：一条 op_compose 样本的 oracle_kind=crash_only 却登记在 D4 档，校验器判定“高难度样本不得配最低验证强度”，直接打回——这是速查表里唯一一条跨字段的交叉约束，也是防止难度与验证强度错配的最后一道闸。

速查表之外：合成样本的失效边界与系统代价

速查表给的是“照着填”的字段与阈值，但字段一旦落到流水线上，真正的风险不在填错值，而在填对值却越过了方案的适用边界。这套合成流程的隐含前提是：参考实现可执行、算子组合可枚举、形状扰动可参数化、错误注入可定位。四个前提任一崩塌，样本就从“可验证的训练信号”退化为“带噪声的标签”。最典型的失效条件是参考实现本身含未定义行为（越界读写、竞态、依赖未初始化显存），此时正确性 oracle 会把错误注入样本判成“与参考一致”，污染率沿难度分层向上扩散——高难度样本恰恰最依赖参考的可靠性。第二个失效条件是算子组合的语义不可交换：把两个各自正确的 kernel 串联，若中间张量的布局假设（stride、对齐、dtype 提升）不一致，组合样本的正确性无法由分量正确性推出，去重与污染检测也查不出来，因为它在文本层面是“新”的。第三个是形状扰动的退化区：当扰动把维度压到小于 warp 粒度或触发 bank 冲突的边界值时，性能标签的方差会盖过难度信号，样本教给模型的是测量噪声而非优化策略。

量化这套边界的代价，需要一个可计算的判据。设合成样本总数为 N，参考实现失效率为 p_ref，错误注入被 oracle 漏检的条件概率为 p_miss，则污染样本的期望数量近似为

$$E[\text{contam}] \approx N \cdot \bigl(p_{\text{ref}} + (1-p_{\text{ref}})\, p_{\text{miss}}\bigr)$$

这个式子说明两件事：参考失效率是乘性放大的主项，漏检率是次项但不可忽略；把 N 堆大并不能稀释污染，只能等比放大。工程上的应对不是提高阈值，而是把参考实现先过一遍差分测试（同一语义的两种独立写法互校），把 p_ref 压到可接受区间后再放量合成。代价是编译与执行时间：每个参考实现多跑一遍对照，合成阶段的 GPU 时延大致翻倍，且差分测试本身需要额外的显存驻留两份中间张量。

失效条件观测信号系统代价处置
参考含 UB注入样本被判“一致”污染随 N 线性增长差分预检，压 p_ref
组合语义不可交换分量正确、组合错去重失效，文本层查不出组合级 oracle 重跑
形状扰动退化性能标签方差大难度信号被噪声淹没设最小形状下界

去重与污染检测的口径同样有边界。基于文本/结构哈希的去重只能拦住“同源改写”，拦不住“语义等价但写法不同”的样本——后者要靠执行轨迹指纹（同一输入下的访存模式与输出哈希）比对，代价是每个候选样本都要真跑一次，token 与 GPU 时延同时上升。污染检测针对基准测试集时，若只做输入形状的集合交集，会漏掉“形状不同但计算图同构”的泄漏；可靠做法是把基准样本的算子图规范化后与合成样本做子图匹配，匹配成本随图规模超线性增长，通常只对高难度分层启用。一个具体例子：某合成批次里，形状扰动把 M=1024 改成 M=1008（非 2 的幂），本意是制造对齐压力，但参考实现对该形状走了标量回退路径，性能标签骤降，模型学到的是“避开非对齐”而非“处理非对齐”，这类样本必须在难度分层里单独标记，不能与常规扰动混算通过率。
