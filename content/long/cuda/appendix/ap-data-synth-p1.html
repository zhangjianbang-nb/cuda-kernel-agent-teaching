一 · 条目边界：什么算“训练数据合成”，什么不算

在 kernel agent 的语境里，“训练数据合成”指一条可复现的流水线：以参考实现（reference implementation）为种子，通过算子组合、形状扰动、错误注入三类变换，产出带有可执行验证信号的训练样本，并对难度分布与泄漏风险施加显式控制。它必须同时满足三个条件才算条目范围内的合成：其一，样本的“正确性标签”不是人工标注，而是由编译—运行—比对这条链自动产生；其二，样本与评测基准之间存在可度量、可审计的去重与污染检测记录；其三，样本的难度是分布参数（而非单点）的函数，能被调度器按需采样。缺任一条，就落到相邻条目里：只有参考实现没有变换，那是“基准速查”里的题目集合；只有变换没有验证链，那是数据增强而非合成；只有难度标签没有污染检测，那是课程学习配方。

把这条边界形式化，一条合成样本可写成四元组 S = (P, T, L, V)，其中 P 是问题陈述（含形状、dtype、语义约束），T 是参考实现及其调用契约，L 是难度标签向量，V 是验证器组合。合成的“合”字落在 V 上：没有 V 的样本在 RL 里无法产生可验证奖励，只能进 SFT 语料，而 SFT 语料不属于本条目讨论的可验证合成。这个划分直接决定了工程代价——带 V 的样本每条都要跑一次编译加运行，编译时间与执行时延是合成吞吐的硬上限；不带 V 的样本便宜但不可用于多轮 RL。读者若关心验证器本身的设计，见“正确性验证器清单”条目，此处只把它当作样本的一个字段。

一个具体例子：以 softmax 的参考实现为种子，做“沿最后一维切分 + 非连续 stride”的形状扰动，同时注入“忘记减最大值”的错误变体。前者产出正样本（参考实现可跑通、验证器判对），后者产出负样本（验证器判错并给出错误类型）。两者共享同一个 P 模板但 L 不同：正样本难度标为“内存受限 + 归约轴不规则”，负样本额外标“数值稳定性缺陷”。若不做这个标注分离，训练信号会把“形状难”和“语义错”混为一谈，agent 学到的就不是 kernel 能力而是猜题能力。

二 · 分类维度：四个正交轴，而不是一棵树

合成策略的分类不应做成互斥的树，因为一条样本可以同时是“算子组合 + 形状扰动 + 错误注入”。工程上更有用的是四个正交轴，每个轴对应一个可调参数和一种代价。

  • 种子来源轴：单算子参考实现 / 多算子融合图 / 已有 kernel 的变体。种子越复杂，P 的语义约束越难写清，验证器的误判率上升；代价是验证器开发时间与假阴性率。
  • 变换类型轴：算子组合（composition）、形状扰动（shape perturbation）、错误注入（fault injection）。组合扩大搜索空间但让 roofline 归属模糊；扰动廉价但容易退化成同一 kernel 的重复；错误注入提供负样本但要求错误类型可判定。
  • 难度控制轴：按目标分布采样 vs 按课程递进采样。前者要求难度可度量，后者要求难度可排序。代价体现在采样器的实现复杂度与分布漂移的监控成本。
  • 泄漏控制轴：与基准集的去重强度、污染检测粒度（题目级 / 子图级 / 常量级）。强度越高，可用样本越少，合成吞吐下降。

四轴之间不是独立的：错误注入轴上的样本天然带有“负标签”，若同时落在高难度区间，验证器需要区分“因难度而错”与“因注入而错”，否则奖励信号被污染。这条耦合关系是分类维度里最容易被忽略的工程约束，也是后面难度分布控制要处理的核心矛盾。

三 · 难度是可计算的量，不是主观评级

难度若靠人工打标，合成流水线就无法规模化，也无法在多轮 RL 中按需采样。可行做法是把难度定义为若干可测量分量的加权组合，每个分量都能在合成时算出或从一次 profile 中得到。一个可用的定义是：

$$L(S) = w_1 \cdot \frac{\text{FLOPs}}{\text{Peak FLOPs}} + w_2 \cdot \frac{\text{Bytes}}{\text{Peak BW}} + w_3 \cdot \text{irregularity} + w_4 \cdot \text{semantic\_depth}$$

前两项是 roofline 意义下的时间下界占比，直接给出“这个 kernel 至少要吃多少算力或带宽”；第三项刻画访存或归约轴的不规则程度（例如非连续 stride、动态长度、稀疏索引），它决定向量化与合并访存能否成立；第四项是语义深度，可用融合算子数 k 或需要跨越的同步层数代理。四项都可从 P 静态推出，不需要先跑出正确 kernel，因此难度标签可以在样本生成时即时写入，代价只是一次轻量的静态分析。

这套定义的价值在于它把“难度”与“性能上界”绑定：L 高的样本，其 SOL（speed-of-light）利用率的分母更大，agent 即便写出正确 kernel 也难拿高分，奖励曲线因此更陡。代价是 w 权重的标定需要与实测 profile 对齐，否则会出现“标签说很难、实测却很轻松”的漂移；监控这个漂移本身要消耗采样预算。具体例子：一个 LayerNorm 变体在 irregularity 上因最后一维长度非 2 的幂而升高，但 Bytes 项很小，加权后 L 中等；若权重把 w_3 调得过高，这类样本会挤占高 w_1 的 GEMM 类样本的采样配额，导致训练集偏向小算子。这就是难度分布控制必须与分类轴联动的理由。

四 · 与相邻概念的分界：增强、蒸馏、基准扩充

合成与“数据增强”的分界在验证链：增强只改变输入分布，标签沿用原样本；合成要为每个变体重建 V，因为形状或语义变了，原来的比对逻辑可能不再成立。合成与“蒸馏”的分界在信号来源：蒸馏的标签来自更大的模型或更强的 agent 的输出，合成标签来自执行反馈（编译成功、数值比对、profile 指标）。合成与“基准扩充”的分界在泄漏控制：基准扩充的目标是覆盖更多题型以衡量能力，合成训练集的目标是提升能力且必须证明与评测集不重叠，两者的去重强度要求相反。

这三条分界在工程上表现为不同的失败模式。把增强当合成，会让 agent 在形状变化后拿到错误的“正确”标签，训练出对形状不敏感的 kernel；把蒸馏当合成，会让奖励信号依赖教师模型的偏好而非可执行事实，多轮 RL 的可验证性被破坏；把基准扩充当训练集合成，会直接造成污染，评测分数虚高而生产端无收益。第三种失败最难自查，因为它不表现为训练 loss 异常，只表现为评测与线上指标的系统性背离。

一个具体例子能说明分界的实操意义：把 matmul 的 M,N,K 各扰动若干档，若只改形状而沿用原参考实现的输出比对，这是增强；若同时把 K 拉到需要分块累加、并重写验证器以容忍浮点累加顺序差异，这才是合成。后者的代价是验证器要引入相对误差阈值与累加顺序无关的判据，假阴性率随之上升，必须在样本元数据里记录阈值，否则同一批样本在不同验证器版本下标签不一致，RL 训练会出现奖励抖动。

五 · 泄漏风险的结构：题目级、子图级、常量级

泄漏控制在合成条目里不是可选项，因为合成样本的种子往往就来自公开基准的参考实现。风险分三层：题目级泄漏指合成样本与基准题目在问题陈述上高度相似；子图级泄漏指合成样本的某个融合子图与基准题目的核心计算同构；常量级泄漏指形状、dtype、常量参数与基准题目完全一致。三层的检测成本递增，题目级可用文本与签名的粗粒度比对，子图级需要计算图规范化后做同构判定，常量级要求把形状元组纳入去重键。

去重键的设计直接决定吞吐。一个可操作的键是 key = (op_set, normalized_shape, dtype, semantic_hash)，其中 semantic_hash 是对计算图做规范化（交换律重排、常量折叠）后的哈希。键越细，去重越严，可用样本越少；键越粗，常量级泄漏越容易漏网。工程判断是：对训练集用细键，对评测集用粗键加人工抽检，因为评测集的污染代价远高于训练集少几个样本。代价体现在合成吞吐上——细键要求每条样本都做图规范化，这一步的编译时间与哈希计算会成为流水线瓶颈，尤其当融合算子数 k 较大时。

污染检测还需要一个“反向”检查：不仅查合成样本是否撞上基准，还要查基准题目是否已被合成样本的变体覆盖。后者用子图同构在基准侧跑一遍，成本高但能发现“基准题目其实是某条合成样本的特例”这类隐蔽污染。具体例子：某条合成样本把 attention 的 softmax 与 matmul 融合，若基准里恰好有一道只考 softmax 的题，子图级检测会命中，此时应把该合成样本降权或移出训练集，而不是简单删除——删除会损失一个高难度正样本，降权则保留其梯度贡献但限制其采样频率。这个取舍是泄漏控制轴与难度控制轴耦合的又一体现。

六 · 元数据契约：让分类可审计

分类维度若不落到样本元数据上，就只是文档里的概念。可审计的合成流水线要求每条样本携带一份元数据契约，至少包含：种子来源标识、变换类型与参数、难度四分量及其权重版本、验证器版本与阈值、去重键与污染检测结论。这份契约的作用是让“同一批样本在不同时间、不同验证器下”仍可复现标签，也让 RL 训练在奖励抖动时能定位到是验证器版本变了还是难度权重漂移了。

契约的代价是存储与传输开销：每条样本的元数据在小规模下可忽略，但当合成集达到需要分布式采样的量级时，元数据的读写会成为数据加载的瓶颈，尤其当 semantic_hash 需要现场重算时。工程判断是把元数据与样本体分离存储，元数据用列式格式按轴索引，样本体按需拉取；这样按难度轴采样时只读元数据列，避免把整个样本体载入。具体例子：课程采样器按 L 的第四分量（语义深度）排序取批次，只需读元数据中的该列与样本 ID，样本体在训练 step 时才解码，显存占用与 IO 时延都被压到与批次大小成正比而非与全集成正比。

最后落在一条工程判断上：合成条目的准确定义不是“能生成样本”，而是“每条样本都带可复现的验证信号、可计算的难度标签、可审计的去重记录”。三者缺一，样本在 RL 里要么不可验证、要么难度不可调度、要么污染不可追溯；而这三者的实现成本分别落在编译时间、静态分析开销与图规范化开销上，正是流水线设计时最先要做的取舍。

合成样本的边界条件：何时“合成”反而制造噪声

把参考实现、算子组合、形状扰动与错误注入四类来源放在同一分类轴上时，真正的分界不是“来源”，而是可判定的正确性契约是否闭合。参考实现派生样本的契约由 PyTorch 语义给出，闭合度高；算子组合样本的契约依赖组合规则本身是否正确，一旦组合跨越了归约轴与广播语义的边界，契约就退化为“看起来对”。形状扰动样本的失效条件是扰动落入未定义行为区（如越界对齐、零长度维度、非连续 stride 下的隐式拷贝），此时参考实现与 kernel 的差异不再反映能力差距，而是反映测试脚手架自身的缺陷。错误注入样本则要求注入的错误必须可被 oracle 单点定位，否则一条样本同时携带多个缺陷，奖励信号被稀释成噪声。

$$\text{usable}(s)=\mathbb{1}\big[\text{oracle}(s)\ \text{deterministic}\big]\cdot\mathbb{1}\big[\text{dist}(s,\mathcal{B})>\tau\big]\cdot\mathbb{1}\big[\text{cost}(s)<C_{\max}\big]$$

三个因子分别对应正确性、泄漏与系统代价。泄漏项里 $\mathcal{B}$ 是基准测试集，$\text{dist}$ 可用输入张量的形状签名与常量指纹做粗筛，再用输出数值的哈希做细筛；阈值 $\tau$ 定得过松会让扰动样本与基准样本共享同一组形状，定得过紧则把合法变体误杀，样本产出率随之下降。代价项 $C_{\max}$ 是单条样本的合成与验证开销上限：错误注入需要在 CPU 端重放参考实现以定位缺陷，形状扰动可能触发参考实现的隐式同步，两者都会把单样本的墙钟时间推高一个量级，进而压缩单位时间内可生成的 token 预算。

来源主要失效条件系统代价
参考实现派生语义版本漂移低，仅需一次编译
算子组合组合规则未覆盖的轴语义中，需逐组合验证
形状扰动落入未定义行为区高，隐式同步与重编译
错误注入多缺陷叠加不可定位高，CPU 侧重放定位

具体例子：一个归约算子样本在形状扰动下把归约维度从 1024 改成 1000，参考实现走的是非对齐分支，而生成的 kernel 假定对齐，二者输出差异被记为“能力不足”，实际是扰动越界。工程判断是：形状扰动必须与参考实现的分支覆盖表联动，只扰动落在已定义分支内的维度；错误注入则限定单缺陷、单定位点，宁可牺牲样本数量也不让奖励信号模糊。
