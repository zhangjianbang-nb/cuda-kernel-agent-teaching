一 · 速查表的字段设计：为什么是这七列

一张能照着用的硬件速查表，字段选择本身就是口径声明。本表固定七列：卡型、SM 数、显存带宽、L2 容量、tensor core 代际、NVLink 拓扑、功耗墙。这七列不是硬件参数的罗列，而是 roofline 与 SOL 计算中每一个分母的唯一来源：SM 数决定算力上界与占用率分母，显存带宽决定带宽屋顶斜率，L2 容量决定分块（tiling）可行域与复用半径，tensor core 代际决定 MMA 指令形状与吞吐档位，NVLink 拓扑决定多卡切分策略的通信项，功耗墙决定持续频率与降频后的有效算力。任何一次 SOL 计算，若这七列中有任一列取值来源不明，结论就不可信。

字段的口径必须写死到“取哪一个数”。SM 数以产品规格的物理 SM 数为准，不以驱动上报的可用 SM 数为准——后者会因 MIG 切分、ECC 保留或故障屏蔽而偏小，用它做占用率分母会系统性高估每 SM 负载。显存带宽取理论峰值（总线位宽 × 有效速率），不取实测 STREAM 值；roofline 的分母是理论上界，实测值属于“可达比例”这一独立指标，两者混用会让 SOL 百分比失去意义。L2 容量取单卡全片容量，MIG 模式下按切分比例折算并在备注列标注。tensor core 代际以架构代号锚定（如 Ampere、Hopper、Blackwell），因为代际直接对应可用的 MMA 形状与是否支持异步拷贝、TMA 一类数据通路原语。NVLink 拓扑记录的是“卡间连接图的形状”，不是单链路带宽数字——形状决定 all-reduce 的环 vs 树选择。功耗墙取板卡 TDP，作为持续频率估算的上界输入。

代价在这里体现为“口径漂移的时延成本”。一个 agent 若在同一轮优化里先后用驱动上报 SM 数和规格 SM 数做分母，两次 SOL 估计的差值会被误读为 kernel 改进，导致错误的方向选择；这种错误不产生编译错误，只产生错误的奖励信号，在 RL 多轮里被放大。具体例子：某 kernel 在 MIG 切片上测得占用率接近 100%，agent 判定“占用率已饱和、应转向指令级优化”，而按物理 SM 数折算实际占用率远低于饱和线，真正瓶颈是并行度不足——一次口径错误就让整轮搜索走错分支。

$$\text{SOL}_{\text{compute}}=\frac{F_{\text{peak}}\cdot \eta_{\text{sm}}}{T_{\text{measured}}},\qquad \text{SOL}_{\text{bw}}=\frac{B_{\text{peak}}\cdot \eta_{\text{l2}}}{T_{\text{measured}}}$$

式中 $F_{\text{peak}}$ 由 SM 数与每 SM 每周期吞吐、时钟共同决定，$B_{\text{peak}}$ 即表中显存带宽列，$\eta$ 项是可达比例而非硬件常数。表中每一列都只提供分母，不提供 $\eta$——这是本表与“实测性能表”的根本分工。

二 · 阈值列：把“够不够”变成可判定的不等式

速查表若只有静态字段，agent 仍需自行推断“这个数算大还是算小”。因此本表在每个字段旁挂一条阈值判据，形式统一为不等式，让判断可执行。算术强度阈值：当 kernel 的 FLOP/Byte 高于 $F_{\text{peak}}/B_{\text{peak}}$ 时归入 compute-bound 侧，低于则归入 memory-bound 侧；这条阈值直接由表中两列相除得到，不需要额外常数。L2 复用阈值：工作集（working set）小于 L2 容量时，跨 block 复用可行，分块策略可以激进；超过 L2 容量则复用半径必须收缩到片上共享内存层级，否则分块带来的额外搬运会反噬带宽。占用率阈值：以每 SM 可驻留 warp 数为分母，低于某比例时优先补并行度而非改指令。通信阈值：单卡计算时间与跨卡传输时间之比低于 1 时，切分策略应从张量并行转向流水并行或数据并行。

这些阈值的价值在于把 agent 的决策从“凭经验”变成“查表代入”。伪代码层面，一次分块决策可以写成：读表中 L2 容量 $C_{L2}$ 与带宽 $B$，计算候选分块的工作集 $W$，若 $W \le C_{L2}$ 则选大分块并预期复用收益，否则选能装入共享内存的分块并预期复用收益为零。这里的关键是阈值比较发生在编译前的策略层，而不是运行后的 profile 层——前者省掉一整轮编译与测量，后者每轮都要付出编译时间与 NCU 采集时延。

代价是阈值判据的保守性带来的性能损失。以算术强度阈值做二分归类，会把恰好落在阈值附近的 kernel 强行归边，而这类 kernel 往往同时受两侧约束，单一归类会漏掉混合优化空间；表现为优化后实测提升小于预期，属于“判据粗糙”的代价而非实现错误。具体例子：一个归一化类 kernel 的算术强度略高于阈值被判为 compute-bound，agent 因此放弃合并访存优化，而实测显示其时间主要花在访存上——阈值只提供初判，最终归因仍需 profile 校正，这一点必须在表的使用说明里写明，否则 agent 会把初判当结论。

判据表达式代入字段触发动作
算术强度分界$I \gtrless F_{\text{peak}}/B_{\text{peak}}$SM 数、带宽选 compute 侧或 bw 侧优化模板
L2 复用可行$W \le C_{L2}$L2 容量放大分块、跨 block 复用
占用率补并行$\text{occ} < \text{occ}_{\text{target}}$SM 数、warp 上限增并行度而非改指令
切分策略切换$T_{\text{comp}}/T_{\text{comm}} < 1$NVLink 拓扑张量并行转流水/数据并行

三 · 代际列与指令形状：tensor core 代际如何改写 SOL 分母

tensor core 代际列不是标签，它直接改写算力分母的构成。不同代际支持的 MMA 指令形状不同，同一份 Triton 或 CuTe 代码在不同代际上会被 lowering 到不同的指令，每周期吞吐随之变化；因此 SOL 计算里的 $F_{\text{peak}}$ 必须按代际取值，而不能跨代际复用同一个数。更关键的是代际决定数据通路原语：异步拷贝与 TMA 一类机制在较新代际可用，它们改变的是“搬运与计算重叠”的能力，从而改变带宽屋顶的实际可达比例 $\eta_{\text{l2}}$。agent 在生成 kernel 时若忽略代际列，会写出在目标卡上无法映射到高效指令的代码，编译能过、正确性 oracle 能过，但 SOL 百分比长期停在低位。

机制上，代际差异通过两条路径影响性能：其一，MMA 形状决定了每个 warp 一次能吞下的矩阵块尺寸，形状不匹配会导致寄存器碎片化与额外搬运；其二，代际引入的异步数据通路让 load 与 MMA 可以在时间上重叠，缺少该通路时只能靠软件流水（software pipelining）手工重叠，编译器生成的流水深度受寄存器压力限制。伪代码层面，一个分块 kernel 的骨架在支持异步通路的代际上可以写成“发起异步拷贝 → 等待屏障 → MMA”，在不支持的代际上则退化为“同步 load → MMA”，后者的停顿直接计入时延。

代价体现在编译时间与寄存器压力两侧。为较新代际启用异步通路与更深流水，会显著增加编译期指令调度的工作量，编译时间上升；同时流水深度增加占用更多寄存器，占用率下降，形成“更深流水 vs 更高占用”的取舍。具体例子：同一份矩阵乘 kernel，在代际较新的卡上映射到更大形状的 MMA 并启用异步拷贝，单轮编译耗时明显长于旧代际路径，且寄存器用量上升导致每 SM 驻留 warp 数减少；agent 若只看单次运行时间而不看编译时间预算，会在多轮搜索中把编译开销累积成不可接受的总时延。

$$F_{\text{peak}}^{\text{(gen)}}=N_{\text{SM}}\cdot f_{\text{clk}}\cdot \text{throughput}_{\text{MMA}}^{\text{(gen)}}(\text{shape})$$

该式说明代际列必须与指令形状联合查表：只写代际不写形状，分母仍不唯一。

四 · NVLink 拓扑列：切分策略的通信项从哪来

NVLink 拓扑列记录的是卡间连接图的形状，而非单链路带宽。形状决定集合通信的算法选择：全互联或交换式拓扑可用环或树，部分连接拓扑需要先做局部聚合再跨组传输。对 kernel agent 而言，这一列的作用是给出通信项的量级与结构，从而判断切分策略是否值得。张量并行把单层切到多卡，每层前后各一次集合通信，通信量与切分度成正比；数据并行只在梯度同步时通信，通信频次低但单次量大；流水并行把通信摊到微批边界，单次量小但引入气泡。拓扑形状决定了这三种策略中哪一种的通信项能被隐藏进计算。

机制上，拓扑列与“计算通信比”阈值联动：当单卡计算时间远大于一次集合通信时间时，张量并行的通信可被重叠隐藏；当两者量级接近时，通信暴露为时延。伪代码层面，一次切分决策读拓扑列得到通信图，估算 all-reduce 的跳数与每跳数据量，再与表中 SM 数折算出的单卡计算时间比较，决定切分维度。这里必须强调：拓扑列不提供带宽数字，只提供形状；带宽数字属于另一张表，混用会让通信估算失去结构信息。

代价是拓扑不匹配导致的带宽浪费与显存占用上升。在部分连接拓扑上强行做全量张量并行，集合通信需要多跳转发，有效带宽低于链路峰值，表现为扩展效率随卡数增加而下降；同时张量并行要求每卡持有切片权重与激活，显存占用随切分度上升，若切分度过高会触发重算或换出，进一步拉长时延。具体例子：一个注意力 kernel 在多卡上做头维切分，拓扑为部分连接，all-reduce 需跨组两跳，agent 观测到扩展效率不随卡数线性增长，若它把原因归为 kernel 实现而非拓扑，就会在错误的维度上反复调参。

五 · 功耗墙列：持续频率与降频后的有效分母

功耗墙列提供的是持续频率估算的上界输入，而不是瞬时性能标签。GPU 在短时突发下可高于持续频率运行，长时间满载则被功耗墙拉回持续频率；因此 SOL 计算若用突发频率做分母，会系统性低估实际耗时，让 agent 误判“还有优化空间”。正确用法是把功耗墙与散热条件一起作为持续频率的约束，得到“降频后的有效算力”作为分母，再与实测时间比较。这一列对长时间运行的 kernel 尤其关键：训练类负载与长序列推理都处于持续满载区，瞬时频率不具代表性。

机制上，功耗墙通过频率-电压曲线作用于算力：功耗近似与频率和电压的乘积相关，撞墙后频率下调，算力分母随之下降。伪代码层面，SOL 计算应先判定负载是否处于持续区（运行时长超过热时间常数），若是则用降频频率，否则用突发频率；这一判定必须显式写入评估流程，否则同一 kernel 在不同测量窗口下会得到不同的 SOL 百分比，破坏多轮 RL 奖励的可比性。代价是降频带来的时延上升与吞吐下降，且降频幅度随散热条件变化，使跨机器比较失去一致性——这正是评估规范要求固定散热与测量窗口的原因。

具体例子：一个长时运行的归约 kernel 在突发窗口内测得时间较短，agent 据此判定带宽利用率已接近屋顶并停止优化；而在持续窗口下同一 kernel 因降频导致时间拉长，实际带宽利用率低于屋顶，仍有合并访存与向量化空间。两次测量差异全部来自功耗墙列的口径选择，与 kernel 代码无关。工程判断是：把功耗墙列与测量窗口绑定写入速查表的使用前提，任何跨窗口比较都必须标注口径，否则 SOL 数字不可比。

$$f_{\text{sustained}}\approx f_{\text{burst}}\cdot \min\!\left(1,\frac{P_{\text{wall}}}{P_{\text{burst}}}\right)^{1/\alpha}$$

式中 $\alpha$ 反映频率-电压关系的陡峭程度，$P_{\text{wall}}$ 即表中功耗墙列；该式只用于定性排序，不作为精确预测。

六 · 表的读取顺序与失效边界

速查表要能“照着用”，必须规定读取顺序，否则 agent 会在字段间来回跳跃、反复重算。推荐顺序是：先读 SM 数与显存带宽得到算术强度阈值，完成 compute/memory 初判；再读 L2 容量确定分块可行域；再读 tensor core 代际与指令形状确定算力分母；然后读 NVLink 拓扑决定是否切分及切分维度；最后读功耗墙并结合测量窗口确定持续频率。这个顺序的每一步都消费前一步的输出，形成一条单向决策链，避免循环依赖。伪代码层面，这条链可以写成一次查表函数：输入 kernel 特征与目标卡型，输出优化模板与预期瓶颈，全过程不触发编译。

失效边界必须与表同页呈现。第一，表中所有字段都是分母来源，不是可达性能承诺；把字段当承诺会让 agent 把“理论屋顶”误读为“应达目标”，在无法达到时错误地继续搜索。第二，跨代际、跨切分模式（如 MIG）、跨散热条件的字段不可直接比较，比较前必须折算并标注。第三，阈值判据是初判，最终归因必须由 profile 校正；把初判当结论会漏掉混合瓶颈。第四，拓扑列只给形状不给带宽，通信估算需另取带宽数字。这四条边界对应四类典型误用，每一类都会在多轮搜索中产生错误的奖励信号，代价是整轮编译与测量预算的浪费。

具体例子：agent 按读取顺序先算出某 kernel 属 memory-bound，据 L2 容量选定大分块，再按代际选定向量化访存指令，最后按功耗墙选定持续窗口测量；一轮编译即得到接近屋顶的结果，省去了“先猜 compute-bound 再改指令”的错误分支。反之，若跳过 L2 容量直接按经验分块，工作集超出 L2 后复用收益归零，agent 会把带宽利用率低误归为指令问题，多轮调参仍不收敛。工程判断落在最后一步：速查表的价值不在于字段多全，而在于读取顺序固定、口径写死、失效边界同页——三者缺一，表就从“可执行判据”退化为“参数清单”。
