一 · 从算子规格到 DSL 初始点：受约束搜索的入口

该方法的流程起点不是一段自然语言需求，而是一份算子规格加一组 DSL 模板。智能体在模板上选定初始分块尺寸、线程映射与流水策略，形成受约束的中间表示。这一步的输入是算子语义（如矩阵乘的 M/N/K 与数据类型）与 DSL 模板库；输出是一个参数元组，而非源码。代价体现在表达力上：DSL 只覆盖模板预置的调度模式，超出模板的调度策略在入口处即不可表达，这是搜索空间压缩的直接代价，也是方法适用边界的来源。具体机制是参数合法性校验前移——分块维度与线程数必须满足模板声明的整除与资源约束，非法组合在展开前被拒绝，因此不会产生编译调用。举例而言，若模板要求线程块内线程数为 2 的幂且共享内存占用不超过模板声明的上限，则一个越界的分块参数在 DSL 前端即被丢弃，省去一次编译—运行往返。这一步不消耗 GPU 时间，但消耗 token：智能体需要读取模板约束并推理出合法参数，模板越复杂，单轮提示中承载约束描述的 token 越多。

把这一步形式化，可写成参数元组到合法性谓词的映射：

$$\mathcal{P}=\{(b_t,b_s,t_m,s_p)\mid \mathrm{valid}(b_t,b_s,t_m,s_p;\ \mathrm{template})=\mathrm{true}\}$$

其中 $b_t$ 为分块维度、$b_s$ 为共享内存分片、$t_m$ 为线程映射、$s_p$ 为流水深度。搜索只在 $\mathcal{P}$ 内进行，这是与自由形式代码生成最本质的差别：后者的搜索空间是全部可编译的 CUDA 源码，前者是有限且语义合法的参数组合。代价是模板未覆盖的最优调度被排除，收益是无效编译与错误候选的比例下降。

二 · DSL 展开与编译：把中间表示变成可执行代码

第二步是代码生成与编译层。输入是上一步选定的参数元组，输出是可编译的 GPU 源码与编译产物。机制上，DSL 展开是确定性的模板实例化：分块参数填入模板的循环边界与索引表达式，线程映射决定 `threadIdx` 到数据坐标的仿射变换，流水策略决定共享内存的分配与同步点插入位置。因为展开是确定性的，同一参数元组总是产生同一份源码，这使候选之间的比较不受生成随机性干扰。代价是编译时间与编译次数：每一轮变异都触发一次展开与编译，编译失败虽被 DSL 前端大幅削减，但模板实例化后的语义错误（如越界访存）仍可能在编译期或运行期暴露。一个具体例子是流水深度参数：当 $s_p$ 增大到共享内存超出模板声明的上限时，展开后的源码在编译期报资源超限，这一失败模式被记录并回灌，智能体据此回退 $s_p$ 而非盲目再试。

这一步的工程判断在于编译开销是否值得。若单次编译耗时远大于一次参数变异的推理耗时，则迭代轮数成为主要成本项；DSL 的价值正是把「编译—失败—再生成」的循环压缩为「校验—拒绝—再变异」，把编译调用次数降下来。论文摘要未给出编译次数或编译时间的量化口径，因此这一收益只能定性表述为方向性的效率改进。

三 · 运行与正确性硬约束：失败模式的分流

第三步在目标 GPU 上运行编译产物，采集耗时与资源占用，并执行正确性检查。输入是编译产物与测试输入，输出是实测耗时、资源占用与正确性判定。机制上，正确性检查被置于编译运行之后作为硬约束：数值错误的候选记录失败模式后回退变异，不进入保留集合。这与 DSL 前端的结构校验形成两道闸门——前者拦截非法结构，后者拦截语义正确但数值错误的实现。代价是运行时间与测试输入的开销：每个候选都要跑一遍参考对比，测试规模越大，单候选的验证成本越高。举例而言，一个分块参数在结构上合法、编译通过，但因边界处理缺失在非整除 shape 上产生错误结果，该候选被正确性检查拦截，其失败模式（边界条件）成为下一轮变异的引导信号，而不是被当作性能候选保留。

这里的分流逻辑可写成候选状态的判定：

$$\mathrm{state}(c)=\begin{cases}\mathrm{reject}, & \lnot\,\mathrm{correct}(c)\ \lor\ \lnot\,\mathrm{compiled}(c)\\ \mathrm{candidate}, & \mathrm{correct}(c)\ \land\ \mathrm{gap}(c)<\mathrm{gap}_{\mathrm{best}}\\ \mathrm{discard}, & \mathrm{correct}(c)\ \land\ \mathrm{gap}(c)\ge\mathrm{gap}_{\mathrm{best}}\end{cases}$$

正确性作为硬约束意味着召回率优先于性能：任何数值错误的候选都不参与性能排序，避免搜索被错误但「看起来快」的实现带偏。代价是正确性检查本身的覆盖度决定方法可信度——若测试输入未覆盖边界 shape，错误候选可能漏网，这一风险在摘要级材料中无法评估。

四 · speed-of-light 归一化：把绝对毫秒换成距上限的差距

第四步是反馈层的核心：计算实测耗时与 speed-of-light 的比值，再折算为归一化差距回灌智能体。输入是实测耗时与硬件模型给出的理论上限耗时，输出是一个无量纲的差距值。机制上，speed-of-light 估计依据硬件模型参数（峰值算力、峰值带宽）与算子的访存/计算量下界，给出该算子在该硬件上不可逾越的耗时下限。归一化后，智能体的决策依据从「这次比上次快了多少毫秒」变为「这次距硬件上限还差多远」，后者在不同算子、不同 shape 之间可比，前者不可比。代价是估计偏差直接扭曲引导信号：若硬件模型高估了可达带宽，则计算密集算子的差距被系统性低估，搜索会误判瓶颈在访存而做无效变异；若低估，则过早停止优化。这是该方法引导信号的天花板，也是其口径依赖硬件的根源。

公式层面，比值与差距的定义为：

$$\mathrm{SOL\ ratio}=\frac{T_{\mathrm{measured}}}{T_{\mathrm{speed\ of\ light}}},\qquad \mathrm{gap}=1-\frac{1}{\mathrm{SOL\ ratio}}$$

当 $\mathrm{SOL\ ratio}\to 1$ 时差距趋零，表示逼近上限；比值大于 1 表示尚有空间。一个具体例子是访存密集算子：若实测耗时是理论上限的两倍，则比值为 2、差距为 0.5，智能体据此判断瓶颈在访存效率，针对性变异分块与流水参数以提高带宽利用率，而非调整计算相关的线程映射。这一步不消耗 GPU 时间，但消耗 token：差距值与瓶颈判定的描述需要进入下一轮提示，反馈的信息密度决定了单轮提示的有效性。

五 · 迭代变异与候选保留：搜索而非梯度

第五步是迭代循环本身。优化配方以搜索为主而非梯度训练：智能体在 DSL 参数空间上做迭代变异，每轮以归一化差距作为奖励信号，保留改善候选、淘汰退化候选，正确性检查作为硬约束过滤。输入是上一轮的差距值与失败模式，输出是新的参数元组与更新后的候选池。机制上，变异是局部扰动：在合法参数集内调整分块、线程映射或流水深度中的一个或几个维度，而非重新生成整段代码。这使每轮变异的语义影响可预测，反馈信号与变异动作之间的因果链更短。代价是局部最优风险：参数空间的局部扰动可能困在模板覆盖的次优区域，无法跳出模板本身的表达力边界；同时候选池规模与迭代上限在摘要中未给出，token 成本随轮数线性增长而收益递减的拐点无法从摘要判断。

伪代码层面的循环骨架为：

  • 读取算子规格，在 DSL 模板上取初始合法参数元组，展开并编译；
  • 运行并做正确性检查，失败则记录失败模式、回退变异；
  • 通过则计算 $\mathrm{gap}$，与当前最优比较，改善则入池、退化则淘汰；
  • 依据 $\mathrm{gap}$ 与瓶颈判定选择下一轮变异的参数维度，重复至差距收敛或达迭代上限；
  • 输出满足正确性且归一化指标最优的 kernel。

这一循环的成本结构是：每轮一次编译加一次运行加一次正确性验证，外加一次智能体推理的 token 开销。DSL 压缩的是编译与运行的无效次数，speed-of-light 压缩的是推理轮数——前者减少机器时间，后者减少 token。论文声称提升了效率，但摘要未给出加速比、通过率、token 成本或编译次数，因此这两个压缩通道各自的贡献无法从摘要级材料分离。

六 · 三层结构的接口与代价归属

把上述步骤归到三层结构，可以看清每一步的代价归属。DSL 前端承担结构校验与展开，代价是表达力损失与模板 token 开销；代码生成与编译层承担实例化与编译，代价是编译时间与编译次数；反馈层承担运行采集与归一化，代价是运行时间、测试输入开销与硬件模型偏差。三层之间的接口是参数元组、源码、实测耗时与归一化差距，接口上的信息密度决定了单轮迭代的有效性。一个工程判断是：若 DSL 模板的表达力足以覆盖目标算子的主要调度族，则压缩搜索空间的收益大于表达力损失；若目标算子需要模板外的非常规调度，则方法在入口处即失效，此时应退回自由形式生成并接受更高的搜索成本。这一判断不依赖具体数字，而依赖算子族与模板覆盖度的匹配关系。

步骤输入输出主要代价
DSL 初始点选取算子规格、模板约束合法参数元组模板 token、表达力损失
展开与编译参数元组源码、编译产物编译时间、编译次数

这张表的意义在于把「效率提升」拆成可归因的通道：DSL 前端减少无效编译，反馈层减少无效轮数，两者都指向同一个工程目标——在有限 token 与有限机器时间内逼近硬件上限。但摘要级材料未给出任何量化口径，因此表中每一行的代价只能定性描述，无法判断哪一行是瓶颈。对使用该方法的工程团队而言，可操作的判断是：先测量自身算子族与 DSL 模板的覆盖匹配度，再测量单次编译与单次推理的相对耗时，若编译远重于推理，则 DSL 的压缩收益显著；若推理远重于编译，则 speed-of-light 的轮数压缩才是主要杠杆。这两个测量都不需要论文给出数字，而是部署前必须自测的口径。

当 DSL 成为搜索边界：失效条件与系统代价

DSL 前端的合法性校验发生在源码展开之前，非法分块或线程映射组合被直接拒绝，这一步省掉的是编译与运行开销，代价却转移到了表达力上：模板未覆盖的调度策略无法被表达，最优解可能落在 DSL 之外。判断该方案是否适用，先看算子能否被现有模板参数化——若关键优化依赖模板外的流水或重排，搜索空间被约束的同时也把最优解排除，此时「效率提升」与「表达力损失」必须分开计量。一个具体例子：某算子最优解要求非规则的线程映射，而 DSL 只允许规则分块，则智能体在合法空间内收敛到的候选虽编译通过、归一化差距改善，却仍远离真实上限。

引导信号的天花板由 speed-of-light 估计本身决定。反馈层把实测耗时折算为归一化差距，公式为

$$\mathrm{gap}=1-\frac{T_{\mathrm{speed\ of\ light}}}{T_{\mathrm{measured}}}$$

若硬件模型参数偏差使 $T_{\mathrm{speed\ of\ light}}$ 偏小，差距被系统性高估，智能体会持续朝访存或计算瓶颈的错误方向变异；偏大则差距被压缩，搜索过早判定收敛。该偏差不随迭代轮数自愈，反而被每轮奖励放大，因此估计口径必须与目标硬件绑定，跨硬件比较差距没有意义。

正确性检查置于编译运行之后作为硬约束，失败候选记录失败模式后回退变异，不进入保留集合。这意味着每一轮仍要付出一次编译与运行的时延，DSL 只削减了非法组合带来的无效编译，未消除合法候选的实测成本；候选池规模与迭代上限未披露，token 与编译次数无法预估。工程判断上，应把 DSL 覆盖度与 SOL 估计误差作为准入条件先测：覆盖度不足则方法不适用，估计误差过大则引导信号失效，二者任一不满足，效率声明都不能当作已验证的加速比引用。
